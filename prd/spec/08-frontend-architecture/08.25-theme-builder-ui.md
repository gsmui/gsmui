# Purpose

This document defines the theme builder: a two-pane UI where designers adjust design tokens
(colors, radius, spacing, typography) and see a live `gsmui:` component gallery re-themed in
real time. Edits write directly to CSS custom properties (`--gsmui-*`) on `:root` and are
serialized to a theme record via Livewire.

---

## 1. Page Composition

| Pane | GsmUi Components | Livewire |
| --- | --- | --- |
| Token controls | `gsmui:color-picker`, `gsmui:slider`, `gsmui:input` | `wire:model="tokens.*"` |
| Live preview | `gsmui:button`, `gsmui:card`, `gsmui:input`, `gsmui:badge` | reacts to `--gsmui-*` |
| Palette | `gsmui:swatch` grid (`gsmui:button`) | `savePalette()` |
| Export | `gsmui:code` (CSS dump) + `gsmui:button` (copy) | `export()` |

## 2. Component Tree

```text
gsmui:layouts.app
└── <builder grid>
    ├── <controls>
    │   ├── gsmui:color-picker (wire:model="tokens.primary")
    │   ├── gsmui:slider      (wire:model="tokens.radius")
    │   └── gsmui:input       (wire:model="tokens.font")
    └── <preview>  (all re-themed via --gsmui-* on :root)
        ├── gsmui:card → gsmui:button, gsmui:badge
        └── gsmui:input (invalid state demo)
```

## 3. Data Flow — Token → CSS Variable → Preview

```text
gsmui:color-picker wire:model="tokens.primary"
        │  input + change events (native range parity)
        ▼
ThemeBuilder::$tokens
        │  updatedTokens()
        ▼
JS: setAttribute('style', '--gsmui-primary: <val>') on :root
        │  (MutationObserver in gsmui web components picks up change)
        ▼
preview components re-render from --gsmui-* (no reload)
        │  on Save:
        ▼
wire:submit  ──▶  ThemeEngine persist (05.16)  ──▶  gsmui:toast
```

- Token edits use `setAttribute`/`removeAttribute` from `utils.js` (not native DOM) so the
  MutationObserver in bundled components reacts correctly (per AGENTS.md JS conventions).
- `gsmui:color-picker` reuses its internal `ui-slider` for the hue track — composed, not rebuilt.
- ARIA labels set from Blade via `__()` (e.g. `__('Primary color')`), with English fallback in JS.

## 4. CSP & Styling

- Dynamic theme CSS injected through `adoptedStyleSheets`; no `@font-face` (system fonts only).
- Color round-trip precision loss is accepted per AGENTS.md ("pragmatic imperfections").

- Real-time `setAttribute` on `:root` vs per-scope wrapper — confirm scoping for multi-theme preview.
- Token validation (invalid hex silently reverts) needs a defined revert rule.

## 6. Preview Pane Architecture

### 6.1 Component Gallery Layout

The preview pane renders a curated gallery of `gsmui:` components that demonstrate every design token in action. The gallery is organized into sections:

```text
<preview pane>
├── <color section>
│   ├── primary button, secondary button, accent button
│   ├── success/warning/danger badges
│   └── surface cards with border tokens
├── <typography section>
│   ├── heading hierarchy (h1–h6)
│   ├── body text paragraph
│   ├── muted text
│   └── code block (mono font)
├── <spacing section>
│   ├── card with varying padding
│   ├── button with varying padding
│   └── stack with varying gap
├── <radius section>
│   ├── cards with increasing radius
│   ├── buttons with increasing radius
│   └── avatar with full radius
├── <shadow section>
│   ├── cards with increasing elevation
│   └── popover with shadow-xl
├── <form section>
│   ├── input (default, focus, invalid, disabled)
│   ├── select
│   ├── checkbox / switch
│   └── textarea
└── <feedback section>
    ├── toast notification
    ├── alert (info, success, warning, danger)
    └── progress bar
```

### 6.2 Live Update Mechanism

When a token control changes, the flow is:

1. User adjusts a `gsmui:slider` or `gsmui:color-picker`
2. Livewire `wire:model` updates the corresponding `ThemeBuilder::$tokens` property
3. The `updatedTokens()` method fires
4. JS interop calls `setAttribute(':root', '--gsmui-<token>', <value>)` via `utils.js`
5. `MutationObserver` in each `gsmui:` web component detects the attribute change
6. Components re-render using the new CSS variable value
7. No full page reload — surgical DOM updates only

This mechanism relies on the `utils.js` `setAttribute`/`removeAttribute` helpers (AGENTS.md JS conventions) which trigger `MutationObserver` callbacks. The preview components are standard `gsmui:` components that read their styling from CSS variables, so they automatically pick up changes.

### 6.3 Preview State Management

The preview pane maintains its own state independently of the token controls:

- **Component state**: The preview inputs, selects, and toggles maintain their own local state (selected values, checked states) across token changes
- **Scroll position**: The preview pane preserves scroll position during token edits
- **Focus management**: Token controls never steal focus from the preview
- **Dark mode**: The preview supports a dark mode toggle that swaps the surface/background tokens to dark variants

### 6.4 Preview Responsiveness

The preview pane is responsive and demonstrates components at different breakpoints:

- **Mobile (< 640px)**: Single column, stacked cards
- **Tablet (640px–1024px)**: Two-column grid
- **Desktop (> 1024px)**: Full three-column layout

A breakpoint toggle in the preview header lets users preview their theme at different viewport widths without resizing the browser.

## 7. Palette System

### 7.1 Palette Generation

The palette section automatically generates a full color palette from the primary color:

- **Shades**: 50, 100, 200, 300, 400, 500, 600, 700, 800, 900, 950
- **Tints**: 5%, 10%, 15%, 20% mix with white
- **Complementary**: hue + 180°
- **Analogous**: hue ± 30°
- **Triadic**: hue + 120°, hue + 240°
- **Split-complementary**: hue + 150°, hue + 210°

### 7.2 Palette Display

```text
<gsmui:swatch grid>
├── shade 50 → 950 (11 swatches)
├── tint 5% → 20% (4 swatches)
├── complementary (1 swatch)
├── analogous (2 swatches)
├── triadic (2 swatches)
└── split-complementary (2 swatches)
```

Each swatch shows:
- The color fill
- The hex value (click to copy)
- The contrast ratio against white/black
- WCAG AA/AAA compliance indicators
- The token name if assigned

### 7.3 Palette Actions

- **Save palette**: Stores the generated palette as a named palette record
- **Export palette**: Downloads as JSON, CSS variables, or Tailwind config
- **Apply palette**: Sets all color tokens from a saved palette
- **Share palette**: Generates a shareable link with palette data encoded in URL

### 7.4 Palette Constraints

- Minimum contrast ratio of 4.5:1 for text colors (WCAG AA)
- Minimum contrast ratio of 3:1 for large text and UI components
- Automatic warning when a color token falls below contrast threshold
- Suggested alternative colors when contrast fails

## 8. Export System

### 8.1 CSS Variable Export

The export panel generates a complete CSS file with all token values:

```css
:root {
  --gsmui-primary: #3b82f6;
  --gsmui-secondary: #6b7280;
  --gsmui-accent: #8b5cf6;
  /* ... all tokens ... */
}

/* Dark mode overrides */
@media (prefers-color-scheme: dark) {
  :root {
    --gsmui-surface: #1f2937;
    --gsmui-background: #111827;
    /* ... dark variants ... */
  }
}
```

### 8.2 Tailwind Config Export

Generates a `tailwind.config.js` compatible object:

```js
module.exports = {
  theme: {
    extend: {
      colors: {
        primary: { DEFAULT: '#3b82f6', /* ... shades ... */ },
        // ...
      },
      borderRadius: { lg: '0.5rem', /* ... */ },
      // ...
    }
  }
}
```

### 8.3 JSON Token Export

Exports the raw token map as a structured JSON file for use in other tools:

```json
{
  "colors": { "primary": "#3b82f6", /* ... */ },
  "typography": { "fontFamily": "...", /* ... */ },
  "spacing": { "1": "4px", /* ... */ },
  "borderRadius": { "lg": "0.5rem", /* ... */ }
}
```

### 8.4 Export Validation

Before export, the system validates:
- All required tokens are present
- No tokens have empty or invalid values
- Contrast ratios meet WCAG AA minimums
- Font family values are valid CSS
- Spacing values are valid CSS lengths

Validation errors are displayed inline with suggestions for fixes.

## 9. Theme Persistence

### 9.1 Save Theme

The save flow:

1. User clicks "Save Theme"
2. `gsmui:modal` opens with theme name input
3. User enters a name and optional description
4. `wire:submit="saveTheme"` fires
5. `ThemeBuilder::saveTheme()` serializes all tokens
6. Theme is stored via `ThemeEngine::persist()` (05.16)
7. `gsmui:toast` confirms "Theme saved"

### 9.2 Load Theme

The load flow:

1. User clicks "Load Theme" in the toolbar
2. `gsmui:modal` opens with a list of saved themes
3. Each theme shows a preview thumbnail and metadata
4. User selects a theme and clicks "Apply"
5. All token controls update to the loaded values
6. Preview re-renders with the loaded theme

### 9.3 Theme History

- Last 20 token states are stored in memory for undo/redo
- Undo/Redo buttons in the toolbar (keyboard shortcuts: Ctrl+Z, Ctrl+Shift+Z)
- History is cleared on theme load or page refresh
- No persistent history across sessions (by design)

### 9.4 Theme Versioning

- Each save creates a new version
- Version history is accessible from the theme list
- Users can compare versions (diff view showing changed tokens)
- Users can revert to any previous version

## 11. Performance

### 11.1 Token Update Budget

- Token changes must complete within 16ms (60fps budget)
- `setAttribute` calls are batched using `requestAnimationFrame`
- No layout thrashing — token updates only change CSS properties
- Preview components use `will-change: background-color, color` on frequently-updated elements

### 11.2 Preview Rendering

- Preview components are lazy-loaded and only render when visible
- Intersection Observer triggers component mounting
- Off-screen preview sections are virtualized (not rendered)
- Theme changes only affect visible preview sections

### 11.3 Memory Management

- Color picker hue wheel uses Canvas for performance
- Palette swatches are virtualized for large palettes
- History stack is capped at 20 entries
- Event listeners are cleaned up on component destroy

## 13. Error Handling

### 13.1 Invalid Token Values

- Invalid hex color: silently reverts to previous value, shows `gsmui:toast` "Invalid color"
- Invalid number (slider): clamps to min/max range
- Invalid font family: shows inline error, reverts on blur
- Empty required token: shows inline error, blocks export

### 13.2 Save Failures

- Network error: `gsmui:toast` "Save failed — try again"
- Duplicate name: prompt to overwrite or rename
- Server error: `gsmui:toast` "Server error — changes preserved locally"

### 13.3 Load Failures

- Theme not found: `gsmui:toast` "Theme not found"
- Corrupted theme data: fallback to default tokens
- Permission denied: `gsmui:toast` "You don't have access to this theme"

## 20. Security

### 20.1 CSP Compliance

- No external fonts (`@font-face` is forbidden)
- No CDN scripts or styles
- All dynamic CSS via `adoptedStyleSheets`
- No `eval()`, `Function()`, or `blob:` URIs
- No network requests for theme data

### 20.2 Input Sanitization

- Token values are sanitized before CSS injection
- Font family names are validated against a safe list
- Hex colors are validated with regex
- Numeric values are clamped to defined ranges

### 20.3 XSS Prevention

- Token values are escaped before rendering in `gsmui:code`
- Export content is sanitized before clipboard copy
- Theme names are HTML-escaped
- Preview renders in a sandboxed iframe (optional)

## 30. Advanced Token Features

### 30.1 Token Inheritance

Tokens can reference other tokens using CSS `var()`:

```css
--gsmui-primary-light: color-mix(in srgb, var(--gsmui-primary) 20%, white);
--gsmui-primary-dark: color-mix(in srgb, var(--gsmui-primary) 80%, black);
```

The theme builder supports:
- Visual token inheritance chain (shows which tokens depend on others)
- Cascade preview (changing base token shows all derived tokens)
- Break inheritance (override derived token with custom value)
- Restore inheritance (revert to computed value)

### 30.2 Token Responsive Overrides

Tokens can have different values at different breakpoints:

```css
:root { --gsmui-space-4: 16px; }
@media (min-width: 640px) { :root { --gsmui-space-4: 20px; } }
@media (min-width: 1024px) { :root { --gsmui-space-4: 24px; } }
```

The theme builder provides:
- Breakpoint tabs for each token category
- Visual indicator when a token has responsive overrides
- Quick copy: apply one breakpoint's values to all
- Preview at different breakpoints (toggle in preview pane)

### 30.3 Token Context Overrides

Tokens can have different values in different contexts (e.g., dark mode, high contrast):

```css
:root { --gsmui-surface: #ffffff; }
@media (prefers-color-scheme: dark) { :root { --gsmui-surface: #1f2937; } }
```

The theme builder supports:
- Context tabs: Light, Dark, High Contrast, Custom
- Quick dark mode: auto-generate dark variants from light tokens
- Context preview: switch preview between contexts
- Export: generates context-specific CSS blocks

### 30.4 Token Composition

Complex tokens can be composed from multiple base tokens:

```css
--gsmui-card: var(--gsmui-radius-lg) var(--gsmui-shadow-sm) var(--gsmui-border-width) var(--gsmui-border-color);
```

The theme builder provides:
- Composition editor (visual builder for compound tokens)
- Token dependency graph (shows how tokens compose)
- Preview of composed token in context
- Validation (ensures all referenced tokens exist)

## 35. Theme Builder Performance Optimization

### 35.1 Rendering Optimization

- Use `requestAnimationFrame` for token updates to batch DOM changes
- Debounce slider input events (16ms) to prevent excessive updates
- Use `will-change` CSS property on frequently-updated elements
- Avoid layout thrashing by reading dimensions before writes
- Use CSS `contain` on preview sections to limit reflow

### 35.2 Memory Optimization

- Limit history stack to 20 entries
- Virtualize palette swatches (only render visible ones)
- Lazy-load preview sections (IntersectionObserver)
- Clean up event listeners on component destroy
- Use WeakMap for component state to allow garbage collection

### 35.3 Network Optimization

- No network requests for theme operations (all client-side)
- Font loading: preload critical fonts, lazy-load others
- Export generation: use Web Workers for large exports
- Theme data: compress with gzip before localStorage backup

### 35.4 Startup Optimization

- Lazy-load non-critical controls (palette, export)
- Defer preview rendering until first token change
- Use `content-visibility: auto` on off-screen sections
- Preload default theme tokens from inline script

## 36. Theme Builder Error Recovery

### 36.1 Local State Recovery

- Auto-save token state to localStorage every 5 minutes
- On page reload, prompt to recover unsaved changes
- Store last 5 token states in localStorage
- Clear recovery data on successful save

### 36.2 Token Corruption Recovery

- Validate all tokens on load
- If a token is invalid, revert to default value
- Log corruption event for debugging
- Show toast: "Some tokens were reset to defaults"

### 36.3 Browser Compatibility Recovery

- Detect unsupported features (Canvas, adoptedStyleSheets)
- Show fallback UI for unsupported browsers
- Disable features that require unsupported APIs
- Log compatibility issues for analytics

## 43. Theme Builder Deployment

### 43.1 Build Process

1. Compile Blade templates with `vite:build`
2. Bundle JavaScript with Vite (tree-shaking)
3. Bundle CSS with Tailwind (purge unused)
4. Generate asset manifest for cache busting
5. Minify JS and CSS for production
6. Generate source maps for debugging

### 43.2 Asset Manifest

```json
{
  "theme-builder.js": "/dist/theme-builder.abc123.js",
  "theme-builder.css": "/dist/theme-builder.def456.css",
  "vendor.js": "/dist/vendor.ghi789.js"
}
```

### 43.3 Caching Strategy

- HTML: `Cache-Control: no-cache` (always revalidate)
- JS/CSS: `Cache-Control: max-age=31536000` (immutable with hash)
- Fonts: `Cache-Control: max-age=31536000` (immutable)
- Images: `Cache-Control: max-age=86400` (1 day)

### 43.4 CDN Configuration

- All assets are self-hosted (no external CDN)
- Serve from same origin to avoid CORS issues
- Use HTTP/2 for parallel asset loading
- Enable Brotli compression for text assets

## 46. Theme Builder Rollback Plan

### 46.1 Rollback Triggers

- Error rate exceeds 5% of sessions
- Token update latency exceeds 100ms
- Save failure rate exceeds 10%
- Critical browser compatibility issue discovered

### 46.2 Rollback Procedure

1. Disable theme builder feature flag
2. Redirect to fallback theme editor (simple form)
3. Notify affected users via email
4. Investigate root cause
5. Fix and redeploy
6. Re-enable feature flag

### 46.3 Data Recovery

- All theme data is persisted in database
- localStorage backup for unsaved changes
- Export files can be re-imported
- No data loss on rollback
