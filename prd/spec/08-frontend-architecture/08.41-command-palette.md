# Purpose

The command palette is a keyboard-first launcher (Cmd/Ctrl+K) for navigation, actions, and quick search. It reuses the search UI results popover (08.36) and the date-picker dialog pattern, layering a global keybinding on top. Commands are registered declaratively and rendered with `<gsmui:command>` and `<gsmui:kbd>` for key hints.

## 0. Architecture Overview

The command palette is a modal overlay triggered by a global keyboard shortcut. It provides a unified interface for:
- Navigation to any route in the application
- Execution of contextual actions
- Quick search across all available commands
- Access to settings and help

The architecture follows the same patterns as the date-picker dialog and search UI popover, ensuring visual and behavioral consistency across the component library.

### 0.1 Component Hierarchy

```
gsmui:command-palette (root)
├── gsmui:command-backdrop (overlay)
├── gsmui:command-panel (dialog)
│   ├── gsmui:command-input (search field)
│   ├── gsmui:command-list (results container)
│   │   ├── gsmui:command-group (section header)
│   │   │   ├── gsmui:command-item (result row)
│   │   │   └── gsmui:command-item
│   │   └── gsmui:command-group
│   │       └── gsmui:command-item
│   └── gsmui:command-footer (keyboard hints)
│       ├── gsmui:kbd
│       └── gsmui:kbd
└── gsmui:command-empty (empty state)
```

### 0.2 Data Flow

```
User Input → Query State → Filter Engine → Grouped Results → DOM Render
     │              │              │              │
     │              │              │              └── Roving Focus
     │              │              └── Score + Sort
     │              └── Debounce (50ms)
     └── Keyboard Event → Shortcut Parser → Action Executor
```

### 0.3 Lifecycle

1. **Registration**: Commands are registered during component init or via `Gsmui::commandPalette()->register()`
2. **Open**: User presses `Meta+K` / `Ctrl+K`, palette renders with empty query
3. **Search**: User types, results filter in real-time
4. **Navigate**: User Arrow-keys through results
5. **Execute**: User presses Enter, action runs, palette closes
6. **Close**: User presses Escape, palette closes, focus restores

### 0.4 Design Principles

The command palette follows these core principles:

1. **Keyboard-first**: Every action is accessible via keyboard. Mouse interaction is secondary.
2. **Instant feedback**: Search results appear within 50ms. No loading spinners for local commands.
3. **CSP-safe**: No `eval()`, no external scripts, no CDN. Everything is self-hosted.
4. **Accessible**: Full ARIA support, screen reader announcements, keyboard navigation.
5. **Consistent**: Uses the same visual language as date-picker, search, and modal components.
6. **Extensible**: Third-party packages can register commands without modifying core code.
7. **Performant**: Lazy initialization, DOM destruction on close, no memory leaks.
8. **Internationalized**: All strings are localized via `__()`.
9. **Theme-aware**: Adapts to light/dark mode via `--gsmui-*` tokens.
10. **Mobile-friendly**: Touch device support with on-screen trigger button.

## 1. Component Contracts

`stubs/resources/views/gsmui/command/index.blade.php`:

```blade
<gsmui:command
    :commands="$commands"
    wire:model.live="query"
    shortcut="meta+k"
    placeholder="{{ __('Type a command…') }}"
/>
```

`stubs/resources/views/gsmui/kbd/index.blade.php`:

```blade
<gsmui:kbd>⌘ K</gsmui:kbd>
```

- The palette panel reuses the AGENTS.md dialog class verbatim (`max-sm:max-h-full! rounded-xl shadow-xl … p-3`).
- Input is a combobox (`role="combobox"`) mirroring 08.36; results are a `role="listbox"` with roving focus.
- Focus ring on the custom panel/options: `has-focus-visible:outline-2 has-focus-visible:outline-[-webkit-focus-ring-color]`.

## 2. Global Keybinding

```js
// assets/js/gsmui/command.js
window.addEventListener('keydown', (e) => {
  if ((e.metaKey || e.ctrlKey) && e.key.toLowerCase() === 'k') {
    e.preventDefault();
    Gsmui.command.open();
  }
});
```

- The open/close state toggles via `setAttribute`/`removeAttribute` from `utils.js`; scroll lock is copied from the date-picker pattern.
- On open, focus moves into the input; Escape closes and restores focus to the previously focused element.

## 3. Command Registration

Commands are plain arrays passed to the component (title, icon, action, group). Icons are inline Heroicons/Lucide SVG. No network calls for local commands (`connect-src 'self'`).

```php
$commands = [
  ['title' => __('Go to Dashboard'), 'icon' => 'home', 'action' => 'navigate:/dashboard'],
  ['title' => __('New Component'), 'icon' => 'plus', 'action' => 'action:create'],
];
```

## 4. Command Data Model

Each command is a plain object conforming to the following shape:

```js
{
  id: 'navigate-dashboard',          // unique kebab-case identifier
  title: 'Go to Dashboard',          // localized via __()
  description: 'Navigate to the main dashboard',  // optional, shown in secondary text
  icon: 'home',                      // Heroicon/Lucide name or inline SVG
  group: 'navigation',               // grouping key for section headers
  action: 'navigate:/dashboard',     // action string (see §5)
  shortcut: 'meta+shift+d',          // optional, displayed in <gsmui:kbd>
  keywords: ['home', 'main', 'dash'], // optional, for fuzzy search matching
  disabled: false,                   // optional, dims the command
  dangerous: false,                  // optional, renders red accent for destructive actions
}
```

### 4.1 Command ID Rules

- IDs MUST be unique across all registered commands. Duplicate IDs are silently ignored with a `console.warn` in development mode.
- IDs are kebab-case, namespaced by group prefix when third-party extensions register commands.
- IDs are used as `data-command-id` attributes in the DOM for Playwright targeting.

### 4.2 Command Groups

Groups define section headers in the palette dropdown. Groups render in registration order unless an explicit `priority` is set.

| Group | Priority | Description |
| --- | --- | --- |
| `navigation` | 10 | Route navigation commands |
| `actions` | 20 | Contextual actions (create, save, delete) |
| `settings` | 30 | Settings and configuration shortcuts |
| `recent` | 5 | Recently used commands (dynamic) |
| `help` | 90 | Documentation and support links |
| `custom` | 50 | User/third-party registered commands |

### 4.3 Command Icons

Icons are inline Heroicons/Lucide SVGs only. No external icon fonts, no CDN. The icon is resolved at registration time and stored as an SVG string in the command object.

## 5. Action System

Actions are string-encoded instructions parsed by the command palette runtime. The format is `type:payload`.

### 5.1 Action Types

| Type | Payload | Behavior |
| --- | --- | --- |
| `navigate` | URL path | Calls `window.location.href` for same-origin, or `Livewire.navigate()` for internal routes |
| `action` | Method name | Calls a registered Livewire method on the current page component |
| `dispatch` | Event name | Fires a Livewire event via `$dispatch()` |
| `toggle` | Feature flag | Toggles a boolean feature flag in local state |
| `open` | Modal key | Opens a modal component by key (reuses 08.38 modal system) |
| `callback` | Function ref | Executes a registered callback function (first-party only, no `eval`) |

### 5.2 Action Parsing

```js
// assets/js/gsmui/command.js
function parseAction(actionString) {
  const colonIndex = actionString.indexOf(':');
  if (colonIndex === -1) {
    return { type: 'callback', payload: actionString };
  }
  return {
    type: actionString.substring(0, colonIndex),
    payload: actionString.substring(colonIndex + 1),
  };
}
```

### 5.3 Action Execution

```js
function executeAction(command) {
  const { type, payload } = parseAction(command.action);

  switch (type) {
    case 'navigate':
      if (payload.startsWith('/')) {
        Livewire.navigate(payload);
      } else {
        window.location.href = payload;
      }
      break;
    case 'action':
      Livewire.dispatch('gsmui:command', { method: payload });
      break;
    case 'dispatch':
      Livewire.dispatch(payload);
      break;
    case 'toggle':
      Gsmui.state.toggle(payload);
      break;
    case 'open':
      Gsmui.modal.open(payload);
      break;
    case 'callback':
      if (typeof Gsmui.callbacks[payload] === 'function') {
        Gsmui.callbacks[payload]();
      }
      break;
  }
}
```

## 6. Search & Fuzzy Matching

The command palette reuses the search UI results popover from `08.36-search-ui.md` for its filtering and display logic.

### 6.1 Fuzzy Matching Algorithm

- Primary match: exact substring of `title` (case-insensitive)
- Secondary match: fuzzy match against `title` using Levenshtein distance (max distance = 3)
- Tertiary match: match against `keywords` array
- Commands with no match are hidden
- Matched characters are highlighted in the results list using `<mark>` elements

### 6.2 Search Scoring

| Criterion | Weight |
| --- | --- |
| Exact title match | 100 |
| Title starts with query | 90 |
| Title contains query | 75 |
| Keyword exact match | 60 |
| Keyword fuzzy match | 40 |
| Description match | 20 |

### 6.3 Recent Commands

When the query is empty, the palette shows:
1. Pinned commands (if any)
2. Recently used commands (last 5, stored in `localStorage['gsmui-recent-commands']`)
3. Default navigation commands

### 6.4 Search Debouncing

Input is debounced at 50ms for local commands. No network calls for local command search (`connect-src 'self'`). If a remote search extension is added in the future, debounce increases to 150ms.

### 7.4 Roving Focus

- Arrow Up/Down moves focus through visible command items (roving tabindex pattern)
- Home jumps to first item, End jumps to last item
- Enter/Space commits the focused command
- Tab is captured and does not leave the palette
- Focus ring uses `has-focus-visible:outline-2 has-focus-visible:outline-[-webkit-focus-ring-color]`

## 8. Keyboard Interaction

### 8.1 Key Bindings

| Key | Action |
| --- | --- |
| `Meta+K` / `Ctrl+K` | Open/close palette |
| `Arrow Up` | Move focus to previous command |
| `Arrow Down` | Move focus to next command |
| `Home` | Move focus to first command |
| `End` | Move focus to last command |
| `Enter` | Execute focused command |
| `Space` | Execute focused command (only when input is empty) |
| `Escape` | Close palette, restore focus |
| `Tab` | Trap focus within palette |
| `Shift+Tab` | Trap focus within palette (reverse) |

### 8.2 Focus Management

On open:
1. Save `document.activeElement` as `previouslyFocused`
2. Move focus to the search input
3. Show the palette with `setAttribute('aria-hidden', 'false')` via `utils.js`
4. Add scroll lock (copied from date-picker pattern)

On close:
1. Hide the palette with `removeAttribute('aria-hidden')` via `utils.js`
2. Remove scroll lock
3. Restore focus to `previouslyFocused`

### 8.3 Conflict Resolution

- `Ctrl+K` does not conflict with Chrome's address bar (Chrome uses `Ctrl+L` / `Alt+D`)
- `Ctrl+K` does not conflict with Firefox's search bar (Firefox uses `Ctrl+K` for search — we intercept first and call `preventDefault()`)
- `Meta+K` does not conflict with macOS system shortcuts
- On Windows, `Ctrl+K` may conflict with some Electron apps — document this in the help overlay

## 10. State Management

### 10.1 Palette State

```js
{
  open: false,
  query: '',
  selectedIndex: 0,
  commands: [],           // registered commands
  filteredCommands: [],   // after search filtering
  groups: {},             // grouped commands for display
  recentCommands: [],     // from localStorage
  pinnedCommands: [],     // user-pinned commands
}
```

### 10.2 State Transitions

```
CLOSED → (Meta+K) → OPEN
OPEN → (Escape) → CLOSED
OPEN → (Enter) → EXECUTE → CLOSED
OPEN → (query) → FILTERED
FILTERED → (Enter) → EXECUTE → CLOSED
```

## 13. Performance Considerations

### 13.1 Command Registration

- Commands are registered once on page load, not on every keystroke
- Registration is batched to avoid multiple re-renders
- Command list is virtualized if > 100 commands (using a simple windowed rendering approach)

### 13.2 Search Performance

- Fuzzy search runs synchronously for < 50 commands
- For 50+ commands, search is offloaded to a Web Worker (same-origin, CSP-safe)
- Worker is lazily loaded only when command count exceeds threshold

### 13.3 Memory Management

- Palette DOM is destroyed on close, not hidden
- Event listeners are removed on destroy
- localStorage reads are cached for the session duration

## 29. Detailed Implementation Notes

### 29.1 Command Registration Flow

```
1. Service Provider boot()
   └── Gsmui::commandPalette()->register([...])
       └── Add to registry array

2. Component init (Blade render)
   └── <gsmui:command :commands="$commands" />
       └── Pass commands to JS via data attribute

3. JS initialization (gsmui.js)
   └── Gsmui.commandPalette.init()
       └── Read commands from data attribute
           └── Merge with registered commands
               └── Build command map
                   └── Index for search
```

### 29.2 Search Algorithm Detail

```
Input: query = "dash"
Commands: [dashboard, settings, profile, create]

Step 1: Exact match
  "dashboard" contains "dash" → score 75
  "settings" contains "dash" → no
  "profile" contains "dash" → no
  "create" contains "dash" → no

Step 2: Fuzzy match (Levenshtein)
  "settings" → "dash" distance = 5 → no match (max 3)
  "profile" → "dash" distance = 6 → no match
  "create" → "dash" distance = 4 → no match

Step 3: Keyword match
  No keywords for these commands

Step 4: Sort by score
  dashboard (75) → displayed first

Result: Only "dashboard" shown
```

### 29.3 Focus Management Flow

```
Open:
1. Save document.activeElement → previouslyFocused
2. Set aria-hidden="false" on palette
3. Add scroll lock to body
4. Focus search input (setTimeout 10ms for render)

Close:
1. Set aria-hidden="true" on palette
2. Remove scroll lock from body
3. Restore focus to previouslyFocused
4. Destroy palette DOM (optional)

Keyboard navigation:
1. Arrow Down → increment selectedIndex
2. Arrow Up → decrement selectedIndex
3. Home → set selectedIndex to 0
4. End → set selectedIndex to last
5. Enter/Space → execute command at selectedIndex
```

### 29.4 Action Execution Flow

```
1. User presses Enter on command
2. Parse action string: "navigate:/dashboard"
   → type = "navigate", payload = "/dashboard"
3. Check if action type is registered
4. Execute handler:
   - navigate: Livewire.navigate(payload)
   - action: Livewire.dispatch('gsmui:command', { method: payload })
   - dispatch: Livewire.dispatch(payload)
   - toggle: Gsmui.state.toggle(payload)
   - open: Gsmui.modal.open(payload)
   - callback: Gsmui.callbacks[payload]()
5. Add to recent commands (localStorage)
6. Dispatch gsmui:command-palette:select event
7. Close palette
```

### 29.6 Search Indexing

Commands are indexed at registration time for fast lookup:

```javascript
function buildSearchIndex(commands) {
  const index = {
    byId: new Map(),
    byGroup: new Map(),
    byKeyword: new Map(),
    tokens: [],
  };

  commands.forEach((cmd) => {
    index.byId.set(cmd.id, cmd);

    if (!index.byGroup.has(cmd.group)) {
      index.byGroup.set(cmd.group, []);
    }
    index.byGroup.get(cmd.group).push(cmd);

    if (cmd.keywords) {
      cmd.keywords.forEach((kw) => {
        if (!index.byKeyword.has(kw.toLowerCase())) {
          index.byKeyword.set(kw.toLowerCase(), []);
        }
        index.byKeyword.get(kw.toLowerCase()).push(cmd);
      });
    }

    index.tokens.push({
      id: cmd.id,
      title: cmd.title.toLowerCase(),
      keywords: (cmd.keywords || []).map((k) => k.toLowerCase()),
    });
  });

  return index;
}
```

### 29.7 Virtual Scrolling

For command lists with more than 50 items, virtual scrolling is used:

```javascript
function initVirtualScroll(listbox, commands, itemHeight = 40) {
  const containerHeight = listbox.clientHeight;
  const visibleCount = Math.ceil(containerHeight / itemHeight);
  const totalHeight = commands.length * itemHeight;

  listbox.style.height = `${totalHeight}px`;
  listbox.style.position = 'relative';

  function renderVisibleItems(scrollTop) {
    const startIndex = Math.floor(scrollTop / itemHeight);
    const endIndex = Math.min(startIndex + visibleCount + 1, commands.length);

    const fragment = document.createDocumentFragment();
    for (let i = startIndex; i < endIndex; i++) {
      const item = createCommandItem(commands[i]);
      item.style.position = 'absolute';
      item.style.top = `${i * itemHeight}px`;
      fragment.appendChild(item);
    }

    listbox.innerHTML = '';
    listbox.appendChild(fragment);
  }

  listbox.addEventListener('scroll', (e) => {
    renderVisibleItems(e.target.scrollTop);
  });

  renderVisibleItems(0);
}
```

### 29.8 Keyboard Shortcut Normalization

Shortcuts are normalized to a canonical format:

```javascript
function normalizeShortcut(combo) {
  const parts = combo.toLowerCase().split('+');
  const modifiers = ['meta', 'ctrl', 'shift', 'alt'];
  const normalized = {
    meta: false,
    ctrl: false,
    shift: false,
    alt: false,
    key: null,
  };

  parts.forEach((part) => {
    if (modifiers.includes(part)) {
      normalized[part] = true;
    } else {
      normalized.key = part;
    }
  });

  return normalized;
}

function matchShortcut(event, normalized) {
  const isMeta = event.metaKey || event.ctrlKey;
  return (
    normalized.meta === isMeta &&
    normalized.shift === event.shiftKey &&
    normalized.alt === event.altKey &&
    normalized.key === event.key.toLowerCase()
  );
}
```

### 29.10 State Persistence

Recent and pinned commands are persisted:

```javascript
const STORAGE_KEYS = {
  recent: 'gsmui-recent-commands',
  pinned: 'gsmui-pinned-commands',
};

function saveRecentCommands(commandIds) {
  try {
    localStorage.setItem(STORAGE_KEYS.recent, JSON.stringify(commandIds));
  } catch (e) {
    // localStorage unavailable, fail silently
  }
}

function loadRecentCommands() {
  try {
    const data = localStorage.getItem(STORAGE_KEYS.recent);
    return data ? JSON.parse(data) : [];
  } catch (e) {
    return [];
  }
}

function addToRecent(commandId) {
  const recent = loadRecentCommands().filter((id) => id !== commandId);
  recent.unshift(commandId);
  saveRecentCommands(recent.slice(0, 5));
}
```

### 29.12 Reduced Motion Support

Animations are disabled when the user prefers reduced motion:

```javascript
function shouldAnimate() {
  if (typeof window === 'undefined') return false;

  const mediaQuery = window.matchMedia('(prefers-reduced-motion: reduce)');
  return !mediaQuery.matches;
}

function animate(element, animation, duration = 200) {
  if (!shouldAnimate()) {
    element.style.opacity = '1';
    return Promise.resolve();
  }

  return new Promise((resolve) => {
    element.animate(animation, {
      duration,
      easing: 'ease-out',
    }).onfinish = resolve;
  });
}
```
