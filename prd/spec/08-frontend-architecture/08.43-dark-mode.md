# 08.43 - Dark Mode

**Project:** GsmUi
**Section:** 08 - Frontend Architecture
**Framework:** Tailwind CSS v4 · CSS Variables · GsmUi Component Library · Livewire 4
**Version:** 1.0.0

---

> See also: `08.03-design-tokens.md` (token taxonomy), `08.04-theme-architecture.md` (theme layering), `06.30-themes.md` (theme persistence). This document specifies the dark-mode *switching mechanism* only and does NOT re-document token semantics or theme schema.

# Purpose

GsmUi ships a single runtime mode-flip driven entirely by CSS variables (`--gsmui-*`) and the `dark` class on a root element. This document specifies the detection order, the toggle contract, the token-swap mechanics, and the SSR/FOUC-safe bootstrap so that every `gsmui:` component renders correctly in light or dark without per-component branching.

---

## 0. Architecture Overview

The dark mode system is a pure CSS-variable remap driven by a single class toggle on the root element. No component markup changes; only the variable values flip. This ensures:

1. **Zero runtime cost**: CSS handles the mode switch
2. **No flash**: Inline script in `<head>` applies the class before first paint
3. **Consistency**: All components share the same mode state
4. **Extensibility**: Third-party themes can override `--gsmui-*` tokens

### 0.1 Component Hierarchy

```
Dark Mode System
├── Mode Detection (prefers-color-scheme)
├── Mode Persistence (localStorage / server)
├── Mode Toggle (class on <html>)
├── Token Swapping (--gsmui-* CSS variables)
├── FOUC Prevention (inline script)
├── Live Updates (CustomEvent dispatch)
└── Server Sync (Livewire round-trip)
```

```

     │              │                        │
     │              │                        └── Component re-renders
     │              └── MutationObserver triggers

```

## 1. Mode Resolution Order

The active mode is resolved with a strict precedence so user choice always wins over the OS:

```text
1. Persisted user choice  (localStorage / server session, via 06.30-themes)
2. prefers-color-scheme  (media query, no choice yet)
3. Default = light
```

| Source | Priority | Where read |
| --- | --- | --- |
| Server-stored theme | 1 (highest) | `06.30-themes.md` + `wire:model` round-trip |
| `localStorage['gsmui-theme']` | 1 | `dist/gsmui.js` bootstrap |
| `matchMedia('(prefers-color-scheme: dark)')` | 2 | `dist/gsmui.js` bootstrap |
| Light | 3 (fallback) | default when nothing set |

## 2. Toggle Mechanism

GsmUi uses a **class-based** toggle (Tailwind v4 `dark:` variant keyed off a `.dark` ancestor), NOT a `data-attribute` scheme, to stay aligned with Tailwind's default `darkVariant`. The class is applied to `<html>` (or the Livewire root) so descendant `dark:` utilities cascade.

```html
<!-- html element carries the mode -->
<html class="dark"> ... </html>
```

Toggle contract (implemented in `dist/gsmui.js`):

| Step | Action | Tooling |
| --- | --- | --- |
| Read | `matchMedia('(prefers-color-scheme: dark)')` | native, no polyfill |
| Apply | `setAttribute('class', 'dark')` / `removeAttribute('class')` via utils | `setAttribute` from `utils.js` |
| Persist | `localStorage.setItem('gsmui-theme', mode)` | browser only |
| Broadcast | `dispatchEvent(new CustomEvent('gsmui:theme-changed'))` | component re-render hook |

Per `AGENTS.md`, always use the `setAttribute`/`removeAttribute` utilities from `utils.js`, never native DOM methods, because they trigger the MutationObserver that other components watch.

---

## 3. Token Swapping (`--gsmui-*`)

Dark mode is a pure CSS-variable remap. No component markup changes; only the variable values flip. Token definitions live in `08.03-design-tokens.md`; the dark overrides are scoped under `.dark`:

```css
:root {
  --gsmui-bg: #ffffff;
  --gsmui-bg-subtle: #fafafa;
  --gsmui-border: #e4e4e7;        /* zinc-200 */
  --gsmui-text: #18181b;
}

.dark {
  --gsmui-bg: #18181b;
  --gsmui-bg-subtle: #27272a;
  --gsmui-border: rgba(255,255,255,0.10);
  --gsmui-text: #fafafa;
}
```

Components must consume `--gsmui-*` (never hard-coded Tailwind colors for themeable surfaces). Example base tokens consumed by the input pattern:

```html
<input class="bg-white dark:bg-white/10 border-zinc-200 border-b-zinc-300/80
             dark:border-white/10 shadow-xs rounded-lg" />
```

## 4. FOUC / SSR-Safe Bootstrap

To avoid a light→dark flash on first paint, the mode decision runs **before** the framework bundle in an inline, CSP-safe (no `eval`) script in the `<head>`:

```html
<script>
  (function () {
    var m = localStorage.getItem('gsmui-theme');
    if (!m) m = matchMedia('(prefers-color-scheme: dark)').matches ? 'dark' : 'light';
    if (m === 'dark') document.documentElement.classList.add('dark');
  })();
</script>
```

This respects the CSP profile (`script-src 'self'`) because it is a trusted inline primer shipped by the package, not a runtime `eval`.

---

## 5. Livewire Re-Hydration

When Livewire 4 re-renders a `gsmui:` component, the `.dark` class on `<html>` survives (it lives outside the Livewire payload). Components must NOT emit their own mode class; they inherit. Mode is therefore a cross-component constant, not per-component state.

## 6. Open Questions / Risks

- **Server vs client mismatch:** if `06.30-themes.md` stores a server-side choice, the inline primer must read the same key/format as the server. Confirm serialization contract.
- **`prefers-color-scheme` change mid-session:** do we live-update when the OS flips, or lock to first choice? Recommend lock-to-choice after explicit toggle, live-follow before any choice.
- **Tailwind `darkVariant` config:** confirm v4 build emits `.dark` (class) variant, not `prefers-color-scheme`, upstream in `dist/`.

## 8. Mode Detection

### 8.1 Detection Order

The active mode is resolved with a strict precedence:

```
1. Persisted user choice (localStorage / server session)
2. prefers-color-scheme (media query, no choice yet)
3. Default = light
```

### 8.2 Detection Implementation

```javascript
function detectMode() {
  // 1. Check localStorage
  const stored = localStorage.getItem('gsmui-theme');
  if (stored === 'dark' || stored === 'light') {
    return stored;
  }

  // 2. Check prefers-color-scheme
  if (window.matchMedia('(prefers-color-scheme: dark)').matches) {
    return 'dark';
  }

  // 3. Default to light
  return 'light';
}
```

### 8.3 OS Change Detection

```javascript
// Listen for OS theme changes
window.matchMedia('(prefers-color-scheme: dark)').addEventListener('change', (e) => {
  // Only update if user hasn't made an explicit choice
  if (!localStorage.getItem('gsmui-theme')) {
    const mode = e.matches ? 'dark' : 'light';
    applyMode(mode);
  }
});
```

## 9. Mode Toggle

### 9.1 Toggle Implementation

```javascript
function toggleMode() {
  const current = document.documentElement.classList.contains('dark') ? 'dark' : 'light';
  const next = current === 'dark' ? 'light' : 'dark';

  applyMode(next);
  persistMode(next);
  broadcastMode(next);
}
```

### 9.2 Apply Mode

```javascript
function applyMode(mode) {
  if (mode === 'dark') {
    document.documentElement.classList.add('dark');
  } else {
    document.documentElement.classList.remove('dark');
  }
}
```

### 9.3 Persist Mode

```javascript
function persistMode(mode) {
  try {
    localStorage.setItem('gsmui-theme', mode);
  } catch (e) {
    // localStorage unavailable
  }
}
```

### 9.4 Broadcast Mode

```javascript
function broadcastMode(mode) {
  const event = new CustomEvent('gsmui:theme-changed', {
    detail: { mode },
    bubbles: true,
  });
  window.dispatchEvent(event);
}
```

### 11.2 CSP Compliance

The inline script is CSP-safe because:
- It is a trusted primer shipped by the package
- It does not use `eval()`, `Function()`, or `blob:`

- `script-src 'self'` allows inline scripts from the same origin

The script must be in the `<head>` before any CSS:

## 12. Livewire Integration

### 12.1 Server-Side Persistence

When `wire:model` is used, the mode is persisted server-side:

```php
// In Livewire component
public $theme = 'light';

public function updatedTheme($value)
{
    session(['gsmui-theme' => $value]);
}
```

### 12.2 Client-Side Sync

```javascript
// Listen for Livewire updates
Livewire.on('theme-changed', (mode) => {
  applyMode(mode);
  persistMode(mode);
});
```

### 12.3 Round-Trip Flow

```
1. User clicks theme switcher
2. Client applies mode locally
3. Client fires Livewire round-trip
4. Server persists to session/database
5. Server responds with confirmation
6. Client updates localStorage
```

### 24.3 JavaScript Toggle Implementation

```javascript
class DarkMode {
  constructor(options = {}) {
    this.storageKey = options.storageKey || 'gsmui-theme';
    this.className = options.className || 'dark';
    this.respectOS = options.respectOS !== false;
    this.listeners = [];
  }

  init() {
    // Apply stored or detected mode
    const mode = this.detect();
    this.apply(mode);

    // Listen for OS changes
    if (this.respectOS) {
      window.matchMedia('(prefers-color-scheme: dark)')
        .addEventListener('change', (e) => {
          if (!localStorage.getItem(this.storageKey)) {
            this.apply(e.matches ? 'dark' : 'light');
          }
        });
    }

    // Listen for storage changes (other tabs)
    window.addEventListener('storage', (e) => {
      if (e.key === this.storageKey) {
        this.apply(e.newValue || 'light');
      }
    });
  }

  detect() {
    const stored = localStorage.getItem(this.storageKey);
    if (stored === 'dark' || stored === 'light') {
      return stored;
    }

    if (this.respectOS && window.matchMedia('(prefers-color-scheme: dark)').matches) {
      return 'dark';
    }

    return 'light';
  }

  apply(mode) {
    if (mode === 'dark') {
      document.documentElement.classList.add(this.className);
    } else {
      document.documentElement.classList.remove(this.className);
    }

    this.persist(mode);
    this.broadcast(mode);
    this.notifyListeners(mode);
  }

  persist(mode) {
    try {
      localStorage.setItem(this.storageKey, mode);
    } catch (e) {
      // localStorage unavailable
    }
  }

  broadcast(mode) {
    const event = new CustomEvent('gsmui:theme-changed', {
      detail: { mode },
      bubbles: true,
    });
    window.dispatchEvent(event);
  }

  toggle() {
    const current = this.get();
    const next = current === 'dark' ? 'light' : 'dark';
    this.apply(next);
  }

  get() {
    return document.documentElement.classList.contains(this.className) ? 'dark' : 'light';
  }

  set(mode) {
    this.apply(mode);
  }

  onChange(callback) {
    this.listeners.push(callback);
    return () => {
      this.listeners = this.listeners.filter((l) => l !== callback);
    };
  }

  notifyListeners(mode) {
    this.listeners.forEach((callback) => callback(mode));
  }
}

// Initialize
Gsmui.darkMode = new DarkMode();
Gsmui.darkMode.init();
```

- No JavaScript-driven color calculations
- No re-render required (CSS handles it)
- Zero layout thrashing

- It executes in < 1ms
- It does not block rendering
- It uses synchronous localStorage read (fast)

### 26.3 localStorage Cost

- Read/write is < 1ms
- Storage is per-origin, not per-page
- No network requests
- No encryption overhead

### 26.4 Event Dispatch Cost

- CustomEvent is a native browser API
- Dispatching is < 1ms
- Listeners run synchronously
- No async overhead

## 49. Appendix: Dark Mode Best Practices

### 49.1 Design Best Practices

1. **Use appropriate contrast**: Ensure text is readable in both modes
2. **Avoid pure black**: Use dark grays instead of `#000000`
3. **Avoid pure white**: Use light grays instead of `#ffffff` for dark mode backgrounds
4. **Test both modes**: Always test components in both light and dark mode
5. **Use semantic colors**: Use `--gsmui-*` tokens instead of hardcoded colors

### 49.2 Development Best Practices

1. **Use Tailwind utilities**: Prefer `dark:` variants over CSS variables
2. **Test toggle**: Ensure smooth toggle between modes
3. **Test persistence**: Ensure mode persists across page loads
4. **Test FOUC**: Ensure no flash on page load
5. **Test accessibility**: Ensure both modes are accessible

### 49.3 Testing Best Practices

1. **Visual testing**: Take screenshots in both modes
2. **Automated testing**: Use Playwright to test toggle
3. **Accessibility testing**: Use axe-core to test contrast
4. **Performance testing**: Measure toggle time
5. **Cross-browser testing**: Test in all target browsers
