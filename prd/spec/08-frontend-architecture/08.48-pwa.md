# 08.48 - PWA

**Project:** GsmUi
**Section:** 08 - Frontend Architecture
**Framework:** Laravel 13 · Vite · Service Worker · GsmUi Component Library
**Version:** 1.0.0

---

> See also: `08.55-frontend-security.md` (CSP directives for workers), `08.46-performance.md` (bundle delivery). This document specifies the *progressive-web-app* layer (installability, offline, manifest) and does NOT re-document the component runtime.

# Purpose

GsmUi can be installed and used offline as a PWA. Because the CSP forbids external resources, the service worker, manifest, and cached assets must all be **same-origin, self-hosted, and eval-free**. This document pins the manifest schema, the worker scope, caching policy, and the CSP additions required when workers are introduced.

This document covers every PWA concern in GsmUi: the Web App Manifest schema in detail, service worker lifecycle and caching strategies, offline behavior for Blade and Livewire pages, push notification architecture (if applicable), background sync, app update flow, CSP compliance for all worker-related features, installability prompts, and the testing gates that verify PWA correctness.

## 2. Service Worker

| Property | Value |
| --- | --- |
| Scope | `/` (same-origin only) |
| Registration | `navigator.serviceWorker.register('/sw.js')` |
| Strategy | Cache-first for `dist/*`, network-first for HTML |
| Executable | Plain JS, no `eval()`/`Function()`/`blob:` (CSP-safe) |

The worker is registered from `dist/gsmui.js` after load, never inline-eval'd.

### 2.1 Service Worker File Structure

The service worker is a standalone file at `public/sw.js`:

```javascript
// public/sw.js — CSP-safe, no eval/Function/blob

const CACHE_NAME = 'gsmui-v1';
const STATIC_CACHE = 'gsmui-static-v1';
const DYNAMIC_CACHE = 'gsmui-dynamic-v1';

const STATIC_ASSETS = [
  '/',
  '/manifest.webmanifest',
  '/dist/gsmui.css',
  '/dist/gsmui.js',
  '/icons/icon-192.png',
  '/icons/icon-512.png',
];

// Install: pre-cache static assets
self.addEventListener('install', function(event) {
  event.waitUntil(
    caches.open(STATIC_CACHE).then(function(cache) {
      return cache.addAll(STATIC_ASSETS);
    })
  );
  self.skipWaiting();
});

// Activate: clean up old caches
self.addEventListener('activate', function(event) {
  event.waitUntil(
    caches.keys().then(function(keys) {
      return Promise.all(
        keys.filter(function(key) {
          return key !== STATIC_CACHE && key !== DYNAMIC_CACHE;
        }).map(function(key) {
          return caches.delete(key);
        })
      );
    })
  );
  self.clients.claim();
});

// Fetch: routing strategies
self.addEventListener('fetch', function(event) {
  var url = new URL(event.request.url);

  // Only handle same-origin requests
  if (url.origin !== location.origin) {
    return;
  }

  // Static assets: cache-first
  if (isStaticAsset(url.pathname)) {
    event.respondWith(cacheFirst(event.request));
    return;
  }

  // HTML pages: network-first
  if (event.request.headers.get('accept').includes('text/html')) {
    event.respondWith(networkFirst(event.request));
    return;
  }

  // Everything else: stale-while-revalidate
  event.respondWith(staleWhileRevalidate(event.request));
});

function isStaticAsset(pathname) {
  return pathname.startsWith('/dist/') ||
         pathname.startsWith('/icons/') ||
         pathname.endsWith('.css') ||
         pathname.endsWith('.js') ||
         pathname.endsWith('.woff2');
}

function cacheFirst(request) {
  return caches.match(request).then(function(cached) {
    if (cached) return cached;
    return fetch(request).then(function(response) {
      return caches.open(STATIC_CACHE).then(function(cache) {
        cache.put(request, response.clone());
        return response;
      });
    });
  });
}

function networkFirst(request) {
  return fetch(request).then(function(response) {
    return caches.open(DYNAMIC_CACHE).then(function(cache) {
      cache.put(request, response.clone());
      return response;
    });
  }).catch(function() {
    return caches.match(request).then(function(cached) {
      return cached || caches.match('/offline.html');
    });
  });
}

function staleWhileRevalidate(request) {
  return caches.match(request).then(function(cached) {
    var fetchPromise = fetch(request).then(function(response) {
      return caches.open(DYNAMIC_CACHE).then(function(cache) {
        cache.put(request, response.clone());
        return response;
      });
    });
    return cached || fetchPromise;
  });
}
```

### 2.2 Service Worker Lifecycle

```
    ┌─────────────┐
    │  Register   │
    │  (gsmui.js) │
    └──────┬──────┘
           │
           ▼
    ┌─────────────┐
    │  Installing │ ← pre-cache STATIC_ASSETS
    │  (install)  │    skipWaiting()
    └──────┬──────┘
           │
           ▼
    ┌─────────────┐
    │  Activating │ ← clean old caches
    │  (activate) │    clients.claim()
    └──────┬──────┘
           │
           ▼
    ┌─────────────┐
    │   Active    │ ← intercepts fetch events
    │  (fetch)    │    routing strategies
    └─────────────┘
```

### 2.3 Registration Code

The service worker is registered from `dist/gsmui.js` after the page loads:

```javascript
// In dist/gsmui.js — registration after DOM ready
if ('serviceWorker' in navigator) {
  window.addEventListener('load', function() {
    navigator.serviceWorker.register('/sw.js', { scope: '/' })
      .then(function(registration) {
        console.log('SW registered:', registration.scope);
      })
      .catch(function(error) {
        console.log('SW registration failed:', error);
      });
  });
}
```

Key constraints:
- Registration happens after `load` event (non-blocking)
- No `eval()` or dynamic code — CSP-safe
- Scope is limited to same-origin `/`
- Registration failure is logged but not fatal (graceful degradation)

### 2.4 Caching Strategies

| Asset Type | Strategy | Rationale |
| --- | --- | --- |
| `dist/*.js`, `dist/*.css` | Cache-first | Hashed filenames, safe to cache aggressively |
| HTML pages | Network-first | Content should be fresh, fall back to cache offline |
| API responses | Network-first | Data must be current, cache for offline fallback |
| Images | Stale-while-revalidate | Show cached version immediately, update in background |
| Fonts | Cache-first | System fonts only, already local |
| Manifest | Cache-first | Rarely changes |

### 2.5 Cache Naming Convention

Caches use a versioned naming scheme:

```javascript
const CACHE_VERSION = 'v1';
const STATIC_CACHE = `gsmui-static-${CACHE_VERSION}`;
const DYNAMIC_CACHE = `gsmui-dynamic-${CACHE_VERSION}`;
const OFFLINE_CACHE = `gsmui-offline-${CACHE_VERSION}`;
```

When the version changes (during deployment), old caches are cleaned up in the `activate` handler.

### 2.6 Cache Size Limits

To prevent excessive storage usage:

```javascript
function trimCache(cacheName, maxItems) {
  return caches.open(cacheName).then(function(cache) {
    return cache.keys().then(function(keys) {
      if (keys.length > maxItems) {
        return cache.delete(keys[0]).then(function() {
          return trimCache(cacheName, maxItems);
        });
      }
    });
  });
}

// In activate handler, trim caches
self.addEventListener('activate', function(event) {
  event.waitUntil(
    Promise.all([
      trimCache(STATIC_CACHE, 100),
      trimCache(DYNAMIC_CACHE, 50),
    ])
  );
});
```

## 3. CSP Additions for Workers

Per `AGENTS.md`, adding a Service Worker requires extending the CSP config in `stubs/config/gsmui-pro-csp.php`:

```php
// gsmui-pro-csp.php
'worker-src' => "'self'",
'child-src'  => "'self'",
```

Without these, the worker is blocked. The base profile (`script-src 'self'`, `style-src 'self' 'unsafe-inline'`, `img-src 'self' data:`, `connect-src 'self'`) remains otherwise intact.

### 3.1 Complete CSP Config for PWA

```php
// stubs/config/gsmui-pro-csp.php
return [
    'script-src' => "'self'",
    'style-src' => "'self' 'unsafe-inline'",
    'img-src' => "'self' data:",
    'font-src' => "'self'",
    'connect-src' => "'self'",
    'worker-src' => "'self'",
    'child-src' => "'self'",
    'frame-src' => "'self'",
    'object-src' => "'none'",
    'base-uri' => "'self'",
    'form-action' => "'self'",
    'frame-ancestors' => "'self'",
    'upgrade-insecure-requests' => true,
];
```

### 3.2 CSP Validation for PWA

The Playwright CSP test verifies worker-related directives:

```javascript
// tests/Browser/pwa/csp-worker.spec.js
test('CSP allows service worker registration', async ({ page }) => {
  await page.goto('/');
  const csp = await page.evaluate(() => {
    return document.querySelector('meta[http-equiv="Content-Security-Policy"]')
      ?.content || '';
  });

  expect(csp).toContain("child-src 'self'");

```

### 3.3 Forbidden Worker Patterns

These patterns are forbidden under the GsmUi CSP:

| Pattern | Why Forbidden | Alternative |
| --- | --- | --- |
| `importScripts('https://...')` | External script load | Self-host all dependencies |
| `new Worker('blob:...')` | Blob URL worker | Use `/sw.js` file |
| `new SharedWorker('...')` | Requires `worker-src blob:` or URL | Use dedicated worker |
| `eval()` in worker | Requires `unsafe-eval` | Write plain JS |
| `Function()` constructor | Requires `unsafe-eval` | Write plain JS |
| Web Workers from CDN | External script | Bundle in `dist/` |

### 4.2 Offline Page Strategy

```javascript
// In service worker: network-first for HTML, offline fallback
function networkFirst(request) {
  return fetch(request).then(function(response) {
    // Cache successful responses
    if (response.status === 200) {
      return caches.open(DYNAMIC_CACHE).then(function(cache) {
        cache.put(request, response.clone());
        return response;
      });
    }
    return response;
  }).catch(function() {
    // Return cached version or offline shell
    return caches.match(request).then(function(cached) {
      return cached || caches.match('/offline.html');
    });
  });
}
```

## 5. Installability Checklist

- Valid manifest with `name` + `icons` (≥192px) + `start_url`.
- Served over HTTPS (`script-src 'self'` implies secure context).
- Registered service worker with a fetch handler.
- No blocked resources in the CSP (no external CDN).

### 5.1 Chrome Install Criteria

Chrome requires:

1. Valid `manifest.webmanifest` with `name`, `icons` (192px+), `start_url`
2. Served over HTTPS
3. Registered service worker with a `fetch` event handler
4. User engagement signal (visits, time on site)

### 5.2 Firefox Install Criteria

Firefox requires:

1. Valid manifest
2. HTTPS
3. Service worker registered
4. `icons` array with appropriate sizes

### 5.3 Safari Install Criteria

Safari (iOS) requires:

1. Valid manifest
2. HTTPS
3. Service worker (or web app meta tags as fallback)
4. `apple-touch-icon` link tags for iOS home screen

```html
<!-- iOS-specific meta tags -->
<link rel="apple-touch-icon" href="/icons/icon-180.png">

<meta name="apple-mobile-web-app-status-bar-style" content="black-translucent">
```

### 5.4 Edge Install Criteria

Edge follows Chrome's criteria (Chromium-based).

### 5.5 Install Prompt Handling

GsmUi handles the `beforeinstallprompt` event to show a custom install button:

```javascript
// In dist/gsmui.js
var deferredPrompt = null;

window.addEventListener('beforeinstallprompt', function(e) {
  e.preventDefault();
  deferredPrompt = e;
  showInstallButton();
});

function showInstallButton() {
  var buttons = document.querySelectorAll('[data-pwa-install]');
  buttons.forEach(function(btn) {
    btn.style.display = '';
    btn.addEventListener('click', function() {
      if (deferredPrompt) {
        deferredPrompt.prompt();
        deferredPrompt.userChoice.then(function(choice) {
          if (choice.outcome === 'accepted') {
            hideInstallButton();
          }
          deferredPrompt = null;
        });
      }
    });
  });
}

function hideInstallButton() {
  var buttons = document.querySelectorAll('[data-pwa-install]');
  buttons.forEach(function(btn) {
    btn.style.display = 'none';
  });
}
```

## 6. App Update Flow

### 6.1 Detecting Updates

When a new service worker is deployed, the browser detects the changed file and triggers the update flow:

```javascript
// In dist/gsmui.js
if ('serviceWorker' in navigator) {
  navigator.serviceWorker.register('/sw.js').then(function(registration) {
    // Check for updates every 60 minutes
    setInterval(function() {
      registration.update();
    }, 60 * 60 * 1000);

    registration.addEventListener('updatefound', function() {
      var newWorker = registration.installing;
      newWorker.addEventListener('statechange', function() {
        if (newWorker.state === 'activated') {
          showUpdateNotification();
        }
      });
    });
  });
}
```

```javascript
        Refresh
      </button>
    </div>
  `;
  document.body.appendChild(notification);

```

### 6.3 Skip Waiting

The new service worker calls `skipWaiting()` to activate immediately:

```javascript
// In new sw.js
self.addEventListener('install', function(event) {
  event.waitUntil(
    caches.open(STATIC_CACHE).then(function(cache) {
      return cache.addAll(STATIC_ASSETS);
    })
  );
  self.skipWaiting(); // Activate immediately
});

self.addEventListener('activate', function(event) {
  event.waitUntil(
    // Clean old caches and claim all clients
    Promise.all([
      caches.keys().then(function(keys) {
        return Promise.all(
          keys.filter(function(key) {
            return key !== STATIC_CACHE && key !== DYNAMIC_CACHE;
          }).map(function(key) {
            return caches.delete(key);
          })
        );
      }),
      self.clients.claim(), // Take control of all pages
    ])
  );
});
```

### 6.4 Versioned Caches

Cache names include the version number to prevent conflicts:

```javascript
// Cache version is updated in the build process
const CACHE_VERSION = 'v2'; // Changed on each deploy
const STATIC_CACHE = `gsmui-static-${CACHE_VERSION}`;
const DYNAMIC_CACHE = `gsmui-dynamic-${CACHE_VERSION}`;
```

## 8. Background Sync (Future Consideration)

Background sync allows queuing actions while offline and sending them when connectivity returns:

### 8.1 Use Cases

| Action | Offline Behavior | Sync Behavior |
| --- | --- | --- |
| Form submission | Queue locally | Submit on reconnect |
| Comment posting | Queue locally | Post on reconnect |
| Analytics events | Queue locally | Send batch on reconnect |
| Theme preference | Save locally | Sync on reconnect |

### 8.2 Background Sync CSP

```php
// If background sync is added
'worker-src' => "'self'",
'sync-xhr' => "'self'",
```

### 8.3 Implementation Pattern

```javascript
// In service worker
self.addEventListener('sync', function(event) {
  if (event.tag === 'gsmui-sync') {
    event.waitUntil(syncPendingData());
  }
});

function syncPendingData() {
  return getAllFromIndexedDB('pending-actions').then(function(actions) {
    return Promise.all(actions.map(function(action) {
      return fetch(action.url, {
        method: action.method,
        headers: action.headers,
        body: action.body,
      }).then(function() {
        return removeFromIndexedDB('pending-actions', action.id);
      });
    }));
  });
}
```

### 8.4 Background Sync Constraints

- Only works for same-origin requests (`connect-src 'self'`)
- IndexedDB must be self-hosted (no external database)
- Sync events are browser-initiated, not user-initiated
- Browser may delay sync events based on connectivity and battery

**Decision:** Background sync is punted for the initial release.

## 9. PWA Performance Considerations

### 9.1 Service Worker Registration Cost

Service worker registration is lightweight but not free:

- Registration: ~1ms
- Install event: depends on cache size
- Activation: ~1ms (cache cleanup)
- Fetch interception: ~0.1ms per request

### 9.2 Cache Storage Limits

Browser cache storage limits vary:

| Browser | Default Limit | Max |
| --- | --- | --- |
| Chrome | 300MB per origin | No hard limit |
| Firefox | 50MB per origin | No hard limit |
| Safari | 50MB per origin | No hard limit |
| Edge | 300MB per origin | No hard limit |

GsmUi's cache budget:

| Cache | Expected Size | Budget |
| --- | --- | --- |
| Static (dist/) | ~500KB | Cache-first, aggressive |
| Dynamic (HTML) | ~2MB | Network-first, limited |
| Offline shell | ~5KB | Always cached |
| **Total** | **~2.5MB** | Well under limits |

### 9.3 Pre-cache Strategy

The install event pre-caches only critical assets:

```javascript
const CRITICAL_ASSETS = [
  '/',
  '/offline.html',
  '/manifest.webmanifest',
  '/dist/gsmui.css',
  '/dist/gsmui.js',
  '/icons/icon-192.png',
  '/icons/icon-512.png',
];
```

Non-critical assets (blog posts, docs pages) are cached on first visit (network-first strategy).

### 9.4 Bundle Size Impact

The service worker file itself adds ~2KB to the page weight (uncompressed). It is loaded asynchronously after the page renders, so it does not block first paint.

## 10. PWA and Livewire Interaction

### 10.1 Livewire Round-Trips Require Connectivity

Livewire components make `fetch` requests to the server for every interaction. When offline:

- Livewire components become non-functional
- The offline shell replaces the page
- Cached versions of the page are shown (if available)

### 10.2 Livewire Caching Strategy

```javascript
// In service worker: don't cache Livewire responses
function isLivewireRequest(request) {
  return request.headers.get('X-Livewire') === 'true' ||
         request.url.includes('/livewire/message/');
}

self.addEventListener('fetch', function(event) {
  if (isLivewireRequest(event.request)) {
    // Don't cache Livewire responses — always go to network
    event.respondWith(fetch(event.request));
    return;
  }
  // ... other strategies
});
```

### 10.3 Livewire Offline Detection

```javascript
// In dist/gsmui.js: detect offline state for Livewire
window.addEventListener('offline', function() {
  // Add offline class to Livewire containers
  document.querySelectorAll('[wire\\:id]').forEach(function(el) {
    el.setAttribute('data-offline', 'true');
  });
});

window.addEventListener('online', function() {
  // Remove offline class
  document.querySelectorAll('[wire\\:id]').forEach(function(el) {
    el.removeAttribute('data-offline');
  });
  // Reload Livewire components
  if (window.Livewire) {
    Livewire.all().forEach(function(component) {
      component.$wire.refresh();
    });
  }
});
```

## 16. Open Questions / Risks

- **Livewire + offline:** offline HTML shell cannot run Livewire round-trips without connectivity — document which routes are PWA-usable offline vs online-only.
- **Editor offline:** `editor.js` (Monaco) is large; confirm it is cached independently so install size stays reasonable.
- **CSP drift:** any new worker must update `stubs/config/gsmui-pro-csp.php` AND the published copy; add a test (see `08.49-testing.md` CSP tests).
- **Push notifications:** deferred to a future release — requires first-party push server.
- **Background sync:** deferred to a future release — requires IndexedDB schema and sync logic.
- **iOS limitations:** Safari has limited PWA support (no push, no background sync, restricted cache) — document known limitations.
- **Cache eviction:** browsers may evict caches under storage pressure — the offline shell must handle missing cache entries gracefully.
- **Service worker scope:** the worker can only control pages in its scope (`/`) — admin routes behind auth may not be controllable.
- **HTTPS requirement:** service workers require HTTPS in production — ensure the deployment environment supports this.

## Appendix G: PWA Security Considerations

### G.1 Service Worker Security

Service workers have significant power — they can intercept all network requests. GsmUi mitigates this:

1. **Same-origin only:** the worker scope is limited to `/`
2. **No external scripts:** `worker-src 'self'` prevents loading external code
3. **No `eval()`:** CSP prevents dynamic code execution in the worker
4. **Self-hosted assets:** no external resources are cached
5. **No sensitive data caching:** auth tokens and session data are not cached

### G.2 Cache Security

Cached data is stored in the browser's cache storage API:

- Cache storage is origin-scoped — other origins cannot access GsmUi's caches
- Cache storage is cleared when the user clears browser data
- Sensitive data (auth tokens, personal info) is NOT cached
- Only public, non-sensitive assets are cached

### G.3 Offline Data Security

If offline data storage is added (IndexedDB):

- Encrypt sensitive data before storing
- Clear stored data on logout
- Set expiration timestamps on cached data
- Never store passwords or auth tokens

### G.4 Service Worker Update Security

Service worker updates are validated:

1. The new worker file is fetched from the same origin (HTTPS)
2. The browser verifies the script is valid JavaScript
3. The browser runs the install event in a new worker
4. Only after successful install does the new worker activate
5. The old worker continues serving requests until the new one activates

## Appendix I: PWA Content Strategy

### I.1 What to Cache First

Priority order for caching:

1. **Critical (install time):** `/`, `/offline.html`, `manifest.webmanifest`, `dist/gsmui.js`, `dist/gsmui.css`
2. **High (first visit):** Component docs pages, template pages
3. **Medium (subsequent visits):** Blog posts, docs sections
4. **Low (never pre-cache):** Admin pages, playground, search

### I.2 Cache Eviction Strategy

When cache storage is under pressure:

1. Evict low-priority caches first (blog posts)
2. Evict medium-priority caches next (docs pages)
3. Never evict critical caches (offline shell, dist/ assets)
4. Log eviction events for monitoring

### I.3 Offline Content Freshness

Cached content should be refreshed periodically:

```javascript
// In service worker: refresh caches on activation
self.addEventListener('activate', function(event) {
  event.waitUntil(
    caches.keys().then(function(keys) {
      return Promise.all(
        keys.map(function(key) {
          if (key.startsWith('gsmui-dynamic-')) {
            // Dynamic caches are refreshed on each network-first fetch
            return Promise.resolve();
          }
          // Static caches are versioned and replaced on deploy
          return Promise.resolve();
        })
      );
    })
  );
});
```

## Appendix L: PWA and Third-Party Libraries

### L.1 Monaco Editor Offline

The Monaco editor (`editor.js`) is large (~2MB). For PWA:

```javascript
// Cache Monaco separately
const MONACO_CACHE = 'gsmui-monaco-v1';

self.addEventListener('fetch', function(event) {
  if (event.request.url.includes('editor.js') || event.request.url.includes('editor.css')) {
    event.respondWith(
      caches.open(MONACO_CACHE).then(function(cache) {
        return cache.match(event.request).then(function(cached) {
          return cached || fetch(event.request).then(function(response) {
            cache.put(event.request, response.clone());
            return response;
          });
        });
      })
    );
    return;
  }
});
```

## Appendix M: PWA Summary

The GsmUi PWA architecture provides installability and offline support while maintaining strict CSP compliance. All assets are self-hosted, no external resources are loaded, and the service worker uses plain JavaScript without `eval()` or `Function()`. The manifest, icons, and offline shell are generated at build time and deployed alongside the main application. The caching strategy is conservative — static assets use cache-first, HTML pages use network-first with offline fallback, and Livewire interactions require connectivity. The PWA is tested with Playwright across installability criteria, manifest validation, service worker lifecycle, offline behavior, and CSP compliance. This ensures GsmUi users can install the application on any device and access cached content when offline, while maintaining the security guarantees of the strict Content Security Policy.

### M.1 Key Takeaways

1. The manifest is self-hosted with no external icon CDNs
2. The service worker uses only same-origin, eval-free JavaScript
3. CSP is extended with `worker-src 'self'` and `child-src 'self'`
4. Static assets are cached aggressively (cache-first)
5. HTML pages use network-first with offline fallback
6. Livewire interactions require connectivity (no offline)
7. Push notifications and background sync are deferred
8. All PWA features are tested with Playwright
9. Safari limitations are documented and gracefully handled
10. Cache versions are bumped on each deployment
