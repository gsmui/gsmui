# 08.03 - Design Tokens

**Project:** GsmUi
**Section:** 08 - Frontend Architecture
**Framework:** Design Token Engine · CSS Variables · Tailwind CSS v4
**Version:** 1.0.0

---

> See also: `05.16-theme-engine.md` (token generation engine), `06.31-theme-tokens.md` (token schema), `08.02-design-system.md` (taxonomy). This document specifies the *token taxonomy and `--gsmui-*` variable contract* and does NOT re-document the token schema that lives in 06.

# Purpose

This document defines how GsmUi tokens are named, structured, and exposed as CSS custom properties so every component and page reads a single source of truth. It establishes the `--gsmui-*` naming scheme, the token engine's role, and the Tailwind v4 fallback strategy that keeps utilities working when a token is absent.

---

## 1. Token Taxonomy

Tokens are grouped by visual dimension. Each group maps to a `--gsmui-<group>-*` variable namespace.

| Group | Example Tokens | Drives |
| --- | --- | --- |
| Color | `--gsmui-color-accent`, `--gsmui-color-bg`, `--gsmui-color-border` | Text, surfaces, focus rings |
| Spacing | `--gsmui-space-1 … --gsmui-space-12` | Padding, gaps, layout rhythm |
| Typography | `--gsmui-font-sans`, `--gsmui-text-sm`, `--gsmui-text-base` | Font family, sizes, line-height |
| Radius | `--gsmui-radius-sm`, `--gsmui-radius-md`, `--gsmui-radius-lg` | `rounded-*` equivalents |
| Shadow | `--gsmui-shadow-xs`, `--gsmui-shadow-sm`, `--gsmui-shadow-xl` | Elevation, popovers |
| Z-index | `--gsmui-z-popover`, `--gsmui-z-modal`, `--gsmui-z-toast` | Stacking order |

---

## 2. Naming Rules

- All token variables are prefixed `--gsmui-` (the upstream fork's prefix is never used).
- Group first, semantic name second: `--gsmui-color-accent` not `--accent-color`.
- Scale tokens use numeric steps (`-1 … -12`) for spacing; named steps (`xs/sm/base/lg/xl`) for type and shadow.
- Semantic aliases (`--gsmui-color-danger`) sit above raw palette tokens; components reference semantic names only.

---

## 3. Token Engine

The Design Token Engine (defined in `05.16-theme-engine.md`, persisted per `06.31-theme-tokens.md`) produces the runtime value set. Its frontend contract:

| Stage | Output | Consumer |
| --- | --- | --- |
| Authoring | Token definitions (JSON/DB) | Theme builder (`08.04-theme-architecture.md`) |
| Compile | Resolved `--gsmui-*` values | CSS layer (`08.06-css-architecture.md`) |
| Runtime apply | `:root` custom properties or `adoptedStyleSheets` | All `gsmui:` components |

```php
// Conceptual: component reads a token via the Gsmui facade, not a hard-coded value
Gsmui::classes('bg-white dark:bg-white/10 border-zinc-200 dark:border-white/10');
```

Tokens are consumed through Tailwind utilities that reference the CSS variables, never as literal hex inside component Blade.

---

## 4. Tailwind v4 Fallback

Tailwind v4 maps tokens into utilities via `@theme` (see `08.05-tailwind-v4.md`). The fallback rule:

- When a token is defined, the utility resolves to `--gsmui-*`.
- When a token is absent (e.g. during theme build), utilities degrade to Tailwind's default scale rather than breaking the build.
- Hard-coded literal colors (e.g. `zinc-200`, `white`) are permitted only as *structural* fallbacks in component Blade — they must be layered, not swapped.

| Case | Resolution |
| --- | --- |
| `--gsmui-color-accent` present | `text-(--gsmui-color-accent)` |
| `--gsmui-color-accent` missing | Falls back to Tailwind default token scale |
| Structural neutral (e.g. `white`) | Allowed as base layer, token overrides at runtime |

---

## 5. Dark Mode Tokens

Dark variants use the `dark:` prefix resolved against `:root.dark` or a `[data-theme="dark"]` scope. Token pairs are emitted together:

```css
:root { --gsmui-color-bg: #ffffff; --gsmui-color-surface: #f4f4f5; }
[data-theme="dark"] { --gsmui-color-bg: #18181b; --gsmui-color-surface: #27272a; }
```

The strategy is documented fully in `08.43-dark-mode.md` and `08.06-css-architecture.md`.

---

## 6. Open Questions / Risks

- **Dynamic vs static emission:** Decide whether token values are inlined into a compiled CSS file or pushed at runtime via `adoptedStyleSheets` for live theme preview.
- **Token collision:** Ensure the `--gsmui-` namespace never collides with consumer app variables; document the prefix as reserved.

## 8. Token Resolution Order

When a token is referenced, the resolution follows this order:

### 8.1 Resolution Chain

```text
1. Component Blade: Gsmui::classes('bg-accent')
         │
         ▼
2. Tailwind utility: bg-accent → @theme mapping
         │
         ▼
3. CSS variable: var(--gsmui-color-accent)
         │
         ▼
4. :root declaration: #2563eb (light) or #3b82f6 (dark)
```

### 8.2 Fallback Behavior

| Scenario | Resolution | Result |
| --- | --- | --- |
| Token defined, dark defined | Full resolution | Correct value for mode |
| Token defined, dark missing | Light value in dark mode | May look wrong |
| Token missing, Tailwind default exists | Tailwind default | Works but not themed |
| Token missing, no Tailwind default | CSS invalid value | Fallback to inherited |

### 8.3 Override Precedence

| Priority | Source | Example |
| --- | --- | --- |
| 1 (highest) | Inline style | `style="--gsmui-color-accent: red"` |
| 2 | `adoptedStyleSheets` (runtime) | Theme builder live preview |
| 3 | `:root` in compiled CSS | Default theme values |
| 4 | Tailwind default scale | `bg-blue-600` fallback |
| 5 (lowest) | Browser default | `color: initial` |

## 9. Token Composition

Tokens can reference other tokens, creating a composition hierarchy.

### 9.1 Composition Layers

```text
Raw palette tokens (zinc-100, blue-600, etc.)
    │
    ▼
Semantic tokens (--gsmui-color-bg, --gsmui-color-accent, etc.)
    │
    ▼
Component tokens (--gsmui-input-bg, --gsmui-button-bg, etc.)
    │
    ▼
Utility classes (bg-accent, text-text, etc.)
```

### 9.2 Semantic Token Composition

```css
:root {
  /* Raw palette */
  --gsmui-palette-blue-500: #3b82f6;
  --gsmui-palette-blue-600: #2563eb;
  --gsmui-palette-zinc-100: #f4f4f5;
  --gsmui-palette-zinc-900: #18181b;

  /* Semantic tokens reference palette */
  --gsmui-color-accent: var(--gsmui-palette-blue-600);
  --gsmui-color-bg: var(--gsmui-palette-white);
  --gsmui-color-text: var(--gsmui-palette-zinc-900);

  /* Component tokens reference semantic tokens */
  --gsmui-button-bg: var(--gsmui-color-accent);
  --gsmui-input-bg: var(--gsmui-color-bg);
}
```

### 9.3 Token Composition Rules

| Rule | Implementation |
| --- | --- |
| Reference, don't duplicate | `--gsmui-color-accent: var(--gsmui-palette-blue-600)` |
| Max 2 levels of indirection | Palette → Semantic → Component |
| No circular references | Token A cannot reference Token B which references Token A |
| Semantic before component | Define `--gsmui-color-*` before `--gsmui-button-*` |

## 10. Token Testing

### 10.1 Visual Regression Tests

Every token value is verified with Playwright screenshots:

```js
test("accent color renders correctly", async ({ page }) => {
  await page.goto("/test/tokens");
  const accent = page.locator("[data-token-accent]");
  await expect(accent).toHaveCSS("color", "rgb(37, 99, 235)");
});
```

### 10.2 Contrast Ratio Tests

All text/background token pairs are tested for WCAG contrast:

```js
test("text on background meets contrast ratio", async ({ page }) => {
  await page.goto("/test/tokens");
  const ratio = await page.evaluate(() => {
    const text = getComputedStyle(document.documentElement)
      .getPropertyValue('--gsmui-color-text');
    const bg = getComputedStyle(document.documentElement)
      .getPropertyValue('--gsmui-color-bg');
    return getContrastRatio(text, bg);
  });
  expect(ratio).toBeGreaterThanOrEqual(4.5);
});
```

### 10.3 Dark Mode Token Tests

```js
test("dark mode tokens flip correctly", async ({ page }) => {
  await page.goto("/test/tokens");
  await page.evaluate(() => {
    document.documentElement.setAttribute("data-theme", "dark");
  });
  const bg = await page.evaluate(() => {
    return getComputedStyle(document.documentElement)
      .getPropertyValue('--gsmui-color-bg');
  });
  expect(bg).toBe("#18181b");
});
```

## 13. Token Engine Architecture

### 13.1 Engine Components

| Component | Responsibility | Location |
| --- | --- | --- |
| Token Parser | Reads token definitions from JSON/DB | `05.16-theme-engine.md` |
| Token Resolver | Resolves references and aliases | Token Engine |
| Token Compiler | Produces CSS custom properties | Token Engine |
| Token Injector | Applies tokens to DOM | `08.06-css-architecture.md` |
| Token Observer | Watches for token changes | MutationObserver |

### 13.2 Engine Pipeline

```text
Token Definitions (JSON/DB)
    │
    ▼
Token Parser ──▶ Token Resolver ──▶ Token Compiler
    │                                    │
    │                                    ▼
    │                              CSS Output
    │                              (:root { --gsmui-*: ... })
    │                                    │
    │                                    ▼
    │                              Token Injector
    │                              (adoptedStyleSheets or <style>)
    │                                    │
    │                                    ▼
    │                              DOM Application
    │                              (components read --gsmui-*)
    │
    └──▶ Token Observer
         (watches for builder changes)
```

### 13.3 Engine Performance

| Metric | Target | Implementation |
| --- | --- | --- |
| Parse time | < 10ms | Efficient JSON parsing |
| Resolve time | < 5ms | Flat reference graph |
| Compile time | < 10ms | String concatenation |
| Inject time | < 5ms | Single `adoptedStyleSheets` update |
| Total pipeline | < 30ms | Optimized for live preview |

## 14. Token Security

### 14.1 Token Injection Prevention

Tokens are never directly interpolated into CSS without sanitization:

```php
// Safe: token values are validated
$value = TokenEngine::resolve('color-accent');
$validated = TokenValidator::color($value); // Returns safe value or default
```

### 14.2 Token Scope

## 21. Token Composition Deep Dive

### 21.1 Reference Chain Rules

Token references form a directed acyclic graph (DAG). The rules for safe composition:

| Rule | Valid Example | Invalid Example |
| --- | --- | --- |
| Reference, don't duplicate | `--gsmui-color-accent: var(--gsmui-palette-blue-600)` | `--gsmui-color-accent: #2563eb` |
| Max 2 levels of indirection | Palette → Semantic → Component | Palette → Semantic → Component → Sub-component |
| No circular references | A → B → C (no C → A) | A → B → A |
| Semantic before component | Define `--gsmui-color-*` before `--gsmui-button-*` | Component before semantic |
| Define before use | Token defined before referenced | Referenced before defined |

### 21.2 Reference Chain Depth

| Depth | Pattern | Example |
| --- | --- | --- |
| Level 0 | Raw value | `#2563eb` |
| Level 1 | Reference to raw | `var(--gsmui-palette-blue-600)` |
| Level 2 | Reference to reference | `var(--gsmui-color-accent)` → `var(--gsmui-palette-blue-600)` |
| Level 3+ | NOT ALLOWED | Too deep, maintainability risk |

### 21.3 Reference Validation

```php
function validateTokenReferences($tokens) {
    $visited = [];
    $errors = [];

    foreach ($tokens as $name => $value) {
        if (str_contains($value, 'var(--')) {
            $ref = extractReference($value);
            if (in_array($ref, $visited)) {
                $errors[] = "Circular reference: $name → $ref";
            }
            $visited[] = $ref;
        }
    }

    return $errors;
}
```

### 23.4 Token Sanitization

```php
function sanitizeTokenName($name) {
    // Remove any characters that aren't alphanumeric, hyphens, or underscores
    return preg_replace('/[^a-z0-9\-_]/', '', strtolower($name));
}

function sanitizeTokenValue($value) {
    // Remove any characters that could be used for CSS injection
    return preg_replace('/[;{}]/', '', $value);
}

## 34. Token System Architecture Deep Dive

### 34.1 Token Resolution Pipeline

The token resolution pipeline transforms abstract token definitions into concrete CSS values that browsers can render. This pipeline is the backbone of the GsmUi theming system.

```text
Token Definition (JSON/DB)
       │
       ▼
┌─────────────────────────────────────────────────┐
│              Token Resolution Pipeline           │
├─────────────────────────────────────────────────┤
│                                                  │
│  1. Parse                                         │
│     └─ Read token definitions from source        │
│     └─ Validate structure and syntax             │
│     └─ Output: Raw token map                     │
│                                                  │
│  2. Resolve References                            │
│     └─ Follow var() reference chains             │
│     └─ Detect circular references                │
│     └─ Output: Flat token map (no references)    │
│                                                  │
│  3. Validate Values                               │
│     └─ Check color formats (hex, rgb, hsl)       │
│     └─ Check length formats (px, rem, em)        │
│     └─ Output: Validated token map               │
│                                                  │
│  4. Generate CSS                                  │
│     └─ Create :root declarations                  │
│     └─ Create dark mode overrides                 │
│     └─ Output: CSS string                        │
│                                                  │
│  5. Inject into DOM                               │
│     └─ Create/update CSSStyleSheet                │
│     └─ Apply via adoptedStyleSheets               │
│     └─ Output: DOM update                        │
│                                                  │
└─────────────────────────────────────────────────┘
```

### 34.2 Token Reference Graph

Tokens form a directed acyclic graph (DAG) where references point from derived tokens to source tokens. Understanding this graph is essential for debugging token resolution issues.

```text
Level 0: Raw Palette
├── --gsmui-palette-white: #ffffff
├── --gsmui-palette-zinc-100: #f4f4f5
├── --gsmui-palette-zinc-900: #18181b
├── --gsmui-palette-blue-500: #3b82f6
├── --gsmui-palette-blue-600: #2563eb
└── ...

Level 1: Semantic Tokens
├── --gsmui-color-bg: var(--gsmui-palette-white)
├── --gsmui-color-surface: var(--gsmui-palette-zinc-100)
├── --gsmui-color-text: var(--gsmui-palette-zinc-900)
├── --gsmui-color-accent: var(--gsmui-palette-blue-600)
└── ...

Level 2: Component Tokens
├── --gsmui-button-bg: var(--gsmui-color-accent)
├── --gsmui-input-bg: var(--gsmui-color-bg)
├── --gsmui-card-bg: var(--gsmui-color-surface)
└── ...

Level 3: Utility Classes (Tailwind)
├── bg-accent → var(--gsmui-color-accent)
├── bg-bg → var(--gsmui-color-bg)
├── text-text → var(--gsmui-color-text)
└── ...
```

### 34.3 Token Validation Rules

| Token Type | Valid Formats | Invalid Formats | Default on Error |
| --- | --- | --- | --- |
| Color | `#hex`, `rgb()`, `hsl()`, `oklch()` | `red`, `inherit`, `transparent` | Token group default |
| Length | `px`, `rem`, `em`, `%` | `auto`, `inherit` | Token group default |
| Font stack | Comma-separated families | Single family | System fonts |
| Shadow | `h-offset v-offset blur spread color` | Invalid syntax | Default shadow |
| Timing | `ms`, `s` | Negative values | Token group default |
| Z-index | Integer | Decimal, negative | Token group default |

### 34.4 Token Conflict Resolution

When multiple token sources define the same token, the resolution follows this priority:

| Priority | Source | Example |
| --- | --- | --- |
| 1 (highest) | Inline style | `style="--gsmui-color-accent: red"` |
| 2 | `adoptedStyleSheets` (runtime) | Theme builder live preview |
| 3 | `:root` in compiled CSS | Default theme values |
| 4 | Tailwind default scale | `bg-blue-600` fallback |
| 5 (lowest) | Browser default | `color: initial` |

## 35. Token Composition Patterns

### 35.1 Reference Chain Patterns

| Pattern | Example | Use Case |
| --- | --- | --- |
| Direct reference | `--gsmui-color-accent: var(--gsmui-palette-blue-600)` | Simple alias |
| Derived reference | `--gsmui-button-bg: var(--gsmui-color-accent)` | Component token |
| Fallback chain | `var(--a, var(--b, #default))` | Graceful degradation |
| Conditional | `@container` media queries | Responsive tokens |

### 35.2 Token Naming Conventions

| Convention | Example | Rule |
| --- | --- | --- |
| Group prefix | `--gsmui-color-*` | Always start with group |
| Semantic name | `--gsmui-color-accent` | Name describes purpose |
| Scale steps | `--gsmui-space-1` through `--gsmui-space-12` | Numeric for scales |
| Named steps | `--gsmui-text-sm`, `--gsmui-text-base` | Named for typography |
| State tokens | `--gsmui-color-accent-hover` | State appended to name |
| Component tokens | `--gsmui-button-bg` | Component prefix |

### 35.3 Token Documentation Format

Every token group is documented with:

```markdown
## Color Tokens

### Purpose
Color tokens define the visual color palette for GsmUi components. They are used for
text, backgrounds, borders, and interactive states.

### Token List

| Token | CSS Variable | Light Value | Dark Value | Tailwind Utility |

### Composition Rules

test("color tokens render correctly", async ({ page }) => {

        { name: "accent", expected: "rgb(37, 99, 235)" },
        { name: "danger", expected: "rgb(220, 38, 38)" },

### 36.2 Contrast Ratio Tests

All text/background token pairs are tested for WCAG contrast compliance:

```js
test("text on background meets contrast ratio", async ({ page }) => {
    await page.goto("/test/tokens");
    const ratio = await page.evaluate(() => {
        const text = getComputedStyle(document.documentElement)
            .getPropertyValue('--gsmui-color-text');
        const bg = getComputedStyle(document.documentElement)
            .getPropertyValue('--gsmui-color-bg');
        return getContrastRatio(text, bg);
    });
    expect(ratio).toBeGreaterThanOrEqual(4.5);
});
```

test("dark mode tokens flip correctly", async ({ page }) => {

### 39.1 Why Three-Layer Token Architecture

### 40.1 Do

| Practice | Example | Benefit |

## 41. Token Security

### 41.1 Token Injection Prevention

Tokens are never directly interpolated into CSS without sanitization:

```php
// Safe: token values are validated
$value = TokenEngine::resolve('color-accent');
$validated = TokenValidator::color($value); // Returns safe value or default
```

### 41.2 Token Scope

| Scope | Access | Use Case |
| --- | --- | --- |
| Global | All components | `--gsmui-color-*`, `--gsmui-space-*` |
| Component | Single component | `--gsmui-button-*`, `--gsmui-input-*` |
| Local | Single instance | Inline `style` overrides |

### 41.3 Token Namespace

The `--gsmui-` prefix is reserved. Consumer apps MUST NOT define tokens with this prefix:

```css
/* Consumer app tokens */
--my-app-*: ...;  /* ✅ Allowed */
--gsmui-*: ...;   /* ❌ Forbidden — reserved for GsmUi */
```

### 41.4 Token Sanitization

```php
function sanitizeTokenName($name) {
    // Remove any characters that aren't alphanumeric, hyphens, or underscores
    return preg_replace('/[^a-z0-9\-_]/', '', strtolower($name));
}

function sanitizeTokenValue($value) {
    // Remove any characters that could be used for CSS injection
    return preg_replace('/[;{}]/', '', $value);
}
```

## 43. Token Accessibility

### 43.1 Contrast Requirements

All token pairs used for text on backgrounds must meet WCAG 2.2 AA contrast ratios:

| Text Size | Minimum Ratio | Token Examples |
| --- | --- | --- |
| Normal text (< 24px) | 4.5:1 | `color-text` on `color-bg` |
| Large text (≥ 24px) | 3:1 | `text-2xl` headings on `color-bg` |
| UI components | 3:1 | `color-border` on `color-bg` |
| Focus indicators | 3:1 | `color-accent` focus ring on `color-bg` |

### 43.2 Color Independence

Tokens must not be the sole means of conveying information:

| Scenario | Requirement |
| --- | --- |
| Error state | Red border + error icon + error text |
| Success state | Green checkmark + success text |
| Required field | Asterisk + "required" text |
| Disabled state | Reduced opacity + `aria-disabled` |

### 43.3 High Contrast Mode

Tokens should work in Windows High Contrast Mode:

```css
@media (forced-colors: active) {
    :root {
        --gsmui-color-accent: Highlight;
        --gsmui-color-text: CanvasText;
        --gsmui-color-bg: Canvas;
    }
}
```

### 43.4 Color Blindness Considerations

| Color Pair | Problem | Solution |
| --- | --- | --- |
| Red/Green | Deuteranopia | Add icons + text labels |
| Blue/Purple | Tritanopia | Ensure sufficient contrast |
| Red/Orange | Protanopia | Add icons + text labels |
