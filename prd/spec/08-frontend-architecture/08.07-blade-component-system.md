# 08.07 - Blade Component System

**Project:** GsmUi
**Section:** 08 - Frontend Architecture
**Framework:** Blade Components · GsmUi Component Library · Laravel 13
**Version:** 1.0.0

---

> See also: `07.20-blade-component-architecture.md` (backend component registration), `06.20-components.md` (component definitions), `06.21-component-variants.md` (variants). This document specifies the *Blade-level component contract* (namespace, slots, props, class merging, ARIA) and does NOT re-document component schema.

# Purpose

This document is the contract for authoring and consuming `gsmui:` Blade components: the anonymous-component namespace, prop/slot conventions, the `Gsmui::classes()` merging utility, and the ARIA patterns mandated by AGENTS.md. It lets an implementer write a component that is visually and semantically identical to its siblings.

---

## 1. Component Namespace & Registration

Components are **anonymous Blade components** registered under the `gsmui:` prefix by `GsmuiProServiceProvider::bootComponentPath()`, pointing at `stubs/resources/views/gsmui/<component>/index.blade.php`.

```blade
{{-- Usage --}}
<gsmui:input wire:model="email" />
<gsmui:button type="button">Save</gsmui:button>
```

| Item | Rule |
| --- | --- |
| Prefix | `gsmui:` (never `flux:`) |
| Path | `stubs/resources/views/gsmui/<name>/index.blade.php` |
| Count | ~70 components (accordion, date-picker, select, slider, editor, …) |
| Facade | `Gsmui` (never `Flux`) |

---

## 2. Props & Slots

| Construct | Convention |
| --- | --- |
| Wire binding | `wire:model` first, then `value`, `name`, `format`, `type`, `placeholder`, `size` |
| Behavioral props | `swatches`, `dropper`, `clearable`, `copyable` (after core props) |
| Meta props | `label`, `description`, `disabled`, `invalid` (last) |
| Slots | Named slots for trigger content; default slot for children |
| Action buttons | Real `<gsmui:button>`; use `<gsmui:button as="div">` only inside a `<button>` |

Prop order is fixed (AGENTS.md docs conventions) to keep generated code blocks consistent across the docs portal.

---

## 3. Class Merging with `Gsmui::classes()`

All class composition goes through `Gsmui::classes()` — never raw string concatenation.

```php
// Inside a component blade / class
{{ Gsmui::classes(
    'bg-white dark:bg-white/10',
    'border-zinc-200 border-b-zinc-300/80 dark:border-white/10',
    'shadow-xs rounded-lg',
    $attributes->get('class') // caller overrides merged last
) }}
```

| Rule | Why |
| --- | --- |
| Caller class merged last | Caller overrides win without clobbering base |
| Layer, don't swap | `data-invalid:` adds over base; never ternary the whole block |
| No `focus:ring-2` | Native outline only; see §5 |

## 4. ARIA Patterns (from AGENTS.md)

ARIA follows the closest existing pattern; do not invent new roles.

| Component shape | ARIA contract |
| --- | --- |
| Input trigger | `role="combobox"` on the `<input>` |
| Button trigger | native `<button>` + `aria-haspopup="dialog"` |
| Popover/dialog | `aria-modal`, focus trap, `Esc` to close |
| Numeric/slider | `aria-valuenow/min/max`, `tabular-nums` display |

Aria-labels MUST use `__()` (localization) set from Blade. JS uses the Blade-set value as primary, with a hardcoded English string only as a fallback. The docs portal uses `<x-docs.variant level="3">` for sub-component reference sections.

## 6. Component File Structure

Every `gsmui:` component lives at a fixed path. This section documents the exact file layout, naming conventions, and internal organization.

### 6.1 File Path Convention

```text
stubs/resources/views/gsmui/
├── accordion/
│   ├── index.blade.php          # Main component
│   └── item.blade.php           # Sub-component (if needed)
├── button/
│   └── index.blade.php
├── card/
│   └── index.blade.php
├── date-picker/
│   ├── index.blade.php          # Main component
│   ├── button.blade.php         # Trigger button
│   ├── calendar.blade.php       # Calendar grid
│   └── footer.blade.php         # Footer actions
├── input/
│   └── index.blade.php
├── modal/
│   └── index.blade.php
├── select/
│   ├── index.blade.php
│   ├── option.blade.php
│   └── dropdown.blade.php
├── slider/
│   └── index.blade.php
└── ...
```

### 6.2 File Naming Rules

| Rule | Example | Rationale |
| --- | --- | --- |
| Kebab-case directories | `date-picker/` | URL-friendly, readable |
| `index.blade.php` for main file | `input/index.blade.php` | Consistent entry point |
| Sub-component files match role | `dropdown.blade.php` | Descriptive, self-documenting |
| No `components/` subdirectory | `input/index.blade.php` | One level deep only |

### 6.3 Component File Internal Structure

Every component file follows this internal order:

```blade
{{-- 1. State root opening tag with attributes --}}
<div
    data-gsmui-{{ $componentName }}
    @class([
        Gsmui::classes(
            // Base classes
            'relative',
            // Component-specific classes
            'bg-white dark:bg-white/10',
        ),
        // State modifiers
        'data-invalid:border-danger' => $invalid,
        'data-disabled:opacity-50' => $disabled,
    ])
    @if($disabled) disabled @endif
    @if($invalid) data-invalid @endif
>

    {{-- 2. Label (optional) --}}
    @if($label)
        <label class="block text-sm font-medium text-zinc-700 dark:text-zinc-300 mb-1">
            {{ $label }}
        </label>
    @endif

    {{-- 3. Trigger / Input area --}}
    {{-- 4. Popover / Dropdown (when open) --}}
    {{-- 5. Error message (when invalid) --}}

</div>
```

### 6.4 Component Attribute Order

Within the state root opening tag, attributes follow this order:

| Order | Attribute | Example |
| --- | --- | --- |
| 1 | Data attributes | `data-gsmui-select` |
| 2 | `@class()` | Class composition block |
| 3 | Wire bindings | `wire:model`, `wire:click` |
| 4 | ARIA attributes | `role`, `aria-expanded`, `aria-labelledby` |
| 5 | Event handlers | `x-on:change`, `x-on:click` |
| 6 | State attributes | `disabled`, `data-invalid` |
| 7 | Refs | `x-ref="input"` |
| 8 | Other | `id`, `name`, `tabindex` |

## 7. Prop Type System

### 7.1 Prop Types

All `gsmui:` component props use PHP types:

| Type | PHP Type | Default | Example |
| --- | --- | --- | --- |
| String | `?string` | `null` | `placeholder="Search..."` |
| Boolean | `bool` | `false` | `searchable` or `:searchable="true"` |
| Integer | `?int` | `null` | `:rows="5"` |
| Float | `?float` | `null` | `:step="0.1"` |
| Array | `array` | `[]` | `:options="$items"` |
| Enum | BackedEnum | varies | `size="sm"` |
| Closure | `\Closure` | varies | `:format fn($v) => ...` |

### 7.2 Prop Default Values

| Prop | Default | Behavior |
| --- | --- | --- |
| `size` | `null` (default size) | Falls back to base size class |
| `disabled` | `false` | Component is interactive |
| `invalid` | `false` | No error styling |
| `placeholder` | `null` | No placeholder shown |
| `label` | `null` | No label rendered |
| `description` | `null` | No description rendered |

### 7.3 Prop Validation

Component props are validated in the Blade template using `@props` directive:

```blade
@props([
    'wire:model' => null,
    'value' => null,
    'placeholder' => '',
    'size' => 'default',
    'disabled' => false,
    'invalid' => false,
    'label' => null,
    'description' => null,
    'clearable' => false,
    'copyable' => false,
])
```

## 8. Slot System

### 8.1 Slot Types

| Slot Type | Syntax | Purpose |
| --- | --- | --- |
| Default slot | `{{ $slot }}` | Primary content area |
| Named slot | `$actions` | Action buttons area |
| Scoped slot | `{{ $option($item) }}` | Render delegation with data |

### 8.2 Slot Examples

```blade
{{-- gsmui:input with all slot types --}}
<gsmui:input wire:model="email" placeholder="Email">
    {{-- Default slot: not typically used for input --}}
    <x-slot:prepend>
        <x-heroicon-o-envelope class="w-4 h-4 text-zinc-400" />
    </x-slot:prepend>

    <x-slot:append>
        <gsmui:button as="div" icon="x" size="xs" />
    </x-slot:append>

    <x-slot:description>
        We'll never share your email.
    </x-slot:description>

    <x-slot:error>
        Please enter a valid email address.
    </x-slot:error>
</gsmui:input>
```

### 8.3 Conditional Slot Rendering

```blade
{{-- Only render slot content if slot is not empty --}}
@if(isset($prepend) && $prepend->isNotEmpty())
    <div class="flex items-center pe-3">
        {{ $prepend }}
    </div>
@endif
```

### 8.4 Slot Ordering

| Order | Slot | Position |
| --- | --- | --- |
| 1 | `prepend` | Before main content |
| 2 | default | Main content area |
| 3 | `append` | After main content |
| 4 | `description` | Below main content |
| 5 | `error` | Below description (when invalid) |

## 9. Class Merging Deep Dive

### 9.1 `Gsmui::classes()` Resolution

The `Gsmui::classes()` method performs the following operations:

```text
1. Flatten all arguments (strings, arrays, conditionals)
2. Merge caller's $attributes->get('class') last
3. Deduplicate classes
4. Return merged class string
```

### 9.2 Class Merging Rules

| Rule | Example | Result |
| --- | --- | --- |
| Caller classes win | `base: p-4` + `caller: p-2` | `p-2` |
| Conditional classes | `'danger:border-red-500' => $invalid` | Applied when true |
| Data attribute selectors | `'data-invalid:border-danger'` | Applied via CSS |
| Responsive classes | `'sm:hidden lg:block'` | Applied at breakpoints |
| Dark mode classes | `'dark:bg-zinc-900'` | Applied in dark mode |

### 9.3 Class Layering Pattern

```blade
@php
$baseClasses = Gsmui::classes(
    // Structural (always present)
    'relative inline-flex items-center justify-center',

    // Visual (token-driven)
    'bg-white dark:bg-white/10',
    'border border-zinc-200 dark:border-white/10',
    'shadow-xs rounded-lg',

    // Size (variant-dependent)
    match($size) {
        'sm' => 'h-8 text-sm px-3 gap-1.5',
        'xs' => 'h-6 text-xs px-2 gap-1',
        default => 'h-10 text-base px-4 gap-2',
    },

    // State (conditional)
    'data-disabled:opacity-50 data-disabled:pointer-events-none',
    'data-invalid:border-red-500 data-invalid:focus:border-red-500',

    // Caller overrides
    $attributes->get('class'),
);
@endphp

<button @class([$baseClasses]) {{ $attributes->merge(['type' => 'button']) }}>
    {{ $slot }}
</button>
```

## 10. ARIA Implementation Guide

### 10.1 ARIA Role Mapping

| Component | Native Element | ARIA Role | Required Attributes |
| --- | --- | --- | --- |
| `gsmui:button` | `<button>` | (native) | `type="button"` |
| `gsmui:input` | `<input>` | (native) | `aria-describedby` (help/error) |
| `gsmui:textarea` | `<textarea>` | (native) | `aria-describedby` (help/error) |
| `gsmui:select` | Custom | `role="combobox"` | `aria-expanded`, `aria-controls`, `aria-activedescendant` |
| `gsmui:modal` | Custom | `role="dialog"` | `aria-modal`, `aria-labelledby`, `aria-describedby` |
| `gsmui:accordion` | Custom | `heading` + region | `aria-expanded`, `aria-controls` |
| `gsmui:tabs` | Custom | `tablist` + `tab` + `tabpanel` | `aria-selected`, `aria-controls` |
| `gsmui:tooltip` | Custom | `role="tooltip"` | `aria-describedby` |
| `gsmui:slider` | Custom | `role="slider"` | `aria-valuenow`, `aria-valuemin`, `aria-valuemax` |
| `gsmui:progress` | Custom | `role="progressbar"` | `aria-valuenow`, `aria-valuemin`, `aria-valuemax` |

### 10.2 ARIA Label Localization

All dynamic ARIA labels use `__()` for localization:

```blade
{{-- ARIA label set from Blade, used by JS --}}
<div
    role="combobox"
    aria-label="{{ __('gsmui.select.placeholder') }}"
    aria-expanded="{{ $isOpen ? 'true' : 'false' }}"
    aria-controls="select-options-{{ $id }}"
    aria-activedescendant="{{ $activeOptionId }}"
>
```

### 10.3 Focus Management Rules

| Context | Rule | Implementation |
| --- | --- | --- |
| Page load | Focus first interactive element | `tabindex="0"` on first element |
| Modal open | Focus first focusable element | `$refs.modal.querySelector('input, button')?.focus()` |
| Modal close | Restore focus to trigger | `$refs.trigger.focus()` |
| Popover open | Focus popover content | `$refs.popover.querySelector('[tabindex]')?.focus()` |
| Popover close | Return focus to trigger | `$refs.trigger.focus()` |
| Error state | Focus first invalid input | `document.querySelector('[data-invalid]')?.focus()` |
| Tab switch | Focus new tab panel | `tabpanel.focus()` |

## 11. Component Testing Patterns

### 11.1 Visual State Verification

Every component is verified in Playwright across these states:

```js
const states = [
    "base",           // Default render
    "hover",          // Mouse hover
    "focus-visible",  // Keyboard focus
    "active",         // Pressed/clicked
    "disabled",       // Disabled state
    "invalid",        // Validation error
    "size-sm",        // Small variant
    "size-xs",        // Extra-small variant
    "dark-base",      // Dark mode base
    "dark-hover",     // Dark mode hover
];
```

### 11.2 Screenshot Test Pattern

```js
// tests/Browser/component-visual.spec.js
test("button renders all states", async ({ page }) => {
    await page.goto("/test/button");

    // Base state
    await expect(page.locator("[data-gsmui-button]")).toHaveScreenshot("button-base.png");

    // Hover state
    await page.hover("[data-gsmui-button]");
    await expect(page.locator("[data-gsmui-button]")).toHaveScreenshot("button-hover.png");

    // Disabled state
    const disabled = page.locator("[data-gsmui-button][disabled]");
    await expect(disabled).toHaveScreenshot("button-disabled.png");

    // Dark mode
    await page.evaluate(() => {
        document.documentElement.setAttribute("data-theme", "dark");
    });
    await expect(page.locator("[data-gsmui-button]")).toHaveScreenshot("button-dark.png");
});
```

### 11.3 Keyboard Test Pattern

```js
test("select is keyboard navigable", async ({ page }) => {
    await page.goto("/test/select");

    // Tab to select
    await page.keyboard.press("Tab");
    await expect(page.locator("[data-gsmui-select]")).toBeFocused();

    // Open with Enter
    await page.keyboard.press("Enter");
    await expect(page.locator("[data-gsmui-select-dropdown]")).toBeVisible();

    // Navigate with arrows
    await page.keyboard.press("ArrowDown");
    await page.keyboard.press("ArrowDown");

    // Select with Enter
    await page.keyboard.press("Enter");
    await expect(page.locator("[data-gsmui-select] input")).toHaveValue("Option 3");
});
```

## 12. Component Error Boundaries

### 12.1 Error Handling Pattern

```blade
@php
try {
    $resolvedOptions = $options->map(fn($option) => [
        'value' => $option->value,
        'label' => $option->label,
    ])->toArray();
} catch (\Exception $e) {
    $resolvedOptions = [];
    $hasError = true;
}
@endphp

@if($hasError)
    <div role="alert" class="text-sm text-red-600 dark:text-red-400">
        {{ __('gsmui.select.error') }}
    </div>
@else
    {{-- Normal render --}}
@endif
```

### 12.2 Graceful Degradation

| Error Type | Behavior |
| --- | --- |
| Invalid options format | Render empty dropdown |
| Missing required prop | Render fallback markup |
| JS bundle failure | Server-rendered content remains |
| CSS failure | Unstyled but functional |
| Token undefined | Tailwind default fallback |

## 13. Component Performance Optimization

### 13.1 Conditional Rendering

Only render expensive sub-components when needed:

```blade
{{-- Don't render popover markup when closed --}}
@if($isOpen)
    <div class="gsmui-popover" role="dialog">
        {{-- Complex popover content --}}
    </div>
@endif
```

### 13.2 Lazy Icon Loading

```blade
{{-- Inline SVG icons, no lazy loading needed --}}
<x-heroicon-o-check class="w-4 h-4" />

{{-- For icon-heavy components, use Blade component caching --}}
@once
    <x-heroicon-o-information-circle class="w-5 h-5" />
@endonce
```

### 13.3 CSS Containment

Apply CSS containment to isolated components:

```blade
<div
    @class([
        Gsmui::classes('relative contain-layout contain-style'),
        // ... other classes
    ])
>
```

### 13.4 Debounced Updates

```blade
{{-- Debounce high-frequency updates --}}
<gsmui:input
    wire:model.debounce.150ms="search"
    x-on:input.debounce.150ms="handleInput"
/>
```

| Rule | Example | Why |

## 22. Component Architecture Deep Dive

### 22.1 Component Anatomy

Every `gsmui:` component follows a consistent internal anatomy. Understanding this structure is essential for building new components that feel native to the system.

```text
┌─────────────────────────────────────────────────┐
│  Label (optional)                                │
│  ┌─────────────────────────────────────────────┐ │
│  │  Trigger / Input Area                       │ │
│  │  ┌─────────────────────────────┬──────────┐ │ │
│  │  │  Value / Placeholder        │ Actions  │ │ │
│  │  │                             │ (clear,  │ │ │
│  │  │                             │  copy)   │ │ │
│  │  └─────────────────────────────┴──────────┘ │ │
│  └─────────────────────────────────────────────┘ │
│  Description (optional)                          │
│  Error message (when data-invalid)               │
│                                                   │
│  ┌─────────────────────────────────────────────┐ │
│  │  Popover / Dropdown (when open)             │ │
│  │  ┌─────────────────────────────────────────┐│ │
│  │  │  Content area                          ││ │
│  │  │  (options, calendar, color grid, etc.)  ││ │
│  │  └─────────────────────────────────────────┘│ │
│  │  Footer (optional)                         │ │
│  └─────────────────────────────────────────────┘ │
└─────────────────────────────────────────────────┘
```

### 22.2 Component Layers

Each component is composed of layers, ordered from innermost to outermost:

| Layer | Purpose | Example |
| --- | --- | --- |
| **State Root** | Manages internal state (open/closed, value, focus) | `<div data-gsmui-select>` |
| **Trigger** | The interactive element that initiates action | `<button>`, `<input>` |
| **Display** | Shows current value or placeholder | `<span>`, `<input value>` |
| **Actions** | Utility buttons (clear, copy, dropper) | `<gsmui:button>` |
| **Popover** | Floating content container | `<div role="dialog">` |
| **Content** | The actual interactive content | Options list, calendar grid |
| **Footer** | Bottom actions (Today, Clear, etc.) | `<div>` with buttons |

### 22.3 State Root Convention

Every component has a state root element that carries the component's identity and state attributes:

```html
<!-- State root carries data-gsmui-* attribute -->
<div data-gsmui-select
     data-gsmui-value=""
     data-gsmui-disabled=""
     data-gsmui-invalid=""
     data-gsmui-open="">
  <!-- children -->
</div>
```

The state root is what GsmUi JS observes via MutationObserver. Changes to `data-gsmui-*` attributes drive UI updates.

## 23. Component Composition Patterns

### 23.1 Composition Over Configuration

GsmUi favors composition over deep prop configuration. When a component needs significant structural variation, it becomes a separate component rather than adding props.

**Good (composition):**
```blade
<gsmui:input-group>
    <x-slot:prepend>
        <gsmui:button icon="search" />
    </x-slot:prepend>
    <gsmui:input wire:model="search" placeholder="Search..." />
    <x-slot:append>
        <gsmui:button icon="x" />
    </x-slot:append>
</gsmui:input-group>
```

**Bad (configuration explosion):**
```blade
{{-- Don't do this --}}
<gsmui:input
    prepend-icon="search"
    append-icon="x"
    prepend-action="search"
    append-action="clear"
    prepend-disabled="false"
    append-disabled="false"
/>
```

### 23.2 Slot Patterns

| Slot Type | Convention | Use Case |
| --- | --- | --- |
| Default slot | Children content | Accordion items, list items |
| Named slots | `x-slot:name` | Trigger content, footer, header |
| Conditional slots | `@if($slot->isNotEmpty())` | Optional sections |
| Fragment slots | Multiple root elements | Complex popover content |

### 23.3 Render Delegation

Some components delegate rendering to slots while maintaining structural guarantees:

```blade
{{-- Component provides structure; slot provides content --}}
<gsmui:accordion-item>
    <x-slot:trigger>
        <span>Section Title</span>  {{-- Caller controls content --}}
    </x-slot:trigger>
    <x-slot:content>
        <p>Section body</p>        {{-- Caller controls content --}}
    </x-slot:content>
</gsmui:accordion-item>
```

The component enforces the accordion structure (trigger + content, expand/collapse behavior) while the caller controls the visual content.

### 29.2 JavaScript Error Boundary

```js
// GsmUi component error boundary
class ComponentErrorBoundary {
    static capture(componentName, error, context = {}) {
        console.error(`[GsmUI] Error in ${componentName}:`, error);

        // Send to error tracking
        if (window.Gsmui?.errorHandler) {
            window.Gsmui.errorHandler(componentName, error, context);
        }

        // Dispatch custom event for parent components
        document.dispatchEvent(
            new CustomEvent("gsmui:error", {
                detail: { component: componentName, error, context },
            })
        );
    }

    static wrap(componentName, fn) {
        return (...args) => {
            try {
                return fn(...args);
            } catch (error) {
                this.capture(componentName, error, { args });
                return null;
            }
        };
    }
}
```

### 31.2 Focus Management Patterns

```text
Focus Trap (Modal):
├── On open: focus first focusable element
├── Tab cycles within modal only
├── Shift+Tab cycles backward
├── Escape closes modal
└── On close: focus returns to trigger

Focus Roving (Tabs):
├── Left/Right arrows move between tabs
├── Home/End go to first/last tab
├── Tab key moves focus into tab panel
└── Arrow keys navigate within panel

Focus Restoration (Popover):
├── On open: focus moves to popover
├── Tab cycles within popover
├── Escape closes popover
└── On close: focus returns to trigger
```

## 36. Component Testing Strategies

### 36.1 Unit Testing Pattern

```php
// tests/Unit/Components/ButtonTest.php
use Tests\TestCase;

class ButtonTest extends TestCase
{
    public function test_button_renders_with_default_classes(): void
    {
        $html = $this->blade(<<<'BLADE'
            <x-gsmui::button>Click me</x-gsmui::button>

        $this->assertStringContainsString('gsmui-button', $html);
        $this->assertStringContainsString('Click me', $html);
    }

    public function test_button_disabled_state(): void
    {
        $html = $this->blade(<<<'BLADE'
            <x-gsmui::button disabled>Click me</x-gsmui::button>
        BLADE);

        $this->assertStringContainsString('disabled', $html);
        $this->assertStringContainsString('aria-disabled="true"', $html);
    }

    public function test_button_size_variants(): void
    {
        foreach (['sm', 'md', 'lg'] as $size) {
            $html = $this->blade(<<<'BLADE'
                <x-gsmui::button size="{{ $size }}">Click</x-gsmui::button>
            BLADE);

            $this->assertStringContainsString("size-{$size}", $html);
        }
    }
}
```
