# Purpose

GsmUi is **mobile-first**: base styles target the smallest viewport, enhancements layer up via Tailwind v4 breakpoints and container queries. The responsive system defines the canonical breakpoint scale, the container-query strategy for component-level responsiveness, and the rules for collapsing shell/navigation on small screens — all via utilities, never JS media-query listeners (per the AGENTS.md "lean on the browser" rule).

---

## 1. Breakpoint Scale

Tailwind v4 default scale is extended in the theme layer (`08.05-tailwind-v4.md`). Canonical tokens:

| Token | Min width | Typical use |
| --- | --- | --- |
| `sm` | 640px | Stacked → 2-col content |
| `md` | 768px | Sidebar visible (static), navlist expanded |
| `lg` | 1024px | Full app shell (`grid-cols-[auto_1fr]`) |
| `xl` | 1280px | Wide tables, multi-pane |
| `2xl` | 1536px | Marketing hero max-width |

Never introduce magic media queries in Blade/JS; express all responsiveness through these utilities so the Design Token Engine can remap them.

## 2. Mobile-First Rule

- Write the base class for the narrowest case, then add `sm:`/`md:` overrides.

```blade
{{-- Stack on mobile, side-by-side from md --}}
<div class="flex flex-col gap-4 md:flex-row md:items-center">
```

- Avoid `hidden md:block` traps that hide critical controls; if a control collapses, provide an equivalent (e.g. drawer) entry point (`08.13`).

## 3. Container Queries

For components that must adapt to their *container* width (cards in a grid, table cells), use Tailwind v4 `@container` + `@md:`/`@lg:`:

```blade
<div class="@container">
    <div class="grid grid-cols-1 @md:grid-cols-2 @lg:grid-cols-3 gap-4">
        {{ $slot }}
    </div>
</div>
```

Use container queries whenever a component is embedded in multiple layouts (dashboard widget, marketing band) so it responds to context, not viewport.

## 4. Shell Collapse Behavior

| Viewport | Sidebar | Navbar | Content |
| --- | --- | --- | --- |
| `< md` | `type="drawer"` (off-canvas) | Hamburger toggle | full width |
| `md – < lg` | `static` collapsed width | full | single col |
| `≥ lg` | `static` full | full | 12-col grid |

Drawer open state locks body scroll (date-picker scroll-lock pattern, AGENTS.md) and traps focus (`08.16`).

## 5. Responsive Tables & Images

- `gsmui:table` wraps in `overflow-x-auto` (`stubs/.../table/index.blade.php`) so wide tables scroll horizontally rather than break layout.
- Images/icons use `size-*`/`max-w-full h-auto`; avatars use fixed `size-*` with `object-cover`.
- Charts (`08.34-chart-system.md`) observe container resize via `ResizeObserver` (browser-native, not polyfilled) and re-render — no JS breakpoint polling.

## 6. Testing Responsiveness

- Verify with Playwright at 375px, 768px, 1280px (`08.49-testing.md`).
- Critical states to capture per AGENTS.md: sidebar drawer at 375px, breadcrumb wrap at 640px, table horizontal scroll at 768px.
- Never guess pixel gaps — measure with Playwright and pick round Tailwind values; fall back to magic numbers like `pe-[9px]` only when no Tailwind token exists.

## 7. Open Questions / Risks

- Should `xl`/`2xl` get additional component density variants, or is `lg` the ceiling? Punt on >2xl until a real use case appears (AGENTS.md: punt semi-aggressively).
- Container-query browser support is modern-only; confirm the support matrix in `08.46-performance.md` before relying on `@container` for core shells.

## 8. Deep Dive: Breakpoint System

### 8.1 Tailwind v4 Breakpoint Configuration

GsmUi extends Tailwind's default breakpoints in the theme layer (`08.05-tailwind-v4.md`):

```css
/* gsmui-theme.css */
@theme {
  --breakpoint-sm: 640px;
  --breakpoint-md: 768px;
  --breakpoint-lg: 1024px;
  --breakpoint-xl: 1280px;
  --breakpoint-2xl: 1536px;
}
```

### 8.2 Breakpoint Usage Matrix

| Breakpoint | Viewport range | Primary use | Shell state |
| --- | --- | --- | --- |
| Base (0–639px) | 0 – 639px | Mobile: stacked layout | Drawer sidebar |
| `sm` (640–767px) | 640 – 767px | Small tablets: 2-col content | Drawer sidebar |
| `md` (768–1023px) | 768 – 1023px | Tablets: sidebar collapsed | Static sidebar (collapsed) |
| `lg` (1024–1279px) | 1024 – 1279px | Desktop: full shell | Static sidebar (full) |
| `xl` (1280–1535px) | 1280 – 1535px | Wide desktop: multi-pane | Static sidebar (full) |
| `2xl` (1536+) | 1536+ | Ultra-wide: marketing max | Static sidebar (full) |

### 8.3 Breakpoint-Specific Component Behavior

| Component | Base | `sm` | `md` | `lg` | `xl` |
| --- | --- | --- | --- | --- | ---|
| Sidebar | Drawer | Drawer | Static (collapsed) | Static (full) | Static (full) |
| Navbar | Hamburger + search | Hamburger + search | Full items (scroll) | Full items | Full items |
| Content | Full width | 2-col grid | 12-col grid | 12-col grid | 12-col grid |
| Table | Card view / scroll | Scroll | Scroll | Full table | Full table |
| Modal | Full-screen | Centered | Centered | Centered | Centered |
| Drawer | Full height | Full height | Full height | Side panel | Side panel |

### 8.4 Breakpoint Media Queries

```css

}

/* md: 768px+ */

}

/* lg: 1024px+ */

  .gsmui-component { /* lg styles */ }
}

/* xl: 1280px+ */
@media (min-width: 1280px) {
  .gsmui-component { /* xl styles */ }
}

/* 2xl: 1536px+ */

  .gsmui-component { /* 2xl styles */ }
}
```

## 9. Deep Dive: Container Queries

### 9.1 Container Query Syntax

Tailwind v4 supports `@container` queries via the `@` variant:

```blade
<div class="@container">
    <div class="grid grid-cols-1 @sm:grid-cols-2 @lg:grid-cols-3 gap-4">
        {{-- Responsive to container width, not viewport --}}
    </div>
</div>
```

### 9.2 Container Query Breakpoints

Container query breakpoints map to the viewport breakpoints:

| Container breakpoint | Min width | Equivalent to |
| --- | --- | --- |
| `@sm` | 640px | Viewport `sm` |
| `@md` | 768px | Viewport `md` |
| `@lg` | 1024px | Viewport `lg` |
| `@xl` | 1280px | Viewport `xl` |
| `@2xl` | 1536px | Viewport `2xl` |

### 9.3 When to Use Container Queries

Use container queries when:
- A component is embedded in different layouts (dashboard widget, marketing card).
- The component's internal layout depends on its parent's width, not the viewport.
- The component may appear in a grid, a sidebar, or full-width.

Do NOT use container queries when:
- The component's layout depends on the viewport (e.g., the app shell itself).
- The component is always full-width (e.g., a page header).

### 9.4 Container Query Patterns

**Card grid:**
```blade
<div class="@container">
    <div class="grid grid-cols-1 @md:grid-cols-2 @xl:grid-cols-3 gap-4">
        @foreach($items as $item)
            <x-card :item="$item" />
        @endforeach
    </div>
</div>
```

**Dashboard widget:**
```blade
<div class="@container bg-white dark:bg-zinc-800 rounded-xl p-4">
    <h3 class="text-sm font-semibold @md:text-base">{{ __('Revenue') }}</h3>
    <div class="mt-2 grid grid-cols-1 @lg:grid-cols-2 gap-4">
        <x-chart :data="$revenueData" />
        <div class="space-y-2">
            {{-- Stats --}}
        </div>
    </div>
</div>
```

**Form layout:**
```blade
<div class="@container">
    <div class="grid grid-cols-1 @md:grid-cols-2 gap-4">
        <x-input label="{{ __('First name') }}" wire:model="firstName" />
        <x-input label="{{ __('Last name') }}" wire:model="lastName" />
    </div>
    <div class="mt-4 @md:w-1/2">
        <x-input label="{{ __('Email') }}" wire:model="email" type="email" />
    </div>
</div>
```

### 9.5 Container Query Fallbacks

For browsers that don't support `@container`:

```css
/* Fallback for browsers without container query support */
@supports not (container-type: inline-size) {
  .gsmui-widget .gsmui-widget-content {
    /* Apply mobile-first styles always */
    grid-template-columns: 1fr;
  }
}
```

## 10. Deep Dive: Shell Collapse Behavior

### 10.1 Sidebar Collapse Animation

The sidebar collapse transition must be smooth and performant:

```css
.gsmui-sidebar {
  transition: width 200ms ease-in-out, transform 200ms ease-in-out;
  will-change: width;
}

/* Collapsed state */
.gsmui-sidebar[data-collapsed="true"] {
  width: 64px;
}

/* Expanded state */
.gsmui-sidebar[data-collapsed="false"] {
  width: var(--gsmui-shell-sidebar-width, 256px);
}
```

### 10.2 Drawer Slide Animation

Mobile drawer uses translateX:

```css
.gsmui-sidebar[type="drawer"] {
  transform: translateX(-100%);
  transition: transform 200ms ease-in-out;
}

.gsmui-sidebar[type="drawer"][data-open="true"] {
  transform: translateX(0);
}
```

### 10.3 Focus Management During Collapse

When the sidebar collapses:
1. If a focused element is inside the sidebar, focus moves to the collapse button.
2. The collapse button retains focus until the user interacts with another element.
3. When the sidebar expands, focus returns to the previously focused element.

### 10.4 Layout Shift Prevention

```css
/* Reserve space for collapsed sidebar */
@media (min-width: 768px) and (max-width: 1023px) {
  .gsmui-shell {
    grid-template-columns: 64px 1fr;
  }
}

/* Reserve space for full sidebar */
@media (min-width: 1024px) {
  .gsmui-shell {
    grid-template-columns: var(--gsmui-shell-sidebar-width, 256px) 1fr;
  }
}
```

## 11. Responsive Component Patterns

### 11.1 Responsive Tables

Tables use a card-view fallback on mobile:

```blade
{{-- Mobile: card view --}}
<div class="md:hidden space-y-4">
    @foreach($items as $item)
        <div class="bg-white dark:bg-zinc-800 rounded-lg border border-zinc-200 dark:border-white/10 p-4">
            <div class="flex items-center justify-between">
                <h3 class="text-sm font-medium text-zinc-900 dark:text-white">{{ $item->name }}</h3>
                <gsmui:badge variant="{{ $item->status }}">{{ $item->status }}</gsmui:badge>
            </div>
            <dl class="mt-2 space-y-1 text-sm text-zinc-500 dark:text-zinc-400">
                <div class="flex justify-between"><dt>Email</dt><dd>{{ $item->email }}</dd></div>
                <div class="flex justify-between"><dt>Role</dt><dd>{{ $item->role }}</dd></div>
            </dl>
        </div>
    @endforeach
</div>

{{-- Desktop: table view --}}
<div class="hidden md:block overflow-x-auto">
    <table class="min-w-full divide-y divide-zinc-200 dark:divide-white/10">
        <thead>...</thead>
        <tbody>...</tbody>
    </table>
</div>
```

### 11.2 Responsive Forms

Forms stack on mobile, go side-by-side on desktop:

```blade
<div class="grid grid-cols-1 @md:grid-cols-2 gap-4">
    <x-input label="{{ __('First name') }}" wire:model="firstName" />
    <x-input label="{{ __('Last name') }}" wire:model="lastName" />
</div>
<div class="grid grid-cols-1 @md:grid-cols-2 gap-4 mt-4">
    <x-input label="{{ __('Email') }}" wire:model="email" type="email" />
    <x-select label="{{ __('Role') }}" wire:model="role" :options="$roles" />
</div>
```

### 11.3 Responsive Modals

Modals are full-screen on mobile, centered on desktop:

```blade
<gsmui:modal>
    {{-- Mobile: full-screen --}}
    <div class="max-sm:max-h-full! max-sm:fixed! max-sm:inset-0!
                sm:relative sm:max-w-lg sm:mx-auto
                rounded-xl shadow-xl sm:shadow-2xs
                bg-white dark:bg-zinc-700
                sm:border border-zinc-200 dark:border-white/10
                p-3">
        {{ $slot }}
    </div>
</gsmui:modal>
```

### 11.4 Responsive Navigation

Navigation adapts to viewport width:

```blade
{{-- Mobile: hamburger + drawer --}}
<gsmui:button class="lg:hidden" wire:click="toggleDrawer">
    <gsmui:icon name="bars-3" variant="mini" />
</gsmui:button>

{{-- Desktop: horizontal nav --}}
<nav class="hidden lg:flex items-center gap-1">
    @foreach($navItems as $item)
        <a href="{{ $item['href'] }}" class="nav-item">{{ $item['label'] }}</a>
    @endforeach
</nav>
```

### 11.5 Responsive Grid Patterns

```blade
{{-- 1-col mobile, 2-col tablet, 3-col desktop, 4-col wide --}}
<div class="grid grid-cols-1 sm:grid-cols-2 lg:grid-cols-3 xl:grid-cols-4 gap-4">
    @foreach($items as $item)
        <x-card :item="$item" />
    @endforeach
</div>

{{-- 1-col mobile, 12-col desktop with spanning --}}
<div class="grid grid-cols-1 md:grid-cols-12 gap-4">
    <div class="md:col-span-8">Main content</div>
    <div class="md:col-span-4">Sidebar</div>
</div>
```

## 16. Responsive Accessibility

### 16.1 Touch Targets

WCAG 2.2 requires a minimum touch target size of 24×24px (Level AA) or 44×44px (Level AAA). GsmUi targets 44×44px:

```blade
{{-- Ensure minimum touch target --}}
<gsmui:button size="xs" class="min-h-11 min-w-11 flex items-center justify-center">
    <gsmui:icon name="x-mark" variant="micro" />
</gsmui:button>
```

### 16.2 Readable Text at All Sizes

Text must remain readable when zoomed to 200%:

```css
/* Ensure text scales properly */
html {
  font-size: 16px; /* Base size — don't override */
}

/* Text containers should not clip at 200% zoom */
.gsmui-card {
  min-height: 44px; /* Prevent text truncation */
  overflow: visible; /* Allow text to wrap */
}
```

### 16.3 Responsive Focus Indicators

Focus indicators must be visible at all viewport sizes:

```css
/* Focus ring scales with element size */
:focus-visible {
  outline: 2px solid var(--gsmui-color-focus, -webkit-focus-ring-color);
  outline-offset: 2px;
}

/* Larger elements get thicker outline */
@media (min-width: 1024px) {
  :focus-visible {
    outline-width: 2px;
  }
}
```

### 16.4 Reduced Motion at All Viewports

The `prefers-reduced-motion` rule applies regardless of viewport:

```css
@media (prefers-reduced-motion: reduce) {
  *, *::before, *::after {
    animation-duration: 0.01ms !important;
    transition-duration: 0.01ms !important;
  }
}
```

## 17. Responsive Performance

### 17.1 Mobile-First Asset Loading

Load critical CSS inline, defer non-critical:

```html
<!-- Critical CSS (navbar + sidebar) -->
<style>
  .gsmui-shell { display: grid; grid-template-columns: 1fr; }
  @media (min-width: 768px) { .gsmui-shell { grid-template-columns: 64px 1fr; } }
  @media (min-width: 1024px) { .gsmui-shell { grid-template-columns: 256px 1fr; } }

<!-- Non-critical CSS -->
<link rel="stylesheet" href="{{ mix('css/app.css') }}" media="print" onload="this.media='all'" />
```

```blade
{{-- Use srcset for responsive images --}}
<img src="{{ $avatar->url('sm') }}"
```

## 18. Common Responsive Mistakes

### 18.1 Hidden Critical Controls

```blade
{{-- ❌ WRONG: Hides search on mobile --}}
<div class="hidden md:block">
    <gsmui:search />
</div>

{{-- ✅ CORRECT: Search always visible, adapts to viewport --}}
<gsmui:search class="w-full md:w-64" />
```

### 18.2 Fixed Pixel Values

```blade
{{-- ❌ WRONG: Fixed pixel width --}}
<div style="width: 768px">

{{-- ✅ CORRECT: Responsive width --}}
<div class="w-full md:w-96">
```

### 18.3 Non-Responsive Images

```blade
{{-- ❌ WRONG: Fixed size image --}}
<img src="/hero.jpg" width="1200" height="600" />

{{-- ✅ CORRECT: Responsive image --}}
<img src="/hero.jpg" class="w-full h-auto max-h-[600px] object-cover" />
```

### 18.4 Ignoring Container Queries

```blade
{{-- ❌ WRONG: Viewport query for a widget in a grid --}}
<div class="lg:grid-cols-3">
    <div class="md:grid-cols-2"> {{-- This responds to viewport, not container --}}
```

## 19. Responsive Design Principles

### 19.1 The 5 Principles of GsmUi Responsive Design

1. **Mobile-first always.** Base styles target the smallest viewport. Enhancements layer up. Never write desktop-first and try to "make it responsive."

2. **Content dictates layout, not viewport.** A form with 2 fields stacks on mobile. A form with 8 fields might use 2 columns on tablet. The content density, not the viewport width alone, determines the layout.

3. **No horizontal scroll on the shell.** The app shell (sidebar + content) must never cause horizontal scrolling. Only specific content regions (wide tables, overflowing code blocks) may scroll horizontally.

4. **Touch targets are non-negotiable.** Every interactive element meets 44×44px minimum on touch devices, regardless of visual design preferences.

5. **Test at real breakpoints, not estimates.** Measure with Playwright at 375px, 768px, 1024px, 1280px, 1536px. Never assume a layout works without testing.

### 19.2 Responsive Decision Framework

When deciding how a component should respond to viewport changes:

```text
1. Does the content change density?
   → Yes: Use a grid breakpoint (sm/md/lg/xl)
   → No: Keep the same layout

2. Does the component appear in different containers?
   → Yes: Use container queries (@container)
   → No: Use viewport breakpoints

3. Does the interaction model change?
   → Yes: Different component variant (e.g., table → card view on mobile)
   → No: Same component, responsive classes
```

### 19.3 Progressive Enhancement Layers

| Layer | What it provides | When it activates |
| --- | --- | --- |
| Base | Mobile layout, stacked content, full-width | Always (0px+) |
| `sm` | Slightly wider spacing, 2-col grids | 640px+ |
| `md` | Sidebar visible, 12-col grid, desktop nav | 768px+ |
| `lg` | Full app shell, multi-pane layouts | 1024px+ |
| `xl` | Extra-wide content areas, side panels | 1280px+ |
| `2xl` | Marketing max-width, ultra-wide support | 1536px+ |

## 20. Container Query Deep Dive

### 20.1 Container Query Syntax

Tailwind v4 container queries use the `@` variant:

```blade
<div class="@container">
```

### 20.2 Named Containers

When a page has multiple container contexts, name them:

```blade
<div class="@container/dashboard">
    <div class="@lg:grid-cols-2 grid grid-cols-1 gap-4">
        {{-- This grid responds to the "dashboard" container width --}}
    </div>

    <div class="@md:block hidden">
        {{-- This responds to the "sidebar" container width --}}
    </div>
</div>
```

### 20.3 Container Query vs Viewport Query Decision

| Scenario | Container query | Viewport query |
| --- | --- | --- |
| Dashboard widget in different layouts | ✅ | ❌ |

| Card grid in a resizable panel | ✅ | ❌ |
| Navbar items visibility | ❌ | ✅ |
| Form layout in different widths | ✅ | ❌ |
| Modal full-screen on mobile | ❌ | ✅ |
| Table column hiding | Depends | Depends |

```javascript
test('all interactive elements meet touch target size on mobile', async ({ page }) => {
  await page.setViewportSize({ width: 375, height: 812 });
  await page.goto('/dashboard');

  const interactive = page.locator('button, a, [role="button"], input, select, textarea');
  for (const el of await interactive.all()) {
```

```javascript
test('no horizontal scroll on app shell', async ({ page }) => {

    return document.documentElement.scrollWidth > document.documentElement.clientWidth;
```

```javascript
test('content reflows at 400% zoom', async ({ page }) => {
```

## 26. Common Responsive Anti-Patterns

### 26.1 Breakpoint Jumps

```blade
{{-- ❌ Wrong: sudden jump from 1 to 3 columns --}}
<div class="grid grid-cols-1 lg:grid-cols-3 gap-4">

{{-- ✅ Correct: gradual progression --}}
<div class="grid grid-cols-1 sm:grid-cols-2 lg:grid-cols-3 gap-4">
```

### 26.2 Hidden Interactive Content

```blade
{{-- ❌ Wrong: hides search on mobile --}}
<div class="hidden md:block">
    <gsmui:search />
</div>

{{-- ✅ Correct: search adapts to viewport --}}
<gsmui:search class="w-full md:w-64" />
```

### 26.3 Fixed Pixel Values

```blade
{{-- ❌ Wrong: fixed pixel width --}}
<div style="width: 768px">

{{-- ✅ Correct: responsive width --}}
<div class="w-full md:w-96">
```

### 26.4 Ignoring Container Queries

```blade
{{-- ❌ Wrong: viewport query for widget in different-width containers --}}
<div class="lg:grid-cols-3">
    <div class="md:grid-cols-2"> {{-- Responds to viewport, not container --}}

{{-- ✅ Correct: container query for widget --}}
<div class="@container">
    <div class="@md:grid-cols-2"> {{-- Responds to container width --}}
```

### 26.5 Touch Target Violations

```blade
{{-- ❌ Wrong: tiny clickable area --}}
<gsmui:button size="xs" class="p-1">
    <gsmui:icon name="x-mark" variant="micro" />
</gsmui:button>

{{-- ✅ Correct: adequate touch target --}}
```

## 30. Responsive Design Contribution Guide

### 30.1 Adding Responsive Behavior to New Components

1. **Start mobile-first:** Write base styles for smallest viewport.
2. **Add breakpoints progressively:** `sm:` → `md:` → `lg:` → `xl:`.
3. **Test at each breakpoint:** Verify layout, interaction, accessibility.
4. **Document responsive behavior:** Add to component PRD's responsive section.
5. **Run Playwright tests:** Capture screenshots at all breakpoints.
6. **Check touch targets:** Measure on mobile viewport.
7. **Check container queries:** If component appears in different-width containers.

### 30.2 Responsive Naming Convention

| Pattern | Example |
| --- | --- |
| Mobile-only class | `lg:hidden` (hidden on desktop) |
| Desktop-only class | `hidden lg:block` (visible on desktop) |
| Responsive size | `size-8 sm:size-10 lg:size-12` |
| Responsive spacing | `p-4 sm:p-6 lg:p-8` |
| Responsive grid | `grid-cols-1 sm:grid-cols-2 lg:grid-cols-3` |

### 30.3 Responsive PRD Template


## 36. Responsive System Error Handling

### 36.1 Breakpoint Detection Errors

```javascript
// Fallback when matchMedia is not supported
function getBreakpoint() {
    if (!window.matchMedia) {
        return 'desktop'; // Default fallback
    }
    
    const breakpoints = [
        { name: '2xl', query: '(min-width: 1536px)' },
        { name: 'xl', query: '(min-width: 1280px)' },
        { name: 'lg', query: '(min-width: 1024px)' },
        { name: 'md', query: '(min-width: 768px)' },
        { name: 'sm', query: '(min-width: 640px)' },
    ];
    
    for (const bp of breakpoints) {
        if (window.matchMedia(bp.query).matches) {
            return bp.name;
        }
    }
    return 'base';
}
```

### 36.2 Responsive Error States

| Error | Symptom | Handling |
| --- | --- | --- |
| matchMedia not supported | Breakpoint detection fails | Default to desktop |
| Container query not supported | Widget not responsive | Fallback to viewport queries |
| Touch detection fails | Wrong interaction mode | Default to mouse |
| Orientation change fails | Layout stuck | Listen for resize event |

### 36.3 Graceful Degradation

```css
/* Fallback when container queries are not supported */
@supports not (container-type: inline-size) {
    .gsmui-widget {
        /* Use viewport-based responsive instead */
        width: 100%;
        max-width: 400px;
    }
    
    @media (min-width: 768px) {
        .gsmui-widget {
            max-width: 600px;
        }
    }
}
```
