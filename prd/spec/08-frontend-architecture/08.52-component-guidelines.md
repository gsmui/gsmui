# 08.52 - Component Guidelines

**Project:** GsmUi
**Section:** 08 - Frontend Architecture
**Framework:** GsmUi Component Library · Tailwind CSS v4 · Blade Components · Alpine.js
**Version:** 1.0.0

---

> See also: `08.50-folder-structure.md` (component namespace), `08.56-coding-standards.md` (general frontend standards). This document is the **authoritative component guideline**, pulled directly from `AGENTS.md`. It does NOT add new rules beyond those conventions.

# Purpose

This document is the single source of truth for how `gsmui:` components are named, styled, and wired. Every rule below is quoted/paraphrased verbatim from `AGENTS.md` so implementers can apply them without context-switching. Violations of these rules are launch blockers per the repo's verification policy.

---

## 1. Naming Conventions

- **Short, natural prop names.** `dropper` not `eye-dropper`. People will know what it means.
- **`-able` suffix for boolean opt-in behaviors.** `clearable`, `copyable`, `searchable`, `expandable`.
- **`type` prop for trigger variants.** `type="input"` vs `type="button"`, not boolean props like `:input="true"`.
- **Consistency across the library wins.**

---

## 2. Styling: Cursors

> `cursor-pointer` only belongs on interactive elements that perform some kind of navigation. Button elements and other clickable widgets should keep default cursor.

---

## 3. Styling: Focus Rings

> Prefer native browser outlines on natively-focusable elements (`<button>`, `<input>`). Add NO classes for focus on those. When a custom element with `tabindex="0"` (or a wrapper around an internal `<input type="range">`) needs visible focus, use the slider thumb pattern: `has-focus-visible:outline-2 has-focus-visible:outline-[-webkit-focus-ring-color]`. Never use `focus:outline-none focus:ring-2 focus:ring-(--color-accent)`.

---

## 6. Styling: Input

Copy classes from `gsmui/stubs/resources/views/gsmui/input/index.blade.php` outline variant. Don't restyle:

```html

border-zinc-200 border-b-zinc-300/80 dark:border-white/10
shadow-xs
rounded-lg
```

Reverting to native focus = no class.

## 7. Styling: Additional Rules

- **Numeric display:** `tabular-nums` when value will change rapidly and cause tiny jarring width-shifts.
- **Disabled on custom elements:** CSS `:disabled` only works on native form elements. Custom elements need `[&[disabled]]:shadow-none!` attribute selectors.
- **Invalid styling:** Layer `data-invalid:` classes on top of base styles. Never ternary-swap the entire class block. Match `gsmui:input` pattern.
- **Whole trigger = one input:** Clicking whitespace in a trigger container should focus the text input. `cursor: text` across the container, except over action buttons.
- **Pixel-level parity:** Measure with Playwright, don't guess. If the exact Tailwind value doesn't exist, use magic numbers like `pe-[9px]`. But strive for round Tailwind values. Bespoke hyper-specific pixel values are often a smell.
- **Critical visual states need explicit checks.** Empty, white-on-white, disabled, focus-visible states routinely hide problems.
- **Text sizes must match** across trigger variants and sibling components.
- **Lock scroll when popover is open.** Copy date-picker pattern.

---

## 8. JavaScript Conventions

- **Use `setAttribute`/`removeAttribute` from `utils.js`**, not native DOM methods (MutationObserver implications).
- **Move interaction logic from Alpine to JS** when it needs disabled-state awareness or component coordination. Alpine should be RARELY used.
- **Fire both `input` and `change` events** on keyboard changes (range spec). `change` fires on pointer commit, not popover close.
- **MutationObserver should watch `value` attribute** in addition to config attributes.
- **Lean on the browser.** `<canvas>` parses any CSS color — don't ship lookup tables or parsers.
- **2D area keyboard navigation:** Arrows move in grid; Home/End = horizontal edges; PageUp/PageDown = vertical edges.

---

## 9. Blade / PHP Conventions

- **Aria-labels must use `__()`** from Blade. JS uses the Blade-set value as primary; hardcoded English is only a fallback.
- **Use real `<gsmui:button>`** for action buttons (clear, copy, dropper) inside input triggers. Only use `<gsmui:button as="div">` when nested inside a `<button>` (nested-button constraint).
- **ARIA follows the closest pattern:** input trigger = `role="combobox"` on the `<input>`; button trigger = native `<button>` with `aria-haspopup="dialog"`.

---

## 10. Architecture & Docs Conventions

- Use existing JS mixins (Controllable, Disableable, Submittable, Focusable); don't force a bad abstraction.
- Compose components (color picker reuses `ui-slider`).
- **Sub-elements call methods on the state root.**
- **Use `detangle()`** to prevent sync loops between Controllable and internal state.
- **Labels only when contextually meaningful** (`label="hex"`, not `label="Clearable"`).
- **Previews dressed up, code blocks minimal** (`value="#0ea5e9"` vs `wire:model="color"`).
- **Remove all scaffolding/testing sections before shipping** (launch blocker).
- **Reference prop order:** wire:model, value, name, format, type, placeholder, size → behavioral props → label, description, disabled, invalid.
- **Document limitations honestly** (e.g. `copyable` doesn't work with `type="button"`).

## 12. Component Composition Patterns

### 12.1 Trigger + Popover Pattern

Used by: select, date-picker, color-picker, dropdown, tooltip

```blade
{{-- Trigger element --}}
<button
    type="button"
    role="combobox"
    aria-haspopup="listbox"
    aria-expanded="false"
    class="..."
>
    {{-- Trigger content --}}
    {{ $trigger ?? $value }}
    {{-- Trigger action (chevron, calendar icon) --}}
</button>

{{-- Popover (hidden by default) --}}
<div
    role="listbox"
    class="hidden ..."
    aria-label="{{ __($label) }}"
>
    {{ $slot }}
</div>
```

### 12.2 Input + Action Pattern

Used by: input, search-input, tag-input, color-picker

```blade
<div class="relative">
    {{-- Input --}}
    <input
        type="text"
        class="w-full ..."
        {{ $attributes }}
    />

    {{-- Action buttons (absolute positioned) --}}
    <div class="absolute right-0 top-0 h-full flex items-center">
        @if($clearable && $value)
            <button type="button" aria-label="{{ __('Clear') }}" class="...">
                {{-- X icon --}}
            </button>
        @endif
        @if($copyable)
            <button type="button" aria-label="{{ __('Copy') }}" class="...">
                {{-- Copy icon --}}
            </button>
        @endif
    </div>
</div>
```

### 12.3 Header + Content Pattern

Used by: accordion, tabs, modal, card

```blade
<div class="...">
    {{-- Header --}}
    <div class="..." role="button" aria-expanded="false" tabindex="0">
        {{ $header }}
    </div>

    {{-- Content (collapsible) --}}
    <div class="..." role="region" aria-labelledby="...">
        {{ $slot }}
    </div>
</div>
```

### 12.4 Composite Component Pattern

Used by: command-palette (modal + input + list), multi-select (select + chips), date-range-picker (two date-pickers)

```blade
{{-- Composite: command palette --}}
<div class="...">
    {{-- Search input --}}
    <input type="search" class="..." placeholder="{{ __('Search...') }}" />

    {{-- Results list --}}
    <div role="listbox" class="...">
        @foreach($results as $result)
            <div role="option" class="...">{{ $result }}</div>
        @endforeach
    </div>

    {{-- Footer --}}
    <div class="...">
        {{ $footer }}
    </div>
</div>
```

## 13. JavaScript Mixin Reference

### 13.1 Controllable Mixin

Provides two-way binding via `wire:model`:

```js
class Controllable {
  constructor(element) {
    this.element = element;
    this.value = element.getAttribute('value') || '';
  }

  setValue(newValue) {
    this.value = newValue;
    this.element.setAttribute('value', newValue);
    this.element.dispatchEvent(new CustomEvent('gsmui:change', {
      detail: { value: newValue },
      bubbles: true,
    }));
  }

  getValue() {
    return this.value;
  }
}
```

### 13.2 Disableable Mixin

Manages disabled state:

```js
class Disableable {
  constructor(element) {
    this.element = element;
    this.disabled = element.hasAttribute('disabled');
  }

  disable() {
    this.disabled = true;
    this.element.setAttribute('disabled', '');
    this.element.setAttribute('aria-disabled', 'true');
  }

  enable() {
    this.disabled = false;
    this.element.removeAttribute('disabled');
    this.element.removeAttribute('aria-disabled');
  }

  isDisabled() {
    return this.disabled;
  }
}
```

### 13.3 Submittable Mixin

Handles form submission:

```js
class Submittable {
  constructor(element) {
    this.element = element;
    this.form = element.closest('form');
  }

  submit() {
    if (this.form) {
      this.form.requestSubmit();
    }
  }

  reset() {
    this.setValue(this.defaultValue);
  }
}
```

### 13.4 Focusable Mixin

Manages focus and keyboard navigation:

```js
class Focusable {
  constructor(element) {
    this.element = element;
    this.setupKeyboardHandlers();
  }

  setupKeyboardHandlers() {
    this.element.addEventListener('keydown', e => {
      switch (e.key) {
        case 'Tab':
          this.handleTab(e);
          break;
        case 'Enter':
        case ' ':
          this.handleActivation(e);
          break;
        case 'Escape':
          this.handleEscape(e);
          break;
        case 'ArrowDown':
        case 'ArrowUp':
          this.handleArrowNavigation(e);
          break;
      }
    });
  }

  focus() {
    this.element.focus();
  }

  blur() {
    this.element.blur();
  }
}
```

### 14.2 Class Merging

```blade
@php
    $classes = Gsmui::classes([
        'base-classes',
        match($size) {
            'sm' => 'size-sm-classes',
            'xs' => 'size-xs-classes',
            default => 'size-default-classes',
        },
        $disabled ? 'disabled-classes' : null,
```

### 14.3 ARIA Attributes

```blade

    {{ $attributes->class($classes) }}

    @if($description) aria-describedby="{{ $id }}-description" @endif

    @if($description)
        <span id="{{ $id }}-description" class="sr-only">
            {{ __($description) }}
        </span>
    @endif
    {{ $slot }}
</div>
```


## 18. Dark Mode Implementation

### 18.1 Dark Mode Strategy

1. Toggle `.dark` on `<html>` via `setAttribute`
2. Persist to `localStorage`
3. Dispatch `gsmui:theme-changed` event
4. All components re-skin via `--gsmui-*` variable overrides

### 18.2 Dark Mode Classes

```blade
    bg-white dark:bg-zinc-800
    text-zinc-900 dark:text-zinc-100
    border-zinc-200 dark:border-zinc-700

    Content

```

### 18.3 Dark Mode Testing

```js
test('component renders correctly in dark mode', async ({ page }) => {
  await page.goto(STORY_ROUTES.component);
  await page.evaluate(() => {
    document.documentElement.classList.add('dark');
```

## 23. Component Lifecycle

### 23.1 Initialization

1. Blade renders component HTML
2. `gsmui.js` finds `[data-gsmui-component]` elements
3. Mixins are applied (Controllable, Disableable, etc.)
4. MutationObserver is registered
5. Initial state is synced from attributes

### 23.2 Update

1. User interaction triggers event
2. Event dispatches `gsmui:input` and `gsmui:change`
3. `wire:model` updates Livewire property
4. Livewire sends signed payload to server
5. Server processes and returns response
6. Livewire hydrates and re-renders component
7. MutationObserver detects attribute change
8. Component reconciles UI

### 23.3 Cleanup

1. Component is removed from DOM
2. MutationObserver is disconnected
3. Event listeners are removed
4. Timers are cleared
5. References are nullified

## 26. Complete Component Examples

### 26.1 Button Component

```blade
@props([
    'type' => 'button',
    'size' => 'default',
    'disabled' => false,
])

@php
    $classes = Gsmui::classes([
        'inline-flex items-center justify-center',
        'rounded-lg font-medium',
        'transition-colors',
        match($size) {
            'sm' => 'h-8 px-3 text-sm',
            'xs' => 'h-6 px-2 text-xs',
            default => 'h-10 px-4 text-base sm:text-sm',
        },
        match($type) {
            'primary' => 'bg-blue-600 text-white hover:bg-blue-700',
            'danger' => 'bg-red-600 text-white hover:bg-red-700',
            default => 'bg-zinc-100 dark:bg-zinc-800 text-zinc-900 dark:text-zinc-100',
        },
        $disabled ? 'opacity-50 cursor-not-allowed' : null,
    ]);
@endphp

<button
    type="{{ $type }}"
    {{ $attributes->class($classes) }}
    @if($disabled) disabled aria-disabled="true" @endif
>
    {{ $slot }}
</button>
```

```blade
{{-- Renderless component — provides state only --}}
@gsmui::color-picker(
    wire:model="color",
    x-slot="{ value, setValue, open, close }"
)
    {{-- Custom trigger --}}
    <button @click="open">
        Current color: {{ $value }}
    </button>

    {{-- Custom popover --}}

        <div class="...">
```

### 27.3 Controlled vs Uncontrolled

```blade
{{-- Controlled (Livewire manages state) --}}
<gsmui:select wire:model="selectedOption" :options="$options" />

{{-- Uncontrolled (component manages state) --}}
<gsmui:select value="option1" :options="$options" />

{{-- Hybrid (initial value, then Livewire) --}}
<gsmui:select wire:model="selectedOption" value="option1" :options="$options" />
```

## 35. JavaScript Patterns

### 35.1 Component Registration

```js
// Register component type
const registry = new Map();

registry.set('color-picker', ColorPickerComponent);
registry.set('date-picker', DatePickerComponent);
registry.set('select', SelectComponent);

// Initialize all components
function initComponents() {
  document.querySelectorAll('[data-gsmui-component]').forEach(el => {
    const type = el.dataset.gsmuiComponent;
    const ComponentClass = registry.get(type);
    if (ComponentClass) {
      new ComponentClass(el);
    }
  });
}
```

### 35.2 State Management

```js
// Component state
class ComponentState {
  constructor(element) {
    this.element = element;
    this.listeners = new Map();
  }

  get(key) {
    return this.element.getAttribute(`data-${key}`);
  }

  set(key, value) {
    this.element.setAttribute(`data-${key}`, value);
    this.notify(key, value);
  }

  on(key, callback) {
    if (!this.listeners.has(key)) {
      this.listeners.set(key, []);
    }
    this.listeners.get(key).push(callback);
  }

  notify(key, value) {
    const callbacks = this.listeners.get(key) || [];
    callbacks.forEach(cb => cb(value));
  }
}
```

### 35.3 Attribute Synchronization

```js
// Sync attribute changes to state
function observeAttributes(element, state) {
  const observer = new MutationObserver(mutations => {
    mutations.forEach(mutation => {
      if (mutation.type === 'attributes') {
        const attr = mutation.attributeName;
        state.set(attr, element.getAttribute(attr));
      }
    });
  });

  observer.observe(element, {
    attributes: true,
    attributeFilter: ['value', 'disabled', 'invalid', 'size'],
  });

  return observer;
}
```

### 42.3 Tab Trap (Modal)

```js
function trapFocus(container) {
  const focusable = container.querySelectorAll(
    'button, [href], input, select, textarea, [tabindex]:not([tabindex="-1"])'
  );
  const first = focusable[0];
  const last = focusable[focusable.length - 1];

  container.addEventListener('keydown', (e) => {
    if (e.key !== 'Tab') return;

    if (e.shiftKey) {
      if (document.activeElement === first) {
        e.preventDefault();
        last.focus();
      }
    } else {
      if (document.activeElement === last) {
        e.preventDefault();
        first.focus();
      }
    }
  });
}
```

```js
function lockScroll() {
  document.body.style.overflow = 'hidden';
  document.documentElement.style.overflow = 'hidden';
}

function unlockScroll() {
  document.body.style.overflow = '';
  document.documentElement.style.overflow = '';
}
```

### 43.2 State Machine Implementation

```js
class ComponentStateMachine {
  constructor(element) {
    this.element = element;
    this.state = 'mounted';
    this.transitions = {
      mounted: { init: 'ready' },
      ready: { disable: 'disabled', focus: 'focused', blur: 'blurred' },
      disabled: { enable: 'ready' },
      focused: { blur: 'blurred', open: 'open' },
      blurred: { focus: 'focused' },
      open: { close: 'closed', select: 'selected' },
      closed: { open: 'open' },
      selected: { open: 'open' },
    };
  }

  transition(event) {
    const currentState = this.transitions[this.state];
    if (currentState && currentState[event]) {
      this.state = currentState[event];
      this.onStateChange(this.state);
    }
  }

  onStateChange(state) {
    this.element.setAttribute('data-state', state);
    this.element.dispatchEvent(new CustomEvent('gsmui:statechange', {
      detail: { state },
    }));
  }
}
```

```js
function validateInput(input, rules) {
  const errors = [];

  if (rules.required && !input.value) {
    errors.push('This field is required');
  }

  if (rules.minLength && input.value.length < rules.minLength) {
    errors.push(`Minimum ${rules.minLength} characters`);
  }

  if (rules.maxLength && input.value.length > rules.maxLength) {
    errors.push(`Maximum ${rules.maxLength} characters`);
  }

  if (rules.pattern && !rules.pattern.test(input.value)) {
    errors.push(rules.patternMessage || 'Invalid format');
  }

  return errors;
}
```
