# 08.06 - CSS Architecture

**Project:** GsmUi
**Section:** 08 - Frontend Architecture
**Framework:** Tailwind CSS v4 · CSS Variables · Vite · Design Token Engine
**Version:** 1.0.0

---

> See also: `07.57-security.md` (CSP policy), `08.04-theme-architecture.md` (runtime tokens), `08.05-tailwind-v4.md` (utility config). This document specifies the *CSS layering, dynamic-style strategy, and CSP-safe rules* and does NOT re-document the token or theme models.

# Purpose

This document defines how GsmUi CSS is layered and ordered, how dynamic (runtime theme) styles are injected without violating CSP, and how dark mode is resolved in the cascade. It is the contract that keeps component styles, Tailwind utilities, and runtime tokens from fighting each other.

---

## 1. CSS Layers

Styles are organized with native CSS `@layer` plus Tailwind's internal layers. Order is lowest→highest priority:

| Layer | Source | Contents |
| --- | --- | --- |
| `base` | Tailwind + GsmUi reset | Element defaults, `:root` token declarations |
| `components` | `gsmui:` component CSS | Trigger, popover, input structural styles |
| `utilities` | Tailwind utilities | Spacing, color, layout helpers |
| `runtime` | `adoptedStyleSheets` | Live theme token overrides (highest) |

```css
@layer base, components, utilities, runtime;
```

Rule: component structural classes live in `components`; all modifier/state styling uses utilities or `data-*` attributes in `utilities`/`runtime`.

---

## 2. Dynamic CSS via `adoptedStyleSheets`

Per AGENTS.md §CSP, dynamic CSS must use `adoptedStyleSheets` rather than inline `<style>` tags. The theme builder (`08.04-theme-architecture.md`) pushes runtime tokens this way.

```js
// Conceptual (lives in dist/gsmui.js)
const sheet = new CSSStyleSheet();
sheet.replaceSync(`:root{--gsmui-color-accent:${value}}`);
document.adoptedStyleSheets = [...document.adoptedStyleSheets, sheet];
```

| Approach | CSP verdict |
| --- | --- |
| `adoptedStyleSheets` | ✅ Allowed (`style-src 'self' 'unsafe-inline'` tolerant) |
| Inline `<style>` injection | ❌ Avoided (prefer adoptedStyleSheets) |
| CDN `<link>` to external CSS | ❌ Forbidden (zero external resources) |

---

## 3. CSP-Safe Styling Rules

From AGENTS.md §CSP and `07.57-security.md`:

- **Scripts:** self-hosted `dist/gsmui.js` only → `script-src 'self'`.
- **Styles:** `dist/editor.css` + `adoptedStyleSheets` → `style-src 'self' 'unsafe-inline'`.
- **Fonts:** system fonts only, no `@font-face` → no `font-src` needed.
- **Images:** inline SVG icons only → `img-src 'self' data:`.
- **Network:** no `fetch`/XHR/WebSocket/Worker → `connect-src 'self'`.
- **Eval:** no `eval()`/`Function()`/`blob:`/`data:` executable → no `unsafe-eval`.

The publishable CSP config lives at `stubs/config/gsmui-pro-csp.php`; middleware at `src/Http/Middleware/CspMiddleware.php`. Test surface: `tests/Browser/CspHeaderTest.php` and `/gsmui-csp-test` route.

## 4. Cascade & Ordering

| Concern | Resolution |
| --- | --- |
| Invalid state | Layered `data-invalid:` over base — never ternary-swap class block |
| Disabled | Native `:disabled` + `[&[disabled]]:shadow-none!` on custom elements |
| Focus | Native outline on `<button>`/`<input>`; `has-focus-visible:outline-2` on custom `tabindex` |
| Popover/dialog | `max-sm:fixed! max-sm:inset-0! sm:backdrop:bg-transparent bg-white dark:bg-zinc-700 …` |

## 5. Dark-Mode Strategy

Dark mode is scope-attribute driven (`08.04-theme-architecture.md`, `08.43-dark-mode.md`):

```css
:root { color-scheme: light; }
[data-theme="dark"] { color-scheme: dark; }
@custom-variant dark (&:where([data-theme="dark"], [data-theme="dark"] *));
```

Tokens flip via `--gsmui-*` pairs; `dark:` utilities resolve against the scope. No per-element class toggling in components.

## 6. CSS Layer Ordering Deep Dive

### 6.1 Layer Priority Chain

The CSS layer ordering determines which styles win when there's a conflict. Understanding this cascade is essential for writing correct component styles.

```css
/* Layer declaration - lowest to highest priority */
@layer base, components, utilities, runtime;
```

| Layer | Priority | Content | Override Rule |
| --- | --- | --- | --- |
| `base` | 1 (lowest) | Reset, `:root` tokens, element defaults | Overridden by everything |
| `components` | 2 | `gsmui:` structural styles | Overridden by utilities and runtime |
| `utilities` | 3 | Tailwind utility classes | Overridden by runtime only |
| `runtime` | 4 (highest) | `adoptedStyleSheets` theme overrides | Wins over everything |

### 6.2 Layer Interaction Examples

```text
Scenario 1: Button background
  base:     (none)
  components: .gsmui-button { background: var(--gsmui-color-surface); }
  utilities:  .bg-accent { background: var(--gsmui-color-accent); }
  runtime:   (none)
  Result: bg-accent wins (utility > component)

Scenario 2: Theme override
  base:     :root { --gsmui-color-accent: #2563eb; }
  components: (none)
  utilities:  .bg-accent { background: var(--gsmui-color-accent); }
  runtime:   :root { --gsmui-color-accent: #10b981; }
  Result: Runtime wins (runtime > base)
```

### 6.3 Layer Conflict Resolution

| Conflict | Resolution | Example |
| --- | --- | --- |
| Component vs Utility | Utility wins | `bg-accent` overrides `.gsmui-button { background }` |
| Utility vs Runtime | Runtime wins | `adoptedStyleSheets` overrides utility |
| Component vs Runtime | Runtime wins | Theme override wins |
| Base vs Component | Component wins | Token reset overridden by component style |
| `!important` in any layer | Wins regardless | `shadow-none!` overrides any shadow |

## 7. `adoptedStyleSheets` Implementation

### 7.1 Browser Support

| Browser | Version | Support |
| --- | --- | --- |
| Chrome | 73+ | Full |
| Firefox | 101+ | Full |
| Safari | 16.4+ | Full |
| Edge | 79+ | Full |
| IE 11 | — | Not supported (polyfill needed for legacy) |

### 7.2 Implementation Pattern

```js
// Conceptual: Theme token injector (lives in dist/gsmui.js)
class GsmuiThemeInjector {
    constructor() {
        this.sheet = new CSSStyleSheet();
        this.rules = [];
    }

    updateToken(name, value) {
        this.rules = this.rules.filter(r => !r.includes(name));
        this.rules.push(`:root { ${name}: ${value}; }`);
        this.sheet.replaceSync(this.rules.join('\n'));
    }

    apply() {
        document.adoptedStyleSheets = [
            ...document.adoptedStyleSheets.filter(s => s !== this.sheet),
            this.sheet,
        ];
    }
}
```

### 7.3 Managed Sheet Strategy

To prevent unbounded growth on repeated builder updates, GsmUi uses a single managed `CSSStyleSheet`:

```text
1. Create one CSSStyleSheet per theme context
2. On token update: modify rules in the sheet
3. Replace sheet content with replaceSync()
4. Sheet reference stays stable across updates
```

| Strategy | Benefit |
| --- | --- |
| Single sheet per context | No memory leaks from abandoned sheets |
| `replaceSync()` | Atomic update, no partial renders |
| Rule deduplication | Only latest value per token in sheet |
| Cleanup on unmount | Remove sheet from `adoptedStyleSheets` |

### 7.4 Performance Characteristics

| Operation | Time | Memory |
| --- | --- | --- |
| Create sheet | < 1ms | ~100 bytes |
| Replace content | < 5ms | Constant |
| Apply to document | < 1ms | Reference only |
| Token update (single) | < 2ms | ~50 bytes |
| Batch token update (10) | < 10ms | ~500 bytes |

## 8. CSS Custom Properties Strategy

### 8.1 Property Declaration Scope

| Scope | Example | Lifetime | Use Case |
| --- | --- | --- | --- |
| `:root` | `--gsmui-color-accent` | Page lifetime | Global theme tokens |
| Component | `--gsmui-button-bg` | Component lifetime | Component-specific tokens |
| Local | `style="--local: value"` | Element lifetime | Instance overrides |
| Media query | `@container` | Container lifetime | Responsive tokens |

### 8.2 Property Inheritance

```css
/* Global tokens on :root - inherited by all elements */
:root {
    --gsmui-color-accent: #2563eb;
    --gsmui-space-4: 16px;
}

/* Component tokens - scoped to component */
[data-gsmui-button] {
    --gsmui-button-bg: var(--gsmui-color-accent);
    background: var(--gsmui-button-bg);
}

/* Local override - scoped to element */
<div style="--gsmui-button-bg: #10b981">
    <!-- This button uses green -->
</div>
```

### 8.3 Property Fallback Chains

```css
/* Three-level fallback: component → semantic → raw palette */
.gsmui-button-primary {
    background: var(
        --gsmui-button-primary-bg,
        var(
            --gsmui-color-accent,
            #2563eb
        )
    );
}
```

### 8.4 Property Validation

Tokens are validated before being injected:

```js
function validateTokenValue(name, value) {
    // Color tokens must be valid CSS color
    if (name.includes('color')) {
        const testEl = document.createElement('div');
        testEl.style.color = value;
        if (!testEl.style.color) return getDefaultValue(name);
    }

    // Spacing tokens must be valid CSS length
    if (name.includes('space')) {
        const testEl = document.createElement('div');
        testEl.style.padding = value;
        if (!testEl.style.padding) return getDefaultValue(name);
    }

    return value;
}
```

## 9. CSS Containment Strategy

### 9.1 Containment Types

| Type | CSS Value | Purpose | Use Case |
| --- | --- | --- | --- |
| Layout | `contain: layout` | Isolate layout calculations | Cards, panels |
| Style | `contain: style` | Isolate counter/quote scope | List items, tables |
| Paint | `contain: paint` | Clip to bounding box, isolate paint | Popovers, modals |
| Size | `contain: size` | Element size independent of children | Virtual list items |
| Content | `contain: content` | Shorthand for layout + style + paint | Most components |

### 9.2 Containment Application

```blade
{{-- Card with containment --}}
<div @class([
    Gsmui::classes(
        'relative contain-content',
        'bg-surface border border-border shadow-sm rounded-xl p-4',
    ),
])>
    {{ $slot }}
</div>

{{-- Modal with full containment --}}
<div @class([
    Gsmui::classes(
        'fixed inset-0 contain-layout',
        'z-modal',
    ),
])>
    {{-- Modal content --}}
</div>
```

### 9.3 Containment Performance Impact

| Containment | Layout Cost | Paint Cost | Memory Cost |
| --- | --- | --- | --- |
| None | High (global reflow) | High (full repaint) | Low |
| `layout` | Low (isolated) | High | Low |
| `paint` | Medium | Low (clipped) | Low |
| `content` | Low | Low | Low |
| `size` | Lowest | Lowest | Medium (pre-computed) |

### 9.4 Containment Limitations

| Limitation | Impact | Workaround |
| --- | --- | --- |
| `size` breaks intrinsic sizing | Element needs explicit size | Use `min-content` or fixed size |
| `layout` breaks `counter()` | Counters don't escape container | Use global counters |
| `paint` clips overflow | Content outside bounds hidden | Use `overflow: visible` when needed |

## 18. CSS Performance Optimization

### 18.1 Selector Performance

| Pattern | Performance | Recommendation |
| --- | --- | --- |
| `.class` | Fast | Use for component selectors |
| `.class .child` | Medium | Limit to 2 levels max |
| `.class > .child` | Fast | Prefer direct children |
| `*` | Slow | Avoid in component CSS |
| `[data-attr]` | Medium | Use for state selectors |
| `:is()` | Medium | Use for grouping |
| `:has()` | Slow | Use sparingly |

### 18.2 Property Performance

| Property | Cost | Recommendation |
| --- | --- | --- |
| `transform` | Low (GPU) | Use for animations |
| `opacity` | Low (GPU) | Use for fade animations |
| `color` | Low | Safe to animate |
| `background-color` | Low | Safe to animate |
| `width` | High (layout) | Avoid animating |
| `height` | High (layout) | Avoid animating |
| `top`/`left` | High (layout) | Use `transform` instead |
| `margin` | High (layout) | Avoid animating |

## 19. CSS Customization API

### 19.1 Consumer Override Points

Consumers can override GsmUi styles at these points:

| Override Point | Method | Risk Level |
| --- | --- | --- |
| Theme tokens | `--gsmui-*` CSS variables | Low (designed for this) |
| Component classes | `class` attribute | Low (designed for this) |
| Global styles | `@layer base` | Medium (affects all components) |
| Component styles | `@layer components` | High (can break components) |
| Runtime styles | `adoptedStyleSheets` | High (intended for theme builder) |

### 19.2 Safe Customization Pattern

```css
/* Safe: Override via tokens */
:root {
    --gsmui-color-accent: #10b981; /* Green accent */
}

/* Safe: Override via utility classes */
<gsmui:button class="bg-green-500 hover:bg-green-600">Green</gsmui:button>

/* Risky: Override via CSS layers */
@layer components {
    .gsmui-button { border-radius: 0; } /* Breaks button design */
}
```

## 24. CSS Architecture Deep Dive

### 24.1 Layer Cascade Order

The CSS layer ordering determines which styles win when there's a conflict. Understanding this cascade is essential for writing correct component styles.

```css
/* Layer declaration - lowest to highest priority */
@layer base, components, utilities, runtime;
```

| Layer | Priority | Content | Override Rule |
| --- | --- | --- | --- |
| `base` | 1 (lowest) | Reset, `:root` tokens, element defaults | Overridden by everything |
| `components` | 2 | `gsmui:` structural styles | Overridden by utilities and runtime |
| `utilities` | 3 | Tailwind utility classes | Overridden by runtime only |
| `runtime` | 4 (highest) | `adoptedStyleSheets` theme overrides | Wins over everything |

### 24.2 Layer Interaction Examples

```text
Scenario 1: Button background
  base:     (none)
  components: .gsmui-button { background: var(--gsmui-color-surface); }
  utilities:  .bg-accent { background: var(--gsmui-color-accent); }
  runtime:   (none)
  Result: bg-accent wins (utility > component)

Scenario 2: Theme override
  base:     :root { --gsmui-color-accent: #2563eb; }
  components: (none)
  utilities:  .bg-accent { background: var(--gsmui-color-accent); }
  runtime:   :root { --gsmui-color-accent: #10b981; }
  Result: Runtime wins (runtime > base)
```

### 24.3 Layer Conflict Resolution

| Conflict | Resolution | Example |
| --- | --- | --- |
| Component vs Utility | Utility wins | `bg-accent` overrides `.gsmui-button { background }` |
| Utility vs Runtime | Runtime wins | `adoptedStyleSheets` overrides utility |
| Component vs Runtime | Runtime wins | Theme override wins |
| Base vs Component | Component wins | Token reset overridden by component style |
| `!important` in any layer | Wins regardless | `shadow-none!` overrides any shadow |

## 25. `adoptedStyleSheets` Implementation

### 25.1 Browser Support

| Browser | Version | Support |
| --- | --- | --- |
| Chrome | 73+ | Full |
| Firefox | 101+ | Full |
| Safari | 16.4+ | Full |
| Edge | 79+ | Full |
| IE 11 | — | Not supported (polyfill needed for legacy) |

### 25.2 Implementation Pattern

```js
// Conceptual: Theme token injector (lives in dist/gsmui.js)
class GsmuiThemeInjector {
    constructor() {
        this.sheet = new CSSStyleSheet();
        this.rules = [];
    }

    updateToken(name, value) {
        this.rules = this.rules.filter(r => !r.includes(name));
        this.rules.push(`:root { ${name}: ${value}; }`);
        this.sheet.replaceSync(this.rules.join('\n'));
    }

    apply() {
        document.adoptedStyleSheets = [
            ...document.adoptedStyleSheets.filter(s => s !== this.sheet),
            this.sheet,
        ];
    }
}
```

### 25.3 Managed Sheet Strategy

To prevent unbounded growth on repeated builder updates, GsmUi uses a single managed `CSSStyleSheet`:

```text
1. Create one CSSStyleSheet per theme context
2. On token update: modify rules in the sheet
3. Replace sheet content with replaceSync()
4. Sheet reference stays stable across updates
```

| Strategy | Benefit |
| --- | --- |
| Single sheet per context | No memory leaks from abandoned sheets |
| `replaceSync()` | Atomic update, no partial renders |
| Rule deduplication | Only latest value per token in sheet |
| Cleanup on unmount | Remove sheet from `adoptedStyleSheets` |

### 25.4 Performance Characteristics

| Operation | Time | Memory |
| --- | --- | --- |
| Create sheet | < 1ms | ~100 bytes |
| Replace content | < 5ms | Constant |
| Apply to document | < 1ms | Reference only |
| Token update (single) | < 2ms | ~50 bytes |
| Batch token update (10) | < 10ms | ~500 bytes |

## 26. CSS Custom Properties Strategy

### 26.1 Property Declaration Scope

| Scope | Example | Lifetime | Use Case |
| --- | --- | --- | --- |
| `:root` | `--gsmui-color-accent` | Page lifetime | Global theme tokens |
| Component | `--gsmui-button-bg` | Component lifetime | Component-specific tokens |
| Local | `style="--local: value"` | Element lifetime | Instance overrides |

### 26.2 Property Inheritance

```css

    --gsmui-color-accent: #2563eb;
    --gsmui-space-4: 16px;

    --gsmui-button-bg: var(--gsmui-color-accent);
    background: var(--gsmui-button-bg);
}

/* Local override - scoped to element */
<div style="--gsmui-button-bg: #10b981">
    <!-- This button uses green -->
</div>
```

### 26.3 Property Fallback Chains

```css
/* Three-level fallback: component → semantic → raw palette */
.gsmui-button-primary {
    background: var(
        --gsmui-button-primary-bg,
        var(
            --gsmui-color-accent,
            #2563eb
        )
    );
}
```

### 26.4 Property Validation

Tokens are validated before being injected:

```js
function validateTokenValue(name, value) {
    // Color tokens must be valid CSS color
    if (name.includes('color')) {
        const testEl = document.createElement('div');
        testEl.style.color = value;
        if (!testEl.style.color) return getDefaultValue(name);
    }

    // Spacing tokens must be valid CSS length
    if (name.includes('space')) {
        const testEl = document.createElement('div');
        testEl.style.padding = value;
        if (!testEl.style.padding) return getDefaultValue(name);
    }

    return value;
}
```

## 27. CSS Containment Strategy

### 27.1 Containment Types

| Type | CSS Value | Purpose | Use Case |
| --- | --- | --- | --- |
| Layout | `contain: layout` | Isolate layout calculations | Cards, panels |
| Style | `contain: style` | Isolate counter/quote scope | List items, tables |
| Paint | `contain: paint` | Clip to bounding box, isolate paint | Popovers, modals |
| Size | `contain: size` | Element size independent of children | Virtual list items |
| Content | `contain: content` | Shorthand for layout + style + paint | Most components |

### 27.2 Containment Application

```blade
{{-- Card with containment --}}
<div @class([
    Gsmui::classes(
        'relative contain-content',
        'bg-surface border border-border shadow-sm rounded-xl p-4',
    ),
])>
    {{ $slot }}
</div>

{{-- Modal with full containment --}}
<div @class([
    Gsmui::classes(
        'fixed inset-0 contain-layout',
        'z-modal',
    ),
])>
    {{-- Modal content --}}
</div>
```

### 27.3 Containment Performance Impact

| Containment | Layout Cost | Paint Cost | Memory Cost |
| --- | --- | --- | --- |
| None | High (global reflow) | High (full repaint) | Low |
| `layout` | Low (isolated) | High | Low |
| `paint` | Medium | Low (clipped) | Low |
| `content` | Low | Low | Low |
| `size` | Lowest | Lowest | Medium (pre-computed) |

### 27.4 Containment Limitations

| Limitation | Impact | Workaround |
| --- | --- | --- |
| `size` breaks intrinsic sizing | Element needs explicit size | Use `min-content` or fixed size |
| `layout` breaks `counter()` | Counters don't escape container | Use global counters |
| `paint` clips overflow | Content outside bounds hidden | Use `overflow: visible` when needed |

## 37. CSS Customization API

### 37.1 Consumer Override Points

Consumers can override GsmUi styles at these points:

| Override Point | Method | Risk Level |
| --- | --- | --- |
| Theme tokens | `--gsmui-*` CSS variables | Low (designed for this) |
| Component classes | `class` attribute | Low (designed for this) |
| Global styles | `@layer base` | Medium (affects all components) |
| Component styles | `@layer components` | High (can break components) |
| Runtime styles | `adoptedStyleSheets` | High (intended for theme builder) |

### 37.2 Safe Customization Pattern

```css
/* Safe: Override via tokens */
:root {
    --gsmui-color-accent: #10b981; /* Green accent */
}

/* Safe: Override via utility classes */
<gsmui:button class="bg-green-500 hover:bg-green-600">Green</gsmui:button>

/* Risky: Override via CSS layers */
@layer components {
    .gsmui-button { border-radius: 0; } /* Breaks button design */
}
```

## 38. CSS Architecture Decisions

### 38.1 Why CSS Layers

| Reason | Benefit |
| --- | --- |
| Predictable cascade | Clear override rules |
| No specificity wars | Layer order determines winner |
| Third-party integration | Consumer styles in `utilities` layer |
| Future-proofing | New layers can be added without breaking |

### 38.2 Why `adoptedStyleSheets`

| Reason | Benefit |
| --- | --- |
| CSP safe | No inline `<style>` needed |
| Performance | Single DOM operation to apply |
| Memory efficient | Sheet reference, not DOM nodes |
| Atomic updates | `replaceSync()` for instant changes |

### 38.3 Why Logical Properties

| Reason | Benefit |
| --- | --- |
| RTL support | No separate RTL stylesheet |
| Consistency | One property, all directions |
| Future-proofing | Native CSS feature |
| Smaller bundle | No RTL overrides needed |

## 39. CSS Migration Guide

### 39.1 v3 to v4 Migration

| Area | v3 Approach | v4 Approach |
| --- | --- | --- |
| Config | `tailwind.config.js` | CSS `@theme` block |
| Custom utilities | JS plugins | `@utility` directive |
| Dark mode | `darkMode: 'class'` | `@custom-variant dark` |
| Layer ordering | Manual | `@layer` directive |
| Content detection | `content: [...]` | Automatic |

### 39.2 Breaking Changes

| Change | Impact | Migration |
| --- | --- | --- |
| Config file removed | Build breaks | Replace with `@theme` in CSS |
| Plugin system changed | Custom plugins break | Convert to `@utility` or `@plugin` |
| Dark mode syntax changed | Dark mode breaks | Update to `@custom-variant dark` |
| PostCSS no longer needed | Build config change | Use `@tailwindcss/vite` plugin |
