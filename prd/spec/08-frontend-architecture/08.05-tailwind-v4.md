**Project:** GsmUi
**Section:** 08 - Frontend Architecture
**Framework:** Tailwind CSS v4 · Vite · CSS Variables · Design Token Engine
**Version:** 1.0.0

---

> See also: `08.03-design-tokens.md` (token variables), `08.06-css-architecture.md` (CSS layering), `08.04-theme-architecture.md` (runtime tokens). This document specifies the *Tailwind v4 CSS-first configuration and Vite integration* and does NOT re-document token taxonomy.

# Purpose

This document defines the Tailwind CSS v4 setup for GsmUi: the CSS-first configuration via `@theme`/`@utility`/`@layer`, the Vite plugin wiring, and the concrete v3→v4 diffs an implementer must apply. It is the canonical reference for how utilities, design tokens, and the `gsmui:` component classes interoperate.

---

## 1. CSS-First Configuration

Tailwind v4 drops `tailwind.config.js` in favor of CSS-driven config. All GsmUi config lives in a primary stylesheet entry.

```css
@import "tailwindcss";

@theme {
  /* Map design tokens to Tailwind utilities */
  --color-accent: var(--gsmui-color-accent);
  --radius-lg: var(--gsmui-radius-lg);
  --text-sm: var(--gsmui-text-sm);
  --shadow-xs: var(--gsmui-shadow-xs);
  --spacing: var(--gsmui-space-1);
  --z-popover: var(--gsmui-z-popover);
}

@utility gsmui-surface {
  background: var(--gsmui-color-surface);
  border: 1px solid var(--gsmui-color-border);
}
```

| Directive | Purpose in GsmUi |
| --- | --- |
| `@import "tailwindcss"` | Loads the engine (replaces config file) |
| `@theme` | Binds `--gsmui-*` tokens to utilities (`bg-accent`, `rounded-lg`) |
| `@utility` | Declares custom component utilities (e.g. `gsmui-surface`) |
| `@layer` | Orders base/components/utilities for cascade control |

---

## 2. Vite Plugin

Tailwind v4 uses the `@tailwindcss/vite` plugin — no PostCSS config required.

```js
// vite.config.js
import { defineConfig } from "vite";
import tailwindcss from "@tailwindcss/vite";

export default defineConfig({
  plugins: [tailwindcss()],
});
```

| Concern | Rule |
| --- | --- |
| Entry CSS | Single `resources/css/app.css` importing `tailwindcss` |
| JS bundle | `dist/gsmui.js` (upstream) + app bundle via Vite |
| CSP | No CDN; everything self-hosted (AGENTS.md §CSP) |
| Source maps | Enabled in dev, stripped in prod |

---

## 3. v3 → v4 Diffs

| Area | v3 | v4 (GsmUi) |
| --- | --- | --- |
| Config | `tailwind.config.js` | CSS `@theme` block |
| Content | `content: [...]` globs | Automatic source detection |
| Dark mode | `darkMode: 'class'` | `@custom-variant dark` bound to scope attr |
| Plugins | JS plugin files | `@plugin` / CSS `@utility` |
| Color opacity | `bg-black/50` | Same, but opacity via color-mix |
| Install | `tailwindcss postcss autoprefixer` | `tailwindcss @tailwindcss/vite` |

```css
/* v4 dark variant bound to GsmUi scope */
@custom-variant dark (&:where([data-theme="dark"], [data-theme="dark"] *));
```

---

## 4. Utility ↔ Token Contract

- Utilities reference tokens through `@theme` indirection; component Blade uses utilities, not raw `var(--gsmui-*)`.
- Tailwind's default scale remains as fallback (`08.03-design-tokens.md` §4).
- Arbitrary values (e.g. `pe-[9px]`) are permitted only when a round Tailwind value does not exist (AGENTS.md "Pixel-level parity").

---

## 5. Component Class Interop

`gsmui:` components emit Tailwind utilities plus `--gsmui-*` references. The cascade order is: Tailwind base → GsmUi component layer → utility overrides. See `08.06-css-architecture.md` for the full layering and `08.07-blade-component-system.md` for component emission.

---

## 6. Open Questions / Risks

- **Token hot-reload:** Confirm Vite HMR picks up `@theme` changes when tokens shift in the builder.
- **Prefix collision:** If a consumer app also runs Tailwind v4, namespace custom utilities with `gsmui-` to avoid clashes.

## 7. Tailwind v4 Configuration Deep Dive

### 7.1 The `@theme` Block

The `@theme` block is the heart of Tailwind v4 configuration. It replaces the entire `tailwind.config.js` file with CSS-native configuration.

```css

    --color-bg: var(--gsmui-color-bg);
    --color-surface: var(--gsmui-color-surface);
    --color-surface-hover: var(--gsmui-color-surface-hover);
    --color-surface-active: var(--gsmui-color-surface-active);
```

### 7.2 The `@utility` Directive

Custom utilities are declared with `@utility`, replacing JS plugins:

```css
/* Custom utility for GsmUi surfaces */
@utility gsmui-surface {
    background: var(--gsmui-color-surface);
    border: 1px solid var(--gsmui-color-border);
}

/* Custom utility for GsmUi cards */
@utility gsmui-card {
    background: var(--gsmui-color-surface);
    border: 1px solid var(--gsmui-color-border);
    border-radius: var(--gsmui-radius-xl);
    box-shadow: var(--gsmui-shadow-sm);
    padding: var(--gsmui-space-4);
}

/* Custom utility for GsmUi triggers */
@utility gsmui-trigger {
    background: var(--gsmui-color-bg);
    border: 1px solid var(--gsmui-color-border);
    border-radius: var(--gsmui-radius-lg);
    box-shadow: var(--gsmui-shadow-xs);
}

/* Custom utility for GsmUi popovers */
@utility gsmui-popover {
    background: var(--gsmui-color-bg);
    border: 1px solid var(--gsmui-color-border);
    border-radius: var(--gsmui-radius-xl);
    box-shadow: var(--gsmui-shadow-xl);
    padding: var(--gsmui-space-3);
}

/* Custom animation utilities */
@utility gsmui-animate-enter {
    animation: gsmui-enter 200ms ease-out;
}

@utility gsmui-animate-exit {
    animation: gsmui-exit 150ms ease-in forwards;
}

/* Custom focus utility */
@utility gsmui-focus-ring {
    outline: 2px solid -webkit-focus-ring-color;
    outline-offset: 2px;
}

/* Custom disabled utility */
@utility gsmui-disabled {
    opacity: 0.5;
    pointer-events: none;
    cursor: not-allowed;
}
```

### 7.3 The `@layer` Directive

CSS layers control the cascade order:

```css
/* Define layer order */
@layer base, components, utilities, runtime;

/* Base layer: reset and defaults */
@layer base {
    :root {
        color-scheme: light;
    }

    [data-theme="dark"] {
        color-scheme: dark;
    }
}

/* Components layer: GsmUi component styles */
@layer components {
    .gsmui-button {
        display: inline-flex;
        align-items: center;
        justify-content: center;
        gap: var(--gsmui-space-2);
        font-weight: 500;
        border-radius: var(--gsmui-radius-lg);
        transition: all var(--gsmui-duration-normal) var(--gsmui-ease-default);
    }
}

/* Utilities layer: Tailwind utilities */
@layer utilities {
    /* Tailwind utilities are automatically placed here */
}

/* Runtime layer: theme overrides via adoptedStyleSheets */
@layer runtime {
    /* Applied by theme builder at runtime */
}
```

## 8. Dark Variant Configuration

### 8.1 Custom Dark Variant

Tailwind v4 uses `@custom-variant` to define dark mode behavior:

```css
/* Dark variant bound to data-theme attribute */
@custom-variant dark (&:where([data-theme="dark"], [data-theme="dark"] *));
```

### 8.2 Dark Variant Usage

```blade
{{-- Dark mode classes --}}
<div class="bg-white dark:bg-zinc-900">
    <p class="text-zinc-900 dark:text-zinc-100">Content</p>
    <gsmui:button class="bg-accent dark:bg-accent-hover">
        Button
    </gsmui:button>
</div>
```

### 8.3 Dark Variant Resolution

| Light Mode Class | Dark Mode Class | Result |
| --- | --- | --- |
| `bg-white` | `dark:bg-zinc-900` | White in light, zinc-900 in dark |
| `text-zinc-900` | `dark:text-zinc-100` | Dark text in light, light text in dark |
| `border-zinc-200` | `dark:border-white/10` | Solid border in light, opacity border in dark |
| `shadow-sm` | `dark:shadow-none` | Shadow in light, no shadow in dark |

### 8.4 Dark Variant Testing

```js
test("dark variant applies correctly", async ({ page }) => {
    await page.goto("/test/component");

    // Light mode
    const lightBg = await page.evaluate(() => {
        return getComputedStyle(document.querySelector('[data-gsmui-component]')).backgroundColor;
    });

    // Dark mode
    await page.evaluate(() => {
        document.documentElement.setAttribute("data-theme", "dark");
    });

    const darkBg = await page.evaluate(() => {
        return getComputedStyle(document.querySelector('[data-gsmui-component]')).backgroundColor;
    });

    expect(lightBg).not.toBe(darkBg);
});
```

## 10. Build Pipeline Integration

### 10.1 Vite Plugin Configuration

```js
// vite.config.js
import { defineConfig } from "vite";
import laravel from "laravel-vite-plugin";
import tailwindcss from "@tailwindcss/vite";

export default defineConfig({
    plugins: [
        laravel({
            input: [
                "resources/css/app.css",
                "resources/js/app.js",
            ],
            refresh: true,
        }),
        tailwindcss(),
    ],
    css: {
        postcss: {
            plugins: [
                // No PostCSS plugins needed for Tailwind v4
            ],
        },
    },
    build: {
        cssMinifier: "lightningcss",
        rollupOptions: {
            output: {
                manualChunks: {
                    "gsmui-core": ["dist/gsmui.js"],
                },
            },
        },
    },
});
```

### 10.2 CSS Entry Point

```css
/* resources/css/app.css */
@import "tailwindcss";

/* GsmUi theme configuration */
@theme {
    /* ... theme tokens ... */
}

/* GsmUi custom utilities */
@utility gsmui-surface { /* ... */ }
@utility gsmui-card { /* ... */ }
@utility gsmui-trigger { /* ... */ }
@utility gsmui-popover { /* ... */ }

/* Dark mode variant */
@custom-variant dark (&:where([data-theme="dark"], [data-theme="dark"] *));

/* Layer ordering */
@layer base, components, utilities, runtime;

/* Base styles */
@layer base {
    :root {
        color-scheme: light;
    }
    [data-theme="dark"] {
        color-scheme: dark;
    }
}
```

### 10.3 JS Entry Point

## 11. Tailwind v4 New Features

### 11.1 CSS-Native Configuration

| Feature | v3 | v4 |
| --- | --- | --- |
| Config file | `tailwind.config.js` | CSS `@theme` block |
| Content detection | Manual `content: [...]` | Automatic source detection |
| Dark mode | `darkMode: 'class'` | `@custom-variant dark` |
| Plugins | JS plugin files | `@utility` / `@layer` |
| Variants | JS variant config | `@custom-variant` |
| PostCSS | Required | Not needed (Vite plugin) |
| Optimizer | PurgeCSS | Built-in tree-shaking |

### 11.2 New CSS Features

| Feature | Syntax | Use Case |
| --- | --- | --- |
| `@theme` | CSS config block | Theme tokens |
| `@utility` | Custom utility definition | Component utilities |
| `@custom-variant` | Custom variant definition | State variants |
| `@layer` | CSS cascade layers | Layer ordering |
| `color-mix()` | CSS color function | Color opacity |
| `oklch()` | CSS color function | Perceptual color |
| Container queries | `@container` | Component responsiveness |

### 11.3 Performance Improvements

| Metric | v3 | v4 | Improvement |
| --- | --- | --- | --- |
| Build time | 2-5s | 0.5-1s | 4x faster |
| CSS output | 50-100KB | 30-60KB | 40% smaller |

## 20. Tailwind v4 Best Practices

### 20.1 DO

| Practice | Example | Benefit |
| --- | --- | --- |
| Use `@theme` for tokens | `--color-accent: var(--gsmui-color-accent)` | Consistent design system |
| Use `@utility` for components | `@utility gsmui-surface { ... }` | Reusable component styles |
| Use `@layer` for ordering | `@layer base, components, utilities` | Predictable cascade |
| Use `@custom-variant` for states | `@custom-variant dark (...)` | Type-safe variants |
| Use automatic content detection | (no config needed) | Zero-config setup |

### 20.2 DON'T

| Anti-Pattern | Why | Alternative |
| --- | --- | --- |
| Use `tailwind.config.js` | Deprecated in v4 | Use `@theme` in CSS |
| Use PostCSS plugins | Not needed in v4 | Use `@tailwindcss/vite` |
| Use `darkMode: 'class'` | Deprecated in v4 | Use `@custom-variant dark` |
| Use JS plugins | Deprecated in v4 | Use `@utility` / `@layer` |
| Manually configure content | Not needed in v4 | Automatic detection |

```blade
        </div>
    @endif

    <div class="{{ isset($header) || isset($footer) ? 'px-4 py-3' : '' }}">
        {{ $slot }}
    </div>

    @if(isset($footer) && $footer->isNotEmpty())
        <div class="border-t border-border px-4 py-3">
            {{ $footer }}
        </div>
    @endif
</div>
```

## 32. Tailwind v4 Best Practices

### 32.1 DO

| Practice | Example | Benefit |
| --- | --- | --- |
| Use `@theme` for tokens | `--color-accent: var(--gsmui-color-accent)` | Consistent design system |
| Use `@utility` for components | `@utility gsmui-surface { ... }` | Reusable component styles |
| Use `@layer` for ordering | `@layer base, components, utilities` | Predictable cascade |
| Use `@custom-variant` for states | `@custom-variant dark (...)` | Type-safe variants |
| Use automatic content detection | (no config needed) | Zero-config setup |

### 32.2 DON'T

| Anti-Pattern | Why | Alternative |
| --- | --- | --- |
| Use `tailwind.config.js` | Deprecated in v4 | Use `@theme` in CSS |
| Use PostCSS plugins | Not needed in v4 | Use `@tailwindcss/vite` |
| Use `darkMode: 'class'` | Deprecated in v4 | Use `@custom-variant dark` |
| Use JS plugins | Deprecated in v4 | Use `@utility` / `@layer` |
| Manually configure content | Not needed in v4 | Automatic detection |

## 33. Tailwind v4 Integration Patterns

### 33.1 Livewire Integration

Tailwind v4 works seamlessly with Livewire 4's Morph algorithm:

```blade
{{-- Livewire component with Tailwind classes --}}
<div wire:model="sortBy"
     class="flex items-center gap-2 text-sm font-medium text-zinc-700 dark:text-zinc-300">
    <span>{{ $label }}</span>
    @if ($sortBy === $column)
        <x-gsmui:icon name="chevron-up" class="size-4" />
    @endif
</div>
```

**Morph Compatibility Rules:**
| Rule | Reason |
| --- | --- |
| Never use `@apply` in Blade | Morph can't detect class changes |
| Use utility classes directly | Morph diffs class attribute strings |
| Avoid conditional `@layer` | Static layer order required |
| Keep class strings stable | Minimize re-render diffs |

```blade
        : 'bg-white text-zinc-900 border border-zinc-200'"
    class="rounded-lg px-4 py-2 text-sm font-medium transition-colors"
```

### 34.3 Breaking Changes Reference

| v3 Syntax | v4 Syntax | Migration |
| --- | --- | --- |

| Plugin `addComponents` | `@layer components { ... }` | Convert to CSS |
| Plugin `addVariant` | `@custom-variant name (...)` | Convert to CSS |

## 36. Tailwind v4 Custom Theme Architecture

### 36.1 Theme Extension vs Override

```css
/* Extension: adds new values alongside defaults */
@theme {
    --color-brand-50: #eff6ff;
    --color-brand-500: #3b82f6;
    --color-brand-900: #1e3a5f;
}

/* Override: replaces default values */
@theme {
    --color-blue-500: #2563eb; /* Replaces Tailwind's default blue-500 */
}

/* Namespace: completely separate palette */
@theme {
    --color-acme-primary: #ff6b00;
    --color-acme-secondary: #0066ff;
}
```

### 36.2 Multi-Brand Theme System

```css
/* Base theme (always loaded) */
@theme {
    --spacing-unit: 4px;
    --font-sans: "Inter", system-ui, sans-serif;
}

/* Brand override (loaded via JS or data-attribute) */
[data-brand="acme"] {
    --color-primary: #ff6b00;
    --color-secondary: #0066ff;
    --radius-default: 8px;
}

[data-brand="globe"] {
    --color-primary: #00a651;
    --color-secondary: #ffd700;
    --radius-default: 0px;
}
```

### 36.3 Theme Token Documentation Template

```css
/**
 * @token color-primary
 * @type color

--color-primary: #3b82f6;
```

## 38. Tailwind v4 Migration Tools

### 38.1 Automated Conversion Scripts

```js
// convert-tailwind-config.js
// Converts tailwind.config.js theme to CSS @theme block

const config = require("./tailwind.config.js");

function themeToCSS(theme) {
    let css = "@theme {\n";
    for (const [key, value] of Object.entries(theme)) {
        if (typeof value === "string") {
            css += `  --${key}: ${value};\n`;
        } else if (typeof value === "object") {
            for (const [subKey, subValue] of Object.entries(value)) {
                css += `  --${key}-${subKey}: ${subValue};\n`;
            }
        }
    }
    css += "}\n";
    return css;
}

console.log(themeToCSS(config.theme.extend));
```
