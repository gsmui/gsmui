# 08.45 - Internationalization

**Project:** GsmUi
**Section:** 08 - Frontend Architecture
**Framework:** Laravel 13 · Blade Components · GsmUi Component Library · Livewire 4
**Version:** 1.0.0

---

> See also: `05.01-overview.md` (system architecture / i18n posture), `05.18-docs-engine.md` (docs localization). This document specifies the *frontend localization contract* for `gsmui:` components and does NOT re-document Laravel's translation loader or message schema.

# Purpose

GsmUi components are localized at render time by Laravel's `__()` helper running inside Blade, then hydrated on the client with a safe English fallback. This document pins where translation happens, how aria-labels are injected, and the JS fallback rule so every component stays CSP-safe and screen-reader-correct in any locale.

---

## 1. Single Source of Truth: Blade

Localization runs in PHP, not JS. Every user-facing string — including ARIA labels — is resolved by `__()` in the Blade template (`stubs/resources/views/gsmui/<component>/index.blade.php`) before the markup reaches the browser.

```html
<!-- date-picker trigger, localized aria-label -->
<button aria-label="{{ __('gsmui::messages.open_calendar') }}"
        aria-haspopup="dialog">
```

Rationale: the JS bundle is locale-agnostic and self-hosted (`script-src 'self'`). Shipping per-locale JS would bloat `dist/` and break CSP hygiene.

---

## 2. aria-label Contract

Per `AGENTS.md`, **aria-labels must use `__()`** and must be set from Blade where the helper executes. The JS layer treats the Blade-set value as primary and falls back to a hardcoded English string only as a safety net.

| Layer | Responsibility |
| --- | --- |
| Blade | Resolve `__('gsmui::messages.*')` → set as attribute |
| JS | Read attribute; if missing/empty, use English default constant |

```js
// utils.js / component init
const label = el.getAttribute('aria-label') || 'Open calendar';
```

---

## 3. Translation Namespace

Messages live under the `gsmui` language namespace so they publish with the package:

```php
// lang/en/messages.php
return [
    'open_calendar' => 'Open calendar',
    'clear_selection' => 'Clear selection',
    'copy_to_clipboard' => 'Copy to clipboard',
];
```

Publishing follows the standard Laravel lang publish flow; no CDN/external catalog (CSP).

---

## 4. Client-Side Dynamic Values

Numbers, dates, and currency that are produced in the browser may use the platform's built-in `Intl` APIs (`Intl.NumberFormat`, `Intl.DateTimeFormat`) rather than backend strings. These are locale-correct without shipping dictionaries.

```js
new Intl.NumberFormat(navigator.language).format(value);
```

---

## 5. RTL & Direction

Direction is declared at the document level (`<html dir="rtl">`) by the host app, not per component. Components consume `--gsmui-*` logical properties where possible (e.g. `ps-*`/`pe-*`) so they flip automatically.

## 7. RTL Support — Complete Specification

### 7.1 Logical Properties

All GsmUi components use CSS logical properties instead of physical properties:

| Physical | Logical | Usage |
| --- | --- | --- |
| `padding-left` | `padding-inline-start` (`ps-*`) | Left/right padding |
| `padding-right` | `padding-inline-end` (`pe-*`) | Left/right padding |
| `margin-left` | `margin-inline-start` (`ms-*`) | Left/right margin |
| `margin-right` | `margin-inline-end` (`me-*`) | Left/right margin |
| `text-align: left` | `text-align: start` | Text alignment |
| `text-align: right` | `text-align: end` | Text alignment |
| `border-left` | `border-inline-start` | Left/right borders |
| `border-right` | `border-inline-end` | Left/right borders |
| `left` | `inset-inline-start` | Absolute positioning |
| `right` | `inset-inline-end` | Absolute positioning |

### 7.2 Tailwind Logical Classes

GsmUi uses Tailwind's logical property classes:

| Physical class | Logical class | Usage |
| --- | --- | --- |
| `pl-3` | `ps-3` | Left padding (flips in RTL) |
| `pr-3` | `pe-3` | Right padding (flips in RTL) |
| `ml-2` | `ms-2` | Left margin (flips in RTL) |
| `mr-2` | `me-2` | Right margin (flips in RTL) |
| `text-left` | `text-start` | Text alignment (flips in RTL) |
| `text-right` | `text-end` | Text alignment (flips in RTL) |
| `border-l` | `border-s` | Left border (flips in RTL) |
| `border-r` | `border-e` | Right border (flips in RTL) |

### 7.3 Magic Number Handling

AGENTS.md allows magic numbers like `pe-[9px]` for pixel-level precision. In RTL mode, these are handled by using logical properties:

```css
/* Physical (breaks in RTL) */
.element { padding-right: 9px; }

/* Logical (works in both LTR and RTL) */
.element { padding-inline-end: 9px; }
```

### 7.4 RTL Testing Checklist

| Component | Test | Expected behavior |
| --- | --- | --- |
| Input | Text alignment | Starts from right edge in RTL |
| Select | Dropdown arrow | Flips to left side in RTL |
| Date Picker | Calendar grid | Days start from right in RTL |
| Table | Sort indicator | Flips direction in RTL |
| Modal | Close button | Flips to left side in RTL |
| Toast | Slide-in animation | Flips direction in RTL |
| Pagination | Previous/Next | Labels swap sides in RTL |

### 7.5 Direction Detection

The `dir` attribute is detected at the document level:

```js
function isRTL() {
  return document.documentElement.dir === 'rtl' ||
         document.documentElement.getAttribute('dir') === 'rtl'
}
```

## 8. Number, Date & Currency Formatting

### 8.1 Number Formatting

```js
function formatNumber(value, locale = navigator.language) {
  return new Intl.NumberFormat(locale).format(value)
}

// Examples:
// formatNumber(1234567.89, 'en-US') → "1,234,567.89"
// formatNumber(1234567.89, 'de-DE') → "1.234.567,89"
// formatNumber(1234567.89, 'ar-SA') → "١٬٢٣٤٬٥٦٧٫٨٩"
```

### 8.2 Currency Formatting

```js
function formatCurrency(value, currency = 'USD', locale = navigator.language) {
  return new Intl.NumberFormat(locale, {
    style: 'currency',
    currency: currency,
  }).format(value)
}

// Examples:
// formatCurrency(1234.56, 'USD', 'en-US') → "$1,234.56"
// formatCurrency(1234.56, 'EUR', 'de-DE') → "1.234,56 €"
// formatCurrency(1234.56, 'SAR', 'ar-SA') → "١٬٢٣٤٫٥٦ ر.س."
```

### 8.3 Date Formatting

```js
function formatDate(date, options = {}, locale = navigator.language) {
  const defaultOptions = {
    year: 'numeric',
    month: 'long',
    day: 'numeric',
  }
  return new Intl.DateTimeFormat(locale, { ...defaultOptions, ...options }).format(date)
}

// Examples:
// formatDate(new Date(), {}, 'en-US') → "July 25, 2025"
// formatDate(new Date(), {}, 'de-DE') → "25. Juli 2025"
// formatDate(new Date(), {}, 'ja-JP') → "2025年7月25日"
```

### 8.4 Relative Time Formatting

```js
function formatRelativeTime(date, locale = navigator.language) {
  const rtf = new Intl.RelativeTimeFormat(locale, { numeric: 'auto' })
  const diff = date - Date.now()
  const minutes = Math.round(diff / 60000)
  const hours = Math.round(diff / 3600000)
  const days = Math.round(diff / 86400000)

  if (Math.abs(minutes) < 60) return rtf.format(minutes, 'minute')
  if (Math.abs(hours) < 24) return rtf.format(hours, 'hour')
  return rtf.format(days, 'day')
}

// Examples:
// formatRelativeTime(new Date(Date.now() - 300000), 'en-US') → "5 minutes ago"
// formatRelativeTime(new Date(Date.now() - 86400000), 'en-US') → "yesterday"
```

### 8.5 Component Integration

Components use `Intl` APIs for dynamic values:

```blade
{{-- Date picker displays formatted date --}}
<time datetime="{{ $date->toISOString() }}">{{ formatDate($date) }}</time>

{{-- Table displays formatted number --}}
<td class="tabular-nums">{{ formatNumber($row->amount) }}</td>

{{-- Toast displays formatted currency --}}
<span>{{ formatCurrency($total, $currency) }}</span>
```

## 9. Pluralization Rules

### 9.1 Laravel Pluralization

Laravel's `__()` helper supports pluralization via pipe syntax:

```php
// lang/en/messages.php
'items_count' => '{0} No items|{1} One item|[2,*] :count items',

// Usage:
__('messages.items_count', ['count' => 0]) // "No items"
__('messages.items_count', ['count' => 1]) // "One item"
__('messages.items_count', ['count' => 5]) // "5 items"
```

### 9.2 Complex Pluralization

For languages with complex plural rules (e.g. Arabic, Polish), use the `Lang::choice()` method:

```php
Lang::choice('messages.items', $count, ['count' => $count]);
```

### 9.3 JavaScript Pluralization

For client-side pluralization (rare — prefer Blade), use the `Intl.PluralRules` API:

```js
const pr = new Intl.PluralRules(navigator.language)
const category = pr.select(count)
// Returns: 'zero', 'one', 'two', 'few', 'many', or 'other'
```

## 10. Locale Switching

### 10.1 Server-Side Locale

The locale is set via Laravel's locale switching:

```php
// In a controller or middleware
app()->setLocale($user->locale);
```

### 10.2 Client-Side Locale Detection

The JS bundle detects the locale from the `<html lang>` attribute:

```js
function getLocale() {
  return document.documentElement.lang || 'en'
}
```

### 10.3 Dynamic Locale Switching

When the user changes language, the page reloads to pick up new translations:

```php
// Livewire component
public function switchLocale(string $locale)
{
    app()->setLocale($locale);
    $this->user->update(['locale' => $locale]);
    $this->redirect(request()->url()); // reload with new locale
}
```

### 10.4 Locale Persistence

The user's locale preference is stored in:
1. The `locale` column on the `users` table
2. A cookie (`gsmui_locale`) as fallback for guests
3. The `<html lang>` attribute for client-side detection

### 12.2 Translation Coverage Report

```php
// tests/Feature/TranslationTest.php
public function test_all_message_keys_are_translated()
{
    $keys = [
        'open_calendar', 'clear_selection', 'copy_to_clipboard',
        // ... all message keys
    ];

    foreach (config('app.locales') as $locale) {
        App::setLocale($locale);
        foreach ($keys as $key) {
            $translation = __("gsmui::messages.{$key}");
            $this->assertNotEmpty($translation, "Missing translation for {$key} in {$locale}");
        }
    }
}
```

## 16. Complete Blade Template — Locale Selector

`stubs/resources/views/gsmui/locale-selector/index.blade.php`:

```blade
@props([
    'locales' => config('app.locales', ['en']),
    'current' => app()->getLocale(),
])

<div x-data="{ open: false }" class="relative">
    <gsmui:button
        as="div"
        size="xs"
        variant="ghost"
        @click="open = !open"
        :aria-label="__('Change language')"
        aria-haspopup="listbox"
    >
        <x-gsmui.icon name="globe-alt" class="w-4 h-4" />
        <span class="ms-1">{{ strtoupper($current) }}</span>
    </gsmui:button>

    <div
        x-show="open"
        @click.outside="open = false"
        x-transition
        class="absolute end-0 mt-1 w-40 bg-white dark:bg-zinc-800 border border-zinc-200 dark:border-white/10 rounded-lg shadow-lg z-50"
        role="listbox"
        :aria-label="__('Select language')"
    >
        @foreach ($locales as $locale)
            <button
                class="w-full text-start px-3 py-2 text-sm hover:bg-zinc-50 dark:hover:bg-white/5 {{ $locale === $current ? 'font-medium bg-zinc-50 dark:bg-white/5' : '' }}"
                role="option"
                :aria-selected="{{ $locale === $current ? 'true' : 'false' }}"
                wire:click="switchLocale('{{ $locale }}')"
                @click="open = false"
            >
                {{ __('locales.' . $locale) }}
            </button>
        @endforeach
    </div>
</div>
```

### 16.1 Locale Selector DOM Structure

```
div[x-data][relative]
├── gsmui:button[aria-haspopup="listbox"]
│   ├── x-gsmui.icon (globe-alt)
│   └── span (current locale code)
└── div[role="listbox"][x-show="open"]
    └── button[role="option"][aria-selected] (per locale)
        └── {{ locale name }}
```

### 16.2 Locale Switching Flow

1. User clicks locale selector button
2. Dropdown opens with available locales
3. User clicks a locale option
4. Livewire `switchLocale()` is called
5. Server sets new locale in session
6. Page reloads with new locale
7. All `__()` calls return translations in new locale

## 21. Performance Considerations

### 21.1 Translation Caching

In production, Laravel caches translations. The `__()` helper reads from cache after the first call:

```php
// Production: translations are cached in bootstrap/cache/
// Development: translations are read from files on each request
```

### 21.2 Bundle Size

The JS bundle is locale-agnostic — no translation strings are bundled. This keeps `dist/gsmui.js` under 50KB (gzipped).

### 21.3 Intl API Performance

The `Intl` APIs are native browser APIs with no download cost:

```js
// Performance benchmark
console.time('NumberFormat')
new Intl.NumberFormat('en-US').format(1234567.89)
console.timeEnd('NumberFormat') // < 1ms
```

### 21.4 Lazy Loading Translations

For large apps with many translations, consider lazy loading:

```js
// Load translations on demand
async function loadTranslations(locale) {
  const response = await fetch(`/lang/${locale}/messages.json`)
  return response.json()
}
```

However, GsmUi prefers Blade-side translation (no client-side loading) to maintain CSP compliance.

## 22. Security Considerations

### 22.1 Translation Injection

Translation files are trusted content (not user-generated). No sanitization is needed for translation values.

### 22.2 CSP Compliance

- No external translation CDN (all translations are self-hosted)
- No `eval()` for translation resolution
- No `Function()` for pluralization

### 22.3 XSS Prevention

Translation values are escaped by Blade's `{{ }}` syntax. Never use `{!! !!}` for translation values that contain user input.

## 26. Advanced i18n Patterns

### 26.1 Interpolation with HTML

For translations that contain HTML (e.g. emphasis, links), use Laravel's `HtmlString`:

```php
// lang/en/messages.php
'welcome_html' => 'Welcome to <strong>:app</strong>!',

// Usage:
__('gsmui::messages.welcome_html', ['app' => 'GsmUi'])
// Returns: "Welcome to <strong>GsmUi</strong>!"
```

In Blade, use `{!! !!}` for HTML translations (only for trusted translation files):

```blade
<p>{!! __('gsmui::messages.welcome_html', ['app' => 'GsmUi']) !!}</p>
```

### 26.2 Gender-Aware Translations

For languages with gendered grammar, use conditional translations:

```php
// lang/fr/messages.php
'greeting' => [
    'male' => 'Bienvenue, :name !',
    'female' => 'Bienvenue, :name !',
    'other' => 'Bienvenue, :name !',
],

// Usage:
__('gsmui::messages.greeting.' . $user->gender, ['name' => $user->name])
```

### 26.3 Date-Relative Translations

For relative dates that need translation:

```php
// lang/en/messages.php
'relative_time' => [
    'ago' => ':time ago',
    'in' => 'in :time',
    'today' => 'today',
    'yesterday' => 'yesterday',
    'tomorrow' => 'tomorrow',
],
```

### 26.4 Context-Sensitive Translations

When the same English word has different translations depending on context:

```php
// lang/en/messages.php
'open' => [
    'verb' => 'Open',        // "Open file"
    'adjective' => 'Open',   // "Status: Open"
    'noun' => 'Opening',     // "The Open"
],
```

## 28. Number System Support

### 28.1 Arabic-Indic Numerals

For Arabic locales, numbers can be displayed in Arabic-Indic numerals:

```js
// Arabic-Indic numerals
function toArabicNumerals(str) {
  return str.replace(/\d/g, d => '٠١٢٣٤٥٦٧٨٩'[d])

// Example:
toArabicNumerals('12345') // '١٢٣٤٥'
```

### 28.2 Extended Arabic-Indic Numerals

For Urdu locales, use Extended Arabic-Indic numerals:

```js
function toUrduNumerals(str) {
  return str.replace(/\d/g, d => '۰۱۲۳۴۵۶۷۸۹'[d])
}
```

### 28.3 Digit Detection

Detect the user's preferred numeral system:

```js
function getDigitSystem() {
  const locale = navigator.language
  if (locale.startsWith('ar')) return 'arabic-indic'
  if (locale.startsWith('ur')) return 'extended-arabic'
  return 'latin'
}
```

## 31. Pluralization Deep Dive

### 31.1 ICU Message Format

For complex pluralization, use the ICU Message Format:

```
{count, plural,
    =0 {No items}
    one {One item}
    other {{count} items}
}
```

### 31.2 Laravel Pluralization

Laravel supports basic pluralization:

```php
// Simple pluralization
'{0} No items|{1} One item|[2,*] :count items'

// With count parameter
__('messages.items', ['count' => $count])
```

### 31.3 JavaScript Pluralization

For client-side pluralization (rare):

```js
function pluralize(count, singular, plural) {
  return count === 1 ? singular : plural
}

// Usage:
pluralize(1, 'item', 'items') // "item"
pluralize(5, 'item', 'items') // "items"
```

### 31.4 Locale-Specific Plural Rules

| Locale | Plural forms | Example |
| --- | --- | --- |
| English | one, other | 1 item, 2 items |
| Arabic | zero, one, two, few, many, other | 0, 1, 2, 3-10, 11-99, 100+ |
| Polish | one, few, many, other | 1, 2-4, 5-21, 22+ |
| Japanese | other | All forms are "other" |

## 38. Migration Guide

### 38.1 Adding i18n to an Existing App

1. Set `locale` in `config/app.php`
2. Publish GsmUi lang files: `php artisan vendor:publish --tag=gsmui-pro-lang`
3. Translate all message keys in the published files
4. Add `<html lang="{{ app()->getLocale() }}" dir="{{ in_array(app()->getLocale(), ['ar', 'he']) ? 'rtl' : 'ltr' }}">` to the layout
5. Test all components in the target locale

### 38.2 From Hardcoded Strings

Replace hardcoded English strings with `__()` calls:

```blade
{{-- Before --}}
<button>Save changes</button>

{{-- After --}}
<button>{{ __('Save changes') }}</button>
```

### 38.3 From Third-Party i18n Libraries

If the host app uses a third-party i18n library (e.g. `laravel-translatable`), ensure GsmUi translations are loaded from the same source. GsmUi uses Laravel's native translation system, so no adapter is needed.

## 39. Troubleshooting Guide

### 39.1 Translations Not Loading

1. Check that the lang file exists in `lang/{locale}/messages.php`
2. Verify the `locale` is set correctly in `config/app.php`
3. Check that the translation key is spelled correctly
4. Verify the lang file returns a valid PHP array

### 39.2 RTL Layout Broken

1. Check that `<html dir="rtl">` is set
2. Verify all components use logical properties (`ps-*`, `pe-*`, `ms-*`, `me-*`)
3. Check for physical property overrides (`left`, `right`, `padding-left`, etc.)
4. Test with Playwright screenshots in RTL mode

### 39.3 Date Formatting Wrong

1. Check that the locale is set correctly
2. Verify the date format pattern is valid
3. Check that `Intl.DateTimeFormat` is available in the browser
4. Test with different date values (edge cases: leap year, end of month)

### 39.4 Number Formatting Wrong

1. Check that the locale is set correctly
2. Verify the number format options are valid
3. Check that `Intl.NumberFormat` is available in the browser
4. Test with different number values (edge cases: zero, negative, very large)

### 39.5 Pluralization Not Working

1. Check that the translation key uses the pipe syntax for pluralization
2. Verify the `count` parameter is passed correctly
3. Test with different count values (0, 1, 2, 5, 100)

## 53. i18n Architecture Diagram

```
┌─────────────────────────────────────────────────────────────┐
│                    i18n Architecture                         │
│                                                             │
│  ┌──────────────┐    ┌──────────────┐    ┌──────────────┐   │
│  │  Blade       │    │  Laravel     │    │  JS Bundle   │   │
│  │  Templates   │───▶│  __() Helper │───▶│  Intl APIs   │   │
│  └──────────────┘    └──────────────┘    └──────────────┘   │
│         │                   │                   │           │
│         ▼                   ▼                   ▼           │
│  ┌──────────────┐    ┌──────────────┐    ┌──────────────┐   │
│  │  aria-labels │    │  Translation │    │  Number/Date │   │
│  │  set in HTML │    │  files       │    │  formatting  │   │
│  └──────────────┘    └──────────────┘    └──────────────┘   │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### 53.1 Data Flow

1. **Blade templates** resolve translations via `__()` at render time
2. **Laravel translation files** provide the source strings
3. **JS bundle** reads aria-labels from HTML attributes (locale-agnostic)
4. **Intl APIs** format numbers, dates, and currencies client-side
5. **Fallback chain** ensures English is always available

### 53.2 Locale Detection Flow

```
Request arrives
    ↓
Check session locale → if set, use it
    ↓
Check cookie locale → if set, use it
    ↓
Check Accept-Language header → parse preferred locale
    ↓
Fall back to config('app.locale') → 'en'
    ↓
Set <html lang="{{ $locale }}" dir="{{ $direction }}">
```

## 54. i18n Checklist for New Components

When adding a new `gsmui:` component, follow this i18n checklist:

- [ ] All user-facing strings use `__()` in Blade
- [ ] ARIA labels use `__()` with `gsmui::messages.*` namespace
- [ ] Translation keys follow naming convention (`component_action`)
- [ ] Default English translations added to `lang/en/messages.php`
- [ ] Placeholder text is translatable
- [ ] Error messages are translatable
- [ ] Screen reader text uses `sr-only` class
- [ ] Component works in RTL mode (logical properties)
- [ ] Component tested with Arabic locale
- [ ] Date/number formatting uses `Intl` APIs (no hardcoded formats)
- [ ] Pluralization handled via Laravel's pipe syntax
- [ ] No hardcoded English strings in Blade templates
