**Project:** GsmUi
**Section:** 08 - Frontend Architecture
**Framework:** Laravel 13 · Livewire 4 · Blade Components · GsmUi Component Library · Tailwind CSS v4 · Vite
**Version:** 1.0.0

---

> See also: `05.17-component-engine.md` (component engine), `06.20-components.md` (component
> catalog records). This document specifies the *component explorer presentation* and does NOT
> re-document the component registry or prop metadata — those live in 05/06.

# Purpose

This document defines the component showcase: a searchable, categorized explorer that lists every
`gsmui:` component, renders live variants, and lets users toggle props/sizes/states to inspect
markup. It is the canonical browsing surface for the library and feeds the docs (`08.23`) and
playground (`08.24`).

---

## 1. Page Composition

| Region | GsmUi Components | Livewire |
| --- | --- | --- |
| Filter bar | `gsmui:search`, `gsmui:tabs` (category) | `wire:model.live` |
| Grid | `gsmui:card` per component | `Showcase::items()` |
| Detail | `gsmui:code`, `gsmui:field` (prop toggles) | `Showcase::variant()` |
| Copy | `gsmui:button` (copy markup) | clipboard |

## 2. Component Tree

```text
gsmui:layouts.app
└── <showcase>
    ├── gsmui:search (wire:model.live="q")
    ├── gsmui:tabs (wire:model="category")
    └── gsmui:card × N
        ├── gsmui:heading (component name)
        ├── <live preview>  (rendered gsmui:* variant)
        └── gsmui:button (open detail)

gsmui:modal (detail)
└── <props>
    ├── gsmui:field → gsmui:switch / gsmui:select (prop toggles)
    └── gsmui:code (generated markup)
```

## 3. Data Flow — Browse → Inspect

```text
gsmui:search wire:model.live="q"
        │
        ▼
Showcase::$q  ──▶  filter ComponentEngine registry (05.17)
        │
        ▼
$items  ──▶  gsmui:card grid (browser re-render)

prop toggle (gsmui:switch)
        │  input/change events
        ▼
Showcase::updatedProp()  ──▶  regenerate markup  ──▶  gsmui:code
```

- Variant state changes use `setAttribute`/`removeAttribute` from `utils.js` (MutationObserver-
  aware) so live previews update without full re-render where possible.
- Reference section structure uses `<x-docs.variant level="3">` for sub-components, matching the
  date-picker/select doc pattern.

## 4. CSP & Styling

- Copy-to-clipboard uses `gsmui:clipboard` (inlined, no external lib).
- No CDN assets; all icons via `gsmui:icon`.

### 6.2 Card States

| State | Visual | Trigger |
| --- | --- | --- |

| Hover | Elevated shadow | Mouse hover |
| Focus | Focus ring | Keyboard focus |
| Active | Pressed state | Mouse down |

### 6.3 Card Responsive Behavior

- **Tablet (640px–1024px)**: 2-column grid

### 7.3 Live Preview Update

When a prop toggle changes:

1. User clicks a switch or selects a value
2. `wire:model` updates the component's props array
3. `Showcase::updatedProp()` fires
4. The live preview re-renders with the new props
5. The markup output regenerates to reflect the change
6. No full modal re-render — surgical update

### 8.2 Markup Formatting

- Indentation: 4 spaces (configurable)
- Attribute order: component name, wire:model, variant, size, other props, slots
- Self-closing tags for void elements
- Comments for complex components
- Slot content properly indented

### 8.3 Markup Variants

Generate different markup styles:

- **Blade**: `<x-gsmui:component>` syntax (default)
- **HTML**: `<gsmui-component>` web component syntax
- **Livewire**: `<livewire:component>` Livewire syntax

### 8.4 Markup Copy

```javascript
// Copy markup to clipboard

    const markup = generateMarkup(component);
    await navigator.clipboard.writeText(markup);
    Livewire.dispatch('show-toast', { message: 'Markup copied to clipboard' });
}
```

## 9. Search & Filter System

### 9.1 Search Implementation

The search bar filters components by name, description, and tags:

```text
gsmui:search (wire:model.live="q")
├── <search icon>
├── <search input> (debounced 200ms)
├── <clear button> (visible when query non-empty)
└── <search results count>
```

### 9.2 Search Algorithm

```php
public function filterComponents(): Collection
{
    return $this->allComponents
        ->when($this->q, fn ($query) => $query->filter(
            fn ($component) => str_contains(strtolower($component['name']), strtolower($this->q))
                || str_contains(strtolower($component['description']), strtolower($this->q))
                || collect($component['tags'])->contains(fn ($tag) => str_contains(strtolower($tag), strtolower($this->q)))
        ))
        ->when($this->category, fn ($query) => $query->where('category', $this->category))
        ->sortBy('name')
        ->values();
}
```

### 9.3 Search Results Display

- Results update in real-time as user types
- No results state shows "No components found" with suggestion
- Search highlights matching text in component names
- Recent searches are stored in localStorage

### 9.4 Advanced Filter

Advanced filter options (expandable):

## 11. Component Playground Integration

### 11.1 Open in Playground

From the detail modal, users can open the component in the playground (08.24):

```text
gsmui:button "Open in playground"
    │  wire:click="openInPlayground('button', $props)"
    ▼
Playground::loadComponent('button', $props)
    │  redirect to /playground?component=button&props=...
    ▼
Playground renders component with current props
```

### 11.2 Props Passthrough

The showcase passes the current prop values to the playground:

- Variant selection
- Size selection
- State toggles (disabled, invalid, loading)
- Custom content (placeholder, label, etc.)

### 11.3 Bidirectional Sync

Changes in the playground can sync back to the showcase:

- Playground prop changes update showcase state
- Showcase prop changes update playground state
- Both views stay in sync via Livewire events

### 12.2 Favorites Storage

Favorites are stored per-user in the database:

```php
// Database table: user_component_favorites
Schema::create('user_component_favorites', function (Blueprint $table) {
    $table->id();
    $table->foreignId('user_id');
    $table->string('component_name');
    $table->timestamps();
    $table->unique(['user_id', 'component_name']);
});
```

## 35. Component Grid Virtualization

### 35.1 Virtualization Strategy

For large component lists (> 100 items), the grid uses virtualization:

```javascript
class ComponentGridVirtualizer {
    constructor(container, options) {
        this.container = container;
        this.itemHeight = options.itemHeight || 200;
        this.overscan = options.overscan || 5;
        this.items = options.items;
        this.visibleItems = [];
        this.render();
    }

    render() {
        const scrollTop = this.container.scrollTop;
        const viewportHeight = this.container.clientHeight;
        const startIndex = Math.floor(scrollTop / this.itemHeight) - this.overscan;
        const endIndex = Math.ceil((scrollTop + viewportHeight) / this.itemHeight) + this.overscan;

        this.visibleItems = this.items.slice(
            Math.max(0, startIndex),
            Math.min(this.items.length, endIndex)
        );

        this.renderItems();
    }
}
```

### 35.2 Virtualization Benefits

- Only visible cards are rendered (DOM nodes)
- Smooth scrolling with 60fps
- Low memory usage for large lists
- Fast initial render

### 35.3 Virtualization Trade-offs

- Search highlights may not be visible
- Keyboard navigation requires scroll management
- Print may not include all components

### 36.2 Favorites Livewire Methods

```php
public function toggleFavorite(string $componentName): void
{
    $userId = auth()->id();
    $exists = DB::table('user_component_favorites')
        ->where('user_id', $userId)
        ->where('component_name', $componentName)
        ->exists();

    if ($exists) {
        DB::table('user_component_favorites')
            ->where('user_id', $userId)
            ->where('component_name', $componentName)
            ->delete();
        $this->dispatch('show-toast', ['message' => 'Removed from favorites']);
    } else {
        DB::table('user_component_favorites')->insert([
            'user_id' => $userId,
            'component_name' => $componentName,
        ]);
        $this->dispatch('show-toast', ['message' => 'Added to favorites']);
    }

    $this->loadFavorites();
}
```

## 39. Component Performance Profiling

### 39.1 Render Time Measurement

```javascript
function measureRenderTime(componentName, renderFn) {
    const start = performance.now();
    renderFn();
    const end = performance.now();
    const duration = end - start;

    // Log to analytics
    gtag('event', 'component_render', {
        component: componentName,
        duration: duration,
    });

    // Warn if slow
    if (duration > 16) {
        console.warn(`Slow render: ${componentName} took ${duration.toFixed(2)}ms`);
    }

    return duration;
}
```

### 39.2 Memory Usage Tracking

```javascript
function trackMemoryUsage(componentName) {
    if ('memory' in performance) {
        const memory = performance.memory;
        gtag('event', 'component_memory', {
            component: componentName,
            usedJSHeapSize: memory.usedJSHeapSize,
            totalJSHeapSize: memory.totalJSHeapSize,
        });
    }
}
```

### 39.3 Performance Budget

| Metric | Budget | Alert Threshold |
| --- | --- | --- |
| First render | < 50ms | > 100ms |
| Re-render | < 16ms | > 32ms |
| Memory per component | < 1KB | > 5KB |
| Total DOM nodes | < 500 | > 1000 |
| Bundle size (JS) | < 50KB | > 100KB |
| Bundle size (CSS) | < 20KB | > 50KB |

## 43. Component Showcase Offline Support

### 43.1 Service Worker

```javascript
// Cache-first strategy for component data
self.addEventListener('fetch', (event) => {
    if (event.request.url.includes('/api/components')) {
        event.respondWith(
            caches.match(event.request).then((response) => {
                return response || fetch(event.request).then((response) => {
                    const clone = response.clone();
                    caches.put(event.request, clone);
                    return response;
                });
            })
        );
    }
});
```
