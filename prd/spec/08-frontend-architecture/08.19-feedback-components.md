# Purpose

Feedback components communicate status to the user without blocking flow: toasts, alerts/callouts, progress indicators, skeletons, and spinners. They follow APG roles (`role="alert"`/`status`), use the `gsmui:badge` color palette for semantics, and animate only via the Motion Layer (`08.15`).

---

## 1. `gsmui:toast`

`stubs/resources/views/gsmui/toast/index.blade.php`:

| Prop | Default | Purpose |
| --- | --- | --- |
| `duration` | `5000` | ms before auto-dismiss (`0` = sticky) |
| `position` | `top-right` | viewport corner |

- Root `data-gsmui-toast` with Alpine `visible`/`remaining`/`timer`; auto-dismiss via `setInterval`.
- `role="alert"` for the live region; close button `aria-label="{{ __('Dismiss') }}"` with `<gsmui:icon.x-mark>`.
- Progress bar shows remaining time: `:style="width: (remaining/duration)*100%"` — uses `tabular-nums` not required but width animates via CSS.
- Multiple toasts stack in a fixed container (`top-right` etc.); container is `aria-live="polite"` so SR users hear one at a time (avoid duplicate reads, `08.16`).

```blade
<gsmui:toast duration="4000">{{ __('Saved successfully.') }}</gsmui:toast>
```

## 2. Alerts & Callouts

`gsmui:callout` / `gsmui:alert`:

| Variant | Color (badge palette) | Icon |
| --- | --- | --- |
| `info` | `blue` | `information-circle` |
| `success` | `green` | `check-circle` |
| `warning` | `amber` | `exclamation-triangle` |
| `danger` | `red` | `exclamation-circle` |

- Destructive/error alerts use `role="alert"`; informational uses `role="status"`.
- Left border accent + tinted surface; icon is `aria-hidden`, text carries meaning.
- Never color-only — pair icon + text (`08.16`).

## 3. `gsmui:progress` & `gsmui:radial-progress`

`stubs/resources/views/gsmui/progress/index.blade.php`:

| Prop | Default | Purpose |
| --- | --- | --- |
| `value` | `0` | current |
| `max` | `100` | total |
| `color` | `blue` | bar color (badge palette) |
| `label` / `description` | — | wrapped via `gsmui:with-field` |

- Track: `bg-zinc-200 dark:bg-zinc-700 rounded-full h-2 overflow-hidden`.
- Bar: `h-full rounded-full transition-all duration-500 ease-out` + width `%`.
- ARIA: `role="progressbar" aria-valuenow aria-valuemin="0" aria-valuemax`.
- `gsmui:radial-progress` is the circular variant (SVG `stroke-dasharray`); same ARIA.
- Under reduced motion the width transition collapses to instant (`08.15`).

## 4. Spinners & Skeletons

- **Spinner:** use `<gsmui:icon name="loading">` (inline SVG, `08.11`) inside busy buttons — never a font/GIF spinner. Keep `aria-hidden`; host button gets `aria-busy="true"`.
- **`gsmui:skeleton`:** shimmer placeholder for loading content; respects `prefers-reduced-motion` (static block, no shimmer) per `08.15`.

## 5. Accessibility & CSP

- All feedback is inline SVG + CSS; zero external requests (CSP profile: `img-src 'self' data:`).
- Live-region strategy: a single global polite announcer for toasts avoids double speech (`08.16` risk).
- Contrast: alert tints must keep AA against text in both themes.

#### 6.1.4 Toast Lifecycle

```text
Show request
    │
    ▼
Create toast element
    │
    ▼
Append to position container
    │
    ▼
Start auto-dismiss timer (if duration > 0)
    │
    ├── Timer expires → animate out → remove
    │
    └── User clicks dismiss → animate out → remove
```

#### 6.4.3 SVG Math

```javascript
function getStrokeDashoffset(value, max, radius) {
  const circumference = 2 * Math.PI * radius // 2πr
  const progress = value / max
  return circumference * (1 - progress)
}

// Example: value=75, max=100, radius=36
// circumference = 2 * π * 36 = 226.19
// progress = 75/100 = 0.75
// offset = 226.19 * (1 - 0.75) = 56.55
```

## 9. Toast Container Architecture

### 9.1 Container HTML

```html

  data-gsmui-toast-container
  data-position="top-right"
  aria-live="polite"
  aria-atomic="false"
  class="fixed top-4 right-4 z-50 flex flex-col gap-2"
>
  <!-- Toasts rendered here -->
```

### 9.2 Container Management

```javascript
class ToastContainer {
  constructor(position) {
    this.position = position
    this.toasts = []
    this.max = 5
    this.container = this.createContainer()
  }

  createContainer() {
    const el = document.createElement('div')
    el.setAttribute('data-gsmui-toast-container', '')
    el.setAttribute('data-position', this.position)
    el.setAttribute('aria-live', 'polite')
    el.setAttribute('aria-atomic', 'false')
    el.className = this.getPositionClasses()
    document.body.appendChild(el)
    return el
  }

  getPositionClasses() {
    const map = {
      'top-right': 'fixed top-4 right-4 z-50 flex flex-col gap-2',
      'top-left': 'fixed top-4 left-4 z-50 flex flex-col gap-2',
      'bottom-right': 'fixed bottom-4 right-4 z-50 flex flex-col gap-2',
      'bottom-left': 'fixed bottom-4 left-4 z-50 flex flex-col gap-2',
    }
    return map[this.position] || map['top-right']
  }

  add(toast) {
    if (this.toasts.length >= this.max) {
      this.remove(this.toasts[0])
    }
    this.toasts.push(toast)
    this.container.appendChild(toast.element)
  }

  remove(toast) {
    toast.element.remove()
    this.toasts = this.toasts.filter(t => t !== toast)
  }
}
```

### 9.3 Global Toast Store

```php
// Livewire
class ToastManager extends Component
{
    public array $toasts = [];

    public function add(string $message, string $type = 'default', int $duration = 5000): void
    {
        $id = uniqid();
        $this->toasts[] = [
            'id' => $id,
            'message' => $message,
            'type' => $type,
            'duration' => $duration,
        ];

        if ($duration > 0) {
            $this->dispatch('removeToast', id: $id, delay: $duration);
        }
    }

    public function remove(string $id): void
    {
        $this->toasts = array_filter($this->toasts, fn ($t) => $t['id'] !== $id);
    }
}
```

## 12. Accessibility Deep-Dive

### 12.1 Toast Accessibility

| Requirement | Implementation |
|-------------|----------------|
| Live region | `role="alert"` on toast |
| Dismiss | `aria-label="Dismiss"` on close button |
| Timer | No announce; visual progress bar |
| Stack | `aria-live="polite"` on container |
| Focus | Not focusable (non-interactive) |

### 12.2 Alert Accessibility

| Requirement | Implementation |
|-------------|----------------|
| Destructive | `role="alert"` for danger/warning |
| Informational | `role="status"` for info/success |
| Icon | `aria-hidden="true"` on icon |
| Text | Primary content carrier |
| Dismiss | `aria-label="Dismiss"` on close |

### 12.3 Progress Accessibility

| Requirement | Implementation |
|-------------|----------------|
| Value | `aria-valuenow` attribute |
| Range | `aria-valuemin="0" aria-valuemax="100"` |
| Label | `aria-label` or `aria-labelledby` |
| Live | `aria-live="polite"` for updates |
| Indeterminate | `aria-valuetext="Loading"` |

### 12.4 Spinner Accessibility

| Requirement | Implementation |
|-------------|----------------|
| Hidden | `aria-hidden="true"` on SVG |
| Button | `aria-busy="true"` on host button |
| Label | Host element has accessible name |
| Reduced motion | Animation stops |

### 12.5 Skeleton Accessibility

| Requirement | Implementation |
|-------------|----------------|
| Hidden | `aria-hidden="true"` on skeleton |
| Screen reader | Actual content announced when loaded |
| Focus | Skeleton not focusable |

## 14. Performance Considerations

### 14.1 Toast Rendering

- Use `document.createElement` (not `innerHTML`) for toast creation
- Batch DOM updates with `requestAnimationFrame`
- Remove toasts from DOM immediately on dismiss

### 14.2 Progress Bar

- Use CSS `width` transition (not JS animation)
- Avoid `requestAnimationFrame` for simple width changes
- Use `will-change: width` for GPU acceleration

### 14.3 Skeleton

- Use CSS `background-size` for shimmer (not multiple gradients)
- Avoid `will-change` on many skeleton elements
- Use `contain: content` for layout isolation

## 17. State Management for Feedback Components

### 17.1 Toast State

```php
class ToastManager extends Component
{
    public array $toasts = [];
    private int $nextId = 0;

    public function success(string $message, int $duration = 5000): void
    {
        $this->add($message, 'success', $duration);
    }

    public function error(string $message, int $duration = 5000): void
    {
        $this->add($message, 'error', $duration);
    }

    public function warning(string $message, int $duration = 5000): void
    {
        $this->add($message, 'warning', $duration);
    }

    public function info(string $message, int $duration = 5000): void
    {
        $this->add($message, 'info', $duration);
    }

    private function add(string $message, string $type, int $duration): void
    {
        $id = $this->nextId++;
        $this->toasts[] = compact('id', 'message', 'type', 'duration');
        $this->dispatch('toast:added', id: $id);

        if ($duration > 0) {
            $this->dispatch('toast:remove', id: $id, delay: $duration);
        }
    }

    public function remove(int $id): void
    {
        $this->toasts = array_filter($this->toasts, fn ($t) => $t['id'] !== $id);
    }
}
```

```php
public function loadData(): void
{
    try {
        $this->data = Cache::remember('data', 3600, function () {
            return DataService::fetch();
        });
        $this->error = null;
    } catch (\Exception $e) {
        $this->error = __('Failed to load data. Please try again.');
        Log::error('Data load failed', ['error' => $e->getMessage()]);
    }
}

public function retry(): void
{
    Cache::forget('data');
    $this->loadData();
}
```

## 34. Performance Optimization

### 34.1 Virtual Toast Queue

```javascript
// Limit visible toasts to prevent performance issues
class VirtualToastQueue {
  constructor(maxVisible = 5) {
    this.maxVisible = maxVisible
    this.queue = []
    this.visible = []
  }

  add(toast) {
    if (this.visible.length >= this.maxVisible) {
      const oldest = this.visible.shift()
      oldest.dismiss()
    }
    this.visible.push(toast)
  }

  remove(toast) {
    this.visible = this.visible.filter(t => t !== toast)
  }
}
```

### 34.2 Debounced Progress Updates

```javascript
// Prevent excessive DOM updates during rapid progress changes
function debounce(fn, delay) {
  let timer
  return (...args) => {
    clearTimeout(timer)
    timer = setTimeout(() => fn(...args), delay)
  }
}

const updateProgress = debounce((value) => {
  progressBar.style.width = `${value}%`
}, 16) // One frame
```

## 37. Open Questions / Risks

- Toast container management: centralize in a Livewire/`Alpine` store vs. standalone components. Recommend a `gsmui:toast.container` for stacking + a11y.
- `duration` auto-dismiss can hurt screen-reader users if too fast; ensure `0`/sticky path for critical alerts.
- Radial-progress SVG math should lean on the browser (no parser) per AGENTS.md; confirm no JS color parsing.
- Toast queue management needs conflict resolution for rapid-fire toasts.
- Alert dismiss animation needs to not interfere with screen reader announcements.
- Progress bar needs to handle value changes during animation.
- Skeleton needs to match actual content shape for accurate loading perception.
- Spinner needs to be inline in buttons without layout shift.
- Toast needs to handle window resize gracefully.
- Alert needs to support custom icons via slot.
- Progress needs indeterminate state for unknown duration operations.
- Radial progress needs to handle value=0 and value=max edge cases.
- Skeleton needs to support custom shapes via CSS classes.
- Toast needs to handle RTL layouts.
- Alert needs to support dismiss callback.
- Toast needs to support action buttons (Undo, Retry).
- Alert needs to support collapsible content for long messages.
- Progress needs to support multi-step indicators.
- Radial progress needs to support multiple arcs for comparison.
- Skeleton needs to support text truncation animation.
- Spinner needs to support different animation styles (pulse, dots).
- Toast needs to support image/icon customization.
- Alert needs to support close animation.
- Progress needs to support segmented progress (steps).
- Radial progress needs to support gauge mode (half circle).
- Skeleton needs to support responsive sizing.
