# Purpose

Motion in GsmUi is a thin **Motion & Animation Layer** built on CSS transitions/transforms and Alpine `x-transition` — no GSAP, no heavy animation libs, no `eval()`. Every animation respects `prefers-reduced-motion`, degrades to instant state changes, and stays CSP-safe (no external font/JS). The goal is perceptible, snappy feedback without distracting or excluding users.

---

## 1. Motion Principles

- **Purposeful only.** Animate open/close, state change, and confirmation — never decorative looping motion (except the `loading` spinner).
- **Native over JS.** Prefer CSS `transition-*` / `transform` and Alpine `x-transition`; avoid `requestAnimationFrame` loops unless a component genuinely needs them (e.g. chart tween, `08.34`).
- **Token-driven durations.** Durations come from `--gsmui-motion-*` tokens:

| Token | Value | Use |
| --- | --- | --- |
| `--gsmui-motion-fast` | 100ms | Hover, tooltip |
| `--gsmui-motion-base` | 150ms | Popover/collapse |
| `--gsmui-motion-slow` | 200–300ms | Modal/dialog |

## 2. Transition Utility Patterns

Reuse the exact patterns established by sibling components:

```blade
{{-- Tooltip (gsmui:tooltip) --}}
x-transition:enter="transition ease-out duration-100"
x-transition:enter-start="opacity-0"
x-transition:enter-end="opacity-100"

{{-- Modal (gsmui:modal) scale-in --}}
x-transition:enter="transition ease-out duration-200"
x-transition:enter-start="opacity-0 scale-95"
x-transition:enter-end="opacity-100 scale-100"
```

For drawer (`gsmui:modal flyout`), slide on the transform axis:

```blade
x-transition:enter-start="opacity-0 translate-x-full"
x-transition:enter-end="opacity-100 translate-x-0"
```

## 3. `prefers-reduced-motion`

A global rule disables non-essential motion. In `dist/` (or `08.06-css-architecture.md` base layer):

```css
@media (prefers-reduced-motion: reduce) {
  *, *::before, *::after {
    animation-duration: 0.01ms !important;
    animation-iteration-count: 1 !important;
    transition-duration: 0.01ms !important;
    scroll-behavior: auto !important;
  }
}
```

Alpine `x-transition` still toggles `display`/`opacity` (state change remains), but the visual tween is neutralized. The `loading` spinner keeps a static or stepwise indicator under reduced motion (no infinite spin).

## 4. Trigger / Popover Motion

- Popovers use the native `popover="manual"` attribute (`gsmui:popover`); visibility toggles `data-open` and CSS `not-data-open:hidden`. Animate via `x-transition` on the inner panel only.
- Scroll lock while a popover/modal is open follows the date-picker pattern (AGENTS.md): add `overflow-hidden` to `<body>` on open, remove on close.

## 5. Loading & Progress Motion

- Use `gsmui:icon name="loading"` (inline SVG spinner) inside busy buttons — never a font spinner.
- `gsmui:progress` animates the bar via `transition-all duration-500 ease-out` (width %). Under reduced motion this collapses to an instant fill.

## 6. Performance & CSP

- All motion is GPU-friendly (`transform`/`opacity`); avoid animating `width`/`height` except progress bars where it is unavoidable.
- No external animation CDN; everything is bundled in `dist/` and styled via `adoptedStyleSheets` (CSP: `style-src 'self' 'unsafe-inline'`).
- Respect `08.46-performance.md` — keep cumulative transition cost low to avoid jank on low-end mobile.

## 7. Open Questions / Risks

- Whether to expose a `motion="none"` prop on overlays for tests (simpler Playwright assertions). Recommend adding it.
- Chart tween libraries (Chart.js/ApexCharts) have their own reduced-motion flags — must be wired to the same media query (`08.34`).
- Confirm the `prefers-reduced-motion` reset lives in the base layer so third-party adapters inherit it.

## 8. Transition Timing Functions

### 8.1 Approved Easing Curves

GsmUi uses a limited set of easing curves to maintain consistency across all components:

| Token | CSS value | Use case |
| --- | --- | --- |
| `ease-out` | `cubic-bezier(0, 0, 0.2, 1)` | Elements entering the viewport (modals, popovers) |
| `ease-in` | `cubic-bezier(0.4, 0, 1, 1)` | Elements leaving the viewport (closing panels) |
| `ease-in-out` | `cubic-bezier(0.4, 0, 0.2, 1)` | State changes within view (expand/collapse, color) |
| `spring` | `cubic-bezier(0.34, 1.56, 0.64, 1)` | Bouncy feedback (checkbox toggle, badge pop) |
| `linear` | `linear` | Progress bar fill, spinner rotation |

### 8.2 Easing Application Rules

| Animation type | Easing | Rationale |
| --- | --- | --- |
| Enter (modal, popover, tooltip) | `ease-out` | Slow start allows user to perceive origin |
| Exit (modal, popover, tooltip) | `ease-in` | Fast start = feels responsive |
| Size change (collapse, expand) | `ease-in-out` | Symmetric = natural |
| Position change (drawer slide) | `ease-in-out` | Smooth reversal at endpoints |
| Opacity fade | `ease-in-out` | Symmetric = gentle |
| Spinner rotation | `linear` | Constant angular velocity = natural |
| Progress fill | `ease-out` | Deceleration at end = completion feel |
| Bounce / spring | `spring` | Overshoot = playful confirmation |

### 8.3 Custom Easing via CSS Variables

Components can accept custom easing through CSS variables:

```css
.gsmui-transition {
  transition-timing-function: var(--gsmui-motion-ease, cubic-bezier(0.4, 0, 0.2, 1));
}
```

Never override the global easing function — use component-scoped tokens only.

## 9. Component-Specific Animation Contracts

### 9.1 Modal / Dialog

```text
Open:  opacity 0→1 (150ms ease-out) + scale 0.95→1 (200ms ease-out)
Close: opacity 1→0 (100ms ease-in) + scale 1→0.95 (150ms ease-in)
Backdrop: opacity 0→1 (150ms ease-out)
```

The modal body and backdrop animate independently — the backdrop is slightly faster so the modal "arrives" after the overlay.

### 9.2 Popover / Dropdown

```text
Open:  opacity 0→1 (100ms ease-out) + translate-y -4→0 (100ms ease-out)
Close: opacity 1→0 (75ms ease-in)
```

Popovers are faster than modals — they are transient and frequent.

### 9.3 Tooltip

```text
Open:  opacity 0→1 (100ms ease-out) after 150ms delay
Close: opacity 1→0 (75ms ease-in) — no delay
```

The delay prevents tooltips from flashing during rapid mouse movement. On close, the delay is removed so the tooltip disappears instantly.

### 9.4 Drawer / Sidebar

```text
Open (mobile):  translateX -100%→0 (200ms ease-in-out)
Close (mobile): translateX 0→-100% (200ms ease-in-out)
Collapse:       width W→64px (200ms ease-in-out)
Expand:         width 64px→W (200ms ease-in-out)
```

Drawer uses `translateX` (GPU-composited) instead of `left` or `margin-left` (layout-triggering).

### 9.5 Accordion / Collapse

```text
Expand: height 0→auto (200ms ease-in-out), opacity 0→1 (150ms ease-in)
Collapse: height auto→0 (150ms ease-in), opacity 1→0 (100ms ease-in)
```

Height animation uses `max-height` trick or Alpine `x-collapse` plugin (self-hosted, CSP-safe).

### 9.6 Toast / Notification

```text
Enter:  opacity 0→1 (200ms ease-out) + translateY 16px→0 (200ms ease-out)
Exit:   opacity 1→0 (150ms ease-in) + translateY 0→-8px (150ms ease-in)
```

Toasts exit upward (away from content) to feel like they are "leaving" the viewport.

### 9.7 Tab / Switcher

```text
Indicator slide: translateX left→right (200ms ease-in-out)
Content: opacity 0→1 (150ms ease-in-out)
```

The active indicator slides under the new tab — it never teleports.

### 9.8 Button Loading State

```text
Content fade:    opacity 1→0 (100ms ease-in)
Spinner appear:  opacity 0→1 + scale 0.8→1 (100ms ease-out)
Complete:        spinner → check icon (200ms spring)
```

The spring easing on completion gives a satisfying "confirmation" bounce.

## 11. Staggered Animations

### 11.1 Stagger Pattern

When multiple elements animate in (list items, grid cards), stagger them:

```css
.gsmui-stagger > * {
  animation: gsmui-fade-in 200ms ease-out both;
}

.gsmui-stagger > *:nth-child(1) { animation-delay: 0ms; }
.gsmui-stagger > *:nth-child(2) { animation-delay: 50ms; }
.gsmui-stagger > *:nth-child(3) { animation-delay: 100ms; }
.gsmui-stagger > *:nth-child(4) { animation-delay: 150ms; }
.gsmui-stagger > *:nth-child(5) { animation-delay: 200ms; }
.gsmui-stagger > *:nth-child(n+6) { animation-delay: 250ms; }

@keyframes gsmui-fade-in {
  from { opacity: 0; transform: translateY(8px); }
  to   { opacity: 1; transform: translateY(0); }
}
```

### 11.2 Stagger Rules

| Rule | Rationale |
| --- | --- |
| Max 6 staggered items | Diminishing returns after 6; rest appear instantly |
| 50ms increment | Fast enough to feel cohesive, slow enough to perceive |
| Total stagger < 300ms | Beyond 300ms, user perceives delay, not animation |
| Under `prefers-reduced-motion`, all appear instantly | No stagger |

### 11.3 Blade Integration

```blade
<div class="gsmui-stagger">
    @foreach($items as $item)
        <x-card :item="$item" />
    @endforeach
</div>
```

The `gsmui-stagger` class is provided by the animation layer — no per-component implementation needed.

## 14. Chart & Data Animation

### 14.1 Chart Transitions

Chart libraries (Chart.js, ApexCharts, ECharts) have their own animation systems. GsmUi wires them to the same reduced-motion media query:

```js
// Chart.js configuration
const chartOptions = {
  animation: {
    duration: window.matchMedia('(prefers-reduced-motion: reduce)').matches ? 0 : 500,
    easing: 'easeOutQuart',
  },
};
```

### 14.2 Counter Animation

For animated number counters (stats cards):

```js
function animateCounter(element, target, duration = 500) {
  if (window.matchMedia('(prefers-reduced-motion: reduce)').matches) {
    element.textContent = target;
    return;
  }

  const start = parseInt(element.textContent) || 0;
  const range = target - start;
  const startTime = performance.now();

  function step(currentTime) {
    const elapsed = currentTime - startTime;
    const progress = Math.min(elapsed / duration, 1);
    const eased = 1 - Math.pow(1 - progress, 3); // ease-out cubic
    element.textContent = Math.round(start + range * eased);
    if (progress < 1) requestAnimationFrame(step);
  }

  requestAnimationFrame(step);
}
```

### 14.3 Data Table Row Animation

When rows are added/removed from a data table:

```css
.gsmui-table-row-enter {
  animation: gsmui-row-slide-in 200ms ease-out;

  animation: gsmui-row-slide-out 150ms ease-in forwards;
}

@keyframes gsmui-row-slide-in {

  to   { opacity: 1; transform: translateX(0); }
}

@keyframes gsmui-row-slide-out {
```

## 15. Animation Performance Budget

### 15.1 GPU Composition Rules

| Property | GPU-composited? | Use |
| --- | --- | --- |
| `transform` | Yes | Preferred for all position/scale/rotate animations |
| `opacity` | Yes | Preferred for fade animations |
| `filter` | Yes (may fallback) | Use sparingly (blur, brightness) |
| `width`/`height` | No | Only for progress bars where unavoidable |
| `left`/`top`/`margin` | No | Never animate these — use `transform: translate` |
| `background-color` | No (unless isolated layer) | Use `opacity` overlay instead |

### 15.2 Jank Prevention

| Rule | Rationale |
| --- | --- |
| Max 3 concurrent animations | More than 3 composited layers = memory pressure |
| Total animated area < 50% viewport | Full-screen animations cause frame drops |
| No animation on `scroll` handler | Use `animation-timeline: scroll()` instead |
| Use `will-change` only before animation | Permanent `will-change` wastes GPU memory |

### 15.3 Will-Change Usage

```css
/* ✅ Add before animation, remove after */
.gsmui-modal[data-open="true"] {
  will-change: transform, opacity;
}

/* ❌ Don't set permanently */
.gsmui-modal {
  will-change: transform, opacity; /* wastes memory */
}
```

### 15.4 Low-End Mobile Considerations

On low-end Android devices (Chrome 90, 2GB RAM):
- Reduce all durations by 50% (feels faster on slow hardware).
- Disable staggered animations (use instant appear).
- Disable scroll-driven animations (use IntersectionObserver fallback).
- Prefer `opacity` over `transform` (less GPU work).

```css
@media (prefers-reduced-motion: reduce) {
  /* Already handles this via the global rule */
}
```

### 16.4 Timing Verification

```javascript
test('modal open animation completes within budget', async ({ page }) => {
  await page.goto('/test/modal');

  const duration = await page.evaluate(async () => {
    const start = performance.now();
    document.querySelector('[data-trigger-modal]').click();
    await new Promise(resolve => {
      const observer = new MutationObserver(() => {
        const el = document.querySelector('[role="dialog"]');
        if (el && getComputedStyle(el).opacity === '1') {
          observer.disconnect();
          resolve();
        }
      });
      observer.observe(document.body, { attributes: true, subtree: true, attributeFilter: ['data-open'] });
    });
    return performance.now() - start;
  });

  expect(duration).toBeLessThan(300); // Within 300ms budget
});
```

## 17. Alpine x-transition Integration

### 17.1 Approved Transition Patterns

Alpine `x-transition` is used only for non-component micro-interactions (per `08.09-alpinejs-architecture.md`). The approved patterns:

```html
<!-- Fade only -->
<div x-show="open"
     x-transition:enter="transition ease-out duration-100"
     x-transition:enter-start="opacity-0"
     x-transition:enter-end="opacity-100"
     x-transition:leave="transition ease-in duration-75"
     x-transition:leave-start="opacity-100"
     x-transition:leave-end="opacity-0">
</div>

<!-- Fade + slide -->
<div x-show="open"
     x-transition:enter="transition ease-out duration-150"
     x-transition:enter-start="opacity-0 -translate-y-1"
     x-transition:enter-end="opacity-100 translate-y-0"
     x-transition:leave="transition ease-in duration-100"
     x-transition:leave-start="opacity-100 translate-y-0"
     x-transition:leave-end="opacity-0 -translate-y-1">
</div>

<!-- Scale (modal-like) -->
<div x-show="open"
     x-transition:enter="transition ease-out duration-200"

     x-transition:enter-end="opacity-100 scale-100"
     x-transition:leave="transition ease-in duration-150"
```

## 18. Animation Accessibility Deep Dive

### 18.1 Vestibular Disorder Considerations

Users with vestibular disorders may experience dizziness, nausea, or disorientation from certain animations. GsmUi mitigates this:

| Animation type | Vestibular risk | Mitigation |
| --- | --- | --- |
| Parallax scrolling | High | Disabled entirely under `prefers-reduced-motion` |
| Zoom/scale transitions | Medium | Reduced to opacity-only |
| Slide transitions | Low | Kept but shortened |
| Rotating elements (spinners) | Medium | Stopped or replaced with pulsing indicator |
| Flashing content | High | Never flash more than 3 times per second (WCAG 2.3.1) |

### 18.2 Seizure Safety

WCAG 2.3.1 (Three Flashes or Below Threshold) requires no content flashes more than 3 times per second:

```css
/* Prevent any animation from exceeding safe flash rate */
@keyframes gsmui-flash {
  0%, 100% { opacity: 1; }
  50% { opacity: 0; }
}

/* This animation runs at 2Hz (safe) */
.gsmui-safe-flash {
  animation: gsmui-flash 500ms ease-in-out infinite;
}
```

### 18.3 Focus and Animation Interaction

When an element receives focus during an animation:
- The animation must not prevent focus from landing on the element.
- Focus indicators must be visible immediately, even during transition.
- Modal focus trap must work correctly during the open animation.

```css
/* Focus ring is always visible, even during transitions */
*:focus-visible {
  outline: 2px solid var(--gsmui-color-focus, -webkit-focus-ring-color);
  outline-offset: 2px;
  transition: none; /* Focus ring does not animate */
}
```

## 19. Motion Design Principles

### 19.1 The 5 Principles of GsmUi Motion

1. **Motion is functional, not decorative.** Every animation communicates a state change, provides feedback, or guides attention. If removing the animation doesn't reduce clarity, remove it.

2. **Motion is fast.** The longest animation in GsmUi is 300ms. Most are 100-200ms. Users should never wait for an animation to complete.

3. **Motion is consistent.** Same types of actions produce same types of animations. All modals scale-in. All drawers slide. All tooltips fade. Predictability builds mental models.

4. **Motion respects the user.** `prefers-reduced-motion` is not optional — it's a hard requirement. Users who request reduced motion get instant state changes with zero visual tweening.

5. **Motion is progressive.** Core functionality works without animation. Animation enhances the experience but never gates it.

### 19.2 Animation Naming Convention

All GsmUi keyframe animations follow a consistent naming pattern:

| Pattern | Example | Use |
| --- | --- | --- |
| `gsmui-{action}` | `gsmui-fade-in`, `gsmui-slide-up` | Generic animations |
| `gsmui-{component}-{action}` | `gsmui-modal-enter`, `gsmui-toast-exit` | Component-specific |
| `gsmui-{feedback}` | `gsmui-bounce`, `gsmui-shake` | User feedback |

### 19.3 Animation Z-Order During Transitions

During transitions, animated elements may need elevated z-index to prevent clipping:

```css
.gsmui-modal[data-opening] {
  z-index: var(--gsmui-z-modal);
}

.gsmui-popover[data-opening] {
  z-index: var(--gsmui-z-dropdown);
}
```

Never use hardcoded z-index values during animation — use the layout token system from `08.12-layout-system.md`.

Users can customize animation tokens:

```css
:root {

  /* Easing overrides */
  --gsmui-motion-ease-enter: cubic-bezier(0, 0, 0.2, 1);
  --gsmui-motion-ease-exit: cubic-bezier(0.4, 0, 1, 1);
  --gsmui-motion-ease-in-out: cubic-bezier(0.4, 0, 0.2, 1);
  --gsmui-motion-ease-spring: cubic-bezier(0.34, 1.56, 0.64, 1);

  /* Scale overrides */
  --gsmui-motion-scale-enter: 0.97;  /* Subtler modal enter */
  --gsmui-motion-scale-exit: 0.97;
  --gsmui-motion-scale-bounce: 1.03; /* Subtler spring */
}
```

### 21.2 Motion Presets

GsmUi provides motion presets for common use cases:

| Preset | Duration | Easing | Use case |
| --- | --- | --- | --- |
| `instant` | 0ms | — | Reduced motion, state changes |
| `fast` | 100ms | ease-out | Tooltips, micro-interactions |
| `base` | 150ms | ease-in-out | Popovers, dropdowns |
| `moderate` | 200ms | ease-in-out | Modals, drawers |
| `slow` | 300ms | ease-in-out | Page transitions |
| `spring` | 200ms | cubic-bezier(0.34, 1.56, 0.64, 1) | Bouncy feedback |

### 21.3 Per-Component Motion Override

Individual components can override motion tokens:

```css
/* Faster modal for this specific instance */
.gsmui-modal[data-speed="fast"] {
  --gsmui-motion-duration-moderate: 100ms;
}

/* No animation for testing */
.gsmui-modal[data-motion="none"] {
  --gsmui-motion-duration-moderate: 0ms;
  --gsmui-motion-duration-slow: 0ms;
}
```

The `data-motion="none"` attribute is useful for Playwright testing (no waiting for animations to complete).

## 24. Animation Best Practices

### 24.1 Timing Best Practices

| Best practice | Rationale | Example |
| --- | --- | --- |
| Enter faster than exit | Users notice arrivals more than departures | Modal enter: 200ms, exit: 150ms |
| Opacity always transitions | Smooth appearance is universally good | All transitions include opacity |
| Transform over layout | GPU-composited = smooth | `translateX` not `left` |
| Ease-out for enters | Slow start = perception of origin | Modal scale-in |
| Ease-in for exits | Fast start = feels responsive | Modal fade-out |
| Spring for confirmation | Overshoot = positive feedback | Checkbox check |

### 24.2 Duration Best Practices

| Duration | Feel | Use case |
| --- | --- | --- |
| 0-50ms | Instant | Button press, checkbox toggle |
| 50-100ms | Quick | Tooltip appear, hover state |
| 100-200ms | Standard | Dropdown, popover |
| 200-300ms | Moderate | Modal, drawer |
| 300-500ms | Slow | Page transition (if used) |
| 500ms+ | Very slow | Avoid (feels sluggish) |

### 24.3 Common Animation Mistakes

| Mistake | Problem | Fix |
| --- | --- | --- |
| Animating layout properties | Triggers reflow, causes jank | Use `transform` and `opacity` |
| Animating too many properties | Performance degradation | Animate max 2 properties |
| No reduced-motion handling | Excludes vestibular users | Global reduced-motion rule |
| Animations longer than 500ms | Feels sluggish | Keep under 300ms |
| Animating on scroll | Jank on low-end devices | Use `animation-timeline: scroll()` |
| Inconsistent easing | Confusing visual language | Use approved easing curves |
| No cleanup after animation | Memory leaks | Remove `will-change`, clean classes |

### 24.4 Animation Accessibility Checklist

| Check | How to verify |
| --- | --- |
| Reduced motion disables animation | Enable in OS settings, verify no animation |
| No flashing > 3 times/second | Visual inspection, no strobing |
| Focus visible during animation | Keyboard test during transitions |
| Focus returns after animation | Close modal, verify focus restored |
| No animation-only information | Information available without animation |
| Spinner accessible under reduced motion | Static indicator instead of spin |

## 28. Animation Performance Budget

### 28.1 Per-Page Animation Budget

| Animation type | Max count | Max total duration | Rationale |
| --- | --- | --- | --- |
| Enter animations | 5 simultaneous | 200ms each | Perception of snappiness |
| Exit animations | 5 simultaneous | 150ms each | Quick cleanup |
| Loading spinners | 3 simultaneous | Infinite (CPU bounded) | Avoid CPU saturation |
| Scroll-triggered | 10 per viewport | 200ms each | Jank prevention |
| Staggered lists | 20 items max | 50ms offset each | Total < 1s |

### 28.2 CPU Budget per Frame

| Target | Budget | Measurement |
| --- | --- | --- |
| JavaScript execution | < 4ms | DevTools Performance |
| Style recalculation | < 2ms | DevTools Performance |
| Layout | < 1ms | DevTools Performance |
| Paint | < 2ms | DevTools Performance |
| Composite | < 1ms | DevTools Performance |
| Total frame time | < 16ms (60fps) | DevTools frame timeline |

### 28.3 Animation Performance Tiers

| Tier | Description | Component examples |
| --- | --- | --- |
| Tier 1 (critical path) | Must be 60fps, user-initiated | Modal open, dropdown select |
| Tier 2 (important) | Should be 60fps, system-initiated | Alert appear, toast appear |
| Tier 3 (decorative) | Best effort, non-interactive | Skeleton pulse, badge bounce |

### 28.4 Performance Monitoring

```javascript
// Monitor animation frame rate
let frameCount = 0;
let lastTime = performance.now();

function checkFPS() {
    frameCount++;
    const now = performance.now();
    if (now - lastTime >= 1000) {
        const fps = Math.round(frameCount * 1000 / (now - lastTime));
        if (fps < 55) {
            console.warn(`[GsmUi Animation] Low FPS: ${fps}`);
        }
        frameCount = 0;
        lastTime = now;
    }
    requestAnimationFrame(checkFPS);
}
```

### 36.4 Animation Performance Monitoring

```javascript
// Monitor animation frame rate
let frameCount = 0;
let lastTime = performance.now();

function checkFPS() {
    frameCount++;
    const now = performance.now();
    if (now - lastTime >= 1000) {
        const fps = Math.round(frameCount * 1000 / (now - lastTime));
        if (fps < 55) {
            console.warn(`[GsmUi Animation] Low FPS: ${fps}`);
        }
        frameCount = 0;
        lastTime = now;
    }
    requestAnimationFrame(checkFPS);
}
```
