## 2. Component Namespace

`GsmuiProServiceProvider::bootComponentPath()` registers `stubs/resources/views/gsmui` as the `gsmui:` anonymous-component namespace. A component is referenced as `<gsmui:input>` and resolves to `gsmui/input/index.blade.php`.

| Convention | Rule |
| --- | --- |
| One folder per component | `gsmui/<name>/index.blade.php` |
| No logic in `src/` | component logic stays in Blade + `dist/gsmui.js` |
| Copy siblings | new components reuse sibling markup/JS (`AGENTS.md`) |

## 3. `dist/` (Build Output, Not Source)

`dist/` has **no in-repo build config** (no vite/rollup/webpack/package.json at root). It is produced upstream. Never commit `dist/` changes unless explicitly asked (`AGENTS.md`).

## 7. Detailed Directory Exploration

### 7.1 `src/` — PHP Source

The `src/` directory is intentionally minimal. It contains only the service provider, manager, facade, helpers, and middleware. There is almost no component logic here — component behavior lives in Blade templates and the `dist/` JavaScript bundle.

```text
src/
├── GsmuiProServiceProvider.php    # Package registration + boot
├── GsmuiManager.php              # Runtime manager (classes(), config)
├── Gsmui.php                     # Facade alias
├── Helpers.php                    # Utility functions
└── Http/
    └── Middleware/
        └── CspMiddleware.php      # Content Security Policy header injection
```

| File | Responsibility | Lines (approx) |
| --- | --- | --- |
| `GsmuiProServiceProvider.php` | Registers config, views, middleware, component path | 150–200 |
| `GsmuiManager.php` | Resolves `Gsmui::classes()` merges, config access | 80–120 |
| `Gsmui.php` | Static facade proxy to manager | 20–30 |
| `Helpers.php` | Shared utility functions (aria, locale) | 40–60 |
| `CspMiddleware.php` | Builds and injects `Content-Security-Policy` header | 100–150 |

**Rule from `AGENTS.md`:** No logic in `src/` beyond registration and facade plumbing. Component rendering, state management, and interaction logic stay in Blade + `dist/gsmui.js`.

### 7.2 `stubs/` — Publishable Templates

`stubs/` contains the Blade component templates and publishable config. When users run `php artisan vendor:publish`, these files are copied into the host application.

```text
stubs/
├── resources/
│   └── views/
│       └── gsmui/                    # The gsmui: anonymous-component namespace
│           ├── accordion/
│           │   └── index.blade.php
│           ├── button/
│           │   └── index.blade.php
│           ├── color-picker/
│           │   ├── index.blade.php
│           │   └── swatch-grid.blade.php
│           ├── date-picker/
│           │   ├── index.blade.php
│           │   ├── button.blade.php      # Trigger pattern source
│           │   └── calendar.blade.php
│           ├── input/
│           │   └── index.blade.php       # Input pattern source (outline variant)
│           ├── modal/
│           │   └── index.blade.php
│           ├── select/
│           │   ├── index.blade.php
│           │   └── option-list.blade.php
│           ├── slider/
│           │   ├── index.blade.php
│           │   └── thumb.blade.php
│           ├── theme-switcher/
│           │   └── index.blade.php       # 08.44 theme switching
│           └── ... (~70 component directories total)
```

**Component registration:** `GsmuiProServiceProvider::bootComponentPath()` registers `stubs/resources/views/gsmui` as the `gsmui:` anonymous-component namespace. A component referenced as `<gsmui:input>` resolves to `stubs/resources/views/gsmui/input/index.blade.php`.

**Convention:** One folder per component, one `index.blade.php` per folder. Complex components may have child Blade partials (e.g., `date-picker/button.blade.php` for the trigger pattern).

### 7.3 `dist/` — Pre-Built Bundles

`dist/` is the build output from an upstream pipeline. There is **no build configuration in this repo** — no vite.config.js, no rollup.config.js, no webpack.config.js, no root package.json. The bundles are committed as artifacts.

```text
dist/
├── gsmui.js           # Main component bundle (self-hosted, CSP-safe)
├── gsmui.min.js       # Minified production variant
├── gsmui.module.js    # ES module variant for modern bundlers
├── editor.js          # Playground/Monaco editor bundle (lazy-loaded)
├── editor.css         # Editor-specific styles
├── editor.min.js      # Minified editor variant
└── manifest.json      # Asset map for host app integration
```

| Bundle | Size (approx) | When Loaded | CSP Directive |
| --- | --- | --- | --- |
| `gsmui.js` | 80–120 KB | On page mount (deferred) | `script-src 'self'` |
| `gsmui.min.js` | 40–60 KB | Production (minified) | `script-src 'self'` |
| `gsmui.module.js` | 70–100 KB | Modern bundler import | `script-src 'self'` |
| `editor.js` | 200–300 KB | Playground route only (lazy) | `script-src 'self'` |
| `editor.css` | 15–25 KB | Playground mount (adoptedStyleSheets) | `style-src 'self' 'unsafe-inline'` |

**Rule from `AGENTS.md`:** Never commit `dist/` changes unless explicitly asked. `dist/` is produced upstream and consumed by the host app through `manifest.json`.

### 7.4 `tests/Browser/` — Playwright Tests

The browser test directory is intentionally isolated from the repo root. It has its own `package.json` with Playwright dependencies, separate from any root-level npm setup.

```text
tests/Browser/
├── playwright.config.ts          # Playwright configuration
├── package.json                  # Isolated Playwright deps
├── README.md                     # Setup + run instructions
├── CspHeaderTest.php             # PHP CSP header assertion (Orchestra Testbench)
├── *.spec.js                     # Component/interaction Playwright tests
├── helpers/
│   ├── fixtures.js               # Shared test fixtures
│   ├── assertions.js             # Custom assertion helpers
│   └── page-objects.js           # Page object models
├── screenshots/                  # Captured verification screenshots
│   └── *.png
└── test-results/                 # Playwright output (git-ignored)
```

**Key rules:**
- Tests run headless unless explicitly asked otherwise.
- Tests assume `:8000` with `CSP_ENABLED=true`.
- DOM-state assertions only — never `el.state.s` internals.
- Screenshot critical states after every CSS change.
- See `08.49-testing.md` for the full test contract.

### 7.5 `workbench/` — Generated (Not Committed)

When `composer serve` runs, it generates a `workbench/` directory inside the package root. This is the Orchestra Testbench workbench — a minimal Laravel app that hosts the package for local development.

```text
workbench/                    # GENERATED — not committed
├── app/
├── config/
├── database/
├── resources/
│   └── views/
│       └── gsmui-stories/    # Component story routes (see 08.54)
└── routes/
    └── web.php
```

**Rule:** `workbench/` must be in `.gitignore`. It should never appear in PRs. If you see it in a diff, the developer forgot to ignore it.

## 8. Component Namespace Deep Dive

### 8.1 How `<gsmui:input>` Resolves

1. Blade encounters `<gsmui:input />` in a template.
2. Blade looks up the registered anonymous-component namespace `gsmui`.
3. It resolves to `stubs/resources/views/gsmui/input/index.blade.php`.
4. The component renders with the provided attributes as props.

### 8.2 Namespace Registration

```php
// GsmuiProServiceProvider.php
public function boot(): void
{
    $this->loadViewsFrom(
        $this->packagePath('stubs/resources/views'),
        'gsmui'
    );
}

protected function packagePath(string $path = ''): string
{
    return dirname(__DIR__, 2) . ($path ? "/{$path}" : '');
}
```

### 8.3 Component Naming Rules

| Rule | Example | Anti-pattern |
| --- | --- | --- |
| One folder per component | `gsmui/input/index.blade.php` | `gsmui/inputs.php` |
| Short, natural names | `gsmui:color-picker` | `gsmui:eye-dropper-color` |
| `-able` suffix for opt-in | `gsmui:select` with `clearable` | `gsmui:clearable-select` |
| `type` for variants | `<gsmui:button type="submit">` | `<gsmui:submit-button>` |
| Consistency across library | Match `gsmui:input` pattern | Invent new patterns |

### 8.4 Adding a New Component

1. Create `stubs/resources/views/gsmui/<name>/index.blade.php`.
2. Follow the sibling pattern (copy from `input`, `select`, `date-picker`).
3. Merge classes via `Gsmui::classes()`.
4. Use `__()` for all user-facing strings and aria-labels.
5. Declare ARIA per closest sibling pattern.
6. Add a story route in `workbench/resources/views/gsmui-stories/<name>.blade.php`.
7. Add Playwright tests in `tests/Browser/<name>.spec.js`.
8. Update the component count in this document.

## 9. `dist/` File Purposes

### 9.1 `gsmui.js` — Main Bundle

The primary JavaScript bundle that initializes all `gsmui:` components on page mount. It contains:

- JS mixins: Controllable, Disableable, Submittable, Focusable
- MutationObserver registration for `value` + config attributes
- `detangle()` sync-loop prevention
- `setAttribute`/`removeAttribute` utilities from `utils.js`
- Component-specific initialization logic

Loaded deferred via `<script src="/vendor/gsmui/dist/gsmui.js" defer>`.

### 9.2 `editor.js` — Playground Bundle

A lazy-loaded bundle for the Monaco Editor integration in the Playground page. Only loaded when the user navigates to `/playground`. Contains:

- Monaco Editor wrapper
- Syntax highlighting for Blade/HTML
- Live preview integration
- Code formatting utilities

Loaded via dynamic `import()` or deferred script tag on the playground route.

### 9.3 `editor.css` — Editor Styles

Styles for the Monaco Editor and Playground UI. Uses `adoptedStyleSheets` for dynamic loading rather than inline `<style>` tags (CSP-safe per `AGENTS.md`).

### 9.4 `manifest.json` — Asset Map

The manifest maps bundle names to their hashed URLs. The host app reads this to inject the correct `<script>` and `<link>` tags:

```json
{
  "gsmui.js": "/vendor/gsmui/dist/gsmui.abc123.js",
  "editor.js": "/vendor/gsmui/dist/editor.def456.js",
  "editor.css": "/vendor/gsmui/dist/editor.ghi789.css"
}
```

The host app should **never hardcode** `/vendor/gsmui/dist/...` — always read from `manifest.json` to survive version bumps.

## 10. Config & Middleware Paths

### 10.1 CSP Configuration

The publishable CSP config at `stubs/config/gsmui-pro-csp.php` defines the Content Security Policy directives:

```php
<?php
return [
    'enabled' => env('CSP_ENABLED', false),
    'report_only' => env('CSP_REPORT_ONLY', false),
    'directives' => [
        'script-src' => ["'self'"],
        'style-src' => ["'self'", "'unsafe-inline'"],
        'img-src' => ["'self'", 'data:'],
        'connect-src' => ["'self'"],
        'font-src' => ["'self'"],
        'object-src' => ["'none'"],
        'frame-ancestors' => ["'none'"],
        'base-uri' => ["'self'"],
        'form-action' => ["'self'"],
    ],
];
```

Publish command: `php artisan vendor:publish --tag=gsmui-pro-csp-config`.

### 10.2 CSP Middleware

`CspMiddleware.php` reads the config and builds the `Content-Security-Policy` header. It:

1. Checks if CSP is enabled via config.
2. Builds the header string from the directives array.
3. Adds `worker-src 'self'` if PWA workers are enabled (see `08.48-pwa.md`).
4. Injects the header on every response.
5. Supports report-only mode for testing.

### 10.3 Middleware Registration

```php
// App\Http\Kernel.php (Laravel 13)
protected $middlewareAliases = [
    'gsmui.csp' => \Gsmui\GsmuiPro\Http\Middleware\CspMiddleware::class,
];
```

Or globally in `bootstrap/app.php`:

```php
->withMiddleware(function (Middleware $middleware) {
    $middleware->append(\Gsmui\GsmuiPro\Http\Middleware\CspMiddleware::class);
})
```

## 11. Import Conventions

### 11.1 Blade Component Imports

```blade
{{-- Correct: use the gsmui: namespace --}}
<gsmui:input wire:model="name" placeholder="Enter name" />

{{-- Incorrect: don't use full vendor path --}}
@include('vendor.gsmui.resources.views.gsmui.input.index')
```

### 11.2 JavaScript Imports

```js
// Host app — import the self-hosted bundle
import 'gsmui/dist/gsmui.js';

// Or via manifest.json mapping
const manifest = await fetch('/vendor/gsmui/dist/manifest.json').then(r => r.json());
const script = document.createElement('script');
script.src = manifest['gsmui.js'];
document.body.appendChild(script);
```

### 11.3 CSS Imports

```css
/* Host app — import editor styles when needed */
@import 'gsmui/dist/editor.css';

/* Or via adoptedStyleSheets (CSP-safe) */
const sheet = new CSSStyleSheet();
await sheet.replace(await fetch('/vendor/gsmui/dist/editor.css').then(r => r.text()));
document.adoptedStyleSheets = [...document.adoptedStyleSheets, sheet];
```

## 18. Open Questions / Risks (Expanded)

- **`workbench/` generation:** `composer serve` generates `workbench/` (not committed) — ensure it is git-ignored so it never appears in PRs.
- **Component count drift:** "~70 components" — keep an index in sync as components are added/removed.
- **Bundle size growth:** monitor `dist/` total size as components are added; set a budget.
- **Story route explosion:** as components grow, story routes multiply; consider lazy-loading or grouping.

- **Test file proliferation:** 100+ spec files may need subdirectory organization.
- **Cross-platform paths:** ensure Windows/Mac/Linux path handling in `composer serve` and tests.

## 19. Component Directory Structures

### 19.1 Simple Component (Button)

```text
gsmui/button/
└── index.blade.php
```

The button component is simple enough that a single Blade file handles all variants (default, sm, xs, submit, etc.) through props.

### 19.2 Medium Component (Select)

```text
gsmui/select/
├── index.blade.php        # Main component with trigger + listbox
└── option-list.blade.php  # Option list partial (reused by multi-select)
```

The select component splits into a main template and an option-list partial for reuse.

### 19.3 Complex Component (Date Picker)

```text
gsmui/date-picker/
├── index.blade.php        # Main component orchestrator
├── button.blade.php       # Trigger button pattern (source for other triggers)
├── calendar.blade.php     # Calendar grid with day cells
└── month-year-nav.blade.php  # Month/year navigation controls
```

The date picker is the reference pattern for complex components. Its `button.blade.php` is the canonical trigger pattern that other components should copy.

### 19.4 Composite Component (Color Picker)

```text
gsmui/color-picker/
├── index.blade.php        # Main component
├── swatch-grid.blade.php  # Preset color swatches
└── format-input.blade.php # Hex/RGB/HSL input field
```

The color picker composes a `ui-slider` element (from `dist/gsmui.js`) for its hue slider rather than implementing its own from scratch. This is the recommended pattern: compose, don't reinvent.

### 19.5 Overlay Component (Modal)

```text
gsmui/modal/
├── index.blade.php        # Dialog with backdrop, focus trap, scroll lock
└── close-button.blade.php # Close button (reused by other overlays)
```

The modal's close button partial is reused by drawers, popovers, and other overlay components.

## 20. `dist/` Bundle Breakdown

### 20.1 Module Format Variants

| Format | File | Use Case | Import Style |
| --- | --- | --- | --- |
| UMD | `gsmui.js` | Traditional `<script>` tag | `<script src="..." defer>` |
| ESM | `gsmui.module.js` | Modern bundlers (Vite, Rollup) | `import 'gsmui/dist/gsmui.module.js'` |
| Minified UMD | `gsmui.min.js` | Production (no build tool) | `<script src="..." defer>` |
| IIFE | `editor.js` | Playground (standalone) | Dynamic `import()` |

### 20.2 Bundle Composition

Each bundle is self-contained — no external imports, no peer dependencies. This is required for CSP compliance (`script-src 'self'`).

**`gsmui.js` contains:**
- Component class definitions
- JS mixins (Controllable, Disableable, Submittable, Focusable)
- MutationObserver setup for `value` + config attributes
- `detangle()` sync-loop prevention
- `setAttribute`/`removeAttribute` utilities
- Event dispatching (`input` + `change` per range spec)
- Keyboard navigation handlers
- Scroll lock utilities
- `adoptedStyleSheets` management

**`editor.js` contains:**
- Monaco Editor wrapper component
- Syntax highlighting for Blade/HTML/CSS/JS
- Live preview iframe management
- Code formatting and linting integration
- Theme synchronization with the main UI

### 20.3 Source Maps

Source maps (`.map` files) are included for debugging but not loaded by default. They allow browser DevTools to map bundled code back to the original source.

| Source Map | Corresponding Bundle | Notes |
| --- | --- | --- |
| `gsmui.js.map` | `gsmui.js` | Development debugging |
| `gsmui.min.js.map` | `gsmui.min.js` | Production debugging |
| `editor.js.map` | `editor.js` | Playground debugging |

## 25. Asset Hashing Strategy

### 25.1 Hash Format

The upstream build uses content-based hashing for cache busting:

```
gsmui.[hash].js       # e.g., gsmui.abc123def.js
editor.[hash].js      # e.g., editor.456ghi789.js
editor.[hash].css     # e.g., editor.jkl012mno.css
```

### 25.2 Cache Headers

The host app should serve `dist/` files with long cache headers:

```
Cache-Control: public, max-age=31536000, immutable
```

The hash in the filename ensures that new versions bypass the cache.

### 25.3 Manifest Versioning

The `manifest.json` is updated with each release. The host app reads it on every page load to resolve the current bundle URLs.

## 32. Migration and Upgrade Paths

### 32.1 Adding a New Component

1. Create `stubs/resources/views/gsmui/<name>/index.blade.php`.
2. Follow sibling patterns (copy from `input`, `select`, `date-picker`).
3. Merge classes via `Gsmui::classes()`.
4. Use `__()` for all user-facing strings and aria-labels.
5. Declare ARIA per closest sibling pattern.
6. Add a story route in `workbench/resources/views/gsmui-stories/<name>.blade.php`.
7. Add Playwright tests in `tests/Browser/<name>.spec.js`.
8. Update the component index in `08.50-folder-structure.md`.
9. Add docs page in `resources/views/gsmui-docs/components/<name>.blade.php`.
10. Verify with Playwright across the state matrix.

### 32.2 Removing a Component

1. Remove `stubs/resources/views/gsmui/<name>/` directory.
2. Remove story route in `workbench/resources/views/gsmui-stories/<name>.blade.php`.
3. Remove Playwright tests in `tests/Browser/<name>.spec.js`.
4. Remove docs page in `resources/views/gsmui-docs/components/<name>.blade.php`.
5. Update the component index in `08.50-folder-structure.md`.
6. Document the deprecation in release notes.

### 32.3 Renaming a Component

1. Create new directory with new name.
2. Copy content from old directory.
3. Update all references (docs, stories, tests).
4. Add a redirect or alias from old name to new name.
5. Deprecate the old name with a warning.

### 32.4 Splitting a Component

When a component becomes too complex, split it into multiple components:

1. Identify the distinct use cases.
2. Create separate directories for each.
3. Move shared partials to a common location.
4. Update imports and references.
5. Document the split in release notes.

## 36. Component Template Anatomy

### 36.1 Standard Template Structure

Every `gsmui:` component Blade template follows this general structure:

```blade
@props([
    'size' => 'default',
    'disabled' => false,
    'invalid' => false,
    'label' => null,
    'description' => null,
])

@php
    $classes = Gsmui::classes([
        // Base classes
        'gsmui-component',
        // Size variant
        match($size) {
            'sm' => 'h-8 text-sm',
            'xs' => 'h-6 text-xs',
            default => 'h-10 text-base sm:text-sm',
        },
        // Disabled state
        $disabled ? 'opacity-50 cursor-not-allowed' : '',
        // Invalid state
        $invalid ? 'data-invalid:border-red-500' : '',
    ]);
@endphp

<div
    {{ $attributes->class($classes) }}
    @if($disabled) disabled @endif
    @if($invalid) data-invalid @endif
    @if($label) aria-label="{{ __($label) }}" @endif
>
    {{ $slot }}
</div>
```

### 36.2 Props Convention

All component props are declared with `@props` at the top of the template. This ensures type safety and default values:

```blade
@props([
    'value' => null,
    'placeholder' => null,
    'size' => 'default',       // 'default' | 'sm' | 'xs'
    'disabled' => false,
    'invalid' => false,
    'label' => null,
    'description' => null,
    'name' => null,
    'wire:model' => null,
])
```

### 36.3 Class Merging with `Gsmui::classes()`

The `Gsmui::classes()` helper merges class arrays intelligently, deduplicating and ordering them:

```blade
@php
    $classes = Gsmui::classes([
        // Base styles
        'bg-white dark:bg-white/10',
        'border border-zinc-200 dark:border-white/10',
        'rounded-lg shadow-xs',
        // Size variant
        match($size) {
            'sm' => 'h-8 text-sm px-3',
            'xs' => 'h-6 text-xs px-2',
            default => 'h-10 text-base sm:text-sm px-4',
        },
        // Conditional classes
        $disabled ? 'opacity-50 cursor-not-allowed' : null,
        $invalid ? 'border-red-500 focus:border-red-500' : null,
    ]);
@endphp
```

### 36.4 ARIA Pattern Assignment

Each component declares its ARIA role and attributes based on the closest sibling pattern:

| Component Type | ARIA Pattern | Example |
| --- | --- | --- |
| Input trigger | `role="combobox"` on `<input>` | select, combobox |
| Button trigger | Native `<button>` with `aria-haspopup="dialog"` | date-picker, modal |
| Toggle | `role="switch"` or `role="checkbox"` | switch, checkbox |
| Navigation | `role="tablist"` + `role="tab"` | tabs |
| Overlay | `role="dialog"` + `aria-modal="true"` | modal, drawer |
| Live region | `aria-live="polite"` | toast, sonner |

### 39.2 Middleware Implementation

```php
<?php
// src/Http/Middleware/CspMiddleware.php

namespace Gsmui\GsmuiPro\Http\Middleware;

use Closure;
use Illuminate\Http\Request;
use Illuminate\Support\Facades\Vite;

class CspMiddleware
{
    public function handle(Request $request, Closure $next)
    {
        $response = $next($request);

        if (!config('gsmui-pro-csp.enabled', false)) {
            return $response;
        }

        $directives = config('gsmui-pro-csp.directives', []);

        // Merge dynamic directives based on feature flags
        $dynamicDirectives = config('gsmui-pro-csp.dynamic_directives', []);
        foreach ($dynamicDirectives as $feature => $featureDirectives) {
            if (config("gsmui-pro-csp.features.{$feature}", false)) {
                foreach ($featureDirectives as $directive => $sources) {
                    $directives[$directive] = array_merge(
                        $directives[$directive] ?? [],
                        $sources
                    );
                }
            }
        }

        // Build header string
        $headerParts = [];
        foreach ($directives as $directive => $sources) {
            $headerParts[] = $directive . ' ' . implode(' ', $sources);
        }
        $headerValue = implode('; ', $headerParts);

        // Add nonce if enabled
        if (config('gsmui-pro-csp.nonce_enabled', false)) {
            $nonce = base64_encode(random_bytes(16));
            $request->attributes->set('csp_nonce', $nonce);
            $headerValue = str_replace(
                "'unsafe-inline'",
                "'unsafe-inline' nonce>{$nonce}'",
                $headerValue
            );
        }

        // Determine header name
        $headerName = config('gsmui-pro-csp.report_only', false)
            ? 'Content-Security-Policy-Report-Only'
            : 'Content-Security-Policy';

        // Add report URI if configured
        $reportUri = config('gsmui-pro-csp.report_uri');
        if ($reportUri) {
            $headerValue .= "; report-uri {$reportUri}";
        }

        $response->headers->set($headerName, $headerValue);

        return $response;
    }
}
```
