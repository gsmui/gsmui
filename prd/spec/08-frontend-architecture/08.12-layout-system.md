This document specifies the *layout shell contract* and does NOT re-document routing or navigation semantics.

# Purpose

The layout system defines the reusable application shell: a fixed `gsmui:sidebar`, a `gsmui:navbar` header, and a scrollable content region, composed through `stubs/resources/views/gsmui/layouts/*`. Layouts are pure structure — they delegate navigation to `08.13-navigation-system.md` and overlays to `08.20-overlay-components.md`. All surfaces use `--gsmui-*` tokens and the `bg-white dark:bg-zinc-800` surface pattern established by sibling components.

---

## 1. App Shell Anatomy

```text
┌────────────┬──────────────────────────────────────┐
│            │  gsmui:navbar (header)               │
│ gsmui:     │──────────────────────────────────────│
│ sidebar    │                                       │
│ (aside)    │  content (main, scrollable)          │
│            │   - containers / grid / cards         │
└────────────┴──────────────────────────────────────┘
```

The shell is a CSS grid: `grid-cols-[auto_1fr]` on `lg+`, collapsing to a single column with an off-canvas `gsmui:sidebar` (`type="drawer"`) below `lg`.

## 2. Surface Token Contract

| Region | Light | Dark | Border |
| --- | --- | --- | --- |
| Sidebar | `bg-white` | `bg-zinc-800` | `border-r border-zinc-200 dark:border-white/10` |
| Navbar | `bg-white` | `bg-zinc-800` | `border-b border-zinc-200 dark:border-white/10` |
| Content | `bg-zinc-50` | `bg-zinc-900` | — |

Never hardcode hex surfaces; prefer `bg-(--gsmui-color-surface)` tokens where the Design Token Engine provides them (`05.16-theme-engine.md`).

## 3. Component Contracts

### 3.1 `gsmui:sidebar`

`stubs/resources/views/gsmui/sidebar/index.blade.php`:

| Prop | Values | Default |
| --- | --- | --- |
| `type` | `static`\|`overlay`\|`drawer` | `static` |
| `position` | `left`\|`right` | `left` |
| `width` | `xs`(w-48) `sm`(w-56) `md`(w-64) `lg`(w-72) `xl`(w-80) | `md` |
| `collapsible` | bool | `false` |
| `open` | bool | `false` |

- Collapse state is Alpine `collapsed` toggled by a `gsmui:button` (no `cursor-pointer` — it is a native `<button>`).
- Aria: the collapse button carries `aria-label="{{ __('Collapse') }}/__('Expand') }}"`; the `<aside>` is a landmark.

### 3.2 `gsmui:navbar`

`stubs/resources/views/gsmui/navbar/index.blade.php`:

| Prop | Values | Default |
| --- | --- | --- |
| `variant` | `null`\|`outline` | `null` |

`outline` adds `rounded-lg border border-zinc-200 dark:border-white/10 bg-white dark:bg-zinc-800 p-1 shadow-xs`. Root is a `<nav data-gsmui-navbar>` with `flex items-center gap-1`.

## 4. Grid & Containers

- Page content uses Tailwind v4 `container` + `mx-auto` with `--gsmui-container-pad` (default `px-4 sm:px-6 lg:px-8`).
- 12-column responsive grid: `grid grid-cols-1 md:grid-cols-12 gap-4`. Dashboard widgets span `md:col-span-*` per `08.21-dashboard-ui.md`.
- Sticky headers use `sticky top-0 z-30` with the navbar surface color to avoid white-on-white scroll overlap (critical state per AGENTS.md).

## 5. Layout Blade Skeleton

```blade
<x-layouts.app>
    <x-slot:sidebar>
        <gsmui:sidebar type="static" collapsible>
            <gsmui:navlist> ... </gsmui:navlist>
        </gsmui:sidebar>
    </x-slot:sidebar>

    <gsmui:navbar>
        <gsmui:command placeholder="{{ __('Search…') }}" />
    </gsmui:navbar>

    <main class="p-4 sm:p-6">
        {{ $slot }}
    </main>
</x-layouts.app>
```

`x-layouts.app` is registered under the `gsmui:` namespace and lives in `stubs/resources/views/gsmui/layouts/`.

## 6. Open Questions / Risks

- Should `type="drawer"` lock body scroll when open (per the date-picker scroll-lock rule in AGENTS.md)? Recommend yes for parity.
- `sidebar` currently duplicates the nav slot for collapsed/expanded; collapse via `x-show` only to avoid duplicate-DOM a11y issues.
- Define a `--gsmui-z-sidebar` token so overlays (`08.20`) layer correctly above/below the shell.

## 7. Deep Dive: App Shell CSS Grid

### 7.1 Grid Definition

The app shell uses CSS Grid for precise region placement:

```css
.gsmui-shell {
  display: grid;
  grid-template-columns: auto 1fr;
  grid-template-rows: auto 1fr;
  grid-template-areas:
    "sidebar navbar"
    "sidebar content";
  min-height: 100vh;
  min-height: 100dvh; /* dynamic viewport height for mobile */
}
```

| Area | Grid placement | Behavior |
| --- | --- | --- |
| `sidebar` | `grid-area: sidebar` | Fixed width (per `width` prop), full height |
| `navbar` | `grid-area: navbar` | Full remaining width, sticky top |
| `content` | `grid-area: content` | Full remaining width, scrollable |

### 7.2 Collapse Breakpoints

| Viewport | Grid definition | Sidebar behavior |
| --- | --- | --- |
| `< 768px` | `grid-template-columns: 1fr` | `type="drawer"` — off-canvas, toggled via hamburger |
| `768px – 1023px` | `grid-template-columns: auto 1fr` | `type="static"`, collapsed width (64px) |
| `≥ 1024px` | `grid-template-columns: auto 1fr` | `type="static"`, full width (per `width` prop) |

### 7.3 Grid Token Variables

```css
:root {
  --gsmui-shell-sidebar-width: 256px;   /* md (w-64) default */
  --gsmui-shell-sidebar-collapsed: 64px;
  --gsmui-shell-navbar-height: 64px;
  --gsmui-shell-z-sidebar: 40;
  --gsmui-shell-z-navbar: 30;
  --gsmui-shell-z-drawer: 50;
  --gsmui-shell-z-overlay: 60;
}
```

### 7.4 Sidebar Width Variants

| Prop value | CSS width | Tailwind | px |
| --- | --- | --- | --- |
| `xs` | `w-48` | `12rem` | 192px |
| `sm` | `w-56` | `14rem` | 224px |
| `md` | `w-64` | `16rem` | 256px |
| `lg` | `w-72` | `18rem` | 288px |
| `xl` | `w-80` | `20rem` | 320px |
| collapsed | `w-16` | `4rem` | 64px |

## 8. Deep Dive: Sidebar Component

### 8.1 Sidebar Types

**Static sidebar:**
```blade
<gsmui:sidebar type="static" width="md">
    <x-slot:logo>
        <img src="/logo.svg" alt="{{ config('app.name') }}" class="h-8" />
    </x-slot:logo>
    <gsmui:navlist>
        {{-- nav items --}}
    </gsmui:navlist>
</gsmui:sidebar>
```

- Always visible on `md+` viewports.
- Collapses to icon-only mode when `collapsible` is true.
- Occupies grid space (pushes content to the right).

**Overlay sidebar:**
```blade
<gsmui:sidebar type="overlay" width="md" :open="$sidebarOpen">
    {{-- same content as static --}}
</gsmui:sidebar>
```

- Floats above content with `position: fixed`.
- Backdrop overlay on open.
- Does NOT push content — content stays full width.
- Used for secondary navigation panels.

**Drawer sidebar:**
```blade
<gsmui:sidebar type="drawer" position="left" :open="$drawerOpen">
    {{-- same content as static --}}
</gsmui:sidebar>
```

- Slides in from the edge (left or right).
- Full height, locks body scroll.
- Traps focus inside the drawer.
- Used as the mobile navigation replacement.

### 8.2 Sidebar Position

```blade
{{-- Left sidebar (default) --}}
<gsmui:sidebar position="left">...</gsmui:sidebar>

{{-- Right sidebar (for settings panels, etc.) --}}
<gsmui:sidebar position="right">...</gsmui:sidebar>
```

Position affects:
- Slide direction (`translate-x` axis).
- Border side (`border-r` for left, `border-l` for right).
- Grid area placement (left = `grid-area: sidebar`, right = `grid-area: sidebar-end`).

### 8.3 Collapsible Behavior

When `collapsible` is true:

```blade
<gsmui:sidebar type="static" collapsible :collapsed="$sidebarCollapsed">
    <x-slot:logo>
        <img src="/logo.svg" alt="{{ config('app.name') }}" class="h-8" />
    </x-slot:logo>
    <x-slot:logo-collapsed>
        <img src="/logo-icon.svg" alt="{{ config('app.name') }}" class="h-8" />
    </x-slot:logo-collapsed>
    <gsmui:navlist :collapsed="$sidebarCollapsed">
        {{-- nav items — labels hidden when collapsed --}}
    </gsmui:navlist>
</gsmui:sidebar>
```

Collapse state management:
- A `gsmui:button` at the bottom of the sidebar toggles collapse.
- The button uses `aria-label="{{ __('Collapse') }}"` / `aria-label="{{ __('Expand') }}"`.
- Collapse state is persisted via `localStorage` (Alpine `x-persist` or Livewire session).
- Transition: `transition-all duration-200 ease-in-out` on the sidebar width.

### 8.4 Sidebar Slots

| Slot | Purpose | Required |
| --- | --- | --- |
| `logo` | Full-width logo (expanded state) | Yes |
| `logo-collapsed` | Icon-only logo (collapsed state) | Only if `collapsible` |
| `default` | Main sidebar content (navlist, etc.) | Yes |
| `footer` | Bottom-pinned content (user menu, etc.) | No |

### 8.5 Sidebar Scroll Behavior

- Sidebar content scrolls independently of the main content area.
- `overflow-y: auto` on the sidebar content region.
- Custom scrollbar styling via `scrollbar-width: thin` and `scrollbar-color`.
- Logo region is sticky at the top: `position: sticky; top: 0; z-index: 10;`.

## 10. Deep Dive: Content Region

### 10.1 Content Container

```blade
<main class="flex-1 overflow-y-auto">
    <div class="gsmui-container mx-auto px-4 sm:px-6 lg:px-8 py-6">
        {{ $slot }}
    </div>
</main>
```

### 10.2 Container Token

The container padding uses a CSS variable for consistency:

```css
:root {
  --gsmui-container-pad-x: 1rem;       /* default: px-4 */
}

@media (min-width: 640px) {
  :root { --gsmui-container-pad-x: 1.5rem; } /* sm: px-6 */
}

@media (min-width: 1024px) {
  :root { --gsmui-container-pad-x: 2rem; }   /* lg: px-8 */
}
```

### 10.3 Content Max Width

For readability, content can be constrained:

| Context | Max width | Class |
| --- | --- | --- |
| Full width (dashboard) | None | — |
| Documentation | `max-w-3xl` | `max-w-3xl mx-auto` |
| Marketing | `max-w-7xl` | `max-w-7xl mx-auto` |
| Single column form | `max-w-lg` | `max-w-lg mx-auto` |

### 10.4 Scroll Behavior

- Content region scrolls independently: `overflow-y: auto` on `<main>`.
- Smooth scrolling: `scroll-behavior: smooth` on the content container (respects `prefers-reduced-motion`).
- Scroll restoration: Livewire preserves scroll position on navigation.

## 13. Z-Index Scale

All z-index values use CSS variables to prevent layering conflicts:

| Token | Value | Use |
| --- | --- | --- |
| `--gsmui-z-base` | 0 | Default content |
| `--gsmui-z-sticky` | 10 | Sticky headers |
| `--gsmui-z-navbar` | 30 | Navbar |
| `--gsmui-z-sidebar` | 40 | Sidebar |
| `--gsmui-z-drawer` | 50 | Mobile drawer |
| `--gsmui-z-dropdown` | 55 | Dropdowns, popovers |
| `--gsmui-z-overlay` | 60 | Modal backdrop |
| `--gsmui-z-modal` | 70 | Modal dialog |
| `--gsmui-z-toast` | 80 | Toast notifications |
| `--gsmui-z-tooltip` | 90 | Tooltips (highest) |

### 13.1 Z-Index Conflicts

Never use raw `z-50` or `z-[9999]` — always use the token:

```blade
{{-- ✅ Correct --}}
<div class="z-[var(--gsmui-z-modal)]">

{{-- ❌ Wrong --}}
<div class="z-50">
```

## 14. Layout Accessibility

### 14.1 Landmark Roles

| Region | HTML element | Implicit ARIA role |
| --- | --- | --- |
| Sidebar | `<aside>` | `complementary` |
| Navbar | `<nav>` | `navigation` |
| Main content | `<main>` | `main` |
| Footer | `<footer>` | `contentinfo` |

### 14.2 Skip Navigation

Every layout includes a skip navigation link:

```blade
<a href="#main-content"
   class="sr-only focus:not-sr-only focus:absolute focus:top-4 focus:left-4 focus:z-[var(--gsmui-z-toast)] focus:bg-white focus:px-4 focus:py-2 focus:rounded-lg focus:shadow-lg">
    {{ __('Skip to main content') }}
</a>

<main id="main-content" tabindex="-1">
    {{ $slot }}
</main>
```

### 14.3 Focus Management in Drawers

When a drawer sidebar opens:
1. Focus moves to the first focusable element inside the drawer.
2. Tab is trapped within the drawer.
3. `Escape` closes the drawer and returns focus to the hamburger button.
4. The backdrop is `aria-hidden="true"` but receives click events to close.

### 14.4 Responsive Focus Considerations

- On mobile, the drawer trap must NOT prevent access to the main content.
- When the drawer closes, focus MUST return to the element that opened it.
- Screen readers must announce the drawer as a navigation region.

## 17. Layout Performance

### 17.1 Critical Rendering Path

The app shell should render above the fold:

1. **Inline critical CSS** — Navbar and sidebar styles are inlined in the `<head>`.
2. **Defer non-critical** — Content area styles load async.
3. **Font loading** — System fonts only (no `@font-face`), zero FOUT.

### 17.2 Layout Shift Prevention

```css
/* Prevent CLS from sidebar collapse */
.gsmui-sidebar {
  transition: width 200ms ease-in-out;
  will-change: width;
}

/* Reserve space for navbar */
.gsmui-shell {
  padding-top: var(--gsmui-shell-navbar-height);
}

/* Sidebar width is known — no layout shift */
.gsmui-sidebar[data-width="md"] { width: 256px; }
```

### 17.3 Scroll Performance

- Content scroll uses `overflow-y: auto` (not `scroll`) for performance.
- `will-change: transform` is NOT applied to the scroll container (causes unnecessary compositing layers).
- Sticky navbar uses `position: sticky` (GPU-accelerated) instead of `position: fixed`.

## 25. Layout Performance Deep Dive

### 25.1 Critical Rendering Path

The layout shell should render above the fold:

```html
<head>
    <!-- Inline critical layout CSS -->
    <style>
        .gsmui-shell { display: grid; grid-template-columns: 1fr; min-height: 100vh; }
        .gsmui-sidebar { display: none; }
        .gsmui-navbar { height: 64px; border-bottom: 1px solid #e4e4e7; background: white; }
        @media (min-width: 768px) {
            .gsmui-shell { grid-template-columns: 64px 1fr; }
            .gsmui-sidebar { display: block; width: 64px; }
        }
        @media (min-width: 1024px) {
            .gsmui-shell { grid-template-columns: 256px 1fr; }
            .gsmui-sidebar { width: 256px; }
        }
    </style>
</head>
```

### 25.2 Layout Shift Prevention

| Shift source | Prevention |
| --- | --- |
| Sidebar width change | Reserved space via grid-template-columns |
| Navbar height change | Fixed height with min-height |
| Content loading | Skeleton placeholders during Livewire loading |
| Font loading | System fonts only (no FOUT) |
| Image loading | `aspect-ratio` or fixed dimensions on images |

### 25.3 Scroll Performance

| Technique | Use | Avoid |
| --- | --- |---|
| `overflow-y: auto` on content region | Independent scroll | `overflow: scroll` (always shows scrollbar) |
| `position: sticky` on navbar | GPU-accelerated stickiness | `position: fixed` (removes from flow) |
| `will-change: transform` | Before animation only | Permanent application |
| `transform: translateZ(0)` | Force GPU layer for sticky elements | Overuse (wastes memory) |

### 25.4 Sidebar Transition Performance

The sidebar collapse/expand transition must be GPU-accelerated:

```css
.gsmui-sidebar {
  will-change: width;
  transition: width 200ms ease-in-out;
}

/* During animation, prevent content reflow */
.gsmui-sidebar.animating {
  contain: layout style;
}
```

## 30. Layout Security Considerations

### 30.1 Content Security Policy

Layouts must not introduce CSP violations:

| Pattern | CSP status | Notes |
| --- | --- | --- |
| Inline `<style>` in layout | ✅ `style-src 'unsafe-inline'` | Used for critical CSS |
| `<script>` tags | ❌ Never in layouts | Scripts in `dist/` only |
| External resources | ❌ Never in layouts | Self-hosted only |
| `eval()` | ❌ Never | CSP violation |

### 30.2 XSS Prevention in Layouts

```blade
{{-- ✅ Safe: escaped output --}}
<h1>{{ config('app.name') }}</h1>

{{-- ❌ Dangerous: unescaped output --}}
<h1>{!! $appName !!}</h1>
```

All user-facing content in layouts must be escaped with `{{ }}`. Raw output `{!! !!}` is only permitted for trusted HTML content.

### 30.3 Session Security

Layout state (sidebar collapse, etc.) should not be stored in cookies without proper security:

```php
// ✅ Safe: server-side session
session(['sidebar-collapsed' => $collapsed]);

// ⚠️ Acceptable: localStorage (client-side only, no sensitive data)
localStorage.setItem('gsmui-sidebar-collapsed', JSON.stringify($collapsed));

// ❌ Never: cookies with sensitive data
setcookie('sidebar', $collapsed); // No sensitive data in layout state
```

test('layout has no layout shift', async ({ page }) => {

    const cls = await page.evaluate(() => {
        return new Promise(resolve => {
            let clsValue = 0;
            const observer = new PerformanceObserver((list) => {
                for (const entry of list.getEntries()) {
                    if (!entry.hadRecentInput) {
                        clsValue += entry.value;
                    }
                }
            });
            observer.observe({ type: 'layout-shift', buffered: true });
            
            setTimeout(() => {
                observer.disconnect();
                resolve(clsValue);
            }, 1000);
        });
    });
    
    expect(cls).toBe(0);
});
