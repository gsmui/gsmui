# 07.04 - Module Architecture

**Project:** GsmUi
**Architecture:** Modular Monolith
**Framework:** Laravel 13 + Livewire 4
**Version:** 1.0.0

---

> See also: `05.05-module-boundaries.md` (module ownership, dependency matrix, forbidden dependencies, communication mechanisms). This document specifies the *implementation contract* — the concrete module manifest, per-module service provider, and public/internal API boundary — required to build modules as described there.

# Purpose

GsmUi is a single deployable Laravel application partitioned into business modules. This document is the implementation contract that makes those modules real: how each module declares itself, how it registers its routes/providers/bindings, and which of its classes are public (consumable by other modules) versus internal (private implementation detail). Following this contract keeps modules swappable and, per `05.05-module-boundaries.md`, extractable into microservices later with minimal change.

Every new module MUST implement the contract below. Deviation is an architectural violation.

---

## 1. Modular Monolith Structure

Each module is a self-contained subtree under `app/Domains/<Name>/`. The root contains a `Module.php` manifest and a `<Name>ServiceProvider.php`.

```text
app/Domains/Components/
├── Module.php                  (manifest)
├── ComponentsServiceProvider.php (registration)
├── Actions/
├── Services/
├── Repositories/
├── Models/
├── Events/
├── Listeners/
├── Jobs/
├── Policies/
├── Enums/
├── ValueObjects/
├── Http/
├── Livewire/
├── Database/
└── Tests/
```

Modules load automatically via a single `DomainServiceProvider` (see `07.05-folder-structure.md`) that discovers every `app/Domains/*/Module.php`.

---

## 2. Module Manifest

Each module exposes a `Module` class describing its metadata and allowed dependencies. This is the machine-readable form of the `05.05-module-boundaries.md` dependency matrix.

```php
namespace App\Domains\Components;

use App\Shared\Module\ModuleManifest;

final class Module extends ModuleManifest
{
    public string $name = 'components';

    /** Modules this module may depend on (downward only). */
    public array $dependsOn = ['users', 'system'];

    /** Public service contracts other modules may consume. */
    public array $publicContracts = [
        \App\Domains\Components\Contracts\ComponentServiceContract::class,
    ];

    /** Routes provided by this module. */
    public array $routeFiles = ['web.php', 'api.php'];

    /** Service provider class for this module. */
    public string $provider = ComponentsServiceProvider::class;
}
```

The base `ModuleManifest` is a Shared Kernel primitive in `app/Shared/Module/ModuleManifest.php`. The `DomainServiceProvider` iterates all manifests to enforce that `dependsOn` never points upward or forms a cycle (failing fast at boot).

## 3. Service Providers Per Module

Each module registers its own bindings, routes, and event listeners in its `<Name>ServiceProvider`. This keeps registration local to the module.

```php
namespace App\Domains\Components;

use App\Domains\Components\Contracts\ComponentServiceContract;
use App\Domains\Components\Repositories\ComponentRepository;
use App\Domains\Components\Repositories\ComponentRepositoryEloquent;
use App\Domains\Components\Services\ComponentService;
use Illuminate\Support\ServiceProvider;

final class ComponentsServiceProvider extends ServiceProvider
{
    public function register(): void
    {
        // Bind repository contract to Eloquent implementation.
        $this->app->bind(ComponentRepository::class, ComponentRepositoryEloquent::class);

        // Bind public service contract.
        $this->app->bind(ComponentServiceContract::class, ComponentService::class);
    }

    public function boot(): void
    {
        // Load module routes (see 05.05 dependency rules).
        $this->loadRoutesFrom(__DIR__ . '/../routes/web.php');
    }
}
```

Rules:

- `register()` binds contracts; `boot()` wires routes, views, migrations, listeners, policies.
- A module provider must only bind its own contracts and routes — never another module's.
- Cross-module consumption goes through the *public contract* (see §4), not through another module's concrete class.

## 4. Public vs Internal APIs

Every module has a clear surface. Internal classes are never referenced outside the module.

| Visibility | Location | Consumable by | Rule |
| --- | --- | --- | --- |
| Public | `Contracts/` + select `Services/` | Other modules | Listed in `Module::$publicContracts` |
| Internal | `Repositories/`, `Models/`, `Actions/` internals | Same module only | Never imported cross-module |

```php
// Public contract (safe to depend on from other modules)
namespace App\Domains\Components\Contracts;

interface ComponentServiceContract
{
    public function find(string $slug): ?Component;
}
```

```php
// Internal — must NOT be imported by another module
namespace App\Domains\Components\Repositories;

final class ComponentRepositoryEloquent implements ComponentRepository { /* ... */ }
```

Cross-module access patterns (per `05.05-module-boundaries.md` "Module Communication"):

1. **Service contract** — synchronous read/write via a `Contracts/*` interface.
2. **Domain event** — fire-and-forget notification (no return value).
3. **Query service** — read-only projection of another module's data.
4. **Shared contract** — interface in `app/Shared/Contracts/`.

Forbidden: repository-to-repository calls, direct cross-module table mutation, `Livewire → Model`, `Controller → Repository` (see `05.06-folder-structure.md` dependency rules).

## 6. Module Discovery and Boot Sequence

### 6.1 Boot Order

The `DomainServiceProvider` iterates all modules and boots them in a specific order to satisfy dependencies.

```text
DomainServiceProvider::boot()
    │
    ├── Step 1: Discover all Module.php manifests
    │       └── Glob: app/Domains/*/Module.php
    │
    ├── Step 2: Validate dependency graph
    │       ├── Check for cycles (A → B → A = ERROR)
    │       ├── Check for upward dependencies (child → parent = ERROR)
    │       └── Check for missing modules (A → B, B doesn't exist = ERROR)
    │
    ├── Step 3: Topological sort (boot dependencies first)
    │       └── Example: users → system → components → themes → billing
    │
    ├── Step 4: Register each module's ServiceProvider
    │       ├── Call register() on each provider
    │       └── Bind contracts, register aliases
    │
    └── Step 5: Boot each module's ServiceProvider
            ├── Load routes, views, migrations, events
            └── Register policies, gates, observers
```

### 6.2 DomainServiceProvider Implementation

```php
namespace App\Providers;

use Illuminate\Support\Facades\File;
use Illuminate\Support\ServiceProvider;

final class DomainServiceProvider extends ServiceProvider
{
    public function register(): void
    {
        $modules = $this->discoverModules();

        $this->validateDependencyGraph($modules);

        $sorted = $this->topologicalSort($modules);

        foreach ($sorted as $module) {
            $provider = new $module->provider($this->app);
            $provider->register();
        }
    }

    public function boot(): void
    {
        $modules = $this->discoverModules();

        foreach ($modules as $module) {
            $provider = new $module->provider($this->app);
            $provider->boot();
        }
    }

    private function discoverModules(): array
    {
        $manifests = [];

        foreach (File::glob(app_path('Domains/*/Module.php')) as $file) {
            $class = $this->resolveClassName($file);
            $manifests[] = new $class();
        }

        return $manifests;
    }

    private function validateDependencyGraph(array $modules): void
    {
        $names = array_map(fn ($m) => $m->name, $modules);

        foreach ($modules as $module) {
            foreach ($module->dependsOn as $dependency) {
                if (! in_array($dependency, $names)) {
                    throw new \RuntimeException(
                        "Module '{$module->name}' depends on '{$dependency}' which does not exist."
                    );
                }
            }
        }

        // Check for cycles
        if ($this->hasCycle($modules)) {
            throw new \RuntimeException('Circular dependency detected in module graph.');
        }
    }

    private function hasCycle(array $modules): bool
    {
        $visited = [];
        $stack = [];

        foreach ($modules as $module) {
            if ($this->dfs($module->name, $modules, $visited, $stack)) {
                return true;
            }
        }

        return false;
    }

    private function dfs(string $name, array $modules, array &$visited, array &$stack): bool
    {
        if (in_array($name, $stack)) {
            return true; // Cycle detected
        }

        if (in_array($name, $visited)) {
            return false; // Already processed
        }

        $visited[] = $name;
        $stack[] = $name;

        $module = collect($modules)->first(fn ($m) => $m->name === $name);

        if ($module) {
            foreach ($module->dependsOn as $dep) {
                if ($this->dfs($dep, $modules, $visited, $stack)) {
                    return true;
                }
            }
        }

        array_pop($stack);
        return false;
    }

    private function topologicalSort(array $modules): array
    {
        $sorted = [];
        $visited = [];

        foreach ($modules as $module) {
            $this->visit($module->name, $modules, $visited, $sorted);
        }

        return $sorted;
    }

    private function visit(string $name, array $modules, array &$visited, array &$sorted): void
    {
        if (in_array($name, $visited)) {
            return;
        }

        $visited[] = $name;

        $module = collect($modules)->first(fn ($m) => $m->name === $name);

        if ($module) {
            foreach ($module->dependsOn as $dep) {
                $this->visit($dep, $modules, $visited, $sorted);
            }
            $sorted[] = $module;
        }
    }
}
```

```php
    // Public routes
    Route::get('/', [ComponentController::class, 'index'])->name('index');

    // Authenticated routes
    Route::middleware('auth')->group(function () {
        Route::get('/create', [ComponentController::class, 'create'])->name('create');
        Route::post('/', [ComponentController::class, 'store'])->name('store');
        Route::get('/{component}/edit', [ComponentController::class, 'edit'])->name('edit');
        Route::put('/{component}', [ComponentController::class, 'update'])->name('update');
        Route::delete('/{component}', [ComponentController::class, 'destroy'])->name('destroy');
    });

    // API routes
    Route::prefix('api')->name('api.')->middleware('auth:sanctum')->group(function () {
        Route::get('/', [ComponentController::class, 'index'])->name('index');
        Route::post('/', [ComponentController::class, 'store'])->name('store');
        Route::put('/{component}', [ComponentController::class, 'update'])->name('update');
        Route::delete('/{component}', [ComponentController::class, 'destroy'])->name('destroy');
    });
});
```

### 7.3 Route Middleware Groups

| Middleware | Applied to | Purpose |
| --- | --- |--- |
| `web` | All web routes | Session, CSRF, validation error sharing |
| `api` | All API routes | Throttle, Sanctum, JSON responses |
| `auth` | Protected routes | Requires authenticated user |
| `auth:sanctum` | API routes | Requires valid API token |
| `verified` | Email-verified routes | Requires verified email |
| `can:{ability}` | Policy-restricted routes | Authorization check |
| `throttle:{rate}` | Rate-limited routes | Rate limiting |
| `signed` | Temporary URLs | URL signature verification |

## 9. Module Communication Patterns (Detailed)

### 9.1 Synchronous Communication

```text
Module A needs data from Module B
    │
    ├── Option 1: Service Contract (recommended)
    │       Module A depends on Contract from Shared/
    │       Module B implements the contract
    │       Resolution via container binding
    │
    ├── Option 2: Event + Response
    │       Module A fires event with callback
    │       Module B listens and provides data
    │       Callback returns data to Module A
    │
    └── Option 3: Query Service (read-only)
            Module A calls QueryService from Module B
            QueryService returns read-only projection
            No write operations exposed
```

### 9.2 Asynchronous Communication

```text
Module A fires domain event
    │
    ├── Option 1: Queued Listener (default)
    │       Event dispatched to queue
    │       Listener processes asynchronously
    │       Module A continues without waiting
    │
    ├── Option 2: Synchronous Listener
    │       Event dispatched in-process
    │       Listener processes immediately
    │       Module A waits for listener to complete
    │
    └── Option 3: Event Batching
            Multiple events batched
            Dispatched as a group
            Reduced queue overhead
```

### 9.3 Communication Anti-Patterns

| Anti-pattern | Problem | Correct approach |
| --- |---|---|
| Direct repository call | Tight coupling, violates boundaries | Use service contract |
| Shared database table | Multiple modules own same data | Each module owns its tables |
| Synchronous cross-module call in transaction | Performance, deadlock risk | Use async events |
| Circular events | A fires event B handles, B fires event A handles | Break cycle with separate events |
| Event with callback | Tight coupling via closure | Use service contract instead |
| God module | One module does everything | Split into multiple modules |

### 13.2 Policy Implementation

```php
namespace App\Domains\Components\Policies;

use App\Domains\Components\Models\Component;
use App\Models\User;

final class ComponentPolicy
{
    public function viewAny(User $user): bool
    {
        return true; // Anyone can view published components
    }

    public function view(User $user, Component $component): bool
    {
        return $component->status === ComponentStatus::Published
            || $component->author_id === $user->id
            || $user->hasRole('admin');
    }

    public function create(User $user): bool
    {
        return $user->hasRole('developer') || $user->hasRole('admin');
    }

    public function update(User $user, Component $component): bool
    {
        return $component->author_id === $user->id
            || $user->hasRole('admin');
    }

    public function delete(User $user, Component $component): bool
    {
        return $component->author_id === $user->id
            || $user->hasRole('admin');
    }

    public function publish(User $user, Component $component): bool
    {
        return ($component->author_id === $user->id || $user->hasRole('admin'))
            && $component->status === ComponentStatus::Draft;
    }
}
```

## 30. Module Architecture Decision Records

### 30.1 ADR-001: Module Communication via Contracts

**Decision:** Cross-module communication uses public contracts (interfaces), not direct class references.

**Rationale:**
- Contracts provide a stable API boundary
- Implementations can change without affecting consumers
- Contracts enable testing with mocks
- Contracts are required for future microservice extraction

**Consequences:**
- More files (contracts + implementations)
- Slightly more complex codebase
- Better long-term maintainability

### 30.2 ADR-002: Events for Cross-Module Side Effects

**Decision:** Cross-module side effects use domain events, not synchronous service calls.

**Rationale:**
- Events decouple modules temporally
- Events can be processed asynchronously
- Events provide audit trail
- Events enable multiple consumers

**Consequences:**
- Eventually consistent (not immediately consistent)
- More complex debugging (events are async)
- Better scalability and performance

### 30.3 ADR-003: One Module Per Business Capability

**Decision:** Each bounded context maps to exactly one module directory.

**Rationale:**
- Clear ownership of data and logic
- Enforces dependency rules
- Enables independent testing
- Enables future extraction

**Consequences:**
- More directories and files
- Clearer architecture
- Easier onboarding

### 30.4 ADR-004: Module-Local Database Tables

**Decision:** Each module owns its database tables. No module may read or write another module's tables directly.

**Rationale:**
- Enforces module boundary at the database level
- Prevents hidden coupling through shared tables
- Enables future database-per-microservice extraction
- Makes module extraction straightforward

**Consequences:**
- Cross-module queries require repository interfaces
- May need denormalization for performance
- More tables overall (some data duplicated)

### 30.5 ADR-005: No Circular Module Dependencies

**Decision:** Module dependency graph must be a DAG (Directed Acyclic Graph). Circular dependencies are an architecture test failure.

**Rationale:**
- Circular dependencies make it impossible to reason about module boundaries
- Prevents independent deployment and testing
- Creates hidden coupling

**Consequences:**
- Must design clean dependency direction upfront
- Shared Kernel or events for genuinely bidirectional needs
- Architecture tests enforce this automatically

### 32.2 Module Registry Service

```php
namespace App\Shared\Modules;

final class ModuleRegistry
{
    private array $modules = [];
    private array $manifests = [];

    public function register(string $manifestPath): void
    {
        $manifest = json_decode(
            file_get_contents($manifestPath),
            associative: true,
        );

        $slug = $manifest['slug'];

        $this->manifests[$slug] = $manifest;
        $this->modules[$slug] = [
            'status' => 'registered',
            'loaded_at' => now(),
        ];
    }

    public function getProvides(string $slug): array
    {
        return $this->manifests[$slug]['provides'] ?? [];
    }

    public function getRequires(string $slug): array
    {
        return $this->manifests[$slug]['requires'] ?? [];
    }

    public function resolveDependencies(): array
    {
        $resolved = [];
        $remaining = array_keys($this->manifests);

        while (!empty($remaining)) {
            $progress = false;

            foreach ($remaining as $slug) {
                $requires = $this->getRequires($slug);
                $met = true;

                foreach ($requires as $dep) {
                    if (!in_array($dep, $resolved)) {
                        $met = false;
                        break;
                    }
                }

                if ($met) {
                    $resolved[] = $slug;
                    $remaining = array_diff($remaining, [$slug]);
                    $progress = true;
                }
            }

            if (!$progress && !empty($remaining)) {
                throw new \RuntimeException(
                    "Circular dependency detected among modules: " .
                    implode(', ', $remaining)
                );
            }
        }

        return $resolved;
    }

    public function validateNoCircles(): bool
    {
        $sorted = $this->resolveDependencies();
        return count($sorted) === count($this->manifests);
    }
}
```

```php
        $component->publish(version: 1);

        $this->assertEquals(
            ComponentStatus::Published,
            $component->status()
        );
        $this->assertEquals(1, $component->version());
    }

    public function test_component_cannot_publish_without_name(): void
    {
        $this->expectException(\InvalidArgumentException::class);

        Component::create(
            name: '',
            slug: ComponentSlug::from('button'),
            authorId: 1,
        );
    }
}
```

## 34. Module Communication Patterns Summary

### 34.1 Decision Matrix

| Pattern | Latency | Coupling | Complexity | Use when |
|---|---|---|---|---|
| Direct service call | Low | High | Low | Same module only |
| Contract injection | Low | Low | Medium | Cross-module, synchronous |
| Domain event (sync) | Low | Low | Medium | Cross-module, same request |
| Domain event (async) | High | Very low | High | Cross-module, different request |
| API route | High | Very low | High | External consumers |
| Queue job | Medium | Low | Medium | Heavy background work |

### 34.2 Communication Flow Diagram

```
User Request
    │
    ▼
┌──────────────┐
│ Controller/  │
│ Livewire     │
└──────┬───────┘
       │
       ▼
┌──────────────┐    Contract     ┌──────────────┐
│ Module A     │ ──────────────▶ │ Module B     │
│ (Component)  │                 │ (User)       │
└──────┬───────┘                 └──────┬───────┘
       │                                │
       │ dispatchAfterCommit            │ dispatchAfterCommit
       ▼                                ▼
┌──────────────┐                 ┌──────────────┐
│ Event:       │                 │ Event:       │
│ Component    │   ┌─────────┐   │ User         │
│ Published    │──▶│ Listener│──▶│ Notified     │
└──────────────┘   └─────────┘   └──────────────┘
```

### 34.3 Anti-Coupling Checklist

- [ ] No module imports another module's Models directly
- [ ] No module imports another module's Repositories directly
- [ ] No module imports another module's Services directly
- [ ] All cross-module communication goes through Contracts
- [ ] Cross-module side effects use domain events
- [ ] Database tables are module-scoped (no shared tables)
- [ ] No circular dependencies (verified by architecture tests)

## 35. Module Evolution Lifecycle

### 35.1 Lifecycle Stages

| Stage | Description | Actions |
|---|---|---|
| **Proposal** | Module idea proposed | Write ADR, get team approval |
| **Scaffold** | Create module structure | Run module generator, create manifest |
| **Develop** | Build core functionality | Implement domain, services, contracts |
| **Stabilize** | Feature complete | Write tests, fix bugs, performance tune |
| **Mature** | In production | Monitor metrics, handle edge cases |
| **Extract** | Independent microservice | Extract to separate repo, set up API |

### 35.2 Module Graduation Criteria

Before marking a module as "mature":

| Criterion | Target | Measurement |
|---|---|---|
| Test coverage | > 80% | PHPUnit coverage report |
| Architecture tests passing | 100% | `php artisan test --filter=Architecture` |
| No circular dependencies | 0 | Architecture test |
| Service class < 500 LOC | Pass | Manual review |
| No public entity properties | Pass | PHPStan level 6 |
| All contracts documented | Pass | DocBlocks on all interface methods |
| Performance benchmarks | < 50ms per action | Benchmark tests |
