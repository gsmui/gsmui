# 07.44 - Analytics

**Project:** GsmUi
**Architecture:** Event Tracking & Aggregation Pipeline
**Framework:** Laravel 13 + Livewire 4
**Version:** 1.0.0

---

> See also: `05.34-analytics-platform.md` (categories, data pipeline, privacy goals) and `06.121-analytics.md` (schema for `analytics_events`, `analytics_sessions`, `analytics_rollups`). This document is the *implementation contract*: the `AnalyticsService` interface, the buffered tracker write path, the aggregation job hook, the reporting query surface, and the PII-hashing rules a builder must follow.

# Purpose

Analytics in GsmUi is a write-heavy, read-light pipeline. The application emits small, structured events from Livewire components, controllers, jobs, and observers; those events are buffered and persisted asynchronously; a scheduled aggregation job folds raw events into pre-computed rollups; and dashboards read exclusively from rollups. This document defines the service contract that guarantees every emitter records events identically, that no request thread ever blocks on analytics I/O, and that no personally identifiable information is stored in raw form.

The design goals are:

- **Non-blocking capture** — tracking a page view or download must add negligible latency to the request. Writes are batched to Redis and flushed by a queue worker.
- **Deterministic schema** — every event carries the same envelope (`name`, `actor`, `context`, `properties`, `occurred_at`) so aggregation is uniform.
- **Privacy by construction** — user identifiers, IPs, and emails are hashed with a keyed HMAC before they ever touch durable storage; opt-out is honored at the tracker boundary.
- **Read from rollups, never raw** — dashboards query `analytics_rollups`; raw `analytics_events` is a short-retention firehose used only for aggregation and forensic replay.

## 1. AnalyticsService Contract

`AnalyticsService` is the single ingress type every layer depends on. It wraps tracking (synchronous, buffered) and reporting (async rollup reads). Emitters never touch `analytics_events` directly.

```php
namespace App\Domains\Analytics\Contracts;

use App\Domains\Analytics\DTOs\AnalyticsSeries;
use App\Domains\Analytics\Enums\AnalyticsEvent;
use Carbon\CarbonImmutable;

interface AnalyticsService
{
    /** Record an event for the current actor. Returns immediately; persistence is async. */
    public function track(AnalyticsEvent $name, array $properties = []): void;

    /** Record an event for an explicit actor (jobs/CLI where auth() is unavailable). */
    public function trackFor(AnalyticsEvent $name, ?int $userId, array $properties = []): void;

    /** Time series of an event over a range, read from rollups (cached). */
    public function series(AnalyticsEvent $name, CarbonImmutable $from, CarbonImmutable $to, string $granularity = 'day'): AnalyticsSeries;

    /** Top dimension values (e.g. most-downloaded components) for an event. */
    public function top(AnalyticsEvent $name, CarbonImmutable $from, CarbonImmutable $to, int $limit = 10): array;
}
```

## 2. Pipeline Overview

```text
Emitter (Livewire / Controller / Job / Observer)
    |
    v
AnalyticsService::track()         [synchronous, in-request]
    |  - opt-out check
    |  - PII hashing
    |  - envelope normalization
    v
Redis buffer (list: analytics:buffer)
    |
    v
FlushAnalyticsBuffer job           [queued, every N seconds / N events]
    |  - bulk insert into analytics_events
    v
analytics_events (raw, 30-day TTL)
    |
    v
AggregateAnalyticsJob              [scheduled, hourly + daily]
    |  - group by (name, dimension, bucket)
    v
analytics_rollups (durable)
    |
    v
AnalyticsService::series()/top()   [dashboards, exports]
```

The synchronous portion (service → Redis) is bounded to a single `RPUSH`. Everything past the buffer is asynchronous and idempotent.

## 3. Event Envelope Contract

Every event is a `TrackedEvent` DTO. Emitters never construct raw arrays.

```php
namespace App\Domains\Analytics\DTOs;

use App\Domains\Analytics\Enums\AnalyticsEvent;
use Carbon\CarbonImmutable;

final readonly class TrackedEvent
{
    /**
     * @param array<string,scalar|null> $context   Environment (path, referrer, device)
     * @param array<string,mixed>       $properties Event-specific payload
     */
    public function __construct(
        public AnalyticsEvent $name,
        public ?string $actorHash,          // HMAC of user id, or null (anonymous)
        public array $context = [],
        public array $properties = [],
        public ?CarbonImmutable $occurredAt = null,
    ) {}

    public function toRow(): array
    {
        return [
            'name'        => $this->name->value,
            'actor_hash'  => $this->actorHash,
            'context'     => json_encode($this->context, JSON_THROW_ON_ERROR),
            'properties'  => json_encode($this->properties, JSON_THROW_ON_ERROR),
            'occurred_at' => ($this->occurredAt ?? CarbonImmutable::now())->toDateTimeString(),
        ];
    }
}
```

Event names are a closed enum so aggregation and reporting share a single vocabulary:

```php
namespace App\Domains\Analytics\Enums;

enum AnalyticsEvent: string
{
    case PageViewed         = 'page.viewed';
    case ComponentViewed    = 'component.viewed';
    case ComponentDownloaded = 'component.downloaded';
    case TemplatePurchased  = 'template.purchased';
    case ThemeExported      = 'theme.exported';
    case SearchPerformed    = 'search.performed';
    case SignupCompleted    = 'signup.completed';
    case CheckoutCompleted  = 'checkout.completed';

    /** Dimension used when rolling this event up (see §5). */
    public function dimension(): string
    {
        return match ($this) {
            self::PageViewed, self::SearchPerformed => 'path',
            self::ComponentViewed, self::ComponentDownloaded => 'component_id',
            self::TemplatePurchased => 'template_id',
            self::ThemeExported => 'theme_id',
            self::CheckoutCompleted, self::SignupCompleted => 'plan',
        };
    }
}
```

## 4. Implementation: Redis-backed Tracker

The concrete `AnalyticsService` enforces opt-out, hashes PII, and buffers to Redis. It performs **no** database writes during the request.

```php
namespace App\Domains\Analytics\Services;

use App\Domains\Analytics\Contracts\AnalyticsService;
use App\Domains\Analytics\DTOs\TrackedEvent;
use App\Domains\Analytics\Enums\AnalyticsEvent;
use App\Domains\Analytics\Support\PiiHasher;
use Illuminate\Support\Facades\Redis;

final class RedisAnalyticsService implements AnalyticsService
{
    private const BUFFER_KEY = 'analytics:buffer';
    private const FLUSH_THRESHOLD = 500;

    public function __construct(private readonly PiiHasher $hasher) {}

    public function track(AnalyticsEvent $name, array $properties = []): void
    {
        $this->trackFor($name, auth()?->id(), $properties);
    }

    public function trackFor(AnalyticsEvent $name, ?int $userId, array $properties = []): void
    {
        if ($this->optedOut($userId)) {
            return;
        }

        $event = new TrackedEvent(
            name:       $name,
            actorHash:  $userId !== null ? $this->hasher->hashActor($userId) : null,
            context:    $this->captureContext(),
            properties: $this->sanitize($properties),
        );

        $length = Redis::rpush(self::BUFFER_KEY, json_encode($event->toRow(), JSON_THROW_ON_ERROR));

        if ($length >= self::FLUSH_THRESHOLD) {
            \App\Domains\Analytics\Jobs\FlushAnalyticsBuffer::dispatch();
        }
    }

    private function captureContext(): array
    {
        $request = request();

        return [
            'path'     => $request?->path(),
            'referrer' => $request?->headers->get('referer'),
            'ip_hash'  => $request ? $this->hasher->hashIp($request->ip()) : null,
            'device'   => $request?->userAgent() ? $this->hasher->deviceClass($request->userAgent()) : null,
        ];
    }

    /** Strip any keys that could smuggle raw PII into properties. */
    private function sanitize(array $properties): array
    {
        return collect($properties)
            ->reject(fn ($_, string $key) => in_array($key, PiiHasher::FORBIDDEN_KEYS, true))
            ->all();
    }

    private function optedOut(?int $userId): bool
    {
        return $userId !== null
            && cache()->remember("analytics:optout:{$userId}", 3600,
                fn () => \App\Domains\Users\Models\UserPreference::where('user_id', $userId)
                    ->value('analytics_opt_out') === true);
    }
}
```

Usage from a Livewire component or controller is a one-liner:

```php
app(AnalyticsService::class)->track(AnalyticsEvent::ComponentDownloaded, [
    'component_id' => $component->id,
    'version'      => $component->latest_version,
]);
```

## 5. PII Hashing

No raw identifier is ever persisted. `PiiHasher` uses a keyed HMAC (SHA-256) with a dedicated app key so hashes are stable for cohort analysis but non-reversible. IPs are truncated before hashing to avoid single-user re-identification.

```php
namespace App\Domains\Analytics\Support;

final class PiiHasher
{
    public const FORBIDDEN_KEYS = ['email', 'name', 'ip', 'phone', 'password', 'token'];

    public function __construct(private readonly string $key) {} // config('analytics.hash_key')

    public function hashActor(int $userId): string
    {
        return hash_hmac('sha256', "user:{$userId}", $this->key);
    }

    public function hashIp(?string $ip): ?string
    {
        if ($ip === null) {
            return null;
        }

        $network = str_contains($ip, ':')
            ? implode(':', array_slice(explode(':', $ip), 0, 3)) . '::'
            : preg_replace('/\.\d+$/', '.0', $ip);

        return hash_hmac('sha256', "ip:{$network}", $this->key);
    }

    public function deviceClass(string $userAgent): string
    {
        return str_contains(strtolower($userAgent), 'mobile') ? 'mobile' : 'desktop';
    }
}
```

Rules a builder must follow:

- Actor identity is stored only as `actor_hash`; joins back to `users` are impossible by design.
- `FORBIDDEN_KEYS` are dropped from `properties` at the tracker boundary — defense in depth against accidental leakage.
- The HMAC key (`config('analytics.hash_key')`) is separate from `APP_KEY` and rotated only with a documented cohort-break.
- Opt-out short-circuits before hashing, so an opted-out user produces zero rows.

## 6. Aggregation Job Hook

Raw events are flushed in bulk, then folded into rollups on a schedule. The aggregation job is idempotent and safe to retry. This is the hook the scheduler (see `07.50-scheduler.md`) invokes.

```php
namespace App\Domains\Analytics\Jobs;

use App\Domains\Analytics\Enums\AnalyticsEvent;
use App\Domains\Analytics\Models\AnalyticsRollup;
use Carbon\CarbonImmutable;
use Illuminate\Bus\Queueable;
use Illuminate\Contracts\Queue\ShouldQueue;
use Illuminate\Foundation\Bus\Dispatchable;
use Illuminate\Queue\InteractsWithQueue;
use Illuminate\Support\Facades\DB;

final class AggregateAnalyticsJob implements ShouldQueue
{
    use Dispatchable, InteractsWithQueue, Queueable;

    public int $tries = 3;
    public int $backoff = 60;

    /** @param 'hour'|'day' $granularity */
    public function __construct(private readonly string $granularity = 'hour') {}

    public function handle(): void
    {
        $bucketExpr = $this->granularity === 'day'
            ? "DATE(occurred_at)"
            : "DATE_FORMAT(occurred_at, '%Y-%m-%d %H:00:00')";

        foreach (AnalyticsEvent::cases() as $event) {
            $dimension = $event->dimension();

            $rows = DB::table('analytics_events')
                ->selectRaw("{$bucketExpr} as bucket")
                ->selectRaw("JSON_UNQUOTE(JSON_EXTRACT(properties, '$.{$dimension}')) as dimension_value")
                ->selectRaw('COUNT(*) as event_count')
                ->selectRaw('COUNT(DISTINCT actor_hash) as unique_actors')
                ->where('name', $event->value)
                ->where('occurred_at', '>=', $this->windowStart())
                ->groupBy('bucket', 'dimension_value')
                ->get();

            foreach ($rows as $row) {
                // Idempotent upsert keyed by (name, granularity, bucket, dimension_value).
                AnalyticsRollup::updateOrCreate(
                    [
                        'name'            => $event->value,
                        'granularity'     => $this->granularity,
                        'bucket'          => $row->bucket,
                        'dimension'       => $dimension,
                        'dimension_value' => $row->dimension_value,
                    ],
                    [
                        'event_count'   => $row->event_count,
                        'unique_actors' => $row->unique_actors,
                    ],
                );
            }
        }
    }

    private function windowStart(): CarbonImmutable
    {
        return $this->granularity === 'day'
            ? CarbonImmutable::now()->subDays(2)->startOfDay()
            : CarbonImmutable::now()->subHours(3)->startOfHour();
    }
}
```

Scheduling:

```php
$schedule->job(new AggregateAnalyticsJob('hour'))->hourly();
$schedule->job(new AggregateAnalyticsJob('day'))->dailyAt('00:15');
$schedule->command('analytics:prune --days=30')->dailyAt('01:00'); // raw retention
```

The re-aggregation window (last 2–3 buckets) plus `updateOrCreate` makes late-arriving events self-healing without double counting.

## 7. Reporting Query Surface

Dashboards read rollups exclusively through the `series()` / `top()` methods of `AnalyticsService`. Raw `analytics_events` is never queried from the read path.

```php
namespace App\Domains\Analytics\Services;

use App\Domains\Analytics\DTOs\AnalyticsSeries;
use App\Domains\Analytics\Enums\AnalyticsEvent;
use App\Domains\Analytics\Models\AnalyticsRollup;
use Carbon\CarbonImmutable;

final class AnalyticsReportService // consumed internally by RedisAnalyticsService
{
    public function series(AnalyticsEvent $event, CarbonImmutable $from, CarbonImmutable $to, string $granularity = 'day'): AnalyticsSeries
    {
        $cacheKey = "analytics:series:{$event->value}:{$granularity}:{$from->toDateString()}:{$to->toDateString()}";

        $rows = cache()->remember($cacheKey, 300, fn () => AnalyticsRollup::query()
            ->where('name', $event->value)
            ->where('granularity', $granularity)
            ->whereBetween('bucket', [$from, $to])
            ->selectRaw('bucket, SUM(event_count) as total, SUM(unique_actors) as uniques')
            ->groupBy('bucket')
            ->orderBy('bucket')
            ->get()
            ->toArray());

        return new AnalyticsSeries($event, $rows);
    }
}
```

Rules reflected above:

- Every read is a rollup aggregation with a short TTL cache, keeping dashboards sub-100ms.
- Ranges are bucket-aligned; the service never scans raw events.
- Exports (CSV) stream from the same service via a queued `ExportAnalyticsReport` job to avoid request timeouts.

## 8. Reuse & Boundary Rules

An analytics emitter MAY:

- Call `AnalyticsService::track()` / `trackFor()` from any layer.
- Attach non-PII properties keyed to the event's declared dimension.

An analytics emitter MUST NOT:

- Write to `analytics_events` or `analytics_rollups` directly.
- Pass raw identifiers (`email`, `ip`, `name`) in `properties`.
- Block the request on aggregation or reporting queries.
- Read from `analytics_events` for dashboards.

| Anti-pattern | Correct form |
| --- | --- |
| `AnalyticsEvent::create([...])` in a controller | `AnalyticsService::track()` → buffered write |
| Dashboard querying `analytics_events` | Query `analytics_rollups` via `AnalyticsService::series()` |
| Storing `user_id` in raw form | Store `actor_hash` via `PiiHasher::hashActor()` |
| Aggregating synchronously on request | `AggregateAnalyticsJob` on the scheduler |

## 10.2 Conversion Funnel Analysis

Analyze conversion through multi-step funnels:

```php
final class FunnelAnalyzer
{
    public function conversionRate(array $steps, CarbonImmutable $from, CarbonImmutable $to): float
    {
        $counts = [];
        foreach ($steps as $step) {
            $counts[] = AnalyticsRollup::where('name', $step->value)
                ->whereBetween('bucket', [$from, $to])
                ->sum('event_count');
        }
        if ($counts[0] === 0) return 0.0;
        return ($counts[array_key_last($counts)] / $counts[0]) * 100;
    }
}
```

## 10.3 Statistical Significance

Calculate whether experiment results are statistically significant:

```php
final class SignificanceCalculator
{
    public function isSignificant(
        int $controlVisitors, int $controlConversions,
        int $variantVisitors, int $variantConversions,
        float $threshold = 0.05
    ): bool {
        $controlRate = $controlConversions / max($controlVisitors, 1);
        $variantRate = $variantConversions / max($variantVisitors, 1);
        $pooledRate = ($controlConversions + $variantConversions) / max($controlVisitors + $variantVisitors, 1);
        $se = sqrt($pooledRate * (1 - $pooledRate) * (1 / max($controlVisitors, 1) + 1 / max($variantVisitors, 1)));
        if ($se === 0) return false;
        $z = ($variantRate - $controlRate) / $se;
        return abs($z) > 1.96;
    }
}
```

# 11. Cohort Analysis

## 11.1 User Cohort Definition

Group users by their first action date for retention analysis:

```php
final class CohortAnalyzer
{
    public function retentionCohorts(AnalyticsEvent $event, int $weeks = 12): Collection
    {
        $cohorts = DB::table('analytics_events')
            ->selectRaw('DATE(occurred_at) as cohort_date, actor_hash')
            ->where('name', $event->value)
            ->where('occurred_at', '>=', now()->subWeeks($weeks))
            ->groupBy('cohort_date', 'actor_hash')
            ->get()
            ->groupBy('cohort_date');

        $result = [];
        foreach ($cohorts as $date => $users) {
            $userHashes = $users->pluck('actor_hash');
            $weekRetention = [];
            for ($week = 0; $week < $weeks; $week++) {
                $weekStart = CarbonImmutable::parse($date)->addWeeks($week);
                $weekEnd = $weekStart->addWeek();
                $activeInWeek = DB::table('analytics_events')
                    ->where('name', $event->value)
                    ->where('actor_hash', 'IN', $userHashes)
                    ->whereBetween('occurred_at', [$weekStart, $weekEnd])
                    ->distinct('actor_hash')
                    ->count('actor_hash');
                $weekRetention[] = $userHashes->count() > 0
                    ? ($activeInWeek / $userHashes->count()) * 100 : 0;
            }
            $result[$date] = $weekRetention;
        }
        return collect($result);
    }
}
```

# 12. Segmentation

## 12.1 User Segmentation

Segment users by behavior for targeted analysis:

```php
final class SegmentDefinition
{
    public function __construct(
        public string $name,
        public array $filters,
    ) {}

    public function matches(array $userProperties): bool
    {
        foreach ($this->filters as $key => $value) {
            if (!isset($userProperties[$key])) return false;
            if (is_array($value)) {
                if (!in_array($userProperties[$key], $value, true)) return false;
            } elseif ($userProperties[$key] !== $value) {
                return false;
            }
        }
        return true;
    }
}
```

## 12.2 Segment-Based Reporting

Generate reports per segment:

```php
final class SegmentedReportService
{
    public function reportForSegment(
        SegmentDefinition $segment, AnalyticsEvent $event,
        CarbonImmutable $from, CarbonImmutable $to

            ->whereBetween('bucket', [$from, $to])
            ->selectRaw('bucket, SUM(event_count) as total')
```

## 13.1 Retention Policy

```php
final class AnalyticsRetentionJob implements ShouldQueue
{
    use Dispatchable, InteractsWithQueue, Queueable;

    public function handle(): void
    {
        DB::table('analytics_events')->where('occurred_at', '<', now()->subDays(30))->delete();
```

## 13.2 GDPR Compliance

```php
final class GdprAnalyticsHandler
{
    public function handleDataDeletion(int $userId): void
    {
        $actorHash = PiiHasher::hashActor($userId);
        DB::table('analytics_events')->where('actor_hash', $actorHash)->delete();
        DB::table('analytics_rollups')->where('actor_hash', $actorHash)->delete();

            ->orderBy('occurred_at')->get()->toArray();
    }
}
```

## 13.3 IP Anonymization

Extended IP anonymization for enhanced privacy:

```php
final class ExtendedPiiHasher extends PiiHasher
{
    public function hashIpExtended(?string $ip): ?string
    {
        if ($ip === null) return null;
        if (filter_var($ip, FILTER_VALIDATE_IP, FILTER_FLAG_IPV4)) {
            $parts = explode('.', $ip);
            $parts[2] = '0';
            $parts[3] = '0';
            $ip = implode('.', $parts);
        }
        return hash_hmac('sha256', "ip:{$ip}", $this->key);
    }
}
```

# 15. Analytics Export

## 15.1 CSV Export

```php
final class ExportAnalyticsCsv implements ShouldQueue
{
    use Dispatchable, InteractsWithQueue, Queueable;

    public function __construct(
        private AnalyticsEvent $event,
        private CarbonImmutable $from,
        private CarbonImmutable $to,
        private int $userId,
    ) {}

    public function handle(): void
    {
        $filePath = storage_path("app/analytics-export-{$this->event->value}.csv");
        $handle = fopen($filePath, 'w');
        fputcsv($handle, ['Date', 'Event', 'Count', 'Unique Actors']);

        AnalyticsRollup::where('name', $this->event->value)
            ->whereBetween('bucket', [$this->from, $this->to])
            ->orderBy('bucket')->get()
            ->each(fn ($row) => fputcsv($handle, [$row->bucket, $row->name, $row->event_count, $row->unique_actors]));

        fclose($handle);

    }
```

# 18. Anti-Patterns and Troubleshooting

| Anti-Pattern | Correct Approach |
|-------------|-----------------|
| `AnalyticsEvent::create([...])` in controller | `AnalyticsService::track()` with buffer |
| Dashboard querying `analytics_events` | Query `analytics_rollups` via `series()` |
| Storing `user_id` in raw form | Store `actor_hash` via `PiiHasher` |
| Aggregating synchronously on request | `AggregateAnalyticsJob` on scheduler |
| Forgetting opt-out check | Always call `optedOut()` before tracking |
| Including PII in properties | Use `sanitize()` with `FORBIDDEN_KEYS` |
| Querying raw events for dashboards | Use rollups exclusively |
| Blocking request on analytics write | Single `RPUSH` to Redis buffer |

# 28. Analytics Error Handling

## 28.1 Buffer Flush Failures

Handle Redis buffer flush failures gracefully:

```php
final class FlushAnalyticsBuffer implements ShouldQueue
{
    use Dispatchable, InteractsWithQueue, Queueable, Batchable;

    public int $tries = 3;
    public int $backoff = 60;

    public function handle(): void
    {
        $buffer = Redis::lrange('analytics:buffer', 0, -1);

        if (empty($buffer)) return;

        try {
            $rows = array_map(fn ($json) => json_decode($json, true), $buffer);
            DB::table('analytics_events')->insert($rows);
            Redis::ltrim('analytics:buffer', count($buffer), -1);
        } catch (\Exception $e) {
            Log::channel('ops')->error('analytics_buffer_flush_failed', [
                'error' => $e->getMessage(),
                'buffer_count' => count($buffer),
            ]);
            throw $e;
        }
    }
}
```

```php
final class AggregateAnalyticsJob implements ShouldQueue

    {

            'granularity' => $this->granularity,

        ]);
```

# 30. Summary

Analytics in GsmUi follows a write-heavy, read-light pipeline: events are buffered to Redis synchronously, flushed to the database asynchronously, aggregated into rollups on a schedule, and read exclusively from rollups for dashboards. The system enforces privacy by construction through HMAC hashing of user identifiers and IP truncation. Opt-out is honored at the tracker boundary before any hashing occurs. Real-time analytics use Redis atomic counters with WebSocket broadcasting for live dashboards. A/B testing integration tracks experiment participation alongside events. Cohort and segmentation analysis enable deep behavioral insights. The system is designed for non-blocking capture, deterministic schema, and privacy compliance including GDPR data export and deletion.

```php
        $rollupCount = AnalyticsRollup::count();

        return [
            'buffer_size' => $bufferSize,
            'last_aggregation' => $lastAggregation?->diffForHumans(),
            'rollup_count' => $rollupCount,
            'healthy' => $bufferSize < 5000 && $lastAggregation?->diffInHours(now()) < 2,
        ];
    }
}
```

## 38.2 Migrating from Legacy Analytics

```php
final class LegacyAnalyticsMigration
{
    public function migrate(): void
    {
        $legacyEvents = DB::connection('legacy')->table('events')->get();

        foreach ($legacyEvents as $event) {
            $analyticsEvent = match ($event->type) {
                'page_view' => AnalyticsEvent::PageViewed,
                'download' => AnalyticsEvent::ComponentDownloaded,
                'signup' => AnalyticsEvent::SignupCompleted,
                default => null,

                    $event->user_id,
                    json_decode($event->properties, true)
                );
            }
        }
    }
}
```

# 39. Troubleshooting Guide

| Symptom | Likely Cause | Solution |
|---------|-------------|----------|
| Buffer growing unbounded | Flush job not running | Check queue worker and job schedule |
| Dashboard shows zero data | Rollup job not running | Run `analytics:aggregate` manually |
| Missing events | Opt-out enabled | Check user preferences |
| Slow dashboard | No rollup cache | Clear cache and verify indexing |
| High memory during flush | Large buffer | Reduce flush threshold |
| Duplicate events | Missing idempotency | Add deduplication key |
| Missing dimensions | Wrong event enum | Verify `dimension()` method |
| Redis memory pressure | Buffer TTL too long | Reduce buffer TTL |

# 41. Analytics Best Practices

## 41.1 Event Naming

- Use `domain.action` format: `component.downloaded`, `page.viewed`
- Be consistent across the codebase
- Use past tense for completed actions
- Avoid abbreviations

## 41.2 Property Guidelines

- Keep properties flat, avoid nested objects
- Use string keys with snake_case naming
- Include the dimension value in properties
- Never include PII in properties

## 41.3 Performance Guidelines

- Track events asynchronously when possible
- Batch multiple events in a single request
- Use Redis buffer for high-volume events
- Monitor buffer size and flush job health

## 41.4 Privacy Guidelines

- Always check opt-out before tracking
- Hash user identifiers with HMAC
- Truncate IP addresses before hashing
- Provide data export and deletion capabilities
- Document data retention periods

# 43. Summary

This document defines the implementation contract for analytics in GsmUi. The system tracks structured events with a closed vocabulary enum, buffers writes to Redis for non-blocking capture, and aggregates raw events into pre-computed rollups for efficient reporting. Privacy is enforced by construction through HMAC hashing of user identifiers, IP truncation, and opt-out support at the tracker boundary. The system supports real-time dashboards, A/B testing, cohort analysis, and segmentation. All analytics data is read exclusively from rollups, never from raw events, ensuring consistent performance and data integrity. The pipeline is designed to add negligible latency to requests while providing deep behavioral insights through a comprehensive reporting API.
