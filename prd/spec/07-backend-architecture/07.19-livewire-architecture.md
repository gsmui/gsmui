# 07.19 - Livewire Architecture

**Project:** GsmUi
**Architecture:** Livewire 4 Full-Stack Reactive Components
**Framework:** Laravel 13 + Livewire 4
**Version:** 1.0.0

---

# Purpose

Livewire powers every interactive surface of GsmUi. A Livewire component binds server-side state to the browser without hand-written JavaScript: properties are serialized, patched over HTTP, and re-hydrated on each request. Because the same component class also renders the initial Blade view, Livewire collapses the controller + view boundary into a single unit.

This document specifies the *implementation mechanics* of GsmUi's Livewire layer: how components are structured, how `Wireable` DTOs cross the wire safely, how pagination and streaming are performed, and which security controls (`#[Locked]`, `lockOutgoing`, method disabling) prevent client-side tampering. Business logic never lives in a component — it delegates to the Action and Service layers.

> See also: 07.08-action-layer.md (Action contract), 07.09-dto-layer.md (DTO contract), 05.07-service-layer.md (Service responsibilities). Livewire components call Services directly; they do not call the HTTP API.

---

# 1. Component Structure

Every GsmUi Livewire component is a class under `app/Livewire/<Domain>/` that extends `Livewire\Component`. Public properties are state; public methods are actions invoked from Blade via `wire:click`, `wire:model`, etc. Private/protected methods are not callable from the client.

```php
<?php

declare(strict_types=1);

namespace App\Livewire\Themes;

use App\Domains\Themes\Actions\CreateThemeAction;
use App\Domains\Themes\Dto\CreateThemeData;
use Livewire\Component;

final class ThemeCreator extends Component
{
    public string $name = '';

    public ?string $description = null;

    public function save(): void
    {
        $validated = $this->validate([
            'name' => ['required', 'string', 'max:255'],
            'description' => ['nullable', 'string', 'max:2000'],
        ]);

        $dto = CreateThemeData::fromRequest($validated);

        $theme = (new CreateThemeAction(
            themeService: app(\App\Domains\Themes\Services\ThemeService::class),
        ))->execute($dto);

        $this->redirectRoute('themes.show', $theme);
    }

    public function render(): \Illuminate\Contracts\View\View
    {
        return view('livewire.themes.theme-creator');
    }
}
```

Rule: a component must hold UI state only. Any domain rule, query, or mutation is pushed down to `07.08-action-layer.md` and `07.06-service-layer.md`.

# 2. Wireable DTOs

Livewire can only rehydrate scalar arrays, models, and objects implementing `Livewire\Wireable`. When a component needs to carry a structured value (filters, search criteria, a selection set) across requests, model it as a `Wireable` DTO rather than loose arrays. This keeps the DTO contract from `07.09-dto-layer.md` intact while satisfying Livewire's serialization boundary.

```php
<?php

declare(strict_types=1);

namespace App\Livewire\Components\Dto;

use Livewire\Wireable;

final class ComponentFilters implements Wireable
{
    public function __construct(
        public readonly string $query = '',
        public readonly array $categories = [],
        public readonly string $sort = 'downloads',
    ) {}

    public function toLivewire(): array
    {
        return [
            'query' => $this->query,
            'categories' => $this->categories,
            'sort' => $this->sort,
        ];
    }

    public static function fromLivewire($value): static
    {
        return new self(
            query: (string) ($value['query'] ?? ''),
            categories: (array) ($value['categories'] ?? []),
            sort: (string) ($value['sort'] ?? 'downloads'),
        );
    }
}
```

Usage in a component:

```php
public ComponentFilters $filters; // rehydrated automatically via Wireable

public function updatedFilters(): void
{
    // fires after any nested property of $filters changes
}
```

`Wireable` differs from the `DtoContract` in `07.09-dto-layer.md`: `DtoContract` governs layer boundaries (request → action), while `Wireable` governs the client ↔ server serialization boundary. A DTO may implement both when it crosses both boundaries.

# 3. Pagination

Read-heavy Livewire lists use the `WithPagination` trait. The query must be executed inside `render()` (or a dedicated query method) so it re-runs each request, and pagination state is tracked automatically by Livewire.

```php
<?php

declare(strict_types=1);

namespace App\Livewire\Marketplace;

use App\Domains\Marketplace\Services\ProductQueryService;
use Livewire\Component;
use Livewire\WithPagination;

final class ProductBrowser extends Component
{
    use WithPagination;

    public string $search = '';

    public function render(): \Illuminate\Contracts\View\View
    {
        $products = app(ProductQueryService::class)
            ->search(query: $this->search)
            ->paginate(perPage: 15);

        return view('livewire.marketplace.product-browser', [
            'products' => $products,
        ]);
    }
}
```

Blade renders pagination with the `gsmui:` namespace component (see `07.20-blade-component-architecture.md`) bound to `$products`:

```blade
<gsmui:pagination :items="$products" />
```

Never call `->paginate()` inside a cached property. Pagination must reflect the current request's query parameters.

# 4. Streaming

For large file generation (theme export, report download) stream the response instead of buffering it in memory. Livewire components return a standard `Response` from an action, and Laravel's streaming responses are fully supported.

```php
public function export(): \Symfony\Component\HttpFoundation\StreamedResponse
{
    $theme = $this->themeService->find($this->themeId);

    return response()->streamDownload(
        function () use ($theme): void {
            echo $this->themeExporter->export($theme);
        },
        filename: "{$theme->slug}.css",
        headers: ['Content-Type' => 'text/css'],
    );
}
```

For incremental server-pushed updates (progress bars, log tails) use `dispatch()` of domain events from `05.10-events.md` and subscribe with `Livewire\Attributes\On`:

```php
use Livewire\Attributes\On;

#[On('import.progress')]
public function onProgress(int $percent): void
{
    $this->progress = $percent;
}
```

# 5. Security: Locking & Disabling Methods

Livewire exposes any public property and public method to the client. GsmUi applies defense-in-depth so a malicious request cannot mutate protected state or invoke unauthorized actions.

## 5.1 Protecting Properties

Use `#[Locked]` to forbid client mutation of a property. Livewire will reject any inbound diff that changes it.

```php
use Livewire\Attributes\Locked;

final class BillingPortal extends Component
{
    #[Locked]
    public int $userId; // set once server-side, never editable from client
}
```

## 5.2 Integrity Hashing

Call `lockOutgoing()` in the component constructor to sign serialized state, and `lockIncoming()` to verify inbound state, preventing tampering of protected properties between requests:

```php
public function __construct()
{
    $this->lockOutgoing();
    $this->lockIncoming();
}
```

## 5.3 Disabling Unwanted Methods

Livewire auto-exposes `update`, `call`, and `fireEvent`. Disable the interaction surface you don't need via `$this->skipRender()`-style guards, or restrict callable methods using the `Only`/`Except` attributes:

```php
use Livewire\Attributes\Only;

#[Only(['next', 'previous'])]
public function navigate(string $direction): void { /* ... */ }
```

## 5.4 Authorization Gatekeeping

Every state-changing action must re-assert authorization server-side — never trust the wire payload. Combine with `07.15-policies.md` and `07.23-authorization.md`:

```php
public function delete(int $id): void
{
    $product = $this->productRepository->findOrFail($id);

    $this->authorize('delete', $product); // Policy from 07.15

    (new DeleteProductAction($this->productService))->execute($product);
}
```

> See also: 05.15-security.md for the platform-wide threat model, CSP, and CSRF posture that complements these component-level controls.

# 6. Component Lifecycle & Rules

```text
Browser request
      │
Livewire Kernel
      │
mount()  ──► set initial public properties
      │
render() ──► Blade view + serialized state
      │
User interaction
      │
updated* / action method
      │
validate() ──► 07.17-validation.md
      │
Action / Service ──► 07.08-action-layer.md, 07.06-service-layer.md
      │
Domain Event ──► 05.10-events.md
      │
re-render (patched DOM)
```

Rule matrix:

| Concern            | Belongs in Livewire | Delegated to |
| ------------------ | ------------------- | ------------ |
| Public UI state    | ✓                   | —            |
| Validation rules   | ✓ (`validate()`)    | `07.17-validation.md` |
| Business logic     | ✗                   | `07.08-action-layer.md` |
| Persistence        | ✗                   | `07.07-repository-layer.md` |
| Authorization      | gate only           | `07.15-policies.md`, `07.23-authorization.md` |
| Event dispatch     | ✓ (`event()`)       | `05.10-events.md` |

# 8. Advanced State Management

## 8.1 Computed Properties

Computed properties derive values from other properties or external data. They are recalculated on every render cycle, ensuring the UI always reflects the latest state.

```php
final class ProductBrowser extends Component
{
    public string $search = '';
    public string $sortBy = 'name';
    public bool $onlyPublished = true;

    public function getProductsProperty(): LengthAwarePaginator
    {
        return Product::query()
            ->when($this->search, fn ($q) => $q->where('name', 'like', "%{$this->search}%"))
            ->when($this->onlyPublished, fn ($q) => $q->whereNotNull('published_at'))
            ->orderBy($this->sortBy)
            ->paginate(15);
    }

    public function getTotalCountProperty(): int
    {
        return Product::query()
            ->when($this->search, fn ($q) => $q->where('name', 'like', "%{$this->search}%"))
            ->count();
    }

    public function render(): View
    {
        return view('livewire.product-browser', [
            'products' => $this->products,
            'totalCount' => $this->total_count,
        ]);
    }
}
```

Rules:
- Prefix computed properties with `get` and suffix with `Property`.
- Computed properties are NOT cached, they re-execute on every `render()` call.
- For expensive computations, cache explicitly using `Cache::remember()`.
- Never mutate state inside a computed property.

## 8.2 State Hydration and Dehydration

Livewire serializes component state between requests. Understanding the hydration cycle is critical for complex components that carry non-scalar data.

```php
final class ThemeEditor extends Component
{
    public ThemeEditorState $editorState;

    public function dehydrateEditorState(): array
    {
        return $this->editorState->toArray();
    }

    public function hydrateEditorState(array $value): void
    {
        $this->editorState = ThemeEditorState::fromArray($value);
    }
}
```

The `dehydrate`/`hydrate` hook pair runs per-property. Use it when a property public type does not match its wire-safe representation (Carbon dates, enums, collections).

## 8.3 Dirty Checking and Confirmation

Livewire tracks which properties have changed since the last render. Use `$this->isDirty()` and `$this->getDirty()` to gate expensive operations or warn users of unsaved changes.

```php
final class SettingsForm extends Component
{
    public string $theme = 'light';
    public string $language = 'en';
    public bool $confirmingNavigation = false;

    public function confirmLeaveIfDirty(): void
    {
        if ($this->isDirty()) {
            $this->confirmingNavigation = true;
            return;
        }
        $this->redirectRoute('dashboard');
    }

    public function discardChanges(): void
    {
        $this->reset(['theme', 'language']);
    }
}
```

## 8.4 Property Initialization Patterns

Proper initialization prevents hydration mismatches. Initialize nullable properties explicitly and use `mount()` for route-parameter-dependent state.

```php
final class ThemeBrowser extends Component
{
    public int $page = 1;
    public string $search = '';
    public ?int $categoryId = null;
    public array $selectedIds = [];

    public function mount(?int $categoryId = null): void
    {
        $this->categoryId = $categoryId;
    }
}
```

Rules:
- Scalar properties must have defaults matching their PHP type.
- Model properties must be nullable or initialized in `mount()`.
- Never use `array` without a default; always `[]`.
- Collections should be `Collection` typed and initialized in `mount()`.

## 8.5 Reset and Hydrate

Reset specific properties to their defaults without re-mounting the component:

```php
public function resetFilters(): void
{
    $this->reset(['search', 'categoryId', 'page']);
}

public function resetAll(): void
{
    $this->reset();
}
```

## 8.6 Cross-Tab State Synchronization

Livewire does not natively synchronize state across browser tabs. For multi-tab applications, use localStorage events or broadcast channels:

```javascript
// In a Blade layout
Livewire.on('stateChanged', (key, value) => {
    localStorage.setItem(`livewire:${key}`, JSON.stringify(value));
});

window.addEventListener('storage', (e) => {
    if (e.key?.startsWith('livewire:')) {
        const key = e.key.replace('livewire:', '');
        Livewire.all().forEach(component => {
            component.set(key, JSON.parse(e.newValue));
        });
    }
});
```

# 9. Event Handling Patterns

## 9.1 Livewire Events

Livewire components communicate via events. Dispatch events with `dispatch()` and listen with `#[On()]` attributes.

```php
final class ThemeCreator extends Component
{
    public function save(): void
    {
        $theme = $this->createTheme();
        $this->dispatch('theme.created', themeId: $theme->id);
    }
}

final class ThemeList extends Component
{
    #[On('theme.created')]
    public function refreshList(): void
    {
        $this->refreshThemes();
    }
}
```

## 9.2 Browser Events

Dispatch events to the browser for Alpine.js or vanilla JS integration:

```php
$this->dispatch('show-toast', message: 'Theme saved', type: 'success');
```

In Blade/Alpine:

```blade
<div x-on:show-toast.window="showToast($event.detail.message, $event.detail.type)">
```

## 9.3 Event Bubbling

Livewire events bubble through the component tree. A parent can listen for events dispatched by any child:

```php
final class ThemeManager extends Component
{
    #[On('theme.*')]
    public function onAnyThemeEvent(string $event, array $data): void
    {
        $this->logActivity($event, $data);
    }
}
```

## 9.4 Event Targeting

Target specific component instances by ID:

```php
$this->dispatch('highlight-theme', themeId: $this->theme->id)
    ->to(ThemeCard::class, "theme-{$this->theme->id}");
```

## 9.5 Event History

Track event history for debugging complex component interactions:

```php
public array $eventLog = [];

protected function logEvent(string $name, array $data = []): void
{
    $this->eventLog[] = [
        'name' => $name,
        'data' => $data,
        'at' => now()->toIso8601String(),
    ];
}
```

## 9.6 Global Event Bus

For application-wide events that cross domain boundaries, use a dedicated event service:

```php
final class AppEventBus
{
    private array $listeners = [];

    public function on(string $event, callable $listener): void
    {
        $this->listeners[$event][] = $listener;
    }

    public function dispatch(string $event, array $data = []): void
    {
        foreach ($this->listeners[$event] ?? [] as $listener) {
            $listener($data);
        }
    }
}
```

# 10. Polling and Real-Time Updates

## 10.1 Simple Polling

Livewire supports automatic polling via the `wire:poll` directive. Use it for dashboards, live feeds, or status checks.

```php
final class SystemStatus extends Component
{
    public int $activeUsers = 0;

    public function boot(): void
    {
        $this->activeUsers = Cache::remember('active_users', 60,
            fn () => User::where('last_active_at', '>', now()->subMinutes(5))->count()
        );
    }
}
```

```blade
<div wire:poll.30s="boot">
    Active users: {{ $activeUsers }}
</div>
```

## 10.2 Conditional Polling

Pause polling when the component is not visible or when the user is idle:

```php
public bool $polling = true;

public function togglePolling(): void
{
    $this->polling = ! $this->polling;
}
```

```blade
<div wire:poll.30s.visible="{{ $polling ? 'boot' : '' }}">
```

## 10.3 Polling Performance Guidelines

- Use `wire:poll.60s` or higher for non-critical updates.
- Avoid polling on pages with many components, each poll is a full HTTP request.
- For real-time updates, consider Laravel Echo + broadcasting instead of polling.
- Always implement `shouldReconnect` logic for WebSocket fallback.
- Monitor server load when multiple users are on polling pages.
- Consider `wire:poll.visible` to pause when the tab is inactive.

## 10.4 Selective Polling Targets

Target a specific method to avoid re-running the entire component:

```blade
<div wire:poll.60s="refreshStats">
```

This only calls `refreshStats()`, not the entire `render()` cycle.

# 11. Model Binding

## 11.1 Eloquent Model Binding

Livewire can bind directly to Eloquent models. The model is hydrated from the route parameter and bound to the component.

```php
final class ThemeEditor extends Component
{
    public Theme $theme;

    public function mount(Theme $theme): void
    {
        $this->theme = $theme;
    }

    public function save(): void
    {
        $this->theme->update($this->validate([
            'theme.name' => ['required', 'string', 'max:255'],
            'theme.description' => ['nullable', 'string', 'max:2000'],
        ]));

        $this->dispatch('theme.updated', themeId: $this->theme->id);
    }
}
```

## 11.2 Soft Binding

For components that should not persist changes automatically, use a copy of the model:

```php
public function mount(Theme $theme): void
{
    $this->theme = $theme->replicate();
}

public function save(): void
{
    $this->theme->save();
}
```

## 11.3 Binding Rules

- Always authorize model access in `mount()` via `$this->authorize('update', $this->theme)`.
- Never bind the authenticated user model directly, use `#[Locked]` on the property.
- For list components, use `wire:model` on scalar fields only, not on model instances.
- Use route model binding for single-model components.

## 11.4 Polymorphic Binding

For polymorphic relationships, pass the type and ID separately:

```php
final class CommentEditor extends Component
{
    public string $commentableType;
    public int $commentableId;

    public function mount(string $commentableType, int $commentableId): void
    {
        $this->commentableType = $commentableType;
        $this->commentableId = $commentableId;
    }
}
```

# 12. File Uploads

## 12.1 Temporary Uploads

Livewire handles file uploads with temporary storage. Files are uploaded to a temp directory and moved to final storage on form submission.

```php
final class ComponentUploader extends Component
{
    public ?string $tempPath = null;
    public string $filename = '';

    public function updatedTempPath(): void
    {
        $this->validate([
            'tempPath' => ['required', 'file', 'max:10240', 'mimes:zip,tar,gz'],
        ]);
    }

    public function save(): void
    {
        $path = Storage::disk('components')->putFile('uploads', $this->tempPath);
        $this->component->update(['file_path' => $path]);
    }
}
```

## 12.2 Upload Security

- Validate MIME types server-side, never trust the client-provided extension.
- Scan uploaded files for malware before processing.
- Store uploads outside the public web root.
- Use signed URLs for temporary access to uploaded files.
- Set file size limits in both PHP config and Livewire validation.
- Never allow executable file types in user uploads.

## 12.3 Progress Tracking

Livewire provides built-in upload progress tracking:

```blade
<div wire:loading wire:target="tempPath">
    Uploading...
    <div class="progress-bar" style="width: {{ $progress }}%"></div>
</div>
```

## 12.4 Multiple File Uploads

For multi-file uploads, use an array property:

```php
public array $photos = [];

public function updatedPhotos(): void
{
    $this->validate([
        'photos' => ['required', 'array', 'max:5'],
        'photos.*' => ['file', 'max:5120', 'mimes:jpg,png,webp'],
    ]);
}
```

# 14. Error Handling

## 14.1 Component-Level Error Handling

Catch and display errors gracefully within components:

```php
final class ThemeImporter extends Component
{
    public ?string $error = null;

    public function import(): void
    {
        try {
            $this->themeImporter->import($this->file);
            $this->dispatch('import.success');
        } catch (ImportException $e) {
            $this->error = $e->getMessage();
            Log::error('theme_import_failed', ['error' => $e->getMessage()]);
        }
    }
}
```

## 14.2 Rendering Errors

Livewire catches unhandled exceptions and renders an error message. Customize the error view:

```php
public function render(): View
{
    return view('livewire.theme-editor')->layout('layouts.app', [
        'errorView' => 'livewire.errors.theme-editor',
    ]);
}
```

## 14.3 Validation Errors

Validation errors are automatically flashed to the session and displayed in the component view:

```blade
<div>
    <input wire:model="name" />
    @error('name')
        <span class="text-red-500">{{ $message }}</span>
    @enderror
</div>
```

## 14.4 Exception Hierarchy

Map exceptions to user-friendly messages:

```php
final class ExceptionHandler
{
    private const MAP = [
        ValidationException::class => 'Please check your input.',
        AuthorizationException::class => 'You do not have permission.',
        NotFoundException::class => 'The requested resource was not found.',
        InfrastructureException::class => 'A temporary error occurred. Please try again.',
    ];

    public function message(Throwable $e): string
    {
        foreach (self::MAP as $type => $msg) {
            if ($e instanceof $type) {
                return $msg;
            }
        }
        return 'An unexpected error occurred.';
    }
}
```

## 14.5 Recovery Patterns

Implement automatic recovery for transient failures:

```php
public function retryAction(): void
{
    $attempts = 0;
    $maxAttempts = 3;

    while ($attempts < $maxAttempts) {
        try {
            $this->performAction();
            return;
        } catch (TransientException $e) {
            $attempts++;
            if ($attempts >= $maxAttempts) {
                $this->error = 'Action failed after multiple attempts.';
                return;
            }
            usleep(500 * 1000); // 500ms backoff
        }
    }
}
```

# 15. Performance Optimization

## 15.1 Skip Render

When a component method does not change the view, call `$this->skipRender()` to avoid unnecessary DOM diffing:

```php
public function toggleSidebar(): void
{
    $this->sidebarOpen = ! $this->sidebarOpen;
    $this->skipRender();
}
```

## 15.2 Debounced Updates

Use `wire:model.debounce` for text inputs to reduce server round-trips:

```blade
<input wire:model.debounce.300ms="search" />
```

## 15.3 Lazy Loading

Load expensive data only when needed:

```php
public ?array $details = null;

public function loadDetails(): void
{
    $this->details = $this->themeService->getFullDetails($this->themeId);
}
```

## 15.4 Memory Management

Monitor and manage memory usage in long-running components:

```php
public function boot(): void
{
    if (memory_get_usage(true) > 50 * 1024 * 1024) {
        logger()->warning('high_memory_usage', [
            'component' => static::class,
            'bytes' => memory_get_usage(true),
        ]);
    }
}
```

## 15.5 Response Compression

Enable gzip/brotli compression at the web server level for Livewire JSON responses. The Livewire payload is JSON and compresses well.

## 15.6 Selective Updates

Use `wire:model.live` only where real-time feedback is needed. For everything else, use `wire:model.blur` or explicit save buttons to reduce server load.

# 16. Testing Patterns

## 16.1 Testing Component State

Test that component properties are set correctly after mount:

```php
test('theme editor mounts with correct theme', function (): void {
    $theme = Theme::factory()->create();

    Livewire::test(ThemeEditor::class, ['themeId' => $theme->id])
        ->assertSet('theme.name', $theme->name)
        ->assertSet('theme.description', $theme->description);
});
```

## 16.2 Testing Events

Assert that events are dispatched:

```php
test('save dispatches theme.updated event', function (): void {
```

# 20. Migration and Upgrade Guide

## 20.1 Livewire 3 to 4 Migration

When upgrading from Livewire 3 to 4, note these breaking changes:

- `$this->emit()` is deprecated in favor of `$this->dispatch()`.
- `#[On]` attribute replaces `@on` directive.
- Component mounting uses `mount()` method, not constructor.
- Properties are public by default; `#[Locked]` replaces `$this->lock()`.
- `wire:model.lazy` is now `wire:model.blur`.
- `@this` is now `$wire` in Alpine.

## 20.2 State Migration

For components with complex state, create a migration helper:

```php
public function migrateState(): void
{
    if (isset($this->oldProperty)) {
        $this->newProperty = $this->oldProperty;
        unset($this->oldProperty);
    }
}
```

## 20.3 Database Migration Safety

When Livewire components trigger database migrations, use the safe migration pattern:

```php
public function runMigration(): void
{
    Schema::disableForeignKeyConstraints();
    Artisan::call('migrate', ['--force' => true]);
    Schema::enableForeignKeyConstraints();
}
```

# 21. Best Practices

## 21.1 Component Design Principles

1. Keep components thin, delegate business logic to Actions and Services.
2. Use `#[Locked]` on properties that should not change client-side.
3. Validate in `mount()` to catch invalid state early.
4. Dispatch events for cross-component communication.
5. Use computed properties for derived data.
6. Cache expensive computations explicitly.
7. Test every state-changing method.

## 21.2 Common Anti-Patterns

| Anti-Pattern | Correct Approach |
|-------------|-----------------|
| Business logic in component | Delegate to Action/Service |
| Direct Eloquent queries in render | Use Repository with eager loads |
| `wire:model.live` on all inputs | Use `.blur` for non-real-time |
| Missing `#[Locked]` on IDs | Always lock server-set properties |
| Nested Livewire components in loops | Extract to child components |
| Storing files in public disk | Use private disk with signed URLs |
| Synchronous file processing | Queue heavy work |

## 21.3 Security Checklist

- [ ] All state-changing methods assert authorization.
- [ ] `#[Locked]` on all server-set properties.
- [ ] `lockOutgoing()`/`lockIncoming()` on sensitive components.
- [ ] File uploads validate MIME type server-side.
- [ ] No raw HTML rendering without sanitization.
- [ ] Rate limiting on state-changing endpoints.
- [ ] CSRF verification on all form submissions.

# 22. API Reference

## 22.1 Component Methods

| Method | Description |
|--------|-------------|
| `mount()` | Called on initial render, receives route parameters |
| `render()` | Returns Blade view, called on every update |
| `boot()` | Called after mount, before first render |
| `hydrate()` | Called when state is deserialized from client |
| `dehydrate()` | Called before state is serialized to client |
| `updated*()` | Called when a specific property changes |
| `validationAttributes()` | Returns custom attribute names for validation |
| `skipRender()` | Prevents re-render for this cycle |

## 22.2 Livewire Directives

| Directive | Description |
|-----------|-------------|
| `wire:model` | Two-way bind a property |
| `wire:model.live` | Update on every keystroke |
| `wire:model.blur` | Update on blur |
| `wire:model.debounce.Xms` | Debounce updates |
| `wire:click` | Call method on click |
| `wire:submit` | Call method on form submit |
| `wire:poll.Xs` | Poll method at interval |
| `wire:loading` | Show element during request |
| `wire:ignore` | Preserve DOM element during updates |
| `wire:key` | Unique key for loop items |

## 22.3 Livewire Attributes

| Attribute | Description |
|-----------|-------------|
| `#[Locked]` | Prevent client mutation of property |

| `#[Only(['method'])]` | Restrict callable methods |
| `#[Url]` | Sync property with URL |
| `#[Rule('...')]` | Apply validation rules |

# 23. Advanced Patterns

## 23.1 Wizard Components

Multi-step forms use a state machine pattern. Each step validates and advances:

```php
final class ThemeWizard extends Component
{
    public int $step = 1;
    public int $totalSteps = 3;
    public array $formData = [];

    public function nextStep(): void
    {
        $this->validate($this->stepRules());
        $this->step++;
    }

    public function previousStep(): void
    {
        $this->step = max(1, $this->step - 1);
    }

    public function submit(): void
    {
        $this->validate($this->allRules());
        (new CreateThemeAction(...))->execute(
            CreateThemeData::fromArray($this->formData)
        );
        $this->redirectRoute('themes.index');
    }

    private function stepRules(): array
    {
        return match ($this->step) {
            1 => ['formData.name' => ['required', 'string', 'max:255']],
            2 => ['formData.category' => ['required', 'string']],
            3 => ['formData.price' => ['required', 'numeric', 'min:0']],
            default => [],
        };
    }
}
```

## 23.3 Optimistic Updates

Update the UI immediately before the server confirms:

```php
public array $localState = [];

public function optimisticToggle(int $id): void
{
    // Update local state immediately
    $this->localState[$id] = !$this->localState[$id];

    // Then sync with server
    try {
        $this->toggleOnServer($id);
    } catch (\Exception $e) {
        // Rollback on failure
        $this->localState[$id] = !$this->localState[$id];
        $this->dispatch('error', message: 'Toggle failed');
    }
}
```

## 23.5 Offline Support

Detect offline status and queue actions:

```php
final class OfflineAwareComponent extends Component
{
    public bool $isOnline = true;
    public array $pendingActions = [];

    public function boot(): void
    {
        $this->isOnline = session()->get('is_online', true);
    }

    public function queueForLater(array $action): void
    {
        $this->pendingActions[] = $action;
        session()->put('pending_actions', $this->pendingActions);
    }

    public function syncPending(): void
    {
        foreach ($this->pendingActions as $action) {
            $this->executeAction($action);
        }
        $this->pendingActions = [];
        session()->forget('pending_actions');
    }
}
```

## 23.9 Event Aggregation

Aggregate multiple events into a single batch update:

```php
final class BatchUpdater extends Component
{
    public array $pendingUpdates = [];

    #[On('item.updated')]
    public function onItemUpdated(int $itemId): void
    {
        $this->pendingUpdates[] = $itemId;

        // Only flush after a short delay (debounce via Alpine)
        if (count($this->pendingUpdates) >= 10) {
            $this->flushUpdates();
        }
    }

    {

        $this->pendingUpdates = [];
    }
}
```

```php
final class ModalForm extends Component
```

## 25.3 Data Table Component

```php
final class DataTable extends Component
{
    public string $resource = '';
    public string $sortColumn = 'id';
    public string $sortDirection = 'asc';
    public int $perPage = 25;
    public array $selected = [];
    public bool $selectAll = false;

    public function sortBy(string $column): void
    {
        if ($this->sortColumn === $column) {
            $this->sortDirection = $this->sortDirection === 'asc' ? 'desc' : 'asc';
        } else {
            $this->sortColumn = $column;
            $this->sortDirection = 'asc';
        }
    }

    public function toggleSelectAll(): void
    {
        if ($this->selectAll) {
            $this->selected = $this->getResourceQuery()->pluck('id')->toArray();
        } else {
            $this->selected = [];
        }
    }

    public function toggleSelect(int $id): void
    {
        if (in_array($id, $this->selected)) {
            $this->selected = array_values(array_diff($this->selected, [$id]));
        } else {
            $this->selected[] = $id;
        }
    }

    public function bulkDelete(): void
    {
        $this->authorize('delete-any', $this->getResourceModel());
        $this->getResourceQuery()->whereIn('id', $this->selected)->delete();
        $this->selected = [];
        $this->selectAll = false;
        $this->dispatch('items.deleted');
    }

    private function getResourceQuery()
    {
        return app($this->resource)::query()
            ->orderBy($this->sortColumn, $this->sortDirection);
    }

    private function getResourceModel(): string
    {
        return $this->resource;
    }
}
```

# 27. Troubleshooting Guide

## 27.1 Common Errors

| Error | Cause | Solution |
|-------|-------|----------|
| `Property not found` | Missing public property | Add public property declaration |
| `Method not callable` | Private/protected method | Make method public |
| `Hydration error` | Non-serializable property | Use `#[Locked]` or dehydrate hook |
| `CSRF token mismatch` | Session expired | Implement `@livewire` layout |
| `Component not found` | Missing mount parameter | Check route and mount signature |
| `Maximum execution timeout` | Heavy computation | Queue the work instead |

## 27.2 Debugging Checklist

1. Check Livewire version compatibility.
2. Verify component class namespace matches config.
3. Ensure all public properties have defaults.
4. Check for circular event dispatching.
5. Verify authorization on all state-changing methods.
6. Monitor database queries for N+1 patterns.
7. Check cache invalidation after writes.
