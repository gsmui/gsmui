# 07.52 - Health Checks

**Project:** GsmUi
**Architecture:** System Health & Readiness
**Framework:** Laravel 13 + Livewire 4 + Spatie Health
**Version:** 1.0.0

---

> See also: `05.15-security.md` for the monitoring/observability layer and `05.43-performance-optimization.md` for the infrastructure view. This document is the *implementation contract*: the `spatie/laravel-health` check registration, the checks that ship with GsmUi, and the `/up` readiness endpoint consumed by the load balancer and the scheduler failure path (see `07.50-scheduler.md`).

# Purpose

Health checks give operators and orchestration a single, machine-readable signal of whether GsmUi is healthy. They probe every external dependency the app cannot function without â€” database, Redis (queue/cache), Horizon workers, Meilisearch (see `07.24-search.md`), and disk space â€” and aggregate them into a pass/fail report. A lightweight `/up` endpoint answers the load balancer's liveness probe, while the full Health report feeds dashboards and alerting.

Goals:

- **Dependency coverage** â€” every critical backend dependency has a check.
- **Silent unless bad** â€” checks log only on degraded status; they do not spam on healthy.
- **Standard endpoint** â€” `/up` returns 200 when healthy, 503 when any critical check fails.
- **Queue-aware** â€” Horizon check confirms workers are actually consuming, not just the process existing.

# 3. Custom Horizon Check

The built-in `HorizonCheck` confirms Horizon is running and has active workers. A minimal custom check subclasses `Check`:

```php
// app/Health/Checks/HorizonCheck.php
declare(strict_types=1);

namespace App\Health\Checks;

use Spatie\Health\Checks\Check;
use Spatie\Health\Enums\Status;
use Laravel\Horizon\Horizon;

final class HorizonCheck extends Check
{
    public function run(): \Spatie\Health\Result|\Spatie\Health\Checks\Result
    {
        $result = \Spatie\Health\Checks\Result::make();

        if (! Horizon::isActive() || count(Horizon::metrics()) === 0) {
            return $result->status(Status::Failed)->shortSummary('Horizon inactive');
        }

        return $result->status(Status::Ok)->shortSummary('Horizon active');
    }
}
```

# 4. The `/up` Endpoint

A minimal liveness endpoint answers the load balancer without running the full check suite. It returns 200 only when the critical dependencies are reachable; otherwise 503.

```php
// routes/web.php (or routes/health.php)
use Illuminate\Support\Facades\Route;
use Spatie\Health\Facades\Health;

Route::get('/up', function () {
    $report = Health::check();

    $critical = ['DatabaseCheck', 'RedisCheck', 'HorizonCheck'];

    foreach ($report->getCheckResults() as $result) {
        if (in_array($result->check->getName(), $critical, true)
            && $result->status !== \Spatie\Health\Enums\Status::Ok) {
            abort(503, 'Service degraded: ' . $result->getMessage());
        }
    }

    return response()->noContent(200);
})->name('health.up');
```

The scheduler (see `07.50-scheduler.md`) and deploy script (see `07.58-deployment.md`) poll `/up` to gate traffic during zero-downtime releases.

# 5. Check Matrix

| Check | Critical? | Failure impact |
| --- | --- | --- |
| `DatabaseCheck` | Yes | 503, no request can proceed |
| `RedisCheck` | Yes | 503, queue/cache unavailable |
| `CacheCheck` (redis) | No | Warn, falls back to DB |
| `MeiliSearchCheck` | No | Warn, search degraded only |
| `HorizonCheck` | Yes | 503, async work stalled |
| `UsedDiskSpaceCheck` | No | Warn â‰¥80%, fail â‰¥90% |

---

# 6. Operational Rules

1. `/up` must stay dependency-light; reserve heavy checks for `/health`.
2. Critical checks drive the 503 gate used by the load balancer and deploy script.
3. Disk and Meili checks warn, not fail, so they never take the site down on their own.
4. Health output flows into the log/monitoring pipeline (see `07.54-logging.md`).
5. Protect `/health` behind auth in production; `/up` may be public for the LB.

# 7. Custom Health Checks

### 7.1 Custom Horizon Check

```php
namespace App\Health\Checks;

use Spatie\Health\Checks\Check;
use Spatie\Health\Enums\Status;
use Laravel\Horizon\Horizon;

final class HorizonCheck extends Check
{
    public function run(): \Spatie\Health\Checks\Result
    {
        $result = \Spatie\Health\Checks\Result::make();

        if (!Horizon::isActive()) {
            return $result
                ->status(Status::Failed)
                ->shortSummary('Horizon inactive')
                ->notificationMessage('Horizon process is not running.');
        }

        $metrics = Horizon::metrics();
        $totalProcesses = collect($metrics)->sum('processes');

        if ($totalProcesses === 0) {
            return $result
                ->status(Status::Failed)
                ->shortSummary('No workers active')
                ->notificationMessage('Horizon has no active workers.');
        }

        return $result
            ->status(Status::Ok)
            ->shortSummary("Horizon active ({$totalProcesses} workers)");
    }
}
```

### 7.2 Custom Meilisearch Check

```php
namespace App\Health\Checks;

use Spatie\Health\Checks\Check;
use Spatie\Health\Enums\Status;
use Illuminate\Support\Facades\Http;

final class MeiliSearchCheck extends Check
{
    public function __construct(
        private readonly string $host,
        private readonly ?string $apiKey = null,
    ) {}

    public static function new(): static
    {
        return new static(
            host: config('scout.meilisearch.host'),
            apiKey: config('scout.meilisearch.key'),
        );
    }

    public function run(): \Spatie\Health\Checks\Result
    {
        $result = \Spatie\Health\Checks\Result::make();

        try {
            $response = Http::timeout(5)
                ->withHeaders($this->apiKey ? ['X-Meili-API-Key' => $this->apiKey] : [])
                ->get("{$this->host}/health");

            if ($response->failed()) {
                return $result
                    ->status(Status::Failed)
                    ->shortSummary('Meilisearch unreachable')
                    ->notificationMessage("HTTP {$response->status()}");
            }

            $data = $response->json();
            if (($data['status'] ?? '') !== 'available') {
                return $result
                    ->status(Status::Warning)
                    ->shortSummary('Meilisearch degraded')
                    ->notificationMessage('Status: ' . ($data['status'] ?? 'unknown'));
            }

            return $result
                ->status(Status::Ok)
                ->shortSummary('Meilisearch healthy');
        } catch (\Throwable $e) {
            return $result
                ->status(Status::Failed)
                ->shortSummary('Meilisearch error')
                ->notificationMessage($e->getMessage());
        }
    }
}
```

### 7.3 Custom Queue Depth Check

```php
namespace App\Health\Checks;

use Spatie\Health\Checks\Check;
use Spatie\Health\Enums\Status;
use Illuminate\Support\Facades\Redis;

final class QueueDepthCheck extends Check
{
    public function __construct(
        private readonly string $queue = 'default',
        private readonly int $warnThreshold = 100,
        private readonly int $failThreshold = 1000,
    ) {}

    public static function new(string $queue = 'default'): static
    {
        return new static(queue: $queue);
    }

    public function run(): \Spatie\Health\Checks\Result
    {
        $result = \Spatie\Health\Checks\Result::make();

        $depth = Redis::connection()->llen("queues:{$this->queue}");

        if ($depth >= $this->failThreshold) {
            return $result
                ->status(Status::Failed)
                ->shortSummary("Queue '{$this->queue}' depth: {$depth}")
                ->notificationMessage("Queue depth exceeds {$this->failThreshold}.");
        }

        if ($depth >= $this->warnThreshold) {
            return $result
                ->status(Status::Warning)
                ->shortSummary("Queue '{$this->queue}' depth: {$depth}")
                ->notificationMessage("Queue depth exceeds {$this->warnThreshold}.");
        }

        return $result
            ->status(Status::Ok)
            ->shortSummary("Queue '{$this->queue}' depth: {$depth}");
    }
}
```

### 7.4 Custom Disk Space Check

```php
namespace App\Health\Checks;

use Spatie\Health\Checks\Check;
use Spatie\Health\Enums\Status;

final class DiskSpaceCheck extends Check
{
    public function __construct(
        private readonly string $disk = 'local',
        private readonly int $warnPercent = 80,
        private readonly int $failPercent = 90,
    ) {}

    public static function new(string $disk = 'local'): static
    {
        return new static(disk: $disk);
    }

    public function run(): \Spatie\Health\Checks\Result
    {
        $result = \Spatie\Health\Checks\Result::make();

        $path = config("filesystems.disks.{$this->disk}.root");
        if (!$path || !is_dir($path)) {
            return $result
                ->status(Status::Warning)
                ->shortSummary("Disk '{$this->disk}' not found");
        }

        $total = disk_total_space($path);
        $free = disk_free_space($path);
        $used = $total - $free;
        $percent = round(($used / $total) * 100, 1);

        if ($percent >= $this->failPercent) {
            return $result
                ->status(Status::Failed)
                ->shortSummary("Disk {$this->disk}: {$percent}% used")
                ->notificationMessage("Disk usage exceeds {$this->failPercent}%.");
        }

        if ($percent >= $this->warnPercent) {
            return $result
                ->status(Status::Warning)
                ->shortSummary("Disk {$this->disk}: {$percent}% used")
                ->notificationMessage("Disk usage exceeds {$this->warnPercent}%.");
        }

        $freeGB = round($free / 1073741824, 2);
        return $result
            ->status(Status::Ok)
            ->shortSummary("Disk {$this->disk}: {$percent}% used ({$freeGB}GB free)");
    }
}
```

### 7.5 Custom Feature Flag Health Check

```php
namespace App\Health\Checks;

use App\Domains\Admin\Models\FeatureFlag;
use Spatie\Health\Checks\Check;
use Spatie\Health\Enums\Status;

final class FeatureFlagHealthCheck extends Check
{
    public function run(): \Spatie\Health\Checks\Result
    {
        $result = \Spatie\Health\Checks\Result::make();

        $totalFlags = FeatureFlag::count();
        $activeFlags = FeatureFlag::where('is_active', true)->count();
        $staleFlags = FeatureFlag::where('is_active', true)
            ->where('updated_at', '<', now()->subDays(90))
            ->count();

        $summary = "{$activeFlags}/{$totalFlags} active";
        if ($staleFlags > 0) {
            $summary .= " ({$staleFlags} stale)";
        }

        if ($staleFlags > 5) {
            return $result
                ->status(Status::Warning)
                ->shortSummary($summary)
                ->notificationMessage("{$staleFlags} flags stale for >90 days.");
        }

        return $result
            ->status(Status::Ok)
            ->shortSummary($summary);
    }
}
```

# 13. Health Check Performance

### 13.1 Execution Time Targets

| Check | Target | Max |
| --- | --- | --- |
| `DatabaseCheck` | < 5ms | 50ms |
| `RedisCheck` | < 5ms | 50ms |
| `CacheCheck` | < 10ms | 100ms |
| `HorizonCheck` | < 50ms | 200ms |
| `MeiliSearchCheck` | < 100ms | 500ms |
| `UsedDiskSpaceCheck` | < 20ms | 100ms |
| `QueueDepthCheck` | < 10ms | 100ms |
| Total `/up` | < 200ms | 1s |

### 13.2 Optimization

```text
1. /up endpoint runs only critical checks (DB, Redis, Horizon)
2. /health endpoint runs all checks
3. Check results cached for 30 seconds
4. Parallel check execution where possible
5. Timeout each check at 5 seconds
```

# 14. Operational Rules

1. `/up` must stay dependency-light; reserve heavy checks for `/health`.
2. Critical checks drive the 503 gate used by the load balancer and deploy script.
3. Disk and Meili checks warn, not fail, so they never take the site down on their own.
4. Health output flows into the log/monitoring pipeline (see `07.54-logging.md`).
5. Protect `/health` behind auth in production; `/up` may be public for the LB.
6. Check execution time should be < 200ms for `/up`.
7. Check results should be cached for 30 seconds to avoid redundant probes.
8. Critical check failures should trigger PagerDuty alerts.
9. Health check history should be retained for 30 days.
10. Health checks should be tested in CI to catch regressions.

```bash

# deploy.sh

# Wait for new container to be healthy
MAX_RETRIES=30
RETRY_COUNT=0

while [ $RETRY_COUNT -lt $MAX_RETRIES ]; do
    HTTP_CODE=$(curl -s -o /dev/null -w "%{http_code}" http://localhost/up)

    if [ $HTTP_CODE -eq 200 ]; then
        echo "Service is healthy."
        exit 0
    fi

    echo "Waiting for service... (attempt $RETRY_COUNT/$MAX_RETRIES)"
    RETRY_COUNT=$((RETRY_COUNT + 1))
    sleep 2
done

echo "Service failed to become healthy."
exit 1
```

### 18.1 Execution Time Targets

| Check | Target | Max | Notes |
| --- | --- | --- | --- |
| `DatabaseCheck` | < 5ms | 50ms | Fast, critical |
| `RedisCheck` | < 5ms | 50ms | Fast, critical |
| `CacheCheck` | < 10ms | 100ms | Fast, warning |
| `HorizonCheck` | < 50ms | 200ms | Medium, critical |
| `MeiliSearchCheck` | < 100ms | 500ms | Network call |
| `UsedDiskSpaceCheck` | < 20ms | 100ms | Filesystem |
| `QueueDepthCheck` | < 10ms | 100ms | Redis call |
| `DiskSpaceCheck` | < 20ms | 100ms | Filesystem |
| `FeatureFlagHealthCheck` | < 50ms | 200ms | DB query |
| Total `/up` | < 200ms | 1s | Critical checks only |
| Total `/health` | < 500ms | 3s | All checks |

### 18.2 Optimization Strategies

```text
1. /up runs only critical checks (DB, Redis, Horizon)
2. /health runs all checks
3. Check results cached for 30 seconds
4. Parallel check execution where possible
5. Timeout each check at 5 seconds
6. Use lightweight checks for /up
7. Heavy checks (disk, search) only on /health
8. Cache check results to avoid redundant probes
```

### 18.3 Caching Check Results

```php
// Cache check results for 30 seconds
Route::get('/up', function () {
    $report = Cache::remember('health:up', 30, function () {
        return Health::checks([
            DatabaseCheck::new(),
            RedisCheck::new(),
            HorizonCheck::new(),
        ])->check();
    });

    // Evaluate cached results
    $critical = ['DatabaseCheck', 'RedisCheck', 'HorizonCheck'];

    foreach ($report->getCheckResults() as $result) {
        if (in_array($result->check->getName(), $critical, true)
            && $result->status !== Status::Ok) {
            abort(503, 'Service degraded: ' . $result->getMessage());
        }
    }

    return response()->noContent(200);
})->name('health.up');
```

```text
  3. Check disk space on DB server
  4. Check for long-running queries

  2. Kill long-running queries
  3. Increase connection pool if needed
  4. Scale DB server if load is high
```

### 20.2 Check Failing: RedisCheck

```text
Symptom: /up returns 503, RedisCheck failed
Impact: Queue/cache unavailable
Investigation:
  1. Check Redis server: redis-cli ping
  2. Check memory usage: redis-cli info memory
  3. Check connection count: redis-cli info clients
Resolution:
  1. Restart Redis server
  2. Clear non-essential keys if OOM
  3. Scale Redis if load is high
```

### 20.3 Check Failing: HorizonCheck

```text
Symptom: /up returns 503, HorizonCheck failed
Impact: Async work stalled
Investigation:
  1. Check Horizon process: ps aux | grep horizon
  2. Check worker logs: tail -f storage/logs/horizon.log
  3. Check queue depth for stuck jobs

  1. Restart Horizon: php artisan horizon:terminate
  2. Check for stuck jobs: Horizon dashboard
  3. Scale workers if needed
```

### 20.4 Check Warning: QueueDepthCheck

```text
Symptom: QueueDepthCheck warning for a queue
Impact: Job processing delay
Investigation:
  1. Check queue depth: redis-cli LLEN queues:default
  2. Check worker throughput: Horizon dashboard
  3. Check for failed jobs
Resolution:
  1. Scale workers for that queue
  2. Check for stuck/slow jobs
  3. Optimize job performance
```

# 21. Operational Rules

1. `/up` must stay dependency-light; reserve heavy checks for `/health`.
2. Critical checks drive the 503 gate used by the load balancer and deploy script.
3. Disk and Meili checks warn, not fail, so they never take the site down on their own.
4. Health output flows into the log/monitoring pipeline.
5. Protect `/health` behind auth in production; `/up` may be public for the LB.
6. Check execution time should be < 200ms for `/up`.
7. Check results should be cached for 30 seconds.
8. Critical check failures should trigger PagerDuty alerts.
9. Health check history should be retained for 30 days.
10. Health checks should be tested in CI to catch regressions.
11. /up endpoint should not expose internal details.
12. /health endpoint requires admin authentication.
13. Deploy scripts should poll `/up` before routing traffic.
14. Kubernetes probes should use `/up` for liveness and readiness.
15. Monitor health check execution time â€” investigate if > 1s.

```php
    {

        // Export to Prometheus/DataDog

        // Export failure metric

    }
}
```

# 36. Health Check History Schema

### 36.1 Database Table Structure

The health_check_result_history_items table stores historical health check results:

| Column | Type | Description |
| --- | --- | --- |
| id | bigint | Primary key |
| check_name | string | Class name of the check |
| status | string | ok, warning, failed |
| message | text | Human-readable message |
| short_summary | string | Brief status summary |
| notification_message | text | Alert message |
| status_label | string | Display label |
| started_at | timestamp | Check start time |
| ended_at | timestamp | Check end time |
| duration_ms | integer | Execution time |
| created_at | timestamp | Record creation |

### 36.2 Querying History

`sql
-- Get all failed checks in the last 24 hours
SELECT check_name, status, message, created_at
FROM health_check_result_history_items
WHERE status = 'failed'
  AND created_at > NOW() - INTERVAL 24 HOUR
ORDER BY created_at DESC;

-- Get average check duration by check name
SELECT check_name, AVG(duration_ms) as avg_ms
FROM health_check_result_history_items
WHERE created_at > NOW() - INTERVAL 7 DAY
GROUP BY check_name;

-- Get uptime percentage per check
SELECT
    check_name,
    ROUND(SUM(CASE WHEN status = 'ok' THEN 1 ELSE 0 END) * 100.0 / COUNT(*), 2) as uptime_pct
FROM health_check_result_history_items
WHERE created_at > NOW() - INTERVAL 30 DAY
GROUP BY check_name;
`

### 36.3 History Retention

| Period | Retention | Action |
| --- | --- | --- |
| 0-7 days | All records | Available for queries |
| 8-30 days | Aggregated | Summarized by day |
| 31-90 days | Monthly stats | Avg, min, max only |
| 90+ days | Deleted | Purged by scheduler |
