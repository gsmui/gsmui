# 07.06 - Service Layer

**Project:** GsmUi
**Architecture:** Service Layer Pattern
**Framework:** Laravel 13 + Livewire 4
**Version:** 1.0.0

---

> See also: `05.07-service-layer.md` (service categories, responsibilities, transaction/event/caching guidance). This document is the *implementation contract*: the concrete `ServiceInterface`, `AbstractService` base, a worked example, DI binding, and the reuse rules a builder must follow.

# Purpose

The Service Layer holds GsmUi's business logic. Controllers, Livewire components, jobs, and console commands orchestrate; services decide. This document specifies the exact shape of a service so every domain implements it identically: a shared `ServiceInterface` marker, an `AbstractService` base providing transaction and dispatch helpers, constructor-injected dependencies, and a strict set of "may / may not" rules. Following this contract makes services testable, swappable behind contracts (per `07.04-module-architecture.md`), and extractable to microservices later.

All domain services extend `AbstractService` and implement `ServiceInterface` (or a domain-specific contract in `Contracts/`).

---

## 1. Service Interface Pattern

Services implement a shared marker plus, where cross-module consumption is needed, a domain contract. The base contract is intentionally minimal.

```php
namespace App\Shared\Contracts;

interface ServiceInterface
{
    /**
     * Marker contract implemented by every application service.
     * Concrete method signatures live on domain-specific contracts
     * (e.g. ComponentServiceContract) or the service class itself.
     */
}
```

```php
// Optional: public contract for cross-module consumption (see 07.04 §4)
namespace App\Domains\Components\Contracts;

use App\Domains\Components\Models\Component;
use App\Domains\Components\DTOs\ComponentData;

interface ComponentServiceContract
{
    public function create(ComponentData $data): Component;
    public function find(string $slug): ?Component;
}
```

## 2. AbstractService Base

`AbstractService` centralizes the two cross-cutting concerns services need: transaction boundaries and event dispatch. It lives in the Shared Kernel.

```php
namespace App\Shared\Support;

use Illuminate\Support\Facades\{DB, Event};

abstract class AbstractService implements \App\Shared\Contracts\ServiceInterface
{
    /**
     * Wrap a unit of work in a database transaction.
     * Network/external calls must happen AFTER the callback returns.
     */
    protected function transaction(callable $callback, int $attempts = 1): mixed
    {
        return DB::transaction($callback, $attempts);
    }

    /**
     * Dispatch a domain event. Prefer dispatching AFTER commit
     * for events that trigger async side effects.
     */
    protected function dispatch(object $event): void
    {
        Event::dispatch($event);
    }

    /**
     * Dispatch an event only after the current transaction commits.
     */
    protected function dispatchAfterCommit(object $event): void
    {
        Event::listen(\Illuminate\Database\Events\TransactionCommitted::class,
            fn () => Event::dispatch($event)
        );
    }
}
```

## 3. Example Service

A concrete domain service injects its repository (and any collaborators) via the constructor and implements business rules.

```php
namespace App\Domains\Components\Services;

use App\Domains\Components\Contracts\ComponentServiceContract;
use App\Domains\Components\DTOs\ComponentData;
use App\Domains\Components\Events\ComponentReleased;
use App\Domains\Components\Exceptions\ComponentAlreadyExistsException;
use App\Domains\Components\Models\Component;
use App\Domains\Components\Repositories\ComponentRepository;
use App\Shared\Support\AbstractService;

final class ComponentService extends AbstractService implements ComponentServiceContract
{
    public function __construct(
        private readonly ComponentRepository $components,
    ) {}

    public function create(ComponentData $data): Component
    {
        if ($this->components->slugExists($data->slug)) {
            throw new ComponentAlreadyExistsException($data->slug);
        }

        return $this->transaction(function () use ($data): Component {
            $component = $this->components->create($data->toArray());

            $this->dispatchAfterCommit(new ComponentReleased($component));

            return $component;
        });
    }

    public function find(string $slug): ?Component
    {
        return $this->components->findBySlug($slug);
    }
}
```

Rules reflected above:

- Constructor injection only; no service locator, no `app()` calls.
- Business precondition checked before the transaction.
- Persistence goes through the repository, never the model directly.
- Event dispatched after commit to keep async side effects consistent.

## 4. Transaction Boundaries

Transactions belong in the service (or the wrapping action). They MUST be short and contain no external/network calls.

```php
// Correct: transaction wraps only DB work.
return $this->transaction(function () use ($data): Component {
    $component = $this->components->create($data->toArray());
    $this->dispatchAfterCommit(new ComponentReleased($component));
    return $component;
});

// Wrong: HTTP/SDK call inside the transaction.
return $this->transaction(function () use ($data): Component {
    $component = $this->components->create($data->toArray());
    $this->stripe->charge(...); // network call — must be outside
    return $component;
});
```

For multi-step workflows spanning modules, the action owns the orchestration and each service keeps its own local transaction; cross-module consistency is achieved via events (per `05.05-module-boundaries.md` "Cross-Module Transactions").

## 5. Dependency Injection Binding

Services are bound in the module's service provider (see `07.04-module-architecture.md` §3). Repository contracts bind to Eloquent implementations; public service contracts bind to the concrete service.

```php
namespace App\Domains\Components;

use App\Domains\Components\Contracts\ComponentServiceContract;
use App\Domains\Components\Repositories\ComponentRepository;
use App\Domains\Components\Repositories\ComponentRepositoryEloquent;
use App\Domains\Components\Services\ComponentService;
use Illuminate\Support\ServiceProvider;

final class ComponentsServiceProvider extends ServiceProvider
{
    public function register(): void
    {
        $this->app->bind(ComponentRepository::class, ComponentRepositoryEloquent::class);
        $this->app->bind(ComponentServiceContract::class, ComponentService::class);
    }
}
```

Consumers receive the contract, never the concrete class:

```php
// Usage (controller / action / Livewire component)
$component = app(ComponentServiceContract::class)
    ->create(ComponentData::fromRequest($request));
```

## 6. Reuse Rules

A service MAY:

- Apply business rules and validation.
- Call its repository (and other modules' public contracts).
- Use value objects and DTOs.
- Throw domain-specific exceptions.
- Dispatch domain events.
- Own cache reads/writes for its own data.

A service MUST NOT:

- Render views or return HTTP responses.
- Read `$request` / `$_POST` / session directly.
- Contain HTML or Blade.
- Call another module's repository or model directly.
- Perform network/SDK calls inside a transaction.
- Hold mutable state between calls (stateless).

| Anti-pattern | Correct form |
| --- | --- |
| Fat controller with logic | Delegate to `Action` → `Service` |
| `Livewire → Model` query | `Livewire → Action → Service → Repository` |
| Repository-to-repository call | Route through a service |
| Business rule in a model | Move into the service |

## 7. Service Lifecycle

### 7.1 Service Instantiation

Services are instantiated by the Laravel container when first resolved. They are registered as singletons in the module's service provider.

```text
Container resolves service
    │
    ├── Check singleton cache
    │       ├── Exists → return cached instance
    │       └── Not exists → instantiate
    │
    ├── Resolve constructor dependencies
    │       ├── RepositoryInterface → bound to Eloquent implementation
    │       ├── Other ServiceInterface → bound to concrete service
    │       └── Scalar values → from config/env
    │
    ├── Store in singleton cache
    └── Return instance
```

### 7.2 Service Method Execution

```text
Caller invokes service method
    │
    ├── Validate input (DTO or scalar)
    ├── Check business preconditions
    │       ├── Precondition met → proceed
    │       └── Precondition failed → throw DomainException
    ├── Execute business logic
    │       ├── Call repository methods
    │       ├── Call other service methods (if needed)
    │       └── Apply business rules
    ├── Return result (model, DTO, collection, primitive)
    └── Caller handles result (action dispatches events, controller builds response)
```

## 8. Service Testing Strategy

### 8.1 Unit Test Pattern

```php
namespace Tests\Unit\Domains\Components\Services;

use App\Domains\Components\DTOs\ComponentData;
use App\Domains\Components\Exceptions\ComponentAlreadyExistsException;
use App\Domains\Components\Models\Component;
use App\Domains\Components\Repositories\Contracts\ComponentRepositoryInterface;
use App\Domains\Components\Services\ComponentService;
use Mockery;
use Tests\TestCase;

class ComponentServiceTest extends TestCase
{
    private ComponentService $service;
    private ComponentRepositoryInterface $repository;

    protected function setUp(): void
    {
        parent::setUp();

        $this->repository = Mockery::mock(ComponentRepositoryInterface::class);
        $this->service = new ComponentService($this->repository);
    }

    /** @test */
    public function create_with_valid_data_persists_component(): void
    {
        // Arrange
        $data = new ComponentData(
            name: 'Button',
            slug: 'button',
            description: 'A clickable button component',
            authorId: 1,
        );

        $expected = Component::factory()->make([
            'slug' => 'button',
            'author_id' => 1,
        ]);

        $this->repository
            ->shouldReceive('slugExists')
            ->with('button')
            ->once()
            ->andReturn(false);

        $this->repository
            ->shouldReceive('create')
            ->once()
            ->andReturn($expected);

        // Act
        $result = $this->service->create($data);

        // Assert
        $this->assertEquals('button', $result->slug);
    }

    /** @test */
    public function create_with_duplicate_slug_throws_exception(): void
    {
        // Arrange
        $data = new ComponentData(
            name: 'Button',
            slug: 'button',
            description: 'A clickable button component',
            authorId: 1,
        );

        $this->repository
            ->shouldReceive('slugExists')
            ->with('button')
            ->once()
            ->andReturn(true);

        // Act & Assert
        $this->expectException(ComponentAlreadyExistsException::class);
        $this->service->create($data);
    }

    /** @test */
    public function find_by_slug_returns_component_when_exists(): void
    {
        // Arrange
        $component = Component::factory()->create(['slug' => 'button']);

        $this->repository
            ->shouldReceive('findBySlug')
            ->with('button')
            ->once()
            ->andReturn($component);

        // Act
        $result = $this->service->findBySlug('button');

        // Assert
        $this->assertNotNull($result);
        $this->assertEquals('button', $result->slug);
    }

    /** @test */
    public function find_by_slug_returns_null_when_not_exists(): void
    {
        // Arrange
        $this->repository
            ->shouldReceive('findBySlug')
            ->with('nonexistent')
            ->once()
            ->andReturn(null);

        // Act
        $result = $this->service->findBySlug('nonexistent');

        // Assert
        $this->assertNull($result);
    }

    protected function tearDown(): void
    {
        Mockery::close();
        parent::tearDown();
    }
}
```

## 9. Service Composition Patterns

### 9.1 Service Delegation

```php
// ThemeService delegates to ComponentService for component lookup
final class ThemeService extends AbstractService implements ThemeServiceContract
{
    public function __construct(
        private readonly ThemeRepositoryInterface $themes,
        private readonly ComponentLookupContract $components,
    ) {}

    public function createThemeWithData(ThemeData $data): Theme
    {
        // Delegate component lookup to Components domain
        $baseComponent = $this->components->findById($data->baseComponentId);

        if (! $baseComponent) {
            throw new ComponentNotFoundException($data->baseComponentId);
        }

        return $this->themes->create($data->toArray());
    }
}
```

### 9.2 Service Chaining

```php
// Action orchestrates multiple service calls
final class PublishThemeAction extends Action
{
    public function __construct(
        private readonly ThemeService $themes,
        private readonly ValidationService $validation,
        private readonly SearchIndexService $search,
    ) {}

    public function handle(Theme $theme, int $userId): Theme
    {
        // Step 1: Validate theme is publishable
        $this->validation->validateForPublishing($theme);

        // Step 2: Publish the theme
        $published = $this->themes->publish($theme, $userId);

        // Step 3: Index in search
        $this->search->indexTheme($published);

        return $published;
    }
}
```

### 9.3 Service with Cache

```php
final class ComponentService extends AbstractService implements ComponentServiceContract
{
    public function __construct(
        private readonly ComponentRepositoryInterface $components,
        private readonly CacheService $cache,
    ) {}

    public function findBySlug(string $slug): ?Component
    {
        return $this->cache->remember(
            key: "component:{$slug}",
            ttl: 3600,
            callback: fn () => $this->components->findBySlug($slug),
        );
    }

    public function paginatePublished(int $perPage = 15): LengthAwarePaginator
    {
        return $this->cache->remember(
            key: "components:published:{$perPage}",
            ttl: 600,
            callback: fn () => $this->components->paginatePublished($perPage),
        );
    }

    public function update(Component $component, array $data): Component
    {
        $updated = $this->components->update($component, $data);

        // Invalidate cache
        $this->cache->forget("component:{$component->slug}");
        $this->cache->forget("components:published");

        return $updated;
    }
}
```

## 10. Service Error Handling

### 10.1 Exception Types

| Exception | When to throw | Example |
| --- |---|---|
| `DomainException` | Business rule violation | `ComponentAlreadyExistsException` |
| `NotFoundException` | Entity not found (after repository returns null) | `ComponentNotFoundException` |
| `ValidationException` | Input validation failure | `InvalidSlugFormatException` |
| `AuthorizationException` | Permission denied | `InsufficientPlanException` |
| `InfrastructureException` | External service failure | `PaymentGatewayTimeoutException` |

### 10.2 Error Handling Pattern

```php
final class ComponentService extends AbstractService implements ComponentServiceContract
{
    public function publish(Component $component, int $userId): Component
    {
        // Business precondition check
        if ($component->status !== ComponentStatus::Draft) {
            throw new ComponentAlreadyPublishedException($component->slug);
        }

        // Repository operation
        $published = $this->components->update($component, [
            'status' => ComponentStatus::Published,
            'published_at' => now(),
        ]);

        // Post-condition validation
        if ($published->status !== ComponentStatus::Published) {
            throw new \RuntimeException('Failed to publish component');
        }

        return $published;
    }
}
```

## 11. Service Performance Guidelines

### 11.1 Query Optimization

| Guideline | Rule | Implementation |
| --- |---|---|
| Eager loading | Always eager-load relations in read methods | `->with(['versions', 'category'])` |
| Select columns | Only select needed columns for list views | `->select(['id', 'name', 'slug'])` |
| Cursor for large sets | Use cursor() for processing large result sets | `Component::cursor()->each(...)` |
| Chunk for bulk | Use chunk() for batch processing | `Component::chunk(500, fn ($items) => ...)` |
| Avoid N+1 | Use with() or load() for relations | Repository enforces this |

### 11.2 Caching Strategy

```php
// Cache-aside pattern
public function find(int $id): ?Component
{
    return Cache::remember("component:{$id}", 3600, function () use ($id) {
        return $this->components->find($id);
    });
}

// Cache invalidation on write
public function update(Component $component, array $data): Component
{
    $updated = $this->components->update($component, $data);

    Cache::forget("component:{$component->id}");
    Cache::forget("component:{$component->slug}");
    Cache::forget("components:published");

    return $updated;
}
```

### 11.3 Memory Management

| Scenario | Memory concern | Solution |
|--- |---|---|
| Large collection processing | Loading all rows into memory | Use `cursor()` or `chunk()` |
| Multiple service calls | Each call creates objects | Reuse instances where possible |
| Event dispatch with payload | Large event objects | Only include IDs, not full models |
| Cache storage | Large values | Compress or paginate cached data |

## 14. Service Migration and Versioning

### 14.1 Adding a New Service Method

```php
// Step 1: Add to contract
interface ComponentServiceContract
{
    public function archive(Component $component): Component; // NEW
}

// Step 2: Implement in service
final class ComponentService extends AbstractService implements ComponentServiceContract
{
    public function archive(Component $component): Component
    {
        return $this->transaction(function () use ($component): Component {
            $archived = $this->components->update($component, [
                'status' => ComponentStatus::Archived,
                'archived_at' => now(),
            ]);

            $this->dispatchAfterCommit(new ComponentArchived($archived));

            return $archived;
        });
    }
}

// Step 3: Add tests

```

## 15. Service Layer Anti-Patterns

| Anti-pattern | Symptom | Fix |
| --- |---|---|
| God service | Service has > 20 methods | Split into focused services |
| Anemic service | Service has only getters/setters, no logic | Add business rules to service |
| Transaction in controller | Controller wraps service call in transaction | Move transaction to service/action |
| Direct model query in service | Service calls Model::query() | Use repository |
| HTTP calls in service | Service calls Guzzle/HTTP client | Move to infrastructure adapter |
| View rendering in service | Service returns view/response | Move to controller |
| Event dispatch in repository | Repository fires events | Move to service/action |
| Validation in repository | Repository validates data | Move to service/DTO |
| Cache in repository | Repository caches results | Move to service layer |
| State in service | Service holds mutable state between calls | Make service stateless |

## 16. Service Layer Complete Reference

### 16.1 Service Interface Contract

| Method pattern | Return type | Description |
| --- |---|---|
| `find(int $id)` | `?Model` | Find by primary key |
| `findOrFail(int $id)` | `Model` | Find by primary key or throw |
| `findBySlug(string $slug)` | `?Model` | Find by unique slug |
| `create(DTO $data)` | `Model` | Create new entity |
| `update(Model $model, array $data)` | `Model` | Update existing entity |
| `delete(Model $model)` | `void` | Remove entity |

| `search(string $query)` | `Collection` | Full-text search |
| `count()` | `int` | Total count |
| `exists(int $id)` | `bool` | Check existence |

| Pattern | Example | Description |
| --- |---|---|
| `create{Entity}` | `createComponent()` | Create new entity |
| `update{Entity}` | `updateComponent()` | Update existing entity |

### 16.4 Service Transaction Pattern

```php
// Transaction boundary in service
public function create(ComponentData $data): Component
{
    // Pre-condition check (outside transaction)
    if ($this->components->slugExists($data->slug)) {
        throw new ComponentAlreadyExistsException($data->slug);
    }

    // Transaction wraps only DB operations
    return $this->transaction(function () use ($data): Component {
        $component = $this->components->create($data->toArray());

        // Event dispatched after commit (not inside transaction)
        $this->dispatchAfterCommit(new ComponentCreated(
            componentId: $component->id,
            userId: $data->authorId,
        ));

        return $component;
    });
}
```

### 16.5 Service Caching Pattern

```php
// Cache-aside pattern in service
public function findBySlug(string $slug): ?Component
{
    return $this->cache->remember(
        key: "component:{$slug}",
        ttl: config('components.cache_ttl', 3600),
        callback: fn () => $this->components->findBySlug($slug),
    );
}

// Cache invalidation on write
public function update(Component $component, array $data): Component
{
    $updated = $this->components->update($component, $data);

    // Invalidate related caches
    $this->cache->forget("component:{$component->id}");
    $this->cache->forget("component:{$component->slug}");
    $this->cache->forget("components:published");
    $this->cache->forget("components:featured");

    return $updated;
}
```

### 16.6 Service Event Dispatch Pattern

```php
// Event dispatch after commit
public function publish(Component $component, int $userId): Component
{
    $published = $this->transaction(function () use ($component, $userId): Component {
        $updated = $this->components->update($component, [
            'status' => ComponentStatus::Published,
            'published_at' => now(),
            'published_by' => $userId,
        ]);

        $this->dispatchAfterCommit(new ComponentPublished(
            componentId: $updated->id,
            slug: $updated->slug,
            userId: $userId,
            version: $updated->version,
        ));

        return $updated;
    });

    return $published;
}
```

## 21. Transaction Management Deep-Dive

### 21.1 Transaction Boundary Rules

| Rule | Description | Example |
|---|---|---|
| Single responsibility | One transaction per business operation | `createOrder()` = 1 transaction |
| Commit at the edge | Commit only after all side-effects are queued | DB commit → then event dispatch |
| No nested transactions | Use `savepoints` only for genuinely nested operations | Avoid when possible |
| Short-lived | Keep transactions < 500ms | Avoid API calls inside transactions |
| Idempotent retries | If transaction fails, retry is safe | Use unique constraints |

### 21.2 Transaction Patterns

**Pattern A: Simple Transaction**

```php
public function create(ComponentData $data): Component
{
    return $this->db->transaction(function () use ($data) {
        $component = Component::create([
            'name' => $data->name,
            'slug' => $data->slug,
            'author_id' => $data->authorId,
            'status' => 'draft',
        ]);

        $this->repository->save($component);

        return $component;
    });
}
```

**Pattern B: Transaction with Event Dispatch**

```php
public function publish(Component $component, int $version): void
{
    $this->db->transaction(function () use ($component, $version) {
        $component->publish(version: $version);
        $this->repository->save($component);

        // Queue event, dispatch after commit
        $this->events->dispatchAfterCommit(
            new ComponentPublished(
                componentId: $component->id(),
                version: $version,
            )
        );
    });
}
```

**Pattern C: Transaction with Compensation**

```php
public function transferOwnership(Component $component, User $newOwner): void
{
    $originalOwner = $component->authorId();

    try {
        $this->db->transaction(function () use ($component, $newOwner) {
            $component->changeAuthor($newOwner->id());
            $this->repository->save($component);

            $this->notifications->notifyUser(
                $newOwner,
                'component.transferred',
                ['component_id' => $component->id()]
            );
        });
    } catch (\Exception $e) {
        // Compensate: revert ownership
        $component->changeAuthor($originalOwner);
        $this->repository->save($component);

        throw $e;
    }
}
```

### 21.3 Transaction Anti-Patterns

| Anti-Pattern | Problem | Fix |
|---|---|---|
| Transaction too large | Locks rows for seconds | Break into smaller transactions |
| API calls inside transaction | Holds DB lock during HTTP roundtrip | Move API calls after commit |
| Nested `DB::transaction()` | Deadlock risk | Use savepoints only when truly needed |
| Swallowing transaction errors | Silent data corruption | Always re-throw or compensate |
| No timeout | Long-running transaction blocks others | Set query timeout |

## 26. Service Caching Strategies

### 26.1 Cache Key Convention

| Pattern | Cache key format | TTL |
|---|---|---|
| Single entity | `{module}:{type}:{id}` | 15 minutes |
| Slug lookup | `{module}:{type}:slug:{slug}` | 15 minutes |
| List (paginated) | `{module}:{type}:list:{filters_hash}:{page}` | 5 minutes |
| Count | `{module}:{type}:count` | 10 minutes |
| User-specific | `{module}:{type}:user:{userId}:{id}` | 15 minutes |

### 26.2 Cache Invalidation Strategy

```php
final class ComponentService extends AbstractService
{
    public function update(Component $component, ComponentData $data): Component
    {
        $component->update($data->toArray());
        $this->repository->save($component);

        // Invalidate all related cache keys
        $this->cache->forget("components:component:{$component->id()}");
        $this->cache->forget("components:component:slug:{$component->slug()}");
        $this->cache->forget("components:component:list:*"); // pattern delete
        $this->cache->forget("components:component:count");

        return $component;
    }
}
```

### 26.3 Cache Stampede Prevention

```php
public function findBySlug(string $slug): ?Component
{
    $key = "components:component:slug:{$slug}";

    // Use lock to prevent stampede
    $lock = $this->cache->lock("lock:{$key}", seconds: 5);

    try {
        // Try to get from cache
        $cached = $this->cache->get($key);
        if ($cached !== null) {
            return $cached;
        }

        // Cache miss — acquire lock and refresh
        if ($lock->get()) {
            try {
                $component = $this->repository->findBySlug($slug);
                $this->cache->put($key, $component, now()->addMinutes(15));
                return $component;
            } finally {
                $lock->release();
            }
        }

        // Another process is refreshing — wait and retry
        usleep(50000); // 50ms
        return $this->cache->get($key);
    } finally {
        $lock?->release();
    }
}
```

## 31. Service Layer Decision Record

### 31.1 ADR: Services as Thin Orchestrators

**Decision:** Services contain orchestration logic only. Business rules live in entities and value objects.

**Context:** The initial implementation placed business validation in service methods, creating anemic domain models.

**Decision:** Move all business rules into entity constructors and domain methods. Services become thin orchestrators that coordinate persistence, events, and cross-module communication.

**Consequences:**
- Entities become richer and more testable
- Services become smaller and more focused
- Business rules are easier to find (in entities, not scattered across services)
- Domain experts can review entity logic more easily

### 31.2 ADR: Contracts for All Service Interfaces

**Decision:** Every service has a contract (interface) in the module's `Contracts/` directory.

**Context:** Direct service class references create tight coupling between modules.

**Decision:** Define `ComponentServiceInterface` in `Contracts/`, implement in `Services/ComponentService.php`. All consumers depend on the interface.

**Consequences:**
- More files (interface + implementation)
- Enables mocking in tests
- Enables decorator pattern (caching, logging)
- Enables future microservice extraction

|---|---|---|
| God service | 500+ lines, 20+ methods | Split into focused services |
| Logic in controller | Business rules in controller | Move to service or entity |
| Logic in migration | Business rules in migration | Move to service |
| Direct DB in Livewire | `Model::query()` in Livewire | Inject service, not model |
| No interface | `ComponentService` used directly | Create `ComponentServiceInterface` |
| Raw array input | `function create(array $data)` | Use typed DTOs |
| Silent failure | `try { ... } catch { }` | Always re-throw or log |
| N+1 in service | Loop with individual queries | Use eager loading or batch |

### 32.1 Anti-Pattern Detection Script

```php
// Check for service anti-patterns automatically
$services = glob('app/Domains/*/Services/*.php');

foreach ($services as $service) {
    $lines = count(file($service));
    $methods = count(preg_grep('/function\s+\w+/', file($services)));

    if ($lines > 300) {
        echo "WARNING: " . basename($service) . " exceeds 300 lines\n";
    }
    if ($methods > 15) {
        echo "WARNING: " . basename($service) . " has more than 15 methods\n";
    }
}
```
