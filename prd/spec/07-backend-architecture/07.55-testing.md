# 07.55 - Testing

**Project:** GsmUi
**Architecture:** Layered Test Pyramid (Pest + PHPUnit)
**Framework:** Laravel 13 + Livewire 4
**Version:** 1.0.0

---

# Purpose

This document is the **implementation contract** for `05.42-testing-strategy.md`. It specifies the concrete test layout, the toolchain (Pest as the default runner with PHPUnit-compatible base classes), factory and fixture conventions, the trait mixins available for HTTP/Livewire/Database tests, service-mocking patterns, and per-module coverage gates enforced in CI. It is written so a developer can scaffold a passing test suite without re-reading the conceptual strategy.

> See also: 05.42-testing-strategy.md (test concept), 07.53-error-handling.md / 07.54-logging.md (what tests must assert), 07.56-performance.md (N+1 test guards), 07.59-coding-standards.md (pre-commit/lint gates).

---

# 1. Toolchain

- **Pest** (`pestphp/pest`) is the runner; tests extend `Tests\TestCase` which extends `PHPUnit\Framework\TestCase`.
- **Orchestra Testbench** provides the Laravel app container for package-style testing; the app itself uses the standard `CreatesApplication` trait.
- **Pest Plugins:** `pest-plugin-laravel`, `pest-plugin-livewire`, `pest-plugin-type-coverage`.
- **Static pairing:** `larastan/larastan` (PHPStan) and `laravel/pint` (formatting) run alongside tests in CI.

`phpunit.xml` essentials:

```xml
<phpunit ...>
  <testsuites>
    <testsuite name="Unit"><directory>tests/Unit</directory></testsuite>
    <testsuite name="Feature"><directory>tests/Feature</directory></testsuite>
    <testsuite name="Browser"><directory>tests/Browser</directory></testsuite>
  </testsuites>
  <source>
    <include><directory>app</directory></include>
  </source>
  <coverage>
    <include><directory suffix=".php">app</directory></include>
  </coverage>
</phpunit>
```

# 2. Directory Layout

```text
tests/
  Pest.php                      # global helpers, uses()
  TestCase.php                  # base case, CreatesApplication
  Unit/
    Domains/{Domain}/{Class}Test.php
  Feature/
    Http/                       # controllers, API (07.21)
    Livewire/                   # components (07.19)
    Actions/                    # action layer (07.08)
    Jobs/                       # queue (07.14, 07.49)
  Fixtures/                     # json, html snapshots
  Factories/                    # model factories
```

Mirror the `app/` namespace: `App\Domains\Search\Services\SearchIndexService` → `tests/Unit/Domains/Search/Services/SearchIndexServiceTest.php`.

# 3. Base Test Case

```php
<?php

declare(strict_types=1);

namespace Tests;

use Illuminate\Foundation\Testing\RefreshDatabase;
use Illuminate\Foundation\Testing\TestCase as BaseTestCase;
use Tests\Concerns\CreatesApplication;

abstract class TestCase extends BaseTestCase
{
    use CreatesApplication;
}
```

`Pest.php` loads shared traits and plugins:

```php
use Tests\TestCase;

uses(TestCase::class)->in('Unit', 'Feature');
uses(Tests\Concerns\RefreshDatabaseOnce::class)->in('Feature');

arch('strict types')->levels(10);
```

# 4. Factories

Use typed, relationship-aware factories. Pivot/state variants encode domain rules.

```php
<?php

declare(strict_types=1);

namespace Database\Factories;

use App\Models\User;
use Illuminate\Database\Eloquent\Factories\Factory;

final class ComponentFactory extends Factory
{
    protected $model = \App\Models\Component::model();

    /** @return array<string, mixed> */
    public function definition(): array
    {
        return [
            'name' => fake()->unique()->company(),
            'slug' => fake()->unique()->slug(),
            'category' => fake()->randomElement(['form', 'navigation', 'data']),
            'downloads' => fake()->numberBetween(0, 50000),
            'user_id' => User::factory(),
            'created_at' => now(),
        ];
    }

    public function published(): static
    {
        return $this->state(fn () => ['published_at' => now()]);
    }
}
```

Never call `fake()->password()` (PII). Use `User::factory()->create()` with a fixed seed in `TestCase::setUp()` for deterministic data.

# 5. HTTP / API Tests

Feature tests assert status, envelope, and authorization — never internal logic. Uses `RefreshDatabase` and the `actingAs` helper.

```php
<?php

declare(strict_types=1);

use App\Models\User;
use Illuminate\Foundation\Testing\RefreshDatabase;

uses(RefreshDatabase::class);

test('authenticated user can list components', function (): void {
    $user = User::factory()->create();

    $this->actingAs($user)
        ->getJson('/api/v1/components')
        ->assertOk()
        ->assertJsonStructure(['data', 'meta', 'links']);
});

test('guest cannot publish a component', function (): void {
    $component = \App\Models\Component::factory()->create();

    $this->deleteJson("/api/v1/components/{$component->id}")
        ->assertUnauthorized();
});
```

API envelopes match `07.21-api-architecture.md` and `07.53-error-handling.md` (`problem+json` on failure).

# 6. Livewire Tests

Use `pest-plugin-livewire`. Assert rendered state, emitted events, and validation errors without touching the DOM directly.

```php
<?php

declare(strict_types=1);

use App\Livewire\Components\CreateComponent;
use App\Models\User;
use Illuminate\Foundation\Testing\RefreshDatabase;
use Livewire\Livewire;

uses(RefreshDatabase::class);

test('component form validates required fields', function (): void {
    $this->actingAs(User::factory()->create());

    Livewire::test(CreateComponent::class)
        ->set('form.name', '')
        ->call('save')
        ->assertHasErrors(['form.name' => 'required'])
        ->assertDispatched('notify', type: 'error');
});

test('successful save redirects and logs', function (): void {
    \Illuminate\Support\Facades\Log::spy();

    Livewire::actingAs(User::factory()->create())
        ->test(CreateComponent::class)
        ->set('form.name', 'Accordion')
        ->set('form.category', 'navigation')
        ->call('save')
        ->assertHasNoErrors()
        ->assertRedirect(route('components.index'));

    \Illuminate\Support\Facades\Log::shouldHaveReceived('info');
});
```

# 7. Database & Repository Tests

Assert query shape and state transitions at the repository boundary (`07.07-repository-layer.md`).

```php
test('repository eager loads author to avoid n+1', function (): void {
    $user = User::factory()->create();
    \App\Models\Component::factory()->for($user)->count(5)->create();

    \DB::enableQueryLog();

    $components = app(\App\Domains\Components\Repositories\ComponentRepository::class)
        ->paginateWithAuthor(perPage: 10);

    expect($components->first()->relationLoaded('user'))->toBeTrue();
    expect(\DB::getQueryLog())->toHaveCount(2); // not 6
});

test('soft delete cascades to media', function (): void {
    $component = \App\Models\Component::factory()->has(\App\Models\Media::factory()->count(3))->create();

    $component->delete();

    expect(\App\Models\Media::where('component_id', $component->id)->count())->toBe(0);
});
```

# 8. Service & Job Mocking

Isolate the unit under test by mocking collaborators via the container. Assert thrown `GsmUiException` types (`07.53-error-handling.md`).

```php
test('index service throws infrastructure exception on search down', function (): void {
    $meili = Mockery::mock(\App\Contracts\SearchClient::class);
    $meili->shouldReceive('addDocuments')->andThrow(new \Meilisearch\Exceptions\ApiException('down'));
    $this->app->instance(\App\Contracts\SearchClient::class, $meili);

    $this->expectException(\App\Exceptions\Infrastructure\SearchEngineException::class);

    app(\App\Domains\Search\Services\SearchIndexService::class)
        ->indexComponents([Component::factory()->make()]);
});

test('export job is queued on publish', function (): void {
    Queue::fake();

    PublishComponentAction::run(Component::factory()->create());

    Queue::assertPushed(\App\Jobs\GenerateComponentExport::class);
});
```

Use `Queue::fake()`, `Event::fake()`, `Notification::fake()`, `Mail::fake()` per test; never let side-effects leak between tests (RefreshDatabase isolates DB, but fakes must be re-declared).

# 9. Fixtures & Snapshots

Store large payloads (webhook bodies, Meilisearch docs, HTML export) as files; load via `Fixture::load()`.

```php
final class Fixture
{
    public static function load(string $name): string
    {
        return file_get_contents(base_path("tests/Fixtures/{$name}"));
    }
}

$body = Fixture::load('stripe/webhook.component.purchased.json');
```

For HTML/Blade snapshots, compare normalized output: `assertStringContainsString()` over `assertEquals()` to survive benign whitespace changes.

A test that only calls a method without asserting behavior fails the "useful assertion" arch rule:

```php
arch('tests have assertions')
    ->expect('Tests')
```

# 11. Test Naming & Style

- Pest closure style: `test('user can publish component', fn () => ...)`.
- One behavior per test; name describes the *expected outcome*, not the method.
- Arrange / Act / Assert spacing with blank lines.
- No `sleep()`; use `Travel::to()` (Carbon) or `Queue::advanceTime()`.
- Database tests opt into `RefreshDatabase`; pure unit tests do not boot the DB.

# 13. Advanced Testing Patterns

## 13.1 Data Providers

Use Pest data providers for testing multiple scenarios:

```php
dataset('invalid_emails', [
    'missing@' => ['missing@'],
    '@missing.com' => ['@missing.com'],
    'spaces in@email.com' => ['spaces in@email.com'],
    '' => [''],
]);

test('email validation rejects invalid formats', function (string $email): void {
    Livewire::test(RegistrationForm::class)
        ->set('email', $email)
        ->call('register')
        ->assertHasErrors(['email' => 'email']);
})->with('invalid_emails');
```

## 13.2 Event Spying

Spy on events to verify dispatching without faking:

```php
test('theme creation dispatches domain event', function (): void {
    Event::spy();

    Livewire::test(ThemeCreator::class)
        ->set('name', 'Midnight')
        ->call('save');

    Event::assertDispatched(ThemeCreated::class, function ($event) {
        return $event->theme->name === 'Midnight';
    });
});
```

## 13.3 Notification Testing

Assert notifications are sent correctly:

```php
test('publish sends notification to subscribers', function (): void {
    Notification::fake();

    $component = Component::factory()->create();
    $subscriber = User::factory()->create();
    $subscriber->subscribe($component);

    Livewire::actingAs($component->user)
        ->test(PublishComponent::class, ['componentId' => $component->id])
        ->call('publish');

    Notification::assertSentTo($subscriber, ComponentPublished::class);
});
```

## 13.4 Mail Testing

Test email sending in feature tests:

```php
test('welcome email is sent after registration', function (): void {
    Mail::fake();

    Livewire::test(RegistrationForm::class)
        ->set('email', 'test@example.com')
        ->set('password', 'password123')
        ->call('register');

    Mail::assertSent(WelcomeEmail::class, function ($mail) {
        return $mail->hasTo('test@example.com');
    });
});
```

## 13.5 Queue Testing

Assert jobs are dispatched to specific queues:

```php
test('export job dispatched to exports queue', function (): void {
    Queue::fake();

    $component = Component::factory()->create();

    Livewire::actingAs($component->user)
        ->test(ExportComponent::class, ['componentId' => $component->id])
        ->call('export');

    Queue::assertPushed(GenerateComponentExport::class, function ($job) {
        return $job->queue === 'exports';
    });
});
```

# 15. Performance Testing

## 15.1 Database Query Count

Assert a page does not trigger excessive queries:

```php
test('component list uses fewer than 10 queries', function (): void {
    Component::factory()->count(50)->create();

    DB::enableQueryLog();

    $this->actingAs(User::factory()->create())
        ->get('/components');

    $queryCount = count(DB::getQueryLog());
    expect($queryCount)->toBeLessThan(10);
});
```

## 15.2 Response Time Testing

```php
test('api responds within 200ms', function (): void {
    $start = microtime(true);

    $this->actingAs(User::factory()->create())
        ->getJson('/api/v1/components');

    $elapsed = (microtime(true) - $start) * 1000;
    expect($elapsed)->toBeLessThan(200);
});
```

## 15.3 Memory Usage Testing

```php
test('export does not exceed memory limit', function (): void {
    $startMemory = memory_get_usage(true);

    Livewire::test(ExportComponent::class)
        ->call('export');

    $endMemory = memory_get_usage(true);
    $usedMB = ($endMemory - $startMemory) / 1024 / 1024;

    expect($usedMB)->toBeLessThan(50); // 50MB limit
});
```

# 16. Security Testing

## 16.1 Authorization Testing

Test that unauthorized users cannot access protected resources:

```php
test('guest cannot view admin dashboard', function (): void {
    $this->get('/admin')
        ->assertRedirect('/login');
});

test('regular user cannot access admin dashboard', function (): void {
    $this->actingAs(User::factory()->create())
        ->get('/admin')
        ->assertForbidden();
});
```

## 16.2 CSRF Testing

Verify CSRF protection is active:

```php
test('forms require csrf token', function (): void {
    $this->withoutMiddleware(VerifyCsrfToken::class)
        ->post('/components', ['name' => 'Test'])
        ->assertStatus(419);
});
```

## 16.3 XSS Testing

Test that user input is properly escaped:

```php
test('component description is escaped', function (): void {
    $component = Component::factory()->create([
        'description' => '<script>alert("xss")</script>',
    ]);

    $this->get("/components/{$component->id}")
        ->assertDontSee('<script>')
        ->assertSee('&lt;script&gt;');
});
```

## 16.4 SQL Injection Testing

Test that inputs are properly parameterized:

```php
test('search is safe from sql injection', function (): void {
    $this->actingAs(User::factory()->create())
        ->getJson('/api/v1/components?search=' . urlencode("'; DROP TABLE components; --"))
        ->assertOk();

    $this->assertDatabaseHas('components', []);
});
```

# 19. Mocking Strategies

## 19.1 Service Mocking

Mock services at the container level:

```php
test('search service handles meilisearch failure', function (): void {
    $this->mock(SearchClient::class, function ($mock) {
        $mock->shouldReceive('addDocuments')
            ->andThrow(new \Meilisearch\Exceptions\ApiException('Service unavailable'));
    });

    $this->expectException(InfrastructureException::class);
    $this->expectExceptionMessage('Search engine unavailable');

    app(SearchIndexService::class)->indexComponents([
        Component::factory()->make(),
    ]);
});
```

## 19.2 Facade Mocking

Mock facades for testing side effects:

```php
test('cache is cleared after component publish', function (): void {
    Cache::shouldReceive('forget')
        ->with('components:popular:24h')
        ->once();

    Livewire::actingAs(User::factory()->create())
        ->test(PublishComponent::class, ['componentId' => 1])
        ->call('publish');
});
```

## 19.3 Partial Mocking

Mock only specific methods:

```php
test('theme export generates file', function (): void {
    $exporter = Mockery::mock(ThemeExporter::class);
    $exporter->shouldReceive('export')
        ->once()
        ->andReturn('.theme-bg { color: black; }');

    $this->app->instance(ThemeExporter::class, $exporter);

    Livewire::test(ThemeExport::class, ['themeId' => 1])
        ->call('export')
        ->assertDispatched('export.complete');
});
```

## 19.4 HTTP Mocking

Mock external HTTP requests:

```php
test('webhook processes stripe event', function (): void {
    Http::fake([
        'api.stripe.com/*' => Http::response(['status' => 'success'], 200),
    ]);

    $payload = Fixture::load('stripe/webhook.component.purchased.json');

    $this->postJson('/api/webhooks/stripe', $payload, [
        'X-Signature' => 'valid-signature',
    ])->assertOk();
});
```

# 23. Test Anti-Patterns

## 23.1 Common Anti-Patterns

| Anti-Pattern | Correct Approach |
|-------------|-----------------|
| Testing implementation details | Test behavior and outcomes |
| Shared mutable state between tests | Use RefreshDatabase and fresh factories |
| Testing framework internals | Trust the framework |
| Ignoring test failures | Fix immediately |
| Testing everything in one test | One behavior per test |
| Using `sleep()` for timing | Use `Travel::to()` |
| Mocking too much | Mock only external dependencies |
| Not testing edge cases | Test empty, null, boundary values |

## 23.2 Test Smells

Identify and fix test smells:

```php
// Smell: Test depends on order
test('first test', function () { /* ... */ });
test('depends on first', function () { /* ... */ })->depends('first test');

// Fix: Independent tests
test('first test', function () { /* ... */ });
test('independent test', function () { /* ... */ });
```

```php
// Smell: Test does too much
test('full user journey', function () {
```

# 33. Test Fixtures and Snapshots

## 33.1 Fixture Loading

```php
final class Fixture
{
    public static function load(string $name): string
    {
        $path = base_path("tests/Fixtures/{$name}");

        if (!file_exists($path)) {
            throw new FileNotFoundException("Fixture not found: {$name}");
        }

        return file_get_contents($path);
    }

    public static function loadJson(string $name): array
    {
        return json_decode(self::load($name), true, 512, JSON_THROW_ON_ERROR);
    }
}
```

## 33.2 Snapshot Testing

Compare rendered output against saved snapshots:

```php
test('badge renders correctly', function (): void {
    $view = $this->blade('<gsmui:badge variant="success">OK</gsmui:badge>');

    $snapshot = 'tests/Fixtures/snapshots/badge-success.html';

    if (!file_exists($snapshot)) {
        file_put_contents($snapshot, $view->render());
        $this->assertTrue(true); // First run creates snapshot
        return;
    }

    $expected = file_get_contents($snapshot);
    expect($view->render())->toEqual($expected);
});
```

# 36. Test Summary

GsmUi uses a layered testing approach with Pest as the primary runner. Unit tests validate pure logic, feature tests validate HTTP and Livewire interactions, browser tests validate full-stack behavior, and performance tests validate speed and resource usage. The test suite enforces a minimum 85% code coverage threshold, with higher targets for critical modules. Tests are organized by domain and follow the Arrange-Act-Assert pattern. Mocking is used sparingly and only for external dependencies. The CI pipeline runs all tests in parallel and blocks merge on any failure.

```php
// In TestCase
protected function setUp(): void
{
    parent::setUp();
    $this->startTime = microtime(true);
    $this->startMemory = memory_get_usage(true);
}

protected function tearDown(): void
{
    $elapsed = (microtime(true) - $this->startTime) * 1000;
    $memoryUsed = (memory_get_usage(true) - $this->startMemory) / 1024 / 1024;

    if ($elapsed > 500) {
        $this->addWarning("Test took {$elapsed}ms (target: < 100ms)");
    }

    if ($memoryUsed > 10) {
        $this->addWarning("Test used {$memoryUsed}MB memory (target: < 5MB)");
    }

    parent::tearDown();
}
```
