# 07.46 - Settings

**Project:** GsmUi
**Architecture:** Settings Repository + Typed Accessors
**Framework:** Laravel 13 + Livewire 4
**Version:** 1.0.0

---

> See also: `06.101-settings.md` (schema for `setting_groups`, `settings`, `setting_scopes`). This document is the *implementation contract*: the `SettingsRepository` interface, typed accessor methods that cast `value` by the `type` column, group + per-scope resolution, and the cache strategy that backs configuration reads platform-wide.

# Purpose

Settings are configuration data, not business records — they are stored as typed key/value rows and resolved at runtime for feature configuration, theming options, and operational toggles. This document specifies the repository and accessor layer so callers read settings through one typed contract (`SettingsRepository::get('mail.from_name')`) instead of querying `settings` directly or hand-decoding JSON.

Goals:

- **Typed access** — `get()` returns a scalar, array, or decrypted value based on the row's `type`, never a raw JSON blob.
- **Scope resolution** — a global value is returned unless a `setting_scopes` override exists for the requesting scope (user, team, etc.).
- **Cacheable** — the resolved value set is cached cluster-wide with a short TTL and invalidated on write.
- **Encrypted support** — rows with `is_encrypted` are transparently decrypted via Laravel's encrypted cast (see `06.01-design-principles.md` §8).

## 1. SettingsRepository Contract

```php
namespace App\Domains\Admin\Contracts;

use App\Domains\Admin\ValueObjects\SettingScope;

interface SettingsRepository
{
    /**
     * Resolve a setting by "group.key".
     * @return mixed scalar | array | null
     */
    public function get(string $key, mixed $default = null, ?SettingScope $scope = null): mixed;

    /** Persist a setting value (creates the row if the group+key is unknown). */
    public function set(string $key, mixed $value, ?SettingScope $scope = null): void;

    /** All resolved settings for a group, optionally scoped. */
    public function all(string $group, ?SettingScope $scope = null): array;
}
```

## 2. Typed Accessor

The repository decodes `value` (stored as JSON) according to the `type` column. Encrypted rows are decrypted by Eloquent's `encrypted` cast before decoding.

```php
namespace App\Domains\Admin\Repositories\Eloquent;

use App\Domains\Admin\Contracts\SettingsRepository;
use App\Domains\Admin\Models\Setting;
use App\Domains\Admin\Models\SettingGroup;
use App\Domains\Admin\Models\SettingScope as ScopeModel;
use App\Domains\Admin\ValueObjects\SettingScope;
use Illuminate\Support\Facades\Cache;

final class SettingsRepositoryEloquent implements SettingsRepository
{
    public function get(string $key, mixed $default = null, ?SettingScope $scope = null): mixed
    {
        [$group, $leaf] = $this->split($key);

        return Cache::remember(
            $this->cacheKey($group, $leaf, $scope),
            300,
            fn () => $this->resolve($group, $leaf, $scope) ?? $default
        );
    }

    public function set(string $key, mixed $value, ?SettingScope $scope = null): void
    {
        [$group, $leaf] = $this->split($key);

        $groupId = SettingGroup::where('name', $group)->firstOrFail()->id;

        $setting = Setting::firstOrCreate(
            ['group_id' => $groupId, 'key' => $leaf],
            ['type' => $this->inferType($value), 'is_encrypted' => false],
        );

        if ($scope === null) {
            $setting->update(['value' => $value]);
        } else {
            ScopeModel::updateOrCreate(
                ['setting_id' => $setting->id, 'scope_type' => $scope->type, 'scope_id' => $scope->id],
                ['value' => $value],
            );
        }

        $this->forget($group, $leaf, $scope);
    }

    private function resolve(string $group, string $leaf, ?SettingScope $scope): mixed
    {
        $setting = Setting::query()
            ->where('key', $leaf)
            ->whereRelation('group', 'name', $group)
            ->first();

        if ($setting === null) {
            return null;
        }

        // Scoped override wins over the global value.
        if ($scope !== null) {
            $override = $setting->scopes()
                ->where('scope_type', $scope->type)
                ->where('scope_id', $scope->id)
                ->first();
            if ($override !== null) {
                return $override->value;
            }
        }

        return $setting->value; // already typed by Eloquent casts
    }

    private function inferType(mixed $value): string
    {
        return is_bool($value) ? 'boolean'
            : is_int($value) ? 'integer'
            : is_array($value) ? 'json'
            : 'string';
    }

    private function split(string $key): array
    {
        return explode('.', $key, 2) + [null, null];
    }

    private function cacheKey(string $group, string $leaf, ?SettingScope $scope): string
    {
        $s = $scope ? "{$scope->type}:{$scope->id}" : 'global';
        return "setting:{$group}.{$leaf}:{$s}";
    }

    private function forget(string $group, string $leaf, ?SettingScope $scope): void
    {
        Cache::forget($this->cacheKey($group, $leaf, $scope));
    }
}
```

## 5. Model Casts (per 06.101)

The `Setting` model declares the casts that make `resolve()` return typed values:

```php
protected $casts = [
    'value'        => 'array',  // decoded from JSON column
    'is_encrypted' => 'boolean',
];
```

For encrypted rows, the migration stores ciphertext and the model uses the `encrypted` cast on `value` (see `06.01-design-principles.md` §8). The repository does not need to know — Eloquent returns the plaintext automatically.

## 6. Caching & Invalidation

| Cache key | TTL | Invalidated on |
| --- | --- | --- |
| `setting:{group}.{leaf}:global` | 300s | `set()` global write |
| `setting:{group}.{leaf}:{type}:{id}` | 300s | `set()` scoped write |

Writes go through `set()` so the relevant key is forgotten; broad invalidation is unnecessary because keys are narrow.

---

## 7. Reuse & Boundary Rules

A caller MAY:

- Read settings via `get()` from any layer.
- Write settings from admin services only (per `05.24-admin-platform-architecture.md`).

A caller MUST NOT:

- Query `settings` / `setting_scopes` directly to fetch configuration.
- Store secrets outside an `is_encrypted` row.
- Cache the resolved value beyond the repository's own TTL.

## 8. Setting Groups & Organization

### 8.1 Group Hierarchy

Settings are organized into groups for logical separation and admin UI grouping. Each group maps to a domain concern.

| Group | Domain | Example keys |
| --- | --- | --- |
| `mail` | Email configuration | `mail.from_name`, `mail.from_address`, `mail.reply_to` |
| `ui` | UI customization | `ui.theme`, `ui.pagination_size`, `ui.rich_editor` |
| `auth` | Authentication | `auth.registration_enabled`, `auth.mfa_required` |
| `integrations` | Third-party | `integrations.stripe_key`, `integrations.slack_webhook` |
| `billing` | Subscription | `billing.trial_days`, `billing.currency` |
| `seo` | Search optimization | `seo.meta_title`, `seo.sitemap_enabled` |
| `search` | Search engine | `search.engine`, `search.index_prefix` |
| `media` | File uploads | `media.max_upload_size`, `media.allowed_types` |
| `notifications` | Alerts | `notifications.channels`, `notifications quiet_hours` |
| `security` | Security policies | `security.session_timeout`, `security.password_min_length` |

### 8.2 Group Model

```php
namespace App\Domains\Admin\Models;

use Illuminate\Database\Eloquent\Model;
use Illuminate\Database\Eloquent\Relations\HasMany;

class SettingGroup extends Model
{
    protected $fillable = ['name', 'label', 'description', 'sort_order', 'is_locked'];

    protected $casts = [
        'is_locked' => 'boolean',
        'sort_order' => 'integer',
    ];

    public function settings(): HasMany
    {
        return $this->hasMany(Setting::class, 'group_id');
    }

    /**
     * Locked groups cannot have settings added/removed via the admin UI.
     * They are managed through migrations and code only.
     */
    public function lock(): void
    {
        $this->update(['is_locked' => true]);
    }

    public function unlock(): void
    {
        if ($this->isSystemGroup()) {
            throw new \DomainException('System groups cannot be unlocked.');
        }
        $this->update(['is_locked' => false]);
    }

    private function isSystemGroup(): bool
    {
        return in_array($this->name, ['mail', 'auth', 'security']);
    }
}
```

### 8.3 Group Registration Service

```php
namespace App\Domains\Admin\Services;

final class SettingGroupService
{
    public function ensureGroup(string $name, string $label, string $description = ''): SettingGroup

        return SettingGroup::firstOrCreate(

                'label' => $label,

                'type' => $type,
                'is_encrypted' => $encrypted,
                'description' => "Auto-registered setting for {$group}.{$key}",
            ]
        );
    }
```

## 9. Encrypted Settings Deep Dive

### 9.1 Encryption Architecture

Encrypted settings use Laravel's `encrypted` cast which applies AES-256-CBC encryption at the model level. The encryption key comes from `APP_KEY`.

```php
namespace App\Domains\Admin\Models;

class Setting extends BaseModel
{
    protected function casts(): array
    {
        return [
            'value' => $this->is_encrypted ? 'encrypted:array' : 'array',
            'is_encrypted' => 'boolean',
        ];
    }
}
```

### 9.2 Encryption Workflow

```text
Write path:
1. Caller passes plaintext value to SettingsRepository::set()
2. Repository persists via Eloquent
3. Eloquent encrypts the value column before INSERT/UPDATE
4. Database stores ciphertext

Read path:
1. Caller invokes SettingsRepository::get()
2. Eloquent fetches ciphertext from database
3. Eloquent decrypts value column automatically
4. Repository returns plaintext to caller
```

### 9.3 Key Rotation

When `APP_KEY` rotates, encrypted settings must be re-encrypted:

```php
namespace App\Console\Commands;

use Illuminate\Console\Command;

final class ReEncryptSettings extends Command
{
    protected $signature = 'gsmui:settings:re-encrypt
        {--old-key= : The previous APP_KEY (if rotated)}';

    protected $description = 'Re-encrypt all encrypted settings with the current APP_KEY';

    public function handle(): int
    {
        $settings = Setting::where('is_encrypted', true)->get();
        $bar = $this->output->createProgressBar($settings->count());

        foreach ($settings as $setting) {
            // Force re-encryption by touching the value
            $currentValue = $setting->value;
            $setting->value = null;
            $setting->save();
            $setting->value = $currentValue;
            $setting->save();
            $bar->advance();
        }

        $bar->finish();
        $this->newLine();
        $this->info("Re-encrypted {$settings->count()} settings.");

        return self::SUCCESS;
    }
}
```

### 9.4 Security Rules for Encrypted Settings

```text
1. Never log decrypted values — use a LogRedactor trait
2. Never return encrypted settings in API responses
3. Never store secrets in non-encrypted rows
4. Never commit APP_KEY to version control
5. Rotate APP_KEY periodically; run re-encrypt command after rotation
6. Backup encrypted settings as ciphertext (not plaintext)
7. Access encrypted settings only through SettingsRepository::get()
```

## 10. Scope Resolution Deep Dive

### 10.1 Scope Precedence

When a scoped setting is requested, the resolution order is:

```text
1. Exact scope match (e.g., User:42 for the specific user)
2. Parent scope match (e.g., Team:5 if user belongs to team 5)
3. Global value (no scope)
4. Default value (caller-provided)
```

### 10.2 Scope Hierarchy

```php
namespace App\Domains\Admin\ValueObjects;

final readonly class SettingScope
{
    public function __construct(
        public string $type,
        public int $id,
    ) {}

    public static function forUser(int $userId): self
    {
        return new self(User::class, $userId);
    }

    public static function forTeam(int $teamId): self
    {
        return new self(Team::class, $teamId);
    }

    /**
     * Returns the parent scope if one exists.
     * User scopes resolve to their primary team scope.
     */
    public function parent(): ?self
    {
        return match ($this->type) {
            User::class => $this->resolveUserTeamScope(),
            Team::class => null, // Teams are top-level
            default => null,
        };
    }

    private function resolveUserTeamScope(): ?self
    {
        $user = User::find($this->id);
        if ($user && $user->team_id) {
            return self::forTeam($user->team_id);
        }
        return null;
    }
}
```

### 10.3 Scope Resolution with Caching

```php
private function resolveWithHierarchy(string $group, string $leaf, ?SettingScope $scope): mixed
{
    $setting = Setting::query()
        ->where('key', $leaf)
        ->whereRelation('group', 'name', $group)
        ->first();

    if ($setting === null) {
        return null;
    }

    // Check exact scope first
    if ($scope !== null) {
        $override = $this->findScope($setting, $scope);
        if ($override !== null) {
            return $override->value;
        }

        // Walk up the scope hierarchy
        $parentScope = $scope->parent();
        while ($parentScope !== null) {
            $override = $this->findScope($setting, $parentScope);
            if ($override !== null) {
                return $override->value;
            }
            $parentScope = $parentScope->parent();
        }
    }

    return $setting->value;
}

private function findScope(Setting $setting, SettingScope $scope): ?SettingScopeModel
{
    return $setting->scopes()
        ->where('scope_type', $scope->type)
        ->where('scope_id', $scope->id)
        ->first();
}
```

### 11.3 Bulk Write Implementation

```php
public function setMany(array $settings, ?SettingScope $scope = null): void
{
    DB::transaction(function () use ($settings, $scope) {
        foreach ($settings as $key => $value) {
            $this->set($key, $value, $scope);
        }
    });
}

public function import(array $dump, bool $overwrite = false): int
{
    $count = 0;

    DB::transaction(function () use ($dump, $overwrite, &$count) {
        foreach ($dump as $groupName => $groupSettings) {
            $group = $this->ensureGroup($groupName);

            foreach ($groupSettings as $key => $config) {
                $existing = Setting::where('group_id', $group->id)
                    ->where('key', $key)
                    ->first();

                if ($existing && !$overwrite) {
                    continue;
                }

                if ($existing) {
                    $existing->update([
                        'value' => $config['value'],
                        'type' => $config['type'] ?? $this->inferType($config['value']),
                        'is_encrypted' => $config['is_encrypted'] ?? false,
                    ]);
                } else {
                    Setting::create([
                        'group_id' => $group->id,
                        'key' => $key,
                        'value' => $config['value'],
                        'type' => $config['type'] ?? $this->inferType($config['value']),
                        'is_encrypted' => $config['is_encrypted'] ?? false,
                    ]);
                }

                $count++;
            }
        }
    });

    return $count;
}
```

## 12. Settings Validation

### 12.1 Type-Safe Setting Definitions

```php
namespace App\Domains\Admin\Enums;

enum SettingType: string
{
    case String = 'string';
    case Integer = 'integer';
    case Float = 'float';
    case Boolean = 'boolean';
    case Json = 'json';
    case Array = 'array';
    case DateTime = 'datetime';

    public function validate(mixed $value): bool
    {
        return match ($this) {
            self::String => is_string($value),
            self::Integer => is_int($value),
            self::Float => is_float($value) || is_int($value),
            self::Boolean => is_bool($value),
            self::Json => is_string($value) && json_decode($value) !== null,
            self::Array => is_array($value),
            self::DateTime => is_string($value) && strtotime($value) !== false,
        };
    }

    public function castValue(mixed $value): mixed
    {
        return match ($this) {
            self::String => (string) $value,
            self::Integer => (int) $value,
            self::Float => (float) $value,
            self::Boolean => (bool) $value,
            self::Json => is_string($value) ? $value : json_encode($value),
            self::Array => (array) $value,
            self::DateTime => (string) $value,
        };
    }
}
```

### 12.2 Settings Schema Registry

```php
namespace App\Domains\Admin\Services;

final class SettingsSchemaRegistry
{
    private const SCHEMA = [
        'mail.from_name' => ['type' => 'string', 'required' => true, 'max' => 255],
        'mail.from_address' => ['type' => 'string', 'required' => true, 'email' => true],
        'ui.pagination_size' => ['type' => 'integer', 'min' => 5, 'max' => 100, 'default' => 15],
        'auth.registration_enabled' => ['type' => 'boolean', 'default' => true],
        'auth.mfa_required' => ['type' => 'boolean', 'default' => false],
        'security.session_timeout' => ['type' => 'integer', 'min' => 300, 'max' => 86400, 'default' => 3600],
        'security.password_min_length' => ['type' => 'integer', 'min' => 6, 'max' => 128, 'default' => 8],
        'media.max_upload_size' => ['type' => 'integer', 'min' => 1, 'max' => 100, 'default' => 10],
        'search.engine' => ['type' => 'string', 'in' => ['meilisearch', 'algolia', 'database']],
        'billing.currency' => ['type' => 'string', 'in' => ['USD', 'EUR', 'GBP'], 'default' => 'USD'],
    ];

    public function validate(string $key, mixed $value): void
    {
        $definition = self::SCHEMA[$key] ?? null;

        if ($definition === null) {
            return; // No schema defined — allow any value
        }

        $type = SettingType::from($definition['type']);
        if (!$type->validate($value)) {
            throw new \InvalidArgumentException(
                "Setting '{$key}' expects {$definition['type']}, got " . get_debug_type($value)
            );
        }

        if (isset($definition['min']) && $value < $definition['min']) {
            throw new \InvalidArgumentException("Setting '{$key}' minimum is {$definition['min']}.");
        }

        if (isset($definition['max']) && $value > $definition['max']) {
            throw new \InvalidArgumentException("Setting '{$key}' maximum is {$definition['max']}.");
        }

        if (isset($definition['in']) && !in_array($value, $definition['in'], true)) {
            throw new \InvalidArgumentException(
                "Setting '{$key}' must be one of: " . implode(', ', $definition['in'])
            );
        }
    }
}
```

### 13.2 Controller Implementation

```php
namespace App\Http\Controllers\Api;

use App\Domains\Admin\Contracts\SettingsRepository;
use App\Domains\Admin\Models\SettingGroup;
use App\Http\Controllers\Controller;
use Illuminate\Http\JsonResponse;
use Illuminate\Http\Request;

final class SettingController extends Controller
{
    public function __construct(
        private readonly SettingsRepository $settings,
    ) {}

    public function groups(): JsonResponse
    {
        $groups = SettingGroup::withCount('settings')
            ->orderBy('sort_order')
            ->get();

        return response()->json($groups);
    }

    public function groupSettings(string $group): JsonResponse
    {
        $settings = $this->settings->all($group);

        return response()->json([
            'group' => $group,
            'settings' => $settings,
        ]);
    }

    public function updateGroupSettings(string $group, Request $request): JsonResponse
    {
        $validated = $request->validate([
            'settings' => 'required|array',
        ]);

        $this->settings->setMany($validated['settings']);

        return response()->json(['message' => 'Settings updated.']);
    }

    public function export(): JsonResponse
    {
        $all = SettingGroup::with('settings')->get()->keyBy('name');

        $export = [];
        foreach ($all as $group) {
            $export[$group->name] = $group->settings->mapWithKeys(fn ($s) => [
                $s->key => [
                    'value' => $s->is_encrypted ? '[encrypted]' : $s->value,
                    'type' => $s->type,
                    'is_encrypted' => $s->is_encrypted,
                ],
            ])->toArray();
        }

        return response()->json($export);
    }

    public function import(Request $request): JsonResponse
    {
        $validated = $request->validate([
            'settings' => 'required|array',
            'overwrite' => 'boolean',
        ]);

        $count = $this->settings->import(
            $validated['settings'],
            $validated['overwrite'] ?? false
        );

        return response()->json(['imported' => $count]);
    }
}
```

## 15. Settings Cache Invalidation

### 15.1 Invalidation Strategy

| Trigger | Scope | Method |
| --- | --- | --- |
| Single setting write | That setting key | `Cache::forget()` for the exact key |
| Group settings update | All keys in the group | Pattern-based invalidation |
| Scope change | That scope + setting | Invalidate both global and scoped keys |
| Bulk import | All groups in import | Batch invalidation |
| Deployment | All settings | `Cache::tags(['settings'])->flush()` |

### 15.2 Tag-Based Invalidation

For Redis with tag support:

```php
public function forget(string $group, string $leaf, ?SettingScope $scope): void
{
    $key = $this->cacheKey($group, $leaf, $scope);
    Cache::tags(['settings', "settings:{$group}"])->forget($key);
}

public function forgetGroup(string $group): void
{
    Cache::tags(["settings:{$group}"])->flush();
}

public function forgetAll(): void
{
    Cache::tags(['settings'])->flush();
}
```

### 15.3 Cross-Node Invalidation

```php
namespace App\Domains\Admin\Services;

use Illuminate\Support\Facades\Redis;

final class SettingsSyncService
{
    private const CHANNEL = 'gsmui:settings:invalidate';

    public function broadcastInvalidation(string $group, string $key): void
    {
        Redis::publish(self::CHANNEL, json_encode([
            'group' => $group,
            'key' => $key,
            'timestamp' => microtime(true),
        ]));
    }

    public function subscribe(): void
    {
        Redis::subscribe([self::CHANNEL], function (string $message) {
            $data = json_decode($message, true);
            $cacheKey = "setting:{$data['group']}.{$data['key']}:global";
            Cache::forget($cacheKey);
        });
    }
}
```

## 19. Operational Rules

1. Never query `settings` / `setting_scopes` directly — use `SettingsRepository::get()`.
2. Never store secrets in non-encrypted rows — always set `is_encrypted = true`.
3. Never cache the resolved value beyond the repository's own TTL.
4. Always validate setting values against the schema before persistence.
5. Always broadcast cache invalidations in multi-node deployments.
6. Settings changes should be audited via observers (see `07.47-observers.md`).
7. Encrypted settings should never appear in logs, API responses, or error messages.
8. Settings migrations should be idempotent — safe to re-run.
9. Scope hierarchy resolution should be cached independently from global values.
10. Bulk imports should be transactional — all-or-nothing.

## 30. Settings in Multi-Node Deployments

### 30.1 Cache Synchronization

In multi-server deployments, settings changes must propagate to all nodes:

```php
namespace App\Domains\Admin\Services;

use Illuminate\Support\Facades\Redis;

final class SettingsSyncService
{
    private const CHANNEL = 'gsmui:settings:invalidate';

    public function broadcastInvalidation(string $group, string $key): void
    {
        Redis::publish(self::CHANNEL, json_encode([
            'group' => $group,
            'key' => $key,
            'timestamp' => microtime(true),
            'server' => gethostname(),
        ]));
    }

    public function subscribe(): void
    {
        Redis::subscribe([self::CHANNEL], function (string $message) {
            $data = json_decode($message, true);

            // Skip messages from this server
            if ($data['server'] === gethostname()) {
                return;
            }

            $cacheKey = "setting:{$data['group']}.{$data['key']}:global";
            Cache::forget($cacheKey);
        });
    }
}
```

### 30.2 Deployment Integration

```bash
# After deploy, warm cache on all nodes
php artisan gsmui:settings:warm-cache

# Clear cache on all nodes (uses Redis broadcast)
php artisan gsmui:settings:clear-cache --broadcast
```

## 31. Operational Rules

1. Never query `settings` / `setting_scopes` directly — use `SettingsRepository::get()`.
2. Never store secrets in non-encrypted rows — always set `is_encrypted = true`.
3. Never cache the resolved value beyond the repository's own TTL.
4. Always validate setting values against the schema before persistence.
5. Always broadcast cache invalidations in multi-node deployments.
6. Settings changes should be audited via observers (see `07.47-observers.md`).
7. Encrypted settings should never appear in logs, API responses, or error messages.
8. Settings migrations should be idempotent — safe to re-run.
9. Scope hierarchy resolution should be cached independently from global values.
10. Bulk imports should be transactional — all-or-nothing.
11. Critical setting changes should notify admin team.
12. Settings used in queue jobs should be snapshotted at dispatch time.
