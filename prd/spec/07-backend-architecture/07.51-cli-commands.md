# 07.51 - CLI Commands

**Project:** GsmUi
**Architecture:** Command-Line Interface (Artisan)
**Framework:** Laravel 13 + Livewire 4
**Version:** 1.0.0

---

> See also: `05.37-cli-architecture.md` for the command taxonomy and the `gsmui:*` naming convention. This document is the *implementation contract*: the `Command` base shape, signature/argument/option conventions, `table()` output, idempotency, and how commands wire into the domain layer (see `07.08-action-layer.md`).

# Purpose

Artisan commands are the operator-facing surface for GsmUi: scaffolding, installs, cache/queue operations, and one-off maintenance or data tasks. They are also the unit the scheduler invokes (see `07.50-scheduler.md`). Commands must never contain business logic directly â€” they parse input, delegate to an `Action` or `Service`, and render output. This keeps behavior identical whether a use case is triggered by HTTP, Livewire, a job, or the CLI.

Goals:

- **Thin commands** â€” a command validates its arguments and calls an `Action`/`Service`; logic lives in the domain layer.
- **Idempotent maintenance** â€” cache clears, reindexes, and imports can be re-run safely (see `07.14-jobs.md` Â§1).
- **Consistent output** â€” use `info`/`warn`/`error` and `table()` for structured terminal output.
- **Safe registration** â€” commands are discovered by Laravel's `load()` or registered explicitly in a provider.

---

# 1. Command Structure

A command extends `Illuminate\Console\Command`, declares a `signature`, and implements `handle()`. It resolves domain services from the container.

```php
// app/Domains/Components/Console/GenerateComponent.php
declare(strict_types=1);

namespace App\Domains\Components\Console;

use App\Domains\Components\Actions\CreateComponentAction;
use App\Domains\Components\DTOs\ComponentData;
use Illuminate\Console\Command;

final class GenerateComponent extends Command
{
    protected $signature = 'gsmui:make:component
        {name : Human-readable component name}
        {--category= : Optional category slug}
        {--dry-run : Validate without persisting}';

    protected $description = 'Scaffold a new GsmUi component';

    public function handle(CreateComponentAction $action): int
    {
        $data = ComponentData::fromArray([
            'name'     => $this->argument('name'),
            'category' => $this->option('category'),
            'userId'   => null,
        ]);

        if ($this->option('dry-run')) {
            $this->info("Would create component: {$data->name}");

            return self::SUCCESS;
        }

        $component = $action->run($data);

        $this->table(
            ['Field', 'Value'],
            [
                ['id', $component->id],
                ['slug', $component->slug],
                ['status', $component->status->value],
            ]
        );

        return self::SUCCESS;
    }
}
```

# 2. Signature Conventions

Follow the `gsmui:<domain>:<verb>` namespace from `05.37-cli-architecture.md`:

| Pattern | Example | Purpose |
| --- | --- | --- |
| `gsmui:make:*` | `gsmui:make:component` | Scaffolding |
| `gsmui:theme:*` | `gsmui:theme:generate` | Theme tooling |
| `gsmui:cache:*` | `gsmui:cache:clear` | Cache/queue ops |
| `gsmui:queue:*` | `gsmui:queue:work` | Worker control |

- Required positional args: `{name}`.
- Optional flags: `{--dry-run}` (never `--no-*` negative forms).
- Prompt when interactive and missing: `{name?}` + `$this->ask()`.

---

# 3. Table & Output

Use `table()` for tabular results and `withProgressBar()` for bulk iterations:

```php
$rows = [];
foreach ($items as $item) {
    $rows[] = [$item->id, $item->slug];
}

$this->table(['ID', 'Slug'], $rows);

$this->withProgressBar($items, fn ($item) => $this->process($item));
$this->newLine();
```

Exit codes follow Symfony conventions: `SUCCESS` (0), `FAILURE` (1), `INVALID` (2). The scheduler (see `07.50-scheduler.md`) uses non-zero to trigger `onFailure`.

---

# 4. Idempotency

Maintenance commands must be safe to re-run. Use cache locks or unique constraints rather than destructive blind writes:

```php
public function handle(): int
{
    if (Cache::has('gsmui:reindex:running')) {
        $this->warn('Reindex already in progress.');

        return self::SUCCESS;
    }

    Cache::put('gsmui:reindex:running', true, 600);

    try {
        \App\Domains\Search\Jobs\SyncSearchIndex::dispatch()->onQueue('search');
    } finally {
        Cache::forget('gsmui:reindex:running');
    }

    $this->info('Dispatched search reindex.');

    return self::SUCCESS;
}
```

For destructive data commands, require a `--force` flag and print affected counts before acting (nuclear options are never default).

# 5. Registration

Laravel auto-discovers commands under `app/Console/Commands` and `app/Domains/**/Console` via the app `load()`. For explicit registration, list them in a provider:

```php
// app/Providers/ArtisanServiceProvider.php
use Illuminate\Support\ServiceProvider;

final class ArtisanServiceProvider extends ServiceProvider
{
    public function boot(): void
    {
        $this->commands([
            \App\Domains\Components\Console\GenerateComponent::class,
            \App\Domains\Themes\Console\GenerateTheme::class,
        ]);
    }
}
```

Register in `bootstrap/providers.php`. Avoid `app:name` and other destructive global commands in production entry points.

# 6. Operational Rules

1. Commands delegate to `Action`/`Service` â€” no inline DB writes.
2. Maintenance commands are idempotent; destructive ones require `--force`.
3. Use typed exit codes so the scheduler can detect failure.
4. Long work dispatches a job to the correct queue (see `07.49-queues.md` Â§3).
5. Secrets are never echoed; redact per `07.54-logging.md` Â§3.

### 8.1 Thin Command Pattern

### 8.2 Interactive Command Pattern

For commands that need user input:

```php
namespace App\Console\Commands;

use Illuminate\Console\Command;

final class ImportData extends Command
{
    protected $signature = 'gsmui:import
        {file? : Path to import file}
        {--type= : Import type (users, components, themes)}
        {--dry-run : Preview without importing}
        {--force : Skip confirmation}';

    public function handle(): int
    {
        $file = $this->argument('file') ?? $this->ask('Enter the import file path');
        $type = $this->option('type') ?? $this->choice('Import type', ['users', 'components', 'themes']);

        if (!file_exists($file)) {
            $this->error("File not found: {$file}");
            return self::FAILURE;
        }

        $rows = $this->countRows($file);
        $this->info("Found {$rows} records to import.");

        if (!$this->option('force') && !$this->confirm("Proceed with import?")) {
            $this->info('Import cancelled.');
            return self::SUCCESS;
        }

        if ($this->option('dry-run')) {
            $this->previewImport($file, $type);
            return self::SUCCESS;
        }

        $bar = $this->output->createProgressBar($rows);
        $bar->start();

        $imported = $this->processImport($file, $type, function () use ($bar) {
            $bar->advance();
        });

        $bar->finish();
        $this->newLine();
        $this->info("Imported {$imported} records.");

        return self::SUCCESS;
    }
}
```

### 8.3 Confirmation Patterns

```php
// Destructive operations require confirmation
if (!$this->confirm('This will DELETE all cached data. Continue?')) {
    return self::SUCCESS;
}

// Force flag bypasses confirmation
if (!$this->option('force') && !$this->confirm('Proceed?')) {
    return self::SUCCESS;
}

// Nuclear options always require --force
if (!$this->option('force')) {
    $this->error('This operation requires --force flag.');
    return self::FAILURE;
}
```

# 9. Command Output Standards

### 9.1 Output Methods

| Method | When to use | Example |
| --- | --- | --- |
| `$this->info()` | Success messages | `$this->info('Cache cleared.')` |
| `$this->warn()` | Warnings | `$this->warn('Deprecated feature.')` |

| Code | Constant | Meaning |

# 12. Operational Rules

1. Commands delegate to `Action`/`Service` â€” no inline DB writes.
2. Maintenance commands are idempotent; destructive ones require `--force`.
3. Use typed exit codes so the scheduler can detect failure.
4. Long work dispatches a job to the correct queue (see `07.49-queues.md` Â§3).
5. Secrets are never echoed; redact per `07.54-logging.md` Â§3.
6. Interactive commands validate input before processing.
7. Progress bars for operations > 5 items.
8. Table output for structured results > 1 row.
9. Dry-run option for commands that modify data.
10. Commands are registered in one place (provider or auto-discovery).
11. Exit code 0 for success, 1 for failure, 2 for invalid input.
12. Commands are tested in CI with `--no-interaction` flag.

# 14. Command Error Handling

### 14.1 Error Reporting

```php
final class ImportData extends Command
{
    public function handle(): int
    {
        try {
            $this->processImport();
            return self::SUCCESS;
        } catch (FileNotFoundException $e) {
            $this->error("File not found: {$e->getMessage()}");
            return self::FAILURE;
        } catch (ValidationException $e) {
            $this->error("Validation failed: {$e->getMessage()}");
            return self::INVALID;
        } catch (\Throwable $e) {
            report($e);
            $this->error("Unexpected error: {$e->getMessage()}");
            return self::FAILURE;
        }
    }
}
```

### 14.2 Exit Code Standards

| Code | Constant | Meaning | Scheduler behavior |
| --- | --- | --- | --- |
| 0 | `self::SUCCESS` | Completed | No failure notification |
| 1 | `self::FAILURE` | Failed | `onFailure` callback |
| 2 | `self::INVALID` | Invalid input | `onFailure` callback |

# 15. Command Security

### 15.1 Sensitive Data Handling

```php
final class ImportUsers extends Command
{
    public function handle(): int
    {
        // Read file contents
        $data = $this->readImportFile($this->argument('file'));

        // Log the operation (without sensitive data)
        Log::info('Import started', [
            'file' => $this->argument('file'),
            'rows' => count($data),
            // Do NOT log: $data (might contain passwords/PII)
        ]);

        foreach ($data as $row) {
            // Sanitize before processing
            $sanitized = $this->sanitizeRow($row);
            $this->importRow($sanitized);
        }

        return self::SUCCESS;
    }

    private function sanitizeRow(array $row): array
    {
        // Remove or redact sensitive fields from logs
        unset($row['password'], $row['ssn']);
        return $row;
    }
}
```

### 15.2 Authorization Checks

```php
final class DeleteUserData extends Command
```

# 21. Command Error Handling

### 21.1 Error Handling Patterns

```php
final class ImportData extends Command
{
    public function handle(): int
    {
        try {
            $this->validateInput();
            $this->processImport();
            return self::SUCCESS;
        } catch (FileNotFoundException $e) {
            $this->error("File not found: {$e->getMessage()}");
            return self::FAILURE;
```

# 22. Command Security

### 22.1 Sensitive Data Handling

```php
final class ImportUsers extends Command
{
    public function handle(): int
    {
        $data = $this->readImportFile($this->argument('file'));

        // Log operation without sensitive data
        Log::info('Import started', [
            'file' => $this->argument('file'),
```

```php
final class LargeImportCommand extends Command
{
    public function handle(): int
    {
        // Process in chunks to control memory
        $file = new \SplFileObject($this->argument('file'));

        $batch = [];
        $lineCount = 0;

        while (!$file->eof()) {
            $line = $file->fgetcsv();
            if (!$line) continue;

            $batch[] = $line;
            $lineCount++;

            if (count($batch) >= 500) {
                $this->processBatch($batch);
                $batch = [];

                // Force garbage collection
                gc_collect_cycles();
            }
        }

        // Process remaining
        if (!empty($batch)) {
            $this->processBatch($batch);
        }

        $this->info("Imported {$lineCount} rows.");
        return self::SUCCESS;
    }
}
```

# 37. Command Lifecycle

### 37.1 Lifecycle Phases

```text
1. Discovery: Laravel finds commands in Console/ directories
2. Registration: Commands registered via auto-discovery or provider
3. Signature Parsing: Artisan parses name, args, options
4. Validation: Required args checked, options validated
5. Resolution: Services resolved from container
6. Execution: handle() method called
7. Output: Results rendered to terminal
8. Exit: Return exit code (0, 1, 2)
```

### 37.2 Error Recovery

```php
final class ResilientCommand extends Command
{
    public function handle(): int
    {
        $checkpoint = new Checkpoint();

        try {
            $checkpoint->save();
            $this->performOperation();
            $checkpoint->complete();
            return self::SUCCESS;
        } catch (\Throwable $e) {
            $checkpoint->fail($e);
            report($e);
            $this->error("Operation failed: {$e->getMessage()}");
            return self::FAILURE;
        }
    }
}
```

# 39. Command Conventions Summary

1. Commands delegate to Action/Service â€” no inline DB writes.
2. Maintenance commands are idempotent; destructive ones require `--force`.
3. Use typed exit codes so the scheduler can detect failure.
4. Long work dispatches a job to the correct queue.
5. Secrets are never echoed; redact per logging conventions.
6. Interactive commands validate input before processing.
7. Progress bars for operations > 5 items.
8. Table output for structured results > 1 row.
9. Dry-run option for commands that modify data.
10. Commands are registered in one place.
11. Exit code 0 for success, 1 for failure, 2 for invalid input.
12. Commands are tested in CI with `--no-interaction` flag.
13. Help text covers all use cases.
14. Sensitive data is never logged or echoed.
15. Destructive commands require environment check + --force.
16. Rate limit destructive operations.
17. Log execution with duration.
18. Use aliases for common commands.
19. Process large datasets in chunks.
20. Force garbage collection between batches.

# 44. Command Conventions Extended

1. Use the shortest working signature.
2. Prefer --option over positional arguments.
3. Validate early, fail fast with clear messages.
4. Use table output for > 1 row.
5. Use bullet output for 1 row details.

7. Log command execution with duration.
8. Test commands in CI with --no-interaction.
9. Provide --dry-run for destructive operations.
10. Use --force to skip confirmation prompts.
11. Process large datasets in chunks.
12. Report failures to bugsnag.
13. Use progress bars for long operations.
14. Redact sensitive data in output.
15. Keep commands under 100 lines in handle().
16. Delegate business logic to actions/services.
17. Use typed properties over arrays.
18. Document command purpose in description.
19. Use consistent naming: verb-noun pattern.
