# 07.17 - Validation

**Project:** GsmUi
**Architecture:** Input Validation Pipeline
**Framework:** Laravel 13 + Livewire 4
**Version:** 1.0.0

---

# Purpose

Validation is the outermost guard of the backend. It runs before authorization (policies/gates, see `07.15-policies.md` / `07.16-gates.md`) and before any Action or Service is invoked (see `05.09-actions.md`). GsmUi standardizes on reusable, invokable custom rule objects and `prepareForValidation` normalization so validation logic is shared across HTTP controllers, Livewire components, and API endpoints without duplication.

This document specifies the validation pipeline position, the custom rule contract, request normalization via `prepareForValidation`, and localized message/attribute overrides. Form Request classes build on these primitives — see `07.18-form-requests.md`.

> See also: `07.09-dto-layer.md` (DTOs are constructed from already-validated input) and `07.11-enums.md` §11 (enum-based validation rules).

---

# 1. Pipeline Position

```text
Request
   │
   ▼
prepareForValidation  (normalize)
   │
   ▼
rules() / custom rules
   │
   ▼
Authorization (policy / gate)
   │
   ▼
Action ─▶ Service ─▶ Repository ─▶ DB
```

Validation assumes nothing about downstream layers and must reject malformed input at the edge.

# 2. Custom Rule Objects

Custom rules are invokable classes implementing `InvokableRule`. They live in the domain's `Rules/` directory.

```php
<?php

declare(strict_types=1);

namespace App\Domains\Components\Rules;

use Closure;
use Illuminate\Contracts\Validation\InvokableRule;

final class ValidComponentSlug implements InvokableRule
{
    public function __invoke(string $attribute, mixed $value, Closure $fail): void
    {
        if (! preg_match('/^[a-z][a-z0-9-]{2,39}$/', (string) $value)) {
            $fail('The :attribute must be 3–40 lowercase letters, numbers, or hyphens.');
        }
    }
}
```

# 3. prepareForValidation (normalization)

Normalize/transform input before rules run — trim, lowercase slugs, cast booleans, default missing keys.

```php
protected function prepareForValidation(): void
{
    $this->merge([
        'slug' => Str::slug($this->input('name') ?? $this->input('slug')),
        'visibility' => strtolower((string) $this->input('visibility', 'private')),
    ]);
}
```

This keeps rules simpler and prevents duplicate normalization inside Actions.

# 5. Conditional & Complex Rules

Use `Rule::when`, `excludeIf`, and `sometimes` for context-dependent validation:

```php
public function rules(): array
{
    return [
        'visibility' => ['required', Rule::in(ThemeVisibility::values())],
        'team_id' => ['sometimes', 'prohibited_unless:visibility,team', 'exists:teams,id'],
    ];
}
```

Enum-backed rules use `spatie/laravel-enum-rules` (see `07.11-enums.md` §11):

```php
'visibility' => [new \Spatie\LaravelEnumRules\Enum(ThemeVisibility::class)],
```

# 6. Usage in Controllers & Livewire

Controller:

```php
$validated = $request->validate([
    'slug' => ['required', 'string', new ValidComponentSlug(), 'unique:components,slug'],
    'visibility' => ['required', Rule::in(ThemeVisibility::values())],
]);
```

Livewire (uses the same rules via the `validate()` helper or a Form Request — see `07.18-form-requests.md`):

```php
public function save(): void
{
    $this->validate([
        'slug' => ['required', 'string', new ValidComponentSlug()],
    ]);

    // proceed to Action
}
```

# 9. Validation Decision Tree

```text
Should I use Validation?
┌─────────────────────────────────────────────────────────────────┐
│                                                                 │
│  Is this user input?                                            │
│  ├─ YES → Validate at the edge (Form Request / Livewire)       │
│  └─ NO  → Is this internal data?                               │
│            ├─ YES → No validation needed (already valid)        │
│            └─ NO  → Is this from an external source?           │
│                      ├─ YES → Validate at the edge             │
│                      └─ NO  → No validation needed             │
│                                                                 │
│  Validation runs BEFORE:                                        │
│  - Authorization (policies/gates)                               │
│  - Business logic (Actions/Services)                            │
│  - Database writes (Repositories)                               │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

# 11. Custom Rule Objects Extended

Custom rules are invokable classes implementing `InvokableRule`:

```php
<?php

declare(strict_types=1);

namespace App\Domains\Components\Rules;

use Closure;
use Illuminate\Contracts\Validation\InvokableRule;

final class ValidComponentSlug implements InvokableRule
{
    public function __invoke(string $attribute, mixed $value, Closure $fail): void
    {
        if (!preg_match('/^[a-z][a-z0-9-]{2,39}$/', (string) $value)) {
            $fail('The :attribute must be 3–40 lowercase letters, numbers, or hyphens.');
        }
    }
}
```

More custom rules:

```php
// ValidMoneyRule
final class ValidMoneyRule implements InvokableRule
{
    public function __invoke(string $attribute, mixed $value, Closure $fail): void
    {
        if (!is_numeric($value) || $value < 0) {
            $fail('The :attribute must be a valid monetary amount.');
        }
    }
}

// ValidThemeTokenRule
final class ValidThemeTokenRule implements InvokableRule
{
    public function __invoke(string $attribute, mixed $value, Closure $fail): void
    {
        if (!preg_match('/^--[a-z0-9-]+$/', (string) $value)) {
            $fail('The :attribute must be a valid CSS custom property name.');
        }
    }
}

// ValidVersionRule
final class ValidVersionRule implements InvokableRule
{
    public function __invoke(string $attribute, mixed $value, Closure $fail): void
    {
        if (!preg_match('/^\d+\.\d+\.\d+$/', (string) $value)) {
            $fail('The :attribute must be a valid semver version (e.g., 1.0.0).');
        }
    }
}

// ValidColorHexRule
final class ValidColorHexRule implements InvokableRule
{
    public function __invoke(string $attribute, mixed $value, Closure $fail): void
    {
        if (!preg_match('/^#([a-fA-F0-9]{3}|[a-fA-F0-9]{6}|[a-fA-F0-9]{8})$/', (string) $value)) {
            $fail('The :attribute must be a valid hex color (e.g., #fff or #0ea5e9).');
        }
    }
}
```

# 12. prepareForValidation Extended

Normalize/transform input before rules run:

```php
protected function prepareForValidation(): void
{
    $this->merge([
        // Auto-generate slug from name
        'slug' => Str::slug($this->input('name') ?? $this->input('slug')),

        // Normalize visibility
        'visibility' => strtolower((string) $this->input('visibility', 'private')),

        // Cast boolean
        'is_public' => filter_var($this->input('is_public', false), FILTER_VALIDATE_BOOLEAN),

        // Default values
        'currency' => $this->input('currency', 'USD'),

        // Trim whitespace
        'name' => trim((string) $this->input('name', '')),

        // Lowercase email
        'email' => strtolower(trim((string) $this->input('email', ''))),
    ]);
}
```

Normalization patterns:

| Pattern | Example | Use Case |
| --- | --- | --- |
| Auto-generate slug | `Str::slug($name)` | Component slug |
| Normalize case | `strtolower()` | Email, visibility |
| Cast boolean | `filter_var()` | Boolean fields |
| Default values | `$this->input('currency', 'USD')` | Optional fields |
| Trim whitespace | `trim()` | String fields |
| Remove HTML | `strip_tags()` | Rich text |
| Sanitize input | `preg_replace()` | User input |

# 14. Conditional & Complex Rules Extended

```php
public function rules(): array
{
    return [
        // Required with enum
        'visibility' => ['required', Rule::in(ThemeVisibility::values())],

        // Conditional required
        'team_id' => ['sometimes', 'prohibited_unless:visibility,team', 'exists:teams,id'],

        // Conditional validation
        'price' => Rule::when($this->input('type') === 'paid', ['required', 'numeric', 'min:0']),

        // Array validation
        'tags' => ['sometimes', 'array', 'max:10'],
        'tags.*' => ['string', 'max:50'],

        // Nested object validation
        'metadata' => ['sometimes', 'array'],
        'metadata.title' => ['required_with:metadata', 'string', 'max:255'],
        'metadata.description' => ['sometimes', 'string', 'max:1000'],

        // Date validation
        'published_at' => ['sometimes', 'date', 'after:now'],

        // File validation
        'avatar' => ['sometimes', 'image', 'max:2048', 'mimes:jpg,png,webp'],
    ];
}
```

Conditional rules:

| Pattern | Example | Use Case |
| --- | --- | --- |
| `Rule::when()` | `Rule::when($cond, [...])` | Conditional rules |
| `sometimes` | `'field' => ['sometimes', ...]` | Optional field |
| `required_with` | `'price' => 'required_with:type'` | Required if present |
| `prohibited_unless` | `'team_id' => 'prohibited_unless:visibility,team'` | Prohibited unless |
| `unique` | `'slug' => 'unique:components,slug'` | Uniqueness check |
| `exists` | `'team_id' => 'exists:teams,id'` | Foreign key check |

# 15. Usage in Controllers Extended

```php
class ComponentController extends Controller
{
    public function store(StoreComponentRequest $request)
    {
        // Validation already passed in FormRequest
        $validated = $request->validated();

        $action = app(CreateComponentAction::class);
        $component = $action->run(new CreateComponentData(
            name: $validated['name'],
            slug: ComponentSlug::fromString($validated['slug']),
            userId: auth()->id(),
        ));

        return redirect()->route('components.show', $component);
    }

    public function update(UpdateComponentRequest $request, Component $component)
    {
        $validated = $request->validated();

        $action = app(UpdateComponentAction::class);
        $action->run(new UpdateComponentData(
            componentId: $component->id,
            name: $validated['name'],
            slug: ComponentSlug::fromString($validated['slug']),
        ));

        return redirect()->route('components.show', $component);
    }
}
```

class ComponentCreate extends Component
{
    public string $name = '';
    public string $slug = '';
    public string $visibility = 'private';

    {

            'name' => ['required', 'string', 'max:255'],

            userId: auth()->id(),
        ));

        return redirect()->route('components.show', $component);
    }

    public function updatedName(): void
    {
        $this->slug = Str::slug($this->name);
    }
}

# 18. Validation Anti-Patterns

| Anti-pattern | Why it's bad | Correct approach |
| --- | --- | --- |
| Validation in Action | Bypasses validation layer | Use Form Request |
| Validation in Service | Bypasses validation layer | Use Form Request |
| Missing `prepareForValidation` | Duplicate normalization | Normalize in prepareForValidation |
| Hardcoded error messages | Not localizable | Use `__()` or lang files |
| Missing unique check | Duplicate data | Use `unique` rule |
| Missing exists check | Invalid foreign key | Use `exists` rule |
| Validation in model | Bypasses validation layer | Use Form Request |
| Missing file validation | Security risk | Use `image`, `mimes`, `max` |

# 19. Validation Security Matrix

| Security Concern | Mitigation |
| --- | --- |
| SQL injection | Use parameterized queries |
| XSS | Sanitize input, escape output |
| File upload attacks | Validate file type, size |
| Mass assignment | Use `$fillable` or `$guarded` |
| CSRF | Use CSRF token |
| Rate limiting | Throttle requests |
| Input length | Use `max` rule |
| Required fields | Use `required` rule |

# 29. Validation Summary

Validation is the outermost guard of the backend in GsmUi. It runs before authorization and business logic, ensuring that only valid data enters the domain. Custom rule objects and `prepareForValidation` normalization provide reusable, testable validation that works across HTTP controllers, Livewire components, and API endpoints.

| --- | --- | --- | --- |

            'metadata' => 'nullable|array',
        ];
    }

    public function withValidator($validator): void
    {
        $validator->after(function ($validator) {
            if ($this->input('amount') && $this->input('currency')) {
                $minAmount = config("payments.min_amount.{$this->input('currency')}", 0.50);

                if ($this->input('amount') < $minAmount) {
                    $validator->errors()->add(
                        'amount',
                        "The minimum amount for {$this->input('currency')} is {$minAmount}."
                    );
                }
            }
        });
    }
}

class NotificationPreferencesRequest extends FormRequest

    public function rules(): array

                    $validator->errors()->add(
                        'quiet_hours_end',
                        'Quiet hours must be at least 1 hour.'
                    );
                }
            }
        });
    }

# 65. Validation Testing Matrix

| Test Type | What to Test | Example |
| --- | --- | --- |
| Required test | Missing required field | `['name' => null]` fails |
| Format test | Invalid format | `['email' => 'invalid']` fails |
| Size test | Too large | `['name' => str_repeat('a', 256)]` fails |
| Custom test | Custom rule fails | `['slug' => 'existing']` fails |
| Normalize test | prepareForValidation normalizes | `['name' => '  John  ']` becomes `['name' => 'John']` |
| Localized test | Error message in language | `['email' => 'invalid']` with `locale=ar` shows Arabic message |
| Conditional test | Conditional rule applies | `['type' => 'manual', 'amount' => null]` passes |
| Array test | Nested array validation | `['items' => [['name' => '']]]` fails |
| File test | Invalid file | `['file' => 'test.txt']` fails |
| Date test | Invalid date format | `['date' => 'invalid']` fails |
| Boolean test | Invalid boolean | `['active' => 'maybe']` fails |
| Numeric test | Invalid numeric | `['price' => 'abc']` fails |
| URL test | Invalid URL | `['url' => 'not-a-url']` fails |
| Max length test | Exceeds max length | `['name' => str_repeat('a', 256)]` fails |
| Min value test | Below minimum | `['price' => -1]` fails |

# 66. Validation Anti-Patterns

| Anti-Pattern | Problem | Solution |
| --- | --- | --- |
| Missing `required` | Accepts null | Add `required` to mandatory fields |
| Only `sometimes` | Validation skipped | Use `required` unless truly optional |
| Ignoring `prepareForValidation` | Normalization skipped | Call parent method |
| Duplicating rules | Maintenance burden | Create custom rule |
| Ignoring localization | English-only errors | Use `__()` in rules |
| Not handling files | File validation skipped | Add file validation |
| Ignoring nested data | Nested array not validated | Validate nested fields |
| Not testing validation | Untested paths | Test every rule |

# 68. Validation Summary Extended

Validation is the outermost guard of the backend in GsmUi. It runs before authorization and business logic, ensuring that only valid data enters the domain. Custom rule objects and `prepareForValidation` normalization provide reusable, testable validation that works across HTTP controllers, Livewire components, and API endpoints.

Key benefits:

| Benefit | Description |
| --- | --- |
| Security | Prevents invalid data from entering domain |
| Data integrity | Ensures data matches expected format |
| Reusability | Custom rules work across controllers |
| Testability | Easy to test all validation paths |
| Maintainability | Centralized validation logic |
| Localization | Error messages are translatable |
| Performance | Fast validation at the edge |
| Audit trail | Log validation attempts |
| Caching | Cache expensive checks |
| Rate limiting | Prevent abuse |
