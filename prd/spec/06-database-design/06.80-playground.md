# 06.80 - Playground

**Project:** GsmUi
**Domain:** Playground
**Version:** 1.0.0

# Purpose

This document defines the database schema for the Playground domain — a live, sandboxed environment where users build interactive GsmUi component previews. A *project* is a saved workspace containing editor code, an optional theme, and an optional component reference. Projects can be private, shared publicly, or forked from another project. *Snapshots* are named checkpoints of a project's code captured over time to provide version history.

# Tables

## playground_projects

**Purpose:** Saved interactive playground projects. Users build live component previews.

**Business Rules:**

- A project belongs to exactly one user (`user_id` required); optionally to a team (`team_id` nullable).
- A project can be forked from another via `parent_id` (self-reference, nullable); the fork is otherwise independent.
- `slug` is unique and URL-friendly; used for public sharing links.
- `status` transitions: `draft` → `published` → `archived`.
- `is_public` controls gallery discoverability; `is_featured` is an editorial flag.
- `fork_count` / `view_count` are denormalized counters maintained by app logic.
- `theme_id` / `component_id` reference optional preview context (nullable).
- Soft-deletable.

## playground_snapshots

**Purpose:** Named snapshots/checkpoints of a playground project for version history.

**Business Rules:**

- Every snapshot belongs to one project (`playground_project_id` required) and is created by a user (`created_by` required).
- Snapshots are immutable historical checkpoints; `code` is captured at creation and not edited afterward.
- Soft-deletable.

**Columns:**

| Column | Type | Nullable | Default | Notes |
|---|---|---|---|---|
| id | BIGINT UNSIGNED | NO | AUTO_INCREMENT | PK |
| playground_project_id | BIGINT UNSIGNED | NO | — | FK → playground_projects.id |
| name | VARCHAR(255) | NO | — | Snapshot label |
| code | LONGTEXT | NO | — | Captured editor content |
| description | TEXT | YES | NULL | Snapshot notes |
| created_by | BIGINT UNSIGNED | NO | — | FK → users.id |
| created_at | DATETIME(3) | NO | CURRENT_TIMESTAMP(3) | |
| updated_at | DATETIME(3) | NO | CURRENT_TIMESTAMP(3) | ON UPDATE |
| deleted_at | DATETIME(3) | YES | NULL | Soft delete |

**Indexes:**

# Cross-Domain Relationships

- **playground_projects → users**: ownership; cascade to projects and snapshots on user delete.
- **playground_projects → teams**: optional team ownership (`team_id` nullable, `nullOnDelete`).
- **playground_projects → playground_projects (self)**: fork lineage via `parent_id` (`nullOnDelete` keeps forks intact).
- **playground_projects → themes / components**: optional preview context (`nullOnDelete`).
- **playground_projects → playground_snapshots**: one-to-many version history (cascade).

## Advanced Query Patterns

### Complex Playground Analytics

```php
// Project engagement metrics
$engagement = PlaygroundProject::selectRaw('
    pp.id,
    pp.name,
    pp.slug,
    pp.view_count,
    pp.fork_count,
    (pp.view_count + pp.fork_count * 10) as engagement_score,
    (SELECT COUNT(*) FROM playground_snapshots WHERE playground_project_id = pp.id AND deleted_at IS NULL) as snapshots_count,
    DATEDIFF(NOW(), pp.created_at) as days_old,
    ROUND(pp.view_count / NULLIF(DATEDIFF(NOW(), pp.created_at), 0), 2) as views_per_day
')
->where('pp.is_public', TRUE)
->where('pp.status', 'published')
->orderByDesc('engagement_score')
->limit(20)
->get();

// Fork lineage analysis
$forkLineage = PlaygroundProject::selectRaw('
    pp.id,
    pp.name,
    pp.parent_id,
    pp.fork_count,
    (SELECT COUNT(*) FROM playground_projects WHERE parent_id = pp.id AND deleted_at IS NULL) as direct_forks,
    (SELECT COUNT(*) FROM playground_projects WHERE parent_id = pp.id AND deleted_at IS NULL) as total_descendants
')
->where('pp.fork_count', '>', 0)
->orderByDesc('pp.fork_count')
->get();

// User productivity metrics
$productivity = PlaygroundProject::selectRaw('
    u.name,
    COUNT(pp.id) as project_count,
    SUM(pp.view_count) as total_views,
    SUM(pp.fork_count) as total_forks,
    AVG(pp.view_count) as avg_views,
    MAX(pp.created_at) as last_project_at
')
->join('users as u', 'pp.user_id', '=', 'u.id')
->where('pp.deleted_at', NULL)
->groupBy('pp.user_id', 'u.name')
->orderByDesc('total_views')
->get();
```

```php
// Playground health score
$health = PlaygroundProject::selectRaw('
```

## Stored Procedures

### sp_create_playground_project

```sql
DELIMITER //
CREATE PROCEDURE sp_create_playground_project(
  IN p_user_id BIGINT,
  IN p_name VARCHAR(255),
  IN p_slug VARCHAR(255),
  IN p_description TEXT,
  IN p_code LONGTEXT,
  IN p_theme_id BIGINT,
  IN p_component_id BIGINT,
  OUT p_project_id BIGINT,
  OUT p_status VARCHAR(50)
)
BEGIN
  DECLARE v_existing_slug INT;

  -- Check slug uniqueness
  SELECT COUNT(*) INTO v_existing_slug
  FROM playground_projects
  WHERE slug = p_slug AND deleted_at IS NULL;

  IF v_existing_slug > 0 THEN
    SET p_status = 'slug_taken';
  ELSE
    INSERT INTO playground_projects (
      user_id, name, slug, description, code, theme_id, component_id,
      is_public, is_featured, fork_count, view_count, status,
      created_at, updated_at
    ) VALUES (
      p_user_id, p_name, p_slug, p_description, p_code, p_theme_id, p_component_id,
      FALSE, FALSE, 0, 0, 'draft', NOW(), NOW()
    );

    SET p_project_id = LAST_INSERT_ID();
    SET p_status = 'created';
  END IF;
END //
DELIMITER ;
```

### sp_fork_playground_project

```sql
DELIMITER //
CREATE PROCEDURE sp_fork_playground_project(
  IN p_original_id BIGINT,
  IN p_forker_id BIGINT,
  OUT p_fork_id BIGINT,
  OUT p_status VARCHAR(50)
)
BEGIN
  DECLARE v_original_status VARCHAR(20);
  DECLARE v_original_name VARCHAR(255);
  DECLARE v_original_slug VARCHAR(255);
  DECLARE v_original_description TEXT;
  DECLARE v_original_code LONGTEXT;
  DECLARE v_original_theme_id BIGINT;
  DECLARE v_original_component_id BIGINT;
  DECLARE v_new_slug VARCHAR(255);
  DECLARE v_slug_suffix INT DEFAULT 0;

  -- Check original project
  SELECT status, name, slug, description, code, theme_id, component_id
  INTO v_original_status, v_original_name, v_original_slug, v_original_description,
       v_original_code, v_original_theme_id, v_original_component_id
  FROM playground_projects
  WHERE id = p_original_id AND deleted_at IS NULL;

  IF v_original_status IS NULL THEN
    SET p_status = 'project_not_found';
  ELSEIF v_original_status != 'published' THEN
    SET p_status = 'project_not_published';
  ELSE
    -- Generate unique slug
    SET v_new_slug = CONCAT(v_original_slug, '-fork');
    SELECT COUNT(*) INTO v_slug_suffix
    FROM playground_projects WHERE slug = v_new_slug AND deleted_at IS NULL;

    WHILE v_slug_suffix > 0 DO
      SET v_new_slug = CONCAT(v_original_slug, '-fork-', v_slug_suffix);
      SELECT COUNT(*) INTO v_slug_suffix
      FROM playground_projects WHERE slug = v_new_slug AND deleted_at IS NULL;
    END WHILE;

    -- Create fork
    INSERT INTO playground_projects (
      user_id, parent_id, name, slug, description, code, theme_id, component_id,
      is_public, is_featured, fork_count, view_count, status,
      created_at, updated_at
    ) VALUES (
      p_forker_id, p_original_id, CONCAT(v_original_name, ' (fork)'), v_new_slug,
      v_original_description, v_original_code, v_original_theme_id, v_original_component_id,
      FALSE, FALSE, 0, 0, 'draft', NOW(), NOW()
    );

    SET p_fork_id = LAST_INSERT_ID();

    -- Increment fork count on original
    UPDATE playground_projects
    SET fork_count = fork_count + 1, updated_at = NOW()
    WHERE id = p_original_id;

    SET p_status = 'forked';
  END IF;
END //
DELIMITER ;
```

### sp_create_snapshot

```sql
DELIMITER //
CREATE PROCEDURE sp_create_snapshot(
  IN p_project_id BIGINT,
  IN p_name VARCHAR(255),
  IN p_description TEXT,
  IN p_created_by BIGINT,
  OUT p_snapshot_id BIGINT,
  OUT p_status VARCHAR(50)
)
BEGIN
  DECLARE v_code LONGTEXT;
  DECLARE v_snapshot_count INT;
  DECLARE v_max_snapshots INT;

  -- Get current code
  SELECT code INTO v_code
  FROM playground_projects
  WHERE id = p_project_id AND deleted_at IS NULL;

  IF v_code IS NULL THEN
    SET p_status = 'project_not_found';
  ELSE
    -- Check snapshot limit (tier-based, simplified)
    SELECT COUNT(*) INTO v_snapshot_count
    FROM playground_snapshots
    WHERE playground_project_id = p_project_id AND deleted_at IS NULL;

    SET v_max_snapshots = 25; -- Pro tier default

    IF v_snapshot_count >= v_max_snapshots THEN
      SET p_status = 'snapshot_limit_reached';
    ELSE
      INSERT INTO playground_snapshots (
        playground_project_id, name, code, description, created_by,
        created_at, updated_at
      ) VALUES (
        p_project_id, p_name, v_code, p_description, p_created_by,
        NOW(), NOW()
      );

      SET p_snapshot_id = LAST_INSERT_ID();
      SET p_status = 'created';
    END IF;
  END IF;
END //
DELIMITER ;
```

```sql
DELIMITER //
CREATE TRIGGER trg_playground_projects_before_update
BEFORE UPDATE ON playground_projects
FOR EACH ROW
BEGIN
  -- Validate slug format
  IF NEW.slug NOT REGEXP '^[a-z0-9-]+$' THEN
    SIGNAL SQLSTATE '45000' SET MESSAGE_TEXT = 'Slug must contain only lowercase letters, numbers, and hyphens';
  END IF;

  -- Ensure view_count never goes negative
  IF NEW.view_count < 0 THEN
    SET NEW.view_count = 0;
  END IF;

  -- Ensure fork_count never goes negative
  IF NEW.fork_count < 0 THEN
    SET NEW.fork_count = 0;
  END IF;
END //
DELIMITER ;
```

```sql
      FROM playground_projects
```

## Detailed Business Rules

### Project Lifecycle

**Project State Transitions:**
```
draft → published → archived
  ↑         ↓
  └─── unarchive (if archived)
```

**Creation Rules:**
- Any authenticated user can create a project
- `user_id` is set to the creating user's ID
- `slug` is auto-generated from `name` (lowercase, hyphenated, URL-safe)
- Slug uniqueness is enforced globally (not per-user)
- Default status is `draft`
- Default `is_public = false` — projects are private until explicitly published
- `code` field stores the full editor content (HTML/CSS/JS mixed)

**Publishing Rules:**
- Status transition: `draft` → `published`
- A project must have non-empty `code` before publishing
- Publishing fires `PlaygroundProjectPublished` event
- Published projects appear in the public gallery (if `is_public = true`)
- URL pattern: `/playground/{slug}`

**Archiving Rules:**
- Status transition: `published` → `archived`
- Archived projects are hidden from gallery but accessible via direct URL
- Archived projects are read-only (no code edits)
- Archiving fires `PlaygroundProjectArchived` event

### Forking

**Fork Mechanics:**
```
1. User clicks "Fork" on a published project
2. System creates new project with parent_id = original project ID
3. New project copies: name (with " (fork)" suffix), code, description
4. New project: user_id = forking user, status = 'draft', is_public = false
5. Original project: fork_count incremented atomically
6. Fork event fired
```

**Fork Rules:**
- Only published projects can be forked
- Forking creates an independent copy — changes to the fork don't affect the original
- `parent_id` is set to the original project's ID (self-reference)
- Fork chain depth is unlimited (fork of a fork of a fork...)
- `fork_count` on the original project is denormalized for display

**Fork Attribution:**
- Forked projects display "Forked from {original_name}" in the UI
- Original project link is preserved via `parent_id`
- Fork chain is traceable via parent relationships

### View Counting

**View Count Rules:**
- `view_count` is incremented on each unique page load
- Deduplication: same user + same project = 1 view per 24 hours
- IP-based deduplication for anonymous views
- Count is atomic (`DB::raw('view_count + 1')`)
- Count is denormalized — not实时 accurate but acceptable for display

### Theme and Component References

**Theme Reference:**
- `theme_id` is optional — links to a theme for preview styling
- When set, the playground preview renders with the specified theme's CSS variables
- Theme deletion: `nullOnDelete` — project retains code but loses theme reference

**Component Reference:**
- `component_id` is optional — links to a component for documentation context
- When set, the playground shows component documentation alongside the editor
- Component deletion: `nullOnDelete` — project retains code but loses component reference

### Metadata

**JSON Metadata Structure:**
```json
{
  "seo": {
    "title": "Custom page title",
    "description": "Custom meta description",
    "og_image": "https://..."
  },
  "custom": {
    "tags": ["animation", "gsap"],
    "difficulty": "advanced",
    " estimated_time": "30 minutes"
  }
}
```

**Metadata Rules:**
- Optional — NULL is valid
- Maximum 10KB JSON size
- SEO fields used for Open Graph / Twitter Card rendering
- Custom fields used for gallery filtering and display

## Snapshot Management

### Snapshot Creation

**Creation Flow:**
```
1. User clicks "Save Snapshot" in playground
2. User enters: name (required), description (optional)
3. System captures current code from playground_projects.code
4. System creates snapshot record with code copy
5. Snapshot is immutable — code cannot be edited after creation
```

**Snapshot Rules:**
- Every snapshot belongs to exactly one project
- `created_by` records who created the snapshot (may differ from project owner)
- `code` is a full copy of the project's code at snapshot time
- Snapshots are soft-deletable (can be restored)

**Naming Rules:**
- Snapshot name is required (e.g., "Before refactoring", "v1.0 release")
- Names are not unique per project (multiple snapshots can have the same name)
- Auto-generated names: "Snapshot 1", "Snapshot 2", etc.

### Snapshot Limits

| Tier | Max Snapshots per Project |
|------|--------------------------|
| Free | 5 |
| Pro | 25 |
| Business | 100 |
| Enterprise | Unlimited |

**Enforcement:**
- Checked at snapshot creation time
- If limit reached, return HTTP 403 with `snapshot_limit_reached` error
- Oldest snapshots can be deleted to make room

### Snapshot Restoration

**Restoration Flow:**
```
1. User selects a snapshot to restore
2. System prompts: "This will replace current code. Create a snapshot first?"
3. If user confirms:
   a. Optionally create a snapshot of current code (auto-named "Before restore")
   b. Copy snapshot.code to playground_projects.code
   c. Update playground_projects.updated_at
   d. Fire PlaygroundProjectRestored event
```

- User deletion: anonymize user_id on projects and snapshots
- Code content: retain for fork lineage; anonymize on user deletion

### Project Factory

```php
class PlaygroundProjectFactory extends Factory

    protected $model = PlaygroundProject::class;

    {

    {
```

## Counter Reconciliation

`view_count` and `fork_count` are denormalized for hot-path reads. A nightly
job reconciles them against source-of-truth counts to correct drift from
skipped increments or cache races.

```php
// playground:sync-counters
PlaygroundProject::chunkById(500, function ($projects) {
    $viewCounts = AnalyticsPageView::whereIn('playground_project_id', $projects->pluck('id'))
        ->selectRaw('playground_project_id, COUNT(*) AS c')
        ->groupBy('playground_project_id')
        ->pluck('c', 'playground_project_id');

    $forkCounts = PlaygroundProject::whereIn('forked_from_id', $projects->pluck('id'))
        ->selectRaw('forked_from_id, COUNT(*) AS c')
        ->groupBy('forked_from_id')
        ->pluck('c', 'forked_from_id');

    foreach ($projects as $project) {
        $project->updateQuietly([
            'view_count' => $viewCounts[$project->id] ?? 0,
            'fork_count' => $forkCounts[$project->id] ?? 0,
        ]);
    }
});
```

Schedule:

```php
Schedule::command('playground:sync-counters')->daily()->lowPriority();
```

## Data Retention

| Table | Retention | Action |
|---|---|---|
| `playground_projects` | Indefinite while owned | Cascades with user deletion |
| `playground_snapshots` | 20 per project cap | Oldest pruned by `playground:prune-snapshots` |
| Orphaned public forks | 90 days after owner deletion | Re-owned to system account or deleted |

### Snapshot Pruning

```php
// playground:prune-snapshots --keep=20
PlaygroundProject::withCount('snapshots')->having('snapshots_count', '>', 20)
    ->chunkById(200, function ($projects) use ($keep) {
        foreach ($projects as $project) {
            $project->snapshots()
                ->orderByDesc('created_at')
                ->offset($keep)
                ->get()
                ->each->delete();
        }
    });
```

## Backup and Recovery

**Scenario: Accidental snapshot deletion**

Snapshots are hard-deleted (no soft delete), so recovery requires backup:

```sql
-- Restore from the most recent daily backup
mysql gsmui < /backups/playground_snapshots_20240630.sql;

-- Verify project's snapshot count
SELECT project_id, COUNT(*) FROM playground_snapshots
WHERE project_id = 42 GROUP BY project_id;
```

**Scenario: Fork chain corruption**

```sql
-- Find projects pointing at nonexistent parents
SELECT p.id, p.name, p.forked_from_id
FROM playground_projects p
LEFT JOIN playground_projects parent ON parent.id = p.forked_from_id
WHERE p.forked_from_id IS NOT NULL AND parent.id IS NULL;

-- Repair: null the dangling reference
UPDATE playground_projects
SET forked_from_id = NULL
WHERE forked_from_id IN (/* ids from above */);
```

Note: the fork repair preserves `fork_count` drift until the next nightly
reconciliation pass corrects the counters automatically.
