# 06.04 - Relationships

**Project:** GsmUi
**Domain:** Database Design - Foundation
**Version:** 1.0.0

---

# Purpose

This document defines the relationship patterns, cascade behaviors, and cardinality rules used across all GsmUi tables. Domain documents reference these patterns rather than redefining them.

---

# 1. Relationship Cardinality

All relationships fall into these categories:

```
One-to-Many    (1:N)   — User hasMany Orders
Many-to-Many   (N:M)   — Products belongToMany Tags
One-to-One     (1:1)   — User hasOne Profile
Polymorphic    (morphTo / morphMany) — Orders belongTo Billable (User or Team)
Hierarchical   (1:N self) — CMS menu items belongTo parent menu item
```

---

# 2. One-to-Many (1:N)

The most common relationship. Foreign key lives on the "many" side.

```
users 1 ──* orders
users 1 ──* products
users 1 ──* content_entries
teams 1 ──* team_members
products 1 ──* product_versions
components 1 ──* component_variants
themes 1 ──* theme_tokens
templates 1 ──* template_files
```

**Cascade behavior:** `ON DELETE CASCADE` on the foreign key. When the parent is deleted, children are deleted. This applies to all 1:N relationships except financial records.

**Exception — financial records:** Subscriptions, invoices, payments, and audit logs use `ON DELETE RESTRICT` or `ON DELETE SET NULL` to preserve historical records when a user or team is deleted. Financial records are never cascade-deleted.

---

# 3. Many-to-Many (N:M)

Implemented via pivot tables. Pivot table naming: alphabetical order of the two tables, e.g., `component_tag`, `theme_token_group`, `coupon_product`.

```
components <*─> tags        (component_tag pivot)
products   <*─> categories  (product_category pivot)
products   <*─> tags        (product_tag pivot)
roles      <*─> permissions (role_permission pivot)
users      <*─> roles       (user_role pivot)
teams      <*─> users       (team_members — carries role data, technically 1:N with extras)
```

Pivot tables with additional data beyond the two foreign keys follow the singular-noun pattern:
- `order_items` (carries quantity, price)
- `subscription_items` (carries plan_id, quantity)
- `invoice_lines` (carries amount, description)
- `coupon_redemptions` (carries user_id, redeemed_at)
- `coupon_products` (carries discount_type, discount_value)

---

# 4. One-to-One (1:1)

Used for profile data that is conceptually separate from the core entity.

```
users 1 ──1 user_profiles
users 1 ──1 user_preferences
users 1 ──1 two_factor_auth
```

**Cascade behavior:** `ON DELETE CASCADE`. Profile and preference data is deleted when the user is deleted.

---

# 5. Polymorphic (morphTo / morphMany)

Billing tables support both individual users and team workspaces as billable entities.

```
orders        belongsTo  billable (User | Team)
subscriptions belongsTo billable (User | Team)
invoices      belongsTo  billable (User | Team)
```

Implementation uses `billable_type` (string) and `billable_id` (bigint). No database foreign key constraint. Application layer validates via `morphTo`.

---

# 6. Hierarchical (Self-Referencing 1:N)

CMS menus and similar tree structures use `parent_id`.

```
cms_menu_items parent_id → cms_menu_items.id
```

`parent_id` is nullable (root items have no parent). `ON DELETE SET NULL` — when a parent is deleted, children become root items (or are soft-deleted if the parent was soft-deleted).

---

# 7. Cascade Behavior Summary

| Relationship Type | On Delete Behavior | Rationale |
|---|---|---|
| 1:N (user → orders) | CASCADE | Business data lives with owner |
| 1:N (product → versions) | CASCADE | Versions are product data |
| 1:N (financial) | RESTRICT / SET NULL | Preserve audit trail |
| 1:1 (user → profile) | CASCADE | Profile is user data |
| N:M pivot (pure) | CASCADE | Pivot has no independent existence |
| N:M pivot (with data) | CASCADE | Data belongs to relationship |
| Self-referencing | SET NULL or RESTRICT | Prevent orphaned subtrees |
| Polymorphic | Application-level | No DB FK possible |

---

# 8. Nullable Foreign Keys

Foreign keys are nullable only when the relationship is genuinely optional:

```
team_members.invited_by  → nullable (inviter may be deleted)
team_invitations.invited_by → nullable
cms_menu_items.parent_id → nullable (root items)
content_entries.parent_id → nullable (some content is top-level)
download_links.expires_at → nullable (some links never expire)
feature_flag_overrides.user_id → nullable (global override)
```

Default assumption: foreign keys are NOT nullable unless explicitly documented otherwise.

---

# 9. Unique Constraints

Unique constraints enforce business invariants at the database level:

| Table | Columns | Rationale |
|---|---|---|
| `users` | `email` | One account per email |
| `users` | `uuid` | Public identifier uniqueness |
| `products` | `slug` | URL uniqueness |
| `products` | `author_id`, `slug` | Slug uniqueness per author |
| `subscriptions` | `stripe_id` | One subscription per Stripe record |
| `subscriptions` | `paddle_id` | One subscription per Paddle record |
| `invoices` | `number` | Invoice number uniqueness |
| `payments` | `idempotency_key` | Idempotency |
| `mcp_tool_calls` | `idempotency_key` | Idempotency |
| `webhook_deliveries` | `idempotency_key` | Idempotency |
| `license_keys` | `key_hash` | Prevent duplicate keys |
| `search_synced_models` | `model_type`, `model_id` | One sync record per entity |
| `team_members` | `team_id`, `user_id` | One membership per team |
| `feature_flag_overrides` | `feature_flag_id`, `user_id` | One override per user |

# 10. Index Strategy

| Pattern | Example | Use Case |
|---|---|---|
| Single-column FK index | `orders.user_id` | JOIN performance |
| Composite FK index | `orders.billable_type, orders.billable_id` | Polymorphic queries |
| Status + timestamp | `subscriptions.user_id, status, created_at` | Dashboard lists |
| Unique slug | `products.slug` | URL lookups |
| Fulltext | `content_entries.search_vector` | Search fallback |
| Composite sort | `cms_menu_items.menu_id, sort_order` | Ordered retrieval |

Indexes are created explicitly in migrations. Eloquent does not auto-create indexes.

# 11. Relationship Documentation Format

Each domain document documents relationships using this format:

```
## Table A → Table B

**Cardinality:** One-to-Many
**Local Key:** table_a.id
**Foreign Key:** table_b.table_a_id
**Cascade:** CASCADE / RESTRICT / SET NULL / Application-level
**Notes:** Optional description
```

---

# 12. Application-Level Relationship Enforcement

These relationships lack database constraints but are enforced in application code:

| Relationship | Enforcement |
|---|---|
| `billable_type` + `billable_id` → User or Team | Repository validates via `morphTo` |
| `team_members.user_id` → `users.id` | Eloquent `belongsTo` with existence check |
| `coupon_products.coupon_id` → `coupons.id` | Business rule validation |
| `content_entries.author_id` → `users.id` | Eloquent relationship |

# 14. Cascade Delete Impact Analysis

When a record is deleted, these cascades fire:

## 14a. User Deletion Impact

```
DELETE FROM users WHERE id = 123

CASCADE deletes:
  → teams (where user_id = 123)
  → team_members (where user_id = 123)
  → team_invitations (where user_id = 123 or invited_by = 123)
  → user_profiles (where user_id = 123)
  → user_preferences (where user_id = 123)
  → two_factor_auth (where user_id = 123)
  → notification_preferences (where user_id = 123)
  → products (where user_id = 123)
  → components (where user_id = 123)
  → themes (where user_id = 123)
  → templates (where user_id = 123)
  → orders (where user_id = 123)
  → order_items (cascade from orders)
  → order_status_histories (cascade from orders)
  → license_keys (where user_id = 123)
  → license_activations (cascade from license_keys)
  → downloads (where user_id = 123)
  → content_entries (where user_id = 123)
  → content_entry_revisions (cascade from content_entries)
  → product_reviews (where user_id = 123)
  → product_favorites (where user_id = 123)
  → coupon_redemptions (where user_id = 123)
  → ai_conversations (where user_id = 123)
  → ai_prompt_templates (where user_id = 123)
  → feature_flag_overrides (where user_id = 123)
  → audit_logs (SET NULL on user_id = 123)

RESTRICT prevents deletion of:
  → subscriptions (where user_id = 123)
  → invoices (where user_id = 123)
  → payments (where user_id = 123)
```

## 14b. Product Deletion Impact

```
DELETE FROM products WHERE id = 456

CASCADE deletes:
  → product_versions (where product_id = 456)
  → product_changelogs (cascade from product_versions)
  → product_compatibility (cascade from product_versions)
  → product_reviews (where product_id = 456)
  → product_favorites (where product_id = 456)
  → order_items (where product_id = 456) — PROBLEM: financial data

SOLUTION: Products use soft deletes only.
  - Soft-deleted products hide from public queries
  - Order items retain product_id reference for history
  - product_versions cascade-deleted (version history belongs to product)
```

## 14c. Order Deletion

```
Orders are NOT soft-deleted and NOT cascade-deleted.
Orders are immutable financial records.
Corrections handled via compensating orders (credit notes).
Order items cascade-deleted with parent order.
Order status histories cascade-deleted with parent order.
```

## 14d. Subscription Deletion

```
Subscriptions use RESTRICT on user_id — cannot delete user with active subscription.
Subscriptions use SET NULL on plan_id — plan deletion nullifies reference.
Subscription items cascade-deleted with parent subscription.
Subscription usage records cascade-deleted with parent subscription.
Subscription status histories cascade-deleted with parent subscription.
Invoices use RESTRICT on subscription_id — cannot delete subscription with invoices.
```

```php
// On Order model
class Order extends Model
```

# 16. Self-Referencing Relationship Patterns

## 16a. CMS Menu Items (Tree)

```php
class CmsMenuItem extends Model
{
    use SoftDeletes;

    public function parent(): BelongsTo
    {
        return $this->belongsTo(CmsMenuItem::class, 'parent_id');
    }

    public function children(): HasMany
    {
        return $this->hasMany(CmsMenuItem::class, 'parent_id')
            ->orderBy('sort_order');
    }

    public function allChildren(): HasManyRecursive
    {
        return $this->children()->with('allChildren');
    }

    public function menu(): BelongsTo
    {
        return $this->belongsTo(CmsMenu::class);
    }

    // Scope: root items only
    public function scopeRoots($query)
    {
        return $query->whereNull('parent_id');
    }

    // Scope: descendants
    public function scopeDescendants($query, $id)
    {
        return $query->where('parent_id', $id);
    }
}
```

# 19. Relationship Loading Strategies

## 19a. Eager Loading (N+1 Prevention)

```php
// Bad: N+1 queries
$orders = Order::all();
foreach ($orders as $order) {
    echo $order->user->name;  // Additional query per order
}

// Good: Eager load relationships
$orders = Order::with(['user', 'items.product', 'coupon'])->get();
foreach ($orders as $order) {
    echo $order->user->name;  // No additional query
    foreach ($order->items as $item) {
```

# 25. Soft Delete and Relationship Interaction

Soft deletes affect relationship queries. Deleted records are hidden by default but relationships still resolve.

```php
// Soft-deleted parent — children still accessible
$user = User::withTrashed()->find($userId);
$user->orders; // Returns all orders, including from before deletion

// Soft-deleted children hidden by default
$user->orders; // Does NOT include soft-deleted orders

// Include soft-deleted children
$user->orders()->withTrashed()->get();

// Only soft-deleted children
$user->orders()->onlyTrashed()->get();

// Restore with relationships
$user->restore();
$user->orders()->restore(); // Restore all child orders too

// Force delete — cascades through soft-deleted children
$user->forceDelete(); // Also force-deletes all orders, products, etc.
```

## 25a. Soft Delete Cascade Patterns

```php
// When a product is soft-deleted
Product::find($id)->delete();

// Hidden from public queries
Product::where('is_published', true)->get(); // Excludes deleted

// But accessible via withTrashed
Product::withTrashed()->find($id); // Still exists

// Product versions still accessible
$product->versions()->get(); // Shows versions
$product->versions()->withTrashed()->get(); // Shows deleted versions too

// When product is force-deleted
$product->forceDelete();
// CASCADE: product_versions → product_changelogs, product_compatibility
// CASCADE: product_reviews, product_favorites
// CASCADE: order_items (DANGEROUS: loses financial data)

// Prevention: Do NOT force-delete products with order_items
class Product extends Model
{
    protected static function booted(): void
    {
        static::deleting(function (Product $product) {
            if ($product->orderItems()->exists()) {
                throw new \RuntimeException(
                    'Cannot delete product with existing orders. Archive instead.'
                );
            }
        });
    }
}
```

# 29. Relationship Service Classes

```php
// Service classes encapsulate complex relationship logic

class OrderService
{
    public function createOrder(
        Model $billable,
        User $purchaser,
        array $items,
        ?string $couponCode = null
    ): Order {
        $order = Order::create([
            'billable_type' => get_class($billable),
            'billable_id' => $billable->id,
            'user_id' => $purchaser->id,
            'order_number' => $this->generateOrderNumber(),
            'status' => 'pending',
            'currency' => 'USD',
        ]);

        foreach ($items as $item) {
            OrderItem::create([
                'order_id' => $order->id,
                'product_id' => $item['product_id'],
                'product_version_id' => $item['version_id'] ?? null,
                'quantity' => $item['quantity'] ?? 1,
                'unit_price' => $item['unit_price'],
                'total_price' => ($item['quantity'] ?? 1) * $item['unit_price'],
                'license_type' => $item['license_type'] ?? 'single',
            ]);
        }

        if ($couponCode) {
            $this->applyCoupon($order, $couponCode);
        }

        $this->recalculateTotals($order);
        $this->recordStatusChange($order, null, 'pending');

        return $order;
    }

    public function completeOrder(Order $order): Order
    {
        $order->update([
            'status' => 'completed',
            'paid_at' => now(),
        ]);

        $this->recordStatusChange($order, 'pending', 'completed');

        // Generate license keys
        foreach ($order->items as $item) {
            LicenseKey::create([
                'user_id' => $order->user_id,
                'product_id' => $item->product_id,
                'order_id' => $order->id,
                'key_encrypted' => encrypt(Str::random(40)),
                'key_hash' => hash('sha256', Str::random(40)),
                'key_prefix' => substr(Str::random(8), 0, 8),
                'status' => 'active',
                'max_activations' => $item->license_type === 'team' ? 999 : 1,
            ]);
        }

        // Update product stats
        foreach ($order->items as $item) {
            Product::where('id', $item->product_id)->increment('sale_count');
        }

        return $order;
    }

    private function recordStatusChange(
        Order $order,
        ?string $from,
        string $to
    ): void {
        OrderStatusHistory::create([
            'order_id' => $order->id,
            'from_status' => $from,
            'to_status' => $to,
            'changed_by' => auth()->id(),
        ]);
    }

    private function generateOrderNumber(): string
    {
        $year = now()->year;
        $sequence = DB::transaction(function () use ($year) {
            $record = DB::select("SELECT NEXTVAL(?) as next", ['order_sequences_' . $year]);
            return $record[0]->next ?? 1;
        });

        return sprintf('GSM-%d-%05d', $year, $sequence);
    }

    private function recalculateTotals(Order $order): void
    {
        $subtotal = $order->items()->sum('total_price');
        $discount = $order->discount_amount ?? 0;
        $tax = $order->tax_amount ?? 0;

        $order->update([
            'subtotal' => $subtotal,
            'total' => $subtotal + $tax - $discount,
        ]);
    }

    private function applyCoupon(Order $order, string $couponCode): void
    {
        $coupon = Coupon::where('code', $couponCode)
            ->where('is_active', true)
            ->first();

        if (!$coupon || !$coupon->isValid()) {
            throw new \InvalidArgumentException('Invalid or expired coupon');
        }

        $discount = $coupon->calculateDiscount($order->subtotal);

        $order->update([
            'coupon_id' => $coupon->id,
            'discount_amount' => $discount,
        ]);

        CouponRedemption::create([
            'coupon_id' => $coupon->id,
            'user_id' => $order->user_id,
            'order_id' => $order->id,
            'discount_amount' => $discount,
            'redeemed_at' => now(),
        ]);
    }
}
```
