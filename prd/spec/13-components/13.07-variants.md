# 13.07 Variants System — GsmUi Variant Specification

## Overview

The variant system provides a consistent way to define visual and behavioral variations of components. Variants are mutually exclusive options that change the component's appearance or behavior significantly.

## Variant Definition

### PHP Enum-Based Variants (Recommended)

```php
<?php

namespace GsmUi\Components\Actions\Button;

enum Variant: string
{
    case Primary = 'primary';
    case Secondary = 'secondary';
    case Outline = 'outline';
    case Ghost = 'ghost';
    case Link = 'link';
    
    public function classes(): string
    {
        return match ($this) {
            self::Primary => 'bg-(--gsmui-color-primary) text-white hover:bg-(--gsmui-color-primary)/90',
            self::Secondary => 'bg-(--gsmui-color-zinc-100) text-zinc-900 dark:bg-(--gsmui-color-zinc-800) dark:text-white hover:bg-(--gsmui-color-zinc-200) dark:hover:bg-(--gsmui-color-zinc-700)',
            self::Outline => 'border border-(--gsmui-color-zinc-300) dark:border-(--gsmui-color-zinc-600) bg-transparent hover:bg-(--gsmui-color-zinc-50) dark:hover:bg-(--gsmui-color-zinc-800/50)',
            self::Ghost => 'bg-transparent hover:bg-(--gsmui-color-zinc-100) dark:hover:bg-(--gsmui-color-zinc-800)',
            self::Link => 'bg-transparent text-(--gsmui-color-primary) underline-offset-2 hover:underline',
        };
    }
}
```

### Component Usage

```php
class Button extends BaseComponent
{
    #[Prop(type: 'Variant', default: 'Variant::Primary')]
    public Variant $variant = Variant::Primary;
    
    public function variantClasses(): string
    {
        return $this->variant->classes();
    }
}
```

## Standard Variants by Category

### Actions (Button, IconButton, Link, etc.)

| Variant | Description | Use Case |
|---------|-------------|----------|
| `primary` | Filled, brand color | Main CTA |
| `secondary` | Filled, neutral | Secondary actions |
| `outline` | Bordered, transparent | Subtle actions |
| `ghost` | No border, transparent | Tertiary actions |
| `link` | Text-only, underlined | Navigation links |

### Forms (Input, Select, Textarea, etc.)

| Variant | Description | Use Case |
|---------|-------------|----------|
| `outline` | Bordered (default) | Standard forms |
| `filled` | Background fill | Dense forms |
| `underlined` | Bottom border only | Minimal forms |
| `flushed` | No border, no bg | Inline editing |

### Feedback (Alert, Toast, Badge, etc.)

| Variant | Description | Use Case |
|---------|-------------|----------|
| `solid` | Filled background | High visibility |
| `soft` | Tinted background | Subtle feedback |
| `outline` | Bordered | Low emphasis |
| `light` | Very subtle | Passive info |

### Overlays (Modal, Drawer, Popover, etc.)

| Variant | Description | Use Case |
|---------|-------------|----------|
| `default` | Centered, elevated | Standard dialogs |
| `fullscreen` | Full viewport | Mobile, complex forms |

## Variant Props vs Separate Props

### ❌ Anti-Pattern: Boolean Variants

```blade
<!-- BAD: Explodes combinatorially -->
<x-gsmui:button 
    :primary="true" 
    :outline="false" 
    :ghost="false" 
    :success="false"
    :danger="false"
/>
```

### ✅ Pattern: Single Variant Prop

```blade
<!-- GOOD: Single source of truth -->
<x-gsmui:button variant="primary-danger" />
<x-gsmui:button variant="outline-success" />
```

### ✅ Pattern: Variant + Color (Orthogonal)

```blade
<!-- GOOD: Independent dimensions -->
<x-gsmui:button variant="primary" color="success" />
<x-gsmui:button variant="outline" color="danger" />
```

## Variant Resolution

### Priority Order

1. **Explicit variant prop** — `<x-gsmui:button variant="outline">`
2. **Context inference** — Inside `gsmui:card` → `variant="ghost"`
3. **Global config** — `config('gsmui.defaults.button.variant')`
4. **Theme default** — `--gsmui-button-variant`
5. **Component default** — `Variant::Primary`

### Context-Aware Variants

```php
trait ResolvesVariantFromContext
{
    protected function resolveVariant(): string
    {
        // Explicit prop wins
        if ($this->attributes->has('variant')) {
            return $this->attributes->get('variant');
        }
        
        // Context inference
        $parent = $this->getParentComponent();
        if ($parent) {
            return match (get_class($parent)) {
                Card::class => 'ghost',
                Toolbar::class => 'outline',
                Navbar::class => 'ghost',
                default => $this->defaultVariant,
            };
        }
        
        return $this->defaultVariant;
    }
}
```

## Variant Deep Dive

### Variant Resolution

Variants are resolved in this order:

1. **Explicit variant prop** — Highest priority
2. **Context inference** — Parent component context
3. **Global config** — Application defaults
4. **Theme default** — CSS variable
5. **Component default** — Lowest priority

```php
trait ResolvesVariant
{
    protected function resolveVariant(): string
    {
        // 1. Explicit prop
        if ($this->attributes->has('variant')) {
            return $this->attributes->get('variant');
        }
        
        // 2. Context inference
        $parent = $this->getParentComponent();
        if ($parent) {
            return match (get_class($parent)) {
                Card::class => 'ghost',
                Toolbar::class => 'outline',
                Navbar::class => 'ghost',
                default => $this->defaultVariant,
            };
        }
        
        // 3. Global config
        $configKey = "gsmui.defaults.{$this->componentName}.variant";
        if (config()->has($configKey)) {
            return config($configKey);
        }
        
        // 4. Theme default
        $token = "--gsmui-{$this->componentName}-variant";
        if ($this->theme && $this->theme->hasToken($token)) {
            return $this->theme->getToken($token);
        }
        
        // 5. Component default
        return $this->defaultVariant;
    }
}
```

### Variant CSS Classes

Each variant maps to CSS classes:

```php
trait HasVariantClasses
```

## Variants Quick Reference

### Available Variants by Component

| Component | Available Variants |
|-----------|-------------------|
| Button | primary, secondary, ghost, danger, link |
| Input | outline, filled, unstyled |
| Card | elevated, outlined, filled |
| Badge | primary, secondary, success, danger, warning, info |
| Alert | info, success, warning, danger |
| Tabs | underline, pills, enclosed |
| Toggle | primary, success, danger |
| Avatar | circle, square, rounded |
| Table | striped, bordered, compact |
| Progress | primary, success, danger, striped, animated |

### Variant Naming Conventions

- Use lowercase for variant names
- Use hyphens for multi-word variants (e.g., `outline-border`)
- Keep variant names short and descriptive
- Use consistent naming across components
- Follow Tailwind CSS naming patterns
