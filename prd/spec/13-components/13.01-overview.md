# 13.01 Overview — GsmUi Component System

## Purpose

This document provides the executive overview of the GsmUi component system — a comprehensive, Laravel-native UI framework built on Livewire 4, Blade components, Tailwind CSS v4, and a design token architecture.

## Design Principles

### 1. Laravel-Native First
Every component is a **Blade anonymous component** with optional **Livewire enhancement**. No React, Vue, or Svelte dependencies required.

### 2. Design Token Driven
All styling derives from **design tokens** (colors, spacing, typography, radii, shadows, motion). Components never hardcode values.

### 3. Livewire-Enhanced, Not Livewire-Dependent
Components work as pure Blade. Add `wire:model` for reactivity. No forced Livewire dependency.

### 4. Accessibility by Default
WCAG 2.1 AA compliance is mandatory. ARIA attributes, keyboard navigation, focus management, and screen reader support are built-in.

### 5. Theme-Aware
Components automatically adapt to light/dark mode and custom themes via CSS custom properties.

### 6. Composable Architecture
Components compose via **slots** and **sub-components**. No monolithic "do-everything" components.

### 6. Developer Experience First
- Type-safe props via PHP docblocks
- IDE autocomplete via Laravel IDE Helper
- Playground for live editing
- AI-assisted documentation generation

## Rendering Pipeline

### Server-Side Rendering (Blade)

```
1. Component Class (PHP)
   ↓ Props resolved, computed properties calculated
2. Blade Template (index.blade.php)
   ↓ @props directive, slot resolution
3. HTML Output
   ↓ CSS classes applied, attributes merged
4. Sent to Browser
```

### Client-Side Enhancement (JS)

```
1. HTML received from server
   ↓
2. Custom Elements defined (gsmui-button, gsmui-select, etc.)
   ↓
3. connectedCallback() fires
   ↓ Shadow DOM created, event listeners bound
4. Attributes observed for changes
   ↓
5. User interaction
   ↓ State updated, events dispatched
6. Livewire sync (if wire:model present)
```

### Hydration Flow (Livewire)

```
1. Initial page load
   ↓ Blade renders static HTML
2. Livewire JavaScript loads
   ↓ DOM diffed, components hydrated
3. wire:model bindings established
   ↓
4. User changes value
   ↓
5. Livewire sends AJAX request
   ↓ Server processes update
6. New HTML returned
   ↓ DOM patched
7. Component re-rendered
```

## Design System Architecture

### Token Taxonomy

The GsmUi design system uses a three-tier token architecture:

```
Tier 1: Primitive Tokens (raw values)
├── Colors: --gsmui-color-blue-500, --gsmui-color-zinc-900
├── Spacing: --gsmui-space-1, --gsmui-space-2
├── Typography: --gsmui-text-sm, --gsmui-text-base
├── Radii: --gsmui-radius-md, --gsmui-radius-lg
├── Shadows: --gsmui-shadow-sm, --gsmui-shadow-md
└── Motion: --gsmui-duration-fast, --gsmui-ease-default

Tier 2: Semantic Tokens (purpose-driven)
├── Colors: --gsmui-color-primary, --gsmui-color-danger
├── Surfaces: --gsmui-surface, --gsmui-surface-elevated
├── Borders: --gsmui-border, --gsmui-border-strong
├── Text: --gsmui-text, --gsmui-text-muted
└── Interactive: --gsmui-focus-ring, --gsmui-hover-bg

Tier 3: Component Tokens (component-specific)
├── Button: --gsmui-btn-bg, --gsmui-btn-radius
├── Input: --gsmui-input-border, --gsmui-input-focus-ring
├── Card: --gsmui-card-bg, --gsmui-card-radius
└── Modal: --gsmui-modal-shadow, --gsmui-modal-radius
```

### Sibling → Sibling (Livewire State)

Shared state through Livewire:

```php
class Page extends LivewireComponent
{

    public function handleTabChange(string $tab): void
    {
        $this->selectedTab = $tab;
    }
}
```

### Cross-Component (Event Bus)

Global event bus for unrelated components:

```javascript
// Dispatch
window.dispatchEvent(new CustomEvent('gsmui:theme-change', {
    detail: { theme: 'dark' }
}));

// Listen
window.addEventListener('gsmui:theme-change', (event) => {
    console.log(event.detail.theme);
});
```

## Component Naming Conventions

### File Naming

| Type | Convention | Example |
|------|-----------|---------|
| PHP Class | PascalCase | `Button.php`, `DatePicker.php` |
| Blade Template | kebab-case | `button/index.blade.php` |
| JavaScript | PascalCase | `Button.js`, `DatePicker.js` |
| CSS | kebab-case | `button.css`, `date-picker.css` |
| Test | PascalCase | `ButtonTest.php`, `DatePickerTest.php` |
| Documentation | kebab-case | `button.md`, `date-picker.md` |

### Class Naming

| Type | Convention | Example |
|------|-----------|---------|
| Component | PascalCase | `Button`, `DatePicker` |
| Trait | PascalCase + able | `Controllable`, `Disableable` |
| Interface | PascalCase + Contract | `ComponentContract` |
| Enum | PascalCase | `Variant`, `Size` |
| Method | camelCase | `getVariantClasses()`, `resolveSize()` |
| Property | camelCase | `$variant`, `$size` |
| Constant | UPPER_SNAKE_CASE | `MAX_SIZE`, `DEFAULT_VARIANT` |

### CSS Naming

| Type | Convention | Example |
|------|-----------|---------|
| Component | `.gsmui-{component}` | `.gsmui-button` |
| Variant | `.gsmui-{component}--{variant}` | `.gsmui-button--primary` |
| Size | `.gsmui-{component}--{size}` | `.gsmui-button--md` |
| State | `.gsmui-{component}--{state}` | `.gsmui-button--disabled` |
| Modifier | `.gsmui-{component}__{element}` | `.gsmui-button__icon` |
