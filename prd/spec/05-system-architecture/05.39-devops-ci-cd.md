# Architecture Overview

The DevOps architecture integrates development and operations practices to enable rapid, reliable software delivery. The CI/CD pipeline automates the build, test, and deployment process, while infrastructure as code ensures consistent and reproducible environments.

The architecture follows the principle of automation first, with manual steps only where human judgment is required. Every process from code validation to production deployment is automated with appropriate quality gates and approval workflows.

The monitoring stack provides visibility into the entire pipeline, from code commit to production deployment. Alerts notify the team of failures, performance degradations, and security issues.

# CI/CD Pipeline

## GitHub Actions Workflow

```yaml
name: CI/CD Pipeline

on:
  push:
    branches: [main, develop]
  pull_request:
    branches: [main]

env:
  PHP_VERSION: '8.4'
  NODE_VERSION: '20'

jobs:
  validate:
    name: Validate
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      
      - name: Setup PHP
        uses: shivammathur/setup-php@v2
        with:
          php-version: ${{ env.PHP_VERSION }}
          extensions: mbstring, xml, ctype, json, bcmath, pdo_mysql
          coverage: none
      
      - name: PHP Lint
        run: find app -name "*.php" -exec php -l {} \;
      
      - name: Code Style
        run: |
          composer global require laravel/pint
          pint --test
      
      - name: Static Analysis
        run: |
          composer require --dev larastan/larastan
          vendor/bin/phpstan analyse --memory-limit=512M

  test:
    name: Test
    needs: validate
    runs-on: ubuntu-latest
    services:
      mysql:
        image: mysql:8.0
        env:
          MYSQL_ROOT_PASSWORD: testing
          MYSQL_DATABASE: gsmui_testing
        ports:
          - 3306:3306
        options: >-
          --health-cmd="mysqladmin ping"
          --health-interval=10s
          --health-timeout=5s
          --health-retries=5
      redis:
        image: redis:7
        ports:
          - 6379:6379
    steps:
      - uses: actions/checkout@v4
      
      - name: Setup PHP
        uses: shivammathur/setup-php@v2
        with:
          php-version: ${{ env.PHP_VERSION }}
          extensions: mbstring, xml, ctype, json, bcmath, pdo_mysql
          coverage: pcov
      
      - name: Install Dependencies
        run: composer install --no-progress --prefer-dist
      
      - name: Prepare Environment
        run: |
          cp .env.ci .env
          php artisan key:generate
      
      - name: Run Migrations
        run: php artisan migrate --force
      
      - name: Seed Database
        run: php artisan db:seed --force
      
      - name: Unit Tests
        run: vendor/bin/phpunit --testsuite=Unit --coverage-cobertura=coverage-unit.xml
      
      - name: Feature Tests
        run: vendor/bin/phpunit --testsuite=Feature --coverage-cobertura=coverage-feature.xml
      
      - name: Upload Coverage
        uses: codecov/codecov-action@v3
        with:
          files: coverage-unit.xml,coverage-feature.xml

  build:
    name: Build
    needs: test
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      
      - name: Setup Node
        uses: actions/setup-node@v4
        with:
          node-version: ${{ env.NODE_VERSION }}
          cache: 'npm'
      
      - name: Install Dependencies
        run: npm ci
      
      - name: Build Assets
        run: npm run build
      
      - name: Upload Build
        uses: actions/upload-artifact@v4
        with:
          name: build
          path: public/build

  deploy-staging:
    name: Deploy Staging
    needs: build
    if: github.ref == 'refs/heads/develop'
    runs-on: ubuntu-latest
    environment: staging
    steps:
      - uses: actions/checkout@v4
      
      - name: Download Build
        uses: actions/download-artifact@v4
        with:
          name: build
          path: public/build
      
      - name: Deploy
        uses: appleboy/ssh-action@v1
        with:
          host: ${{ secrets.STAGING_HOST }}
          username: ${{ secrets.STAGING_USER }}
          key: ${{ secrets.STAGING_SSH_KEY }}
          script: |
            cd /var/www/gsmui-staging
            git pull origin develop
            composer install --no-dev --optimize-autoloader
            php artisan migrate --force
            php artisan config:cache
            php artisan route:cache
            php artisan view:cache
            sudo systemctl restart php8.4-fpm

  deploy-production:
    name: Deploy Production
    needs: build
    if: github.ref == 'refs/heads/main'
    runs-on: ubuntu-latest
    environment: production
    steps:
      - uses: actions/checkout@v4
      
      - name: Download Build
        uses: actions/download-artifact@v4
        with:
          name: build
          path: public/build
      
      - name: Deploy
        uses: appleboy/ssh-action@v1
        with:
          host: ${{ secrets.PRODUCTION_HOST }}
          username: ${{ secrets.PRODUCTION_USER }}
          key: ${{ secrets.PRODUCTION_SSH_KEY }}
          script: |
            cd /var/www/gsmui
            git pull origin main
            composer install --no-dev --optimize-autoloader
            php artisan migrate --force
            php artisan config:cache
            php artisan route:cache
            php artisan view:cache
            sudo systemctl restart php8.4-fpm
            sudo systemctl restart nginx
      
      - name: Health Check
        run: |
          sleep 10
          curl -f https://gsmui.com/health || exit 1
      
      - name: Notify
        if: success()
        run: |
          curl -X POST ${{ secrets.SLACK_WEBHOOK }} \
            -H 'Content-type: application/json' \
            -d '{"text":"Production deployment successful!"}'
```

## Pipeline Stages

### Stage 1: Validate

Code style and static analysis run first to catch issues before tests. This provides fast feedback and prevents style regressions.

- PHP linting for syntax errors
- Laravel Pint for code style
- Larastan for static analysis

### Stage 2: Test

Unit and feature tests run against a real database. Coverage is tracked and reported.

- PHPUnit unit tests
- PHPUnit feature tests
- Code coverage reporting

### Stage 3: Build

Frontend assets are compiled and optimized.

- NPM dependency installation
- Vite build with optimizations
- Artifact upload for deployment

### Stage 4: Deploy Staging

Automatic deployment to staging for develop branch.

- SSH deployment
- Migration execution
- Cache warming
- Service restart

### Stage 5: Deploy Production

Manual approval required for production deployment.

- Production deployment
- Health check verification
- Slack notification

# Backup Strategy

## Database Backups

```bash
#!/bin/bash
# backup-db.sh

BACKUP_DIR="/backups/mysql"
DATE=$(date +%Y-%m-%d_%H-%M-%S)
BACKUP_FILE="$BACKUP_DIR/gsmui_$DATE.sql.gz"

# Create backup
mysqldump -u $DB_USER -p$DB_PASSWORD gsmui | gzip > $BACKUP_FILE

# Upload to S3
aws s3 cp $BACKUP_FILE s3://gsmui-backups/mysql/ --sse AES256

# Clean local backups older than 7 days
find $BACKUP_DIR -name "*.sql.gz" -mtime +7 -delete

echo "Backup completed: $BACKUP_FILE"
```

# Deployment Strategies

## Blue-Green Deployment

Blue-green deployments maintain two identical production environments. At any time, only one (blue) serves live traffic. The other (green) is used for staging and validation.

```text
┌─────────────────────────────────────────────────┐
│                  Load Balancer                    │
│              (Traffic Router)                     │
└────────────┬────────────────────┬────────────────┘
             │                    │
     ┌───────▼───────┐    ┌───────▼───────┐
     │   Blue (Live)  │    │  Green (Idle)  │
     │   v2.15.0      │    │   v2.16.0      │
     │   port 8000    │    │   port 8001    │
     └───────────────┘    └───────────────┘
```

### Blue-Green Deployment Steps

1. Deploy new version to green environment
2. Run smoke tests against green environment
3. Switch load balancer to green
4. Verify production health on green
5. Keep blue as rollback target
6. After stability period, blue becomes new idle

### Blue-Green Configuration

```yaml
# deploy/blue-green.yml
version: '3.8'

services:
  blue:
    image: gsmui-app:current
    container_name: gsmui-blue
    ports:
      - "8000:8000"
    environment:
      - APP_ENV=production
      - APP_VERSION=2.15.0
    healthcheck:
      test: ["CMD", "curl", "-f", "http://localhost:8000/health"]
      interval: 10s
      timeout: 5s
      retries: 3

  green:
    image: gsmui-app:new
    container_name: gsmui-green
    ports:
      - "8001:8000"
    environment:
      - APP_ENV=production
      - APP_VERSION=2.16.0
    healthcheck:
      test: ["CMD", "curl", "-f", "http://localhost:8000/health"]
      interval: 10s
      timeout: 5s
      retries: 3

  nginx:
    image: nginx:alpine
    volumes:
      - ./nginx/blue-green.conf:/etc/nginx/conf.d/default.conf
    ports:
      - "80:80"
      - "443:443"
    depends_on:
      - blue
      - green
```

### Nginx Blue-Green Router

```nginx
# nginx/blue-green.conf
upstream backend {
    least_conn;
    server blue:8000 weight=1;
    server green:8000 weight=0;  # disabled by default
}

upstream backend-switch {
    least_conn;
    server blue:8000 weight=0;  # disabled after switch
    server green:8000 weight=1;
}

server {
    listen 80;
    server_name gsmui.com;

    location / {
        proxy_pass http://backend;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    location /health {
        proxy_pass http://backend/health;
        access_log off;
    }
}
```

### Blue-Green Switch Script

```bash
#!/bin/bash
# switch-blue-green.sh

CURRENT=$(docker inspect --format='{{.Config.Image}}' gsmui-blue)
NEW=$(docker inspect --format='{{.Config.Image}}' gsmui-green)

echo "Current: $CURRENT"
echo "New: $NEW"

# Update nginx to route to green
sed -i 's/server blue:8000 weight=1/server blue:8000 weight=0/' /etc/nginx/conf.d/blue-green.conf
sed -i 's/server green:8000 weight=0/server green:8000 weight=1/' /etc/nginx/conf.d/blue-green.conf

# Reload nginx
docker exec gsmui-nginx nginx -s reload

# Verify health
sleep 5
HEALTH=$(curl -s -o /dev/null -w "%{http_code}" http://localhost/health)

if [ "$HEALTH" = "200" ]; then
    echo "Switch successful. Green is now live."
    # Tag new version
    docker tag gsmui-green:latest gsmui-app:stable
else
    echo "Health check failed. Rolling back..."
    sed -i 's/server blue:8000 weight=0/server blue:8000 weight=1/' /etc/nginx/conf.d/blue-green.conf
    sed -i 's/server green:8000 weight=1/server green:8000 weight=0/' /etc/nginx/conf.d/blue-green.conf
    docker exec gsmui-nginx nginx -s reload
    exit 1
fi
```

### Blue-Green Advantages

- Zero downtime deployments
- Instant rollback capability
- Full testing of new version before switch
- No database migration complexity for UI changes

### Blue-Green Disadvantages

- Double infrastructure cost during deployment
- Database schema must be backward-compatible
- Session state management complexity
- File storage synchronization requirements

## Canary Deployment

Canary deployments gradually shift traffic from the old version to the new version. A small percentage of users receive the new version first, allowing validation before full rollout.

```text
┌──────────────────────────────────────────────────┐
│                   Load Balancer                    │
│              (Weight-based Router)                 │
└──────────┬───────────────────────────┬────────────┘
           │                           │
   ┌───────▼───────┐          ┌───────▼───────┐
   │  Stable (95%)  │          │  Canary (5%)   │
   │   v2.15.0      │          │   v2.16.0      │
   │   3 instances   │          │   1 instance    │
   └───────────────┘          └───────────────┘
```

### Canary Deployment Pipeline

```yaml
# .github/workflows/canary-deploy.yml
name: Canary Deployment

on:
  workflow_dispatch:
    inputs:
      canary_percent:
        description: 'Canary traffic percentage'
        required: true
        default: '5'
      promote:
        description: 'Promote canary to stable'
        required: false
        type: boolean
        default: false

jobs:
  canary:
    name: Deploy Canary
    runs-on: ubuntu-latest
    environment: canary
    steps:
      - uses: actions/checkout@v4

      - name: Build New Image
        run: |
          docker build -t gsmui-app:canary-${{ github.sha }} .
          docker push registry.gsmui.com/gsmui-app:canary-${{ github.sha }}

      - name: Deploy Canary Instance
        run: |
          ssh deploy@canary-server << 'EOF'
            docker pull registry.gsmui.com/gsmui-app:canary-${{ github.sha }}
            docker run -d \
              --name gsmui-canary \
              -p 8001:8000 \
              -e APP_ENV=production \
              registry.gsmui.com/gsmui-app:canary-${{ github.sha }}
          EOF

      - name: Configure Traffic Split
        run: |
          ssh deploy@canary-server << 'EOF'
            # Update nginx weights
            sed -i "s/weight=[0-9]*/weight=$((100 - ${{ inputs.canary_percent }}))/" \
              /etc/nginx/conf.d/upstream.conf
            sed -i "s/canary.*weight=[0-9]*/canary weight=${{ inputs.canary_percent }}/" \
              /etc/nginx/conf.d/upstream.conf
            nginx -s reload
          EOF

      - name: Monitor Canary
        run: |
          for i in $(seq 1 60); do
            ERROR_RATE=$(curl -s http://prometheus:9090/api/v1/query?query=rate(http_requests_total{status=~"5.."}[5m])/rate(http_requests_total[5m]) | jq '.data.result[0].value[1]' -r)
            if (( $(echo "$ERROR_RATE > 0.05" | bc -l) )); then
              echo "Error rate too high: $ERROR_RATE"
              exit 1
            fi
            sleep 30
          done

      - name: Promote Canary
        if: inputs.promote
        run: |
          ssh deploy@production-server << 'EOF'
            docker pull registry.gsmui.com/gsmui-app:canary-${{ github.sha }}
            docker tag registry.gsmui.com/gsmui-app:canary-${{ github.sha }} \
              registry.gsmui.com/gsmui-app:stable
            docker-compose up -d --no-deps app
          EOF
```

### Canary Metrics Collection

```python
# monitoring/canary_metrics.py
import requests
import time
import json

class CanaryMonitor:
    def __init__(self, prometheus_url, canary_threshold):
        self.prometheus_url = prometheus_url
        self.error_threshold = canary_threshold
        self.metrics = []

    def query_error_rate(self, service, duration='5m'):
        query = (
            f'rate(http_requests_total{{service="{service}",status=~"5.."}}[{duration}])'
            f' / rate(http_requests_total{{service="{service}"}}[{duration}])'
        )
        response = requests.get(
            f'{self.prometheus_url}/api/v1/query',
            params={'query': query}
        )
        return float(response.json()['data']['result'][0]['value'][1])

    def query_latency_p99(self, service, duration='5m'):
        query = (
            f'histogram_quantile(0.99, '
            f'rate(http_request_duration_seconds_bucket{{service="{service}"}}[{duration}]))'
        )
        response = requests.get(
            f'{self.prometheus_url}/api/v1/query',
            params={'query': query}
        )
        return float(response.json()['data']['result'][0]['value'][1])

    def compare_canary(self, stable_service, canary_service, duration_minutes=30):
        stable_errors = self.query_error_rate(stable_service)
        canary_errors = self.query_error_rate(canary_service)
        stable_latency = self.query_latency_p99(stable_service)
        canary_latency = self.query_latency_p99(canary_service)

        result = {
            'timestamp': time.time(),
            'stable_error_rate': stable_errors,
            'canary_error_rate': canary_errors,
            'error_rate_delta': canary_errors - stable_errors,
            'stable_p99_latency': stable_latency,
            'canary_p99_latency': canary_latency,
            'latency_delta': canary_latency - stable_latency,
            'passed': canary_errors <= self.error_threshold
        }

        self.metrics.append(result)
        return result

    def should_promote(self, min_samples=10):
        if len(self.metrics) < min_samples:
            return False
        recent = self.metrics[-min_samples:]
        passed_count = sum(1 for m in recent if m['passed'])
        return passed_count >= min_samples * 0.95

    def should_rollback(self, min_samples=5):
        if len(self.metrics) < min_samples:
            return False
        recent = self.metrics[-min_samples:]
        failed_count = sum(1 for m in recent if not m['passed'])
        return failed_count >= 3
```

## Rolling Deployment

Rolling deployments incrementally replace instances of the old version with the new version. At any point, a mix of old and new versions run simultaneously.

```text
Step 2:  [v2.16] [v2.15] [v2.15] [v2.15]
Step 3:  [v2.16] [v2.16] [v2.15] [v2.15]
Step 4:  [v2.16] [v2.16] [v2.16] [v2.15]
Step 5:  [v2.16] [v2.16] [v2.16] [v2.16]
```

### Rolling Update Script

```bash
#!/bin/bash
# rolling-update.sh

INSTANCES=("app-1" "app-2" "app-3")
NEW_IMAGE="gsmui-app:$1"
HEALTH_ENDPOINT="http://localhost:8000/health"
MAX_RETRIES=10
RETRY_INTERVAL=10

for instance in "${INSTANCES[@]}"; do
    echo "Updating $instance to $NEW_IMAGE..."

    # Pull new image
    docker pull "$NEW_IMAGE"

    # Stop current instance
    docker stop "$instance"

    # Remove current instance
    docker rm "$instance"

    # Start new instance
    docker run -d \
        --name "$instance" \
        --network gsmui-network \
        -e APP_ENV=production \
        "$NEW_IMAGE"

    # Wait for health check
    retries=0
    while [ $retries -lt $MAX_RETRIES ]; do
        sleep $RETRY_INTERVAL
        status=$(docker inspect --format='{{.State.Health.Status}}' "$instance")

        if [ "$status" = "healthy" ]; then
            echo "$instance is healthy. Proceeding to next instance."
            break
        fi

        retries=$((retries + 1))
        echo "Waiting for $instance to become healthy... ($retries/$MAX_RETRIES)"
    done

    if [ $retries -eq $MAX_RETRIES ]; then
        echo "ERROR: $instance failed health check. Rolling back..."
        docker stop "$instance"
        docker run -d \
            --name "$instance" \
            --network gsmui-network \
            -e APP_ENV=production \
            "gsmui-app:stable"
        exit 1
    fi
done

echo "Rolling update completed successfully."
```

### Rolling Deployment Advantages

- No additional infrastructure required
- Gradual rollout with automatic rollback
- Simple implementation
- Resource-efficient

### Rolling Deployment Disadvantages

- Version skew during deployment
- Database schema must support both versions
- Potential request inconsistency
- Slower than blue-green for large deployments

|----------|----------|----------------|---------------------|------------|------|

## Feature Flag Implementation

### PHP Feature Flag Service

```php
<?php

namespace App\Features;

class FeatureFlag
{
    private static array $flags = [];
    private static array $overrides = [];

    public static function load(): void
    {
        $flagsPath = config('features.flags_file', base_path('config/feature-flags.json'));

        if (file_exists($flagsPath)) {
            self::$flags = json_decode(file_get_contents($flagsPath), true) ?? [];
        }
    }

    public static function isEnabled(string $flag, ?int $userId = null): bool
    {
        // Check overrides first (for testing)
        if (isset(self::$overrides[$flag])) {
            return self::$overrides[$flag];
        }

        // Check if flag exists
        if (!isset(self::$flags[$flag])) {
            return false;
        }

        $config = self::$flags[$flag];

        // Check if globally disabled
        if (!$config['enabled'] ?? false) {
            return false;
        }

        // Check percentage rollout
        if (isset($config['percentage'])) {
            $hash = crc32($flag . ($userId ?? 'anonymous'));
            return ($hash % 100) < $config['percentage'];
        }

        // Check user whitelist
        if (isset($config['whitelist']) && $userId !== null) {
            return in_array($userId, $config['whitelist']);
        }

        // Check user blacklist
        if (isset($config['blacklist']) && $userId !== null) {
            return !in_array($userId, $config['blacklist']);
        }

        return $config['enabled'] ?? false;
    }

    public static function override(string $flag, bool $value): void
    {
        self::$overrides[$flag] = $value;
    }

    public static function clearOverrides(): void
    {
        self::$overrides = [];
    }

    public static function getAllFlags(): array
    {
        return self::$flags;
    }
}
```

```php
<?php

namespace App\Livewire\Admin\Features;

use App\Features\FeatureFlag;
use Livewire\Component;

class FeatureFlagManager extends Component
{
    public array $flags = [];
    public ?string $editingFlag = null;
    public bool $enabled = false;
    public int $rolloutPercentage = 0;

    public function mount(): void
    {
        $this->loadFlags();
    }

    public function loadFlags(): void
    {
        $this->flags = FeatureFlag::getAllFlags();
    }

    public function editFlag(string $name): void
    {
        $this->editingFlag = $name;
        $flagConfig = $this->flags[$name] ?? [];
        $this->enabled = $flagConfig['enabled'] ?? false;
        $this->rolloutPercentage = $flagConfig['percentage'] ?? 0;
    }

    public function saveFlag(): void
    {
        if (!$this->editingFlag) {
            return;
        }

        $flagsPath = config('features.flags_file', base_path('config/feature-flags.json'));
        $flags = json_decode(file_get_contents($flagsPath), true) ?? [];

        $flags[$this->editingFlag]['enabled'] = $this->enabled;
        $flags[$this->editingFlag]['percentage'] = $this->rolloutPercentage;

        file_put_contents($flagsPath, json_encode($flags, JSON_PRETTY_PRINT));

        FeatureFlag::load();
        $this->loadFlags();
        $this->editingFlag = null;

        session()->flash('success', 'Feature flag updated successfully.');
    }

    public function toggleFlag(string $name): void
    {
        $flagsPath = config('features.flags_file', base_path('config/feature-flags.json'));
        $flags = json_decode(file_get_contents($flagsPath), true) ?? [];

        $flags[$name]['enabled'] = !($flags[$name]['enabled'] ?? false);

        file_put_contents($flagsPath, json_encode($flags, JSON_PRETTY_PRINT));

        FeatureFlag::load();
        $this->loadFlags();
    }

    public function render()
    {
        return view('livewire.admin.features.feature-flag-manager');
    }
}
```

### Environment Promotion Pipeline

```yaml
# .github/workflows/promote.yml
name: Environment Promotion

on:
  workflow_dispatch:
    inputs:
      from_env:
        description: 'Source environment'
        required: true
        type: choice
        options:
          - development
          - staging
          - pre-production
      to_env:
        description: 'Target environment'
        required: true
        type: choice
        options:
          - staging
          - pre-production
          - production
      version:
        description: 'Version tag'
        required: true

jobs:
  promote:
    name: Promote ${{ inputs.from_env }} → ${{ inputs.to_env }}
    runs-on: ubuntu-latest
    environment: ${{ inputs.to_env }}
    steps:
      - uses: actions/checkout@v4

      - name: Validate Promotion Path
        run: |
          VALID_PATHS=(
            "development:staging"
            "staging:pre-production"
            "pre-production:production"
          )
          PROMOTION="${{ inputs.from_env }}:${{ inputs.to_env }}"
          if [[ ! " ${VALID_PATHS[@]} " =~ " ${PROMOTION} " ]]; then
            echo "Invalid promotion path: $PROMOTION"
            exit 1
          fi

      - name: Run Smoke Tests
        run: |
          # Run smoke tests against source environment
          SOURCE_URL=$(yq e ".environments.${{ inputs.from_env }}.url" environments.yml)
          php artisan test --testsuite=Smoke --env-from-url="$SOURCE_URL"

      - name: Run Database Compatibility Check
        run: |
          # Compare schemas between environments
          php artisan migrate:status --env=${{ inputs.from_env }}
          php artisan migrate:status --env=${{ inputs.to_env }}

      - name: Deploy to Target
        run: |
          TARGET_HOST=$(yq e ".environments.${{ inputs.to_env }}.host" environments.yml)
          ssh deploy@$TARGET_HOST << EOF
            cd /var/www/gsmui-${{ inputs.to_env }}
            git fetch origin
            git checkout ${{ inputs.version }}
            composer install --no-dev --optimize-autoloader
            php artisan migrate --force
            php artisan config:cache
            php artisan route:cache
            php artisan view:cache
            sudo systemctl restart php8.4-fpm
          EOF

      - name: Health Check
        run: |
          TARGET_URL=$(yq e ".environments.${{ inputs.to_env }}.url" environments.yml)
          for i in $(seq 1 12); do
            HTTP_STATUS=$(curl -s -o /dev/null -w "%{http_code}" "$TARGET_URL/health")
            if [ "$HTTP_STATUS" = "200" ]; then
              echo "Health check passed"
              exit 0
            fi
            sleep 5
          done
          echo "Health check failed"
          exit 1

      - name: Run Post-Deploy Tests
        run: |
          TARGET_URL=$(yq e ".environments.${{ inputs.to_env }}.url" environments.yml)
          php artisan test --testsuite=PostDeploy --env-from-url="$TARGET_URL"

      - name: Notify
        if: success()
        run: |
          curl -X POST ${{ secrets.SLACK_WEBHOOK }} \
            -H 'Content-type: application/json' \
            -d "{\"text\":\"Successfully promoted ${{ inputs.version }} from ${{ inputs.from_env }} to ${{ inputs.to_env }}\"}"
```

# Rollback Procedures

## Automated Rollback

### CI/CD Rollback Workflow

```yaml
# .github/workflows/rollback.yml
name: Rollback

on:
  workflow_dispatch:
    inputs:
      version:
        description: 'Version to rollback to'
        required: true
      environment:
        description: 'Target environment'
        required: true
        type: choice
        options:
          - staging
          - production
      reason:
        description: 'Rollback reason'
        required: true

jobs:
  rollback:
    name: Rollback to ${{ inputs.version }}
    runs-on: ubuntu-latest
    environment: ${{ inputs.environment }}
    steps:
      - uses: actions/checkout@v4
        with:
          ref: ${{ inputs.version }}

      - name: Capture Current State
        run: |
          CURRENT_VERSION=$(curl -s https://${{ inputs.environment }}.gsmui.com/health | jq -r '.version')
          echo "Rolling back from $CURRENT_VERSION to ${{ inputs.version }}"
          echo "ROLLBACK_FROM=$CURRENT_VERSION" >> $GITHUB_ENV

      - name: Notify Rollback Start
        run: |
          curl -X POST ${{ secrets.SLACK_WEBHOOK }} \
            -H 'Content-type: application/json' \
            -d "{\"text\":\"⚠️ Rollback initiated: ${ENVIRONMENT} rolling back from ${{ env.ROLLBACK_FROM }} to ${{ inputs.version }}\\nReason: ${{ inputs.reason }}\"}"

      - name: Execute Rollback
        run: |
          TARGET_HOST=$(yq e ".environments.${{ inputs.environment }}.host" environments.yml)
          ssh deploy@$TARGET_HOST << EOF
            cd /var/www/gsmui-${{ inputs.environment }}
            git fetch origin
            git checkout ${{ inputs.version }}
            composer install --no-dev --optimize-autoloader
            php artisan migrate:rollback --force
            php artisan config:cache
            php artisan route:cache
            php artisan view:cache
            sudo systemctl restart php8.4-fpm
          EOF

      - name: Health Check
        run: |
          TARGET_URL="https://${{ inputs.environment }}.gsmui.com"
          for i in $(seq 1 12); do
            HTTP_STATUS=$(curl -s -o /dev/null -w "%{http_code}" "$TARGET_URL/health")
            if [ "$HTTP_STATUS" = "200" ]; then
              echo "Health check passed"
              exit 0
            fi
            sleep 5
          done
          echo "Health check failed after rollback"
          exit 1

      - name: Notify Rollback Complete
        if: success()
        run: |
          curl -X POST ${{ secrets.SLACK_WEBHOOK }} \
            -H 'Content-type: application/json' \
            -d "{\"text\":\"✅ Rollback complete: ${{ inputs.environment }} is now on ${{ inputs.version }}\"}"

      - name: Notify Rollback Failed
        if: failure()
        run: |
          curl -X POST ${{ secrets.SLACK_WEBHOOK }} \
            -H 'Content-type: application/json' \
            -d "{\"text\":\"🔴 CRITICAL: Rollback failed on ${{ inputs.environment }}. Manual intervention required.\"}"
```

### Rollback Decision Tree

```text
Issue Detected
    │
    ├── Is the application responding?
    │   ├── YES → Is error rate > 5%?
    │   │   ├── YES → Automated rollback
    │   │   └── NO → Monitor, investigate
    │   └── NO → Immediate rollback
    │
    ├── Is data corruption detected?
    │   ├── YES → Stop traffic + rollback + restore backup
    │   └── NO → Continue assessment
    │
    ├── Is it a security vulnerability?
    │   ├── CRITICAL → Immediate rollback + incident response
    │   └── MEDIUM → Scheduled rollback
    │
    └── Is it a performance degradation?
        ├── SEVERITY HIGH → Rollback
        └── SEVERITY LOW → Hotfix or next window
```

### Rollback Verification Checklist

```markdown
## Post-Rollback Verification

- [ ] Application health check passing
- [ ] Error rate returned to baseline
- [ ] Response time within SLA
- [ ] Database state consistent
- [ ] Cache cleared and rebuilt
- [ ] Queue processing resumed
- [ ] Scheduled tasks running
- [ ] External integrations functional
- [ ] Monitoring alerts resolved
- [ ] Team notified of rollback status
```

# Backup Strategy

## Database Backups

```bash
#!/bin/bash
# backup-db.sh

BACKUP_DIR="/backups/mysql"
DATE=$(date +%Y-%m-%d_%H-%M-%S)
BACKUP_FILE="$BACKUP_DIR/gsmui_$DATE.sql.gz"

# Create backup
mysqldump -u $DB_USER -p$DB_PASSWORD gsmui | gzip > $BACKUP_FILE

# Upload to S3
aws s3 cp $BACKUP_FILE s3://gsmui-backups/mysql/ --sse AES256

# Clean local backups older than 7 days
find $BACKUP_DIR -name "*.sql.gz" -mtime +7 -delete

echo "Backup completed: $BACKUP_FILE"
```

## File Backups

```bash
#!/bin/bash
# backup-files.sh

BACKUP_DIR="/backups/files"
DATE=$(date +%Y-%m-%d_%H-%M-%S)
BACKUP_FILE="$BACKUP_DIR/gsmui_files_$DATE.tar.gz"

# Create backup
tar -czf $BACKUP_FILE \
    /var/www/gsmui/storage \

aws s3 cp $BACKUP_FILE s3://gsmui-backups/files/ --sse AES256

# Clean local backups older than 30 days

echo "Backup completed: $BACKUP_FILE"
```

# Risk Assessment

| Risk | Probability | Impact | Mitigation |
|------|-------------|--------|------------|
| Pipeline flakiness causes false failures | High | Medium | Quarantine flaky tests; retry logic; stability budget |
| Secrets leaked in CI/CD logs | Low | Critical | GitHub Actions secret masking; no echo commands; audit |
| Terraform state corruption | Low | High | State locking (DynamoDB); remote state; backup snapshots |
| Docker image vulnerabilities | Medium | High | Scanning in pipeline (Trivy); base image updates; minimal images |
| Deploy to wrong environment | Low | Critical | Environment protection rules; manual approval gates |
| Monitoring blind spots | Medium | Medium | Synthetic monitoring; canary deployments; user-facing checks |
| Cost overrun from unused resources | Medium | Medium | Resource tagging; automated cleanup; cost alerts |
| Team skill gaps in IaC | Medium | Low | Pair programming; documentation; training budget |

## Contingency Plans

- **Pipeline Failure**: Manual deploy process documented; on-call trained
- **Secrets Compromise**: Rotate all secrets; audit access logs; incident response
- **Infrastructure Outage**: Multi-AZ deployment; failover procedures tested monthly

# Brand Guidelines

## Pipeline Identity

- **Workflow Name**: "CI/CD Pipeline" (not "Build" or "Deploy")
- **Job Names**: Descriptive; verb-first — `validate`, `test`, `build`, `deploy`
- **Step Names**: Action-oriented — "Run PHP Lint", "Build Frontend Assets"

## Notification Voice

- **Success**: "Gsmui v2.15.1 deployed to staging. All checks passed."
- **Failure**: "Pipeline failed at test stage. 2 of 340 tests failing."
- **Warning**: "Build succeeded but code coverage dropped to 78%."
- **Rollback**: "Automatic rollback triggered. Previous version restored."

## Commit Message Convention

| Prefix | Use Case | Example |
|--------|----------|---------|
| `ci:` | Pipeline changes | `ci: add PHPStan to validate stage` |
| `deploy:` | Deployment config | `deploy: update Terraform to t3.medium` |
| `infra:` | Infrastructure changes | `infra: add Redis cluster for caching` |
| `ops:` | Operational changes | `ops: update alert thresholds for API latency` |
