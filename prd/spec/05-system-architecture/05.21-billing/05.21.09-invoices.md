# Invoice Number Format

## Format Specification

`INV-YYYY-NNNNNN`

| Component | Description | Example |
|-----------|-------------|---------|
| `INV` | Fixed prefix | INV |
| `YYYY` | 4-digit year | 2026 |
| `-` | Separator | - |
| `NNNNNN` | 6-digit sequential number | 000123 |

## Gap Prevention

| Mechanism | Description | Implementation |
|-----------|-------------|---------------|
| Database sequence | Auto-increment with row lock | MySQL/PostgreSQL sequence |
| Year rollover | Reset to 000001 each year | Scheduled job on Jan 1 |
| Gap detection | Daily audit for gaps | Cron job |
| Manual correction | Admin can fill gaps | Admin interface |

## Number Reservation

| Scenario | Behavior | Lock Duration |
|----------|----------|---------------|
| Concurrent generation | Pessimistic locking | Transaction scope |
| Failed generation | Release reserved number | On rollback |
| Manual generation | Reserve before render | 5 minutes |

## Invoice Line Item Calculation

```php
class InvoiceCalculator
{
    public function calculate(Subscription $subscription, Carbon $periodStart, Carbon $periodEnd): InvoiceLineItems
    {
        $lineItems = new InvoiceLineItems();

        // Base subscription amount
        $lineItems->add(new LineItem(
            description: "{$subscription->plan->name} (Monthly)",
            amount: $subscription->plan->price_cents,
            quantity: 1,
            tax_class: 'digital_services'
        ));

        // Usage-based charges
        if ($subscription->hasUsageBilling()) {
            $usage = $this->usageRepository->getUsageForPeriod(
                $subscription->user_id,
                $periodStart,
                $periodEnd
            );
            foreach ($usage as $metric => $quantity) {
                $rate = $subscription->plan->getUsageRate($metric);
                $lineItems->add(new LineItem(
                    description: "{$metric} ({$quantity} units)",
                    amount: $quantity * $rate,
                    quantity: 1,
                    tax_class: 'digital_services'
                ));
            }
        }

        // Proration for mid-cycle changes
        if ($subscription->hasProration()) {
            $proration = $this->prorationCalculator->calculate($subscription);
            $lineItems->add($proration);
        }

        // Addons
        foreach ($subscription->activeAddons() as $addon) {
            $lineItems->add(new LineItem(
                description: $addon->name,
                amount: $addon->price_cents,
                quantity: 1,
                tax_class: 'digital_services'
            ));
        }

        return $lineItems;
    }
}
```

## Invoice Number Generator - Detailed

```php
class InvoiceNumberGenerator
{
    public function generate(): string
    {
        $year = Carbon::now()->year;
        $prefix = "INV-{$year}-";

        return DB::transaction(function () use ($prefix) {
            $last = Invoice::where('number', 'LIKE', "{$prefix}%")
                ->lockForUpdate()
                ->orderByDesc('number')
                ->value('number');

            if ($last) {
                $sequence = (int) substr($last, -6) + 1;
            } else {
                $sequence = 1;
            }

            return $prefix . str_pad($sequence, 6, '0', STR_PAD_LEFT);
        });
    }
}
```

```php
    private const TRANSITIONS = [
        'draft' => ['issued', 'canceled'],
        'issued' => ['paid', 'overdue', 'canceled'],
        'paid' => ['refunded'],
        'overdue' => ['paid', 'canceled'],
        'canceled' => [],
        'refunded' => [],
    ];

    public function canTransition(string $from, string $to): bool
    {
        return in_array($to, self::TRANSITIONS[$from] ?? []);
    }

    public function transition(Invoice $invoice, string $to): void
    {
        if (!$this->canTransition($invoice->status, $to)) {
            throw new InvalidTransitionException(
                "Cannot transition from {$invoice->status} to {$to}"
            );
        }

        $invoice->update(['status' => $to]);
        $this->fireEvents($invoice, $to);
    }
}
```

```php
class InvoiceDeliveryPipeline
{
    public function deliver(Invoice $invoice, string $template): void
    {
        // 1. Render email
        $email = $this->renderEmail($invoice, $template);

        // 2. Attach PDF
        $pdfPath = $this->storage->getPdfPath($invoice);
        $email->attach($pdfPath, [
            'as' => "invoice-{$invoice->number}.pdf",
            'mime' => 'application/pdf',
        ]);

            'invoice_id' => $invoice->id,
            'template' => $template,
            'recipient' => $invoice->user->email,
        ]);
    }
}
```

# Invoice Conclusion

The GsmUi invoicing system provides comprehensive invoice generation, management, and delivery capabilities that integrate seamlessly with the billing module. With automated generation, PDF rendering, email delivery, and multi-currency support, the system handles all invoicing needs from launch through enterprise scale.

The modular architecture ensures long-term maintainability and developer productivity.

The GsmUi billing overview module establishes a robust, scalable financial infrastructure capable of handling subscriptions, one-time purchases, invoicing, and revenue tracking. By leveraging Stripe as the primary payment gateway with Paddle as a fallback, the system ensures 99.9% uptime and global payment coverage. The Laravel-native architecture integrates seamlessly with the existing Livewire/Alpine.js stack, maintaining consistency across the GsmUi ecosystem. With PCI-DSS compliance achieved through Stripe Elements (zero card data storage), comprehensive webhook processing, and automated invoice generation, the billing module is positioned to support GsmUi's growth from launch through enterprise scale. The modular design allows incremental feature additions (coupon engine, team billing, usage-based pricing) without architectural changes, ensuring long-term maintainability and developer productivity.
