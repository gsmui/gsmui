**Project:** GsmUi
**Architecture:** C4 Model – Level 2 (Container)
**Container:** Queue Workers

**Version:** 1.0.0

# Purpose

This document describes how GsmUi routes jobs to queues, manages priority ordering, and ensures critical workloads receive processing resources before less urgent tasks.

Queue priority is the primary mechanism for controlling job execution order when workers are contested.

---

# Responsibilities

Queue priority system is responsible for:

* Defining queue hierarchy
* Routing jobs to appropriate queues
* Enforcing priority ordering
* Preventing priority inversion
* Documenting queue selection criteria
* Managing queue-specific worker pools

---

# Queue Hierarchy

GsmUi defines eight logical queues ordered by priority:

```text
Priority 1 (Highest):  high
Priority 2:            default
Priority 3:            mail
Priority 4:            media
Priority 5:            search
Priority 6:            exports
Priority 7:            analytics
Priority 8 (Lowest):   backups
```

Higher-priority queues have dedicated worker pools that are never starved by lower-priority work.

# Queue Selection Criteria

Jobs are routed to queues based on their urgency, resource requirements, and failure impact.

| Queue | Criteria | Examples |
|-------|----------|----------|
| `high` | User-facing, time-sensitive, or transactional | Password resets, verification emails, webhooks, payment confirmations |
| `default` | General application jobs not in other queues | Notifications, status updates, general background tasks |
| `mail` | All email delivery | Transactional emails, marketing emails, newsletters |
| `media` | Resource-intensive processing | Image resizing, video transcoding, format conversion |
| `search` | Index maintenance | Search index updates, document sync, synonym updates |
| `exports` | Data export operations | CSV exports, PDF generation, bulk data pulls |
| `analytics` | Aggregation and reporting | Daily aggregations, event processing, metric calculations |
| `backups` | Maintenance and infrastructure | Database backups, storage cleanup, log rotation |

# Queue Routing Rules

Jobs are routed to queues using Laravel's `onQueue()` method:

```php
class SendVerificationEmail implements ShouldQueue
{
    public function handle()
    {
        // High priority — user is waiting
    }
}

// Dispatched to high queue
SendVerificationEmail::dispatch($user)->onQueue('high');

class ProcessMedia implements ShouldQueue
{
    public function handle()
    {
        // Low priority — can wait
    }
}

// Dispatched to media queue
ProcessMedia::dispatch($file)->onQueue('media')->delay(now()->addMinutes(5));
```

# Priority Inversion Prevention

Priority inversion occurs when a high-priority job is blocked because all workers are busy processing low-priority jobs.

GsmUi prevents priority inversion by:

1. **Dedicated worker pools** — Each queue has its own worker pool. High-priority workers never process low-priority jobs.
2. **Separate supervisor groups** — Each supervisor manages one queue only.
3. **Worker count allocation** — High-priority queues have proportionally more workers.

---

# Worker Count Allocation

Worker counts are allocated based on expected throughput and latency requirements:

| Queue | Workers | Rationale |
|-------|---------|-----------|
| `high` | 6 | User-facing latency-sensitive jobs need fast processing |
| `default` | 4 | General purpose, moderate throughput |
| `mail` | 3 | External SMTP latency limits throughput |
| `media` | 4 | Resource-intensive but batchable |
| `search` | 2 | Periodic bulk updates, low steady-state |
| `exports` | 2 | Long-running, triggered by users |
| `analytics` | 2 | Background, non-urgent |
| `backups` | 1 | Nightly, single job at a time |

---

# Queue Weight

Worker counts represent the relative weight of each queue:

```text
Total workers: 24

high:      6/24 = 25%
default:   4/24 = 17%
mail:      3/24 = 12.5%
media:     4/24 = 17%
search:    2/24 = 8.3%
exports:   2/24 = 8.3%
analytics: 2/24 = 8.3%
backups:   1/24 = 4.2%
```

This allocation ensures that the most critical workloads receive the most processing capacity.

# Fallback Queues

If a job's target queue is unavailable, it falls back to the `default` queue:

```php
// Queue connection fallback
'connections' => [
    'redis' => [
        'driver' => 'redis',
        'connection' => 'default',
        'queue' => env('REDIS_QUEUE', 'default'),
        'retry_after' => 120,
    ],
],
```

This ensures jobs are not lost if a queue is temporarily unavailable.

---

# Priority in Batch Operations

Laravel batches process jobs in parallel. Batch jobs inherit the queue of the parent batch unless overridden:

```php
Bus::batch([
    new ProcessItem($item1),
    new ProcessItem($item2),
    new ProcessItem($item3),
])->onQueue('media')
  ->dispatch();
```

Batch jobs use the batch's queue, ensuring consistent priority across all batch items.

# Rate-Limited Queues

Some queues benefit from rate limiting to protect downstream services:

```php
class SendBulkEmail implements ShouldQueue
{
    use Dispatchable, InteractsWithQueue, Queueable, SerializesModels;

    public function handle()
    {
        Mail::to($this->user)->send(new Notification());
    }

// Rate-limited to 100 jobs per minute
SendBulkEmail::dispatch($user)
    ->onQueue('mail')
    ->rateLimited('mail');
```

Laravel's `RateLimited` middleware controls the dispatch rate.

# Summary

Queue priorities ensure that critical workloads receive processing resources before less urgent tasks. By dedicating worker pools to each queue and routing jobs based on urgency, GsmUi prevents priority inversion and maintains predictable processing latency for user-facing operations.

# Queue Priority Deep Dive

## Priority Enforcement Mechanism

Queue priority is enforced at the infrastructure level, not the application level. Workers are dedicated to specific queues, so high-priority jobs are never competing with low-priority jobs for worker resources.

```text
Without isolation (broken):
┌──────────────────────────────────────┐
│  Shared Worker Pool                   │
│  ├─ Processing: GenerateExport (slow) │
│  ├─ Waiting: SendEmail (urgent!)      │
│  └─ Waiting: ProcessPayment (urgent!) │
└──────────────────────────────────────┘
Priority inversion: urgent jobs blocked by slow job

With isolation (correct):
┌──────────────────────────────────────┐  ┌──────────────────────────────────────┐
│  High Priority Pool                   │  │  Exports Pool                         │
│  ├─ Processing: SendEmail             │  │  ├─ Processing: GenerateExport        │
│  └─ Worker available for payment      │  │  └─ Worker available for next export  │
└──────────────────────────────────────┘  └──────────────────────────────────────┘
No priority inversion: separate worker pools
```

---

## Priority Guarantees

GsmUi provides the following priority guarantees:

| Guarantee | Description |
|-----------|-------------|
| No starvation | High-priority queues always have dedicated workers |
| Bounded latency | High-priority jobs processed within 10 seconds |
| Resource isolation | Queue workers do not share resources |
| Failure isolation | A failing queue does not affect other queues |
| Capacity reservation | Each queue has reserved worker capacity |

---

## Priority Metrics

Track priority effectiveness through these metrics:

| Metric | Description | Target |
|--------|-------------|--------|
| Queue latency per queue | Time from dispatch to processing | Varies by queue |
| Worker idle time per queue | Time workers spend waiting for jobs | <20% |
| Queue depth ratio | Depth of high vs low priority queues | High queue always < Low queue |
| Priority inversion events | Times high-priority job waited for low-priority | 0 |

# Queue Routing Implementation

## Route by Job Class

Each job class declares its queue in the class definition:

```php
class SendVerificationEmail implements ShouldQueue
{
    use Dispatchable, InteractsWithQueue, Queueable, SerializesModels;

    public string $queue = 'high';

    public function handle(): void
    {
        // Processing logic
    }
}
```

---

## Route by Dispatch Call

Override the queue at dispatch time:

```php
// Default queue (from class)
SendVerificationEmail::dispatch($user);

// Explicit queue
SendVerificationEmail::dispatch($user)->onQueue('high');

// With delay
ProcessMedia::dispatch($file)->onQueue('media')->delay(now()->addMinutes(5));

// With connection
ProcessMedia::dispatch($file)->onConnection('redis')->onQueue('media');
```

---

## Route by Middleware

Use middleware to dynamically route jobs:

```php
class RouteByPriority implements ShouldQueue
{
    use Dispatchable, InteractsWithQueue, Queueable, SerializesModels;

    public function middleware(): array
    {
        return [new RouteToQueue()];
    }

    public function handle(): void
    {
        // Processing logic
    }
}

class RouteToQueue
{
    public function handle(object $job, Closure $next): void
    {
        if ($job->isUrgent()) {
            $job->onQueue('high');
        } elseif ($job->isBulk()) {
            $job->onQueue('exports');
        } else {
            $job->onQueue('default');
        }

        $next($job);
    }
}
```

# Rate-Limited Queue Patterns

Some queues benefit from rate limiting to protect downstream systems:

## Email Rate Limiting

```php
class SendEmail implements ShouldQueue
{
    use Dispatchable, InteractsWithQueue, Queueable, SerializesModels;

    public function middleware(): array
    {
        return [
            (new WithoutOverlapping('email'))->dontRelease(),
            new RateLimited('email'),
        ];
    }

    public function handle(): void
    {
        Mail::to($this->recipient)->send($this->message);
    }
}

// Rate limit configuration
// AppServiceProvider.php
RateLimiter::for('email', function () {
    return Limit::perMinute(100);
});
```

# Queue Priority Anti-Patterns

| Anti-Pattern | Problem | Fix |
|-------------|---------|-----|
| All jobs on `high` | No priority differentiation | Use proper queue selection |
| All jobs on `default` | No isolation between workloads | Separate by resource needs |
| Dynamic queue in job | Unpredictable routing | Declare queue in class |
| Queue hopping | Confusing job lifecycle | Pick one queue per job type |
| No delay on bulk jobs | Thundering herd | Use staggered delays |

# Queue Documentation Standards

Every job class must document its queue selection:

```php
/**
 * Process uploaded media files for display.
 *
 * This job handles image resizing, thumbnail generation, and format
 * conversion. It is dispatched to the media queue because it is
 * resource-intensive and does not require immediate processing.
 *
 * @queue media
 * @priority low
 * @timeout 300
 * @tries 3
 * @backoff [30, 60, 120]
 *
 * @see docs/queue-routing.md
 */
class ProcessMedia implements ShouldQueue
{
    use Dispatchable, InteractsWithQueue, Queueable, SerializesModels;

    public string $queue = 'media';
    public int $timeout = 300;
    public int $tries = 3;

    public function backoff(): array
    {
        return [30, 60, 120];
    }

    public function handle(MediaProcessor $processor): void
    {
        $processor->convert($this->file);
    }
}
```

# Queue Priority Implementation Details

## Queue Selection Algorithm

The queue selection algorithm determines which queue a job is dispatched to:

```text
Job Dispatch
    │
    ▼
┌─────────────────────┐
│ Job has explicit     │──Yes──▶ Use explicit queue
│ queue assignment?    │
└─────────────────────┘
    │ No
    ▼
┌─────────────────────┐
│ Job class has        │──Yes──▶ Use class queue
│ queue property?      │
└─────────────────────┘
    │ No
    ▼
┌─────────────────────┐
│ Job implements       │──Yes──▶ Use viaQueues()
│ viaQueues()?         │
└─────────────────────┘
    │ No
    ▼
┌─────────────────────┐
│ Use default queue    │
│ (config/queue.php)   │
└─────────────────────┘
```

---

## Queue Selection Priority

```text
Priority 1: Explicit onQueue() at dispatch time
Priority 2: Job class $queue property
Priority 3: Job class viaQueues() method
Priority 4: Default queue from config/queue.php
```

```php
class QueueDrainMonitor
{
    public function getDrainRate(string $queue): float
    {
        $startDepth = $this->getDepthAt($queue, now()->subMinutes(5));
        $endDepth = $this->getDepthAt($queue, now());
        
        $timeDiff = 5; // minutes
        $depthDiff = $startDepth - $endDepth;
        
        return $depthDiff / $timeDiff; // jobs per minute
    }

    public function estimateClearTime(string $queue): int
    {
        $currentDepth = Redis::llen("queues:{$queue}");
        $drainRate = $this->getDrainRate($queue);
        
        if ($drainRate <= 0) {
            return PHP_INT_MAX; // Queue is growing
        }
        
        return (int) ceil($currentDepth / $drainRate); // minutes
    }
}
```

## Queue Sharding

```php
class ShardedQueue
{
    public function __construct(
        private int $shardCount = 4,
    ) {}

    public function dispatch(string $queue, object $job): void
    {
        $shard = $this->getShard($job);
        $shardedQueue = "{$queue}:shard:{$shard}";
        
        $job->onQueue($shardedQueue)->dispatch();
    }

    private function getShard(object $job): int
    {
        $hash = crc32(serialize($job));
        return $hash % $this->shardCount;
    }

    public function getDepth(string $queue): int
    {
        $totalDepth = 0;
        
        for ($i = 0; $i < $this->shardCount; $i++) {
            $totalDepth += Redis::llen("{$queue}:shard:{$i}");
        }
        
        return $totalDepth;
    }
}
```

## Priority Queue with Weighted Routing

```php
class WeightedQueueRouter
{
    private array $weights = [
        'high' => 10,
        'default' => 5,
        'mail' => 3,
        'media' => 2,
        'search' => 1,
        'exports' => 1,
        'analytics' => 1,
        'backups' => 1,
    ];

    public function getNextQueue(): string
    {
        $totalWeight = array_sum($this->weights);
        $random = mt_rand(1, $totalWeight);
        
        $current = 0;
        foreach ($this->weights as $queue => $weight) {
            $current += $weight;
            if ($random <= $current) {
                return $queue;
            }
        }
        
        return 'default';
    }
}
```

## Queue Priority with Circuit Breaker

```php
class CircuitBreakerQueue
{
    private array $circuitBreakers = [];

    public function dispatch(string $queue, object $job): void
    {
        if ($this->isCircuitOpen($queue)) {
            $job->onQueue('default')->dispatch();
            return;
        }
        
        try {
            $job->onQueue($queue)->dispatch();
            $this->recordSuccess($queue);
        } catch (\Exception $e) {
            $this->recordFailure($queue);
            $job->onQueue('default')->dispatch();
        }
    }

    private function isCircuitOpen(string $queue): bool
    {
        $breaker = $this->circuitBreakers[$queue] ?? null;
        
        if (!$breaker) {
            return false;
        }
        
        return $breaker['failures'] >= 5 && 
               $breaker['last_failure'] > now()->subMinutes(5);
    }
}
```

# Queue Priority Migration Guide

## Migrating Jobs Between Queues

```php
class QueueMigrationCommand extends Command
{
    protected $signature = 'queue:migrate 
                            {from : Source queue}
                            {to : Destination queue}
                            {--limit=1000 : Maximum jobs to migrate}';

    public function handle(): int
    {
        $from = $this->argument('from');
        $to = $this->argument('to');
        $limit = $this->option('limit');
        
        $migrated = 0;
        
        while ($migrated < $limit) {
            $job = Redis::rpop("queues:{$from}");
            
            if (!$job) {
                break;
            }
            
            Redis::lpush("queues:{$to}", $job);
            $migrated++;
        }
        
        $this->info("Migrated {$migrated} jobs from {$from} to {$to}");
        
        return self::SUCCESS;
    }
}
```
