# Purpose

This document describes how GsmUi uses Laravel's batch, chain, and chunking features to coordinate multi-job operations. Batch processing enables parallel execution, progress tracking, and atomic completion semantics for groups of related jobs.

---

# Responsibilities

Batch processing is responsible for:

* Grouping related jobs into batches
* Processing batch jobs in parallel
* Tracking batch progress
* Executing batch completion callbacks
* Handling batch cancellation
* Implementing job chains
* Processing large datasets via chunking

---

# Batch Processing Overview

Laravel batches allow multiple jobs to be dispatched and processed as a unit with:

* **Parallel execution** — Jobs run concurrently across workers
* **Progress tracking** — Batch status is queryable in real time
* **Completion callbacks** — Actions triggered when all jobs finish
* **Failure handling** — Batch-level failure callbacks
* **Cancellation** — Entire batch can be cancelled mid-execution

# Creating a Batch

```php
use Illuminate\Bus\Batch;
use Illuminate\Support\Facades\Bus;

$batch = Bus::batch([
    new ProcessItem($item1),
    new ProcessItem($item2),
    new ProcessItem($item3),
    // ... potentially thousands of jobs
])->onQueue('media')
  ->then(function (Batch $batch) {
      // All jobs completed successfully
      Log::info('Batch completed', ['batch' => $batch->id]);
  })
  ->catch(function (Batch $batch, Throwable $e) {
      // First batch job failure detected
      Log::error('Batch failed', ['batch' => $batch->id, 'error' => $e]);
  })
  ->finally(function (Batch $batch) {
      // Batch cleanup (runs on success or failure)
      Cache::forget('batch:' . $batch->id);
  })
  ->name('Process Media Batch')
  ->dispatch();
```

---

# Batch State

A batch transitions through the following states:

```text
pending → processing → completed
                → cancelled
                → failed
```

| State | Description |
|-------|-------------|
| `pending` | Batch created, jobs not yet processed |
| `processing` | At least one job is processing |
| `completed` | All jobs finished successfully |
| `cancelled` | Batch was cancelled mid-execution |
| `failed` | A job failed and batch is not continuing |

# Batch Progress

Batch progress is tracked in Redis:

```text
Key: laravel:batch:{batch-id}
Fields:
  - total_jobs
  - pending_jobs
  - failed_jobs
  - processed_jobs
  - finished_at
  - cancelled_at
  - options
```

Progress is queryable via the batch ID:

```php
$batch = Bus::findBatch($batchId);

echo $batch->finished();  // bool
echo $batch->progress();  // percentage (0-100)
echo $batch->pendingJobs; // int
echo $batch->failedJobs;  // int
```

# Batch Completion Callbacks

### then()

Called when all jobs in the batch complete successfully:

```php
->then(function (Batch $batch) {
    // All jobs succeeded
    Notification::send($user, new BatchCompleteNotification($batch));
})
```

### catch()

Called when a job fails (first failure only by default):

```php
->catch(function (Batch $batch, Throwable $e) {
    // Handle batch failure
    Log::error('Batch failed', ['batch' => $batch->id]);
    Notification::send($admin, new BatchFailedNotification($batch));
})
```

### finally()

Called when the batch finishes regardless of outcome:

```php
->finally(function (Batch $batch) {
    // Cleanup
    Cache::forget('batch:' . $batch->id);
    $this->updateBatchStatus($batch);
})
```

# Job Chains

Job chains execute jobs sequentially — each job starts only after the previous job completes successfully.

```php
use Illuminate\Foundation\Bus\PendingChain;

ProcessMedia::withChain([
    new GenerateThumbnails($file),
    new UpdateSearchIndex($file),
    new NotifyUser($user),
])->onQueue('media')
  ->dispatch();
```

If any job in the chain fails, subsequent jobs are not dispatched.

---

# Chunking Large Datasets

For processing large datasets, use chunking to process records in batches:

```php
// Process 10,000 records in chunks of 100
Model::chunk(100, function ($records) {
    Bus::batch($records->map(fn ($record) => new ProcessRecord($record)))
        ->onQueue('exports')
        ->dispatch();
});
```

Chunking prevents memory exhaustion and provides natural retry boundaries.

# Batch Options

Batches support configurable options:

```php
$batch = Bus::batch([
    // jobs...
])->onQueue('media')
  ->allowFailures()  // Continue processing even if some jobs fail
  ->backoff(60)      // Delay before retrying failed jobs (seconds)
  ->then(...)
  ->catch(...)
  ->finally(...)
  ->dispatch();
```

| Option | Purpose |
|--------|---------|
| `allowFailures()` | Continue batch despite individual job failures |
| `backoff(seconds)` | Retry delay for failed batch jobs |
| `name(string)` | Human-readable batch name for debugging |

# Batch Cancellation

Batches can be cancelled programmatically:

```php
$batch = Bus::findBatch($batchId);

if ($batch && !$batch->finished()) {
    $batch->cancel();
}
```

When cancelled:

* Remaining unprocessed jobs are not started
* Currently processing jobs are allowed to complete
* `finally()` callback is triggered

# Batch vs. Individual Jobs

Use batches when:

* Jobs are related and share a completion point
* Progress tracking is needed
* Atomic completion semantics are required
* Cancellation is a requirement

Use individual jobs when:

* Jobs are independent
* No coordination is needed
* Simplicity is preferred

# Batch Performance Considerations

* Large batches (10,000+ jobs) consume Redis memory for batch state

# Error Handling in Batches

When a batch job fails:

1. Exception is recorded in batch state
2. `catch()` callback is triggered (if defined)
3. Job is retried per retry policy
4. If retries exhausted, job moves to DLQ
5. Remaining batch jobs continue if `allowFailures()` is set

---

* Batch data is stored in Redis and should not contain sensitive payloads
* Batch names are logged — avoid including PII in names
* Batch completion callbacks should verify authorization before triggering actions

# Advanced Batch Patterns

## Nested Batches

Batches can contain other batches:

```php
$outerBatch = Bus::batch([
    Bus::batch([
        new ProcessItem($item1),
        new ProcessItem($item2),
    ])->onQueue('media')->name('Sub-batch 1'),
    Bus::batch([
        new ProcessItem($item3),
        new ProcessItem($item4),
    ])->onQueue('media')->name('Sub-batch 2'),
])->onQueue('media')
  ->then(function (Batch $batch) {
      Log::info('All sub-batches complete');
  })
  ->dispatch();
```

Nested batch behavior:

* Each sub-batch tracks its own progress
* Outer batch completes when all sub-batches complete
* Failure in one sub-batch does not affect others
* Progress is aggregate of all sub-batches

## Batch with Progress Reporting

```php
class ProcessLargeDataset implements ShouldQueue
{
    use Batchable;

    public function handle(): void
    {
        $records = $this->getRecords();
        $total = count($records);
        
        foreach ($records as $index => $record) {
            if ($this->batch()?->cancelled()) {
                return;
            }

            $this->processRecord($record);

            // Report progress every 100 records
            if (($index + 1) % 100 === 0) {
                $progress = (($index + 1) / $total) * 100;
                Log::info("Batch progress", [
                    'batch_id' => $this->batch()?->id,
                    'progress' => round($progress, 2),
                    'processed' => $index + 1,
                    'total' => $total,
                ]);
            }
        }
    }
}
```

## File Chunking

```php
class ProcessLargeFile implements ShouldQueue
{
    public function handle(): void
    {
        $handle = fopen($this->filePath, 'r');
        $chunkSize = 1000;
        $chunk = [];
        $lineNumber = 0;

        while (($line = fgets($handle)) !== false) {
            $chunk[] = $line;
            $lineNumber++;

            if (count($chunk) >= $chunkSize) {
                $this->processChunk($chunk);
                $chunk = [];
            }
        }

        // Process remaining lines
        if (!empty($chunk)) {
            $this->processChunk($chunk);
        }

        fclose($handle);
    }
}
```

## API Chunking

```php
class SyncExternalData implements ShouldQueue
{
    public function handle(): void
    {
        $page = 1;
        $perPage = 100;

        do {
            $response = Http::withToken($this->apiToken)
                ->get($this->apiUrl, [
                    'page' => $page,

                    ->dispatch();
            }

            $page++;
        } while ($hasMore);

}
```

# Batch Error Handling

## Allow Failures

```php
$batch = Bus::batch([
    new ProcessItem($item1),
    new FailingItem(), // This will fail
    new ProcessItem($item3),
])->onQueue('media')
  ->allowFailures() // Continue processing despite failures
  ->then(function (Batch $batch) {
      Log::info("Batch complete: {$batch->processedJobs}/{$batch->totalJobs} succeeded");
  })
  ->catch(function (Batch $batch, Throwable $e) {
      Log::error("Batch failed: {$e->getMessage()}");
  })
  ->finally(function (Batch $batch) {
      Log::info("Batch finished", [
          'total' => $batch->totalJobs,
          'processed' => $batch->processedJobs,
          'failed' => $batch->failedJobs,
      ]);
  })
  ->dispatch();
```

---

## Custom Failure Handling

```php
class ProcessItem implements ShouldQueue
{
    use Batchable;

    public function handle(): void
    {
        try {
            $this->process();
        } catch (ValidationException $e) {
            // Log and skip — don't count as failure
            Log::warning('Validation failed', ['item' => $this->item->id]);
            return;
        } catch (ConnectionException $e) {
            // Transient — retry
            throw $e;
        } catch (\Exception $e) {
            // Permanent failure
            $this->fail($e);
        }
    }
}
```

# Batch Performance Optimization

## Optimal Batch Size

```text
Small batch (10-50 jobs):
  ✓ Fast completion
  ✓ Low memory usage
  ✓ Easy to track
  ✗ High per-job overhead

Medium batch (100-500 jobs):
  ✓ Balanced overhead
  ✓ Good throughput
  ✓ Manageable progress tracking

Large batch (1000+ jobs):
  ✓ Low per-job overhead
  ✓ High throughput
  ✗ High memory for batch state
  ✗ Harder to track progress
```

## Batch Redis Memory

Batch state is stored in Redis. For large batches:

```text
Batch with 1000 jobs:
  - Redis key: ~1 KB
  - Job IDs: ~10 KB
  - State: ~1 KB
```

# Batch Best Practices

1. **Use meaningful batch names** — Help operators identify batch purpose
2. **Set appropriate timeouts** — Prevent batches from hanging indefinitely
3. **Handle failures gracefully** — Use `allowFailures()` when appropriate
4. **Monitor batch progress** — Track completion and failure rates
5. **Use sub-batches for large datasets** — Limit Redis memory usage
6. **Test batch callbacks** — Verify `then()`, `catch()`, and `finally()` work correctly
7. **Document batch use cases** — Explain why batches are used
8. **Implement idempotent jobs** — Ensure batch jobs can be safely retried
9. **Use batch cancellation** — Allow batches to be cancelled when no longer needed
10. **Archive batch results** — Store batch outcomes for auditing

## Dynamic Batch Sizing

```php
class DynamicBatchSizer
{
    public function createBatches(array $items, int $maxBatchSize = 500): array
    {
        $batches = [];
        $chunks = collect($items)->chunk($maxBatchSize);
        
        foreach ($chunks as $index => $chunk) {
            $batches[] = Bus::batch(
                $chunk->map(fn ($item) => new ProcessItem($item))
            )->onQueue('media')
              ->name("Batch " . ($index + 1))
              ->then(function (Batch $batch) {
                  Log::info("Batch {$batch->name} completed");
              })
```

```php
class BatchErrorHandler
{
    public function handle(Batch $batch, Throwable $exception): void
    {
        // Classify the error
        $classification = $this->classifyError($exception);
        
        switch ($classification) {
            case 'transient':
                $this->retryFailedJobs($batch);
                break;
            case 'permanent':
                $this->logAndAlert($batch, $exception);
                break;
            case 'resource':
                $this->scaleAndRetry($batch);
                break;
            default:
                $this->logAndAlert($batch, $exception);
        }
    }

    private function classifyError(Throwable $exception): string
    {
        return match (true) {
            $exception instanceof ConnectionException => 'transient',
            $exception instanceof TimeoutException => 'transient',
            $exception instanceof MemoryException => 'resource',
            $exception instanceof ValidationException => 'permanent',
            default => 'unknown',
        };
    }
}
```

## Batch Failure Recovery

```php
class BatchRecovery
{
    public function recover(Batch $batch): void
    {
        $failedJobs = $batch->failedJobs();
        
        foreach ($failedJobs as $jobId) {
            $job = DB::table('failed_jobs')->where('uuid', $jobId)->first();
            
            if ($job && $this->shouldRetry($job)) {
                $this->retryJob($job);
            }
        }
    }

    private function shouldRetry($job): bool
    {
        $payload = json_decode($job->payload, true);
        $exception = $job->exception;
        
        // Don't retry permanent failures
        if (str_contains($exception, 'ValidationException')) {
            return false;
        }
        
        // Don't retry if max attempts exceeded
        if ($payload['attempts'] >= 5) {
            return false;
        }
        
        return true;
    }
}
```

```php
class BatchProgressTracker
{
    public function track(string $batchId): array
    {
        $batch = Bus::findBatch($batchId);
        
        if (!$batch) {
            return ['error' => 'Batch not found'];
        }
        
        return [
            'id' => $batch->id,
            'name' => $batch->name,
            'total_jobs' => $batch->totalJobs,
            'processed_jobs' => $batch->processedJobs,
            'failed_jobs' => $batch->failedJobs,
            'pending_jobs' => $batch->pendingJobs,
            'progress' => $batch->progress(),
            'finished' => $batch->finished(),
            'cancelled' => $batch->cancelled(),
            'created_at' => $batch->createdAt,
            'finished_at' => $batch->finishedAt,
            'estimated_completion' => $this->estimateCompletion($batch),
        ];
    }

    private function estimateCompletion(Batch $batch): ?string
    {
        if ($batch->finished()) {
            return null;
        }
        
        $elapsed = $batch->finishedAt
            ? $batch->finishedAt->diffInSeconds($batch->createdAt)
            : now()->diffInSeconds($batch->createdAt);
        
        $rate = $batch->processedJobs / max(1, $elapsed);
        $remaining = $batch->pendingJobs;
        
        $estimatedSeconds = $remaining / max(1, $rate);
        
        return now()->addSeconds($estimatedSeconds)->toISOString();
    }
}
```

```php
class BatchSecurity
{
    public function validateBatch(array $jobs): bool
    {
        foreach ($jobs as $job) {
            if (!$this->isAuthorized($job)) {
                return false;

        $user = auth()->user();

        }

        return $user->can('dispatch', $job);
```
