# Versioning System

## Revision Model

- Every save creates a revision (draft autosaves: rolling 20 kept; publish snapshots: kept forever).
- Named snapshots on publish with version label (v1, v2, ...).
- Compare view: side-by-side markdown diff with change highlighting.
- Restore action creates a new revision pointing to old content (non-destructive).

## Revision List UI

| Column | Behavior |
|--------|----------|
| Timestamp | Editor timezone |
| Editor | Avatar + name |
| Type | Autosave / Snapshot / Restore |
| Summary | Auto-generated ("Updated installation steps section") |
| Actions | View, Compare with current, Restore |

## Restore Guardrails

- Restore requires `documentation.publish` if page is currently published.
- Restore triggers re-validation checklist before going live.
- Audit entry with revision refs.

# Admin User Flows

## Flow: Write and Publish an Installation Guide

| Step | Action | Outcome |
|------|--------|---------|
| 1 | Docs > New page | Template picker: Blank / Installation / API / Tutorial |
| 2 | Choose Installation template | Scaffold with required sections |
| 3 | Write content, insert demos | Autosave indicator active |
| 4 | Fill SEO panel | Snippet preview live |
| 5 | Run publish checklist | Blocking issues listed |
| 6 | Fix alt texts | Checklist item clears |
| 7 | Publish | Page live, cache invalidated, notification to watchers |
| 8 | View public | Verify rendering, demo component boots |

## Flow: Emergency Correction to Published Page

| Step | Action | Outcome |
|------|--------|---------|
| 1 | Report of wrong command in docs | Admin opens page |
| 2 | Edit + save | New revision created immediately (autosave live for published pages) |
| 3 | Review diff | Compare with previous snapshot |
| 4 | Publish correction | Cache purged within 60s |
| 5 | Audit | Correction logged with reason |

## Flow: Import Legacy Docs

| Step | Action | Outcome |
|------|--------|---------|
| 1 | Import page > upload zip (markdown + images) | Validation report |
| 2 | Mapping screen | Assign target chapters per file |
| 3 | Dry run preview | Diffs shown per page |
| 4 | Confirm import | Pages created as drafts |
| 5 | Bulk review | Checklist + publish wave |
| 6 | Redirects | Old slug → new slug map auto-generated |

## Flow: Localization Workflow

| Step | Action | Outcome |
|------|--------|---------|
| 1 | Base page published in `en` | Translation task auto-created for `es`, `de` |
| 2 | Translator opens task | Side-by-side base + target editor |
| 3 | Save translation | Status per locale tracked |
| 4 | Publish translated version | Locale route serves, hreflang updated |
| 5 | Base page updated later | Translations flagged stale with diff |

## Flow: Deprecated Page Lifecycle

| Step | Action | Outcome |
|------|--------|---------|
| 1 | Mark page deprecated | Banner editor: version notice + successor link |
| 2 | Public banner shows | "This applies to v1; see v3 docs" |
| 3 | After sunset period | Unpublish via schedule |
| 4 | Redirect rule | Slug → successor permanent |

## PUT Page Request (Partial)

```json
{
  "title": "Install GsmUi Pro",
  "slug": "install-gsmui-pro",
  "chapter_id": 4,
  "body_markdown": "---\ntitle: Install\n---\n# Install GsmUi Pro\n...",
  "seo": { "seo_title": "Install GsmUi Pro | Docs", "seo_description": "..." },
  "base_revision_id": 128
}
```

Response 409 on `base_revision_id` mismatch with current revision for concurrent edit safety.

## Publish Request

```json
{
  "acknowledged_warnings": ["code-block-language-missing"],
  "schedule_at": null
}
```

## Autosave Protocol

| Event | Behavior |
|-------|----------|
| Content change | Debounce 10s → PUT revision (type: autosave) |
| Tab hidden | Immediate save flush |
| Save conflict | 409 → conflict banner (keep mine / take theirs) |
| Offline | Queue locally; sync on reconnect with conflict check |
| Indicator states | Saving (pulse) / Saved (check) / Error (retry) |

Rolling window: keep last 20 autosaves; pruned job nightly.

## Editing Lock

- Opening editor acquires soft lock (5 min TTL, heartbeat 60s).
- Second editor sees read-only banner with lock owner + steal-lock action (audited).
- Steal-lock confirms impact ("Jane has unsaved changes indicator unknown — steal?").
- Locks released on route leave/crash detection (TTL).

|----------|--------------------|
| Installation | Prerequisites, Package install, Provider setup, Verify |
| Configuration | Options table, Environment variables, Defaults |
| API Reference | Methods table, Params, Returns, Examples |
| Tutorial | Objective, Steps (numbered), Troubleshooting, Next |
| Migration | Breaking changes, Upgrade steps, Rollback |

Scaffolds insert markdown skeletons + required-block markers checked by publish validation.

# Translation Workflow (Detailed)

## Task Lifecycle

```
base_published --> task_created --> in_translation --> review --> published
                                              \--> stale (base changed)
```

| State | Description |
|-------|-------------|
| task_created | Auto-created for each enabled locale |
| in_translation | Translator assigned (self-claim) |
| review | Peer/lead review required for regulated content |
| published | Locale live |
| stale | Base revision changed; diff shown, re-review needed |

## Assignment Rules

- Translators claim tasks in language queue; max 5 active claims.
- Priority scoring: page views × staleness age.
- Machine-assisted prefill optional (flagged for mandatory human review).

## Staleness Detection

| Trigger | Action |
|---------|--------|
| Base page publish | Compare `base_revision_id` on translations → mark stale |
| Stale publish attempt | Blocked with diff view requirement |
| Stale > 30 days | Report to content lead |

## hreflang & SEO

- Published translations emit hreflang link set.
- Canonical points to base locale unless translation overrides.
- Sitemap includes all locale variants.

# Docs Module Runbooks

## Symptom: Published page showing stale content

1. Verify purge job ran (log with purge tag).
2. Check edge `X-Cache-Age`; manual purge action from page header.
3. Confirm no deploy lock blocking purges.
4. If bundle-related, trigger demo bundle purge batch.

## Symptom: Import job stuck in validating

1. Inspect import report for malformed entries.
2. Re-upload corrected bundle (previous marked failed).
3. If systemic, check zip traversal scanner health.

## Symptom: Translation publish blocked unexpectedly

1. Check staleness diff — base revision changed.
2. Review required: translator re-reviews diff, clears stale flag.
3. Audit records override if lead force-publishes (permission `documentation.force-publish`).

## Symptom: Publish scheduler missed target

1. Verify scheduler heartbeat (health probe).
2. Check job queue health.
3. Manual dispatch with audit note; alert configured for > 30s drift.

- **Then** 409 with conflict banner offering keep-mine/take-theirs.

- **Then** live page unchanged until explicit publish.

- **Then** blocked with itemized list.

- **Given** restore to snapshot N
- **When** executed
- **Then** new revision created pointing to N; no data loss.

- **When** translator attempts publish
- **Then** blocked until stale diff reviewed.

- **Then** live within 30s of T.
