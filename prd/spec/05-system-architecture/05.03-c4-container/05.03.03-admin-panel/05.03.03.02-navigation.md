## Navigation Badge Contract

Badges are computed through a dedicated `NavigationBadgeService` to avoid N+1 queries during sidebar rendering.

| Badge Source | Cache Key | TTL | Invalidation |
|--------------|-----------|-----|--------------|
| Pending component count | `nav:badge:components:pending` | 60s | `ComponentSubmitted`, `ComponentReviewed` events |
| Pending template count | `nav:badge:templates:pending` | 60s | `TemplateSubmitted`, `TemplateReviewed` |
| Pending order count | `nav:badge:orders:pending` | 60s | `OrderCreated`, `OrderProcessed` |
| Flagged review count | `nav:badge:reviews:flagged` | 60s | `ReviewFlagged`, `ReviewModerated` |
| Health alert count | `nav:badge:health:alerts` | 30s | `HealthAlertRaised`, `HealthAlertResolved` |
| Scheduled post count | `nav:badge:posts:scheduled` | 300s | `PostScheduled`, `PostPublished` |
| Failed test run count | `nav:badge:tests:failed` | 300s | `TestRunCompleted` |
| Low stock swag count | `nav:badge:swag:low_stock` | 900s | `InventoryUpdated` |

### Badge Rendering Rules

- Zero values render nothing (no empty badge, no "0").
- Counts above 99 display "99+".
- Critical badges (health alerts) use danger color; informational badges use neutral tint.
- Badges are hidden entirely when the user lacks the underlying permission.

# Breadcrumb System

## Breadcrumb Generation

Each page contributes a breadcrumb segment through Filament's `getBreadcrumbs()` override. The hierarchy is encoded in route segment order.

| Route Pattern | Breadcrumb Output |
|---------------|-------------------|
| `/admin` | `Admin` |
| `/admin/users` | `Admin / Users` |
| `/admin/users/{id}` | `Admin / Users / {name}` |
| `/admin/users/{id}/edit` | `Admin / Users / {name} / Edit` |
| `/admin/components` | `Admin / Content / Components` |
| `/admin/components/{id}/review` | `Admin / Content / Components / {name} / Review` |
| `/admin/marketplace/orders/{id}` | `Admin / Marketplace / Orders / #{number}` |

## Breadcrumb Behaviors

- Segments are clickable links except the current (last) page.
- Long entity names truncate at 40 characters with `title` tooltip for full text.
- Record pages (`View`/`Edit`) use the record's display name, not the ID.
- Custom pages define breadcrumbs via a static route map since they lack model context.
- Breadcrumbs are cached per route pattern per request; no per-render computation beyond the record label.

## Breadcrumb Accessibility

- Rendered inside `<nav aria-label="Breadcrumb">` with `aria-current="page"` on the final item.
- Each segment separated by a screen-reader-visible delimiter.
- On narrow screens, middle segments collapse into an ellipsis menu with full path in dropdown.

# Mobile Navigation

| 768-1023px | Persistent sidebar collapsed by default; expandable overlay |

## Slide-Over Drawer Specification

- Full-height drawer, 280px width, with backdrop scrim (tap-to-close).
- Drawer header shows panel logo and collapse control.
- Groups render as `<details>`-style collapsibles with chevron; expanded state persisted per device.
- Navigation badges visible inside drawer matching desktop rendering.
- Drawer closes automatically on route change.
- Focus trapped inside open drawer; Escape closes and returns focus to trigger.
- Body scroll locked while drawer open (scroll position restored on close).

- Admins can pin/unpin up to 5 items from any navigation leaf.
- Persisted in per-user navigation preferences.
- Icons only with `aria-label`; no text labels at this size.

# Permission-Based Visibility

## Visibility Resolution Pipeline

1. Compute user permission set once per request (cached after first Gate call).
2. For each navigation group: if the user has no child item they can see, the entire group is omitted.
3. Items filtered out are never rendered as disabled (avoid leaking capability knowledge).
4. Direct URL access to a hidden page returns 403 regardless of navigation state.

## Group → Permission Matrix

| Group | View | Any Child Grants |
|-------|------|------------------|
| Users | `users.view` OR any `users.*` | Roles & Permissions needs `roles.view` |
| Content | any of `components.view`, `documentation.view`, `themes.view`, `templates.view`, `blog.view`, `showcase.view` | Item-level |
| Marketplace | `marketplace.view` OR `orders.view` | Item-level |
| Analytics | `analytics.view` | All children |
| Settings | `settings.view` | Feature Flags needs `feature-flags.view` |
| System | `system.view` | Audit needs `audit.view` |

## Edge Visibility Rules

| Scenario | Behavior |
|----------|----------|
| User role gains a permission mid-session | Next page load re-renders nav (cache invalidated by event) |
| Role revoked mid-session | Next navigation action hits 403; sidebar updates on reload |
| Permission on a single child in a group | Group shows with only that child |
| All children hidden | Group hidden entirely |
| Custom page without permission gate | Page must declare explicit `canAccess()` or it is hidden |

## Hidden But Accessible by URL

Certain deep links bypass navigation (e.g., from activity feed). Permission is enforced at route level; navigation hiding never replaces authorization.

| Deep Link Source | Target Protection |
|------------------|-------------------|
| Activity feed item | Route middleware + Gate check on page mount |
| Notification deep link | Same |
| Search result | Same |
| Quick action | Handler re-verifies permission before execution |

# Admin Search

## Searchable Entity Registration

The global search aggregates registered providers implementing `AdminSearchable`.

| Provider | Entity | Matched Fields | Permission | Result Display |
|----------|--------|----------------|------------|----------------|
| `UserSearchProvider` | User | name, email, id | `users.view` | Avatar, name, email, role badge |
| `ComponentSearchProvider` | Component | name, slug | `components.view` | Icon, name, status badge |
| `DocumentationSearchProvider` | DocumentationPage | title, slug | `documentation.view` | Icon, title, chapter |
| `OrderSearchProvider` | Order | number, buyer email | `orders.view` | Receipt icon, number, amount |
| `TemplateSearchProvider` | Template | name, slug | `templates.view` | Thumbnail, name |
| `BlogPostSearchProvider` | BlogPost | title, slug | `blog.view` | Icon, title, status |
| `ThemeSearchProvider` | Theme | name | `themes.view` | Swatch, name |
| `AuditSearchProvider` | AuditLog | actor name, action, route | `audit.view` | Icon, action, timestamp |

## Search Interaction Model

| Interaction | Behavior |
|-------------|----------|
| Trigger | Top-bar input (desktop), search icon (mobile), keyboard shortcut `Ctrl/Cmd + K` |
| Debounce | 300ms after last keystroke |
| Minimum query length | 2 characters |
| Results grouping | By provider, max 5 per provider |
| Empty state | "No matches for {query}" with spelling hint |
| Keyboard nav | Arrow keys move selection; Enter navigates; Esc closes |
| History | Last 8 searches per user; removable individually |

## Search API Contract (Livewire)

The Livewire component calls a single endpoint to aggregate results:

| Request Field | Type | Description |
|---------------|------|-------------|
| `query` | string | Search text |
| `providers` | array | Optional subset to limit scope |

| Response Field | Type | Description |
|----------------|------|-------------|
| `groups[].provider` | string | Provider key |
| `groups[].results[].title` | string | Display title |
| `groups[].results[].subtitle` | string | Secondary line |
| `groups[].results[].url` | string | Destination route |
| `groups[].results[].badge` | object | Optional status badge |
| `latency_ms` | int | Server aggregation time |

## Search Permission Enforcement

- Each provider checks permission before querying; unauthorized providers return empty groups silently.
- Search never reveals existence of records the user cannot view (no "restricted" placeholders).
- Global audit log records searches touching audit provider (high-sensitivity).

# Admin User Flow: Cross-Module Navigation

## Flow: Review a Pending Component Submission

| Step | Location | Action |
|------|----------|--------|
| 1 | Sidebar | Content > Components (badge shows pending count) |
| 2 | Component list | Filter by status = Pending |
| 3 | Row action | Open Review page |
| 4 | Review page | Approve / Reject with feedback |
| 5 | Post-action | Redirect back to pending list; badge decrements |
| 6 | Breadcrumb | Admin / Content / Components / Pending |

## Flow: Process an Order Refund

| Step | Location | Action |
|------|----------|--------|
| 1 | Notification bell | "Order awaiting processing" notification |
| 2 | Notification click | Deep link to order detail |
| 3 | Order detail | Review line items, customer notes |
| 4 | Action | Issue refund (full/partial) with confirmation |
| 5 | Post-action | Order status badge updates; audit entry logged |
| 6 | Return | Breadcrumb back to Orders list with filters intact |

## Flow: Toggle a Feature Flag Safely

| Step | Location | Action |
|------|----------|--------|
| 1 | Sidebar | Settings > Feature Flags |
| 2 | Flag row | View description, rollout %, last modified by |
| 3 | Toggle | Confirmation modal shows blast radius summary |
| 4 | Post-action | Flag state cached; audit logged; optional notification to watchers |
| 5 | Guard | Flags marked "dangerous" require password re-entry |

# URL Design

## Route Conventions

| Pattern | Convention |
|---------|------------|
| Resource index | `/admin/{resource}` |
| Resource view | `/admin/{resource}/{id}` |
| Resource edit | `/admin/{resource}/{id}/edit` |
| Resource create | `/admin/{resource}/create` |
| Custom page | `/admin/{area}/{page}` |
| Nested relation | `/admin/{resource}/{id}/{relation}` |

## Query String State

List page filters, sort, and pagination persist in query string for shareable URLs:

| Param | Example | Purpose |
|-------|---------|---------|
| `tableFilters[status][value]` | `pending` | Filter state |
| `tableSort` | `-created_at` | Sort column and direction |
| `tableRecordsPerPage` | `25` | Page size |
| `tableSearch` | `query` | Column search |

Deep links from notifications/search restore this state on arrival.

# Edge Cases

| # | Scenario | Behavior |
|---|----------|----------|
| 1 | User has zero visible items (permission stripped) | Sidebar shows Dashboard-only minimum; notice links to access request |
| 2 | Badge count query fails | Badge hidden for that cycle; error logged, no broken UI |
| 3 | Notification deep link to deleted record | Redirect to parent list with "record no longer exists" toast |
| 4 | Search result points to 403 page | Provider filters pre-check; never returned |
| 5 | Two browsers, one changes nav prefs | Last write wins; poll picks up on reload |
| 6 | Impersonation active | Quick toolbar pins hidden; banner takes precedence |
| 7 | Extremely long group label | Truncate with ellipsis; tooltip full text |
| 8 | Maintenance mode enabled | Banner inserted above nav; nav still functional |
| 9 | First login (no prefs) | Defaults applied; no errors on hydration |
| 10 | RTL language | Logical properties ensure correct mirroring |

# Acceptance Criteria (Navigation)

## AC-N1: Permission Scoping

- **Given** a user with only `users.view` and `roles.view`
- **When** sidebar renders
- **Then** exactly Dashboard and Users group (two children) appear.
- **And** direct URL to any other page returns 403.

## AC-N2: Badge Freshness

- **Given** a pending component exists
- **When** it is approved
- **Then** the sidebar badge decrements within 60 seconds.

## AC-N3: Mobile Drawer Focus

- **Given** mobile viewport
- **When** drawer opens
- **Then** focus moves into drawer, Tab cycles within, Escape closes and restores focus.

## AC-N4: Search Security

- **Given** a user without `audit.view`
- **When** searching text that appears only in audit logs
- **Then** no audit results or hints are returned.

## AC-N5: Saved View Round Trip

- **Given** saved view with filters+sort
- **When** applied from dropdown
- **Then** list matches exactly; shareable URL reproduces same state in a fresh session.

## AC-N6: Keyboard Shortcuts

- **Given** focus outside inputs
- **When** pressing `g then u`
- **Then** navigates to Users list without full page search focus interference.
- **And** while typing in an editor, shortcuts remain inert.

## AC-N7: Zero Badge Suppression

- **Given** zero pending reviews
- **When** sidebar renders
- **Then** Reviews item shows no badge and no "0".

## AC-N8: Drawer Auto-Close

- **Given** drawer open on mobile
- **When** a nav item is tapped and route changes
- **Then** drawer closes and scroll position of new page is top.

## AC-N9: Deep Link State Restore

- **Given** a notification deep link with filters
- **When** opened
- **Then** target list renders with those filters active and URL shareable.

## AC-N10: RTL Correctness

- **Given** an `ar` locale admin
- **When** sidebar renders
- **Then** layout mirrors, drawer slides from right, chevrons point correctly.

# Navigation Rendering Pipeline

1. `NavigationBuilder` collects resource/page definitions via Filament discovery.
2. Permission filter applied; unauthorized items dropped before rendering.
3. Badges resolved through `NavigationBadgeService` (cached).
4. Grouping and ordering by declared `navigationSort` and group order.
5. Active item detection via current route match (exact, then prefix for child routes).
6. Breadcrumb chain built from matched hierarchy.
7. HTML emitted with accessibility attributes; hydration for interactive parts.

## Caching

| Layer | Key | TTL |
|-------|-----|-----|
| Nav tree (per permission set hash) | `nav:tree:{permissionHash}` | 300s |
| Badges | Per-item keys (see badge table) | 30-900s |
| Breadcrumb labels | Cached per route + record label | 300s |

Permission hash recomputed only on role/permission mutation events.

# Appendix: Support & Runbook Snippets

## Symptom: Sidebar missing items after deploy

1. Check `admin-panel-v2` flag state.
2. Verify permission seed ran (`php artisan gsmui:permissions --verify`).
3. Inspect nav tree API response for the affected user.
4. Clear `nav:tree:*` cache keys scoped to permission hashes.
5. Confirm user's role mappings in database.

## Symptom: Badges stuck stale

1. Check badge cache TTL keys for presence.
2. Verify event listeners registered (`php artisan event:list | grep Badge`).
3. Force invalidation via admin diagnostics action.
4. Review queue health for event dispatch delays.
