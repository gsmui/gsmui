# Purpose

This document outlines the monitoring, observability, and alerting strategy for the GsmUi platform. It provides comprehensive coverage of how the platform's health, performance, and business metrics are tracked, analyzed, and acted upon.

---

# Architecture Overview

The monitoring architecture follows the three pillars of observability: metrics, logs, and traces. Each pillar is implemented with purpose-built tools that integrate to provide a complete picture of platform health.

Metrics are collected at the application, infrastructure, and business levels using a combination of Laravel's built-in instrumentation, custom metrics, and infrastructure monitoring agents. Logs are structured and centralized for efficient querying and analysis. Distributed tracing follows requests through the entire stack to identify bottlenecks and failures.

The monitoring stack is designed to be lightweight in production with minimal performance overhead. Collection agents use async I/O and batch processing to avoid impacting request handling. Alert routing ensures the right people are notified through the right channels based on severity and on-call schedules.

# Monitoring Stack

## Application Monitoring

### Laravel Telescope

Telescope provides deep insight into requests, exceptions, database queries, jobs, mail, and cache operations during development. It is disabled in production to avoid performance overhead and data exposure.

### Laravel Debugbar

Debugbar adds real-time performance metrics to the browser toolbar during local development. It shows query counts, memory usage, route information, andblade rendering times.

### Spatie Health

Spatie Health provides configurable health checks that run on a schedule and report to the monitoring dashboard. Checks include database connectivity, cache availability, queue worker status, disk space, and external service reachability.

### Custom Metrics

Business-specific metrics are collected through a custom metrics service that records:
- User registrations per hour
- Component downloads per day
- Subscription changes per week
- Revenue per month
- API usage per endpoint

## Infrastructure Monitoring

### Server Metrics

- CPU utilization per core
- Memory usage and swap activity
- Disk I/O and space utilization
- Network throughput and latency
- Process count and resource consumption

### Database Metrics

- Query execution time (p50, p95, p99)
- Slow query log analysis
- Connection pool utilization
- Replication lag (read replicas)
- Lock contention and deadlocks

### Queue Metrics

- Job processing rate
- Queue depth per queue
- Failed job count and rate
- Worker status and uptime
- Job execution time distribution

### Cache Metrics

- Hit rate per cache store
- Memory utilization
- Eviction rate
- Key count and size distribution
- Connection pool utilization

# Distributed Tracing

## Trace Structure

Every request receives a unique trace ID that follows it through the entire stack:

```text
Request Arrives
    |- Trace ID: abc-123
    |
Nginx (edge timing)
    |
PHP-FPM (worker assignment)
    |
Laravel Middleware (timing per middleware)
    |
Livewire Component (mount/update timing)
    |
Service Layer (method timing)
    |
Repository Layer (query timing)
    |
Database (query execution timing)
    |
Cache (hit/miss timing)
    |
Response Sent
```

## Trace Storage

Traces are stored in a dedicated database table with minimal overhead:

```php
Schema::create('traces', function (Blueprint $table) {
    $table->id();
    $table->string('trace_id', 36);
    $table->string('span_id', 16);
    $table->string('parent_span_id', 16)->nullable();
    $table->string('operation');
    $table->decimal('duration_ms', 10, 2);
    $table->json('metadata')->nullable();
    $table->timestamp('created_at');
});
```

# Performance Optimization

## Monitoring Overhead

The monitoring stack is designed to add less than 1% overhead to request handling:

- Metrics collection uses async writes to avoid blocking
- Log shipping happens in background workers
- Health checks run on separate connections
- Tracing uses sampling (100% for errors, 10% for success)

## Data Retention

Monitoring data follows a tiered retention strategy:

- **Hot** (0-7 days): Full resolution, instant query
- **Warm** (7-30 days): 1-minute resolution, fast query
- **Cold** (30-365 days): 5-minute resolution, archived query
- **Frozen** (1+ year): Hourly resolution, cold storage

# Detailed Monitoring Specifications

## Metrics Collection Architecture

### Application Metrics

```php
// app/Metrics/ApplicationMetrics.php
class ApplicationMetrics
{
    private Counter $requestCounter;
    private Histogram $requestDuration;
    private Gauge $activeUsers;
    private Counter $errorCounter;

    public function __construct()
    {
        $this->requestCounter = new Counter(
            'gsmui_http_requests_total',
            'Total HTTP requests',
            ['method', 'route', 'status']
        );

        $this->requestDuration = new Histogram(
            'gsmui_http_request_duration_seconds',
            'HTTP request duration in seconds',
            ['method', 'route'],
            [0.01, 0.05, 0.1, 0.25, 0.5, 1.0, 2.5, 5.0, 10.0]
        );

        $this->activeUsers = new Gauge(
            'gsmui_active_users',
            'Currently active users'
        );

        $this->errorCounter = new Counter(
            'gsmui_errors_total',
            'Total errors',
            ['type', 'severity']
        );
    }

    public function recordRequest(string $method, string $route, int $status, float $duration): void
    {
        $this->requestCounter->inc([$method, $route, (string) $status]);
        $this->requestDuration->observe($duration, [$method, $route]);
    }

    public function recordError(string $type, string $severity): void
    {
        $this->errorCounter->inc([$type, $severity]);
    }

    public function setActiveUsers(int $count): void
    {
        $this->activeUsers->set($count);
    }
}
```

### Infrastructure Metrics

```php
// app/Metrics/InfrastructureMetrics.php
class InfrastructureMetrics
{
    private Gauge $databaseConnections;
    private Gauge $queueDepth;
    private Gauge $cacheHitRate;
    private Gauge $diskUsage;

    public function __construct()
    {
        $this->databaseConnections = new Gauge(
            'gsmui_database_connections_active',
            'Active database connections'
        );

        $this->queueDepth = new Gauge(
            'gsmui_queue_depth',
            'Queue depth',
            ['queue']
        );

        $this->cacheHitRate = new Gauge(
            'gsmui_cache_hit_rate',
            'Cache hit rate percentage',
            ['store']
        );

        $this->diskUsage = new Gauge(
            'gsmui_disk_usage_bytes',
            'Disk usage in bytes',
            ['mount_point']
        );
    }

    public function collectMetrics(): void
    {
        // Database connections
        $connections = DB::connection()->getPdo()->getAttribute(PDO::ATTR_CONNECTION_COUNT);
        $this->databaseConnections->set($connections);

        // Queue depth
        foreach (['default', 'marketplace', 'notifications'] as $queue) {
            $depth = Queue::size($queue);
            $this->queueDepth->set($depth, [$queue]);
        }

        // Disk usage
        $total = disk_total_space('/');
        $free = disk_free_space('/');
        $used = $total - $free;
        $this->diskUsage->set($used, ['/']);
    }
}
```

## Monitoring Middleware

```php
// app/Http/Middleware/MonitoringMiddleware.php
class MonitoringMiddleware
{
    public function handle(Request $request, Closure $next): Response
    {
        $start = microtime(true);

        $response = $next($request);

        $duration = (microtime(true) - $start) * 1000;

        // Record metrics
        $metrics = app(ApplicationMetrics::class);
        $metrics->recordRequest(
            $request->method(),
            $request->route()?->getName() ?? $request->path(),
            $response->getStatusCode(),
            $duration
        );

        // Add response headers
        $response->headers->set('X-Response-Time', round($duration, 2) . 'ms');
        $response->headers->set('X-Request-Id', $request->header('X-Request-Id', Str::uuid()));

        // Log slow requests
        if ($duration > 1000) {
            Log::warning('Slow request detected', [
                'method' => $request->method(),
                'path' => $request->path(),
                'duration' => $duration,
                'user_id' => auth()->id(),
            ]);
        }

        return $response;
    }
}
```

# Log Analysis (Expanded)

## Log Query Examples

```sql
-- Find slow queries in the last hour
SELECT 
    timestamp,
    json_extract(context, '$.sql') as query,
    json_extract(context, '$.time') as duration
FROM logs
WHERE channel = 'slow'
AND timestamp > DATE_SUB(NOW(), INTERVAL 1 HOUR)
AND json_extract(context, '$.time') > 100
ORDER BY duration DESC
LIMIT 10;

-- Find failed login attempts
SELECT 
    timestamp,
    json_extract(context, '$.user_id') as user_id,
    json_extract(context, '$.ip') as ip_address,
    COUNT(*) as attempts
FROM logs
WHERE channel = 'auth'
AND message = 'Login failed'
AND timestamp > DATE_SUB(NOW(), INTERVAL 24 HOUR)
GROUP BY ip_address
```

```php
// app/Tracing/DistributedTracer.php
class DistributedTracer
{
    private string $traceId;
    private ?string $parentSpanId;
    private array $spans = [];

    public function __construct()
    {
        $this->traceId = request()->header('X-Trace-Id', Str::uuid());
        $this->parentSpanId = request()->header('X-Span-Id');
    }

    public function startSpan(string $operation, array $metadata = []): Span
    {
        $span = new Span(
            id: Str::random(16),
            traceId: $this->traceId,
            parentSpanId: $this->parentSpanId,
            operation: $operation,
            startTime: microtime(true),
            metadata: $metadata
        );

        $this->spans[] = $span;
        $this->parentSpanId = $span->id;

        return $span;
    }

    public function endSpan(Span $span): void
    {
        $span->endTime = microtime(true);
        $span->duration = ($span->endTime - $span->startTime) * 1000;

        // Store span
        $this->storeSpan($span);
    }

    public function trace(callable $callback, string $operation): mixed
    {
        $span = $this->startSpan($operation);
        
        try {
            $result = $callback();
            $span->status = 'ok';
            return $result;
        } catch (\Throwable $e) {
            $span->status = 'error';
            $span->metadata['error'] = $e->getMessage();
            throw $e;
        } finally {
            $this->endSpan($span);
        }
    }

    private function storeSpan(Span $span): void
    {
        // Store in database for analysis
        TraceSpan::create([
            'trace_id' => $span->traceId,
            'span_id' => $span->id,
            'parent_span_id' => $span->parentSpanId,
            'operation' => $span->operation,
            'duration_ms' => $span->duration,
            'status' => $span->status,
            'metadata' => $span->metadata,
        ]);
    }
}
```

```php
    private function buildTraceTree(Collection $spans): array
    {
        $tree = [];
        $spanMap = $spans->keyBy('id');

        foreach ($spans as $span) {
            if ($span->parent_span_id && $spanMap->has($span->parent_span_id)) {
                $spanMap[$span->parent_span_id]->children[] = $span;
            } else {
                $tree[] = $span;
            }
        }

        return $tree;
    }
}
```

```php
// app/Console/Commands/UptimeCheck.php
class UptimeCheck extends Command
{
    protected $signature = 'uptime:check';

    public function handle(): int
    {
        $endpoints = [
            ['name' => 'Homepage', 'url' => config('app.url'), 'expected_status' => 200],
            ['name' => 'API', 'url' => config('app.url') . '/api/health', 'expected_status' => 200],
            ['name' => 'Dashboard', 'url' => config('app.url') . '/dashboard', 'expected_status' => 302],
            ['name' => 'Search', 'url' => config('services.meilisearch.host') . '/health', 'expected_status' => 200],
        ];

        foreach ($endpoints as $endpoint) {
            $result = $this->checkEndpoint($endpoint);
            
            if (!$result['healthy']) {
                $this->alertUptimeIssue($endpoint['name'], $result);
            }

            UptimeLog::create([
                'endpoint' => $endpoint['name'],
                'url' => $endpoint['url'],
                'status_code' => $result['status_code'],
                'response_time' => $result['response_time'],
                'healthy' => $result['healthy'],
            ]);
        }

        return 0;
    }

    private function checkEndpoint(array $endpoint): array
    {
        $start = microtime(true);
        
        try {
            $response = Http::timeout(10)->get($endpoint['url']);
            $duration = (microtime(true) - $start) * 1000;

            return [
                'status_code' => $response->status(),
                'response_time' => $duration,
                'healthy' => $response->status() === $endpoint['expected_status'],
            ];
        } catch (\Throwable $e) {
            return [
                'status_code' => 0,
                'response_time' => 0,
                'healthy' => false,
                'error' => $e->getMessage(),
            ];
        }
    }

    private function alertUptimeIssue(string $endpoint, array $result): void
    {
        // Send alert via configured channels
        alert("Uptime issue detected for {$endpoint}", [
            'endpoint' => $endpoint,
            'status_code' => $result['status_code'],
            'error' => $result['error'] ?? null,
        ]);
    }
}
```

# Monitoring Best Practices

## Metric Naming Conventions

- Use snake_case for metric names
- Prefix with application name: `gsmui_`
- Use descriptive suffixes: `_total`, `_seconds`, `_bytes`
- Include labels for dimensions: `{method, route, status}`

## Alert Design Principles

- Alert on symptoms, not causes
- Include actionable context in alerts
- Provide runbook links
- Use appropriate severity levels
- Avoid alert fatigue

## Log Best Practices

- Use structured JSON logging
- Include request ID for correlation
- Sanitize sensitive data
- Use appropriate log levels
- Implement log sampling for high-volume logs

## Tracing Best Practices

- Sample traces appropriately (100% for errors, 10% for success)
- Propagate trace context across services
- Keep span metadata concise
- Use meaningful operation names
- Monitor trace overhead

# Monitoring Runbooks

## High Error Rate Runbook

### Investigation Steps

1. **Check error logs**
   ```bash
   tail -f storage/logs/laravel.log | grep -i error
   ```

2. **Check recent deployments**
   ```bash
   git log --oneline -10
   ```

3. **Check database status**
   ```bash
   mysql -u root -p -e "SHOW PROCESSLIST;"
   ```

4. **Check queue status**
   ```bash
   php artisan queue:status
   ```

### Resolution Steps

1. If caused by recent deployment:
   ```bash
   ./scripts/rollback.sh production
   ```

2. If caused by database issues:
   ```bash
   php artisan migrate:status
   # Check for stuck migrations
   ```

3. If caused by external service:
   - Check service status page
   - Enable circuit breaker if available
   - Notify team

## High Response Time Runbook

### Investigation Steps

1. **Check slow query log**
   ```bash
   tail -f /var/log/mysql/slow.log
   ```

2. **Check application metrics**
   ```bash
   curl http://localhost:9090/metrics | grep response_time
   ```

3. **Check server resources**
   ```bash
   top -bn1 | head -20
   free -h
   df -h
   ```

### Resolution Steps

1. If database-bound:
   - Check for missing indexes
   - Analyze slow queries
   - Consider adding read replicas

2. If CPU-bound:
   - Check for infinite loops
   - Profile application code
   - Scale server resources

3. If memory-bound:
   - Check for memory leaks
   - Restart PHP-FPM workers
   - Increase memory limits

## Database Connection Issues Runbook

### Investigation Steps

1. **Check connection count**
   ```bash
   mysql -u root -p -e "SHOW STATUS LIKE 'Threads_connected';"
   ```

2. **Check for blocking queries**
   ```bash
   mysql -u root -p -e "SHOW PROCESSLIST WHERE State != 'Sleep';"
   ```

3. **Check replication lag**
   ```bash
   mysql -u root -p -e "SHOW SLAVE STATUS\G"
   ```

### Resolution Steps

1. Kill blocking queries:
   ```bash
   mysql -u root -p -e "KILL [process_id];"
   ```

2. Increase connection limit:
   ```bash
   mysql -u root -p -e "SET GLOBAL max_connections = 300;"
   ```

3. Restart database if needed:
   ```bash
   sudo systemctl restart mysql
   ```
