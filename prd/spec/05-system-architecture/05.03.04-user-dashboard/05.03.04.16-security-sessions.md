# Risk

| Risk | Likelihood | Impact | Mitigation |
|------|-----------|--------|------------|
| 2FA lockout (lost device) | Medium | Critical | Backup codes, recovery flow, admin override |
| Session token theft | Low | Critical | Short-lived tokens, device fingerprinting |
| Brute force password attacks | Medium | High | Rate limiting, account lockout, CAPTCHA |
| Alert email delivery failure | Low | High | Multi-provider fallback (SES + SendGrid) |
| 2FA time drift | Low | Medium | Allow ±30s window, NTP sync |
| Security log storage bloat | Medium | Low | TTL on detailed logs, aggregated summaries |

---

# Security

| Concern | Implementation |
|---------|---------------|
| Session token storage | Hashed tokens in database, not plaintext |
| Device fingerprinting | User-agent + IP + device hash for session identification |
| 2FA TOTP | RFC 6238 compliant, 30-second window, SHA-1 |
| Backup codes | 10 single-use codes, hashed before storage |
| Password policy | Min 8 chars, required: uppercase, lowercase, number |
| Password history | Last 5 passwords checked, cannot reuse |
| Account lockout | 5 failed attempts → 15min lock, then CAPTCHA |
| Security alerts | Email + in-app notification on suspicious activity |
