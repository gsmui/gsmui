# 06.03 - Common Columns & Schema Standards

**Project:** GsmUi
**Architecture:** Database Standards
**Database:** MySQL 8.4 LTS (InnoDB)
**Framework:** Laravel 13 + Eloquent ORM
**Version:** 1.0.0

---

# Purpose

This document defines the reusable column standards used across every table in the GsmUi database.

Rather than designing each table independently, every domain follows a consistent schema pattern for identifiers, timestamps, ownership, status, auditing, publishing, versioning, and metadata.

These standards improve:

* Consistency
* Query optimization
* Developer productivity
* Migration quality
* API consistency
* Future scalability

---

# Standard Table Layout

Unless a business rule requires otherwise, tables follow this order:

```text
Primary Key

Ownership

Business Columns

Status Columns

Ordering Columns

Version Columns

Metadata

Audit Columns

Timestamps

Soft Delete
```

This ordering should be consistent across every migration.

---

# Primary Identifier

Every business table begins with:

```php
$table->id();
```

Generated column:

```text
id
BIGINT UNSIGNED
PRIMARY KEY
AUTO_INCREMENT
```

Used internally by:

* Eloquent
* Foreign Keys
* Relationships
* Joins

---

# Public Identifier

Public-facing resources should expose a ULID.

Example:

```php
$table->ulid('public_id')->unique();
```

Benefits:

* Safer URLs
* Harder enumeration
* Better API design
* Public sharing

Used for:

* Themes
* Templates
* Orders
* Licenses
* Downloads
* API resources

Internal relationships continue to use `id`.

---

# Ownership Columns

When data belongs to a user:

```php
$table->foreignId('user_id')
    ->constrained()
    ->cascadeOnDelete();
```

Examples:

```text
user_id

author_id

owner_id

created_by

updated_by
```

Always reference `users.id`.

---

# Organization Ownership (Future)

Enterprise-ready tables should optionally support organizations.

```php
$table->foreignId('organization_id')
      ->nullable()
      ->constrained();
```

Reserved for:

* Teams
* Workspaces
* Enterprise accounts

---

# Name Column

Business entities typically include:

```php
$table->string('name');
```

Examples:

* Theme
* Component
* Category
* Product

Avoid using `title` unless the entity represents content.

---

# Title Column

Content entities use:

```php
$table->string('title');
```

Examples:

* Blog posts
* Documentation pages
* CMS pages
* Announcements

---

# Slug Column

Public resources should include:

```php
$table->string('slug')->unique();
```

Characteristics:

* SEO-friendly
* URL-safe
* Immutable after publication unless redirected

---

# Description

Short description:

```php
$table->string('description')
      ->nullable();
```

Long description:

```php
$table->longText('content')
      ->nullable();
```

---

# Status

Standard status column:

```php
$table->string('status')
      ->default('draft');
```

Common values:

```text
draft

pending

published

active

inactive

archived

deleted
```

Status transitions are handled by Services, not controllers.

---

# Visibility

Use when public exposure differs from publication status.

```php
$table->string('visibility')
      ->default('private');
```

Examples:

```text
private

public

unlisted

premium

enterprise
```

---

# Boolean Flags

Convention:

```php
$table->boolean('is_active')
      ->default(true);
```

Examples:

```text
is_public

is_featured

is_verified

is_premium

is_default

has_children
```

Always prefix with verbs.

---

# Ordering

Sortable entities include:

```php
$table->unsignedInteger('sort_order')
      ->default(0);
```

Used for:

* Navigation
* Categories
* Documentation
* CMS blocks
* Menus

---

# Version

Versioned entities include:

```php
$table->string('version')
      ->nullable();
```

Examples:

```text
1.0.0

2.1.3

3.0.0-beta
```

Published artifacts should never overwrite historical versions.

---

# Metadata

Flexible metadata:

```php
$table->json('metadata')
      ->nullable();
```

Examples:

* Theme options
* Export configuration
* Build information
* Analytics

Core relational data must not be stored in JSON.

---

# Settings

Configurable entities may include:

```php
$table->json('settings')
      ->nullable();
```

Examples:

* User preferences
* Theme configuration
* Playground options

---

# Monetary Columns

Always use decimal values.

```php
$table->decimal('price',12,2);
```

Additional fields:

```php
discount_amount

tax_amount

total_amount

currency
```

Never use floating-point types.

---

# File Information

Standard columns:

```php
filename

path

mime_type

file_size

checksum
```

Spatie Media Library remains the primary media manager.

# Timestamps

Every mutable table includes:

```php
$table->timestamps();
```

Generated:

```text
created_at

updated_at
```

Always stored in UTC.

---

# Soft Deletes

Recoverable entities include:

```php
$table->softDeletes();
```

Generated:

```text
deleted_at
```

Not recommended for:

* Orders
* Payments
* Invoices
* Activity logs

# Standard Laravel Blueprint

Typical migration:

```php
Schema::create('themes', function (Blueprint $table) {
    $table->id();
    $table->ulid('public_id')->unique();

    $table->foreignId('author_id')->constrained('users');

    $table->string('name');
    $table->string('slug')->unique();
    $table->string('description')->nullable();

    $table->string('status')->default('draft');
    $table->string('visibility')->default('private');

    $table->boolean('is_featured')->default(false);

    $table->unsignedInteger('sort_order')->default(0);

    $table->json('metadata')->nullable();

    $table->timestamps();
    $table->softDeletes();
});
```

This serves as the reference pattern for business entities.

# Anti-Patterns

Avoid:

* Generic `data` columns
* Multiple unrelated JSON blobs
* Duplicate timestamps
* Nullable foreign keys without business justification
* Mixed naming styles
* Overloaded status fields

Every column should have a single, well-defined responsibility.

# Security

Column standards support security:

* `public_id` (ULID) prevents URL enumeration
* `status` columns enable access control states
* `visibility` columns control public exposure
* `is_featured` flags enable premium content gating
* Audit columns (`created_by`, `updated_by`) track modifications
* `deleted_at` enables soft delete recovery workflows
* `metadata` JSON stores non-sensitive configuration
* `settings` JSON stores user preferences (never secrets)
* Monetary columns use DECIMAL (no floating-point)
* File columns track `mime_type` and `checksum`

# Performance

Column standards impact performance:

* `id` (BIGINT) primary keys: fast joins, small indexes
* `slug` with unique index: fast URL lookups
* `status` with index: efficient filtering
* `published_at` with index: date-range queries
* `sort_order` with index: ordered results
* `is_featured` with index: featured content queries
* `metadata` JSON: flexible without schema changes
* `timestamps`: created_at/updated_at for recency queries
* `deleted_at` with index: soft delete filtering

Column ordering in tables follows the standard layout for consistency.
