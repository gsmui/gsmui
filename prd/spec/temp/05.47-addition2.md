# Business Rule State Transitions

## Component State Transitions

```
draft
    +-- submit --> pending_review
    +-- delete --> deleted (soft)

pending_review
    +-- approve --> published
    +-- reject --> rejected
    +-- request_changes --> draft

published
    +-- archive --> archived
    +-- unpublish --> draft

archived
    +-- republish --> published
    +-- delete --> deleted (soft)

rejected
    +-- resubmit --> pending_review
    +-- delete --> deleted (soft)
```

## Order State Transitions

```
pending
    +-- payment_initiated --> processing
    +-- cancel --> cancelled

processing
    +-- payment_succeeded --> paid
    +-- payment_failed --> failed

paid
    +-- refund_requested --> refunding
    +-- complete --> completed

refunding
    +-- refund_processed --> refunded
    +-- refund_failed --> paid (revert)

failed
    +-- retry --> processing
    +-- abandon --> cancelled

cancelled
    (terminal state)

refunded
    (terminal state)

completed
    (terminal state)
```

## Subscription State Transitions

```
trial
    +-- payment_succeeded --> active
    +-- trial_expired, no_payment --> grace_period
    +-- user_cancels --> cancelled

active
    +-- payment_succeeded --> active (renew)
    +-- payment_failed --> past_due
    +-- user_cancels --> cancelled
    +-- admin_suspend --> suspended

past_due
    +-- payment_succeeded --> active
    +-- all_retries_failed --> grace_period
    +-- user_cancels --> cancelled

grace_period
    +-- payment_succeeded --> active
    +-- grace_expired --> inactive
    +-- user_cancels --> cancelled

suspended
    +-- payment_succeeded --> active
    +-- admin_unsuspend --> active
    +-- user_cancels --> cancelled
    +-- suspension_expired --> inactive

cancelled
    +-- period_end --> inactive
    +-- reactivate --> active (within 30 days)

inactive
    +-- reactivate --> active (within 30 days)
    +-- (after 30 days) --> archived
```

# Business Metrics Definitions

## User Metrics

| Metric | Definition | Calculation | Target |
|--------|-----------|-------------|--------|
| Registered Users | Total accounts created | COUNT(users WHERE deleted_at IS NULL) | 10,000+ |
| Monthly Active Users | Users with activity in last 30 days | COUNT(DISTINCT user_id FROM activity_logs WHERE created_at > NOW() - 30 DAY) | 5,000+ |
| Daily Active Users | Users with activity today | COUNT(DISTINCT user_id FROM activity_logs WHERE DATE(created_at) = CURDATE()) | 1,000+ |
| New Users (Daily) | Registrations today | COUNT(users WHERE DATE(created_at) = CURDATE()) | 50+ |
| New Users (Monthly) | Registrations this month | COUNT(users WHERE MONTH(created_at) = MONTH(NOW())) | 500+ |
| User Retention (30-day) | % of users active 30 days after registration | (Users active day 30 / Users registered day 0) * 100 | > 60% |
| Churn Rate | % of subscribers who cancel per month | (Cancelled this month / Total subscribers start of month) * 100 | < 5% |
| NPS Score | Net Promoter Score | % Promoters - % Detractors | > 50 |

## Revenue Metrics

| Metric | Definition | Calculation | Target |
|--------|-----------|-------------|--------|
| MRR | Monthly Recurring Revenue | SUM(active subscription prices) | $50,000+ |
| ARR | Annual Recurring Revenue | MRR * 12 | $600,000+ |
| ARPU | Average Revenue Per User | MRR / Active subscribers | $40+ |
| CAC | Customer Acquisition Cost | Marketing spend / New subscribers | < $50 |
| LTV | Customer Lifetime Value | ARPU * Average subscription length | > $500 |
| LTV:CAC Ratio | Return on acquisition | LTV / CAC | > 10:1 |
| Conversion Rate | Trial to paid | (Paid conversions / Trial starts) * 100 | > 30% |
| Refund Rate | % of orders refunded | (Refunded orders / Total orders) * 100 | < 5% |

## Component Metrics

| Metric | Definition | Calculation | Target |
|--------|-----------|-------------|--------|
| Total Components | Published components | COUNT(components WHERE status = 'published') | 200+ |
| Components Published (Monthly) | New components this month | COUNT(components WHERE MONTH(published_at) = MONTH(NOW())) | 20+ |
| Average Downloads/Component | Mean downloads per component | AVG(downloads_count) | 500+ |

| Review Response Rate | % of reviews with author response | (Reviews with response / Total reviews) * 100 | > 50% |
| Component Update Frequency | Average days between updates | AVG(DAYS BETWEEN updated_at and published_at) | < 90 days |

# Escalation Procedures

## Account Suspension Escalation

```
Suspension Trigger
    |
    +-- Level 1: Warning
    |   +-- Email notification to user
    |   +-- 7-day grace period
    |   +-- Access still available
    |
    +-- Level 2: Restricted
    |   +-- Download limit reduced to 0
    |   +-- Cannot submit new content
    |   +-- Can still access existing content
    |
    +-- Level 3: Suspended
    |   +-- All access revoked
    |   +-- Login blocked
    |   +-- Admin notification
    |
    +-- Level 4: Banned
        +-- Account permanently disabled
        +-- Data retained for 30 days
        +-- IP logged for security
```

## Payment Failure Escalation

```
Payment Failed
    |
    +-- Attempt 1: Immediate retry
    |   +-- Notify user of failure
    |   +-- Retry in 24 hours
    |
    +-- Attempt 2: Second retry
    |   +-- Notify user of failure
    |   +-- Retry in 48 hours
    |
    +-- Attempt 3: Final retry
    |   +-- Notify user of failure
    |   +-- Retry in 72 hours
    |
    +-- All retries failed: Grace period
    |   +-- Notify user of grace period
    |   +-- Access retained for 3 more days
    |   +-- Final payment attempt
    |
    +-- Grace period expired: Downgrade
        +-- Downgrade to free tier
        +-- Revoke Pro features
        +-- Send downgrade notification
        +-- Offer reactivation link
```

## Content Moderation Escalation

```
Content Reported
    |
    +-- Report Count < 3
    |   +-- Log report
    |   +-- Queue for review
    |   +-- Notify admin
    |
    +-- Report Count = 3
    |   +-- Auto-hide content
    |   +-- Notify content owner
    |   +-- Priority admin review
    |
    +-- Report Count > 3
    |   +-- Content removed
    |   +-- Author warned
    |   +-- Admin investigation
    |
    +-- Repeated violations
        +-- Account suspension
        +-- Content removal
        +-- Permanent ban (if severe)
```

# Business Rule Testing Scenarios

## Registration Scenarios

| Scenario | Input | Expected Result |
|----------|-------|----------------|
| Valid registration | Valid email, strong password | 201, user created |
| Duplicate email | Existing email | 409, email taken |
| Weak password | Short, no complexity | 422, validation error |
| Invalid email format | Not an email | 422, validation error |
| Disposable email | temp-mail.org | 422, invalid domain |
| Rate limit exceeded | 6+ registrations from IP | 429, too many requests |
| Terms not accepted | terms=false | 422, must accept terms |

| Scenario | Input | Expected Result |

| Trial already used | User with has_used_trial=true | 403, trial already used |
| Subscribe with valid card | Plan, payment method | 201, subscription active |
| Subscribe with invalid card | Plan, declined card | 402, payment failed |
| Cancel active subscription | Subscription ID | 200, cancelled at period end |
| Cancel already cancelled | Cancelled subscription | 400, already cancelled |
| Upgrade plan | Higher-tier plan | 200, plan changed |
