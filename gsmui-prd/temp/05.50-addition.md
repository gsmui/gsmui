# Acceptance Criteria Templates

## Feature Acceptance Criteria

```markdown
### Feature: [Feature Name]

**User Story:** As a [role], I want [feature] so that [benefit].

**Acceptance Criteria:**
- [ ] Given [context], when [action], then [result]
- [ ] Given [context], when [action], then [result]
- [ ] Given [context], when [action], then [result]

**Technical Requirements:**
- [ ] Database migration completed
- [ ] API endpoint documented
- [ ] Unit tests added (100% coverage)
- [ ] Feature tests added (happy path + edge cases)
- [ ] Browser tests added (critical flows)
- [ ] Performance: response time < 200ms
- [ ] Security: input validation, authorization checks
- [ ] Accessibility: keyboard navigation, screen reader
- [ ] Dark mode: styles applied
- [ ] Mobile responsive: tested on small screens

**Definition of Done:**
- [ ] Code reviewed and approved
- [ ] All CI checks pass
- [ ] Documentation updated
- [ ] Deployed to staging
- [ ] QA verified on staging
- [ ] Product owner accepted
```

## Bug Fix Acceptance Criteria

```markdown
### Bug: [Bug Title]

**Issue:** [Description of the bug]

**Steps to Reproduce:**
1. [Step 1]
2. [Step 2]
3. [Step 3]

**Expected Result:** [What should happen]
**Actual Result:** [What actually happens]

**Fix:**
- [ ] Root cause identified
- [ ] Fix implemented
- [ ] Regression test added
- [ ] Existing tests still pass
- [ ] Verified on staging
- [ ] No side effects identified
```
