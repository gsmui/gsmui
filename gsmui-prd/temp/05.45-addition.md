# Complete Table Definitions

## Users Table

```sql
CREATE TABLE users (
    id BIGINT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
    name VARCHAR(255) NOT NULL,
    email VARCHAR(255) NOT NULL,
    email_verified_at TIMESTAMP NULL,
    password VARCHAR(255) NOT NULL,
    role_id BIGINT UNSIGNED NOT NULL DEFAULT 1,
    status ENUM('pending', 'active', 'suspended', 'banned') NOT NULL DEFAULT 'pending',
    avatar_url VARCHAR(500) NULL,
    bio TEXT NULL,
    website VARCHAR(500) NULL,
    location VARCHAR(255) NULL,
    timezone VARCHAR(50) NOT NULL DEFAULT 'UTC',
    locale VARCHAR(10) NOT NULL DEFAULT 'en',
    last_login_at TIMESTAMP NULL,
    last_login_ip VARCHAR(45) NULL,
    login_count INT UNSIGNED NOT NULL DEFAULT 0,
    has_used_trial TINYINT(1) NOT NULL DEFAULT 0,
    subscription_status ENUM('none', 'active', 'trialing', 'past_due', 'cancelled') NOT NULL DEFAULT 'none',
    downloads_this_month INT UNSIGNED NOT NULL DEFAULT 0,
    downloads_reset_at TIMESTAMP NULL,
    stripe_customer_id VARCHAR(255) NULL,
    remember_token VARCHAR(100) NULL,
    created_at TIMESTAMP NULL,
    updated_at TIMESTAMP NULL,
    deleted_at TIMESTAMP NULL,

    UNIQUE KEY idx_users_email (email),
    KEY idx_users_role (role_id, status),
    KEY idx_users_status (status),
    KEY idx_users_stripe (stripe_customer_id),
    KEY idx_users_created (created_at)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;
```

## Subscription Status Sync

```sql
DELIMITER //
CREATE PROCEDURE SyncSubscriptionStatus()
BEGIN
    -- Mark expired trials
    UPDATE subscriptions
    SET status = 'expired'
    WHERE status = 'trialing'
      AND trial_ends_at < NOW();

    -- Mark cancelled subscriptions that have passed their end date
    UPDATE subscriptions
    SET status = 'expired'
    WHERE status = 'cancelled'
      AND ends_at < NOW();

    -- Update user subscription status from active subscriptions
    UPDATE users u
    INNER JOIN (
        SELECT user_id, MAX(status) as best_status
        FROM subscriptions
        WHERE status IN ('active', 'trialing')
        GROUP BY user_id
    ) s ON u.id = s.user_id
    SET u.subscription_status = CASE
        WHEN s.best_status = 'active' THEN 'active'
        WHEN s.best_status = 'trialing' THEN 'trialing'
        ELSE u.subscription_status
    END;

    -- Set users with no active subscription to 'none'
    UPDATE users u
    SET u.subscription_status = 'none'
    WHERE u.id NOT IN (
        SELECT user_id FROM subscriptions
        WHERE status IN ('active', 'trialing')
    )
    AND u.subscription_status != 'none';
END //
DELIMITER ;
```

## Partition Maintenance Script

```sql
DELIMITER //
CREATE PROCEDURE MaintainPartitions()
BEGIN
    DECLARE next_month DATE;
    DECLARE partition_name VARCHAR(20);

    SET next_month = DATE_ADD(LAST_DAY(NOW()), INTERVAL 2 MONTH);
    SET partition_name = CONCAT('p', DATE_FORMAT(next_month, '%Y%m'));

    -- Add new partition for 2 months ahead
    SET @sql = CONCAT(
        'ALTER TABLE page_views REORGANIZE PARTITION p_future INTO (',
        'PARTITION ', partition_name, ' VALUES LESS THAN (',
        DATE_FORMAT(DATE_ADD(next_month, INTERVAL 1 MONTH), '%Y%m'),
        '), PARTITION p_future VALUES LESS THAN MAXVALUE)'
    );
    PREPARE stmt FROM @sql;
    EXECUTE stmt;
    DEALLOCATE PREPARE stmt;
END //
DELIMITER ;
```

# Migration Safety Guidelines

## Zero-Downtime Migration Rules

| Rule | Description | Example |
|------|-------------|---------|
| Never drop columns | Mark as deprecated first, drop in next release | ALTER TABLE ... ADD COLUMN deprecated_at |
| Never rename columns | Add new column, migrate data, drop old in next release | ADD new_col, UPDATE, DROP old_col |
| Add columns as nullable | Avoid default values that lock tables | ALTER TABLE ... ADD COLUMN col TYPE NULL |
| Use online DDL | MySQL 8.0 supports instant ADD COLUMN | ALGORITHM=INSTANT |
| Batch large updates | Update in chunks of 1000 rows | WHERE id BETWEEN x AND y LIMIT 1000 |
| Create indexes online | Use ALGORITHM=INPLACE for index creation | ALTER TABLE ... ADD INDEX ... ALGORITHM=INPLACE |
| Test on staging first | Always validate on production-sized dataset | php artisan migrate --seed on staging |

## Migration Testing Checklist

| Check | Description | Command |
|-------|-------------|---------|
| Forward migration | Runs without error | php artisan migrate |
| Backward migration | Rollback completes cleanly | php artisan migrate:rollback |
| Data integrity | No data loss after migrate + rollback | Verify row counts |
| Performance | Migration completes within time budget | Time the migration |
| Lock impact | No table locks exceeding 5 seconds | Monitor SHOW PROCESSLIST |
| Replication lag | Migration does not cause replication lag | Monitor SHOW SLAVE STATUS |

# Index Optimization Guide

## Composite Index Design

The order of columns in composite indexes matters. Follow this priority:

1. Equality conditions first (=, IN)
2. Range conditions second (>, <, BETWEEN)
3. Sort columns third (ORDER BY)
4. Selectivity: higher-selectivity columns first

```sql
-- Query: SELECT * FROM components WHERE category_id = ? AND status = ? ORDER BY created_at DESC
-- Optimal index:
KEY idx_components_category_status_created (category_id, status, created_at)

-- Query: SELECT * FROM orders WHERE user_id = ? AND status = ? AND paid_at > ?
-- Optimal index:
KEY idx_orders_user_status_paid (user_id, status, paid_at)

-- Query: SELECT * FROM activity_logs WHERE subject_type = ? AND subject_id = ? ORDER BY created_at DESC
-- Optimal index:
KEY idx_al_subject_created (subject_type, subject_id, created_at)
```

## Index Maintenance

| Task | Frequency | Command |
|------|-----------|---------|
| Check index usage | Monthly | SELECT * FROM sys.schema_unused_indexes |
| Check index bloat | Monthly | pgstattuple extension or pt-index-usage |
| Analyze table statistics | Weekly | ANALYZE TABLE {table} |
| Rebuild fragmented indexes | As needed | ALTER TABLE ... ENGINE=InnoDB |
| Remove unused indexes | Quarterly | Review sys.schema_unused_indexes |
