# AI Prompt Templates

## Component Generation Prompts

### Basic Component Prompt

```text
You are an expert Laravel Livewire developer specializing in the GsmUI component library.
Generate a Livewire component based on the following requirements:

Component Name: {name}
Description: {description}
Category: {category}
Target Laravel Version: {laravel_version}
Target Livewire Version: 3.x

Requirements:
{requirements}

Output Format:
1. PHP Livewire class (app/Livewire/ComponentName.php)
2. Blade template (resources/views/livewire/component-name.blade.php)
3. Alpine.js integration (if needed)
4. Tailwind CSS classes (using GsmUI design tokens)
5. Component documentation (README.md)

Constraints:
- Follow GsmUI coding standards (PSR-12, Alpine.js patterns)
- Use GsmUI design tokens (--gsmui-* CSS variables)
- Include proper ARIA attributes for accessibility
- Support dark mode via Tailwind dark: prefix
- Include x-data, x-on, x-show, x-bind directives
- No eval() or Function() constructor
- No external CDN dependencies
- Include proper error handling
- Include loading states
- Support responsive design
```

### Advanced Component Prompt

```text

Component: {name}
Features Required:
{features_list}

Technical Requirements:

Output Structure:

   - Authorization checks

2. Blade template with:
   - Component markup using GsmUI components
   - Alpine.js directives for interactivity
   - Tailwind CSS classes
   - Dark mode support
   - Responsive design
   - Accessibility attributes
   - Loading indicators
   - Error states

3. JavaScript (if needed):
   - Alpine.js data/methods
   - Custom event handlers
   - DOM manipulation (minimal)
   - WebSocket connection (if real-time)

4. Documentation:
   - Installation instructions
   - Usage examples
   - Props/parameters reference
   - Events reference
   - Accessibility notes
```

# AI Security Framework

## Input Sanitization

| Check | Pattern | Action |
|-------|---------|--------|
| Prompt injection | Ignore previous instructions | Reject |
| Code injection | eval, exec, system, passthru | Reject |
| SQL injection | UNION, SELECT, INSERT, DROP | Reject |
| XSS | <script>, javascript:, onerror | Reject |
| Path traversal | ../, ..\, /etc/passwd | Reject |
| Secret exposure | API keys, passwords, tokens | Sanitize |

## Output Validation

| Check | Tool | Action |
|-------|------|--------|
| PHP syntax | php -l | Reject if invalid |
| Blade syntax | Custom parser | Reject if invalid |
| JavaScript syntax | ESLint | Auto-fix or reject |
| SQL queries | Custom scanner | Reject if raw queries |
| File operations | Custom scanner | Reject if dangerous |
| Network requests | Custom scanner | Reject if external |

## Data Privacy

| Rule | Implementation |
|------|---------------|
| No PII in prompts | Strip names, emails, phones |
| No secrets in prompts | Mask API keys, passwords |
| No user code in prompts | Use templates, not user snippets |
| No proprietary data | Use only public GsmUI metadata |
| Opt-in for data sharing | Explicit consent required |

## Streaming Implementation

```text
Streaming Response Flow
    |
    +-- User submits request
    |
    +-- Check cache
    |   +-- Hit --> Return cached response
    |   +-- Miss --> Continue
    |
    +-- Start streaming
    |   +-- Send SSE headers
    |   +-- Open connection to AI provider
    |   +-- Stream tokens as they arrive
    |
    +-- Client receives tokens
    |   +-- Render incrementally
    |   +-- Show loading indicator
    |
    +-- Stream complete
    |   +-- Cache full response
    |   +-- Send completion event
    |   +-- Close connection
    |
    +-- Post-processing
        +-- Validate generated code
        +-- Run security scan
        +-- Add to history
```
