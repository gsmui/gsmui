# 07.27 - Notifications

**Project:** GsmUi
**Architecture:** Laravel Notifications (Multi-Channel)
**Framework:** Laravel 13 + Livewire 4
**Version:** 1.0.0

---

# Purpose

> See also: `05.33-notification-system.md` for the conceptual notification model, types, channels, and delivery strategy, and `06.110-notifications.md` for the `notifications` / `notification_queues` / `notification_preferences` schema. This document specifies the **implementation contract** — concrete notification classes, channel configuration, on-demand (guest) notifications, and database-channel persistence that realize that design.

GsmUi delivers alerts through multiple channels: email, in-app (database), SMS (future), push (future), and webhooks. Notifications are triggered by domain events (`07.12-events.md`) consumed by queued listeners (`07.13-listeners.md`). Each notification is a `final` class implementing Laravel's `Notification` contract with a `via()` channel resolver and per-channel message builders. The `database` channel stores in-app inbox records (schema in `06.110-notifications.md`); the `mail` channel delegates to a Mailable (`07.28-mail.md`).

# 2. Notification Class Contract

A notification carries only the data needed to render each channel. It is `final`, uses `Queueable`, and resolves channels via `via()`.

```php
<?php

declare(strict_types=1);

namespace App\Domains\Notifications\Notifications;

use App\Domains\Users\Models\User;
use App\Domains\Marketplace\Models\Product;
use Illuminate\Bus\Queueable;
use Illuminate\Notifications\Messages\MailMessage;
use Illuminate\Notifications\Notification;

final class ProductUpdated extends Notification
{
    use Queueable;

    public function __construct(
        public readonly int $productId,
        public readonly string $productName,
        public readonly string $version,
    ) {}

    /** @param User $notifiable */
    public function via($notifiable): array
    {
        return ['mail', 'database'];
    }

    /** @param User $notifiable */
    public function toMail($notifiable): MailMessage
    {
        return (new MailMessage())
            ->subject("{$this->productName} updated to {$this->version}")
            ->line("Version {$this->version} of {$this->productName} is now available.")
            ->action('View Product', url("/products/{$this->productId}"));
    }

    /** @param User $notifiable */
    public function toArray($notifiable): array
    {
        return [
            'type'        => 'product_updated',
            'product_id'  => $this->productId,
            'product_name' => $this->productName,
            'version'     => $this->version,
        ];
    }
}
```

The `toArray()` return is exactly the JSON persisted to `notifications.data` (see `06.110-notifications.md`). `type` is the discriminator used by `notification_preferences.notification_type`.

# 3. Database (In-App) Channel

The `database` channel writes a row to `notifications` automatically when `toArray()` is present. Marking read is handled by the `Notifiable` trait:

```php
$user->unreadNotifications()->where('type', ProductUpdated::class)->markAsRead();
```

The inbox query reads `notifications` ordered by `created_at` with an index on `read_at` (see `06.110-notifications.md` §Index Strategy).

# 4. On-Demand Notifications

Guests (no persisted `User`) receive notifications via `Notification::route()`. This is used for transactional receipts and passwordless login links.

```php
use Illuminate\Support\Facades\Notification;

Notification::route('mail', 'guest@example.com')
    ->route('webhook', 'https://client.example.com/hooks/order')
    ->notify(new OrderConfirmation(
        orderId: $order->id,
        total: $order->total,
    ));
```

For a custom channel, implement `send()`:

```php
final class WebhookChannel
{
    public function send($notifiable, Notification $notification): void
    {
        $payload = $notification->toWebhook($notifiable);
        // POST to the registered webhook URL (signature per 07.29-webhooks.md)
    }
}
```

# 5. Dispatch From Listeners

Domain events trigger notifications through queued listeners (idempotent, see `07.13-listeners.md`):

```php
// app/Domains/Notifications/Listeners/SendCommentReplyNotification.php
namespace App\Domains\Notifications\Listeners;

use App\Domains\Components\Events\CommentReplyCreated;
use App\Domains\Notifications\Notifications\CommentReply;
use Illuminate\Contracts\Queue\ShouldQueue;

final class SendCommentReplyNotification implements ShouldQueue
{
    public function handle(CommentReplyCreated $event): void
    {
        $author = User::findOrFail($event->authorId);
        $author->notify(new CommentReply(
            commentId: $event->commentId,
            replierName: $event->replierName,
        ));
    }
}
```

# 6. Channel Resolution & Preferences

Channel selection respects per-user preferences (`06.110-notifications.md`). A `ChannelResolver` maps the notification `type` and user preferences to the final `via()` set:

| Notification type | Default channels | Preference override |
| --- | --- | --- |
| `subscription_renewed` | mail, database | per-channel `notification_preferences` |
| `comment_reply` | database | quiet hours respected |
| `product_updated` | mail, database | digest frequency honored |

Quiet hours and digest batching are applied by the queue processor (`notification_queues`); the `Notification` class only declares its *supported* channels.

```php
final class NotifyAuthorOfComponentPublished implements ShouldQueue

    public function handle(ComponentPublished $event): void

        $followers = $event->component->user->followers;

        foreach ($followers as $follower) {
            $follower->notify(new ComponentPublishedNotification(

                componentName: $event->component->name,

    {
        $comment = \App\Domains\Comments\Models\Comment::findOrFail($event->commentId);

            $author->notify(new CommentReply(
                commentId: $event->commentId,
                replierName: $event->replierName,
                commentPreview: $event->commentBody,
            ));
        }
    }
}
```

# 10. Notification Preferences Service

```php
<?php

declare(strict_types=1);

namespace App\Domains\Notifications\Services;

use App\Domains\Users\Models\User;
use Illuminate\Support\Facades\DB;

final class NotificationPreferenceService
{
    public function getChannels(User $user, string $notificationType): array
    {
        $preference = DB::table('notification_preferences')
            ->where('user_id', $user->id)
            ->where('notification_type', $notificationType)
            ->first();

        if (! $preference) {
            return $this->getDefaultChannels($notificationType);
        }

        return json_decode($preference->channels, true);
    }

    public function updatePreference(User $user, string $notificationType, array $channels): void
    {
        DB::table('notification_preferences')->updateOrInsert(
            ['user_id' => $user->id, 'notification_type' => $notificationType],
            [
                'channels' => json_encode($channels),
                'updated_at' => now(),
            ]
        );
    }

    public function isQuietHours(User $user): bool
    {
        $preferences = $this->getUserPreferences($user);

        if (! $preferences->quiet_hours_enabled) {
            return false;
        }

        $now = now()->timezone($user->timezone ?? 'UTC');
        $start = Carbon::parse($preferences->quiet_hours_start, $user->timezone ?? 'UTC');
        $end = Carbon::parse($preferences->quiet_hours_end, $user->timezone ?? 'UTC');

        if ($start->isAfter($end)) {
            // Overnight quiet hours (e.g. 10 PM to 8 AM)
            return $now->greaterThan($start) || $now->lessThan($end);
        }

        return $now->between($start, $end);
    }

    public function isDigestEnabled(User $user): bool
    {
        $preferences = $this->getUserPreferences($user);
        return $preferences->digest_enabled ?? false;
    }

    private function getDefaultChannels(string $notificationType): array
    {
        return match ($notificationType) {
            'purchase_confirmation' => ['mail', 'database'],
            'new_sale' => ['mail', 'database'],
            'review_received' => ['mail', 'database'],
            'comment_reply' => ['database'],
            'component_published' => ['mail', 'database'],
            'team_invite' => ['mail', 'database'],
            'password_changed' => ['mail'],
            'login_new_device' => ['mail'],
            default => ['database'],
        };
    }

    private function getUserPreferences(User $user): object
    {
        return DB::table('user_notification_settings')
            ->where('user_id', $user->id)
            ->first() ?? (object) [
                'quiet_hours_enabled' => false,
                'quiet_hours_start' => '22:00',
                'quiet_hours_end' => '08:00',
                'digest_enabled' => false,
            ];
    }
}
```

# 11. Notification Controller

```php
<?php

declare(strict_types=1);

namespace App\Http\Controllers;

use App\Domains\Notifications\Services\NotificationPreferenceService;
use App\Models\User;
use Illuminate\Http\JsonResponse;
use Illuminate\Http\Request;
use Illuminate\Notifications\DatabaseNotification;

final class NotificationController extends Controller
{
    public function index(Request $request): JsonResponse
    {
        $notifications = $request->user()
            ->notifications()
            ->orderByDesc('created_at')
            ->paginate(20);

        return response()->json([
            'data' => $notifications->items(),
            'meta' => [
                'unread_count' => $request->user()->unreadNotifications()->count(),
                'total' => $notifications->total(),
                'current_page' => $notifications->currentPage(),
                'last_page' => $notifications->lastPage(),
            ],
        ]);
    }

    public function markRead(Request $request, DatabaseNotification $notification): JsonResponse
    {
        abort_unless($notification->notifiable_id === $request->user()->id, 403);

        $notification->markAsRead();

        return response()->json(['message' => 'Notification marked as read.']);
    }

    public function markAllRead(Request $request): JsonResponse
    {
        $request->user()->unreadNotifications()->update([
            'read_at' => now(),
        ]);

        return response()->json(['message' => 'All notifications marked as read.']);
    }

    public function preferences(Request $request, NotificationPreferenceService $service): JsonResponse
    {
        $types = [
            'component_published',
            'comment_reply',
            'purchase_confirmation',
            'new_sale',
            'review_received',
            'team_invite',
            'password_changed',
            'login_new_device',
        ];

        $preferences = [];
        foreach ($types as $type) {
            $preferences[$type] = $service->getChannels($request->user(), $type);
        }

        return response()->json(['data' => $preferences]);
    }

    public function updatePreferences(Request $request, NotificationPreferenceService $service): JsonResponse
    {
        $validated = $request->validate([
            'preferences' => ['required', 'array'],
            'preferences.*.type' => ['required', 'string'],
            'preferences.*.channels' => ['required', 'array'],
            'preferences.*.channels.*' => ['string', Rule::in(['mail', 'database', 'sms', 'push'])],
        ]);

        foreach ($validated['preferences'] as $pref) {
            $service->updatePreference(
                $request->user(),
                $pref['type'],
                $pref['channels'],
            );
        }

        return response()->json(['message' => 'Preferences updated.']);
    }

    public function unreadCount(Request $request): JsonResponse
    {
        return response()->json([
            'count' => $request->user()->unreadNotifications()->count(),
```

# 22. Notification Best Practices

1. **Use `Queueable` trait** on all notifications for non-blocking dispatch.
2. **Store data in `toArray()`** — the database channel persists this for the inbox.
3. **Use `via()` to resolve channels** per notification type and user preferences.
4. **Respect quiet hours** — check preferences before dispatching mail/SMS.
5. **Use `MailMessage`** for consistent email formatting across notifications.
6. **Test with `Notification::fake()`** in unit tests for deterministic assertions.
7. **Dispatch from listeners**, not from controllers — keep controllers thin.
8. **Record notification analytics** — track send rates, open rates, delivery failures.
9. **Provide preference UI** — let users control which channels they receive.
10. **Use signed URLs** for sensitive notification links (password reset, invitations).

# 24. Notification Analytics Service

```php
<?php

declare(strict_types=1);

namespace App\Domains\Notifications\Services;

use Illuminate\Support\Facades\DB;
use Carbon\Carbon;

final class NotificationAnalyticsService
{
    public function getSendStats(string $notificationType, int $days = 30): array
    {
        return DB::table('notifications')
            ->where('type', $notificationType)
            ->where('created_at', '>=', now()->subDays($days))
            ->select(
                DB::raw('date(created_at) as date'),
                DB::raw('count(*) as count')
            )
            ->groupBy('date')
            ->orderBy('date')
            ->get()
            ->toArray();
    }

    public function getOpenRate(string $notificationType, int $days = 30): float
    {
        $total = DB::table('notifications')
            ->where('type', $notificationType)
            ->where('created_at', '>=', now()->subDays($days))
            ->count();

        if ($total === 0) {
            return 0;
        }

        $read = DB::table('notifications')
            ->where('type', $notificationType)
            ->where('created_at', '>=', now()->subDays($days))
            ->whereNotNull('read_at')
            ->count();

        return round(($read / $total) * 100, 2);
    }

    public function getChannelDistribution(int $days = 30): array
    {
        return DB::table('notifications')
            ->where('created_at', '>=', now()->subDays($days))
            ->select('type', DB::raw('count(*) as count'))
            ->groupBy('type')
            ->orderByDesc('count')
            ->get()
            ->keyBy('type')
            ->map(fn ($row) => $row->count)
            ->toArray();
    }

    public function getFailureRate(int $days = 30): array
    {
        return DB::table('notification_failures')
            ->where('created_at', '>=', now()->subDays($days))
            ->select('type', DB::raw('count(*) as count'))
            ->groupBy('type')
            ->get()
            ->keyBy('type')
            ->map(fn ($row) => $row->count)
            ->toArray();
    }

    public function getUserEngagement(int $userId, int $days = 30): array
    {
        $notifications = DB::table('notifications')
            ->where('notifiable_id', $userId)
            ->where('created_at', '>=', now()->subDays($days))
            ->get();

        $total = $notifications->count();
        $read = $notifications->where('read_at', '!=', null)->count();

        return [
            'total_received' => $total,
            'total_read' => $read,
            'open_rate' => $total > 0 ? round(($read / $total) * 100, 2) : 0,
            'by_type' => $notifications->groupBy('type')->map(fn ($group) => [
                'total' => $group->count(),
                'read' => $group->where('read_at', '!=', null)->count(),
            ]),
        ];
    }
}
```

# 28. Notification Delivery Service

```php
<?php

declare(strict_types=1);

namespace App\Domains\Notifications\Services;

use App\Domains\Users\Models\User;
use Illuminate\Notifications\Notification;
use Illuminate\Support\Facades\DB;

final class NotificationDeliveryService
{
    public function __construct(
        private NotificationPreferenceService $preferences,
    ) {}

    public function send(User $user, Notification $notification): void
    {
        $notificationType = $this->resolveType($notification);
        $channels = $this->preferences->getChannels($user, $notificationType);

        // Check quiet hours for non-critical notifications
        if ($this->preferences->isQuietHours($user) && ! $this->isCritical($notificationType)) {
            $channels = array_filter($channels, fn ($c) => $c !== 'mail' && $c !== 'sms');
        }

        if (empty($channels)) {
            return;
        }

        try {
            $user->notify($notification, $channels);

            $this->logDelivery($notificationType, $user, $channels, true);
        } catch (\Throwable $e) {
            $this->logDelivery($notificationType, $user, $channels, false, $e->getMessage());
            report($e);
        }
    }

    public function sendToMultiple(array $users, Notification $notification): void
    {
        foreach ($users as $user) {
            $this->send($user, $notification);
        }
    }

    private function resolveType(Notification $notification): string
    {
        $class = get_class($notification);

        return class_basename($class);
    }

    private function isCritical(string $type): bool
    {
        return in_array($type, [
            'PasswordChanged',
            'LoginFromNewDevice',
            'SuspiciousActivity',
            'PurchaseConfirmation',
        ]);
    }

    private function logDelivery(string $type, User $user, array $channels, bool $success, ?string $error = null): void
    {
        DB::table('notification_logs')->insert([
            'type' => $type,
            'notifiable_id' => $user->id,
            'notifiable_type' => get_class($user),
            'channel' => implode(',', $channels),
            'success' => $success,
            'error' => $error,
            'sent_at' => now(),
            'created_at' => now(),
        ]);
    }
}
```

# 32. Notification Best Practices (Extended)

1. **Never send notifications synchronously** — always use queued jobs.
2. **Use `Notification::fake()`** in tests to avoid real deliveries.
3. **Log delivery failures** — track failure rates per channel.
4. **Respect user preferences** — check `NotificationPreferenceService` before sending.
5. **Use signed URLs** for sensitive links (password reset, invitations).
6. **Provide preference UI** — let users control channels and quiet hours.
7. **Monitor queue health** — alert when notification queue exceeds threshold.
8. **Use `MailMessage`** for consistent email formatting.
9. **Record analytics** — track open rates, delivery rates, engagement.
10. **Test notification data shape** — ensure `toArray()` matches database schema.
