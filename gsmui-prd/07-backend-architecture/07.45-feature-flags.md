# 07.45 - Feature Flags

**Project:** GsmUi
**Architecture:** Feature Flag Service
**Framework:** Laravel 13 + Livewire 4
**Version:** 1.0.0

---

> See also: `06.102-feature-flags.md` (schema for `feature_flags`, `feature_flag_overrides`, `feature_flag_history`). This document is the *implementation contract*: the `FeatureFlagService` interface, the `isEnabled` evaluation rule set (global flag + percentage rollout + per-user override), evaluation caching, and the history-writing hook.

# Purpose

Feature flags let GsmUi ship code dark, run gradual percentage rollouts, run A/B splits, and kill-switch misbehaving features without a deployment. This document specifies the evaluation service so every caller — controller, Livewire component, job, or Artisan command — resolves a flag through one contract, and so flag state is consistent and cacheable across requests.

Goals:

- **One evaluation seam** — callers use `FeatureFlagService::isEnabled('name', $userId)`, never raw DB queries against `feature_flags`.
- **Override precedence** — per-user override beats the global flag; a disabled global flag is a hard kill-switch regardless of override.
- **Cheap evaluation** — the resolved flag set is cached per request/per user with a short TTL; the global flag set is cached cluster-wide.
- **Auditable changes** — every activation/deactivation/rule update writes a `feature_flag_history` row (see `06.102-feature-flags.md`).

## 1. FeatureFlagService Contract

```php
namespace App\Domains\Shared\Contracts;

interface FeatureFlagService
{
    /** Evaluate a flag for an optional actor (null = anonymous/global evaluation). */
    public function isEnabled(string $name, ?int $userId = null): bool;

    /** Force a flag on/off for a specific user (creates/updates an override). */
    public function setOverride(string $name, ?int $userId, bool $enabled): void;

    /** Activate/deactivate the global flag and record history. */
    public function setActive(string $name, bool $active, ?int $actorId = null): void;

    /** Replace rollout rules (percentage, segments) and record history. */
    public function setRules(string $name, array $rules, ?int $actorId = null): void;
}
```

---

## 2. Evaluation Rules

Resolution order for `isEnabled($name, $userId)`:

```text
1. Flag missing?                       -> false (fail closed)
2. Global is_active == false?          -> false (kill-switch, ignore override)
3. Override exists for (flag, user)?   -> override.is_enabled
4. rules.percentage set?               -> hash(userId) % 100 < percentage
5. rules.segments match user?          -> true
6. Otherwise                           -> global is_active
```

The percentage rollout is deterministic: the same user always lands in or out of the bucket, keyed by a stable HMAC of `user_id` so the result does not flicker between requests.

## 3. Implementation

```php
namespace App\Domains\Shared\Services;

use App\Domains\Shared\Contracts\FeatureFlagService;
use App\Domains\Admin\Models\FeatureFlag;
use App\Domains\Admin\Models\FeatureFlagOverride;
use Illuminate\Support\Facades\{Cache, DB};

final class FeatureFlagServiceImpl implements FeatureFlagService
{
    public function isEnabled(string $name, ?int $userId = null): bool
    {
        $flag = $this->flag($name);

        if ($flag === null || ! $flag->is_active) {
            return false; // fail closed + kill-switch
        }

        if ($userId !== null) {
            $override = $this->override($flag->id, $userId);
            if ($override !== null) {
                return $override->is_enabled;
            }
        }

        return $this->matchesRollout($flag->rules ?? [], $userId);
    }

    public function setOverride(string $name, ?int $userId, bool $enabled): void
    {
        $flag = $this->flag($name) ?? throw new \InvalidArgumentException("Unknown flag: {$name}");

        FeatureFlagOverride::updateOrCreate(
            ['feature_flag_id' => $flag->id, 'user_id' => $userId],
            ['is_enabled' => $enabled],
        );

        $this->forgetUserCache($name, $userId);
    }

    public function setActive(string $name, bool $active, ?int $actorId = null): void
    {
        DB::transaction(function () use ($name, $active, $actorId): void {
            $flag = $this->flag($name) ?? throw new \InvalidArgumentException("Unknown flag: {$name}");
            $old = $flag->is_active;
            $flag->update(['is_active' => $active]);
            $this->recordHistory($flag->id, $actorId, $active ? 'activated' : 'deactivated',
                ['is_active' => $old], ['is_active' => $active]);
        });

        $this->forgetGlobalCache($name);
    }

    private function matchesRollout(array $rules, ?int $userId): bool
    {
        if (isset($rules['percentage']) && $userId !== null) {
            $bucket = hexdec(substr(hash_hmac('sha256', "flag:{$userId}", config('app.key')), 0, 2)) % 100;
            if ($bucket < (int) $rules['percentage']) {
                return true;
            }
        }

        if (! empty($rules['segments']) && $userId !== null) {
            return $this->userInSegments($userId, $rules['segments']);
        }

        return true; // global flag is active and no targeting matched
    }

    private function flag(string $name): ?FeatureFlag
    {
        return Cache::remember("flag:{$name}", 300,
            fn () => FeatureFlag::where('name', $name)->first());
    }

    private function override(int $flagId, int $userId): ?FeatureFlagOverride
    {
        return Cache::remember("flag:override:{$flagId}:{$userId}", 300,
            fn () => FeatureFlagOverride::where('feature_flag_id', $flagId)
                ->where('user_id', $userId)->first());
    }

    private function recordHistory(int $flagId, ?int $actorId, string $action, array $old, array $new): void
    {
        \App\Domains\Admin\Models\FeatureFlagHistory::create([
            'feature_flag_id' => $flagId,
            'user_id'         => $actorId,
            'action'          => $action,
            'old_value'       => $old,
            'new_value'       => $new,
        ]);
    }
}
```

## 5. Caching & Invalidation

| Cache key | TTL | Invalidated on |
| --- | --- | --- |
| `flag:{name}` | 300s | `setActive`, `setRules` |
| `flag:override:{flagId}:{userId}` | 300s | `setOverride` |
| request-level resolved set | per request | n/a (fresh per request) |

Cluster-wide invalidation uses the cache `forget` calls above; for Redis tag support see `07.25-cache.md`.

## 6. History & Audit

Every `setActive` / `setRules` / override change appends a `feature_flag_history` row via `recordHistory()`, satisfying the schema defined in `06.102-feature-flags.md` and feeding the admin audit trail (see `05.24-admin-platform-architecture.md`). Override creation also surfaces in `activity_logs` through an observer (see `07.47-observers.md`).

| Operation | `feature_flag_history.action` |
| --- | --- |
| Global flag on/off | `activated` / `deactivated` |
| Rules changed | `rules_updated` |
| Per-user override set | `override_added` / `override_removed` |

## 7. Reuse & Boundary Rules

A caller MAY:

- Call `isEnabled()` from any layer for gating behavior.
- Set overrides/active state from admin services only.

A caller MUST NOT:

- Query `feature_flags` directly to decide behavior.
- Infer rollout buckets manually instead of `matchesRollout()`.
- Cache the boolean result beyond the service's own cache TTL (stale kill-switch risk).

## 8. Feature Flag Lifecycle States

Every flag transitions through a well-defined lifecycle. Understanding these states prevents accidental misuse and provides a clear audit trail.

### 8.1 State Diagram

```text
[draft] --activate--> [active]
[active] --deactivate--> [inactive]
[inactive] --activate--> [active]
[active] --archive--> [archived]
[inactive] --archive--> [archived]
[archived] -- (no transitions allowed)
```

### 8.2 State Definitions

| State | Description | `isEnabled()` behavior | Allowed transitions |
| --- | --- | --- | --- |
| `draft` | Created but never activated; no rollout rules apply | `false` (flag missing from cache) | `active` |
| `active` | Global flag enabled; rollout rules evaluated normally | Depends on rules | `inactive`, `archived` |
| `inactive` | Global flag disabled; acts as kill-switch | `false` (hard) | `active`, `archived` |
| `archived` | Permanently retired; kept for audit trail only | `false` | None |

### 8.3 Lifecycle Management Service

```php
namespace App\Domains\Admin\Services;

use App\Domains\Admin\Models\FeatureFlag;
use App\Domains\Admin\Enums\FeatureFlagState;

final class FeatureFlagLifecycleService
{
    public function __construct(
        private readonly FeatureFlagService $flags,
    ) {}

    public function archive(string $name, int $actorId): void
    {
        $flag = FeatureFlag::where('name', $name)->firstOrFail();

        if ($flag->state === FeatureFlagState::Archived) {
            throw new \DomainException("Flag '{$name}' is already archived.");
        }

        // Must deactivate before archiving
        if ($flag->is_active) {
            $this->flags->setActive($name, false, $actorId);
        }

        $flag->update(['state' => FeatureFlagState::Archived]);
        $this->flags->forgetGlobalCache($name);

        $this->flags->recordHistory(
            $flag->id,
            $actorId,
            'archived',
            ['state' => $flag->state->value],
            ['state' => FeatureFlagState::Archived->value]
        );
    }

    public function bulkDeactivate(array $names, int $actorId): int
    {
        $count = 0;
        foreach ($names as $name) {
            $flag = FeatureFlag::where('name', $name)->where('is_active', true)->first();
            if ($flag) {
                $this->flags->setActive($name, false, $actorId);
                $count++;
            }
        }
        return $count;
    }
}
```

### 8.4 State Transition Validation

```php
namespace App\Domains\Admin\Enums;

enum FeatureFlagState: string
{
    case Draft = 'draft';
    case Active = 'active';
    case Inactive = 'inactive';
    case Archived = 'archived';

    public function canTransitionTo(self $target): bool
    {
        return match ($this) {
            self::Draft => in_array($target, [self::Active]),
            self::Active => in_array($target, [self::Inactive, self::Archived]),
            self::Inactive => in_array($target, [self::Active, self::Archived]),
            self::Archived => false,
        };
    }

    public function label(): string
    {
        return match ($this) {
            self::Draft => 'Draft (never activated)',
            self::Active => 'Active (evaluating)',
            self::Inactive => 'Inactive (kill-switch engaged)',
            self::Archived => 'Archived (permanently retired)',
        };
    }
}
```

## 9. Percentage Rollout Deep Dive

### 9.1 Deterministic Bucketing Algorithm

The bucketing uses HMAC-SHA256 to ensure deterministic, stable assignment. The same user always lands in the same bucket regardless of which server evaluates the flag.

```php
private function computeBucket(int $userId, string $flagName): int
{
    // HMAC key is the app key — different per environment, prevents cross-env leaks
    $hmac = hash_hmac('sha256', "flag:{$flagName}:{$userId}", config('app.key'));

    // Take the first 8 hex characters (32 bits) for uniform distribution
    $hex = substr($hmac, 0, 8);

    return hexdec($hex) % 100;
}
```

### 9.2 Bucket Distribution Guarantees

| Percentage | Expected users (per 1000) | Variance (σ) | Notes |
| --- | --- | --- | --- |
| 1% | 10 | ±3.2 | Statistical noise is high at low percentages |
| 5% | 50 | ±6.9 | Acceptable for early validation |
| 10% | 100 | ±9.5 | Good signal-to-noise ratio |
| 25% | 250 | ±13.7 | Reliable metric collection |
| 50% | 500 | ±15.8 | A/B test territory |
| 75% | 750 | ±13.7 | Pre-full-rollout validation |
| 90% | 900 | ±9.5 | Final validation before 100% |
| 100% | 1000 | 0 | Full rollout — no bucketing |

### 9.3 Gradual Rollout Playbook

When rolling out a new feature incrementally:

```text
Week 1:  1%  → validate no errors, monitor key metrics
Week 2:  5%  → validate performance impact
Week 3:  15% → collect user feedback, monitor support tickets
Week 4:  25% → validate business metrics (conversion, retention)
Week 5:  50% → full A/B comparison
Week 6:  75% → near-full validation
Week 7:  100% → remove flag, clean up conditional code
```

Each step requires a `setRules` call with the updated percentage, and the history record captures who changed it and when.

### 9.4 Anti-Patterns in Percentage Rollouts

```text
❌ Using rand() instead of HMAC — bucket assignment flickers between requests
❌ Changing the HMAC key between deploys — all users shift buckets
❌ Rollout 1% then jump to 100% — no gradual validation
❌ No rollback plan — always have a one-click deactivate ready
❌ Ignoring statistical significance — 1% rollout gives no signal
```

## 10. Segment-Based Targeting

### 10.1 Segment Types

Segments allow targeting flags to specific user groups without percentage rollouts.

```php
namespace App\Domains\Admin\Enums;

enum SegmentType: string
{
    case Role = 'role';           // Users with a specific role
    case Team = 'team';           // Users belonging to a specific team
    case Plan = 'plan';           // Users on a specific subscription plan
    case Attribute = 'attribute'; // Users matching an attribute (country, locale, etc.)
    case List = 'list';           // Explicit user ID list
}
```

### 10.2 Segment Resolution

```php
private function userInSegments(int $userId, array $segments): bool
{
    $user = \App\Domains\Users\Models\User::find($userId);
    if ($user === null) {
        return false;
    }

    foreach ($segments as $segment) {
        $type = SegmentType::from($segment['type']);

        $match = match ($type) {
            SegmentType::Role => $user->roles()->where('name', $segment['value'])->exists(),
            SegmentType::Team => $user->teams()->where('id', $segment['value'])->exists(),
            SegmentType::Plan => $user->subscription?->plan === $segment['value'],
            SegmentType::Attribute => data_get($user, $segment['key']) === $segment['value'],
            SegmentType::List => in_array($userId, $segment['user_ids'], true),
        };

        if ($match) {
            return true;
        }
    }

    return false;
}
```

### 10.3 Segment Configuration Schema

```json
{
    "segments": [
        {
            "type": "role",
            "value": "admin",
            "operator": "equals"
        },
        {
            "type": "plan",
            "value": "enterprise",
            "operator": "in",
            "values": ["enterprise", "business"]
        },
        {
            "type": "attribute",
            "key": "country",
            "value": "US",
```

### 10.4 Match Modes

| Mode | Behavior | Use case |
| --- | --- | --- |
| `any` | Flag is enabled if ANY segment matches | Broader targeting (OR logic) |
| `all` | Flag is enabled only if ALL segments match | Narrow targeting (AND logic) |

## 11. A/B Testing Integration

### 11.1 Variant Assignment


### 11.2 Variant Configuration

```json

        "control": {
            "weight": 50,
            "payload": {"button_color": "blue", "layout": "classic"}
        },
        "treatment_a": {
            "weight": 30,
            "payload": {"button_color": "green", "layout": "modern"}
```

### 11.3 Variant Resolution

```php
public function variant(string $name, ?int $userId = null): ?string
{
    $flag = $this->flag($name);

    if ($flag === null || !$flag->is_active || empty($flag->rules['variants'])) {
        return null;
    }

    if ($userId !== null) {
        $override = $this->override($flag->id, $userId);
        if ($override !== null && isset($override->variant)) {
            return $override->variant;
        }
    }

    $bucket = $this->computeBucket($userId ?? 0, $name);
    $variants = $flag->rules['variants'];

    $cumulative = 0;
    foreach ($variants as $key => $config) {
        $cumulative += $config['weight'];
        if ($bucket < $cumulative) {
            return $key;
        }
    }

    return array_key_first($variants);
}
```

## 12. Flag Dependencies & Ordering

### 12.1 Dependency Graph

Some flags depend on other flags being active. The dependency system prevents enabling a child flag before its parent is active.

```php
namespace App\Domains\Admin\Models;

use Illuminate\Database\Eloquent\Model;

class FeatureFlagDependency extends Model
{
    protected $fillable = ['feature_flag_id', 'depends_on_feature_flag_id'];

    public function flag(): BelongsTo
    {
        return $this->belongsTo(FeatureFlag::class, 'feature_flag_id');
    }

    public function dependsOn(): BelongsTo
    {
        return $this->belongsTo(FeatureFlag::class, 'depends_on_feature_flag_id');
    }
}
```

### 12.2 Dependency Validation

```php
public function validateDependencies(string $name): array
{
    $flag = FeatureFlag::where('name', $name)->firstOrFail();
    $issues = [];

    $dependencies = $flag->dependsOn;
    foreach ($dependencies as $dep) {
        if (!$dep->is_active) {
            $issues[] = "Flag '{$name}' requires '{$dep->name}' to be active first.";
        }
    }

    // Check for circular dependencies
    $visited = [];
    $this->detectCycles($flag->id, $visited, $issues);

    return $issues;
}

private function detectCycles(int $flagId, array &$visited, array &$issues): void
{
    if (in_array($flagId, $visited, true)) {
        $issues[] = "Circular dependency detected involving flag ID {$flagId}.";
        return;
    }

    $visited[] = $flagId;

    $dependents = FeatureFlagDependency::where('depends_on_feature_flag_id', $flagId)
        ->with('flag')
        ->get();

    foreach ($dependents as $dep) {
        $this->detectCycles($dep->feature_flag_id, $visited, $issues);
    }
}
```

### 12.3 Dependency Cascade Rules

```text
1. Parent flag deactivated → all child flags evaluate as disabled
2. Parent flag archived → child flags must be archived or their dependencies removed
3. Circular dependencies are rejected at the validation layer
4. Maximum dependency depth: 5 levels (prevents overly complex chains)
5. Dependency graph changes are audited like any other flag change
```

### 13.2 Controller Implementation

```php
namespace App\Http\Controllers\Api;

use App\Domains\Admin\Models\FeatureFlag;
use App\Domains\Shared\Contracts\FeatureFlagService;
use App\Http\Controllers\Controller;
use Illuminate\Http\JsonResponse;
use Illuminate\Http\Request;

final class FeatureFlagController extends Controller
{
    public function __construct(
        private readonly FeatureFlagService $flags,
    ) {}

    public function index(Request $request): JsonResponse
    {
        $flags = FeatureFlag::query()
            ->when($request->has('state'), fn ($q) => $q->where('state', $request->input('state')))
            ->when($request->has('search'), fn ($q) => $q->where('name', 'like', "%{$request->input('search')}%"))
            ->with('dependencies')
            ->orderBy('name')
            ->paginate($request->integer('per_page', 25));

        return response()->json($flags);
    }

    public function store(Request $request): JsonResponse
    {
        $validated = $request->validate([
            'name' => 'required|string|max:100|regex:/^[a-z][a-z0-9._-]*$/|unique:feature_flags,name',
            'description' => 'nullable|string|max:500',
            'rules' => 'nullable|array',
            'rules.percentage' => 'nullable|integer|min:0|max:100',
            'rules.segments' => 'nullable|array',
            'rules.variants' => 'nullable|array',
        ]);

        $flag = FeatureFlag::create([
            'name' => $validated['name'],
            'description' => $validated['description'] ?? null,
            'rules' => $validated['rules'] ?? null,
            'state' => 'draft',
            'is_active' => false,
        ]);

        return response()->json($flag, 201);
    }

    public function activate(FeatureFlag $flag, Request $request): JsonResponse
    {
        $this->flags->setActive($flag->name, true, $request->user()->id);

        return response()->json(['status' => 'activated']);
    }

    public function history(FeatureFlag $flag): JsonResponse
    {
        $history = $flag->history()->orderByDesc('created_at')->paginate(50);

        return response()->json($history);
    }

    public function bulkActivate(Request $request): JsonResponse
    {
        $validated = $request->validate([
            'flags' => 'required|array|min:1',
            'flags.*' => 'string|exists:feature_flags,name',
        ]);

        $count = 0;
        foreach ($validated['flags'] as $name) {
            $this->flags->setActive($name, true, $request->user()->id);
            $count++;
        }

        return response()->json(['activated' => $count]);
    }
}
```

## 14. Flag Synchronization Across Nodes

### 14.1 Cache Invalidation Strategy

In a multi-server deployment, flag changes must propagate to all nodes. The service uses Redis pub/sub for cross-node cache invalidation.

```php
namespace App\Domains\Shared\Services;

use Illuminate\Support\Facades\{Cache, Redis};

final class FeatureFlagSyncService
{
    private const CHANNEL = 'gsmui:feature-flags:invalidate';

    public function broadcastInvalidation(string $flagName): void
    {
        // Forget local cache
        Cache::forget("flag:{$flagName}");

        // Publish to Redis channel for other nodes
        Redis::publish(self::CHANNEL, json_encode([
            'flag' => $flagName,
            'timestamp' => microtime(true),
        ]));
    }

    public function subscribeToInvalidations(): void
    {
        Redis::subscribe([self::CHANNEL], function (string $message): void {
            $data = json_decode($message, true);
            Cache::forget("flag:{$data['flag']}");
        });
    }
}
```

### 14.2 Event-Driven Sync

For Horizon-processed invalidations (non-realtime acceptable):

```php
namespace App\Domains\Shared\Events;

use Illuminate\Foundation\Events\Dispatchable;

final class FeatureFlagChanged
{
    use Dispatchable;

    public function __construct(
        public readonly string $flagName,
        public readonly string $changeType,
        public readonly int $actorId,
    ) {}
}

// Listener that clears cache on all nodes via Redis broadcast
final class InvalidateFeatureFlagCache
{
    public function handle(FeatureFlagChanged $event): void
    {
        app(FeatureFlagSyncService::class)->broadcastInvalidation($event->flagName);
    }
}
```

### 14.3 Consistency Guarantees

| Guarantee | Mechanism | TTL fallback |
| --- | --- | --- |
| Immediate propagation | Redis pub/sub | 300s TTL expires stale entries |
| Eventual consistency | Cache TTL | 300s maximum staleness |
| Atomic flag update | DB transaction + cache forget | N/A |

## 19. Performance Considerations

### 19.1 Cache Strategy Matrix

| Operation | Cache layer | TTL | Invalidation |
| --- | --- | --- | --- |
| `flag($name)` | Redis | 300s | `setActive`, `setRules`, pub/sub |
| `override($flagId, $userId)` | Redis | 300s | `setOverride`, pub/sub |
| `variant($name, $userId)` | Request-scoped | Per request | N/A |
| `matchesRollout` | Computed | Per evaluation | N/A (cheap) |

### 19.2 Benchmark Targets

| Metric | Target | Notes |
| --- | --- | --- |
| `isEnabled()` cold | < 5ms | First call, cache miss |
| `isEnabled()` cached | < 0.5ms | Subsequent calls in same request |
| `isEnabled()` with override | < 1ms | Override cached separately |
| `setActive()` latency | < 50ms | DB write + cache invalidation |
| Bulk evaluation (100 flags) | < 10ms | All cached within request |

### 19.3 Memory Footprint

Per-request memory for feature flags:
- Base service: ~2KB
- Per evaluated flag: ~200 bytes (cached in request scope)
- Per user override: ~150 bytes
- Total typical request: < 50KB for 100 flags

### 19.4 Performance Optimization Rules

```text
1. Never evaluate the same flag twice per request (request-scoped cache)
2. Batch flag evaluations when checking multiple flags for the same user
3. Pre-warm cache on deploy for critical flags (optional optimization)
4. Monitor cache hit rate; investigate if below 90%
5. Use Redis pipeline for bulk invalidations during bulk flag changes
```

## 21. Configuration Validation

### 21.1 Rules Schema Validation

Every rules update is validated before persistence:

```php
namespace App\Domains\Admin\Services;

final class FeatureFlagValidationService
{
    private const SCHEMA = [
        'percentage' => 'nullable|integer|min:0|max:100',
        'segments' => 'nullable|array',
        'segments.*.type' => 'required|string|in:role,team,plan,attribute,list',
        'segments.*.value' => 'required_unless:type,list',
        'segments.*.user_ids' => 'required_if:type,list|array',
        'variants' => 'nullable|array',
        'variants.*.weight' => 'required|integer|min:1|max:100',
        'match_mode' => 'nullable|string|in:any,all',
    ];

    public function validateRules(array $rules): array
    {
        $validator = \Validator::make($rules, self::SCHEMA);

        if ($validator->fails()) {
            throw new \InvalidArgumentException(
                'Invalid flag rules: ' . $validator->errors()->first()
            );
        }

        // Validate variant weights sum to 100
        if (isset($rules['variants'])) {
            $total = array_sum(array_column($rules['variants'], 'weight'));
            if ($total !== 100) {
                throw new \InvalidArgumentException(
                    "Variant weights must sum to 100, got {$total}."
                );
            }
        }

        return $validator->validated();
    }
}
```

### 27.2 Tenant-Aware Evaluation

```php
namespace App\Domains\Shared\Services;

final class TenantFeatureFlagService implements FeatureFlagService
{
    public function isEnabledForTenant(string $name, int $tenantId, ?int $userId = null): bool
    {
        $flag = $this->globalFlag($name);

        if ($flag === null) {
            return false;
        }

        // Tenant-specific override
        $tenantFlag = $this->tenantFlag($flag->id, $tenantId);
        if ($tenantFlag !== null) {
            if (!$tenantFlag->is_active) {
                return false; // Tenant-level kill-switch
            }

            // Check user override within tenant
            if ($userId !== null) {
                $userOverride = $this->tenantUserOverride($tenantFlag->id, $userId);
                if ($userOverride !== null) {
                    return $userOverride->is_enabled;
                }
            }

            return $this->matchesRollout($tenantFlag->rules ?? $flag->rules ?? [], $userId);
        }

        // Fall back to global evaluation
        return $this->isEnabled($name, $userId);
    }

    private function tenantFlag(int $flagId, int $tenantId): ?TenantFeatureFlag
    {
        return Cache::remember(
            "flag:tenant:{$flagId}:{$tenantId}",
            300,
            fn () => TenantFeatureFlag::where('feature_flag_id', $flagId)
                ->where('tenant_id', $tenantId)
                ->first()
        );
    }
}
```

## 28. Feature Flag Analytics

### 28.1 Evaluation Tracking

Track flag evaluations for analytics and debugging:

```php
namespace App\Domains\Shared\Services;

final class FeatureFlagAnalyticsService
{
    public function recordEvaluation(string $flagName, ?int $userId, bool $result, string $reason): void
    {
        // Use a lightweight append-only table
        DB::table('feature_flag_evaluations')->insert([
            'flag_name' => $flagName,
            'user_id' => $userId,
            'result' => $result,
            'reason' => $reason, // 'global_active', 'override', 'percentage', 'segment', etc.
            'created_at' => now(),
        ]);
    }

    public function getEvaluationStats(string $flagName, \DateTimeInterface $from, \DateTimeInterface $to): array
    {
        return DB::table('feature_flag_evaluations')
            ->where('flag_name', $flagName)
            ->whereBetween('created_at', [$from, $to])
            ->selectRaw('
                COUNT(*) as total_evaluations,
                SUM(CASE WHEN result = 1 THEN 1 ELSE 0 END) as enabled_count,
                SUM(CASE WHEN result = 0 THEN 1 ELSE 0 END) as disabled_count,
                COUNT(DISTINCT user_id) as unique_users
            ')
            ->first();
    }

    public function getEvaluationReasons(string $flagName, \DateTimeInterface $from, \DateTimeInterface $to): Collection
    {
        return DB::table('feature_flag_evaluations')
            ->where('flag_name', $flagName)
            ->whereBetween('created_at', [$from, $to])
            ->selectRaw('reason, COUNT(*) as count')
            ->groupBy('reason')
            ->orderByDesc('count')
            ->get();
    }

    public function getDailyEvaluationTrend(string $flagName, int $days = 30): Collection
    {
        return DB::table('feature_flag_evaluations')
            ->where('flag_name', $flagName)
            ->where('created_at', '>=', now()->subDays($days))
            ->selectRaw('
                DATE(created_at) as date,
                COUNT(*) as total,
                SUM(CASE WHEN result = 1 THEN 1 ELSE 0 END) as enabled
            ')
            ->groupBy('date')
            ->orderBy('date')
            ->get();
    }
}
```

### 30.2 Optimization Guidelines

```text
1. Keep flag count per request under 20 for optimal performance
2. Use request-scoped caching for repeated evaluations of the same flag
3. Pre-warm critical flags in middleware for high-traffic routes
4. Monitor cache hit rate — investigate if below 95%
5. Use Redis pipeline for bulk invalidations
6. Avoid computing segments on every evaluation — cache segment membership
7. Consider flag evaluation budget: ~5ms total per request for all flags
```
