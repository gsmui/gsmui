# 07.01 - Overview

**Project:** GsmUi
**Architecture:** Modular Monolith / Service Layer
**Framework:** Laravel 13 + Livewire 4
**Version:** 1.0.0

---

> See also: `05.01-overview.md` (system architecture overview), `05.06-folder-structure.md` (physical directory layout). This document scopes Section 07 and does NOT re-document the conceptual architecture — it specifies the *backend implementation mechanics* on top of those foundations.

# Purpose

Section 07 is the contractor-ready, implementation-level companion to the conceptual architecture in Section 05 and the database schema in Section 06. Where 05 describes *what the system is* and 06 describes *how data is stored*, 07 specifies *how the backend is built*: concrete interfaces, class skeletons, method signatures, directory contracts, configuration, middleware, exception handling, service-provider registration, and per-layer testing.

The goal of this section is to remove ambiguity for implementers. A developer reading 07.06 must be able to write a service that compiles and matches the rest of the codebase without further clarification. Cross-references to 05/06 are filename-based so the chain stays stable as those documents evolve.

The scope of Section 07 covers every backend domain, pattern, and mechanism through the full request lifecycle — from the HTTP kernel down to the model and back out through the response handler — plus cross-cutting concerns (errors, logging, security, testing, deployment, coding standards).

## 2. Layer Recap

The GsmUi backend is a **Modular Monolith**. A single Laravel 13 application is partitioned into business domains under `app/Domains/*`, each communicating through services, actions, events, and queries rather than direct persistence access.

| Layer | Responsibility | Defined in |
| --- | --- | --- |
| Presentation | Blade / Livewire / API HTTP concerns | `07.19-livewire-architecture.md`, `07.20-blade-component-architecture.md`, `07.21-api-architecture.md` |
| Application | Actions + Services (use cases) | `07.06-service-layer.md`, `07.08-action-layer.md` |
| Domain | Entities, VOs, ENUMs, rules | `07.10-value-objects.md`, `07.11-enums.md`, `07.48-models.md` |
| Infrastructure | Repositories, cache, search, storage | `07.07-repository-layer.md`, `07.24-search.md`, `07.25-cache.md` |
| Cross-cutting | Errors, logging, security, testing | `07.53-error-handling.md`, `07.54-logging.md`, `07.57-security.md`, `07.55-testing.md` |

The dependency rule is strict: `Livewire/Controller → Action → Service → Repository → Model`. Forbidden edges are documented in `05.06-folder-structure.md` and re-stated as implementation contracts in `07.07-repository-layer.md`.

## 4. Coding Conventions Summary

All backend code in Section 07 follows a single set of conventions. Deviations require an architectural review.

### 4.1 PHP Style Rules

| Rule | Standard | Example |
| --- | --- | --- |
| PSR | PSR-12 (Extended Coding Style) | Opening braces on same line for classes, next line for methods |
| Strict types | `declare(strict_types=1)` on every file | First line of every PHP file |
| Return types | Always declared; `void` when nothing returned | `public function find(int $id): ?Component` |
| Nullable types | `?Type` syntax (not `Type\|null`) | `public function findBySlug(string $slug): ?Component` |
| Readonly classes | `final readonly class` for Value Objects | `final readonly class ThemeToken` |
| Immutability | Value objects are `readonly`, DTOs are `readonly` | `readonly class` or `readonly` properties |
| Naming | `PascalCase` for classes, `camelCase` for methods, `snake_case` for DB columns | `ComponentService`, `findBySlug()`, `created_at` |
| Visibility | Explicit `public` / `protected` / `private` on every member | No implicit public methods |
| Enums | Backed enums with `string` or `int` backing | `ComponentStatus::Published` |
| Final | Services, Actions, Value Objects, DTOs are `final` | Prevents accidental extension |
| No magic | No `__call`, no `__get`, no dynamic properties | Explicit methods only |
| Array shapes | Use DTOs or Value Objects, not raw arrays | `ComponentData` instead of `array` |

### 4.2 File Naming Conventions

| Artifact | Pattern | Example |
| --- | --- | --- |
| Service | `{Name}Service.php` | `ComponentService.php` |
| Repository Interface | `{Name}RepositoryInterface.php` | `ComponentRepositoryInterface.php` |
| Repository Implementation | `{Name}Repository.php` | `ComponentRepository.php` |
| Action | `{Verb}{Name}Action.php` | `CreateComponentAction.php` |
| DTO | `{Name}Data.php` | `ComponentData.php` |
| Value Object | `{Concept}.php` | `ThemeToken.php` |
| Enum | `{Concept}.php` | `ComponentStatus.php` |
| Event | `{Name}{PastVerb}.php` | `ComponentReleased.php` |
| Listener | `{Name}{PastVerb}Listener.php` | `ComponentReleasedListener.php` |
| Policy | `{Model}Policy.php` | `ComponentPolicy.php` |
| Form Request | `{Action}{Model}Request.php` | `CreateComponentRequest.php` |
| Livewire Component | `{Name}Page.php` or `{Name}Form.php` | `ComponentShowPage.php` |
| Migration | `{Timestamp}_{description}.php` | `2025_01_01_000001_create_components_table.php` |
| Factory | `{Model}Factory.php` | `ComponentFactory.php` |
| Test | `{ClassName}Test.php` | `ComponentServiceTest.php` |

### 4.3 Method Naming Rules

| Method type | Pattern | Example |
| --- | --- | --- |
| Finder | `find{By}{Field}()` | `findBySlug()`, `findById()` |
| Collection | `all{Filtered}()` or `paginate{Filtered}()` | `allPublished()`, `paginatePublished()` |
| Check | `exists{Condition}()` or `has{Condition}()` | `slugExists()`, `hasActiveSubscription()` |
| Mutation | `create{Data}()`, `update{Model}()`, `delete{Model}()` | `create(ComponentData $data)` |
| Query | `query{Concept}()` or `search{Concept}()` | `searchComponents()` |
| Event dispatch | `dispatch{Event}()` | `dispatchAfterCommit()` |
| Validation | `validate{Condition}()` | `validateUniqueSlug()` |

## 5. Dependency Injection Strategy

GsmUi uses Laravel's container for all dependency resolution. No manual service location (`app()`) is allowed outside of service providers.

### 5.1 Binding Rules

| Binding type | Registered in | Lifetime |
| --- | --- | --- |
| Repository contract → Eloquent impl | Domain `<Name>ServiceProvider` | Singleton (shared instance) |
| Service contract → Concrete service | Domain `<Name>ServiceProvider` | Singleton |
| Action classes | Auto-resolved by container | Transient (new instance per call) |
| External SDK adapters | `InfrastructureServiceProvider` | Singleton |
| Shared contracts | `SharedServiceProvider` | Singleton or factory as needed |

### 5.2 Constructor Injection Pattern

```php
// Correct: all dependencies injected via constructor
final class ComponentService extends AbstractService implements ComponentServiceContract
{
    public function __construct(
        private readonly ComponentRepositoryInterface $components,
        private readonly UserRepositoryInterface $users,
        private readonly CacheService $cache,
    ) {}
}

// Wrong: service locator
final class ComponentService extends AbstractService
{
    public function create(array $data): Component
    {
        $repo = app(ComponentRepository::class); // FORBIDDEN
        return $repo->create($data);
    }
}
```

### 5.3 Container Resolution Flow

```text
Action::run()
    │
    ├── Container resolves Action
    │       ├── Inject Service contract (bound by DomainServiceProvider)
    │       ├── Inject Repository contract (bound by DomainServiceProvider)
    │       └── Inject Cache contract (bound by InfrastructureServiceProvider)
    │
    ├── Service resolves internally
    │       ├── Repository implementation (already bound)
    │       └── Other service contracts (cross-module via Contracts/)
    │
    └── Repository resolves internally
            ├── Model class (string, not injected)
            └── Query scope helpers (static, not injected)
```

### 5.4 Scoped Bindings for Request-Specific State

```php
// In DomainServiceProvider
$this->app->scoped(CurrentUserService::class, fn ($app) => new CurrentUserService(
    auth()->user(),
));
```

`scoped` ensures a single instance per request but allows re-resolution between requests (important for queue workers).

## 6. Error Handling Strategy

Section 07 establishes a uniform error-handling contract. The full specification lives in `07.53-error-handling.md`; this overview defines the principles.

### 6.1 Exception Hierarchy

```text
Throwable
├── RuntimeException (framework)
│   ├── InvalidArgumentException (validation)
│   ├── LogicException (programming errors)
│   │   └── DomainException (GsmUi business rule violations)
│   │       ├── ComponentAlreadyExistsException
│   │       ├── SubscriptionRequiredException
│   │       ├── ThemeAlreadyPublishedException
│   │       └── LicenseExpiredException
│   └── HttpException (HTTP status codes)
│       ├── 400 BadRequestException
│       ├── 401 AuthenticationException
│       ├── 403 AuthorizationException
│       ├── 404 NotFoundException
│       ├── 409 ConflictException
│       ├── 422 ValidationException
│       └── 429 TooManyRequestsException
├── \Exception (unexpected)
└── \Error (PHP fatal)
```

### 6.2 Exception Placement Rules

| Layer | May throw | Must NOT throw |
| --- | --- | --- |
| Repository | `ModelNotFoundException`, `QueryException`, `ConnectionException` | Business logic exceptions |
| Service | Domain exceptions (`ComponentAlreadyExistsException`) | HTTP exceptions, raw DB exceptions |
| Action | Domain exceptions, re-throws from service | Exceptions that should be handled (swallowed) |
| Controller | Nothing — delegates to exception handler | Business logic exceptions |
| Livewire | Nothing — delegates to exception handler | Direct DB exceptions |

### 6.3 Handler Rendering

```text
Exception thrown
    │
    ▼
Handler::render($request, $exception)
    │
    ├── API request (Accept: application/json)
    │       └── Problem+JSON response
    │           {
    │               "type": "https://gsmui.dev/errors/component-exists",
    │               "title": "Component Already Exists",
    │               "status": 409,
    │               "detail": "A component with slug 'button' already exists.",
    │               "instance": "/components/button"
    │           }
    │
    ├── Web request (traditional)
    │       └── Blade error view (404, 403, 419, 429, 500)
    │
    └── Livewire request
            └── Livewire component error (flash message + redirect or re-render)
```

## 7. Logging and Observability

Logging is defined in `07.54-logging.md`. The overview establishes the principles:

### 7.1 Log Levels

| Level | When to use | Example |
| --- | --- | --- |
| `debug` | Development-only diagnostics | Variable dumps, query timing |
| `info` | Normal business events | User registered, component published |
| `warning` | Unexpected but recoverable | Rate limit approaching, cache miss |
| `error` | Operation failed but app continues | External API timeout, payment failed |
| `critical` | Immediate attention required | Database connection lost, disk full |

### 7.2 Context Fields

Every log entry must include:

| Field | Type | Source |
| --- | --- | --- |
| `correlation_id` | `string` (UUID) | HTTP middleware or queue middleware |
| `user_id` | `int\|null` | Auth context |
| `module` | `string` | Domain name (`components`, `billing`) |
| `action` | `string` | Method name or use case |
| `model_type` | `string\|null` | Eloquent model class name |
| `model_id` | `int\|null` | Eloquent model ID |

### 7.3 Activity Log

Significant state changes are recorded to an `activity_log` table (via `spatie/laravel-activitylog` or a custom implementation). This provides an audit trail independent of application logs.

| Event | Activity logged | Retention |
| --- | --- | --- |
| User login/logout | User ID, IP, user agent | 90 days |
| Component created/published/deleted | Component ID, actor, before/after | 1 year |
| Subscription changed | Subscription ID, plan, status | 7 years |
| Payment processed | Payment ID, amount, status | 7 years |
| Admin action | Admin ID, target, action | 7 years |

## 8. Security Overview

Security is detailed in `07.57-security.md`. The overview states the principles:

### 8.1 Security Layers

```text
┌─────────────────────────────────────────────────────────┐
│                    Security Layers                      │
├─────────────────────────────────────────────────────────┤
│  1. Network       │ TLS termination, WAF, rate limiting │
│  2. HTTP          │ CSRF, CORS, security headers        │
│  3. Auth          │ Laravel Breeze, session/token auth   │
│  4. Authorization │ Policies, Gates, role-based access   │
│  5. Validation    │ Form Requests, DTO validation        │
│  6. Data          │ Encryption at rest, hashing          │
│  7. CSP           │ Content Security Policy headers      │
│  8. Audit         │ Activity log, login tracking         │
└─────────────────────────────────────────────────────────┘
```

### 8.2 Authentication Flow

```text
User submits credentials
    │
    ▼
LoginController → Validates credentials
    │
    ├── Success → Creates session → Redirects to dashboard
    │       ├── Sets CSRF token
    │       ├── Logs activity (user_id, IP, user_agent)
    │       └── Checks two-factor auth requirement
    │
    └── Failure → Increments attempt counter → Returns with error
            └── After 5 failures → Rate limit (15 min cooldown)
```

### 8.3 Authorization Flow

```text
Request enters system
    │
    ▼
Gate/Policy check
    │
    ├── Policy::view($user, $component)
    │       ├── $component->user_id === $user->id  →  allow
    │       ├── $user->hasRole('admin')            →  allow
    │       └── otherwise                          →  deny (403)
    │
    └── Gate::define('publish-component', fn ($user, $component) => ...)
            └── Used for fine-grained, non-model-specific checks
```

## 9. Testing Strategy

Testing is detailed in `07.55-testing.md`. The overview defines the testing pyramid for GsmUi:

### 9.1 Testing Pyramid

```text
        ╱╲
       ╱  ╲          Browser Tests (Playwright)
      ╱    ╲         Full user flows, visual regression
     ╱──────╲
    ╱        ╲       Feature Tests (HTTP + Livewire)
   ╱          ╲      Controller/Action/Livewire integration
  ╱────────────╲
 ╱              ╲    Unit Tests (Services, Repositories, Actions)
╱                ╲   Individual class behavior, isolated
╱──────────────────╲
```

### 9.2 Test Types and Scope

| Test type | Scope | Runs against | Speed target |
| --- | --- |--- | --- |
| Unit | Single class, mocked dependencies | In-memory | < 10ms each |
| Feature | Action + Service + Repository, real DB | Test database | < 100ms each |
| Integration | Cross-module flows, queue jobs | Test database + Redis | < 500ms each |
| HTTP | Controller responses, API contracts | Test database | < 200ms each |
| Livewire | Component render + interaction | Test database + DOM | < 500ms each |
| Browser | End-to-end user flows | Running app | < 5s each |
| Architecture | Dependency rules, namespace constraints | Static analysis | < 1s each |

### 9.3 Test Naming Convention

```php
// Feature test: method_name_scenario_expected_result
class ComponentServiceTest extends TestCase
{
    /** @test */
    public function create_with_valid_data_persists_component(): void { /* ... */ }

    /** @test */
    public function create_with_duplicate_slug_throws_exception(): void { /* ... */ }

    /** @test */
    public function find_with_nonexistent_id_returns_null(): void { /* ... */ }

    /** @test */
    public function publish_dispatches_event_after_commit(): void { /* ... */ }

```

## 10. Performance Guidelines

### 10.1 Database Performance

| Guideline | Rule | Enforcement |
| --- | --- | --- |
| N+1 prevention | Eager-load all relations in repository `find`/`paginate` methods | Repository contract, code review |
| Query optimization | Use `select()` for list views, `chunk()` for bulk operations | Repository implementation |
| Indexing | Every foreign key indexed, frequently queried columns indexed | Migration review |
| Soft deletes | Use `SoftDeletes` on user-owned models; hard delete on related pivot data | Model trait |
| Connection pooling | Use read replicas for heavy read queries | Repository config |

### 10.2 Caching Strategy

```text
┌─────────────────────────────────────────────────────────┐
│                    Caching Layers                       │
├─────────────────────────────────────────────────────────┤
│  1. Application cache  │ Redis for hot data (5-60 min)  │
│  2. Query cache        │ Eloquent query result cache     │
│  3. View cache         │ Compiled Blade templates        │
│  4. Route cache        │ Compiled route definitions      │
│  5. Config cache       │ Merged config files             │
│  6. Event cache        │ Domain event listener results   │
└─────────────────────────────────────────────────────────┘
```

### 10.3 Queue and Job Performance

| Pattern | When to use | Example |
| --- | --- | --- |
| Sync (no queue) | Fast operations (< 100ms) | Activity log write |
| Queued (default queue) | Medium operations (100ms - 5s) | Email send, notification |
| Queued (priority queue) | Time-sensitive operations | Payment processing |
| Queued (bulk queue) | Batch operations | Search re-indexing, export |
| Delayed queue | Scheduled future work | License renewal reminder |

### 10.4 Memory Management

- Use `cursor()` for large result sets instead of `get()`
- Use `chunk()` for processing in batches of 500-1000 rows
- Avoid loading full models when only a few columns are needed (use `select()`)
- Use `defer()` for non-blocking background work within requests
- Monitor queue worker memory with `queue:work --max-jobs=1000 --max-time=3600`

## 12. Monitoring and Alerting

### 12.1 Health Check Endpoint

```php
// GET /up
Route::get('/up', function () {
    return response()->json([
        'status' => 'ok',
        'timestamp' => now()->toIso8601String(),
        'checks' => [
            'database' => DB::connection()->getPdo() ? 'ok' : 'error',
            'cache'    => Cache::store('default')->get('health-check') !== null ? 'ok' : 'error',
            'queue'    => Queue::size() < 1000 ? 'ok' : 'warning',
        ],
    ]);
});
```

### 12.2 Metrics Collection

| Metric | Type | Alert threshold |
| --- |--- | --- |
| Request latency (p50/p95/p99) | Histogram | p99 > 2s |
| Queue depth | Gauge | > 1000 pending jobs |
| Queue processing time | Histogram | avg > 5s |
| Database connection count | Gauge | > 80% pool |
| Error rate (5xx) | Counter | > 1% of requests |
| Memory usage | Gauge | > 80% of limit |
| Disk usage | Gauge | > 90% of capacity |

### 12.3 Alerting Rules

```text
Alert: High Error Rate
  Condition: 5xx rate > 1% for 5 minutes
  Action: Notify team (Slack/email)
  Severity: Critical

Alert: Slow Requests
  Condition: p99 latency > 5s for 10 minutes
  Action: Notify team
  Severity: Warning

Alert: Queue Backlog
  Condition: Pending jobs > 1000 for 5 minutes
  Action: Scale workers
  Severity: Warning

Alert: Disk Full
  Condition: Disk usage > 90%
  Action: Notify team + auto-cleanup logs
  Severity: Critical
```

## 14. Migration and Schema Management

### 14.1 Migration Rules

| Rule | Enforcement |
| --- | --- |
| One migration per table | Initial `create_{table}_table`, subsequent `add_{column}_to_{table}` |
| Reversible | Every `up()` has a matching `down()` |
| Domain-scoped | Migrations live in `database/migrations/{domain}/` |
| Timestamped | Standard Laravel timestamped filenames |
| No raw SQL | Use Schema Builder for portability |
| Foreign keys | Explicit `constrained()` with `onDelete` behavior |
| Indexes | Named explicitly: `idx_{table}_{column}` |

### 14.2 Seeder Strategy

### 19.3 Writing a New ADR

```markdown
# ADR-011: Switch from Meilisearch to Elasticsearch

## Status
Proposed

## Context
Our search requirements have grown. Meilisearch handles most use cases well,
but we need advanced analytics, faceted search, and aggregation queries that
Meilisearch does not support natively. The marketplace module needs complex
filtering (price ranges, category hierarchies, rating distributions).

## Decision
We will add Elasticsearch as an optional search engine backend alongside
Meilisearch. The SearchEngineInterface contract will support both. The default
installation will continue to use Meilisearch; Elasticsearch will be opt-in
via configuration.

## Consequences
- Pro: Advanced search capabilities for marketplace
- Pro: Backward compatible (Meilisearch remains default)
- Con: Two search engines to maintain
- Con: Elasticsearch requires more operational overhead
- Con: Migration tooling needed for index sync

## Alternatives Considered
1. Stick with Meilisearch only — rejected, lacks analytics
2. Replace Meilisearch entirely — rejected, Meilisearch is simpler for most modules
3. Use Algolia — rejected, vendor lock-in, cost
```

## 20. Refactoring Guidelines

### 20.1 When to Refactor

| Trigger | Priority | Action |
| --- | --- | --- |
| Service has > 15 methods | Medium | Split into focused services |
| Controller has > 5 methods | Medium | Extract to Actions |
| Repository has > 15 methods | Low | Extract query services |
| Module has > 100 files | High | Review module boundaries |
| Method has > 50 lines | High | Extract to helper or sub-method |
| Duplicate code in 2+ services | High | Extract to shared service or trait |
| Circular dependency detected | Critical | Break cycle with events or contracts |
| Test takes > 1s | Medium | Optimize or split test |

### 20.2 Refactoring Process

```text
Step 1: Write tests for current behavior (safety net)
    │
    ▼
Step 2: Identify the refactoring target
    │
    ├── Code smell (long method, god class, duplicate code)
    ├── Architecture violation (wrong layer, wrong module)
    └── Performance issue (N+1, missing index, slow query)
    │
    ▼
Step 3: Apply small, incremental changes
    │
    ├── Extract method
    ├── Extract class
    ├── Move to correct module
    ├── Introduce interface
    └── Add caching
    │
    ▼
Step 4: Run all tests after each change
    │
    ├── Tests pass → continue
    └── Tests fail → revert and try smaller step
    │
    ▼
Step 5: Update documentation
    │
    ├── Update PHPDoc
    ├── Update ADR if architectural change
    └── Update relevant Section 07 document
    │
    ▼
Step 6: Code review with architecture checklist
```

### 20.3 Refactoring Anti-Patterns

| Anti-pattern | Problem | Correct approach |
| --- | --- | --- |
| Big bang refactoring | Rewrite everything at once | Small, incremental changes |
| Refactor without tests | No safety net | Write tests first |
| Refactor + feature in same PR | Mixed concerns | Separate PRs |
| Refactor + rename in same PR | Hard to review | Separate PRs |
| Premature optimization | Optimize before measuring | Profile first |
| Copy-paste extraction | Duplicated logic extracted to shared function | Extract to domain service |

<?php

declare(strict_types=1);

namespace App\Domains\Components\Services;

use App\Domains\Components\Contracts\ComponentServiceContract;
use App\Domains\Components\DTOs\ComponentData;
use App\Domains\Components\Enums\ComponentStatus;
use App\Domains\Components\Events\{ComponentCreated, ComponentPublished, ComponentArchived};
use App\Domains\Components\Exceptions\{ComponentAlreadyExistsException, ComponentNotFoundException};
use App\Domains\Components\Models\Component;
use App\Domains\Components\Repositories\Contracts\ComponentRepositoryInterface;
use App\Shared\Support\AbstractService;
use Illuminate\Contracts\Pagination\LengthAwarePaginator;
use Illuminate\Database\Eloquent\Collection;

/**
 * Service for managing UI components.
 *
 * Handles CRUD operations, publishing, and versioning of components.
 * Components are the core building blocks of the GsmUi platform.
 *
 * @see ComponentServiceContract
 * @see ComponentRepositoryInterface
 */
final class ComponentService extends AbstractService implements ComponentServiceContract
{
    public function __construct(
        private readonly ComponentRepositoryInterface $components,
    ) {}

    /**
     * Create a new component.
     *
     * Validates the slug is unique, persists the component,
     * and dispatches a ComponentCreated event after commit.
     *
     * @param ComponentData $data Validated component data
     * @return Component The newly created component
     *
     * @throws ComponentAlreadyExistsException If slug is already taken
     */
    public function create(ComponentData $data): Component
    {
        if ($this->components->slugExists($data->slug)) {
            throw new ComponentAlreadyExistsException($data->slug);
        }

        return $this->transaction(function () use ($data): Component {
            $component = $this->components->create($data->toArray());

            $this->dispatchAfterCommit(new ComponentCreated(
                componentId: $component->id,
                userId: $data->authorId,
            ));

            return $component;
        });
    }

    /**
     * Find a component by its URL slug.
     *
     * @param string $slug The URL-friendly identifier
     * @return Component|null The component or null
     */
    public function findBySlug(string $slug): ?Component
    {
        return $this->components->findBySlug($slug);
    }

    /**
     * Publish a component.
     *
     * Transitions the component from draft to published status.
     *
     * @param Component $component The component to publish
     * @param int $userId The user publishing the component
     * @return Component The published component
     *
     * @throws ComponentNotFoundException If component not found
     */
    public function publish(Component $component, int $userId): Component
    {
        if ($component->status !== ComponentStatus::Draft) {
            throw new \App\Domains\Components\Exceptions\ComponentAlreadyPublishedException(
                $component->slug
            );
        }

        return $this->transaction(function () use ($component, $userId): Component {
            $published = $this->components->update($component, [
                'status' => ComponentStatus::Published,
                'published_at' => now(),
                'version' => $component->version + 1,
            ]);

            $this->dispatchAfterCommit(new ComponentPublished(
                componentId: $published->id,
                slug: $published->slug,
                userId: $userId,
                version: $published->version,
            ));

            return $published;
        });
    }

    /**
     * Paginate published components.
     *
     * @param int $perPage Results per page
     * @return LengthAwarePaginator Paginated results
     */
    public function paginatePublished(int $perPage = 15): LengthAwarePaginator
    {
        return $this->components->paginatePublished($perPage);
    }

    /**
     * Search components by query.
     *
     * @param string $query Search query
     * @return Collection Matching components
     */
    public function search(string $query): Collection
    {
        return $this->components->search($query);
    }

    /**
     * Update a component.
     *
     * @param Component $component The component to update
     * @param array $data The data to update
     * @return Component The updated component
     */
    public function update(Component $component, array $data): Component
    {
        return $this->components->update($component, $data);
    }

    /**
     * Delete a component.
     *
     * @param Component $component The component to delete
     * @return void
     */
    public function delete(Component $component): void
    {
        $this->components->delete($component);
    }

    /**
     * Archive a component.
     *
     * @param Component $component The component to archive
     * @param int $userId The user archiving the component
     * @return Component The archived component
     */
    public function archive(Component $component, int $userId): Component
    {
        return $this->transaction(function () use ($component, $userId): Component {
            $archived = $this->components->update($component, [
                'status' => ComponentStatus::Archived,
                'archived_at' => now(),
            ]);

            $this->dispatchAfterCommit(new ComponentArchived(
                componentId: $archived->id,
                userId: $userId,
            ));

            return $archived;
        });
    }
}

<?php

declare(strict_types=1);

namespace App\Domains\Components\DTOs;

/**
 * Immutable data transfer object for component creation.
 *
 * Validates input in the constructor and provides
 * a clean interface for passing data between layers.
 */
final readonly class ComponentData
{
    public function __construct(
        public string $name,
        public string $slug,
        public string $description,
        public int $authorId,
        public ?int $categoryId = null,
    ) {
        if (strlen($name) < 3 || strlen($name) > 255) {
            throw new \InvalidArgumentException('Name must be 3-255 characters');
        }

        if (! preg_match('/^[a-z0-9-]+$/', $slug)) {
            throw new \InvalidArgumentException('Slug must be lowercase alphanumeric with hyphens');
        }

        if (strlen($slug) < 3 || strlen($slug) > 100) {
            throw new \InvalidArgumentException('Slug must be 3-100 characters');
        }
    }

    /**
     * Create DTO from HTTP request.
     */
    public static function fromRequest(\Illuminate\Http\Request $request): self
    {
        return new self(
            name: $request->input('name'),
            slug: $request->input('slug'),
            description: $request->input('description', ''),
            authorId: $request->user()->id,
            categoryId: $request->input('category_id'),
        );
    }

    /**
     * Create DTO from array.
     */
    public static function fromArray(array $data): self
    {
        return new self(
            name: $data['name'],
            slug: $data['slug'],
            description: $data['description'] ?? '',
            authorId: $data['author_id'],
            categoryId: $data['category_id'] ?? null,
        );
    }

    /**
     * Convert to array for persistence.
     */
    public function toArray(): array
    {
        return [
            'name' => $this->name,
            'slug' => $this->slug,
            'description' => $this->description,
            'author_id' => $this->authorId,
            'category_id' => $this->categoryId,
            'status' => 'draft',
        ];
    }
