# 07.08 - Action Layer

**Project:** GsmUi
**Architecture:** Application Layer – Actions Pattern
**Framework:** Laravel 13 + Livewire 4
**Version:** 1.0.0

---

# Purpose

> See also: `05.09-actions.md` for the conceptual Actions architecture. This document specifies the **implementation contract** — the `Action` base class, the entry-point method convention (`run()`/`handle()`), transaction wrapping, event dispatch after commit, and the idempotency markers every GsmUi action must implement.

Actions are the single entry point for every write use case in GsmUi. Controllers, Livewire components, Artisan commands, queued jobs, and API endpoints all delegate to an `Action` rather than calling services or repositories directly. An Action coordinates one use case: it validates business preconditions through services, wraps the work in a database transaction, and dispatches domain events only after the transaction commits. This keeps the surrounding layers tiny and guarantees identical business behavior regardless of how the request entered the system.

Each Action is a final, single-responsibility class named for the verb it performs (`CreateComponentAction`, `PublishThemeAction`, `PurchaseTemplateAction`). It receives a strongly-typed DTO (see `07.09-dto-layer.md`) and returns a domain model, DTO, value object, or primitive — never an HTTP response or a Blade view.

# 2. Action Base Class

A shared `App\Actions\Action` base provides the transaction wrapper and idempotency helpers. Concrete actions extend it and implement `handle()`.

```php
namespace App\Actions;

use Closure;
use Illuminate\Support\Facades\DB;

abstract class Action
{
    /**
     * Execute the wrapped unit of work inside a database transaction.
     * Override to implement the use case.
     */
    abstract public function handle(mixed ...$args): mixed;

    /**
     * Public entry point. Alias for handle() that guarantees a transaction
     * boundary and after-commit event dispatch.
     */
    public function run(mixed ...$args): mixed
    {
        return DB::transaction(fn () => $this->handle(...$args));
    }

    /**
     * Dispatch an event only if the surrounding transaction commits.
     */
    protected function dispatchAfterCommit(object $event): void
    {
        DB::afterCommit(fn () => event($event));
    }

    /**
     * Guard against duplicate execution for idempotent actions.
     */
    protected function alreadyProcessed(string $key): bool
    {
        return \Cache::has("action:idempotency:{$key}");
    }

    protected function markProcessed(string $key, Closure $onFirst): mixed
    {
        if ($this->alreadyProcessed($key)) {
            return null;
        }
        $result = $onFirst();
        \Cache::forever("action:idempotency:{$key}", true);
        return $result;
    }
}
```

# 3. The `run()` / `handle()` Contract

- `run()` is the **public** entry point. It opens the transaction and returns whatever `handle()` produced. Callers (controllers, Livewire, jobs) always call `run()`.
- `handle()` contains the orchestration and must **not** open its own transaction — the base already did.
- `handle()` receives a typed DTO and returns a domain result.

```php
namespace App\Domains\Components\Actions;

use App\Actions\Action;
use App\Domains\Components\DTOs\ComponentData;
use App\Domains\Components\Events\ComponentCreated;
use App\Domains\Components\Repositories\Contracts\ComponentRepositoryInterface;
use App\Domains\Components\Services\ComponentService;
use App\Models\Component;

final class CreateComponentAction extends Action
{
    public function __construct(
        private ComponentService $service,
        private ComponentRepositoryInterface $components,
    ) {}

    public function handle(ComponentData $data): Component
    {
        $component = $this->components->create(
            $this->service->normalize($data)
        );

        $this->dispatchAfterCommit(new ComponentCreated(
            componentId: $component->id,
            userId: $data->userId,
        ));

        return $component;
    }
}
```

# 4. Transaction Boundaries

One transaction per use case. The base `run()` opens it; services and repositories run inside it. Keep transactions short and avoid network calls (external HTTP, queue push of non-event work) inside the transaction.

```text
Controller / Livewire
        │
        ▼
Action::run()  ── DB::transaction begins
        │
        ▼
handle() → Service → Repository → DB
        │
        ▼
dispatchAfterCommit(event)  ── fires only on commit
        │
        ▼
DB::transaction commits
```

---

# 5. Event Dispatch After Commit

Events are dispatched with `dispatchAfterCommit()` so listeners never observe rolled-back state (see `07.12-events.md` and `05.10-events.md` §"Transaction Rules"). The base helper encodes this pattern; do not call the global `event()` directly inside an action.

```php
$this->dispatchAfterCommit(new ComponentPublished(
    componentId: $component->id,
    userId: $data->userId,
    version: $component->latestVersion(),
));
```

# 6. Idempotency

Actions that may be retried — payment webhooks, license generation, search indexing — implement idempotency via a natural unique key plus the base `markProcessed()` helper. The cache key is scoped to the operation and the generating service.

```php
final class PurchaseTemplateAction extends Action
{
    public function handle(PurchaseTemplateData $data): Order
    {
        return $this->markProcessed(
            "purchase:{$data->userId}:{$data->productId}:{$data->idempotencyKey}",
            fn () => $this->executePurchase($data),
        ) ?? $this->orders->findByKey($data->idempotencyKey);
    }
}
```

| Mechanism            | Use for                          |
| -------------------- | -------------------------------- |
| Cache idempotency key | Webhook / retried queue jobs     |
| DB unique constraint | `payments.idempotency_key`, `webhook_deliveries.idempotency_key` (see `06.01-design-principles.md` §15) |
| Idempotency VO        | `IdempotencyKey` value object (see `07.10-value-objects.md`) |

# 7. Dependency Injection

Actions use constructor injection and are resolved by the container, so they can be invoked directly: `app(CreateComponentAction::class)->run($data)`. No manual service location.

---

# 8. Reuse Across Entry Points

The same action serves every entry point, guaranteeing consistent behavior.

```php
// Inside a Livewire component
$component = app(CreateComponentAction::class)->run($this->form->toData());

// Inside an API controller
$component = app(CreateComponentAction::class)->run(ComponentData::fromRequest($request));

// Inside an Artisan command
$component = app(CreateComponentAction::class)->run(ComponentData::fromArray($row));
```

# 9. Error Handling

Actions throw **domain exceptions** (not HTTP exceptions). Presentation layers translate them into responses (see `07.53-error-handling.md`). The transaction wraps the throw, so a domain exception automatically rolls back.

```text
ComponentAlreadyExistsException
SubscriptionRequiredException
LicenseExpiredException
ThemeAlreadyPublishedException
```

# 11. Action Lifecycle (Detailed)

### 11.1 Action Instantiation

Actions are resolved by the container. Each invocation creates a new instance (transient lifetime).

```text
Caller invokes action
    │
    ▼
Container resolves action
    ├── New instance created (transient)
    ├── Constructor dependencies injected
    │       ├── Service contracts (from DomainServiceProvider)
    │       ├── Repository contracts (from DomainServiceProvider)
    │       └── Other action contracts (if needed)
    └── Instance returned
    │
    ▼
Action::run($dto) called
    │
    ├── DB::transaction begins
    ├── handle($dto) executed
    │       ├── Service calls
    │       ├── Repository calls
    │       ├── Business logic
    │       └── dispatchAfterCommit(event)
    ├── Transaction commits (or rolls back on exception)
    └── Return result
```

### 11.2 Action Method Execution Flow

```text
Action::run($dto)
    │
    ▼
DB::transaction(fn () => $this->handle($dto))
    │
    ▼
handle($dto)
    │
    ├── Step 1: Validate preconditions
    │       ├── Check business rules
    │       ├── Check permissions
    │       └── Check resource existence
    │
    ├── Step 2: Execute business logic
    │       ├── Call service methods
    │       ├── Call repository methods
    │       └── Apply business rules
    │
    ├── Step 3: Persist changes
    │       ├── Repository create/update/delete
    │       └── Return persisted model
    │
    ├── Step 4: Dispatch events
    │       ├── dispatchAfterCommit(new SomeEvent(...))
    │       └── Event fires only after transaction commits
    │
    └── Step 5: Return result
            ├── Model (for CRUD actions)
            ├── DTO (for complex results)
            ├── ValueObject (for computed results)
            └── Primitive (for simple results)
```

# 12. Action Composition Patterns

### 12.1 Action Calling Another Action

```php
// Some actions compose other actions for complex workflows
final class PublishThemeAction extends Action
{
    public function __construct(
        private readonly ThemeService $themes,
        private readonly ValidateThemeForPublishAction $validate,
        private readonly IndexThemeAction $index,
    ) {}

    public function handle(Theme $theme, int $userId): Theme
    {
        // Delegate validation
        $this->validate->run($theme);

        // Publish the theme
        $published = $this->themes->publish($theme, $userId);

        // Index in search
        $this->index->run($published);

        return $published;
    }
}
```

### 12.2 Action with Multiple Services

```php
final class PurchaseTemplateAction extends Action
{
    public function __construct(
        private readonly MarketplaceService $marketplace,
        private readonly BillingService $billing,
        private readonly LicenseService $licenses,
        private readonly SearchIndexService $search,
    ) {}

    public function handle(PurchaseTemplateData $data): Order
    {
        // Step 1: Verify product exists
        $product = $this->marketplace->findProduct($data->productId);

        // Step 2: Process payment
        $payment = $this->billing->charge(
            amount: $product->price,
            customerId: $data->customerId,
        );

        // Step 3: Create order
        $order = $this->marketplace->createOrder([
            'user_id' => $data->userId,
            'product_id' => $data->productId,
            'payment_id' => $payment->id,
            'amount' => $product->price,
        ]);

        // Step 4: Generate license
        $license = $this->licenses->generate($order, $product);

        // Step 5: Update search index
        $this->search->reindexProduct($product);

        return $order;
    }
}
```

### 12.3 Action with Event Batching

```php
final class BulkPublishComponentsAction extends Action
{
    public function __construct(
        private readonly ComponentService $components,
    ) {}

    public function handle(array $componentIds, int $userId): array
    {
        $published = [];

        foreach ($componentIds as $id) {
            $component = $this->components->findById($id);

            if ($component && $component->status === ComponentStatus::Draft) {
                $published[] = $this->components->publish($component, $userId);
            }
        }

        // Batch all events for efficiency
        foreach ($published as $component) {
            $this->dispatchAfterCommit(new ComponentPublished(
                componentId: $component->id,
                userId: $userId,
            ));
        }

        return $published;
    }
}
```

# 13. Action Error Handling

### 13.1 Exception Handling Flow

```text
Action::run($dto)
    │
    ▼
handle($dto) throws exception
    │
    ├── DomainException (business rule violation)
    │       ├── Transaction rolls back automatically
    │       ├── No data persisted
    │       └── Exception bubbles to caller
    │
    ├── ModelNotFoundException (record not found)
    │       ├── Transaction rolls back automatically
    │       └── Exception bubbles to caller
    │
    ├── QueryException (database constraint violation)
    │       ├── Transaction rolls back automatically
    │       └── Exception bubbles to caller
    │
    └── Throwable (unexpected error)
            ├── Transaction rolls back automatically
            ├── Error logged with context
            └── Exception bubbles to caller
```

### 13.3 Error Recovery Pattern

```php
final class PurchaseTemplateAction extends Action
{
    public function handle(PurchaseTemplateData $data): Order
    {
        try {
            $order = $this->executePurchase($data);
        } catch (PaymentFailedException $e) {
            // Log the failure
            Log::warning('Payment failed', [
                'user_id' => $data->userId,
                'product_id' => $data->productId,
                'error' => $e->getMessage(),
            ]);

            // Re-throw as domain exception
            throw new OrderCreationException(
                'Payment processing failed. Please try again.',
                previous: $e,
            );
        }

        return $order;
    }
}
```

# 14. Action Authorization

### 14.1 Authorization in Actions

Actions can check authorization before executing business logic. This is separate from HTTP-level authorization (which happens in middleware/policies).

```php
final class DeleteComponentAction extends Action
{
    public function __construct(
        private readonly ComponentService $components,
        private readonly AuthorizationService $auth,
    ) {}

    public function handle(Component $component, int $userId): void
    {
        // Check authorization
        if (! $this->auth->can('delete', $component, $userId)) {
            throw new AuthorizationException('You are not authorized to delete this component');
        }

        // Check business precondition
        if ($component->hasActiveSubscribers()) {
            throw new ComponentHasActiveSubscribersException($component->slug);
        }

        // Execute
        $this->components->delete($component);
    }
}
```

### 14.2 Authorization Testing

```php
/** @test */
public function delete_throws_when_unauthorized(): void
{
    $component = Component::factory()->create(['author_id' => 1]);
    $otherUser = User::factory()->create();

    $this->expectException(AuthorizationException::class);

    app(DeleteComponentAction::class)->run($component, $otherUser->id);
}

/** @test */
public function delete_succeeds_when_authorized(): void
{
    $component = Component::factory()->create(['author_id' => 1]);

    app(DeleteComponentAction::class)->run($component, 1);

    $this->assertDatabaseMissing('components', ['id' => $component->id]);
}
```

# 15. Action Performance

### 15.1 Transaction Duration

| Guideline | Target | Enforcement |
| --- |---|---|
| Transaction duration | < 100ms | Monitor with query log |
| Queries per transaction | < 10 | Count queries in tests |
| Network calls in transaction | 0 | Code review |
| Lock duration | < 50ms | Database monitoring |

### 15.2 Action Optimization Patterns

```php
// Use lazy collections for bulk operations
final class BulkUpdateComponentsAction extends Action
{
    public function handle(array $updates): int
    {
        $count = 0;

        foreach ($updates as $id => $data) {
            $component = $this->components->find($id);

            if ($component) {
                $this->components->update($component, $data);
                $count++;
            }
        }

        return $count;
    }
}

// Use chunking for large datasets
final class ReindexAllComponentsAction extends Action
{
    public function handle(): int
    {
        $count = 0;

        Component::query()
            ->published()
            ->chunk(100, function ($components) use (&$count) {
                foreach ($components as $component) {
                    $this->search->indexComponent($component);
                    $count++;
                }
            });

        return $count;
    }
}
```

# 17. Action Testing Patterns

### 17.1 Unit Test

```php
namespace Tests\Unit\Domains\Components\Actions;

use App\Domains\Components\Actions\CreateComponentAction;
use App\Domains\Components\DTOs\ComponentData;

use Tests\TestCase;

class CreateComponentActionTest extends TestCase
{
    /** @test */
    public function create_component_returns_model(): void
    {
        // Arrange
        $data = ComponentData::fromArray([
            'name' => 'Button',
            'slug' => 'button',
            'description' => 'A clickable button component',
            'author_id' => 1,
        ]);

        // Act
        $component = app(CreateComponentAction::class)->run($data);

        $this->assertNotNull($component);
        $this->assertEquals('button', $component->slug);

    /** @test */
    public function create_component_dispatches_event_after_commit(): void

        Event::fake([ComponentCreated::class]);

            'name' => 'Button',

            'author_id' => 1,

        // Act
        $component = app(CreateComponentAction::class)->run($data);

        // Assert
        Event::assertDispatched(ComponentCreated::class, function ($event) use ($component) {
            return $event->componentId === $component->id;
        });

        // Arrange

            'author_id' => 1,
```

# 18. Action Anti-Patterns

| Anti-pattern | Symptom | Fix |
| --- |---|---|
| Action with business logic | Action validates data, checks rules | Move logic to service |
| Action calling repository directly | Action uses repository | Use service layer |
| Action opening its own transaction | Action calls DB::transaction | Use base run() pattern |
| Action rendering views | Action returns response/view | Return model/DTO, let caller render |
| Action with HTTP concerns | Action reads $request | Use DTO from FormRequest |
| Action with mutable state | Action holds state between calls | Make action stateless |
| Action with too many dependencies | Action constructor has > 5 params | Split into smaller actions |
| Action dispatching events before commit | Action calls event() directly | Use dispatchAfterCommit() |
| Action with cache logic | Action caches data | Move cache to service layer |
| Action with logging logic | Action logs extensively | Use service/event for logging |

# 21. Action Layer Summary

### 21.1 Action Responsibilities

| Responsibility | Description |
| --- | --- |
| Use-case orchestration | Coordinates service calls for a single use case |
| Transaction management | Wraps work in a database transaction |
| Event dispatch | Dispatches events after transaction commits |
| Authorization checks | Verifies user permissions |
| Precondition validation | Checks business rules before execution |
| Idempotency | Prevents duplicate execution for retried operations |
| Error handling | Throws domain exceptions, rolls back on failure |

### 21.2 Action Rules Summary

| Rule | Description |
| --- |---|
| One action per use case | Each action handles one business operation |
| Final class | Actions are final, not extendable |
| Constructor injection | All dependencies injected via constructor |
| DTO input | Actions receive typed DTOs |
| Model/DTO output | Actions return domain objects, not responses |
| No HTTP concerns | Actions don't read $request or return responses |
| No view rendering | Actions don't render HTML or Blade |
| No direct repository access | Actions use services, not repositories |
| Transaction via base | Use run() for transaction, not DB::transaction |
| Events via dispatchAfterCommit | Use base method, not event() directly |
| Stateless | Actions hold no mutable state between calls |
| Testable | Actions are easily unit and feature tested |

### 22.2 Action Dependency Graph

```text
CreateComponentAction
```

### 22.3 Action Transaction Pattern

### 22.5 Action Idempotency Pattern

```php
// Idempotent action for webhook processing
final class ProcessWebhookAction extends Action
{
    public function __construct(
        private readonly WebhookService $webhooks,
        private readonly OrderService $orders,
    ) {}

    public function handle(WebhookPayload $payload): void
    {
        $key = "webhook:{$payload->provider}:{$payload->id}";

        $this->markProcessed($key, function () use ($payload): void {
            match ($payload->event) {
                'payment.succeeded' => $this->handlePaymentSuccess($payload),
                'payment.failed' => $this->handlePaymentFailed($payload),
                default => null, // Ignore unknown events
            };
        });
    }

    private function handlePaymentSuccess(WebhookPayload $payload): void
    {
        $order = $this->orders->findByPaymentId($payload->data['payment_id']);

        if ($order && $order->status !== OrderStatus::Completed) {
            $this->orders->complete($order);
        }
    }
}
```

### 31.3 Circuit Breaker Pattern

```php
final class ExternalServiceAction extends Action
{
    private int $failureCount = 0;
    private int $threshold = 5;
    private \Carbon\Carbon $lastFailure;

    public function handle(mixed $input): mixed
    {
        if ($this->isCircuitOpen()) {
            throw new CircuitOpenException(
                'External service unavailable. Try again later.'
            );
        }

        try {
            $result = $this->callExternalService($input);
            $this->failureCount = 0;
            return $result;
        } catch (\Exception $e) {
            $this->failureCount++;
            $this->lastFailure = now();

            if ($this->failureCount >= $this->threshold) {
                Log::critical('Circuit breaker opened', [
                    'failures' => $this->failureCount,
                    'service' => get_class($this),
                ]);
            }

            throw $e;
        }
    }

    private function isCircuitOpen(): bool
    {
        if ($this->failureCount < $this->threshold) {
            return false;
        }

        // Half-open: try again after 30 seconds
        return $this->lastFailure->diffInSeconds(now()) < 30;
    }
}
```

```php
    public function handle(array $componentIds, int $version): array
    {
        $results = [];

        foreach ($componentIds as $id) {
            $component = $this->repository->find($id);

            if ($component && $component->canPublish()) {
                $this->publish->handle($component, $version);
                $results[$id] = 'success';
            } else {
                $results[$id] = 'skipped';
            }
        }

        return $results;
    }
}
```

### 35.3 Action Timeout

```php
abstract class Action
{
    protected function withTimeout(int $seconds, callable $callback): mixed
    {
        $start = microtime(true);

        return Timer::timeout($seconds, function () use ($callback, $start) {
            $result = $callback();
            $elapsed = microtime(true) - $start;

            if ($elapsed > $seconds * 0.8) {
                Log::warning('Action nearing timeout', [
                    'action' => static::class,
                    'elapsed_ms' => round($elapsed * 1000),
                    'timeout_ms' => $seconds * 1000,
                ]);
            }

            return $result;
        });
    }
}
```
