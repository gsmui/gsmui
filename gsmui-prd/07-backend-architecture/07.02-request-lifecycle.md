# 07.02 - Request Lifecycle

**Project:** GsmUi
**Architecture:** Modular Monolith / HTTP + Livewire Request Pipeline
**Framework:** Laravel 13 + Livewire 4
**Version:** 1.0.0

---

> See also: `05.01-overview.md` (high-level request flow). There is no `05.02` file in the current repo; the conceptual lifecycle is defined in the 05.01 "Request Lifecycle" and "Data Flow" sections. This document specifies the *implementation contract* for each stage of the pipeline.

# Purpose

This document defines the concrete, code-level path a request takes through the GsmUi backend, for both classic HTTP routes and Livewire updates. It identifies the exact middleware, service-provider, and handler touchpoints so implementers wire new routes, components, and global behaviors consistently. It also enumerates every exception-handling point so error behavior is uniform across the platform.

The lifecycle is the backbone that the per-layer contracts in `07.06-service-layer.md`, `07.07-repository-layer.md`, and `07.53-error-handling.md` plug into. A new endpoint is correct only when it passes through the documented stages in order.

---

## 1. HTTP Request Flow

A standard page load or API call follows this pipeline. Stages in **bold** are framework/contract points; the rest are application code.

```text
Browser
   │
   ▼
public/index.php
   │
   ▼
Bootstrap / Application (bootstrap/app.php)
   │
   ▼
HTTP Kernel → Global Middleware (trust proxies, encrypt cookies,
   │           CSRF, locale, session start)
   ▼
Route Resolution (routes/web.php, routes/api.php,
   │             routes/domains/*.php via DomainServiceProvider)
   ▼
Route Middleware (auth, can, throttle, signed, verified)
   │
   ▼
Controller / Form Request (authorize + rules)
   │
   ▼
Action (use case: precondition check + transaction + dispatch)
   │
   ▼
Service (business rule) ──▶ Repository ──▶ Model ──▶ Database
   │                                                  │
   ▼                                                  │
Domain Event ──▶ Listener ──▶ Queue Job              │
   │                                                  │
   ▼                                                  │
Response (View / JSON Resource / Redirect) ◀─────────┘
```

### Contract points

| Stage | File / Class | Responsibility |
| --- | --- | --- |
| Bootstrap | `bootstrap/app.php` | Build `Illuminate\Foundation\Application`, register base bindings |
| HTTP Kernel | `app/Core/Kernel/HttpKernel.php` (or default `Illuminate\Foundation\Http\Kernel`) | Global middleware stack |
| Route loading | `app/Providers/RouteServiceProvider.php`, `DomainServiceProvider` | Load `routes/domains/*.php` |
| Controller | `app/Domains/<Domain>/Http/Controllers/*` | Thin; delegates to Action |
| Form Request | `app/Domains/<Domain>/Http/Requests/*` | `authorize()`, `rules()` |
| Action | `app/Domains/<Domain>/Actions/*` | Transaction + event dispatch |
| Service | `app/Domains/<Domain>/Services/*` | Business logic |
| Repository | `app/Domains/<Domain>/Repositories/*` | Persistence only |

## 2. Livewire Request Flow

Livewire updates bypass controller routing but still traverse the same application layers. The HTTP kernel stages (middleware, session, CSRF) run first.

```text
Browser (wire:model / action)
   │
   ▼
POST /livewire/update  (Livewire 4 endpoint)
   │
   ▼
Livewire 4 Middleware + Session + CSRF
   │
   ▼
Livewire Component (state hydration / property sync)
   │
   ▼
Component Action Method  →  Action / Service  →  Repository  →  Model
   │
   ▼
Domain Event ──▶ Queue Job (async side effects)
   │
   ▼
Response: re-rendered HTML fragment (or streamed)
```

Rules:

- Livewire components MUST NOT touch the database directly; they call an `Action` or `Service` (see `05.06-folder-structure.md` dependency rules).
- `Wireable` DTOs (see `07.09-dto-layer.md`) are the only state carriers crossing the hydration boundary.
- Disallowed methods (`$disableRateLimit`/`$lockOutgoing` excluded) are controlled per component; see `07.19-livewire-architecture.md`.

## 3. Exception-Handling Points

Every failure is converted to a uniform response at one of these touchpoints. The hierarchy is defined in `07.53-error-handling.md`; the handler lives in `app/Core/Exceptions/Handler.php`.

```text
Throw site (Service / Action / Repository)
   │
   ▼
app/Core/Exceptions/Handler.php  → render()
   │
   ├── DomainException  → 4xx JSON / 4xx view + Activity Log
   ├── ValidationException (FormRequest) → 422 + errors
   ├── AuthorizationException / Gate/Policy → 403
   ├── AuthenticationException → 401 / redirect login
   ├── HttpException (abort) → mapped status
   └── Throwable (unexpected) → 500 + report() to logs
```

Points:

1. **Service/Action throw** — domain exceptions carry a user-safe message.
2. **Form Request** — `Illuminate\Validation\ValidationException` auto-rendered as 422.
3. **Policy/Gate** — `Illuminate\Auth\Access\AuthorizationException` → 403.
4. **Handler `report()`** — every non-`ValidationException` is logged with correlation ID (`07.54-logging.md`).
5. **Handler `render()`** — maps to Problem+JSON for API, or a Blade error view for web.

## 4. Console / Scheduled Flow

Artisan commands and scheduled tasks enter through the Console Kernel and MUST reuse the same Action/Service layer — never duplicate logic inline.

```text
schedule/call → Command → Action → Service → Repository → Model
                                      │
                                      ▼
                                  Domain Event → Queue Job
```

## 5. Middleware Pipeline (Detailed)

The middleware pipeline executes in a precise order. Each middleware wraps the next, forming a Russian-doll structure.

### 5.1 Global Middleware Stack

```text
Request enters HTTP Kernel
    │
    ▼
┌──────────────────────────────────────────────────────┐
│ TrustProxies                                       │ 1. Resolves true client IP behind load balancers
├──────────────────────────────────────────────────────┤
│ HandleCors                                         │ 2. CORS headers for API requests
├──────────────────────────────────────────────────────┤
│ PreventRequestsDuringMaintenance                   │ 3. Returns 503 when app is in maintenance mode
├──────────────────────────────────────────────────────┤
│ ValidatePostSize                                   │ 4. Rejects requests exceeding max POST size
├──────────────────────────────────────────────────────┤
│ TrimStrings                                        │ 5. Strips whitespace from request inputs
├──────────────────────────────────────────────────────┤
│ ConvertEmptyStringsToNull                          │ 6. Converts "" to null in request data
├──────────────────────────────────────────────────────┤
│ ShareErrorsFromSession                             │ 7. Shares validation errors with views
├──────────────────────────────────────────────────────┤
│ StartSession                                       │ 8. Starts/renews session, sets session cookie
├──────────────────────────────────────────────────────┤
│ VerifyCsrfToken                                    │ 9. Validates CSRF token for state-changing requests
├──────────────────────────────────────────────────────┤
│ SubstituteBindings                                 │ 10. Injects route model bindings into controller params
├──────────────────────────────────────────────────────┤
│ DispatchRequestsToController                       │ 11. Routes the request to the matched controller
└──────────────────────────────────────────────────────┘
```

### 5.2 Route Middleware Groups

| Middleware | Applied to | Behavior |
| --- | --- | --- |
| `auth` | Protected web routes | Requires authenticated session; redirects to login |
| `auth:sanctum` | Protected API routes | Requires valid API token |
| `verified` | Email-verified routes | Requires `email_verified_at` to be set |
| `can:{ability}` | Gate-restricted routes | Checks authorization via Policy/Gate |
| `throttle:{rate}` | API + login routes | Rate limiting (requests per minute) |
| `signed` | Temporary URLs | Validates URL signature (expiration-based) |
| `cache.headers:{directive}` | Response caching routes | Sets cache-control headers |

### 5.3 Custom Middleware

```php
namespace App\Core\Middleware;

use Closure;
use Illuminate\Http\Request;

final class SetLocaleMiddleware
{
    public function handle(Request $request, Closure $next)
    {
        $locale = $request->user()?->preferred_locale
            ?? config('app.locale');

        app()->setLocale($locale);

        return $next($request);
    }
}
```

```php
namespace App\Core\Middleware;

use Closure;
use Illuminate\Http\Request;
use Illuminate\Support\Facades\Log;

final class CorrelationIdMiddleware
{
    public function handle(Request $request, Closure $next)
    {
        $correlationId = $request->header('X-Correlation-ID', (string) Str::uuid());

        // Store in request for downstream use
        $request->attributes->set('correlation_id', $correlationId);

        // Log with correlation context
        Log::withContext(['correlation_id' => $correlationId]);

        $response = $next($request);

        // Add to response headers
        $response->headers->set('X-Correlation-ID', $correlationId);

        return $response;
    }
}
```

## 6. Controller Lifecycle (Detailed)

### 6.1 Controller Execution Flow

```text
HTTP Kernel dispatches request
    │
    ▼
Route matched → Controller resolved
    │
    ▼
Form Request authorize() called
    ├── Returns false → 403 Forbidden
    └── Returns true → continues
    │
    ▼
Form Request validate() called
    ├── Validation fails → 422 with errors bag
    └── Validation passes → continues
    │
    ▼
Controller method invoked
    │
    ├── Calls Action::run($dto)
    │       ├── Transaction begins
    │       ├── Service → Repository → DB
    │       ├── Event dispatch after commit
    │       └── Returns domain result
    │
    ├── Wraps result in Response
    │       ├── View response (web)
    │       ├── Json/Resource response (API)
    │       └── Redirect response (form submit)
    │
    └── Response passes through middleware (outbound)
            ├── Add security headers
            ├── Add CORS headers
            └── Set cache headers
```

### 6.2 Controller Skeleton

```php
namespace App\Domains\Components\Http\Controllers;

use App\Domains\Components\Actions\CreateComponentAction;
use App\Domains\Components\Http\Requests\CreateComponentRequest;
use App\Domains\Components\DTOs\ComponentData;
use App\Domains\Components\Resources\ComponentResource;
use Illuminate\Http\JsonResponse;
use Illuminate\Http\Response;

final class ComponentController extends Controller
{
    public function __construct(
        private CreateComponentAction $createComponent,
    ) {}

    public function store(CreateComponentRequest $request): JsonResponse
    {
        $component = $this->createComponent->run(
            ComponentData::fromRequest($request)
        );

        return (new ComponentResource($component))
            ->response()
            ->setStatusCode(Response::HTTP_CREATED);
    }
}
```

### 6.3 Form Request Lifecycle

```text
Form Request instantiated by Laravel
    │
    ▼
authorize() called
    │
    ├── true  → continue to validation
    ├── false → AuthorizationException → 403
    └── null  → no authorization needed (default)
    │
    ▼
rules() called → validator built
    │
    ├── passes  → request continues to controller
    └── fails   → ValidationException → 422 + error bag
```

## 7. Livewire Lifecycle (Detailed)

### 7.1 Livewire Component Initialization

```text
Initial Page Load:
    │
    ▼
Blade template renders <livewire:component-name />
    │
    ▼
Livewire bootstraps component
    ├── Resolves component class from container
    ├── Hydrates initial state (from HTML attributes / session)
    ├── Calls mount() (first visit only)
    └── Renders Blade template to HTML
    │
    ▼
HTML sent to browser with Livewire JavaScript
    │
    ▼
Livewire JS initializes
    ├── Scans DOM for Livewire components
    ├── Stores component state (snapshot)
    ├── Attaches event listeners (wire:click, wire:model, etc.)
    └── Ready for interaction
```

### 7.2 Livewire Update Request

```text
User interacts (click, type, submit)
    │
    ▼
Livewire JS sends POST /livewire/update
    │
    ├── Snapshot (serialized component state)
    ├── Updates (changed properties)
    ├── Events (server events to dispatch)
    └── CSRF token
    │
    ▼
Livewire Middleware (CSRF, session, auth)
    │
    ▼
Livewire Server
    ├── Deserializes snapshot → component instance
    ├── Applies property updates (wire:model bindings)
    ├── Calls action method (wire:click="save")
    │       ├── Action::run() (if following pattern)
    │       │       ├── Service → Repository → DB
    │       │       └── Event dispatch
    │       └── Or direct service call (simpler components)
    ├── Collects any emit() calls
    ├── Re-renders component Blade
    └── Returns new HTML fragment + new snapshot
    │
    ▼
Livewire JS
    ├── Diffs old HTML vs new HTML (morph)
    ├── Applies minimal DOM updates
    ├── Updates component snapshot
    └── Emits any server events to child components
```

### 7.3 Livewire Property Binding Types

| Binding | Directive | HTTP behavior | Use case |
| --- | --- | --- | --- |
| Two-way | `wire:model="name"` | Sends on every keystroke (debounced) | Text inputs |
| Two-way (lazy) | `wire:model.lazy="name"` | Sends on blur/change | Selects, textareas |
| Two-way (debounced) | `wire:model.debounce.500ms="name"` | Sends after 500ms pause | Search inputs |
| Action | `wire:click="method"` | Sends action on click | Buttons |
| Action (key) | `wire:keydown.enter="submit"` | Sends on key event | Form submissions |
| Polling | `wire:poll.5s="refresh"` | Periodic update requests | Live data |
| Loading | `wire:loading` | Shows element during request | Loading states |
| Disable | `wire:loading.attr="disabled"` | Disables during request | Prevent double-click |

### 7.4 Livewire Event System

```text
Component A
    │
    ├── emit('eventName', $data)
    │       │
    │       ├── Same component → handled by onEventName()
    │       ├── Parent component → handled by onEventName()
    │       └── Named component → handled by specific component
    │
    ├── emitUp('eventName', $data)
    │       └── Only to parent components
    │
    ├── emitTo('component-name', 'eventName', $data)
    │       └── Only to specific named component
    │
    └── broadcast('eventName', $data)
            └── To all browser tabs (via WebSocket)
```

## 8. Queue Job Lifecycle

### 8.1 Job Dispatch Flow

```text
Action::dispatchAfterCommit(new SomeEvent())
    │
    ▼
Event::dispatch(new SomeEvent())
    │
    ▼
Listener handles event
    │
    ├── Synchronous: processes immediately
    └── Queued: dispatches job
            │
            ▼
        Job serialized and pushed to queue
            │
            ▼
        Queue Worker picks up job
            ├── Deserializes job
            ├── Resolves dependencies from container
            ├── Calls handle()
            │       ├── Service → Repository → DB
            │       └── May dispatch more events
            ├── On success: job marked as completed
            └── On failure: retry logic applied
                    ├── Attempts < maxTries → re-queue
                    └── Attempts >= maxTries → failed()
                        └── Moved to failed_jobs table
```

### 8.2 Job Configuration

```php
namespace App\Domains\Components\Jobs;

use App\Domains\Components\Models\Component;
use App\Domains\Search\Services\SearchIndexService;
use Illuminate\Bus\Queueable;
use Illuminate\Contracts\Queue\ShouldQueue;
use Illuminate\Foundation\Bus\Dispatchable;
use Illuminate\Queue\{InteractsWithQueue, SerializesModels};

final class IndexComponentJob implements ShouldQueue
{
    use Dispatchable, InteractsWithQueue, Queueable, SerializesModels;

    public int $tries = 3;
    public int $timeout = 30;
    public int $backoff = 60;
    public string $queue = 'search';

    public function __construct(
        public Component $component,
    ) {}

    public function handle(SearchIndexService $search): void
    {
        $search->index($this->component);
    }

    public function failed(\Throwable $exception): void
    {
        \Log::error('Component indexing failed', [
            'component_id' => $this->component->id,
            'error' => $exception->getMessage(),
        ]);
    }
}
```

## 9. API Request Lifecycle

### 9.1 API-Specific Pipeline

```text
API Request
    │
    ▼
Route: api.php (or routes/domains/*.php api group)
    │
    ▼
API Middleware Group
    ├── throttle:api (rate limiting)
    ├── auth:sanctum (token authentication)
    └── EnsureFrontendRequestsAreStateful (if SPA)
    │
    ▼
Controller / ActionRequest
    │
    ├── Validates input (FormRequest or inline rules)
    ├── Calls Action::run()
    └── Returns JsonResource response
    │
    ▼
Response
    ├── Content-Type: application/json
    ├── X-Correlation-ID header
    └── Cache-Control headers (if applicable)
```

### 9.2 API Response Format

```json
// Success (single resource)
{
    "data": {
        "id": 1,
        "type": "component",
        "attributes": {
            "name": "Button",
            "slug": "button",
            "status": "published"
        },
        "relationships": {
            "author": {
                "data": { "id": 1, "type": "user" }
            }
        }
    }
}

// Success (collection)
{
    "data": [
        { "id": 1, "type": "component", "attributes": { ... } },
        { "id": 2, "type": "component", "attributes": { ... } }
    ],
    "meta": {
        "current_page": 1,

        "self": "/api/components?page=1",
```

## 10. Cache Lifecycle

### 10.1 Cache Strategy by Data Type

| Data type | Cache driver | TTL | Invalidation trigger |
| --- | --- | --- | --- |
| User session | Redis | Until logout | Session destroy |
| Auth tokens | Redis | Until revoked | Token delete |
| View fragments | File | Until clear | `view:clear` |
| Route definitions | File | Until clear | `route:clear` |
| Config values | File | Until clear | `config:clear` |
| Domain data | Redis | 5-30 min | Domain event |
| Search index | Meilisearch | Real-time | Model observer |
| Activity log | Database | Indefinite | Retention policy |

### 10.2 Cache Invalidation Pattern

```php
// In Service — invalidate on mutation
public function update(Component $component, array $data): Component
{
    $updated = $this->components->update($component, $data);

    // Invalidate related caches
    Cache::forget("component:{$updated->slug}");
    Cache::forget("components:published");
    Cache::forget("components:featured");

    return $updated;
}
```

## 11. Session Lifecycle

### 11.1 Session Flow

```text
Request with session cookie
    │
    ▼
StartSession middleware
    ├── Loads session from store (Redis/DB/file)
    ├── Refreshes expiration (if sliding window)
    └── Attaches session to Request object
    │
    ▼
Controller/Action reads/writes session
    ├── session('key')  → read
    ├── session(['key' => $value]) → write
    └── session()->forget('key') → delete
    │
    ▼
Response sent
    │
    ▼
StartSession middleware
    ├── Saves session to store
    └── Sends session cookie in response
```

### 11.2 Session Configuration

| Setting | Value | Purpose |
| --- | --- | --- |
| Driver | `redis` | Fast, persistent, shared across workers |
| Lifetime | 120 minutes | Session expires after 2 hours of inactivity |
| Chunking | Enabled | Splits large session data for storage limits |
| Encryption | Enabled | Session data encrypted at rest |
| Lot sharing | `partition` | Redis key partitioning for performance |

## 12. Error Lifecycle (Detailed)

### 12.1 Exception Propagation Path

```text
Exception thrown in Service/Action/Repository
    │
    ▼
PHP unwinds the call stack
    │
    ▼
Handler::report($exception)
    ├── Determines log level
    ├── Adds context (correlation_id, user_id, module)
    ├── Sends to log channel (stack, daily, slack, etc.)
    └── Reports to external service (Sentry/Flare) if configured
    │
    ▼
Handler::render($request, $exception)
    │
    ├── Determines response format (JSON vs HTML vs Livewire)
    ├── Maps exception to status code
    ├── Generates response body
    │       ├── API: Problem+JSON
    │       ├── Web: Blade error view
    │       └── Livewire: Component error state
    └── Returns Response object
```

### 12.2 Exception-to-Status-Code Mapping

| Exception class | HTTP status | API response | Web response |
| --- | --- | --- |--- |
| `ModelNotFoundException` | 404 | Problem JSON | 404 Blade view |
| `AuthorizationException` | 403 | Problem JSON | 403 Blade view |
| `AuthenticationException` | 401 | Problem JSON | Redirect to login |
| `ValidationException` | 422 | Problem JSON + errors | Redirect with errors |
| `DomainException` | 409 | Problem JSON | Redirect with flash |
| `NotFoundHttpException` | 404 | Problem JSON | 404 Blade view |
| `MethodNotAllowedHttpException` | 405 | Problem JSON | 405 Blade view |
| `TooManyRequestsHttpException` | 429 | Problem JSON | 429 Blade view |
| `TooManyAttemptsException` | 429 | Problem JSON | 429 Blade view |
| Generic `\Throwable` | 500 | Problem JSON | 500 Blade view |

### 12.3 Livewire Error Handling

```text
Livewire component throws exception
    │
    ▼
Livewire catches internally
    ├── If in action method → catches and stores in component state
    ├── If in mount/render → catches and shows error in place
    └── If unrecoverable → returns error response to JS
    │
    ▼
Livewire JS
    ├── Displays error UI (if render mode)
    ├── Fires event (if action mode)
    └── Logs to console (development only)
```

## 13. Rate Limiting Lifecycle

### 13.1 Rate Limit Configuration

```php
// In RouteServiceProvider or Route::configureRateLimiting()
RateLimiter::for('api', function (Request $request) {
    return Limit::perMinute(60)->by(
        $request->user()?->id ?: $request->ip()
    );
});

RateLimiter::for('login', function (Request $request) {
    return Limit::perMinute(5)->by($request->input('email'));
});

RateLimiter::for('webhook', function (Request $request) {
    return Limit::perMinute(100)->by($request->ip());
});
```

### 13.2 Rate Limit Flow

```text
Request enters throttled route
    │
    ▼
ThrottleRequests middleware
    ├── Extracts rate limit key (user ID or IP)
    ├── Checks Redis for existing count
    │       ├── count < limit → allow, increment
    │       ├── count >= limit → deny (429)
    │       └── no count → create, set TTL, allow
    ├── Sets X-RateLimit-Remaining header
    ├── Sets X-RateLimit-Reset header
    └── On 429: sets Retry-After header
```

## 14. Queue Worker Lifecycle

### 14.1 Worker Process Flow

```text
php artisan queue:work
    │
    ├── Daemon mode (default): stays in memory, processes jobs sequentially
    ├── Once mode: processes one job, then exits
    └── Supervisor manages restart on failure
    │
    ▼
Worker polls queue connection (Redis/SQS/Database)
    │
    ├── No job available → waits (sleep) → polls again
    └── Job available → dequeues job
            │
            ├── Checks if job should be deleted (e.g., model missing)
            ├── Resolves dependencies from container
            ├── Calls job::handle()
            │       ├── Success → marks as completed
            │       └── Failure → attempts++ → retry or fail
            │
            ├── Max attempts reached → job::failed() + moves to failed_jobs
            ├── Memory limit exceeded → worker restarts
            └── Time limit exceeded → worker restarts
```

### 14.2 Queue Configuration Matrix

| Queue name | Connection | Priority | Use cases | Worker config |
| --- | --- | --- | --- | --- |
| `default` | Redis | Normal | General async work | `--queue=default` |
| `high` | Redis | High | Time-critical operations | `--queue=high,default` |
| `search` | Redis | Low | Search indexing | `--queue=search` |
| `mail` | Redis | Low | Email dispatch | `--queue=mail` |
| `broadcast` | Redis | Normal | WebSocket broadcasts | `--queue=broadcast` |

### 14.3 Worker Scaling

```text
Current queue depths:
    high:     3 jobs
    default:  12 jobs
    search:   847 jobs
    mail:     23 jobs

Scaling decisions:
    high:     1 worker (low volume, high priority)
    default:  2 workers (moderate volume)
    search:   4 workers (high volume, can be delayed)
    mail:     2 workers (moderate volume)
```

## 15. Database Connection Lifecycle

### 15.1 Connection Pool

```text
Request arrives
    │
    ▼
Database connection required
    ├── Pool has available connection → use it
    └── Pool exhausted → wait (max 30s) or throw ConnectionException
    │
    ▼
Query executed
    │
    ▼
Connection returned to pool (not closed)
    │
    ▼
Request complete
    └── Connection stays in pool for next request
```

### 15.2 Transaction Lifecycle

```text
DB::transaction(function () {
    │
    ├── BEGIN issued to database
    │
    ├── Query 1: INSERT INTO components ...
    ├── Query 2: UPDATE theme_tokens SET ...
    ├── Query 3: INSERT INTO activity_log ...
    │
    ├── All queries succeed
    │       └── COMMIT issued → data persisted
    │
    └── Any query fails
            └── ROLLBACK issued → all changes discarded
                └── TransactionException thrown
```

## 21. Performance Considerations

### 21.1 Request Timing Budget

```text
Total request budget: 500ms (p95 target)
    │
    ├── Middleware: 10ms (5ms global + 5ms route)
    ├── Database queries: 100ms (target: <10ms per query)
    ├── Service/Action processing: 150ms
    ├── View rendering: 100ms
    ├── Response serialization: 20ms
    └── Network overhead: 120ms (varies)
```

### 21.2 Common Performance Bottlenecks

| Bottleneck | Symptom | Solution |
| --- | --- | --- |
| N+1 queries | Slow list pages, high query count | Eager load in repository |
| Missing indexes | Slow WHERE queries | Add migration index |
| Unoptimized eager loads | Loading unnecessary relations | Trim `with()` array |
| Synchronous external calls | 2-5s response times | Move to queued job |
| Large response payloads | Slow serialization, high memory | Paginate, use minimal data |
| Session contention | High Redis latency | Use session locking sparingly |
| Cache stampede | Multiple workers regenerating cache | Use `Cache::lock()` |

### 21.3 Performance Monitoring Commands

### 29.3 Exception Handler Configuration

```php
// app/Core/Exceptions/Handler.php
namespace App\Core\Exceptions;

use App\Shared\Exceptions\DomainException;
use Illuminate\Foundation\Exceptions\Handler as ExceptionHandler;
use Illuminate\Auth\AuthenticationException;
use Illuminate\Auth\Access\AuthorizationException;
use Illuminate\Validation\ValidationException;
use Symfony\Component\HttpKernel\Exception\HttpException;
use Throwable;

class Handler extends ExceptionHandler
{
    protected $dontFlash = [
        'current_password',
        'password',
        'password_confirmation',
    ];

    public function register(): void
    {
        $this->reportable(function (Throwable $e) {
            // Log with correlation ID
            if ($correlationId = request()->attributes->get('correlation_id')) {
                \Log::withContext(['correlation_id' => $correlationId]);
            }
        });
    }

    public function render($request, Throwable $e)
    {
        if ($request->expectsJson()) {
            return $this->handleApiException($request, $e);
        }

        return parent::render($request, $e);
    }

    private function handleApiException($request, Throwable $e)
    {
        if ($e instanceof ValidationException) {
            return response()->json([
                'type' => 'https://gsmui.dev/errors/validation',
                'title' => 'Validation Failed',
                'status' => 422,
                'errors' => $e->errors(),
            ], 422);
        }

        if ($e instanceof DomainException) {
            return response()->json([
                'type' => 'https://gsmui.dev/errors/domain',
                'title' => get_class($e),
                'status' => $e->getCode() ?: 400,
                'detail' => $e->getMessage(),
            ], $e->getCode() ?: 400);
        }

        if ($e instanceof AuthenticationException) {
            return response()->json([
                'type' => 'https://gsmui.dev/errors/auth',
                'title' => 'Unauthenticated',
                'status' => 401,
            ], 401);
        }

        if ($e instanceof AuthorizationException) {
            return response()->json([
                'type' => 'https://gsmui.dev/errors/authorization',
                'title' => 'Forbidden',
                'status' => 403,
            ], 403);
        }

        if ($e instanceof HttpException) {
            return response()->json([
                'type' => 'https://gsmui.dev/errors/http',
                'title' => $e->getMessage(),
                'status' => $e->getStatusCode(),
            ], $e->getStatusCode());
        }

        // Unexpected error
        \Log::error('Unexpected error', [
            'exception' => $e->getMessage(),
            'trace' => $e->getTraceAsString(),
        ]);

        return response()->json([
            'type' => 'https://gsmui.dev/errors/server',
            'title' => 'Internal Server Error',
            'status' => 500,
        ], 500);
    }

    protected function unauthenticated($request, AuthenticationException $e)
    {
        if ($request->expectsJson()) {
            return response()->json(['message' => 'Unauthenticated.'], 401);
        }

        return redirect('/');
    }
}
```

```php
use Illuminate\Http\Request;
use Illuminate\Cache\RateLimiting\Limit;
use Illuminate\Support\Facades\RateLimiter;

class RouteServiceProvider extends ServiceProvider
{
    public const HOME = '/dashboard';

    public function boot(): void
    {
        $this->configureRateLimiting();

        $this->routes(function () {
            Route::middleware('web')
                ->group(base_path('routes/web.php'));

            Route::prefix('api')
                ->middleware('api')
                ->group(base_path('routes/api.php'));

            Route::middleware('web')
                ->group(base_path('routes/console.php'));
        });
    }

    private function configureRateLimiting(): void
    {
        RateLimiter::for('api', function (Request $request) {
            return Limit::perMinute(60)->by(
                $request->user()?->id ?: $request->ip()
            );
        });

        RateLimiter::for('login', function (Request $request) {
            return Limit::perMinute(5)->by($request->input('email'));
        });

        RateLimiter::for('webhook', function (Request $request) {
            return Limit::perMinute(100)->by($request->ip());
        });
    }
```

### 29.8 Common Request Flow Errors

| Error | Stage | Cause | Fix |
| --- |---|---|---|
| 419 Page Expired | CSRF middleware | Invalid CSRF token | Refresh page, resubmit |
| 422 Validation Error | FormRequest | Invalid input | Check request data |
| 403 Forbidden | Policy/Gate | Unauthorized | Check permissions |
| 404 Not Found | Route resolution | Route doesn't exist | Check route definition |
| 405 Method Not Allowed | Route resolution | Wrong HTTP method | Check route method |
| 429 Too Many Requests | Throttle middleware | Rate limit exceeded | Wait, reduce frequency |
| 500 Server Error | Exception handler | Unexpected error | Check logs |
| 503 Service Unavailable | Maintenance mode | App in maintenance | Wait for maintenance to end |

## Lifecycle Performance Budget

Every stage in the request lifecycle has a micro-budget. Exceeding it doesn't crash the app — it degrades UX.

| Stage | Budget | Measurement Tool |
|---|---|---|
| TLS handshake | < 100ms | Browser DevTools → Network → Timing |
| Web server routing | < 5ms | Laravel Debugbar → Boot |
| Middleware stack | < 20ms | `microtime(true)` diff |
| Route resolution | < 5ms | Debugbar → Routing |
| Controller/Livewire dispatch | < 10ms | Debugbar → Dispatch |
| Database queries (total) | < 50ms | Debugbar → Queries |
| View/blade compilation | < 30ms | Debugbar → Views |
| Response serialization | < 5ms | Custom timing middleware |
| **Total server time** | **< 100ms** | X-Response-Time header |
