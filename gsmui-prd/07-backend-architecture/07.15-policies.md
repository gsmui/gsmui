# 07.15 - Policies

**Project:** GsmUi
**Architecture:** Authorization – Resource Policies
**Framework:** Laravel 13 + Livewire 4
**Version:** 1.0.0

---

# Purpose

Policies centralize authorization logic for a specific resource (model). Each GsmUi domain model that has access rules — `Component`, `Theme`, `Product`, `DocPage`, etc. — owns a matching Policy class. Policies answer questions of the form "can this user perform `update` on this `Component`?" and keep authorization out of controllers, Livewire components, and Actions (see `05.09-actions.md`).

This document specifies the concrete policy structure, the standard CRUD ability methods, registration via `Gate::policy` and `authorizeResource`, and the gate fallback chain used when no policy method matches. For ad-hoc, non-resource abilities, see `07.16-gates.md`.

> See also: `05.15-security.md` and `10-permissions.md` (Spatie Permission roles/permissions and team scoping). Policies compose with Spatie permissions; a policy method typically checks both ownership and the Spatie `can()` ability.

---

# 1. When to Use a Policy

Use a policy when authorization is *bound to a resource instance*:

```text
view, create, update, delete, restore, forceDelete
publish, archive, approve, download
```

Use a gate (see `07.16-gates.md`) for *action-based* abilities not tied to a model instance, e.g. `access-admin` or `export-themes`.

# 3. Standard Policy Structure

```php
<?php

declare(strict_types=1);

namespace App\Domains\Components\Policies;

use App\Domains\Components\Models\Component;
use App\Models\User;
use Illuminate\Auth\Access\HandlesAuthorization;

final class ComponentPolicy
{
    use HandlesAuthorization;

    public function view(User $user, Component $component): bool
    {
        if ($component->status->isPublic()) {
            return true;
        }

        return $component->user_id === $user->id || $user->can('components.view.any');
    }

    public function update(User $user, Component $component): bool
    {
        return $component->user_id === $user->id || $user->can('components.update.any');
    }

    public function delete(User $user, Component $component): bool
    {
        return $component->user_id === $user->id || $user->can('components.delete.any');
    }

    public function publish(User $user, Component $component): bool
    {
        return $user->can('components.publish');
    }
}
```

Use the `HandlesAuthorization` trait so `before()`/fallthrough behavior matches Laravel defaults.

# 4. Registration

Register policies in `AppServiceProvider` (or a dedicated `AuthServiceProvider`):

```php
use App\Domains\Components\Models\Component;
use App\Domains\Components\Policies\ComponentPolicy;
use Illuminate\Support\Facades\Gate;

public function boot(): void
{
    Gate::policy(Component::class, ComponentPolicy::class);

    Gate::policy(\App\Domains\Themes\Models\Theme::class, \App\Domains\Themes\Policies\ThemePolicy::class);
}
```

Group CRUD routes via `authorizeResource` in a controller:

```php
public function __construct()
{
    $this->authorizeResource(Component::class, 'component');
}
```

This auto-maps `index`→`viewAny`, `show`→`view`, `edit`/`update`→`update`, `destroy`→`delete`, etc.

# 5. Gate Fallback

When a model has no matching policy, or the ability has no method, Laravel falls through to the registered gates. Define a `before` hook to short-circuit for super admins:

```php
Gate::before(function (User $user, string $ability) {
    if ($user->can('admin.*')) {
        return true;
    }

    return null; // continue to policy
});
```

Returning `null` is critical — any truthy/falsy non-null value short-circuits all policy resolution.

```text

┌─────────────────────────────────────────────────────────────────┐
│                                                                 │
```

```text
│  ├─ YES → Use a Policy                                         │

│                      ├─ YES → Policy viewAny()                 │
```

# 12. Policy Authorization Patterns

```php
// Pattern 1: Ownership check
public function update(User $user, Component $component): bool
{
    return $component->user_id === $user->id;
}

// Pattern 2: Ownership + permission
public function update(User $user, Component $component): bool
{
    return $component->user_id === $user->id
        || $user->can('components.update.any');
}

// Pattern 3: Status-based
public function publish(User $user, Component $component): bool
{
    return $component->status === ComponentStatus::Draft
        && $user->can('components.publish');
}

// Pattern 4: Team-based
public function update(User $user, Component $component): bool
{
    return $component->team_id !== null
        && $user->teams()->contains($component->team_id)
        && $user->can('components.update');
}

// Pattern 5: Subscription-based
public function export(User $user, Theme $theme): bool
{
    return $user->subscription?->isActive()
        && $user->can('themes.export');
}
```

# 14. Gate Fallback Extended

```php
// Super admin bypass
Gate::before(function (User $user, string $ability) {
    if ($user->can('admin.*')) {
        return true;
    }

    return null; // continue to policy
});

// Suspended user block
Gate::before(function (User $user, string $ability) {
    if ($user->is_suspended) {
        return false;
    }

    return null;
});

// Internal staff override
Gate::after(function (User $user, string $ability, ?bool $result) {
    if ($result === null && $user->isInternalStaff()) {
        return true;
    }

    return $result;
});
```

# 15. Usage in Controllers Extended

```php
class ComponentController extends Controller
{
    public function __construct()
    {
        $this->authorizeResource(Component::class, 'component');
    }

    public function index()
    {
        // Automatically calls viewAny()
        $components = Component::where('user_id', auth()->id())->get();
        return view('components.index', compact('components'));
    }

    public function show(Component $component)
    {
        // Automatically calls view()
        $this->authorize('view', $component);
        return view('components.show', compact('component'));
    }

    public function update(UpdateComponentRequest $request, Component $component)
    {
        // Automatically calls update()
        $this->authorize('update', $component);

        $action = app(UpdateComponentAction::class);
        $action->run($request->validated());

        return redirect()->route('components.show', $component);
    }

    public function destroy(Component $component)
    {
        // Automatically calls delete()
        $this->authorize('delete', $component);

        $action = app(DeleteComponentAction::class);
        $action->run($component->id);

        return redirect()->route('components.index');
    }
}
```

# 18. Policy Anti-Patterns

| Anti-pattern | Why it's bad | Correct approach |
| --- | --- | --- |
| Business logic in policy | Violates SRP | Delegate to Service |
| Database queries in policy | Performance impact | Use cached values or relationships |
| Authorization in Action | Bypasses policy | Use policy in Controller/Livewire |
| Skipping authorization | Security risk | Always authorize before action |
| Hardcoded roles in policy | Not flexible | Use Spatie permissions |
| Policy without tests | Missing coverage | Test all authorization paths |
| Policy with side effects | Unexpected behavior | Policies are pure functions |
| Policy accessing request | Ties to HTTP | Use method parameters |

# 20. Policy and Team Scoping

```php
class ComponentPolicy
{
    use HandlesAuthorization;

    public function view(User $user, Component $component): bool
    {
        if ($component->team_id === null) {
            return $component->user_id === $user->id
                || $user->can('components.view.any');
        }

        return $user->teams()->contains($component->team_id)
            && $user->can('components.view.team');
    }

    public function update(User $user, Component $component): bool
    {
        if ($component->team_id === null) {
            return $component->user_id === $user->id
                || $user->can('components.update.any');
        }

        return $user->teams()->contains($component->team_id)
            && $user->can('components.update.team');
    }
}
```

# 23. Policy Security Matrix

| Security Concern | Mitigation |
| --- | --- |
| Missing authorization | Always call `$this->authorize()` |
| Bypassing policy | Use `Gate::before()` for admin only |
| IDOR via policy bypass | Policy checks ownership |
| Team scoping bypass | Policy checks team membership |
| Status-based bypass | Policy checks status |
| Subscription bypass | Policy checks subscription |

# 29. Policy and Event Integration

```php
// Policy checks before event dispatch
class PublishComponentAction extends Action
{
    public function run(PublishComponentData $data): void
    {
        $component = Component::find($data->componentId);
        $user = User::find($data->userId);

        // Policy check
        if (!$user->can('publish', $component)) {
            throw new \Illuminate\Auth\Access\AuthorizationException(
                'You cannot publish this component.'
            );
        }

        $component->update(['status' => ComponentStatus::Published]);

        $this->dispatchAfterCommit(new ComponentPublished(
            componentId: $component->id,
            userId: $user->id,
            version: $component->version,
        ));
    }
}
```

```php
// Policy checks in jobs
class ProcessRefund extends AbstractJob
{
    public function handle(): void
    {
        $order = Order::find($this->orderId);
        $user = User::find($order->user_id);

        // Policy check

            logger()->warning('refund.unauthorized', [
                'order_id' => $this->orderId,
                'user_id' => $user->id,
```

```php
    use HandlesAuthorization;
```

```php
        if ($component->team_id === null) {
            return $component->user_id === $user->id
                || $user->can('components.view.any');

            && $user->can('components.view.team');

                || $user->can('components.update.any');

            ->where('team_id', $component->team_id)
            ->first();

        if (!$teamMember) {
            return false;
        }

        return in_array($teamMember->role, ['owner', 'admin'])
            && $user->can('components.update.team');
    }

        if ($component->team_id === null) {
            return $component->user_id === $user->id
                || $user->can('components.delete.any');

            ->where('team_id', $component->team_id)
            ->first();

        if (!$teamMember) {
            return false;

        return $teamMember->role === 'owner'
            && $user->can('components.delete.team');
```

# 67. Policy and Webhook Integration

```php
class WebhookPolicy
{
    use HandlesAuthorization;

    public function update(User $user, Webhook $webhook): bool
    {
        // Check if webhook is active
        if ($webhook->status === 'inactive') {
            return false;
        }

        return $webhook->user_id === $user->id
            || $user->can('webhooks.update.any');
    }

    public function delete(User $user, Webhook $webhook): bool
    {
        // Check if webhook has recent deliveries
        $recentDeliveries = WebhookDelivery::where('webhook_id', $webhook->id)
            ->where('created_at', '>', now()->subHour())
            ->count();

        if ($recentDeliveries > 0) {
            return false;
        }

        return $webhook->user_id === $user->id
            || $user->can('webhooks.delete.any');
    }
}
```

```php
class ThemePolicy
{
    use HandlesAuthorization;

    public function export(User $user, Theme $theme): bool
    {
        // Check subscription tier
        $tier = $user->subscription?->tier ?? 'free';

        $maxExports = match ($tier) {
            'free' => 0,
            'basic' => 5,
            'pro' => 50,
            'enterprise' => PHP_INT_MAX,
            default => 0,
        };

        $exportCount = ExportLog::where('user_id', $user->id)
            ->where('created_at', '>', now()->subMonth())
            ->count();

        if ($exportCount >= $maxExports) {
            return false;
        }

        return $theme->user_id === $user->id
            && $user->can('themes.export');
    }
}
```

# 69. Policy and Team Role Integration

```php
class ComponentPolicy
{
    use HandlesAuthorization;

    public function update(User $user, Component $component): bool
    {
        if ($component->team_id === null) {
            return $component->user_id === $user->id
                || $user->can('components.update.any');
        }

        $teamMember = TeamMember::where('user_id', $user->id)
            ->where('team_id', $component->team_id)
            ->first();

        if (!$teamMember) {
            return false;
        }

        // Check role-based permissions
        return match ($teamMember->role) {
            'owner' => true,
            'admin' => $user->can('components.update.team'),
            'member' => $component->user_id === $user->id,
            'viewer' => false,
            default => false,
        };
    }
}
```

# 70. Policy Summary Extended

Policies are the backbone of resource-based authorization in GsmUi. They centralize authorization logic for specific resources, keeping authorization out of controllers, Livewire components, and Actions. Policies compose with Spatie permissions to provide flexible, testable authorization that scales with the application.

Key benefits:

| Benefit | Description |
| --- | --- |
| Centralization | All authorization logic in one place |
| Testability | Easy to test all authorization paths |
| Reusability | Use across controllers, Livewire, API |
| Security | Prevents authorization bypasses |
| Maintainability | Easy to update authorization rules |
| Scalability | Scales with application growth |
| Audit trail | Log authorization decisions |
| Caching | Cache expensive checks |
| Rate limiting | Prevent abuse |
| Event dispatch | Trigger side effects on authorization |
