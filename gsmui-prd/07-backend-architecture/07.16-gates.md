# 07.16 - Gates

**Project:** GsmUi
**Architecture:** Authorization – Ad-hoc Gates
**Framework:** Laravel 13 + Livewire 4
**Version:** 1.0.0

---

# Purpose

Gates provide authorization for abilities that are **not bound to a single resource instance**. Where policies (see `07.15-policies.md`) answer "can this user update *this* component?", gates answer "can this user access the admin area?" or "can this user export themes at all?". Gates are defined as named abilities — `access-admin`, `export-themes`, `manage-marketplace` — and are the fallback layer when a policy method is absent.

This document specifies the gate definition contract, ability naming conventions, closure vs class-based gates, `before`/`after` hooks, and the decision rule for choosing gates versus policies. Gates compose with Spatie permissions (see `10-permissions.md`); a gate typically delegates to `$user->can('permission.name')`.

> See also: `07.15-policies.md` (resource-bound authorization) and `05.15-security.md` (authorization middleware and threat model).

---

# 1. Gates vs Policies

Use the following decision rule:

| Scenario | Mechanism |
| --- | --- |
| Ability about a specific model instance (`update`, `delete`, `publish`) | Policy (`07.15-policies.md`) |
| Ability about an action, not a model (`access-admin`, `export-themes`) | Gate (this document) |
| Ability about a collection (`viewAny`) | Policy `viewAny`, fallback gate |
| Cross-cutting super-admin bypass | Gate `before` hook |

# 2. Gate Definition (closure)

Define gates in `AppServiceProvider::boot()` or a dedicated `AuthServiceProvider`:

```php
use App\Models\User;
use Illuminate\Support\Facades\Gate;

Gate::define('access-admin', function (User $user): bool {
    return $user->can('admin.access');
});

Gate::define('export-themes', function (User $user): bool {
    return $user->can('themes.export') && $user->subscription?->isActive();
});
```

Always type-hint `User` so unauthenticated calls resolve to `false` (Laravel passes `null` and the type hint fails closed).

# 3. Ability Naming

Use kebab-case, domain-prefixed ability names:

```text
access-admin
export-themes
manage-marketplace
impersonate-users
view-analytics
```

Avoid vague names like `canDoThing` or `isAllowed`.

# 4. Class-based Gates

For gates with non-trivial logic, extract the check into an invokable class under `Policies/` or `Authorization/`:

```php
<?php

declare(strict_types=1);

namespace App\Domains\Admin\Authorization;

use App\Models\User;

final class AccessAdminGate
{
    public function __invoke(User $user): bool
    {
        return $user->can('admin.access')
            && ! $user->is_suspended;
    }
}
```

```php
Gate::define('access-admin', AccessAdminGate::class);
```

# 5. before / after Hooks

`before` runs before any gate/policy and short-circuits when it returns a non-null value:

```php
Gate::before(function (User $user, string $ability) {
    if ($user->can('admin.*')) {
        return true;
    }

    return null;
});
```

`after` runs after resolution and can override the result (use sparingly):

```php
Gate::after(function (User $user, string $ability, ?bool $result) {
    if ($ability === 'access-admin' && $result === null) {
        return $user->isInternalStaff();
    }

    return $result;
});
```

# 12. Gate Definition (closure) Extended

```php
use App\Models\User;
use Illuminate\Support\Facades\Gate;

// Simple gate
Gate::define('access-admin', function (User $user): bool {
    return $user->can('admin.access');
});

// Complex gate with multiple conditions
Gate::define('export-themes', function (User $user): bool {
    return $user->can('themes.export')
        && $user->subscription?->isActive()
        && !$user->is_suspended;
});

// Gate with parameter
Gate::define('view-user-profile', function (User $user, User $target): bool {
    return $user->id === $target->id
        || $user->can('users.view.any')
        || $target->is_public;
});

// Gate returning response (not just bool)
Gate::define('access-premium-feature', function (User $user): \Illuminate\Auth\Access\Response|bool {
    if ($user->can('premium.access')) {
        return true;
    }

    if ($user->subscription?->isTrial()) {
        return \Illuminate\Auth\Access\Response::allowWithMessage(
            'You are on a trial period.'
        );
    }

    return false;
});
```

# 15. before / after Hooks Extended

`before` runs before any gate/policy and short-circuits when it returns a non-null value:

```php
// Super admin bypass
Gate::before(function (User $user, string $ability) {
    if ($user->can('admin.*')) {
        return true;
    }

    return null;
});

// Suspended user block
Gate::before(function (User $user, string $ability) {
    if ($user->is_suspended) {
        return false;
    }

    return null;
});

// Internal staff override
Gate::before(function (User $user, string $ability) {
    if ($user->isInternalStaff() && $user->can("{$ability}.internal")) {
        return true;
    }

    return null;
});
```

`after` runs after resolution and can override the result:

```php
Gate::after(function (User $user, string $ability, ?bool $result) {
    if ($ability === 'access-admin' && $result === null) {
        return $user->isInternalStaff();
    }

    return $result;
});
```

Hook execution order:

| Order | Hook | Purpose |
| --- | --- | --- |
| 1 | `Gate::before()` | Admin bypass, suspended block |
| 2 | `Gate::define()` | Ability-specific logic |
| 3 | `Gate::after()` | Override result (rare) |

# 17. Gate Testing Extended

```php
class GateTest extends TestCase
{
    use RefreshDatabase;

    public function test_super_admin_passes_every_gate_via_before(): void
    {
        $admin = User::factory()->create();
        $admin->givePermissionTo('admin.*');

        $this->assertTrue(Gate::forUser($admin)->allows('export-themes'));
        $this->assertTrue(Gate::forUser($admin)->allows('manage-marketplace'));
        $this->assertTrue(Gate::forUser($admin)->allows('impersonate-users'));
    }

    public function test_free_user_cannot_export_themes(): void
    {
        $user = User::factory()->create();

        $this->assertFalse(Gate::forUser($user)->allows('export-themes'));
    }

    public function test_premium_user_can_export_themes(): void
    {
        $user = User::factory()->create();
        $user->givePermissionTo('themes.export');
        $user->subscription = Subscription::factory()->active()->create();

        $this->assertTrue(Gate::forUser($user)->allows('export-themes'));
    }

    public function test_suspended_user_blocked_by_before_hook(): void
    {
        $user = User::factory()->create(['is_suspended' => true]);
        $user->givePermissionTo('admin.access');

        $this->assertFalse(Gate::forUser($user)->allows('access-admin'));
    }

    public function test_gate_with_parameter(): void
    {
        $user = User::factory()->create();
        $target = User::factory()->create(['is_public' => true]);

        $this->assertTrue(Gate::forUser($user)->allows('view-user-profile', $target));
    }

    public function test_gate_denies_when_parameter_fails(): void
    {
        $user = User::factory()->create();
        $target = User::factory()->create(['is_public' => false]);

        $this->assertFalse(Gate::forUser($user)->allows('view-user-profile', $target));
    }

    public function test_gate_returns_response_with_message(): void
    {
        $user = User::factory()->create();

        $response = Gate::forUser($user)->inspect('access-premium-feature');

        $this->assertTrue($response->allowed());
        $this->assertNotEmpty($response->message());
    }
}
```

# 18. Gate Anti-Patterns

| Anti-pattern | Why it's bad | Correct approach |
| --- | --- | --- |
| Gate with business logic | Violates SRP | Delegate to Service |
| Gate accessing database | Performance impact | Use cached values |
| Gate with side effects | Unexpected behavior | Gates are pure functions |
| Gate without type-hint | Unauthenticated access | Type-hint User |
| Vague ability names | Hard to understand | Use kebab-case, domain-prefixed |
| Gate in Action | Bypasses authorization | Use in Controller/Livewire |
| Missing tests | Missing coverage | Test all authorization paths |
| Gate with request access | Ties to HTTP | Use method parameters |

# 31. Gate and Policy Comparison

| Aspect | Gate | Policy |
| --- | --- | --- |
| Binding | Action-based | Resource-based |
| Model instance | No | Yes |
| Naming | `access-admin` | `update`, `delete` |
| Registration | `Gate::define()` | `Gate::policy()` |
| Usage | `Gate::allows('access-admin')` | `$user->can('update', $model)` |
| before/after | Yes | Yes (via Gate) |
| Class-based | Yes (invokable) | Yes (policy class) |

# 46. Gate Anti-Patterns Extended

| Anti-pattern | Why it's bad | Correct approach |
| --- | --- | --- |
| Gate with business logic | Violates SRP | Delegate to Service |
| Gate accessing database | Performance impact | Use cached values |
| Gate with side effects | Unexpected behavior | Gates are pure functions |
| Gate without type-hint | Unauthenticated access | Type-hint User |
| Vague ability names | Hard to understand | Use kebab-case, domain-prefixed |
| Gate in Action | Bypasses authorization | Use in Controller/Livewire |
| Missing tests | Missing coverage | Test all authorization paths |
| Gate with request access | Ties to HTTP | Use method parameters |
| Gate with too much logic | Hard to maintain | Extract to class-based gate |
| Gate without documentation | Hard to understand | Add PHPDoc |
| Gate with model in parameter | Ties to persistence | Use scalar IDs |
| Gate with service in parameter | Hidden coupling | Construct services inside gate |

# 47. Gate Documentation Standards Extended

Every gate must document:

```php
/**
 * Gate: access-admin
 *
 * Checks if a user can access the admin area.
 * Requires the 'admin.access' permission.
 * Blocked for suspended users.
 *
 * @see \App\Domains\Admin\Authorization\AccessAdminGate
 */
Gate::define('access-admin', function (User $user): bool {
    return $user->can('admin.access');
});

/**
 * Gate: view-user-profile
 *
 * Checks if a user can view another user's profile.
 * Allowed if:
 * - Target user is public
 * - Viewer is the target user
 * - Viewer has 'users.view.any' permission
 *
 * @param User $target The user whose profile is being viewed
 */
Gate::define('view-user-profile', function (User $user, User $target): bool {
    return $target->is_public
        || $user->id === $target->id
        || $user->can('users.view.any');
});
```
