# 07.10 - Value Objects

**Project:** GsmUi
**Architecture:** Domain Primitives / Value Object Pattern
**Framework:** Laravel 13 + Livewire 4
**Version:** 1.0.0

---

# Purpose

> See also: `05.07-service-layer.md` §"Service Responsibilities" (services may use value objects). This document specifies the **implementation contract** for GsmUi's domain primitives — immutable, self-validating value objects that replace raw strings/scalars for concepts with rules: `Money`, `Slug`, `ThemeToken`, `ComponentSlug`, and `Email`.

Value objects encode validation and formatting at the type level. A `Money` is always a valid minor-unit integer with a known currency; a `ComponentSlug` is always a URL-safe, lowercased token; an `Email` always passes RFC-shape validation. By constructing these in DTOs (see `07.09-dto-layer.md`) and service inputs, invalid primitives can never enter the domain, and comparison is by value rather than by reference.

Value objects are `final readonly`, hold no identity, and expose `equals()` for equality. They are serializable to/from their scalar storage form so they can live in Eloquent casts and Livewire state.

---

# 1A. Value Object Architecture Overview

Value objects are the building blocks of type-safe domain modeling. They replace raw strings, integers, and arrays with self-validating, immutable primitives.

```text
┌─────────────────────────────────────────────────────────────────────────┐
│                    VALUE OBJECT ARCHITECTURE                            │
├─────────────────────────────────────────────────────────────────────────┤
│                                                                         │
│  Raw PHP (fragile):                                                     │
│  ┌─────────────────────────────────────────────────────────┐            │
│  │  $amount = 999;        // int? cents? dollars?          │            │
│  │  $currency = 'USD';    // string? always uppercase?      │            │
│  │  $slug = 'my-slug';    // valid? who validated?          │            │
│  │  $email = 'a@b.com';   // really an email?               │            │
│  └─────────────────────────────────────────────────────────┘            │
│                                                                         │
│  Value Objects (safe):                                                   │
│  ┌─────────────────────────────────────────────────────────┐            │
│  │  $amount = Money::fromMajor(9.99, 'USD');               │            │
│  │  // Always valid: 999 cents, USD currency               │            │
│  │                                                         │            │
│  │  $slug = ComponentSlug::fromString('my-slug');          │            │
│  │  // Always valid: lowercase, kebab-case, ≤120 chars     │            │
│  │                                                         │            │
│  │  $email = Email::fromString('a@b.com');                 │            │
│  │  // Always valid: RFC-shape, lowercased                 │            │
│  └─────────────────────────────────────────────────────────┘            │
│                                                                         │
└─────────────────────────────────────────────────────────────────────────┘
```

# 1B. Value Object vs Entity vs DTO

| Concept | Identity | Mutable | Validation | Example |
| --- | --- | --- | --- | --- |
| Value Object | No (equality by value) | No (`readonly`) | Constructor validates | `Money`, `Email`, `Slug` |
| Entity | Yes (has ID) | Yes (attributes change) | Model-level validation | `Component`, `User`, `Theme` |
| DTO | No (equality by value) | No (`readonly`) | Factory validates | `CreateComponentData` |

The key distinction: two `Money(999, 'USD')` instances are identical. Two `Component(id:1)` instances are different entities even with the same attributes.

# 1E. Value Object Design Principles

| Principle | Description | Example |
| --- | --- | --- |
| Immutability | Cannot change after construction | `readonly` class property |
| Self-validation | Constructor rejects invalid values | `InvalidArgumentException` |
| Normalization | Input normalized on construction | `"My Slug"` → `"my-slug"` |
| Equality by value | Two VOs with same values are equal | `$a->equals($b)` |
| Scalar storage | Serializable to/from a scalar | `toString()`, `__toString()` |
| No identity | No ID, no database row | `Money` is not an entity |
| No behavior beyond formatting | No business logic | `Money::add()` is allowed (pure) |

Anti-pattern: Value objects with `update()` methods or mutable properties. They are immutable by contract.

# 2. Immutability & Equality Contract

Every value object follows the same shape:

- `final readonly` class.
- Constructor validates and normalizes; throws `InvalidArgumentException` on failure.
- A `fromString()` / `from*` factory for clarity at call sites.
- `equals(self $other): bool` compares by value.
- `toString()` / `__toString()` for scalar storage and display.

---

# 2A. Extended Immutability & Equality Contract

Every value object follows the same shape. The contract is enforced by code review and PHPStan:

| Requirement | Implementation | Rationale |
| --- | --- | --- |
| `final readonly` class | `final readonly class Money` | Prevents inheritance and mutation |
| Constructor validates | Throws `InvalidArgumentException` on invalid input | Fail fast at construction |
| `fromString()` factory | Named constructor for clarity | `Money::fromString('9.99')` reads well |
| `equals(self $other)` | Compares by value, not reference | Two `Money(999, 'USD')` are equal |
| `toString()` / `__toString()` | Scalar representation | For storage, display, and serialization |
| No setters | No `set*()` or `update()` methods | Immutability is absolute |

# 2B. Value Object Equality Deep Dive

Equality semantics differ between VOs:

```php
// Money: amount + currency must match
$usd1 = new Money(999, 'USD');
$usd2 = new Money(999, 'USD');
$eur = new Money(999, 'EUR');

$usd1->equals($usd2); // true (same amount, same currency)
$usd1->equals($eur);  // false (different currency)

// Slug: normalized value must match
$slug1 = ComponentSlug::fromString('My-Slug');
$slug2 = ComponentSlug::fromString('my-slug');
$slug1->equals($slug2); // true (both normalize to 'my-slug')

// Email: normalized address must match
$email1 = Email::fromString('User@Example.COM');
$email2 = Email::fromString('user@example.com');
$email1->equals($email2); // true (both normalize to 'user@example.com')
```

Equality rules:

| VO | Equality Basis | Normalization |
| --- | --- | --- |
| `Money` | `amount` + `currency` | None (already integers) |
| `Slug` | `value` | Lowercase, trim, kebab-case |
| `ComponentSlug` | `value` (inherited) | Lowercase, trim, kebab-case |
| `Email` | `address` | Lowercase, trim |
| `ThemeToken` | `name` + `value` | Strip `--` prefix for comparison |
| `Url` | Full URL string | Trim, lowercase host |
| `Locale` | Language code | Lowercase, normalize separator |

# 3. Money

`Money` stores integer minor units (e.g. cents) plus an ISO-4217 currency code. Never store floats.

```php
namespace App\Domains\Shared\ValueObjects;

use InvalidArgumentException;

final readonly class Money
{
    public function __construct(
        public int $amount,      // minor units
        public string $currency, // ISO-4217, e.g. "USD"
    ) {
        if ($amount < 0) {
            throw new InvalidArgumentException('Money amount cannot be negative.');
        }
        if (!preg_match('/^[A-Z]{3}$/', $currency)) {
            throw new InvalidArgumentException('Invalid ISO-4217 currency code.');
        }
    }

    public static function fromMajor(float $major, string $currency = 'USD'): self
    {
        return new self((int) round($major * 100), $currency);
    }

    public static function fromString(string $value, string $currency = 'USD'): self
    {
        return self::fromMajor((float) $value, $currency);
    }

    public function add(Money $other): self
    {
        $this->assertSameCurrency($other);
        return new self($this->amount + $other->amount, $this->currency);
    }

    public function equals(Money $other): bool
    {
        return $this->amount === $other->amount
            && $this->currency === $other->currency;
    }

    public function toString(): string
    {
        return sprintf('%s %.2f', $this->currency, $this->amount / 100);
    }

    private function assertSameCurrency(Money $other): void
    {
        if ($this->currency !== $other->currency) {
            throw new InvalidArgumentException('Currency mismatch.');
        }
    }
}
```

# 3A. Money Operations

`Money` supports arithmetic operations while maintaining immutability:

```php
// Addition
$sum = $price->add($tax);
// $price remains unchanged (immutable)

// Subtraction
$difference = $total->subtract($discount);

// Multiplication (for quantity)
$total = $unitPrice->multiply(3);

// Comparison
if ($price->greaterThan($otherPrice)) { ... }
if ($price->lessThanOrEqual($threshold)) { ... }

// Formatting
$price->toString();    // "USD 9.99"
$price->format();      // "$9.99" (locale-aware)
$price->minorUnits();  // 999
```

---

# 3B. Money Anti-Patterns

| Anti-pattern | Why it's bad | Correct approach |
| --- | --- | --- |
| `Money::fromFloat(9.99)` | Float precision loss | `Money::fromMajor(9.99)` or `Money::fromMinor(999)` |
| Storing money as `float` | Rounding errors accumulate | Always `int` minor units |
| `$amount = 999` without currency | Currency context lost | Always `Money` object |
| Mixing currencies in `add()` | `USD + EUR` is meaningless | Check currency first, throw on mismatch |
| `Money::fromString('$9.99')` | Parsing locale-dependent formats | Parse in Form Request, construct VO with clean data |

# 4. Slug & ComponentSlug

`Slug` is the base URL-safe token; `ComponentSlug` specializes it with component-specific length/character rules.

```php
namespace App\Domains\Shared\ValueObjects;

use InvalidArgumentException;

abstract class Slug
{
    public function __construct(public string $value)
    {
        $normalized = strtolower(trim($value));
        if (!preg_match('/^[a-z0-9]+(?:-[a-z0-9]+)*$/', $normalized)) {
            throw new InvalidArgumentException("Invalid slug: {$value}");
        }
        $this->value = $normalized;
    }

    public static function fromString(string $value): static
    {
        return new static($value);
    }

    public function equals(self $other): bool
    {
        return $this->value === $other->value;
    }

    public function __toString(): string
    {
        return $this->value;
    }
}

final class ComponentSlug extends Slug
{
    public function __construct(string $value)
    {
        if (strlen($value) > 120) {
            throw new InvalidArgumentException('Component slug exceeds 120 chars.');
        }
        parent::__construct($value);
    }
}
```

# 4B. Slug Normalization Rules

| Input | Normalized Output | Rule Applied |
| --- | --- | --- |
| `"My Component"` | `"my-component"` | Lowercase + replace spaces with hyphens |
| `"Hello World!"` | `"hello-world"` | Strip non-alphanumeric + kebab-case |
| `"  lots-of-spaces  "` | `"lots-of-spaces"` | Trim + collapse hyphens |
| `"UPPER-CASE"` | `"upper-case"` | Lowercase |
| `"already-valid"` | `"already-valid"` | No change (already normalized) |
| `"a--b"` | `"a-b"` | Collapse consecutive hyphens |
| `"--leading--"` | `"leading"` | Strip leading/trailing hyphens |

# 4C. Slug Uniqueness Strategy

Slugs are unique per domain scope. The uniqueness is enforced at the Service layer, not the VO layer:

```php
// In a Service:
public function create(CreateComponentData $data): Component
{
    $slug = $data->slug->value;

    // Check uniqueness within the user's components
    if ($this->components->slugExistsForUser($slug, $data->userId)) {
        $slug = $this->generateUniqueSlug($slug, $data->userId);
    }

    return $this->components->create([
        'name' => $data->name,
        'slug' => $slug,
        // ...
    ]);
}

private function generateUniqueSlug(string $base, int $userId): string
{
    $slug = $base;
    $counter = 1;

    while ($this->components->slugExistsForUser($slug, $userId)) {
        $slug = "{$base}-{$counter}";
        $counter++;
    }

    return $slug;
}
```

The VO validates format; the Service validates uniqueness.

# 5. ThemeToken

`ThemeToken` represents a single `--gsmui-*` design token (name + resolved value), validated against the token naming scheme.

```php
namespace App\Domains\Shared\ValueObjects;

use InvalidArgumentException;

final readonly class ThemeToken
{
    public function __construct(
        public string $name,   // e.g. "color-accent"
        public string $value,  // e.g. "#0ea5e9"
    ) {
        if (!str_starts_with($name, 'gsmui-') && !str_starts_with($name, '--gsmui-')) {
            throw new InvalidArgumentException("Token name must be a --gsmui-* token: {$name}");
        }
        if (!self::isValidColorOrMeasure($value)) {
            throw new InvalidArgumentException("Invalid token value: {$value}");
        }
    }

    public static function fromString(string $name, string $value): self
    {
        return new self($name, $value);
    }

    public function equals(self $other): bool
    {
        return $this->name === $other->name && $this->value === $other->value;
    }

    private static function isValidColorOrMeasure(string $value): bool
    {
        return (bool) preg_match('/^(#[0-9a-f]{3,8}|rgb|hsl|[0-9.]+(px|rem|em|%|-))$/i', $value);
    }
}
```

```php
final readonly class Email

        return new self($address);
    }

    public function equals(self $other): bool
    {
        return $this->address === $other->address;
    }

    {

    }
}
```

# 6A. Email Normalization

`Email` normalizes the address on construction:

| Input | Normalized Output | Rule |
| --- | --- | --- |
| `"User@Example.COM"` | `"user@example.com"` | Lowercase |
| `"  test@test.com  "` | `"test@test.com"` | Trim |
| `"test.name+tag@domain.co"` | `"test.name+tag@domain.co"` | Valid (local part preserved) |
| `"test@domain.com"` | `"test@domain.com"` | Already normalized |
| `"invalid"` | throws `InvalidArgumentException` | No `@` sign |
| `"@domain.com"` | throws `InvalidArgumentException` | Missing local part |
| `"test@"` | throws `InvalidArgumentException` | Missing domain |

# 6B. Email and Notifications

`Email` is used in notification channels:

```php
// Sending an email:
$recipient = Email::fromString($request->input('email'));
```

# 7A. Complete Eloquent Cast Implementations

Every value object needs a custom Eloquent cast for persistence:

```php
namespace App\Domains\Shared\Casts;

use App\Domains\Shared\ValueObjects\Money;
use Illuminate\Contracts\Database\Eloquent\CastsAttributes;

class MoneyCast implements CastsAttributes
{
    public function get($model, string $key, $value, array $attributes): ?Money
    {
        $amountKey = $key;
        $currencyKey = "{$key}_currency";

        if (!isset($attributes[$amountKey], $attributes[$currencyKey])) {
            return null;
        }

        return new Money(
            amount: (int) $attributes[$amountKey],
            currency: $attributes[$currencyKey],
        );
    }

    public function set($model, string $key, $value, array $attributes): ?array
    {
        if ($value === null) {
            return [$key => null, "{$key}_currency" => null];
        }

        $money = $value instanceof Money ? $value : Money::fromString($value);

        return [
            $key => $money->amount,
            "{$key}_currency" => $money->currency,
        ];
    }
}
```

# 7A4. ThemeTokenCast Implementation

```php
namespace App\Domains\Shared\Casts;

use App\Domains\Shared\ValueObjects\ThemeToken;
use Illuminate\Contracts\Database\Eloquent\CastsAttributes;

class ThemeTokenCast implements CastsAttributes
{
    public function get($model, string $key, $value, array $attributes): ?ThemeToken
    {
        // ThemeToken stored as JSON: {"name": "...", "value": "..."}
        $decoded = json_decode($value, true);

        if (!is_array($decoded) || !isset($decoded['name'], $decoded['value'])) {
            return null;
        }

        return ThemeToken::fromString($decoded['name'], $decoded['value']);
    }

    public function set($model, string $key, $value, array $attributes): ?string
    {
        if ($value === null) {
            return null;
        }

        $token = $value instanceof ThemeToken ? $value : throw new \InvalidArgumentException(
            'ThemeTokenCast requires a ThemeToken instance'
        );

        return json_encode([
            'name' => $token->name,
            'value' => $token->value,
        ]);
    }
}
```

# 7A5. Cast Performance Considerations

| Cast Type | Performance Impact | Optimization |
| --- | --- | --- |
| `MoneyCast` | Low (two columns) | Cache parsed Money objects |
| `SlugCast` | Very low (string in, string out) | No optimization needed |
| `EmailCast` | Very low (string in, string out) | No optimization needed |
| `ThemeTokenCast` | Low (JSON decode/encode) | Batch decode for collections |
| Composite casts | Medium (multiple columns) | Use `with()` for eager loading |

For bulk operations (1000+ models), consider using raw queries with manual VO construction instead of relying on casts:

```php
// Slow: Creates 1000 Money objects via cast
$orders = Order::where('status', 'paid')->get();

// Fast: Raw query, manual construction
$orders = DB::select('SELECT total, total_currency FROM orders WHERE status = ?', ['paid']);
$moneyObjects = array_map(fn ($row) => new Money((int) $row->total, $row->total_currency), $orders);
```

# 7A6. Cast Error Recovery

When corrupted data exists in the database, casts must handle gracefully:

```php
class MoneyCast implements CastsAttributes
{
    public function get($model, string $key, $value, array $attributes): ?Money
    {
        $amountKey = $key;
        $currencyKey = "{$key}_currency";

        if (!isset($attributes[$amountKey], $attributes[$currencyKey])) {
            return null;
        }

        try {
            return new Money(
                amount: (int) $attributes[$amountKey],
                currency: $attributes[$currencyKey],
            );
        } catch (\InvalidArgumentException $e) {
            // Log corrupted data for investigation
            logger()->warning('Corrupted Money value in database', [
                'model' => get_class($model),
                'key' => $key,
                'amount' => $attributes[$amountKey],
                'currency' => $attributes[$currencyKey],
                'error' => $e->getMessage(),
            ]);

            // Return null or throw, depending on strictness
            return null;
        }
    }
}
```

# 7A10. Value Object Immutability Guarantees

The `readonly` keyword enforces immutability at the PHP level:

```php
final readonly class Money
{
    public function __construct(
        public int $amount,      // cannot be changed
        public string $currency, // cannot be changed
    ) {}
}

$money = new Money(999, 'USD');

// This throws \Error:
$money->amount = 1000; // Cannot modify readonly property

// This creates a new instance:
$newMoney = new Money(1000, 'USD'); // $money unchanged
```

Immutability benefits:

| Benefit | Description |
| --- | --- |
| Thread safety | Safe to share across requests |
| Predictability | No unexpected mutations |
| Testability | No need to reset state between tests |
| Caching | Safe to cache without copy-on-write |
| Equality | Value comparison is reliable |

# 9H. Value Object Anti-Patterns Summary

| Anti-pattern | Why it's bad | Correct approach |
| --- | --- | --- |
| Mutable value object | Breaks immutability contract | Use `final readonly` |
| Value object with identity | Confuses with entities | VOs have no ID |
| Value object with business logic | Violates single responsibility | Move logic to Service |
| Value object that references Eloquent | Ties VO to persistence | Use scalar values |
| Value object with `validate()` method | Duplicates constructor validation | Validate in constructor |
| Value object stored as float | Precision loss | Use integer minor units |
| Value object with static `create()` factory | Confusing naming | Use `fromString()` |
| Value object without `equals()` | Cannot compare values | Always implement `equals()` |
| Value object with `toArray()` returning objects | Serialization breaks | Return scalar arrays |

# 9I. Value Object Security Considerations

| Risk | Mitigation |
| --- | --- |
| Injection via VO constructor | VO validates and normalizes all input |
| Corrupted database data | Casts handle gracefully with logging |
| Serialization leakage | `toArray()` exposes only safe data |
| Cache poisoning | VOs are immutable; safe to cache |
| IDOR via VO manipulation | VOs don't contain IDs |
| Mass assignment | VOs are constructed explicitly, not via mass assignment |

# 9J. Value Object Documentation Standards

Every VO must be documented with:

```php
/**
 * Represents a monetary amount in minor units (cents) with ISO-4217 currency.
 *
 * @see https://www.iso.org/iso-4217-currency-codes.html
 *
 * Storage: int (minor units) + string (currency code)
 * Example: Money::fromMajor(9.99, 'USD') → 999 cents, 'USD'
 *
 * Immutability: This class is final readonly. Operations return new instances.
 * Equality: Two Money objects are equal if amount AND currency match.
 * Arithmetic: add(), subtract(), multiply() maintain immutability.
 * Serialization: toString() → "USD 9.99", toArray() → ['amount' => 999, 'currency' => 'USD']
 */
final readonly class Money
{
    // ...
}
```

# 9K. Value Object Versioning Strategy

When a VO needs new fields (rare), follow this pattern:

```php
// Version 1:
final readonly class Money
{
    public function __construct(
        public int $amount,
        public string $currency,
    ) {}
}

// Version 2 (backward compatible):
final readonly class Money
{
    public function __construct(
        public int $amount,
        public string $currency,
        public ?int $cents = null, // NEW — optional, defaults to amount
    ) {
        // Backward compatibility: if cents is null, use amount
        $this->cents = $cents ?? $amount;
    }
}
```

The cast handles both old and new storage formats:

```php
class MoneyCast implements CastsAttributes
{
    public function get($model, string $key, $value, array $attributes): ?Money
    {
        // Handle both v1 and v2 storage
        if (isset($attributes["{$key}_cents"])) {
            // v2: separate cents column
            return new Money(
                amount: (int) $attributes["{$key}_cents"],
                currency: $attributes["{$key}_currency"],
                cents: (int) $attributes["{$key}_cents"],
            );
        }

        // v1: legacy column
        return new Money(
            amount: (int) $attributes[$key],
            currency: $attributes["{$key}_currency"],
        );
    }
}
```
