# 1. N+1 Prevention — Eager Loading

Every repository read that renders a relation must `with()` it. The default `ComponentRepository` listing:

```php
<?php

declare(strict_types=1);

namespace App\Domains\Components\Repositories;

use App\Models\Component;
use Illuminate\Contracts\Pagination\LengthAwarePaginator;

final class ComponentRepository
{
    public function paginateWithAuthor(int $perPage = 15): LengthAwarePaginator
    {
        return Component::query()
            ->with(['user:id,name,avatar'])          // author
            ->withCount(['downloads', 'likes'])      // counters, no extra row fetch
            ->with(['category:id,name,slug'])        // belongsTo
            ->whereNotNull('published_at')
            ->latest('published_at')
            ->paginate($perPage);
    }

    /** Nested + conditional load for detail pages. */
    public function findForShow(int $id): Component
    {
        return Component::query()
            ->with([
                'user:id,name,avatar',
                'media:id,component_id,path,type',
                'versions' => fn ($q) => $q->latest()->limit(5),
                'tags:id,name',
            ])
            ->findOrFail($id);
    }
}
```

Rules:

- Always select only needed columns on relations: `with('user:id,name')`.
- Use `withCount()` instead of loading a collection just to call `->count()`.
- Avoid `with()` on relations you do not render.
- For authorization-heavy lists, avoid loading the full `user` model; load a read-only projection.

# 2. N+1 Detection in Dev

Enable Laravel's `PreventLazyLoading` in non-production to fail fast:

```php
// AppServiceProvider::boot() (local only)
if (app()->environment('local', 'testing')) {
    \Illuminate\Database\Eloquent\Model::preventLazyLoading(! $this->app->runningUnitTests());
    \Illuminate\Database\Eloquent\Model::handleLazyLoadingViolationUsing(
        fn ($model, $relation) => logger()->warning('lazy_load', [
            'model' => $model::class, 'relation' => $relation,
        ])
    );
}
```

It throws `LazyLoadingViolationException` outside tests so regressions surface immediately in the browser.

# 3. Query Monitoring

Log slow queries via a listener on `QueryExecuted` (threshold 50 ms, matching `05.43-performance-optimization.md`).

```php
<?php

declare(strict_types=1);

namespace App\Listeners;

use Illuminate\Database\Events\QueryExecuted;
use Illuminate\Support\Facades\Log;

final class LogSlowQuery
{
    public function handle(QueryExecuted $event): void
    {
        if ($event->time < 50.0) {
            return;
        }

        Log::channel('integrations')->warning('slow_query', [
            'sql' => $event->sql,
            'bindings' => $event->bindings,
            'time_ms' => $event->time,
            'connection' => $event->connectionName,
        ]);
    }
}
```

Register in `EventServiceProvider` (dev/test only to avoid prod overhead). Use `DB::enableQueryLog()` only inside tests (`07.55-testing.md`).

# 4. Caching Strategy

Four layers, all on Redis (`redis` driver). User-specific keys are namespaced by `user_id`; shared keys use a global namespace.

```php
// Shared, expensive computed result
$popular = Cache::remember(
    'components:popular:24h',
    now()->addHour(),
    fn () => $this->repo->popularLast24h(20),
);

// User-specific
$recent = Cache::remember(
    "user:{$user->id}:recent-components",
    now()->addMinutes(10),
    fn () => $this->repo->recentFor($user, 10),
);

// Search results (Scout/Meilisearch) short TTL
Cache::remember(
    "search:" . md5($query),
    now()->addMinutes(5),
    fn () => Component::search($query)->take(20)->get(),
);
```

Cache invalidation hooks fire on writes via model observers (`07.47-observers.md`):

```php
public function created(Component $component): void
{
    Cache::forget('components:popular:24h');
    Cache::forget("user:{$component->user_id}:recent-components");
}
```

| Layer | Driver | TTL | Example |
| --- | --- | --- | --- |
| Object/computed | Redis | 5–60 min | popular list, user recents |
| Search | Redis | 5 min | Meilisearch queries |
| HTTP/Vite | CDN/opcache | build | assets, hashed filenames |
| DB | MySQL buffer pool | provider | indexed rows |

# 5. OPcache & Preload

Production `php.ini`:

```ini
opcache.enable=1
opcache.enable_cli=1
opcache.memory_consumption=256
opcache.interned_strings_buffer=16
opcache.max_accelerated_files=20000
opcache.validate_timestamps=0   ; disable in prod, enable in dev
opcache.preload=/var/www/gsmui/bootstrap/preload.php
opcache.preload_user=www-data
```

Generate `bootstrap/preload.php` via `composer dump-autoload --optimize --classmap-authoritative` plus a preload script that requires framework + domain classes:

```php
<?php
$paths = [
    __DIR__ . '/../vendor/autoload.php',
    // app domain classes enumerated by a build step
];
foreach ($paths as $p) { if (is_file($p)) require_once $p; }
```

Redis `maxmemory-policy=allkeys-lru` so cache evicts gracefully under memory pressure.

# 6. Queue Offloading

Any work > ~200 ms or side-effecting goes to a queue (`07.49-queues.md`). Examples:

```php
// Synchronous controller should NOT do this:
// $this->meili->addDocuments($docs); $this->exportToS3($component);

// Instead dispatch:
GenerateComponentExport::dispatch($component)->onQueue('exports');
SearchIndexJob::dispatch($component)->onQueue('search');
NotifySubscribers::dispatch($component)->onQueue('default');
```

Horizon supervises workers with tuned queues:

```php
// config/horizon.php
'production' => [
    'supervisor-www' => [
        'connection' => 'redis',
        'queue' => ['default', 'search', 'exports', 'low'],
        'maxProcesses' => 10,
        'balance' => 'auto',
    ],
],
```

Long-running jobs set `timeout`, `tries`, and `backoff`; they never serialize the `Request` or the authenticated `User` (see `05.15-security.md`).

# 7. Profiling in Development

Use Laravel Telescope (local) and clock-style timing helpers for manual profiling. Never enable Telescope in production.

```php
use Illuminate\Support\Facades\DB;

$start = hrtime(true);
$result = $this->service->heavyComputation();
$ms = (hrtime(true) - $start) / 1_000_000;

if (app()->environment('local') && $ms > 100) {
    Log::debug('slow_computation', ['ms' => $ms, 'method' => __METHOD__]);
}
```

Telescope entries to watch: queries > 50 ms, duplicate queries, jobs > 1 s.

# 8. Indexing Policy

Repositories must declare the indexes their queries rely on. Migration contract:

```php
Schema::table('components', function (Blueprint $t): void {
    $t->index(['published_at', 'category']);   // list + filter
    $t->fullText(['name', 'description']);      // search fallback
    $t->foreignId('user_id')->constrained()->index();
});
```

- Composite indexes ordered by selectivity + equality-before-range.
- `EXPLAIN` any query touching > 10k rows in reviews.
- Avoid `LIKE '%term%'` on un-indexed columns; prefer Meilisearch (`07.21-api-architecture.md`).

# 9. Livewire Performance

- Use `wire:model.lazy` / `.debounce` for text inputs to cut round-trips.
- Call `$this->skipRender()` in polling-only actions when the view is unchanged.
- Cache expensive computed properties: compute once in `mount()`, store on the component.
- Lock the component to the minimum data needed; do not pass full models to the frontend.

```php
public function mount(): void
{
    $this->popular = Cache::remember('components:popular:24h', now()->addHour(),
        fn () => Component::popular()->limit(8)->get(['id','name','slug']));
}
```

```php
        'tries' => 3,
        'timeout' => 60,
        'nice' => 0,
    ],
],
```

## 14.2 Job Batching

Process jobs in batches for efficiency:

```php
use Illuminate\Bus\Batch;

Bus::batch([
    new ProcessComponent($component1),
    new ProcessComponent($component2),
    new ProcessComponent($component3),
])->then(function (Batch $batch) {
    // All jobs completed
})->catch(function (Batch $batch, Throwable $e) {
    // First batch job failure
})->finally(function (Batch $batch) {
    // All jobs have completed or failed
})->onConnection('redis')->onQueue('high')->dispatch();
```

## 14.3 Rate Limiting on Queues

Prevent queue overload:

```php
Bus::batch($jobs)
    ->then(fn () => Log::info('Batch complete'))
    ->onConnection('redis')
    ->onQueue('default')
    ->allowFailures()
    ->dispatch();
```

# 18. Caching Strategies

## 18.1 Cache Invalidation Patterns

```php
// Tag-based invalidation
Cache::tags(['components', 'user:'.$userId])->flush();

// Event-based invalidation
Event::listen(ComponentCreated::class, function ($event) {
    Cache::forget('components:popular:24h');
    Cache::forget("user:{$event->component->user_id}:recent-components");
});

// Time-based invalidation
Cache::remember('key', 3600, fn () => expensive computation);
```

## 18.2 Multi-Layer Caching

```php
final class MultiLayerCache
{
    public function get(string $key, callable $callback, int $ttl = 3600)
    {
        // L1: In-memory (request scope)
        if (isset($this->memory[$key])) {
            return $this->memory[$key];
        }

        // L2: Redis
        $value = Cache::get($key);
        if ($value !== null) {
            $this->memory[$key] = $value;
            return $value;
        }

        // L3: Database
        $value = $callback();
        Cache::put($key, $value, $ttl);
        $this->memory[$key] = $value;

        return $value;
    }
}
```

# 22. Performance Monitoring

## 22.1 Application Performance Monitoring

```php
final class ApplicationPerformanceMonitor
{
    public function recordRequest(Request $request, float $startTime): void
    {
        $duration = (microtime(true) - $startTime) * 1000;

        $metrics = [
            'method' => $request->method(),
            'path' => $request->path(),
            'status' => $request->status(),
            'duration_ms' => round($duration, 2),
            'memory_bytes' => memory_get_usage(true),
            'query_count' => count(DB::getQueryLog()),
            'cache_hits' => Cache::getHitCount(),
            'timestamp' => now()->toIso8601String(),
        ];

        // Send to monitoring service
        $this->sendMetrics($metrics);

        // Log slow requests
        if ($duration > 200) {
            Log::channel('performance')->warning('slow_request', $metrics);
        }
    }
}
```

## 22.3 Queue Performance Monitoring

```php
final class QueuePerformanceMonitor
{
    public function monitor(): void
    {
        $queues = ['default', 'high', 'low'];

        foreach ($queues as $queue) {
            $size = DB::table('jobs')->where('queue', $queue)->count();
            $processing = DB::table('jobs')->where('queue', $queue)->where('reserved_at', '!=', null)->count();

            Cache::put("metrics:queue:{$queue}:size", $size, 60);
            Cache::put("metrics:queue:{$queue}:processing", $processing, 60);

                Log::channel('ops')->warning('queue_backlog', [
                    'queue' => $queue,
                    'size' => $size,
                ]);
            }
        }
    }
}
```

## 23.2 Custom Profiling

```php
final class Profiler
{
    private array $startTimes = [];
    private array $metrics = [];

    public function start(string $label): void
    {
        $this->startTimes[$label] = microtime(true);
    }

    public function stop(string $label): float
    {
        $elapsed = (microtime(true) - $this->startTimes[$label]) * 1000;
        $this->metrics[$label][] = $elapsed;

        if ($elapsed > 100) {
            Log::debug('slow_operation', [
                'label' => $label,
                'ms' => round($elapsed, 2),
            ]);
        }

        return $elapsed;
    }

    public function report(): array
    {
        return array_map(fn ($times) => [
            'count' => count($times),
            'avg' => round(array_sum($times) / count($times), 2),
            'max' => round(max($times), 2),
            'min' => round(min($times), 2),
        ], $this->metrics);
    }
}
```

# 24. Performance Optimization Techniques

## 24.1 Lazy Collection Processing

Process large datasets without loading all into memory:

```php
// Using cursor (memory efficient)
foreach (Component::where('active', true)->cursor() as $component) {
    $this->processComponent($component);
}

// Using chunk (batch processing)
Component::where('active', true)->chunk(100, function ($components) {
    foreach ($components as $component) {
        $this->processComponent($component);
    }
});

// Using lazy collection
$lazy = Component::where('active', true)->lazy();
foreach ($lazy as $component) {
    $this->processComponent($component);
}
```

## 24.2 Selective Column Loading

Only load columns you need:

```php
// Bad: loads all columns
$users = User::all();

// Good: loads only needed columns
$users = User::select('id', 'name', 'email')->get();

// Good: with relation counts
$users = User::withCount('components')->get();
```

## 24.3 Database Index Optimization

```php
// Composite index for common queries
Schema::table('components', function (Blueprint $table) {
    $table->index(['published_at', 'category', 'downloads']);
});

// Partial index for filtered queries
Schema::table('components', function (Blueprint $table) {
    $table->index('name')->where('published_at', '!=', null);
});
```

## 24.4 Query Result Caching

Cache expensive query results:

```php
final class CachedComponentQuery
{
    public function popularLast24h(int $limit = 20): Collection
    {
        return Cache::remember(
            "components:popular:24h:{$limit}",
            now()->addHour(),
            fn () => Component::where('published_at', '>=', now()->subDay())
                ->orderByDesc('downloads')
                ->limit($limit)
                ->get()
        );
    }
}
```

# 39. Performance Metrics Collection

## 39.1 Custom Metrics

```php
final class PerformanceMetrics
{
    public static function record(string $metric, float $value, array $tags = []): void
    {
        $key = "metrics:{$metric}:" . now()->format('Y-m-d-H');

        Redis::hset($key, uniqid(), json_encode([
            'value' => $value,
            'tags' => $tags,
            'timestamp' => microtime(true),
        ]));

        Redis::expire($key, 86400); // 24 hours
    }

    public static function average(string $metric, int $hours = 24): float
    {
        $total = 0;
        $count = 0;

        for ($i = 0; $i < $hours; $i++) {
            $key = "metrics:{$metric}:" . now()->subHours($i)->format('Y-m-d-H');
            $data = Redis::hgetall($key);

            foreach ($data as $entry) {
                $decoded = json_decode($entry, true);
                $total += $decoded['value'];
                $count++;
            }
        }

        return $count > 0 ? $total / $count : 0;
    }
}
```
