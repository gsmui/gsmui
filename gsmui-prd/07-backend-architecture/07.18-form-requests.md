# 07.18 - Form Requests

**Project:** GsmUi
**Architecture:** HTTP Request Validation
**Framework:** Laravel 13 + Livewire 4
**Version:** 1.0.0

---

# Purpose

Form Request classes are the standard, reusable container for HTTP input validation and authorization in GsmUi. They group `rules()`, `authorize()`, `prepareForValidation()`, localized `messages()`/`attributes()`, and `after()` hooks into one testable class instead of scattering them across controllers. Controllers and routes type-hint the Form Request and receive a validated, normalized array — keeping controllers thin and pushing all edge-validation into a single contract.

This document specifies the Form Request structure, how `authorize()` composes with policies (see `07.15-policies.md`) and gates (see `07.16-gates.md`), how reusable rule objects from `07.17-validation.md` are referenced, and the `after()` hook pattern for cross-field validation.

> See also: `07.17-validation.md` (custom rule objects, `prepareForValidation`, localized messages — the primitives Form Requests compose). Form Requests are the primary consumer of those rules.

---

# 1. Form Request Rules

1. **One Form Request per write operation** (create vs update differ in `rules()`).
2. **Never call the database for business logic in `rules()`** beyond uniqueness/existence checks.
3. **Delegate authorization to policies/gates** via `authorize()` — do not reimplement ownership checks.
4. **Reuse rule objects** from `07.17-validation.md` rather than inline closures.
5. **Keep controllers free of `validate()` calls** — rely on the type-hinted Form Request.

# 3. Standard Form Request Structure

```php
<?php

declare(strict_types=1);

namespace App\Domains\Components\Http\Requests;

use App\Domains\Components\Models\Component;
use App\Domains\Components\Rules\ValidComponentSlug;
use Illuminate\Foundation\Http\FormRequest;

final class UpdateComponentRequest extends FormRequest
{
    public function authorize(): bool
    {
        return $this->user()->can('update', $this->route('component'));
    }

    public function rules(): array
    {
        return [
            'name' => ['sometimes', 'required', 'string', 'max:120'],
            'slug' => ['sometimes', 'required', 'string', new ValidComponentSlug(),
                       'unique:components,slug,'.$this->route('component')->id],
            'visibility' => ['sometimes', 'required', Rule::in(ThemeVisibility::values())],
            'team_id' => ['sometimes', 'prohibited_unless:visibility,team', 'exists:teams,id'],
        ];
    }

    protected function prepareForValidation(): void
    {
        if ($this->filled('name') && ! $this->filled('slug')) {
            $this->merge(['slug' => Str::slug($this->input('name'))]);
        }
    }

    public function messages(): array
    {
        return [
            'slug.unique' => 'That component slug is already taken.',
        ];
    }
}
```

# 4. Reusable Rule Objects

Reference rule objects defined in `07.17-validation.md` rather than duplicating logic:

```php
use App\Domains\Components\Rules\ValidComponentSlug;

'slug' => ['required', 'string', new ValidComponentSlug()],
```

For enum-backed fields use `spatie/laravel-enum-rules` (see `07.11-enums.md` §11).

---

# 5. after() Hooks

Use `after()` for validation that needs the *validated* data or cross-field consistency that simple rules cannot express:

```php
public function after(): array
{
    return [
        function (\Illuminate\Validation\Validator $validator) {
            if ($this->input('visibility') === 'team' && ! $this->input('team_id')) {
                $validator->errors()->add('team_id', 'A team must be selected for team visibility.');
            }
        },
    ];
}
```

Prefer `after()` over complex closures inside `rules()` because it runs after field-level rules pass.

# 6. Usage in Routes / Controllers

Route model binding injects the validated request:

```php
Route::put('/components/{component}', [ComponentController::class, 'update'])
    ->middleware('can:update,component');

public function update(UpdateComponentRequest $request, Component $component): JsonResponse
{
    $dto = UpdateComponentData::fromRequest($request);

    $component = app(UpdateComponentAction::class)->execute($dto);

    return ComponentResource::make($component)->response();
}
```

`$request->validated()` is guaranteed normalized and authorized before the Action runs (see `05.09-actions.md`).

---

# 7. Livewire Integration

Livewire components reuse the same Form Request via `validate()` with the request's rules:

```php
public function save(): void
{
    $data = $this->validate(
        app(UpdateComponentRequest::class)->rules()
    );

    app(UpdateComponentAction::class)->execute(UpdateComponentData::fromArray($data));
}
```

This guarantees identical validation between HTTP and Livewire entry points.

# 8. Testing

```php
public function test_update_request_authorizes_owner_only(): void
{
    $owner = User::factory()->create();
    $other = User::factory()->create();
    $component = Component::factory()->for($owner)->create();

    $request = UpdateComponentRequest::create("/components/{$component->id}", 'PUT', ['name' => 'X']);
    $request->setUserResolver(fn () => $other);

    $this->assertFalse($request->authorize());
}

public function test_update_request_validates_unique_slug(): void
{
    Component::factory()->create(['slug' => 'taken']);

    $request = UpdateComponentRequest::create('/components/1', 'PUT', ['slug' => 'taken']);

    $validator = Validator::make($request->all(), $request->rules());

    $this->assertTrue($validator->fails());
}
```

```php
            'category.required' => 'Select a category for your component.',
            'tags.max' => 'You can add up to 15 tags.',
            'tags.*.max' => 'Each tag must be 50 characters or fewer.',
        ];
    }

    public function attributes(): array
    {
        return [
            'name' => 'component name',
            'slug' => 'URL slug',
            'long_description' => 'full description',
            'category' => 'category',
```

### PublishThemeRequest

```php
<?php

declare(strict_types=1);

namespace App\Domains\Themes\Http\Requests;

use Illuminate\Foundation\Http\FormRequest;
use Illuminate\Validation\Rule;

final class PublishThemeRequest extends FormRequest
{
    public function authorize(): bool
    {
        return $this->user()->can('publish', $this->route('theme'));
    }

    public function rules(): array
    {
        return [
            'changelog' => ['required', 'string', 'max:2000'],
            'version' => ['required', 'string', 'regex:/^\d+\.\d+\.\d+$/'],
            'confirm_publish' => ['required', 'accepted'],
        ];
    }

    public function messages(): array
    {
        return [
            'changelog.required' => 'Provide a changelog describing what changed in this release.',
            'version.regex' => 'Version must follow semantic versioning (e.g. 1.0.0).',
            'confirm_publish.accepted' => 'You must confirm you want to publish this theme.',
        ];
    }

    public function after(): array
    {
        return [
            function (\Illuminate\Validation\Validator $validator) {
                $theme = $this->route('theme');

                if ($theme && $theme->status === 'published' && ! $validator->errors()->any()) {
                    $existing = \App\Domains\Themes\Models\ThemeVersion::where('theme_id', $theme->id)
                        ->where('version', $this->input('version'))
                        ->exists();

                    if ($existing) {
                        $validator->errors()->add(
                            'version',
                            "Version {$this->input('version')} has already been published for this theme."
                        );
                    }
                }
            },
        ];
    }
}
```

### PurchaseProductRequest

```php
<?php

declare(strict_types=1);

namespace App\Domains\Marketplace\Http\Requests;

use Illuminate\Foundation\Http\FormRequest;

final class PurchaseProductRequest extends FormRequest
{
    public function authorize(): bool
    {
        $product = $this->route('product');

        return $this->user() !== null
            && $product->isPublished()
            && ! $this->user()->hasPurchased($product);
    }

    public function rules(): array
    {
        return [
            'payment_method' => ['required', 'string', Rule::in(['stripe', 'paypal'])],
            'accept_terms' => ['required', 'accepted'],
            'coupon_code' => ['nullable', 'string', 'max:50', 'exists:coupons,code'],
        ];
    }

    public function messages(): array
    {
        return [
            'payment_method.required' => 'Select a payment method.',
            'accept_terms.accepted' => 'You must accept the terms of service.',
            'coupon_code.exists' => 'Invalid coupon code.',
        ];
    }

    public function after(): array
    {
        return [
            function (\Illuminate\Validation\Validator $validator) {
                if ($this->filled('coupon_code') && ! $validator->errors()->has('coupon_code')) {
                    $coupon = \App\Domains\Marketplace\Models\Coupon::where('code', $this->input('coupon_code'))->first();

                    if ($coupon && $coupon->isExpired()) {
                        $validator->errors()->add('coupon_code', 'This coupon has expired.');
                    }

                    if ($coupon && $coupon->max_uses !== null && $coupon->used_count >= $coupon->max_uses) {
                        $validator->errors()->add('coupon_code', 'This coupon has reached its usage limit.');
                    }
                }
            },
        ];
    }
}
```

```php
                'sometimes', 'required', 'string', 'min:3', 'max:30',
                'regex:/^[a-z0-9][a-z0-9_-]*$/',

            'bio' => ['nullable', 'string', 'max:500'],
```

## 10.3 Date Range Validation

Ensure start dates precede end dates:

```php
public function rules(): array
{

        'end_date' => ['required', 'date', 'after:start_date'],

public function after(): array
{

            $end = $this->input('end_date');
```

# 12. Form Request Service Provider Registration

Bind custom validation rules and authorize logic in service providers:

```php
<?php

namespace App\Providers;

use App\Domains\Components\Rules\ValidComponentSlug;
use Illuminate\Support\ServiceProvider;
use Illuminate\Support\Facades\Validator;

final class ValidationServiceProvider extends ServiceProvider
{
    public function boot(): void
    {
        Validator::extend('valid_component_slug', function (string $attribute, $value) {
            return preg_match('/^[a-z][a-z0-9-]*$/', $value) && strlen($value) <= 120;
        }, 'The :attribute must be a valid component slug.');

        Validator::extend('unique_slug_except', function (string $attribute, $value, array $parameters) {
            $table = $parameters[0];
            $column = $parameters[1] ?? 'slug';
            $exceptId = $parameters[2] ?? null;

            $query = \DB::table($table)->where($column, $value);

            if ($exceptId) {
                $query->where('id', '!=', $exceptId);
            }

            return ! $query->exists();
        }, 'The :attribute slug is already taken.');

        Validator::replacer('valid_component_slug', function ($message, $attribute) {
            return str_replace(':attribute', $attribute, $message);
        });
    }
}
```

# 13. Form Request Authorization Patterns

## 13.1 Policy-Based Authorization

Most Form Requests delegate to policies. The `authorize()` method calls the gate, which resolves the policy:

```php
// ComponentPolicy
final class ComponentPolicy
{
    public function create(User $user): bool
    {
        return $user->hasRole(['admin', 'author']);
    }

    public function update(User $user, Component $component): bool
    {
        return $user->id === $component->user_id
            || $user->hasRole('admin');
    }

    public function delete(User $user, Component $component): bool
    {
        return $user->id === $component->user_id
            || $user->hasRole('admin');
    }

    public function publish(User $user, Component $component): bool
    {
        return $user->id === $component->user_id
            && $component->status === 'draft'
            && $user->hasRole(['admin', 'author']);
    }
}
```

# 15. Form Request Performance Considerations

## 15.1 Avoiding N+1 in `authorize()`

Never run queries inside `authorize()` that cause N+1. Load the model via route model binding:

```php
// BAD: runs a query every time
public function authorize(): bool
{
    $component = \App\Models\Component::find($this->route('component')->id);
    return $this->user()->can('update', $component);
}

// GOOD: uses the already-resolved route model
public function authorize(): bool
{
    return $this->user()->can('update', $this->route('component'));
}
```

## 15.2 Lazy Validation with `sometimes()`

Only validate fields that are present in the request. The `sometimes()` method applies rules conditionally:

```php
public function rules(): array
{
    $rules = [
        'name' => ['required', 'string', 'max:120'],
    ];

    if ($this->isMethod('POST')) {
        $rules['slug'] = ['required', 'string', new ValidComponentSlug(), 'unique:components,slug'];
    }

    if ($this->isMethod('PUT') || $this->isMethod('PATCH')) {
        $component = $this->route('component');
        $rules['slug'] = ['sometimes', 'required', 'string', new ValidComponentSlug(),
                          'unique:components,slug,' . ($component?->id ?? '0')];
    }

    return $rules;
}
```

## 15.3 Caching Route Model Resolution

Route model binding caches the resolved model in the request. Multiple calls to `$this->route('component')` return the same instance without re-querying.

```php
            'slug' => ['required', 'string', 'max:120', new ValidComponentSlug(), 'unique:components,slug'],
            'description' => ['required', 'string', 'max:2000'],
            'category' => ['required', 'string', Rule::in(['ui', 'backend', 'devtools', 'utilities'])],
            'visibility' => ['sometimes', 'string', Rule::in(['public', 'private', 'team'])],
            'team_id' => ['nullable', 'required_if:visibility,team', 'exists:teams,id'],
            'tags' => ['nullable', 'array', 'max:15'],
            'tags.*' => ['string', 'max:50'],
        ];
    }

    public function messages(): array
    {
        return [
            'name.required' => 'The component name field is required.',
            'slug.unique' => 'A component with this slug already exists.',
        ];
    }

    public function attributes(): array
    {
        return [
            'name' => 'name',
            'slug' => 'slug',
            'description' => 'description',
            'category' => 'category',
        ];
    }
}
```

# 19. Error Response Formatting

Form Request validation errors are automatically converted to JSON in API contexts. Customize the format via `FailedValidation` trait:

```php
use Illuminate\Foundation\Http\FormRequest;
use Illuminate\Contracts\Validation\Validator;
use Illuminate\Http\Exceptions\HttpResponseException;

abstract class BaseFormRequest extends FormRequest
{
    protected function failedValidation Validator $validator): void
    {
        if ($this->expectsJson()) {
            throw new HttpResponseException(
                response()->json([
                    'success' => false,
                    'message' => 'Validation failed.',
                    'errors' => $validator->errors()->toArray(),
                ], 422)
            );
        }

        parent::failedValidation($validator);
    }

    protected function failedAuthorization(): void
    {
        if ($this->expectsJson()) {
            throw new HttpResponseException(
                response()->json([
                    'success' => false,
                    'message' => 'Unauthorized.',
                ], 403)
            );
        }

        parent::failedAuthorization();
    }
}
```

All domain Form Requests extend `BaseFormRequest` instead of the raw Laravel `FormRequest`:

```php
final class StoreComponentRequest extends BaseFormRequest
{
    // ...
}
```

# 20. Form Request DTO Bridge

Form Requests produce validated data that flows into DTOs. The bridge ensures type safety:

```php
// DTO
final class CreateComponentData
{
    public function __construct(
        public readonly string $name,
        public readonly string $slug,
        public readonly string $description,
        public readonly string $category,
        public readonly string $visibility = 'public',
        public readonly ?int $teamId = null,
        public readonly ?array $tags = null,
    ) {}

    public static function fromRequest(array $validated): self
    {
        return new self(
            name: $validated['name'],
            slug: $validated['slug'],
            description: $validated['description'],
            category: $validated['category'],
            visibility: $validated['visibility'] ?? 'public',
            teamId: $validated['team_id'] ?? null,
            tags: $validated['tags'] ?? null,
        );
    }
}

// Controller usage
public function store(StoreComponentRequest $request, CreateComponentAction $action): JsonResponse
{
    $dto = CreateComponentData::fromRequest($request->validated());
    $component = $action->execute($dto);

    return ComponentResource::make($component)
        ->response()
        ->setStatusCode(201);
}
```
