# 07.20 - Blade Component Architecture

**Project:** GsmUi
**Architecture:** Blade Anonymous + Class Component System
**Framework:** Laravel 13 + Livewire 4
**Version:** 1.0.0

---

# Purpose

GsmUi ships its UI as Blade components. Two flavors exist: anonymous components (single `.blade.php` file, no PHP class) and class components (a PHP class paired with a view). The `gsmui-pro` package registers an anonymous-component namespace, `gsmui:`, so any stub view under `stubs/resources/views/gsmui` becomes instantly usable as `<gsmui:button>` without a class. This document specifies how GsmUi authors, registers, and consumes Blade components, and when to choose each flavor.

The contract reuses the component engine concepts from `05.17-component-engine.md` (variant system, slots, theme tokens). Here we document the concrete PHP/Buildside mechanics: the service-provider registration, the `AnonymousComponent` resolution, the `AttributeBag`, and slot contracts. The Livewire interactive wrappers documented in `07.19-livewire-architecture.md` are consumed *through* these Blade components.

This file is implementation-only. It does not restate the conceptual rendering pipeline or the design-token model.

**Goals:**

- Document the `gsmui:` anonymous namespace and how `GsmuiProServiceProvider` registers it
- Define the decision rule for anonymous vs class components
- Standardize `AttributeBag` forwarding and slot contracts
- Specify how components wrap Livewire state (`wire:model`) and gsmui helpers
- Provide a copy-paste service-provider and component skeleton

> See also: `07.19-livewire-architecture.md` for the interactive wrapper; `05.17-component-engine.md` for variants/slots/tokens; the `gsmui-pro` package `src/GsmuiProServiceProvider.php` for the real registration code.

# 1. Component Flavor Overview

| Flavor | Definition | Use when |
| ------ | ---------- | -------- |
| Anonymous | Single `*.blade.php`, no class | Pure markup + slots, theme-aware styling, no logic |
| Class | PHP class + view | Needs computed props, hooks, `Illuminate\View\Component` logic |
| Livewire | Extends `Livewire\Component` | Needs interactivity / server state |

Gsmui-pro ships ~70 components as anonymous components under the `gsmui:` namespace; interactive ones pair the anonymous view with a Livewire class from the host app.

---

# 2. The `gsmui:` Anonymous Namespace

The service provider calls `Blade::anonymousComponentPath()` to bind a directory to a namespace prefix. This is the exact registration in `src/GsmuiProServiceProvider.php`:

```php id="bc01"
protected function bootComponentPath(): void
{
    Blade::anonymousComponentPath(
        __DIR__.'/../stubs/resources/views/gsmui',
        'gsmui'
    );
}
```

After boot, every `*.blade.php` file or subdirectory under that path is reachable as `<gsmui:name>`. Directory nesting becomes a path:

```text id="bc02"
stubs/resources/views/gsmui/
├── button/index.blade.php        →  <gsmui:button>
├── input/index.blade.php         →  <gsmui:input>
├── date-picker/
│   ├── index.blade.php           →  <gsmui:date-picker>
│   └── button.blade.php          →  <gsmui:date-picker.button>
└── modal/index.blade.php         →  <gsmui:modal>
```

The provider also `loadViewsFrom()` the same path under the `gsmui` name so class components and `@include`/`view()` can resolve `gsmui::button` equivalently.

# 3. Anonymous Component Anatomy

A minimal anonymous component is just Blade. Attributes and slots are available via `$attributes` and `$slot`.

```blade id="bc03"
{{-- stubs/resources/views/gsmui/badge/index.blade.php --}}
@props([
    'variant' => 'soft',
    'size' => 'md',
])

<span
    {{ $attributes
        ->class(gsmui_classes('badge', $variant, $size))
        ->merge(['class' => 'inline-flex items-center']) }}
>
    {{ $slot }}
</span>
```

Usage:

```blade id="bc04"
<gsmui:badge variant="success" size="sm" class="ml-2">Live</gsmui:badge>
```

Rules:

- `@props()` declares typed defaults; unknown attributes fall through `$attributes`.
- Always merge with `->merge()` so consumer `class` is preserved, then layer via `gsmui_classes()`.
- Never hard-code colors; call `gsmui_classes('badge', $variant, $size)` (helper in `src/helpers.php`).

# 4. Class Components

When logic is required, extend `Illuminate\View\Component`. The class resolves props; the view renders.

```php id="bc05"
namespace GsmuiPro\View\Components;

use Illuminate\View\Component;
use Illuminate\View\View;

class Badge extends Component
{
    public function __construct(
        public string $variant = 'soft',
        public string $size = 'md',
    ) {}

    public function classes(): string
    {
        return gsmui_classes('badge', $this->variant, $this->size);
    }

    public function render(): View
    {
        return view('gsmui::badge');
    }
}
```

Register the class component explicitly (class components are not auto-discovered by the anonymous path):

```php id="bc06"
use Illuminate\Support\Facades\Blade;

Blade::component(\GsmuiPro\View\Components\Badge::class, 'gsmui-badge');
```

Now `<gsmui-badge variant="success" />` and `<gsmui:badge>` can coexist; prefer the anonymous form for consistency unless logic demands a class.

# 5. Attribute Bag Contract

The `AttributeBag` is the contract for forwarding arbitrary HTML attributes. Gsmui components follow a strict merge order so consumer intent is never lost.

```php id="bc07"
{{-- Merge order: base → variant → consumer --}}
<span
    {{ $attributes
        ->merge(['class' => 'base'])
        ->class(gsmui_classes('input', $variant, $size)) }}
>
```

| Operation | Behavior |
| --------- | -------- |
| `merge()` | Sets defaults; consumer overrides |
| `class()` | Appends/merges utility classes (does not replace) |
| `except()` | Strip internal props before forwarding (`except('variant')`) |
| `whereStartsWith()` | Forward only `wire:`/`x-` prefixes |

Internal props (`variant`, `size`, `label`) MUST be stripped with `except()` so they are not rendered as invalid HTML attributes:

```blade id="bc08"
<button {{ $attributes->except(['variant', 'size'])->class(gsmui_classes('button', $variant, $size)) }}>
    {{ $slot }}
</button>
```

# 6. Slot Contracts

Gsmui uses default, named, and scoped slots consistently.

```blade id="bc09"
<x-gsm-card>
    <x-slot:header>
        <gsmui:badge variant="soft">New</gsmui:badge>
    </x-slot:header>

    {{ $slot }}

    <x-slot:footer>
        <gsmui:button variant="primary">Save</gsmui:button>
    </x-slot:footer>
</x-gsm-card>
```

Scoped slots pass data back to the consumer for lists:

```blade id="bc10"
<ul>
    {{ $slot->forEach($items, function ($item) {
        return '<li>'.e($item->name).'</li>';
    }) }}
</ul>
```

Slot rules:

- Default slot is required content; render `{{ $slot }}` exactly once.
- Named slots are optional; guard with `@isset($header)`.
- Never inject unescaped user content; rely on `{{ }}` auto-escaping.

# 7. Wrapping Livewire With Blade Components

Interactive gsmui components are consumed through the same `gsmui:` tag; `wire:` directives pass through via the attribute bag.

```blade id="bc11"
<gsmui:input
    wire:model.live="search"
    variant="outline"
    placeholder="{{ __('Search components') }}"
/>
```

The anonymous view forwards `wire:*` untouched:

```blade id="bc12"
<input
    {{ $attributes->except(['variant','size'])->class(gsmui_classes('input', $variant, $size)) }}
/>
```

This keeps the conceptual Livewire component (`07.19`) decoupled from styling; the Blade layer owns markup, the Livewire layer owns state.

# 8. Service Provider Registration Skeleton

A host app (or the gsmui-pro package) registers everything in one provider. Reference implementation:

```php id="bc13"
namespace GsmuiPro;

use Illuminate\Support\ServiceProvider;
use Illuminate\Support\Facades\Blade;

class GsmuiProServiceProvider extends ServiceProvider
{
    public function register(): void
    {
        $this->app->singleton(GsmuiProManager::class, fn () => new GsmuiProManager());
        $this->app->alias(GsmuiProManager::class, 'gsmui-pro');

        $this->mergeConfigFrom(
            __DIR__.'/../stubs/config/gsmui-pro.php', 'gsmui-pro'
        );
    }

    public function boot(): void
    {
        // 1. Anonymous namespace (gsmui:)
        Blade::anonymousComponentPath(
            __DIR__.'/../stubs/resources/views/gsmui', 'gsmui'
        );

        // 2. Class components (explicit)
        Blade::component(\GsmuiPro\View\Components\Badge::class, 'gsmui-badge');

        // 3. Views for @include / view()
        $this->loadViewsFrom(
            __DIR__.'/../stubs/resources/views/gsmui', 'gsmui'
        );

        // 4. Publishable config + views
        $this->publishes([
            __DIR__.'/../stubs/config/gsmui-pro.php' => config_path('gsmui-pro.php'),
        ], 'gsmui-pro-config');
    }
}
```

Publish views for downstream override:

```php id="bc14"
$this->publishes([
    __DIR__.'/../stubs/resources/views/gsmui' => resource_path('views/vendor/gsmui'),
], 'gsmui-pro-views');
```

# 9. Decision Matrix

| Need | Choose |
| ---- | ------ |
| Static markup + slots | Anonymous component |
| Theme/variant-only styling | Anonymous component |
| Computed props / conditionals on data | Class component |
| Server state / interactivity | Livewire class + anonymous view |
| Reusable across apps with logic | Class component registered explicitly |

When in doubt, start anonymous. Promote to a class only when view logic becomes non-trivial.

---

# 10. Security Contract

- Escape by default: `{{ }}` auto-escapes; use `{!! !!}` only after explicit sanitization.
- Strip internal props via `except()` so they are not emitted as DOM attributes.
- Validate dynamic attribute URLs (href/src) to avoid `javascript:` injection.
- CSP-safe: gsmui views emit no inline scripts; styles come from `dist/` (see `GsmuiProServiceProvider` + `CspMiddleware`).
- Arbitrary HTML slots require sanitization before render.

---

# 11. Testing Contract

Anonymous components are tested by rendering and asserting markup:

```php id="bc15"
public function test_badge_renders_variant_class(): void
{
    $view = $this->blade('<gsmui:badge variant="success">OK</gsmui:badge>');

    $view->assertSee('gsmui-badge-success');
    $view->assertSee('OK');
}
```

Class components additionally test `render()` output and prop resolution. Every component requires a render + slot + variant test (per `05.17-component-engine.md`).

# Summary

Gsmui Blade components are registered through `Blade::anonymousComponentPath()` under the `gsmui:` namespace, with class components added explicitly for logic-heavy cases. The `AttributeBag` merge contract preserves consumer classes while layering variant/size styling via `gsmui_classes()`, and slot contracts keep markup composable. Interactive behavior is layered on top via pass-through `wire:` directives, keeping presentation and state cleanly separated.

# 12. Component Composition Patterns

## 12.1 Headless Components

Headless components provide behavior without markup. They wrap stateful logic and expose it via slots:

```blade
{{-- stubs/resources/views/gsmui/combobox/index.blade.php --}}
@props(['options' => [], 'model' => null, 'searchable' => false])

<x-gsmui::headless-listbox :options="$options" :model="$model" :searchable="$searchable">
    <x-slot:trigger>
        {{ $trigger ?? $slot }}
    </x-slot:trigger>

    <x-slot:options>
        {{ $options }}
    </x-slot:options>
</x-gsmui::headless-listbox>
```

Usage:

```blade
<gsmui:combobox :options="$themes" model="selectedTheme" searchable>
    <x-slot:trigger>
        <gsmui:input type="button" :value="$selectedTheme->name ?? 'Select theme'" />
    </x-slot:trigger>
</gsmui:combobox>
```

## 12.2 Renderless Components

Components that compute state but delegate rendering entirely to slots:

```php
class ThemeDataProvider extends Component
{
    public string $themeSlug;

    public function __construct(public string $slug)
    {
        $this->themeSlug = $slug;
    }

    public function render(): View
    {
        return app('view')->make('gsmui::theme-data-provider', [
            'theme' => Theme::where('slug', $this->themeSlug)->firstOrFail(),
        ]);
    }
}
```

```blade
<gsmui:theme-data-provider slug="midnight">
    <x-slot:default="{ theme }">
        <div class="theme-preview" style="--bg: {{ theme.bg_color }}">
            {{ theme.name }}
        </div>
    </x-slot:default>
</gsmui:theme-data-provider>
```

## 12.3 Compound Components

Compound components share state through context. The parent provides context, children consume it:

```blade
{{-- tabs/index.blade.php --}}
@props(['activeTab' => null])

<div {{ $attributes }}>
    {{ $slot }}
</div>

{{-- tabs/tab.blade.php --}}
@props(['id' => null, 'label' => ''])

<button
    {{ $attributes->class([
        'tab-button',
        'active' => $activeTab === $id,
    ]) }}
>
    {{ $label }}
</button>
```

```blade
<gsmui:tabs active-tab="general">
    <gsmui:tabs:tab id="general" label="General">General content</gsmui:tabs:tab>
    <gsmui:tabs:tab id="security" label="Security">Security content</gsmui:tabs:tab>
</gsmui:tabs>
```

## 12.4 Wrapper Components

Wrapper components add behavior around content without modifying the content itself:

```blade
{{-- tooltip/index.blade.php --}}
@props(['content' => '', 'position' => 'top'])

<span
    {{ $attributes->merge(['class' => 'relative group']) }}
    x-data="{ show: false }"
    x-on:mouseenter="show = true"
    x-on:mouseleave="show = false"
>
    {{ $slot }}

    <span
        x-show="show"
        x-transition
        class="absolute z-50 px-2 py-1 text-xs bg-zinc-900 text-white rounded
               @if($position === 'top') bottom-full left-1/2 -translate-x-1/2 mb-2 @endif
               @if($position === 'bottom') top-full left-1/2 -translate-x-1/2 mt-2 @endif
               @if($position === 'left') right-full top-1/2 -translate-y-1/2 mr-2 @endif
               @if($position === 'left') left-full top-1/2 -translate-y-1/2 ml-2 @endif"
    >
        {{ $content }}
    </span>
</span>
```

## 12.5 Polymorphic Components

Components that adapt their rendering based on the `as` prop:

```blade
{{-- button/index.blade.php --}}
@props([
    'as' => 'button',
    'variant' => 'primary',
    'size' => 'md',
])

@if($as === 'a')
    <a {{ $attributes->class(gsmui_classes('button', $variant, $size)) }}>
        {{ $slot }}
    </a>
@elseif($as === 'div')
    <div {{ $attributes->class(gsmui_classes('button', $variant, $size)) }} role="button" tabindex="0">
        {{ $slot }}
    </div>
@else
    <button {{ $attributes->class(gsmui_classes('button', $variant, $size)) }}>
        {{ $slot }}
    </button>
@endif
```

# 13. Advanced Slot Patterns

## 13.1 Scoped Slots with Data

Pass computed data back to the consumer:

```blade
{{-- data-table/index.blade.php --}}
@props(['columns' => [], 'rows' => []])

<table>
    <thead>
        <tr>
            @foreach($columns as $col)
                <th>{{ $col['label'] }}</th>
            @endforeach
        </tr>
    </thead>
    <tbody>
        @foreach($rows as $row)
            <tr>
                @foreach($columns as $col)
                    <td>
                        {{ $slot->row($row, $col['key']) }}
                    </td>
                @endforeach
            </tr>
        @endforeach
    </tbody>
</table>
```

```blade
<gsmui:data-table :columns="$columns" :rows="$rows">
    <x-slot:row="{ row, key }">
        {{ data_get($row, $key) }}
    </x-slot:row>
</gsmui:data-table>
```

## 13.2 Conditional Slot Rendering

Only render slots when they are provided:

```blade
@section('header')
    @isset($header)
        <div class="component-header">
            {{ $header }}
        </div>
    @endisset
@endsection

@section('body')
    <div class="component-body">
        {{ $slot }}
    </div>
@endsection

@section('footer')
    @isset($footer)
        <div class="component-footer">
            {{ $footer }}
        </div>
    @endisset
@endsection
```

## 13.3 Slot Loops

Iterate over slot content efficiently:

```blade
<ul>
    @foreach($items as $index => $item)
        <li wire:key="item-{{ $index }}">
            {{ $slot->item($item, $index) }}
        </li>
    @endforeach
</ul>
```

## 13.4 Fragment Slots

Multiple root elements from a single slot:

```blade
<x-slot:head>
    <meta name="description" content="..." />
    <title>Page Title</title>
</x-slot:head>

<x-slot:default>
    <header>...</header>
    <main>{{ $slot }}</main>
    <footer>...</footer>
</x-slot:default>
```

# 14. Dynamic Component Loading

## 14.1 Dynamic Tag Resolution

Resolve component names at runtime:

```blade
@php
    $componentType = match($block->type) {
        'text' => 'gsmui:text-block',
        'image' => 'gsmui:image-block',
        'video' => 'gsmui:video-block',
        'code' => 'gsmui:code-block',
        default => 'gsmui:text-block',
    };
@endphp

<x-dynamic-component :component="$componentType" :data="$block" />
```

## 14.2 Conditional Component Loading

Choose component variant based on context:

```blade
@if($variant === 'card')
    <x-gsmui:card {{ $attributes->merge(['class' => 'component-card']) }}>
        {{ $slot }}
    </x-gsmui:card>
@elseif($variant === 'inline')
    <x-gsmui:inline {{ $attributes }}>
        {{ $slot }}
    </x-gsmui:inline>
@else
    <div {{ $attributes }}>
        {{ $slot }}
    </div>
@endif
```

## 14.3 Component Factories

Use a factory to create component instances dynamically:

```php
final class ComponentFactory
{
    private const MAP = [
        'button' => 'gsmui::button',
        'input' => 'gsmui::input',
        'select' => 'gsmui::select',
        'modal' => 'gsmui::modal',
    ];

    public static function make(string $type, array $props = []): \Illuminate\View\ComponentView
    {
        $view = self::MAP[$type] ?? throw new InvalidArgumentException("Unknown component: {$type}");

        return view($view, $props);
    }
}
```

# 15. Component Inheritance and Extends

## 15.1 View Inheritance

Use `@extends` for component layouts:

```blade
{{-- base-component.blade.php --}}
<div class="base-component">
    @section('header')
        <div class="default-header">{{ $title ?? 'Default Title' }}</div>
    @show

    <div class="component-body">
        {{ $slot }}
    </div>

    @hasSection('footer')
        <div class="component-footer">
            @yield('footer')
        </div>
    @endif
</div>
```

```blade
{{-- extended-component.blade.php --}}
@extends('gsmui::base-component')

@section('header')
    <div class="custom-header">{{ $title }}</div>
@endsection

@section('footer')
    <gsmui:button variant="primary" wire:click="save">Save</gsmui:button>
@endsection
```

## 15.2 Component Stacking

Layer components to build complex UIs from simple pieces:

```blade
<x-gsmui:card>
    <x-slot:header>
        <x-gsmui:heading level="3">Theme Settings</x-gsmui:heading>
    </x-slot:header>

    <x-gsmui:form wire:submit="save">
        <x-gsmui:input wire:model="theme.name" label="Theme Name" />
        <x-gsmui:textarea wire:model="theme.description" label="Description" />

        <x-slot:footer>
            <x-gsmui:button variant="secondary" wire:click="cancel">Cancel</x-gsmui:button>
            <x-gsmui:button variant="primary" type="submit">Save</x-gsmui:button>
        </x-slot:footer>
    </x-gsmui:form>
</x-gsmui:card>
```

## 15.3 Mixin Pattern

Share behavior across components via PHP traits:

```php
trait HasVariants
{
    public string $variant = 'default';

    public function variantClasses(): string
    {
        return gsmui_classes(static::COMPONENT_NAME, $this->variant);
    }
}

class Alert extends Component
{
    use HasVariants;

    const COMPONENT_NAME = 'alert';

    public string $message = '';
}
```

# 16. Component Rendering Optimization

## 16.1 Lazy Rendering

Defer rendering of expensive components:

```blade
<x-gsmui:chart lazy wire:model="chartData" />
```

The `lazy` attribute defers the initial render until the component is in the viewport.

## 16.2 Memoization

Cache expensive computations within component views:

```blade
@php
    $stats = cache()->remember("stats:{$user->id}", 60, function () use ($user) {
        return [
            'components' => $user->components()->count(),
            'downloads' => $user->components()->sum('downloads'),
        ];
    });
@endphp

<div class="stats">
    Components: {{ $stats['components'] }}
    Downloads: {{ number_format($stats['downloads']) }}
</div>
```

## 16.3 Partial Rendering

Render only changed sections with Livewire:

```blade
<div wire:ignore.self id="chart-container">
    <canvas wire:model.debounce.500ms="chartData"></canvas>
</div>
```

## 16.4 Output Buffering

Use output buffering for components that generate HTML dynamically:

```php
public function render(): View
{
    ob_start();
    // complex rendering logic
    $html = ob_get_clean();

    return view('gsmui::complex-component', ['html' => $html]);
}
```

# 17. Custom Blade Directives

## 17.1 Registering Custom Directives

Extend Blade with domain-specific directives:

```php
// In a service provider
Blade::directive('gsmuiicon', function (string $expression) {
    return "<?php echo app('gsmui.icons')->render({$expression}); ?>";
});

Blade::directive('gsmuidate', function (string $expression) {
    return "<?php echo \\Carbon\\Carbon::parse({$expression})->locale(app()->getLocale())->isoFormat('LL'); ?>";
});
```

Usage:

```blade
<gsmui:icon name="{{ @gsmuiicon('check') }}" />
<span>{{ @gsmuidate($theme->created_at) }}</span>
```

## 17.2 Custom Component Attributes

Register custom attribute casters for component props:

```php
// In a component class
public function __construct(
    #[CastAttribute(CarbonImmutable::class)]
    public ?CarbonImmutable $startDate = null,

    #[CastAttribute(Enum::class, ThemeStatus::class)]
    public string $status = 'active',
) {}
```

## 17.3 Anonymous Component With Code

Anonymous components can include PHP code blocks at the top:

```blade
@php
    $computedValue = $items->pluck('value')->sum();
    $average = $items->count() > 0 ? $computedValue / $items->count() : 0;
@endphp

<div class="summary">
    Total: {{ number_format($computedValue) }}
    Average: {{ number_format($average, 2) }}
</div>
```

# 18. Component Testing Patterns

## 18.1 Snapshot Testing

Capture rendered output and compare across versions:

```php
test('button renders with variant classes', function (): void {
    $view = $this->blade('<gsmui:button variant="primary">Click</gsmui:button>');

    $view->assertSee('gsmui-button');
    $view->assertSee('primary');
    $view->assertSee('Click');
});
```

## 18.2 Attribute Forwarding Tests

Verify that attributes are properly forwarded:

```php
test('button forwards data attributes', function (): void {
    $view = $this->blade('<gsmui:button data-testid="submit">Submit</gsmui:button>');

    $view->assertSee('data-testid="submit"');
});
```

## 18.3 Slot Rendering Tests

Test that slots render correctly:

```php
test('card renders header slot', function (): void {
    $view = $this->blade('
        <x-gsm-card>
            <x-slot:header>My Header</x-slot:header>
            Body content
        </x-gsm-card>
    ');

    $view->assertSee('My Header');
    $view->assertSee('Body content');
});
```

## 18.4 Accessibility Testing

Verify ARIA attributes and roles:

```php
test('modal has correct aria attributes', function (): void {
    $view = $this->blade('<gsmui:modal open>Content</gsmui:modal>');

    $view->assertSee('role="dialog"');
    $view->assertSee('aria-modal="true"');
    $view->assertSee('aria-labelledby');
});
```

## 18.5 Responsive Testing

Test component rendering at different breakpoints:

```php
test('button uses correct size at mobile', function (): void {
    $view = $this->blade('<gsmui:button size="sm">Small</gsmui:button>');

    $view->assertSee('h-8');  // sm size
    $view->assertSee('text-sm');
});
```

# 19. Accessibility Guidelines

## 19.1 ARIA Patterns

Follow ARIA Authoring Practices for complex components:

```blade
{{-- accordion/index.blade.php --}}
<div role="region" aria-label="{{ $label }}">
    @foreach($items as $item)
```

# 22. Component Security Best Practices

## 22.1 Escaping Strategy

All Blade output is auto-escaped by default. Explicitly bypass escaping only after sanitization:

```blade
{{-- Safe: auto-escaped --}}
{{ $userInput }}

{{-- Unsafe: raw output --}}
{!! $userInput !!}

{{-- Safe: sanitized HTML --}}
{!! clean($userInput) !!}
```

## 22.2 Attribute Injection Prevention

Strip internal props before forwarding to prevent attribute injection:

```blade
<button {{ $attributes->except(['variant', 'size', 'label', 'icon'])
    ->class(gsmui_classes('button', $variant, $size))
    ->merge(['type' => 'button']) }}
>
    {{ $slot }}
</button>
```

## 22.3 URL Validation

Validate URLs in href and src attributes to prevent javascript: injection:

```php
// In a component class
public function validatedUrl(string $url): string
{
    $parsed = parse_url($url);

    if ($parsed['scheme'] === 'javascript') {
        throw new InvalidArgumentException('JavaScript URLs are not allowed.');
    }

    return $url;
}
```

## 22.4 CSP Considerations

All gsmui components must work within the CSP policy. Never emit inline scripts:

```blade
{{-- Safe: event handlers via Livewire/Alpine --}}
<button wire:click="save">Save</button>

{{-- Unsafe: inline onclick --}}
<button onclick="save()">Save</button>
```

## 22.5 CSRF in Forms

Always include CSRF tokens in forms:

```blade
<form method="POST" action="/submit">
    @csrf
    <gsmui:button type="submit">Submit</gsmui:button>
</form>
```

Livewire components automatically include CSRF tokens.

```php
final class ComponentDocGenerator
{
    public function generate(string $componentClass): array
    {
        $reflection = new ReflectionClass($componentClass);
        $constructor = $reflection->getConstructor();

        $props = [];
        foreach ($constructor->getParameters() as $param) {
            $props[] = [

                'required' => !$param->isOptional(),
            ];
        }

        return $props;
    }
}
```

# 25. Component Migration Guide

## 25.1 Migrating from Blade Components to Livewire

When upgrading a static component to Livewire:

1. Create a Livewire component class.
2. Move state to public properties.
3. Move actions to public methods.
4. Update the Blade view to use `wire:` directives.
5. Test state transitions and events.

## 25.2 Migrating from Livewire to Blade

When simplifying a Livewire component to Blade:

1. Remove the Livewire component class.
2. Move state to props or parent component.
3. Remove `wire:` directives.
4. Use Alpine.js for interactivity if needed.
5. Update the parent component to pass data as props.

## 25.3 Version Upgrade Checklist

When upgrading the gsmui package:

1. Run `php artisan view:clear` to clear compiled views.
2. Check for deprecated component APIs in the changelog.
3. Update any published views to match new signatures.
4. Run the component test suite.
5. Verify visual rendering in the browser.

# 35. Summary

Gsmui Blade components are registered through `Blade::anonymousComponentPath()` under the `gsmui:` namespace, with class components added explicitly for logic-heavy cases. The `AttributeBag` merge contract preserves consumer classes while layering variant/size styling via `gsmui_classes()`, and slot contracts keep markup composable. Interactive behavior is layered on top via pass-through `wire:` directives, keeping presentation and state cleanly separated.

The component system supports headless components, compound patterns, polymorphic rendering, dynamic loading, and comprehensive accessibility. Performance is managed through lazy rendering, caching, and DOM size budgets. Security is enforced through auto-escaping, attribute stripping, and URL validation. All components follow a consistent design token system for spacing, color, typography, and animation.

# 37. Common Pitfalls

| Pitfall | Solution |
|---------|----------|
| Internal props rendered as HTML attributes | Use `except()` to strip them |
| Consumer classes overwritten | Use `class()` not `merge()` for appending |
| Missing `wire:key` in loops | Add unique key to prevent DOM recycling |
| Inline `onclick` violating CSP | Use `wire:click` or Alpine `x-on:` |
| `wire:model.live` on all inputs | Use `.blur` for non-real-time fields |
| Missing `@csrf` in forms | Always include CSRF token |
| Hardcoded colors | Use CSS custom properties from design tokens |
| Missing `aria-label` on icon buttons | Always add accessible labels |
| `@include` breaking component encapsulation | Use slots instead |
| Calling `env()` outside config | Use `config()` helper |
| Missing translation in component | Wrap strings in `__()` |
| Forgetting dark mode variants | Include `dark:` classes where needed |
