# 10.12 — Component Permissions

**Project:** GsmUi
**Domain:** Authorization & RBAC
**Version:** 1.0.0

---

## Purpose

This document defines the complete authorization rules for the **Component domain** in GsmUi. Components are reusable UI building blocks — buttons, inputs, modals, sliders, date-pickers, and the like — that creators build, publish to the marketplace, and that users install into their projects. This specification governs who can create, edit, publish, fork, bundle, and delete components, and enforces ownership, moderation workflows, and component-to-theme relationships.

Components are the atomic building blocks of the GsmUi ecosystem. They interact with the [Theme domain](./10.11-theme-permissions.md), the [Marketplace domain](./10.10-marketplace-permissions.md), and the [Template domain](./10.13-template-permissions.md).

## Scope

Component permissions apply to:

* Component creation and editing (source, metadata, docs)
* Component publishing and approval workflow
* Component forking (creating derivative works)
* Component bundling into themes
* Component variant management
* Component deletion and archival
* Component marketplace listing interactions
* Component asset management (previews, screenshots, source files)

## Component Lifecycle States

```text
draft
  ↓ (submit for review)
pending_review
  ↓ (approve)
published
  ↓ (feature)
featured

pending_review
  ↓ (reject)
rejected
  ↓ (owner edits & resubmits)
pending_review

published
  ↓ (unpublish)
unpublished
  ↓ (resubmit)
pending_review
```

### State Transition Matrix

| From State | To State | Trigger | Permission Required |
|---|---|---|---|
| `draft` | `pending_review` | Owner submits | `components.publish` (own) |
| `pending_review` | `published` | Moderator approves | `components.publish` (moderator+) |
| `pending_review` | `rejected` | Moderator rejects | `components.publish` (moderator+) |
| `pending_review` | `draft` | Owner withdraws | `components.update` (own) |
| `rejected` | `pending_review` | Owner resubmits | `components.publish` (own) |
| `published` | `featured` | Admin features | `components.feature` (admin+) |
| `featured` | `published` | Admin unfeatures | `components.feature` (admin+) |
| `published` | `unpublished` | Owner/admin unpublishes | `components.unpublish` (own or admin) |
| `unpublished` | `pending_review` | Owner resubmits | `components.publish` (own) |
| Any | `draft` | Owner deletes | `components.delete` (own) |

## Component Ownership

### Creator Ownership

A component's `user_id` field determines ownership. Ownership grants:

* Full edit rights while in `draft` or `rejected` state
* Ability to submit for review
* Ability to withdraw from review
* Ability to unpublish a published component
* Revenue share from marketplace sales (see [10.10-marketplace-permissions.md](./10.10-marketplace-permissions.md))

### Ownership Transfer

Same scenarios as themes — gift, acquisition, account merger, succession. See [10.11-theme-permissions.md](./10.11-theme-permissions.md) for the full ownership transfer protocol.

### Fork Ownership

When a component is forked:

* The forked copy belongs to the forker (new `user_id`)
* The original component's `forked_from_id` field references the source
* The original creator retains ownership of the original
* Forks must carry attribution metadata
* Forks are independent — changes to the fork do not affect the original

```php
// Forking creates a new component under the forker's ownership
$fork = $original->replicate();
$fork->user_id = auth()->id();
$fork->forked_from_id = $original->id;
$fork->status = 'draft';
$fork->name = $original->name . ' (Fork)';
$fork->save();

activity()
    ->performedOn($fork)
    ->withProperties([
        'original_id' => $original->id,
        'original_user_id' => $original->user_id,
    ])
    ->event('component.forked')
    ->log('Component forked');
```

## Component vs Theme Distinction

| Aspect | Component | Theme |
|---|---|---|
| Scope | Single UI element (button, input, etc.) | Complete visual skin (colors, typography, layout) |
| Complexity | Low — focused on one element | High — complex multi-element system |
| Dependency | Can be standalone or part of a theme | Composed of multiple components |
| Namespace | `components.*` | `themes.*` |
| Can be bundled | No (it IS a building block) | Yes (receives bundled components) |
| Forking | Allowed (creates derivative) | Allowed (creates derivative) |
| Marketplace | Sold individually | Sold as complete packages |

## Component Bundle Authorization

A component can be bundled into a theme. This requires ownership of both resources:

```php
public function bundle(User $user, Component $component, Theme $theme): bool
{
    // Must own both the component and the theme
    if ($user->id !== $component->user_id) {
        return false;
    }

    if ($user->id !== $theme->user_id) {
        return false;
    }

    // Both must be in a bundleable state
    if ($component->status !== 'published') {
        return false;
    }

    if (! in_array($theme->status, ['draft', 'rejected'])) {
        return false;
    }

    return true;
}
```

### Bundle Constraints

* Only published components can be bundled
* Only draft/rejected themes can receive bundles
* A theme cannot bundle components from different owners without admin approval
* Bundled components retain their own licensing and attribution
* Removing a bundled component from a theme does not delete it

## Component Variant Permissions

Components can have variants (e.g., `button-primary`, `button-outline`, `button-ghost`). Variants inherit the parent component's permissions:

```php

    public function delete(User $user, ComponentVariant $variant): bool
```

## Policy Implementation

```php
<?php

namespace App\Policies;

use App\Models\User;
use App\Models\Component;
use Illuminate\Auth\Access\HandlesAuthorization;

class ComponentPolicy
{
    use HandlesAuthorization;

    /**
     * Determine whether the user can view any components.
     * Public browsing.
     */
    public function viewAny(User $user): bool
    {
        return true;
    }

    /**
     * Determine whether the user can view the component.
     * Published components are public.
     * Draft/rejected components are owner/admin only.
     */
    public function view(User $user, Component $component): bool
    {
        if (in_array($component->status, ['published', 'featured'])) {
            return true;
        }

        if ($component->status === 'pending_review') {
            return $user->id === $component->user_id
                || $user->hasRole(['moderator', 'admin', 'super_admin']);
        }

        return $user->id === $component->user_id
            || $user->hasRole(['admin', 'super_admin']);
    }

    /**
     * Determine whether the user can create components.
     * Requires 'creator' or 'admin' role.
     */
    public function create(User $user): bool
    {
        return $user->hasRole(['creator', 'admin', 'super_admin']);
    }

    /**
     * Determine whether the user can update the component.
     * Only owner, only in draft/rejected state.
     */
    public function update(User $user, Component $component): bool
    {
        if (! in_array($component->status, ['draft', 'rejected'])) {
            return false;
        }

        return $user->id === $component->user_id;
    }

    /**
     * Determine whether the user can delete the component.
     * Owner or admin.
     */
    public function delete(User $user, Component $component): bool
    {
        if ($user->hasRole(['admin', 'super_admin'])) {
            return true;
        }

        return $user->id === $component->user_id;
    }

    /**
     * Determine whether the user can publish/submit for review.
     */
    public function publish(User $user, Component $component): bool
    {
        if ($user->hasRole(['admin', 'super_admin'])) {
            return true;
        }

        if ($user->hasRole('moderator') && $component->status === 'pending_review') {
            return true;
        }

        return $user->id === $component->user_id
            && in_array($component->status, ['draft', 'rejected']);
    }

    /**
     * Determine whether the user can unpublish the component.
     */
    public function unpublish(User $user, Component $component): bool
    {
        if (! in_array($component->status, ['published', 'featured'])) {
            return false;
        }

        if ($user->hasRole(['admin', 'super_admin'])) {
            return true;
        }

        return $user->id === $component->user_id;
    }

    /**
     * Determine whether the user can feature the component.
     */
    public function feature(User $user, Component $component): bool
    {
        if ($component->status !== 'published') {
            return false;
        }

        return $user->hasRole(['admin', 'super_admin']);
    }

    /**
     * Determine whether the user can fork the component.
     * All authenticated users can fork published components.
     */
    public function fork(User $user, Component $component): bool
    {
        if (! in_array($component->status, ['published', 'featured'])) {
            return false;
        }

        // Cannot fork your own component (create a new one instead)
        if ($user->id === $component->user_id) {
            return false;
        }

        return true;
    }

    /**
     * Determine whether the user can bundle the component into a theme.
     * Must own both component and theme.
     */
    public function bundle(User $user, Component $component, $theme = null): bool
    {
        if ($theme === null) {
            return false;
        }

        if ($user->hasRole(['admin', 'super_admin'])) {
            return true;
        }

        return $user->id === $component->user_id
            && $user->id === $theme->user_id
            && $component->status === 'published'
            && in_array($theme->status, ['draft', 'rejected']);
    }

    /**
     * Determine whether the user can view analytics.
     */
    public function viewAnalytics(User $user, Component $component): bool
    {
        if ($user->hasRole(['admin', 'super_admin'])) {
            return true;
        }

        return $user->id === $component->user_id;
    }

    /**
     * Determine whether the user can manage versions.
     */
    public function manageVersions(User $user, Component $component): bool
    {
        if ($user->hasRole(['admin', 'super_admin'])) {
            return true;
        }

        return $user->id === $component->user_id;
    }
}
```

## Controller Integration

```php
<?php

namespace App\Http\Controllers;

use App\Models\Component;
use Illuminate\Http\Request;

class ComponentController extends Controller
{
    public function __construct()
    {
        $this->authorizeResource(Component::class, 'component');
    }

    public function index()
    {
        // viewAny — public marketplace browsing
    }

    public function store(Request $request)
    {
        // create — requires 'creator' or 'admin' role

        $component = Component::create([
            'user_id' => auth()->id(),
            'name' => $request->name,
            'slug' => $request->slug,
            'description' => $request->description,
            'status' => 'draft',
        ]);

        return redirect()->route('components.edit', $component);
    }

    public function update(Request $request, Component $component)
    {
        // update — owner only, draft/rejected state only

        $component->update($request->validated());

        return back()->with('success', 'Component updated.');
    }

    public function fork(Component $component)
    {
        $this->authorize('fork', $component);

        $fork = $component->replicate();
        $fork->user_id = auth()->id();
        $fork->forked_from_id = $component->id;
        $fork->status = 'draft';
        $fork->name = $component->name . ' (Fork)';
        $fork->save();

        return redirect()->route('components.edit', $fork);
    }

    public function destroy(Component $component)
    {
        $this->authorize('delete', $component);

        $component->delete();

        return redirect()->route('components.index');
    }
}
```

## Component Asset Management

Component assets include source files, preview screenshots, documentation, and compiled bundles. Access rules mirror the component's lifecycle state.

### Asset Types and Access Rules

| Asset Type | Visibility | Max Size | Allowed Formats |
|---|---|---|---|
| Source files | Owner + Admin | 10MB total | JS, TS, CSS, SCSS, Blade |

| Compiled bundle | Owner + Admin | 5MB | JS, CSS |
| Documentation | Public (published) | N/A | Markdown |
| Demo HTML | Public (published) | 1MB | HTML |

## Component Search Authorization

Component search is public-facing with result filtering based on user role and ownership.

### Search Permission Matrix

| Search Scope | Guest | User | Pro User | Creator | Admin |
|---|---|---|---|---|---|
| Published components | ✅ | ✅ | ✅ | ✅ | ✅ |
| Draft components | ❌ | ❌ | ❌ | ❌ | ✅ |
| Pending review components | ❌ | ❌ | ❌ | ❌ | ✅ |
| Rejected components | ❌ | ❌ | ❌ | ❌ | ✅ |
| Revenue data | ❌ | ❌ | ❌ | ✅ (own) | ✅ |

### Search Service

```php
class ComponentSearchService
{
    public function search(string $query, User $user = null): Collection
    {
        $builder = Component::query()
            ->where('status', 'in', ['published', 'featured']);

        if ($user && $user->hasRole(['admin', 'super_admin'])) {
            $builder = Component::query();
        }

        return $builder
            ->where(function ($q) use ($query) {
                $q->where('name', 'LIKE', "%{$query}%")
                  ->orWhere('description', 'LIKE', "%{$query}%")
                  ->orWhere('tags', 'LIKE', "%{$query}%");
            })
            ->orderBy('featured', 'desc')
            ->orderBy('name')
            ->get();
    }
}
```

### ACL Resolution

```php
class ComponentAclResolver
{
    public function resolve(User $user, Component $component, string $permission): bool
    {
        if ($user->can($permission, $component)) {
            return true;
        }

        $acl = ComponentAcl::where('component_id', $component->id)
            ->where('user_id', $user->id)
            ->where('permission', $permission)
            ->where(function ($q) {
                $q->whereNull('expires_at')
                  ->orWhere('expires_at', '>', now());
            })
            ->first();

        return $acl !== null;
    }
}
```

## Component Versioning Migration

When upgrading between major versions, a migration path must be provided:

| Migration Step | Permission Required | Validation |
|---|---|---|
| Create migration script | components.manage-versions | Script validated before execution |
| Back up current version | components.view | Backup stored in secure location |
| Execute migration | components.update | Atomic transaction rollback on failure |
| Verify migration | components.view | Automated tests pass on new version |
| Notify theme owners | components.view | All dependent theme owners notified |
| Rollback if needed | components.update | Previous version restored within 24h |

## Bundle Dependency Resolution

When creating bundles, dependency resolution follows strict rules:

```sql
CREATE TABLE component_bundle_dependencies (
    id BIGINT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
    bundle_id BIGINT UNSIGNED NOT NULL,
    component_id BIGINT UNSIGNED NOT NULL,
    min_version VARCHAR(20) NOT NULL,
    max_version VARCHAR(20) NULL,
    is_optional BOOLEAN DEFAULT FALSE,
    conflict_component_id BIGINT UNSIGNED NULL,
    conflict_reason TEXT NULL,
    created_at TIMESTAMP NULL,
    updated_at TIMESTAMP NULL,
    FOREIGN KEY (bundle_id) REFERENCES component_bundles(id) ON DELETE CASCADE,
    FOREIGN KEY (component_id) REFERENCES components(id) ON DELETE CASCADE,
    UNIQUE KEY unique_bundle_component (bundle_id, component_id)
);
```

| Dependency Rule | Enforcement | Error Code |
|---|---|---|
| Circular dependency detected | Reject bundle creation | `DEPENDENCY_CYCLE` |
| Missing required dependency | Block publication | `MISSING_DEPENDENCY` |
| Version conflict | Warn before publication | `VERSION_CONFLICT` |
| Optional dependency missing | Allow with warning | `OPTIONAL_MISSING` |
| Dependency ownership mismatch | Require both owners consent | `OWNERSHIP_CONFLICT` |
