# 10.06 - Gates

**Project:** GsmUi
**Domain:** Authorization & RBAC
**Version:** 1.0.0

---

## Purpose

Gates provide **ad-hoc authorization checks** for non-resource operations. Unlike [policies](./10.05-policies.md) (which are tied to a model instance), gates are callable closures registered in `AuthServiceProvider`. They answer the question: *"Can this user perform this action?"* without requiring a specific model.

Gates are the correct abstraction when:

* The operation does not map to a single Eloquent model (e.g., viewing the admin panel).
* The check combines role, subscription, quota, and environment conditions.
* The authorization logic is used in controllers, Blade templates, Livewire components, and routes interchangeably.

## Gate Registration

All gates are registered in `AuthServiceProvider::boot()` using `Gate::define()`. The provider must be published and maintained as the single source of truth for gate definitions.

```php
// app/Providers/AuthServiceProvider.php

namespace App\Providers;

use Illuminate\Foundation\Support\Providers\AuthServiceProvider as ServiceProvider;
use Illuminate\Support\Facades\Gate;
use App\Models\User;

class AuthServiceProvider extends ServiceProvider
{
    protected $policies = [
        // Policies registered here — see 10.05-policies.md
    ];

    public function boot(): void
    {
        $this->registerPolicies();
        $this->registerPlatformGates();
        $this->registerContentGates();
        $this->registerSystemGates();
        $this->registerMarketplaceGates();
        $this->registerBillingGates();

        // Super admin bypass — see Super Admin Override below
        Gate::before(function (User $user, string $ability) {
            if ($user->hasRole('super_admin')) {
                return true;
            }
        });
    }

    protected function registerPlatformGates(): void
    {
        // Platform gates defined below
    }

    protected function registerContentGates(): void
    {
        // Content gates defined below
    }

    protected function registerSystemGates(): void
    {
        // System gates defined below
    }

    protected function registerMarketplaceGates(): void
    {
        // Marketplace gates defined below
    }

    protected function registerBillingGates(): void
    {
        // Billing gates defined below
    }
}
```

## Platform Gates

Platform gates control access to top-level sections of the application that are not tied to a specific model.

### `view-admin-panel`

Grants access to the `/admin` route group. Requires the `admin` or `super_admin` role.

```php
Gate::define('view-admin-panel', function (User $user) {
    return $user->hasRole(['admin', 'super_admin']);
});
```

| Role | Access |
|---|---|
| Guest | ❌ |
| User | ❌ |
| Pro User | ❌ |
| Creator | ❌ |
| Moderator | ❌ |
| Support | ❌ |
| Editor | ❌ |
| Admin | ✅ |
| Super Admin | ✅ |

### `access-playground`

Grants access to the interactive code playground. Any authenticated user may access the playground, but execution limits differ by role (see [10.16-playground-permissions.md](./10.16-playground-permissions.md)).

```php
Gate::define('access-playground', function (User $user) {
    return $user->hasVerifiedEmail();
});
```

### `access-ai`

Grants access to the AI engine features. Requires an authenticated user with a verified email. May additionally check AI quota remaining for the user's subscription tier.

```php
Gate::define('access-ai', function (User $user) {
    if (! $user->hasVerifiedEmail()) {
        return false;
    }

    // Check if user has exhausted AI quota
    $quotaService = app(AiQuotaService::class);

    return ! $quotaService->isExhausted($user);
});
```

### `manage-billing`

Grants access to billing settings, invoice history, and subscription management. Requires `admin` or `owner` role (owner = account owner in team contexts, falls back to admin).

```php
Gate::define('manage-billing', function (User $user) {
    return $user->hasRole(['admin', 'super_admin', 'owner']);
});
```

### `view-analytics`

Grants access to platform analytics dashboards. Requires `admin` or `editor` role.

```php
Gate::define('view-analytics', function (User $user) {
    return $user->hasRole(['admin', 'super_admin', 'editor']);
});
```

### `manage-settings`

Grants access to platform settings (site name, feature flags, integrations). Requires `admin` role.

```php
Gate::define('manage-settings', function (User $user) {
    return $user->hasRole(['admin', 'super_admin']);
});
```

### `access-mcp`

Grants access to the Model Context Protocol (MCP) server. Requires an authenticated user with a verified email and an active API token.

```php
Gate::define('access-mcp', function (User $user) {
    if (! $user->hasVerifiedEmail()) {
        return false;
    }

    return $user->tokens()->where('name', 'mcp')->exists()
        || $user->hasRole(['admin', 'super_admin']);
});
```

## Content Gates

Content gates control creation, moderation, and publishing of platform content. They combine role checks with ownership and status conditions.

### `publish-content`

Grants ability to submit content for publication. Requires the user to be a creator or admin, and the content must meet minimum approval requirements.

```php
Gate::define('publish-content', function (User $user) {
    if (! $user->hasRole(['creator', 'admin', 'super_admin'])) {
        return false;
    }

    // Creator accounts must have an approved creator profile
    if ($user->hasRole('creator')) {
        return $user->creatorProfile
            && $user->creatorProfile->status === 'approved';
    }

    return true;
});
```

### `moderate-content`

Grants ability to review, approve, or reject submitted content. Requires `moderator`, `admin`, or `super_admin` role.

```php
Gate::define('moderate-content', function (User $user) {
    return $user->hasRole(['moderator', 'admin', 'super_admin']);
});
```

### `manage-documentation`

Grants ability to create, edit, or delete documentation pages. Requires `editor` or `admin` role.

```php
Gate::define('manage-documentation', function (User $user) {
    return $user->hasRole(['editor', 'admin', 'super_admin']);
});
```

### `manage-blog`

Grants ability to create, edit, publish, or delete blog posts. Requires `editor` or `admin` role.

```php
Gate::define('manage-blog', function (User $user) {
    return $user->hasRole(['editor', 'admin', 'super_admin']);
});
```

## System Gates

System gates control access to infrastructure-level operations. These are the most restricted gates on the platform.

### `view-system-health`

Grants access to system health dashboards, uptime monitors, and diagnostic tools. Requires `super_admin` role only.

```php
Gate::define('view-system-health', function (User $user) {
    return $user->hasRole('super_admin');
});
```

### `manage-system`

Grants ability to perform system-level operations: cache clearing, queue management, scheduler control, deployment hooks. Requires `super_admin` role only.

```php
Gate::define('manage-system', function (User $user) {
    return $user->hasRole('super_admin');
});
```

### `access-debug`

Grants access to debug tools, verbose error pages, and profiling. Requires `super_admin` role AND the application must not be in production.

```php
Gate::define('access-debug', function (User $user) {
    return $user->hasRole('super_admin')
        && app()->environment(['local', 'staging', 'development']);
});
```

## Marketplace Gates

Marketplace gates control browsing, purchasing, and selling operations on the marketplace. See [10.10-marketplace-permissions.md](./10.10-marketplace-permissions.md) for the full marketplace permission matrix.

### `browse-marketplace`

Grants access to browse marketplace listings. Available to all visitors (guests included).

```php
Gate::define('browse-marketplace', function (?User $user) {
    return true; // Public marketplace
```

### `purchase-marketplace-item`

Grants ability to purchase themes, components, or templates. Requires an authenticated user with a verified email and an active payment method.

```php
Gate::define('purchase-marketplace-item', function (User $user) {
    if (! $user->hasVerifiedEmail()) {
        return false;

    return $user->hasPaymentMethod() || $user->hasRole(['admin', 'super_admin']);
});
```

### `manage-own-listings`

Grants ability to manage marketplace listings owned by the user. Requires `creator` or `admin` role with ownership.

```php
Gate::define('manage-own-listings', function (User $user) {
    return $user->hasRole(['creator', 'admin', 'super_admin']);
});
```

Billing gates control access to financial operations.

Grants ability to view invoices. Requires authenticated user (users see their own, admins see all).

```php
Gate::define('view-invoices', function (User $user) {
    return $user->hasVerifiedEmail();

```

### `process-refund`

Grants ability to process refunds. Requires `support` or `admin` role.

```php
Gate::define('process-refund', function (User $user) {
    return $user->hasRole(['support', 'admin', 'super_admin']);
});
```

## Super Admin Override

The `Gate::before()` callback grants super administrators unrestricted access to every gate on the platform. This is the single bypass point and must be the first registration in `boot()`.

```php
Gate::before(function (User $user, string $ability) {
    if ($user->hasRole('super_admin')) {
        return true;
    }

    // Null return defers to individual gate definitions
    return null;
});
```

**Important:** Returning `true` from `Gate::before()` short-circuits all subsequent gate checks. Returning `null` defers to the next callback or the gate definition itself.

## Usage in Controllers

Gates are evaluated using `$user->can()` / `$user->cannot()` or the `Gate::allows()` / `Gate::denies()` facades.

### Inline Authorization

```php
// app/Http/Controllers/Admin/DashboardController.php

public function index(Request $request)
{
    if ($request->user()->cannot('view-admin-panel')) {
        abort(403, 'Unauthorized access to admin panel.');
    }

    return view('admin.dashboard');
}
```

### Gate Facade

```php
use Illuminate\Support\Facades\Gate;

if (Gate::denies('manage-system')) {
    abort(403);
}
```

### Authorization Exception with Message

```php
use Illuminate\Auth\Access\AuthorizationException;

throw new AuthorizationException(
    'You do not have permission to access the system health dashboard.'
);
```

### Before/After Middleware (Recommended)

For route-level protection, use the `can` middleware instead of inline checks:

```php
Route::middleware(['can:view-admin-panel'])->group(function () {
    Route::prefix('admin')->group(function () {
        Route::get('/', [DashboardController::class, 'index']);
        Route::get('/users', [UserController::class, 'index']);
    });
});
```

## Usage in Blade

Blade provides `@can`, `@cannot`, and `@canany` directives for conditional rendering.

### `@can` / `@endcan`

```blade
@can('view-admin-panel')
    <x-admin-sidebar />
@endcan

@can('publish-content')
    <x-gsmui-button tag="a" href="/content/create">
        Create Content
    </x-gsmui-button>
@endcan
```

### `@cannot` / `@endcannot`

```blade
@cannot('access-debug')
    <p>Debug tools are not available in production.</p>
@endcannot
```

### `@canany` / `@endcanany`

```blade
@canany(['manage-documentation', 'manage-blog'])
    <x-admin-content-nav />
@endcanany
```

### Inline `@can` with Model

```blade
@can('moderate-content')
    <form action="/admin/content/{{ $post->id }}/approve" method="POST">
        @csrf
        <x-gsmui-button type="submit">Approve</x-gsmui-button>
    </form>
@endcan
```

## Usage in Livewire

Livewire components use the `$this->authorize()` method, which delegates to the gate system.

### Component-Level Authorization

```php
// app/Livewire/Admin/UserManager.php

class UserManager extends Component
{
    public function mount(): void
    {
        $this->authorize('view-admin-panel');
    }

    public function deleteUser(User $user): void
    {
        $this->authorize('view-admin-panel');

        if (auth()->user()->cannot('delete', $user)) {
            $this->dispatch('notify', type: 'error', message: 'Cannot delete this user.');
            return;
        }

        $user->delete();

        $this->dispatch('notify', type: 'success', message: 'User deleted.');
    }
}
```

### Conditional Rendering in Blade

```blade
{{-- resources/views/livewire/admin/user-manager.blade.php --}}

<div>
    @can('view-admin-panel')
        <table>
            @foreach ($users as $user)
                <tr>
                    <td>{{ $user->name }}</td>
                    <td>
                        @can('delete', $user)
                            <x-gsmui-button
                                wire:click="deleteUser({{ $user->id }})"
                                color="danger"
                                size="xs"
                            >
                                Delete
                            </x-gsmui-button>
                        @endcan
                    </td>
                </tr>
            @endforeach
        </table>
    @else
        <p>You do not have permission to view this page.</p>
    @endcan
</div>
```

## Gate Policy Integration

Gates and policies work together. When checking authorization on a model, Laravel automatically invokes the corresponding policy. Gates handle non-model checks. If both are registered for the same ability, the policy takes precedence for model checks.

```php
// This invokes ThemePolicy@update if $theme is a Theme model
$this->authorize('update', $theme);

// This invokes the 'view-admin-panel' gate (no model)
$this->authorize('view-admin-panel');
```

## Testing Gates

Gates should be tested in feature tests to ensure authorization logic is correct.

```php
// tests/Feature/Authorization/GateTest.php

use Tests\TestCase;
use App\Models\User;

class GateTest extends TestCase
{
    public function test_admin_can_view_admin_panel(): void
    {
        $admin = User::factory()->create();
        $admin->assignRole('admin');

        $this->actingAs($admin);
        $this->assertTrue($admin->can('view-admin-panel'));
    }

    public function test_regular_user_cannot_view_admin_panel(): void
    {
        $user = User::factory()->create();
        $user->assignRole('user');

        $this->actingAs($user);
        $this->assertFalse($user->can('view-admin-panel'));
    }

    public function test_super_admin_bypasses_all_gates(): void
    {
        $superAdmin = User::factory()->create();
        $superAdmin->assignRole('super_admin');

        $this->actingAs($superAdmin);
        $this->assertTrue($superAdmin->can('view-admin-panel'));
        $this->assertTrue($superAdmin->can('manage-system'));
        $this->assertTrue($superAdmin->can('access-debug'));
    }

    public function test_debug_gate_blocked_in_production(): void
    {
        app()->detectEnvironment(fn() => 'production');

        $superAdmin = User::factory()->create();
        $superAdmin->assignRole('super_admin');

        $this->actingAs($superAdmin);
        $this->assertFalse($superAdmin->can('access-debug'));
    }

    public function test_publish_requires_approved_creator_profile(): void
    {
        $creator = User::factory()->create();
        $creator->assignRole('creator');

        $this->actingAs($creator);
        $this->assertFalse($creator->can('publish-content'));

        $creator->creatorProfile()->create(['status' => 'approved']);
        $this->assertTrue($creator->can('publish-content'));
    }
}
```

## Gate Cache & Performance

Gates are registered once per request in `AuthServiceProvider::boot()`. The closure evaluations happen on each `can()` call. For gates that perform database queries (e.g., quota checks), consider caching the result per-request:

```php
Gate::define('access-ai', function (User $user) {
    // Cache the result for the duration of the request
    return once(fn() => ! app(AiQuotaService::class)->isExhausted($user));
});
```

## Gate Design Patterns

### Pattern 1: Simple Role Gate

The most basic gate pattern. Checks if the user holds a specific role.

```php
Gate::define('simple-role-gate', function (User $user) {
    return $user->hasRole('admin');
});
```

Use when: The check is simple role membership with no additional conditions.

### Pattern 2: Permission-Based Gate

Checks if the user holds a specific permission. More granular than role-based gates.

```php
Gate::define('permission-gate', function (User $user) {
    return $user->hasPermissionTo('themes.publish');
});
```

Use when: You need to support direct permission overrides or want to decouple from specific role names.

### Pattern 3: Compound Gate

Combines multiple conditions (role, permission, ownership, status).

```php
Gate::define('compound-gate', function (User $user) {
    return $user->hasRole('creator')
        && $user->creatorProfile
        && $user->creatorProfile->status === 'approved'
        && $user->hasVerifiedEmail();
});
```

Use when: The authorization logic involves multiple conditions that must all be true.

### Pattern 4: Quota Gate

Combines permission checks with usage quotas.

```php
Gate::define('quota-gate', function (User $user) {
    $quotaService = app(QuotaService::class);
    return ! $quotaService->isExhausted($user, 'ai_generation');
});
```

Use when: Access depends on remaining quota, not just role.

### Pattern 5: Environment Gate

Combines permission checks with application environment.

```php
Gate::define('environment-gate', function (User $user) {
    return $user->hasRole('super_admin')
        && app()->environment(['local', 'staging']);
});
```

Use when: The feature should only be available in non-production environments.

### Pattern 6: Before/After Gate

Uses `Gate::before()` or `Gate::after()` for global authorization logic.

```php
Gate::before(function (User $user, string $ability) {
    if ($user->hasRole('super_admin')) {
        return true; // Super admin bypass
    }
    return null; // Defer to individual gate
});
```

Use when: You need a global bypass or global authorization check.

## Gate Composition

### Combining Multiple Gates

Gates can be combined using `Gate::any()`, `Gate::none()`, or `Gate::before()`.

```php
// Check if user has ANY of these gates
if (Gate::any(['manage-documentation', 'manage-blog'])) {
    // User can manage at least one content type
}

// Check if user has NONE of these gates
if (Gate::none(['manage-system', 'access-debug'])) {
    // User has no system-level access
}
```

### Gate Inheritance

Gates can inherit from other gates:

```php
// Base gate
Gate::define('manage-content', function (User $user) {
    return $user->hasRole(['editor', 'admin', 'super_admin']);
});

// Inherit and extend
Gate::define('manage-documentation', function (User $user) {
    return Gate::allows('manage-content')
        && $user->hasPermissionTo('documentation.create');
});
```

### Gate Pipelines

Use pipelines for complex gate logic:

```php
Gate::define('advanced-gate', function (User $user) {
    return app(Pipeline::class)
        ->send($user)
        ->through([
            EnsureVerifiedEmail::class,
            EnsureActiveSubscription::class,
            EnsurePermission::class,
            EnsureQuota::class,
        ])
        ->thenReturn();
});
```

## Gate Performance Optimization

### Caching Gate Results

Cache expensive gate calculations:

```php
Gate::define('expensive-gate', function (User $user) {
    return once(function () use ($user) {
        // Expensive calculation
        return $user->hasRole('admin') && $this->checkComplexCondition($user);
    });
});
```

### Reducing Database Queries

Optimize gate logic to minimize database queries:

```php
// BAD: Multiple queries
Gate::define('bad-gate', function (User $user) {
    return $user->hasRole('admin')
        && $user->orders()->count() > 10
        && $user->totalSpent() > 1000;
});

// GOOD: Single query with eager loading
Gate::define('good-gate', function (User $user) {
    $user->loadCount('orders');
    return $user->hasRole('admin')
        && $user->orders_count > 10
        && $user->total_spent > 1000;
});
```

### Gate Registration Timing

Register gates in `AuthServiceProvider::boot()` for optimal performance:

```php
class AuthServiceProvider extends ServiceProvider
{
    public function boot(): void
    {
        $this->registerPolicies();
        
        // Register gates early in boot process
        $this->registerPlatformGates();
        $this->registerContentGates();
        $this->registerSystemGates();
    }
}
```

### Testing Gate Interactions

```php

class GateInteractionTest extends TestCase
{
    public function test_gate_and_policy_work_together(): void
    {
        $user = User::factory()->create();
        $theme = Theme::factory()->create(['user_id' => $user->id]);
        
        // Gate allows the operation
        $this->assertTrue(Gate::allows('manage-content'));
        
        // Policy allows the operation
        $this->assertTrue($user->can('update', $theme));
    }

    public function test_gate_blocks_when_policy_allows(): void
    {
        $user = User::factory()->create();
        $theme = Theme::factory()->create(['user_id' => $user->id]);
        
        // Gate blocks (user is not admin)
        Gate::define('custom-gate', fn() => false);
        
        $this->assertFalse(Gate::allows('custom-gate'));
        
        // But policy still allows (user owns the theme)
        $this->assertTrue($user->can('update', $theme));
    }
}
```

## Gate Security Considerations

### Preventing Gate Bypass

```php
// Ensure gates cannot be bypassed via client-side manipulation
Gate::define('secure-gate', function (User $user) {
    // Always check server-side
    if (! $user) {
```

```php
// app/Services/GateCache.php

class GateCache
{
    private CacheRepository $cache;
    private int $ttl = 300;

    public function __construct(CacheRepository $cache)
    {
        $this->cache = $cache;
    }

    public function remember(User $user, string $ability, $arguments, Closure $gate): bool
    {
        $key = $this->buildKey($user, $ability, $arguments);

        return $this->cache->remember($key, $this->ttl, function () use ($gate) {
            return $gate();
        });
    }

    protected function buildKey(User $user, string $ability, $arguments): string
    {
        $argHash = is_object($arguments)
            ? spl_object_id($arguments)
            : md5(json_encode($arguments));

        return "gate:${$user->id}:${$ability}:${$argHash}";
    }
}
```

### Circuit Breaker Pattern

```php
// app/Services/CircuitBreakerGate.php

class CircuitBreakerGate
{
    private string $state = 'closed';
    private int $failureCount = 0;
    private int $failureThreshold = 5;
    private int $recoveryTimeout = 60;
    private ?int $openedAt = null;

    public function evaluate(User $user, string $ability, Closure $gate): bool
    {
        if ($this->state === 'open') {
            if ($this->shouldAttemptRecovery()) {
                $this->state = 'half-open';
            } else {
                return $this->fallbackDecision($ability);
            }
        }

        try {
            $result = $gate();
            $this->onSuccess();
            return $result;
        } catch (\Exception $e) {
            $this->onFailure();
            return $this->fallbackDecision($ability);
        }
    }

    protected function onSuccess(): void
    {
        $this->failureCount = 0;
        $this->state = 'closed';
    }

    protected function onFailure(): void
    {
        $this->failureCount++;
        if ($this->failureCount >= $this->failureThreshold) {
            $this->state = 'open';
            $this->openedAt = time();
        }
    }

    protected function shouldAttemptRecovery(): bool
    {
        return (time() - ($this->openedAt ?? 0)) >= $this->recoveryTimeout;
    }

    protected function fallbackDecision(string $ability): bool
    {
        $sensitiveAbilities = ['users.delete', 'system.settings', 'roles.assign'];
        return ! in_array($ability, $sensitiveAbilities);
    }
}
```

## Appendix: Gate Extension Points

### Custom Gate Drivers

```php
<?php

namespace GsmUi\Auth\Gates\Drivers;

interface GateDriverInterface
{
    public function check(string $ability, mixed $user, array $arguments = []): bool;
    
    public function getPolicyClass(string $model): ?string;
    
    public function before(mixed $user, string $ability): ?bool;
}

class DatabaseGateDriver implements GateDriverInterface
{
    protected array $permissions = [];
    
    public function __construct(array $permissions = [])
    {
        $this->permissions = $permissions;
    }
    
    public function check(string $ability, mixed $user, array $arguments = []): bool
    {
        if (!$user) {
            return false;
        }
        
        $userPermissions = $this->getUserPermissions($user);
        
        return in_array($ability, $userPermissions) || 
               in_array('*', $userPermissions) ||
               $this->checkWildcard($ability, $userPermissions);
    }
    
    protected function checkWildcard(string $ability, array $permissions): bool
    {
        $parts = explode('.', $ability);
        
        foreach ($permissions as $permission) {
            $permParts = explode('.', $permission);
            
            if (count($permParts) !== count($parts)) {
                continue;
            }
            
            $match = true;
            for ($i = 0; $i < count($parts); $i++) {
                if ($permParts[$i] !== '*' && $permParts[$i] !== $parts[$i]) {
                    $match = false;
                    break;
                }
            }
            
            if ($match) {
                return true;
            }
        }
        
        return false;
    }
    
    protected function getUserPermissions(mixed $user): array
    {
        if (method_exists($user, 'getAllPermissions')) {
            return $user->getAllPermissions()->pluck('name')->toArray();
        }
        
        return $this->permissions;
    }
    
    public function getPolicyClass(string $model): ?string
    {
        return null;
    }
    
    public function before(mixed $user, string $ability): ?bool
    {
        if (method_exists($user, 'isSuperAdmin') && $user->isSuperAdmin()) {
```

### Gate Caching Strategy

```php
<?php

namespace GsmUi\Auth\Gates;

class CachedGate extends Gate
{
    protected int $ttl = 300; // 5 minutes
    
    public function allows(string $ability, array $arguments = []): bool
    {
        $user = $this->getUserResolver()();
        
        if (!$user) {
            return false;
        }
        
        $cacheKey = $this->buildCacheKey($ability, $user, $arguments);
        
        return $this->cache()->remember($cacheKey, $this->ttl, function () use ($ability, $arguments) {
            return parent::allows($ability, $arguments);
        });
    }
    
    protected function buildCacheKey(string $ability, mixed $user, array $arguments): string
    {
        $userId = method_exists($user, 'getKey') ? $user->getKey() : 'guest';
        $argsHash = md5(serialize($arguments));
        
        return "gate:{$ability}:{$userId}:{$argsHash}";
    }
    
    public function flushCache(mixed $user = null): void
    {
        if ($user) {
            $userId = method_exists($user, 'getKey') ? $user->getKey() : 'guest';
            $this->cache()->flush("gate:*:{$userId}:*");
        } else {
            $this->cache()->flush('gate:*');
        }
    }
}
```

```php
<?php

namespace GsmUi\Auth\Listeners;

use GsmUi\Auth\Events\GateCheckPerformed;
use Illuminate\Support\Facades\Log;

class LogGateChecks
{
    public function handle(GateCheckPerformed $event): void
    {
        if (config('gsmui.auth.log_gate_checks', false)) {
            Log::channel('gate-checks')->info('Gate check performed', [
                'ability' => $event->ability,
                'user_id' => $event->user?->getKey(),
                'result' => $event->result,
                'duration_ms' => round($event->duration * 1000, 2),
                'policy' => $event->policyClass,
            ]);
        }
        
        // Alert on denied critical abilities
        if (!$event->result && $this->isCriticalAbility($event->ability)) {
            Log::channel('security')->warning('Critical gate denied', [
                'ability' => $event->ability,
                'user_id' => $event->user?->getKey(),
                'ip' => request()->ip(),
            ]);
        }
    }
    
    protected function isCriticalAbility(string $ability): bool
    {
        $critical = [
            'admin.*',
            'system.*',
            'billing.*',
            'user.delete',
            'team.delete',
        ];
        
        foreach ($critical as $pattern) {
            if (fnmatch($pattern, $ability)) {
                return true;
            }
        }
        
        return false;
    }
}
```

### Migration Guide: Gates v1 → v2

| v1 Pattern | v2 Replacement |
|------------|----------------|
| `Gate::define('ability', fn() => ...)` | `Gate::define('ability', [GateHandler::class, 'handle'])` |
| `$user->can('ability')` | `$user->can('ability')` (unchanged) |
| `before` closures | `before` method on driver |
| Manual cache | `CachedGate` class |

### Troubleshooting

| Issue | Cause | Solution |
|-------|-------|----------|
| Gate always returns false | Missing policy registration | Register policy in `AuthServiceProvider` |
| Gate caching stale results | User permissions changed | Call `Gate::flushCache($user)` after permission changes |
| Super admin denied | `before` hook not returning true | Ensure `before` returns `true` for super admins |
| Wildcard not matching | Pattern mismatch | Use `fnmatch` syntax: `admin.*` matches `admin.users.view` |
| Performance degradation | Missing indexes | Add indexes on `permissions.name`, `model_has_permissions.permission_id` |
