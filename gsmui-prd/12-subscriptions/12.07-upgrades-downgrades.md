# 12.07 — Upgrades & Downgrades

**Project:** GsmUi
**Domain:** Subscription Management
**Version:** 1.0.0

---

## Purpose

Define how subscription plan changes (upgrades and downgrades) are handled — when changes take effect, how proration is calculated, and how entitlements transition between plans.

## Plan Change Architecture

```text
Upgrade:        Free ──→ Pro ──→ Team ──→ Enterprise
                (immediate, prorated)

Downgrade:      Enterprise ──→ Team ──→ Pro ──→ Free
                (end of period, scheduled)

Cross-grade:    Pro Monthly ──→ Pro Yearly
                (immediate, prorated)
```

## Upgrade Flow

### Immediate Activation

Upgrades take effect immediately. The user gets the new plan's features right away.

```text
1. User selects new plan (higher tier or same tier annual)
2. Proration calculated
3. Current plan credit applied to new plan
4. Payment provider updates subscription
5. Status remains Active
6. Entitlements synchronized for new plan
7. Upgrade logged in status_histories
```

### Proration Calculation

```php
public function calculateUpgradeProration(Subscription $subscription, Plan $newPlan): int
{
    $oldPlan = $subscription->plan;
    $periodStart = $subscription->period()->start;
    $periodEnd = $subscription->period()->end;
    $daysTotal = $periodStart->diffInDays($periodEnd);
    $daysRemaining = now()->diffInDays($periodEnd);

    // Unused portion of current plan
    $credit = $oldPlan->price * ($daysRemaining / $daysTotal);

    // Cost of new plan for remaining period
    $cost = $newPlan->price * ($daysRemaining / $daysTotal);

    // Amount to charge
    $amountDue = max(0, $cost - $credit);

    return (int) $amountDue; // In cents
}
```

### Upgrade Scenarios

| From | To | Effect | Proration |
|---|---|---|---|
| Free | Pro | Immediate | Full Pro price |
| Free | Team | Immediate | Full Team price |
| Pro | Team | Immediate | Credit + prorated difference |
| Team | Pro | Downgrade (scheduled) | N/A |
| Pro Monthly | Pro Yearly | Immediate | Credit applied to annual |
| Pro | Enterprise | Immediate | Custom quote |

## Downgrade Flow

### Scheduled Activation

Downgrades take effect at the end of the current billing period.

```text
1. User selects lower plan (lower tier)
2. No immediate change to features
3. `plan_id` updated immediately for billing
4. `cancel_at_period_end` remains false
5. Scheduled plan swap at period end
6. Entitlements remain at current plan until period end
7. Downgrade logged
```

### Implementation

```php
public function downgrade(Subscription $subscription, Plan $newPlan): void
{
    // Store target plan for end-of-period swap
    $subscription->metadata = array_merge($subscription->metadata ?? [], [
        'scheduled_plan_id' => $newPlan->id,
        'scheduled_change_at' => $subscription->period()->end->toDateTimeString(),
    ]);
    $subscription->save();

    // Schedule the actual swap
    ProcessScheduledDowngradeJob::dispatch($subscription)
        ->delay($subscription->period()->end);

    SubscriptionDowngradeScheduled::dispatch($subscription, $newPlan);
}
```

### End-of-Period Swap

```php
// app/Jobs/ProcessScheduledDowngradeJob.php
class ProcessScheduledDowngradeJob implements ShouldQueue
{
    public function handle(): void
    {
        $scheduledPlanId = $this->subscription->metadata['scheduled_plan_id'] ?? null;

        if (!$scheduledPlanId) {
            return; // Plan was upgraded again since scheduling
        }

        $newPlan = Plan::find($scheduledPlanId);

        $this->subscription->plan_id = $newPlan->id;
        $this->subscription->save();

        // Remove scheduled change metadata
        $metadata = $this->subscription->metadata;
        unset($metadata['scheduled_plan_id'], $metadata['scheduled_change_at']);
        $this->subscription->metadata = $metadata;
        $this->subscription->save();

        // Synchronize entitlements (reduced feature set)
        app(EntitlementService::class)->synchronize($this->subscription);

        SubscriptionDowngraded::dispatch($this->subscription, $newPlan);
    }
}
```

## Entitlement Transition

### On Upgrade

```text
Old Entitlements
    ↓
Merge: new plan entitlements override old
    ↓
New entitlements cached in Redis
    ↓
User immediately sees new features
```

### On Downgrade

```text
Old Entitlements (remain until period end)
    ↓
[ period end ]
    ↓
New entitlements calculated
    ↓
Restricted features revoked
    ↓
User notified of feature changes
```

## Edge Cases

### Multiple Changes in One Period

**Rule:** Only the last scheduled change applies. If a user downgrades then upgrades, the upgrade takes effect immediately and cancels the scheduled downgrade.

```php
public function swap(Subscription $subscription, Plan $newPlan): void
{
    // Cancel any scheduled downgrade
    $metadata = $subscription->metadata ?? [];
    unset($metadata['scheduled_plan_id'], $metadata['scheduled_change_at']);
    $subscription->metadata = $metadata;

    if ($this->isUpgrade($subscription->plan, $newPlan)) {
        $this->upgradeImmediately($subscription, $newPlan);
    } else {
        $this->scheduleDowngrade($subscription, $newPlan);
    }
}
```

### Plan No Longer Available

If a user plans to downgrade to a plan that was archived, the system prevents the downgrade and prompts the user to select an available plan.

### Free Plan Downgrade

Downgrading from Pro to Free is allowed. At period end:
- Premium entitlements revoked
- Downloads limited to 10/month
- AI credits reduced to 50/month
- MCP connections closed

## Detailed Upgrade Scenarios

### Scenario: Free to Pro (Immediate)

When a user upgrades from Free to Pro, the entire Pro price is charged immediately with no proration since there is no existing billing period.

```text
User Flow:
1. User clicks "Upgrade to Pro" on pricing page
2. Stripe Checkout session created with Pro price
3. User completes payment
4. Subscription created with status=active, plan_id=pro
5. Entitlements synchronized immediately
6. User gains access to premium components, themes, templates
7. Download limit changes from 10/mo to 100/mo
8. AI credits enabled at 500/month
9. MCP connections enabled (1 concurrent)
10. Welcome email sent with upgrade confirmation
```

```php
public function upgradeFromFree(User $user, Plan $newPlan): Subscription
{
    $subscription = Subscription::create([
        'user_id' => $user->id,
        'plan_id' => $newPlan->id,
        'status' => SubscriptionStatus::Active,
        'period_start' => now(),
        'period_end' => $newPlan->getNextBillingDate(now()),
        'trial_ends_at' => null,
    ]);

    // Process payment via Stripe
    $this->billing->createSubscription($user, $newPlan);

    // Synchronize entitlements
    app(EntitlementService::class)->synchronize($subscription);

    // Log the upgrade
    $subscription->statusHistories()->create([
        'from_status' => null,
        'to_status' => SubscriptionStatus::Active,
        'changed_by' => $user->id,
        'reason' => 'Free to Pro upgrade',
    ]);

    // Dispatch events
    SubscriptionUpgraded::dispatch($subscription, null, $newPlan);

    return $subscription;
}
```

### Scenario: Pro to Team (Prorated Upgrade)

When upgrading from Pro to Team, the user receives a credit for the unused portion of their Pro subscription and pays the prorated difference for the Team plan.

```text
User Flow:
1. User selects Team plan from billing dashboard
2. System calculates proration:
   - Pro monthly: $15/month
   - Team monthly: $49/month
   - Days remaining in period: 15 of 30
   - Pro credit: $15 × (15/30) = $7.50
   - Team cost: $49 × (15/30) = $24.50
   - Amount due: $24.50 - $7.50 = $17.00
3. User confirms upgrade with proration details displayed
4. Payment processed for $17.00
5. Plan changed immediately to Team
6. Team workspace provisioned
7. Seat allocation enabled (owner + 4 additional seats)
8. Shared entitlement pool activated
```

```php
public function upgradeWithProration(Subscription $subscription, Plan $newPlan): UpgradeResult
{
    $oldPlan = $subscription->plan;
    $periodStart = $subscription->period_start;
    $periodEnd = $subscription->period_end;
    $now = now();

    $daysTotal = $periodStart->diffInDays($periodEnd);
    $daysElapsed = $periodStart->diffInDays($now);
    $daysRemaining = $now->diffInDays($periodEnd);

    // Calculate credit for unused portion of current plan
    $dailyRate = $oldPlan->price / $daysTotal;
    $creditAmount = $dailyRate * $daysRemaining;

    // Calculate cost of new plan for remaining period
    $newDailyRate = $newPlan->price / $daysTotal;
    $costAmount = $newDailyRate * $daysRemaining;

    // Net amount due
    $amountDue = max(0, $costAmount - $creditAmount);

    // Process payment
    if ($amountDue > 0) {
        $this->billing->chargeUpgrade($subscription->user, $amountDue, [
            'description' => "Upgrade from {$oldPlan->name} to {$newPlan->name}",
            'metadata' => [
                'old_plan' => $oldPlan->slug,
                'new_plan' => $newPlan->slug,
                'proration_credit' => $creditAmount,
                'proration_cost' => $costAmount,
            ],
        ]);
    }

    // Update subscription
    $subscription->plan_id = $newPlan->id;
    $subscription->save();

    // Synchronize entitlements for new plan
    app(EntitlementService::class)->synchronize($subscription);

    return new UpgradeResult(
        amountDue: $amountDue,
        creditApplied: $creditAmount,
        newPlan: $newPlan,
    );
}
```

### Scenario: Pro Monthly to Pro Yearly (Cross-Grade)

Converting from monthly to yearly billing provides a significant discount. The remaining monthly credit is applied to the annual price.

```text
User Flow:
1. User selects "Switch to Annual" on billing page
2. System calculates:
   - Pro monthly: $15/month
   - Pro yearly: $150/year ($12.50/month equivalent)
   - Days remaining: 15 of 30
   - Monthly credit: $15 × (15/30) = $7.50
   - Annual cost: $150 - $7.50 = $142.50
3. User confirms with savings displayed
4. Payment processed for $142.50
5. Billing cycle changes to annual
6. Next renewal in 365 days
7. User saves $30/year ($2.50/month × 12)
```

```php
public function crossGradeToAnnual(Subscription $subscription): UpgradeResult
{
    $monthlyPlan = $subscription->plan;
    $yearlyPlan = Plan::where('slug', 'pro-yearly')->firstOrFail();

    $daysRemaining = now()->diffInDays($subscription->period_end);
    $daysInMonth = now()->diffInDays(now()->endOfMonth());

    // Credit for remaining monthly period
    $creditAmount = $monthlyPlan->price * ($daysRemaining / $daysInMonth);

    // Annual price minus credit
    $amountDue = $yearlyPlan->price - $creditAmount;

    $this->billing->chargeUpgrade($subscription->user, $amountDue, [
        'description' => 'Switch from Pro Monthly to Pro Yearly',
    ]);

    // Update subscription
    $subscription->plan_id = $yearlyPlan->id;
    $subscription->period_start = now();
    $subscription->period_end = now()->addYear();
    $subscription->save();

    return new UpgradeResult(
        amountDue: $amountDue,
        creditApplied: $creditAmount,
        newPlan: $yearlyPlan,
    );
}
```

## Detailed Downgrade Scenarios

### Scenario: Team to Pro (Scheduled Downgrade)

When downgrading from Team to Pro, the user retains Team features until the end of the billing period, then transitions to Pro.

```text
User Flow:
1. User selects Pro plan from billing dashboard
2. System shows confirmation:
   "Your plan will change to Pro at the end of your current billing period (March 15, 2026).
    You will lose access to:
    - Team workspace
    - 2000 AI credits/month → 500 AI credits/month
    - Team collaboration features
    - Priority support"
3. User confirms downgrade
4. Scheduled downgrade recorded
5. User retains all Team features until March 15
6. On March 15:
   - Plan changes to Pro
   - Team workspace archived (read-only)
   - Entitlements reduced
   - Notification sent
```

```php
public function scheduleDowngrade(Subscription $subscription, Plan $newPlan): void
{
    $currentPlan = $subscription->plan;

    // Validate it's actually a downgrade
    if ($newPlan->sort_order >= $currentPlan->sort_order) {
        throw new NotADowngradeException('Target plan must be lower tier');
    }

    // Check for existing scheduled change
    if (isset($subscription->metadata['scheduled_plan_id'])) {
        // Cancel previous scheduled downgrade
        $metadata = $subscription->metadata;
        unset($metadata['scheduled_plan_id'], $metadata['scheduled_change_at']);
        $subscription->metadata = $metadata;
    }

    // Schedule the downgrade
    $subscription->metadata = array_merge($subscription->metadata ?? [], [
        'scheduled_plan_id' => $newPlan->id,
        'scheduled_change_at' => $subscription->period_end->toDateTimeString(),
        'downgrade_from_plan' => $currentPlan->id,
    ]);
    $subscription->save();

    // Schedule the job
    ProcessScheduledDowngradeJob::dispatch($subscription)
        ->delay($subscription->period_end);

    // Notify user
    $subscription->user->notify(new DowngradeScheduledNotification(
        $subscription,
        $newPlan,
        $subscription->period_end
    ));

    // Log the scheduled change
    $subscription->statusHistories()->create([
        'from_status' => $subscription->status,
        'to_status' => $subscription->status, // No immediate status change
        'changed_by' => auth()->id(),
        'reason' => "Scheduled downgrade to {$newPlan->name} at period end",
    ]);

    SubscriptionDowngradeScheduled::dispatch($subscription, $newPlan);
}
```

### Scenario: Enterprise to Team (Major Downgrade)

Enterprise to Team downgrades involve additional complexity due to SSO, white-label, and custom entitlements.

```text
Enterprise → Team Downgrade Flow:
1. Admin requests downgrade (or contract expires)
2. SSO configuration archived
3. White-label settings removed
4. Custom domain deactivated
5. SCIM provisioning disabled
6. Dedicated support channel closed
7. Custom entitlements revoked
8. Team members notified of feature changes
9. Data export available for 90 days
10. Support ticket created for migration assistance
```

```php
public function downgradeFromEnterprise(EnterpriseSubscription $enterprise, TeamPlan $teamPlan): void
{
    $organization = $enterprise->organization;

    // Archive SSO configuration
    $this->ssoConfigArchiver->archive($organization);

    // Remove white-label settings
    $this->whiteLabelRemover->remove($organization);

    // Revoke custom entitlements
    EntitlementGrant::where('grantee_type', 'organization')
        ->where('grantee_id', $organization->id)
        ->delete();

    // Create standard team subscription
    $teamSubscription = Subscription::create([
        'user_id' => $enterprise->owner_id,
        'plan_id' => $teamPlan->id,
        'status' => SubscriptionStatus::Active,
        'period_start' => now(),
        'period_end' => now()->addMonth(),
        'metadata' => [
            'migrated_from_enterprise' => $enterprise->id,
            'migration_date' => now()->toDateTimeString(),
        ],
    ]);

    // Notify all organization members
    foreach ($organization->members as $member) {
        $member->notify(new EnterpriseDowngradeNotification($teamPlan));
    }

    // Archive enterprise subscription
    $enterprise->update(['status' => 'migrated']);

    // Create support ticket for migration
    SupportTicket::create([
        'subject' => "Enterprise to Team migration: {$organization->name}",
        'priority' => 'high',
        'metadata' => [
            'enterprise_id' => $enterprise->id,
            'organization_id' => $organization->id,
            'new_subscription_id' => $teamSubscription->id,
        ],
    ]);
}
```

## Proration Edge Cases

### Upgrade on Trial

When a user upgrades during a trial period, the trial continues on the new plan with the upgraded feature set.

```php
public function upgradeDuringTrial(Subscription $subscription, Plan $newPlan): void
{
    if (!$subscription->onTrial()) {
        throw new NotOnTrialException();
    }

    // No payment needed during trial
    $subscription->plan_id = $newPlan->id;
    $subscription->save();

    // Sync entitlements for new plan
    app(EntitlementService::class)->synchronize($subscription);

    // Trial continues on new plan
    SubscriptionUpgraded::dispatch($subscription, $subscription->plan, $newPlan);
}
```

### Mid-Period Upgrade After Previous Upgrade

If a user upgrades twice in the same billing period, the second upgrade uses the current plan as the baseline for proration.

```php
public function upgradeAgainMidPeriod(Subscription $subscription, Plan $newPlan): UpgradeResult
{
    $currentPlan = $subscription->plan;

    // Calculate credit based on what was actually paid
    // (not the original plan)
    $daysRemaining = now()->diffInDays($subscription->period_end);
    $daysTotal = $subscription->period_start->diffInDays($subscription->period_end);

    $currentDailyRate = $currentPlan->price / $daysTotal;
    $creditAmount = $currentDailyRate * $daysRemaining;

    $newDailyRate = $newPlan->price / $daysTotal;
    $costAmount = $newDailyRate * $daysRemaining;

    $amountDue = max(0, $costAmount - $creditAmount);

    // Process payment
    if ($amountDue > 0) {
        $this->billing->chargeUpgrade($subscription->user, $amountDue);
    }

    $subscription->plan_id = $newPlan->id;
    $subscription->save();

    app(EntitlementService::class)->synchronize($subscription);

    return new UpgradeResult(
        amountDue: $amountDue,
        creditApplied: $creditAmount,
        newPlan: $newPlan,
    );
}
```

### Downgrade During Grace Period

Users cannot downgrade while in a grace period (payment failed). They must resolve the payment issue first.

```php
public function downgradeDuringGrace(Subscription $subscription, Plan $newPlan): void
{
    if ($subscription->status === SubscriptionStatus::PastDue) {
        throw new GracePeriodActiveException(
            'Cannot change plans during grace period. Please update your payment method first.'
        );
    }

    $this->scheduleDowngrade($subscription, $newPlan);
}
```

### Cancel Scheduled Downgrade

Users can cancel a scheduled downgrade before it takes effect:

```php
public function cancelScheduledDowngrade(Subscription $subscription): void
{
    if (!isset($subscription->metadata['scheduled_plan_id'])) {
```

```php
public function adminForceUpgrade(Subscription $subscription, Plan $newPlan, string $reason): void
```

### Force Downgrade

Admins can immediately downgrade a subscription, bypassing the scheduled downgrade:

```php
public function adminForceDowngrade(Subscription $subscription, Plan $newPlan, string $reason, bool $prorated = false): void
{
    throw_unless(auth()->user()->isAdmin(), AuthorizationException::class);

    $oldPlan = $subscription->plan;

    // Clear any scheduled changes
    $metadata = $subscription->metadata ?? [];
    unset($metadata['scheduled_plan_id'], $metadata['scheduled_change_at']);

    // Update plan immediately
    $subscription->plan_id = $newPlan->id;
    $subscription->metadata = $metadata;
    $subscription->save();

    // Optionally issue prorated refund
    if ($prorated) {
        $this->billing->issueProratedRefund($subscription, $oldPlan);
    }

    // Synchronize entitlements
    app(EntitlementService::class)->synchronize($subscription);

    // Log admin action
    AdminAction::log('subscription.force_downgrade', [
        'subscription_id' => $subscription->id,
        'old_plan' => $oldPlan->slug,
        'new_plan' => $newPlan->slug,
        'reason' => $reason,
        'prorated_refund' => $prorated,
    ]);

    SubscriptionDowngraded::dispatch($subscription, $oldPlan);

    $subscription->user->notify(new AdminDowngradeNotification($subscription, $oldPlan, $reason));
}
```

## Upgrade/Downgrade Analytics

### Tracking Metrics

```php
class UpgradeDowngradeAnalytics
{
    public function trackUpgrade(Subscription $subscription, Plan $oldPlan, Plan $newPlan, int $amount): void
    {
        Analytics::track('subscription_upgraded', [
            'user_id' => $subscription->user_id,
            'old_plan' => $oldPlan->slug,
            'new_plan' => $newPlan->slug,
            'amount' => $amount,
            'upgrade_type' => $this->determineUpgradeType($oldPlan, $newPlan),
            'time_on_old_plan_days' => $subscription->created_at->diffInDays(now()),
        ]);
    }

    public function trackDowngrade(Subscription $subscription, Plan $oldPlan, Plan $newPlan, string $reason = null): void
    {
        Analytics::track('subscription_downgraded', [
            'user_id' => $subscription->user_id,
            'old_plan' => $oldPlan->slug,
            'new_plan' => $newPlan->slug,
            'reason' => $reason,
            'scheduled' => $subscription->metadata['scheduled_plan_id'] ?? null,
            'time_on_old_plan_days' => $subscription->created_at->diffInDays(now()),
        ]);
    }

    public function getUpgradeRevenue(string $period = 'month'): array
    {
        return Subscription::where('status', SubscriptionStatus::Active)
            ->where('updated_at', '>=', now()->sub($period))
            ->whereRaw("plan_id != (SELECT plan_id FROM subscriptions WHERE id = subscriptions.id)")
            ->sum('amount');
    }

    public function getDowngradeRate(string $period = 'month'): float
    {
        $totalActive = Subscription::where('status', SubscriptionStatus::Active)->count();
        $downgrades = Subscription::where('status', SubscriptionStatus::Active)
            ->whereHas('statusHistories', function ($q) use ($period) {
                $q->where('reason', 'like', '%downgrade%')
                  ->where('created_at', '>=', now()->sub($period));
            })
            ->count();

        return $totalActive > 0 ? $downgrades / $totalActive : 0;
    }
}
```

### Currency Handling

```php
class ProrationCalculator
{
    public function calculate(Subscription $subscription, Plan $newPlan): ProrationResult
    {
        $currency = $subscription->currency ?? 'USD';

        // Get prices in the subscription's currency
        $oldPrice = $this->currencyConverter->convert(
            $subscription->plan->price,
            'USD',
            $currency
        );

        $newPrice = $this->currencyConverter->convert(
            $newPlan->price,
            'USD',
            $currency
        );

        // Calculate proration
        $daysRemaining = now()->diffInDays($subscription->period_end);
        $daysTotal = $subscription->period_start->diffInDays($subscription->period_end);

        $credit = $oldPrice * ($daysRemaining / $daysTotal);
        $cost = $newPrice * ($daysRemaining / $daysTotal);
        $amountDue = max(0, $cost - $credit);

        return new ProrationResult(
            amountDue: (int) round($amountDue),
            creditApplied: (int) round($credit),
            currency: $currency,
            formattedAmountDue: $this->formatter->format($amountDue, $currency),
            formattedCredit: $this->formatter->format($credit, $currency),
        );
    }
}
```

```php
            ->where('created_at', '>=', now()->subHours($hours))

            ->where('created_at', '>=', now()->subDays(7))
```

## Upgrade/Downgrade Scheduling

### Scheduled Change Manager

```php
class ScheduledChangeManager
{
    public function getScheduledChange(Subscription $subscription): ?ScheduledChange
    {
        if (!isset($subscription->metadata['scheduled_plan_id'])) {
            return null;
        }

        return new ScheduledChange(
            subscription: $subscription,
            targetPlan: Plan::find($subscription->metadata['scheduled_plan_id']),
            effectiveDate: Carbon::parse($subscription->metadata['scheduled_change_at']),
            changeType: $this->determineChangeType($subscription),
        );
    }

    public function hasScheduledChange(Subscription $subscription): bool
    {
        return isset($subscription->metadata['scheduled_plan_id']);
    }

    public function cancelScheduledChange(Subscription $subscription): void
    {
        $metadata = $subscription->metadata ?? [];
        unset(
            $metadata['scheduled_plan_id'],
            $metadata['scheduled_change_at'],
            $metadata['downgrade_from_plan']
        );
        $subscription->metadata = $metadata;
        $subscription->save();
    }

    protected function determineChangeType(Subscription $subscription): string
    {
        $currentPlan = $subscription->plan;
        $scheduledPlan = Plan::find($subscription->metadata['scheduled_plan_id']);

        if ($scheduledPlan->price < $currentPlan->price) {
            return 'downgrade';
        } elseif ($scheduledPlan->price > $currentPlan->price) {
            return 'upgrade';
        }

        return 'cross_grade';
    }
}
```

### Cron Job for Processing Scheduled Changes

```php
// app/Console/Commands/ProcessScheduledChanges.php
class ProcessScheduledChanges extends Command
{
    protected $signature = 'subscriptions:process-scheduled-changes';
    protected $description = 'Process scheduled plan changes that are due';

    public function handle(): int
    {
        $dueChanges = Subscription::where('status', SubscriptionStatus::Active)
            ->whereNotNull('metadata->scheduled_plan_id')
            ->where('metadata->scheduled_change_at', '<=', now())
            ->get();

        $processed = 0;
        $failed = 0;

        foreach ($dueChanges as $subscription) {
            try {
                $this->processChange($subscription);
                $processed++;
            } catch (\Exception $e) {
                $failed++;
                $this->error("Failed to process change for subscription {$subscription->id}: {$e->getMessage()}");
            }
        }

        $this->info("Processed {$processed} changes, {$failed} failures");

        return $failed > 0 ? 1 : 0;
    }

    protected function processChange(Subscription $subscription): void
    {
        $scheduledPlanId = $subscription->metadata['scheduled_plan_id'];
        $targetPlan = Plan::find($scheduledPlanId);

        if (!$targetPlan) {
            throw new \RuntimeException("Scheduled plan not found: {$scheduledPlanId}");
        }

        // Update subscription
        $subscription->plan_id = $targetPlan->id;
        $this->cancelScheduledChange($subscription);

        // Synchronize entitlements
        app(EntitlementService::class)->synchronize($subscription);

        // Dispatch event
        SubscriptionDowngraded::dispatch($subscription, $subscription->plan, $targetPlan);

        // Log
        $subscription->statusHistories()->create([
            'from_status' => $subscription->status,
            'to_status' => $subscription->status,
            'reason' => "Scheduled change to {$targetPlan->name} executed",
        ]);
    }
}
```

## Upgrade/Downgrade Rate Limiting

### Rate Limiter

```php
class UpgradeDowngradeRateLimiter
{
    public function canUpgrade(User $user): bool
    {
        $key = "upgrades:{$user->id}";

        // Max 3 upgrades per month
        return RateLimiter::tooManyAttempts($key, 3) === false;
    }

    public function canDowngrade(User $user): bool
    {
        $key = "downgrades:{$user->id}";

        // Max 2 downgrades per month
        return RateLimiter::tooManyAttempts($key, 2) === false;
    }

    public function attemptUpgrade(User $user): void
    {
        $key = "upgrades:{$user->id}";
        RateLimiter::hit($key, now()->addMonth());
    }

    public function attemptDowngrade(User $user): void
    {
        $key = "downgrades:{$user->id}";
        RateLimiter::hit($key, now()->addMonth());
    }

    public function remainingUpgrades(User $user): int
    {
        $key = "upgrades:{$user->id}";
        return max(0, 3 - RateLimiter::attempts($key));
    }

    public function remainingDowngrades(User $user): int
    {
        $key = "downgrades:{$user->id}";
        return max(0, 2 - RateLimiter::attempts($key));
    }
}
```

## Upgrade/Downgrade Job Processing

### Upgrade Job

```php
// app/Jobs/ProcessUpgradeJob.php
class ProcessUpgradeJob implements ShouldQueue
{
    use Dispatchable, InteractsWithQueue, Queueable, SerializesModels;

    public int $tries = 3;
    public int $timeout = 60;

    public function __construct(
        public Subscription $subscription,
        public Plan $newPlan,
        public User $user,
    ) {}

    public function handle(): void
    {
        $upgradeService = app(UpgradeService::class);

        $result = $upgradeService->upgrade(
            $this->subscription,
            $this->newPlan
        );

        // Log success
        UpgradeLog::create([
            'subscription_id' => $this->subscription->id,
            'user_id' => $this->user->id,
            'old_plan_id' => $this->subscription->plan_id,
            'new_plan_id' => $this->newPlan->id,
            'amount' => $result->amountDue,
            'credit_applied' => $result->creditApplied,
            'status' => 'completed',
            'processing_time_ms' => microtime(true) - $this->startTime,
        ]);
    }

    public function failed(\Throwable $exception): void
    {
        UpgradeLog::create([
            'subscription_id' => $this->subscription->id,
            'user_id' => $this->user->id,
            'old_plan_id' => $this->subscription->plan_id,
            'new_plan_id' => $this->newPlan->id,
            'status' => 'failed',
            'error' => $exception->getMessage(),
        ]);

        // Notify user of failure
        $this->user->notify(new UpgradeFailedNotification(
            $this->subscription,
            $this->newPlan,
            $exception->getMessage()
        ));
    }
}
```

### Downgrade Job

```php
// app/Jobs/ProcessScheduledDowngradeJob.php
class ProcessScheduledDowngradeJob implements ShouldQueue
{
    use Dispatchable, InteractsWithQueue, Queueable, SerializesModels;

    public int $tries = 3;
    public int $timeout = 60;

    public function __construct(
        public Subscription $subscription,
    ) {}

    public function handle(): void
    {
        $scheduledPlanId = $this->subscription->metadata['scheduled_plan_id'] ?? null;

        if (!$scheduledPlanId) {
            return;
        }

        $newPlan = Plan::find($scheduledPlanId);

        if (!$newPlan) {
            throw new \RuntimeException("Scheduled plan not found: {$scheduledPlanId}");
        }

        // Store old plan for event
        $oldPlan = $this->subscription->plan;

        // Update subscription
        $this->subscription->plan_id = $newPlan->id;

        // Clear scheduled change metadata
        $metadata = $this->subscription->metadata;
        unset($metadata['scheduled_plan_id'], $metadata['scheduled_change_at']);
        $this->subscription->metadata = $metadata;
        $this->subscription->save();

        // Synchronize entitlements
        app(EntitlementService::class)->synchronize($this->subscription);

        // Dispatch event
        SubscriptionDowngraded::dispatch($this->subscription, $oldPlan, $newPlan);

        // Log success
        DowngradeLog::create([
            'subscription_id' => $this->subscription->id,
            'user_id' => $this->subscription->user_id,
            'old_plan_id' => $oldPlan->id,
            'new_plan_id' => $newPlan->id,
            'status' => 'completed',
            'processing_time_ms' => microtime(true) - $this->startTime,
        ]);
    }

    public function failed(\Throwable $exception): void
    {
        DowngradeLog::create([
            'subscription_id' => $this->subscription->id,
            'user_id' => $this->subscription->user_id,
            'status' => 'failed',
            'error' => $exception->getMessage(),
        ]);

        $this->subscription->user->notify(
            new DowngradeFailedNotification($this->subscription, $exception->getMessage())
        );
    }
}
```
