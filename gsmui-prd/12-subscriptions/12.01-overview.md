# 12.01 — Subscriptions Overview

**Project:** GsmUi
**Domain:** Subscription Management
**Version:** 1.0.0

---

## Purpose

This document defines the **complete Subscription Management System** for GsmUi. Subscriptions are not merely a billing mechanism — they are the core access control layer for the entire platform. Every premium feature, component download, theme access, AI credit, API limit, MCP connection, and team capability is governed by subscription entitlements.

GsmUi is both a **UI framework** and a **commercial SaaS platform**. Subscriptions control:

* **Feature access** — which UI components, themes, and templates are available
* **Download limits** — how many marketplace items can be downloaded per month
* **AI usage** — chat credits, code generation limits
* **MCP access** — server connections and tool execution
* **API limits** — rate limits and endpoint access
* **Team capabilities** — seat count, collaboration features
* **Support level** — community vs. priority support
* **Updates & upgrades** — access to new releases

## Scope

GsmUi's subscription system must serve:

* **Individual users** — Free, Pro, and lifetime plans
* **Teams** — multi-seat subscriptions with shared entitlements
* **Enterprises** — custom contracts, SSO, dedicated support
* **Admins** — plan management, subscription administration
* **API consumers** — token-based subscription verification
* **Marketplace creators** — revenue sharing and creator plan access

## Subscription Architecture

```text
Customer
    ↓
Subscription Plan (Free / Pro / Team / Enterprise)
    ↓
Subscription (active, trialing, past_due, canceled, expired)
    ↓
Entitlement Resolution (plan + add-ons + overrides)
    ↓
Feature Gates (premium components, themes, AI, API, MCP)
    ↓
Application Access (UI, downloads, API, CLI, MCP)
```

Subscriptions determine what a user **can access**, while billing determines **how they pay**. These are separate concerns that integrate through the Entitlement Service.

## Core Principles

1. **Entitlements over Plan Names.** Code never checks `$user->plan === 'pro'`. It checks `$user->hasEntitlement('component.pro')`. This allows plan restructuring without application changes.

2. **Real-time Entitlement Resolution.** Entitlements are cached in Redis but can be invalidated instantly. A payment failure immediately revokes premium access.

3. **Provider-Agnostic Core.** The domain model does not depend on Stripe, Paddle, or Lemon Squeezy. Provider IDs are stored but not used in business logic. Provider switching requires only new webhook handlers.

4. **Immutable Audit Trail.** All subscription state changes are logged in `subscription_status_histories`. No state is overwritten — only transitions are recorded.

5. **Grace Before Revocation.** Payment failures trigger a grace period before access revocation. Users are notified at every stage.

6. **Composable Entitlements.** Entitlements combine base plan features, add-on purchases, promotional grants, and admin overrides into a unified access profile.

# Detailed Entitlement Resolution

The entitlement system is the bridge between subscriptions and application access. It resolves what a user can do, see, and download based on their current subscription state.

## Resolution Pipeline

```text
Request for entitlement check
    ↓
Check Redis cache (TTL: 60s)
    ↓ Cache miss
Load user's active subscription
    ↓
Load plan's base entitlements (JSON column)
    ↓
Load subscription items (add-ons)
    ↓
Load active grants (admin overrides, promotions)
    ↓
Merge all entitlements (grants override plan)
    ↓
Filter expired entitlements
    ↓
Build EntitlementSet value object
    ↓
Store in Redis cache
    ↓
Return result to caller
```

## Entitlement Set

```php
class EntitlementSet
{
    protected array $entitlements = [];

    public function add(string $key, mixed $value, ?Carbon $expiresAt = null): self
    {
        $this->entitlements[$key] = new EntitlementValue(
            value: $value,
            expiresAt: $expiresAt,
        );
        return $this;
    }

    public function has(string $key): bool
    {
        return isset($this->entitlements[$key])
            && !$this->entitlements[$key]->isExpired();
    }

    public function value(string $key, mixed $default = null): mixed
    {
        if (!$this->has($key)) {
            return $default;
        }
        return $this->entitlements[$key]->value;
    }

    public function merge(EntitlementSet $other): self
    {
        foreach ($other->entitlements as $key => $value) {
            $this->entitlements[$key] = $value;
        }
        return $this;
    }

    public function applyGrant(EntitlementGrant $grant): self
    {
        $this->entitlements[$grant->key] = new EntitlementValue(
            value: $grant->value,
            expiresAt: $grant->expires_at,
        );
        return $this;
    }

    public function filterActive(): self
    {
        $this->entitlements = array_filter(
            $this->entitlements,
            fn($e) => !$e->isExpired()
        );
        return $this;
    }

    public function toArray(): array
    {
        return array_map(fn($e) => $e->value, $this->entitlements);
    }
}
```

# Subscription Lifecycle States

## Complete State Definitions

| State | Code | Description | Access | Can Renew | Can Resume | Terminal |
|---|---|---|---|---|---|---|
| Incomplete | `incomplete` | Initial payment pending | No | N/A | N/A | No |
| Trialing | `trialing` | Within trial period | Full plan | N/A | N/A | No |
| Active | `active` | Paid and current | Full plan | Yes | N/A | No |
| Past Due | `past_due` | Payment failed, grace period | Full plan (grace) | No | Yes | No |
| Canceled | `canceled` | Canceled at period end | Until period end | No | Yes (before expiry) | No |
| Expired | `expired` | Period ended after cancel | No | No | No | Yes |
| Unpaid | `unpaid` | Provider collection exhausted | No | N/A | N/A | Yes |
| Incomplete Expired | `incomplete_expired` | Initial payment timed out | No | N/A | N/A | Yes |

## State Transition Matrix

| From ↓ \ To → | Incomplete | Trialing | Active | Past Due | Canceled | Expired | Unpaid | Incomplete Expired |
|---|---|---|---|---|---|---|---|---|
| Incomplete | — | ✓ | — | — | — | — | — | ✓ |
| Trialing | — | — | ✓ | ✓ | ✓ | — | — | — |
| Active | — | — | — | ✓ | ✓ | — | ✓ | — |
| Past Due | — | — | ✓ | — | ✓ | — | ✓ | — |
| Canceled | — | — | ✓ | — | — | ✓ | — | — |
| Expired | — | — | — | — | — | — | — | — |
| Unpaid | — | — | — | — | — | — | — | — |
| Incomplete Expired | — | — | — | — | — | — | — | — |

## Terminal States

Three states are terminal — once entered, no further transitions are possible:

1. **Expired** — Subscription ended after cancellation
2. **Unpaid** — All collection efforts exhausted
3. **Incomplete Expired** — Initial payment never completed

## Proration Calculation

When upgrading mid-period, credit remaining on the current plan is applied:

```php
function calculateProration(Subscription $sub, Plan $newPlan): float
{
    $daysRemaining = $sub->period()->daysRemaining();
    $daysTotal = $sub->period()->daysTotal();
    $credit = $sub->plan->price * ($daysRemaining / $daysTotal);

    return max(0, $newPlan->price - $credit);
}
```

# Trial Management

## Trial Flow

```text
User selects plan with trial
    ↓
Payment method collected (no charge)
    ↓
Subscription created with status = 'trialing'
    ↓
trial_ends_at = now + plan.trial_days
    ↓
Full plan access granted immediately
    ↓
Trial expiry job scheduled
    ↓
On trial end: attempt to charge payment method
    ↓
Success: status = 'active'
Failure: status = 'past_due' (grace period begins)
```

## Trial Eligibility

- One trial per plan type per user lifetime
- One trial per billing entity (team trials don't affect individual)
- Admins can reset trial eligibility
- Free plan never has trials

## Trial Notifications

|---|---|---|

| Day 7 | Mid-trial reminder | Email |
| Day 12 | 2 days remaining | Email, In-app |
| Day 13 | 1 day remaining | Email |
| Day 14 | Trial expires today | Email, In-app |

# Renewal System

## Automatic Renewal Flow

```text
T-7 days:  Renewal reminder email
T-1 day:   Payment method verification
T-0:       Provider charges payment method
    ↓
Webhook: invoice.payment_succeeded
    ↓
Subscription status remains Active
    ↓
Entitlements synchronized
    ↓
Renewal logged in status_histories
```

## Payment Retry Schedule

| Attempt | Timing | Action |
|---|---|---|
| 1 | Immediate | Webhook-triggered retry |
| 2 | +24 hours | Email notification |
| 3 | +72 hours | Final warning |
| — | After 3 retries | Status → Unpaid, entitlements revoked |

## Price Locking

Subscribers keep their original price for the duration of their subscription. Price increases apply only to new subscribers. Price decreases can optionally be applied as a goodwill gesture.

```text
User requests cancellation
    ↓

    ↓

    ↓

    ↓
Set ends_at = current_period_end
    ↓
Notify user of access end date
    ↓
Schedule entitlement revocation at ends_at
    ↓
```

# Grace Period System

## Grace Period Flow

```text
Payment fails
    ↓
Status → Past Due
Grace period starts (3 days default)
    ↓
Day 1: Email notification
Day 2: In-app banner
Day 3: Final warning
    ↓
If payment recovered: status → Active
If grace expires: status → Unpaid, entitlements revoked
```

## Grace Period Configuration

```php
// config/subscriptions.php
'grace_period_days' => 3,
'grace_period_notifications' => [
    1 => 'Email notification',
    2 => 'In-app banner',
    3 => 'Final warning email',
],
'retry_schedule' => [0, 24, 72], // hours
'max_retries' => 3,
```

# Entitlement System Deep Dive

## Entitlement Resolution Pipeline

The entitlement system resolves what a user can access based on their subscription, add-ons, grants, and promotions. It follows a strict resolution order where each layer can override the previous.

### Resolution Order

```text
1. Free tier defaults (always available to all users)
2. Base plan entitlements (from active subscription)
3. Subscription item entitlements (add-ons and extras)
4. Admin grants (manual overrides)
5. Promotional grants (marketing campaigns)
6. Expired entitlement filtering (remove expired)
7. Cache storage (Redis with 60-second TTL)
```

### Entitlement Set Value Object

```php
class EntitlementSet
{
    protected array $entitlements = [];

    public function add(string $key, mixed $value, ?Carbon $expiresAt = null): self
    {
        $this->entitlements[$key] = new EntitlementValue(
            value: $value,
            expiresAt: $expiresAt,
        );
        return $this;
    }

    public function has(string $key): bool
    {
        return isset($this->entitlements[$key])
            && !$this->entitlements[$key]->isExpired();
    }

    public function value(string $key, mixed $default = null): mixed
    {
        if (!$this->has($key)) {
            return $default;
        }
        return $this->entitlements[$key]->value;
    }

    public function merge(EntitlementSet $other): self
    {
        foreach ($other->entitlements as $key => $value) {
            $this->entitlements[$key] = $value;
        }
        return $this;
    }

    public function applyGrant(EntitlementGrant $grant): self
    {
        $this->entitlements[$grant->key] = new EntitlementValue(
            value: $grant->value,
            expiresAt: $grant->expires_at,
        );
        return $this;
    }

    public function filterActive(): self
    {
        $this->entitlements = array_filter(
            $this->entitlements,
            fn($e) => !$e->isExpired()
        );
        return $this;
    }

    public function toArray(): array
    {
        return array_map(fn($e) => $e->value, $this->entitlements);
    }
}
```

# Subscription Lifecycle Deep Dive

## State Machine Implementation

```php
class SubscriptionStateMachine
{
    protected array $allowedTransitions = [
        'incomplete' => ['trialing', 'incomplete_expired'],
        'trialing' => ['active', 'past_due', 'canceled'],
        'active' => ['past_due', 'canceled', 'unpaid'],
        'past_due' => ['active', 'unpaid', 'canceled'],
        'canceled' => ['active', 'expired'],
        'expired' => [], // terminal
        'unpaid' => [], // terminal
        'incomplete_expired' => [], // terminal
    ];

    public function canTransition(Subscription $subscription, string $newStatus): bool
    {
        $current = $subscription->status;
        return in_array($newStatus, $this->allowedTransitions[$current] ?? []);
    }

    public function transition(Subscription $subscription, string $newStatus, array $context = []): void
    {
        if (!$this->canTransition($subscription, $newStatus)) {
            throw new InvalidTransitionException(
                "Cannot transition from {$subscription->status} to {$newStatus}"
            );
        }

        $fromStatus = $subscription->status;

        // Call specific transition method
        $method = 'transitionTo' . Str::studly($newStatus);
        if (method_exists($this, $method)) {
            $this->{$method}($subscription, $context);
        }

        // Audit trail
        $subscription->statusHistories()->create([
            'from_status' => $fromStatus,
            'to_status' => $newStatus,
            'changed_by' => auth()->id(),
            'metadata' => $context,
        ]);
    }
}
```

# Trial System Deep Dive

## Trial Flow

```text
User subscribes to plan with trial
    ↓
Payment method collected (no charge)
    ↓
Subscription enters Trialing state
    ↓
14-day countdown begins
    ↓
[end of trial]
    ↓
Payment method charged
    ↓
Success → Active
Failure → Past Due (grace period)
```

## Trial Eligibility Rules

1. **One trial per plan type per user lifetime.** A user who tried Pro cannot trial Pro again. They can trial Team (different tier).
2. **One trial per billing entity.** If a user was on a team subscription trial, their individual trial eligibility is unaffected.
3. **Trial reset on admin grant.** Admins can reset trial eligibility for support purposes.
4. **Trial not available on Free plan.** Free is always free — no trial needed.

## Proration Calculation

```php
function calculateProration(Subscription $sub, Plan $newPlan): float
{
    $daysRemaining = $sub->period()->daysRemaining();
    $daysTotal = $sub->period()->daysTotal();
    $credit = $sub->plan->price * ($daysRemaining / $daysTotal);

    return max(0, $newPlan->price - $credit);
}
```

# Troubleshooting

## Common Issues

| Issue | Cause | Solution |
|---|---|---|
| Entitlements not updating | Cache not invalidated | Clear Redis cache |
| Webhook not processing | Signature verification failed | Check webhook secret |
| Subscription not renewing | Payment method expired | Notify user to update |
| Trial not starting | Payment method invalid | Validate card details |
| Upgrade not prorating | Plan price not set | Verify plan pricing |
| Download limit not enforced | Entitlements not synced | Re-sync entitlements |
