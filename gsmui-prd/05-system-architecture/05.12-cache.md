# 05.12 - Cache Architecture

**Project:** GsmUi
**Architecture:** Redis Cache Layer
**Framework:** Laravel 13 + Redis
**Version:** 1.0.0

---

# Purpose

The Cache Layer reduces database load and improves response times by storing frequently accessed and computationally expensive data in Redis.

Caching is treated as an optimization layer only. The database remains the source of truth.

---

# Objectives

The caching strategy should:

* Reduce database queries
* Improve page load times
* Minimize API latency
* Support cache invalidation
* Scale horizontally
* Provide predictable cache keys
* Avoid stale data

---

# Cache Principles

* Cache read-heavy data.
* Never cache business transactions.
* Keep cache keys predictable.
* Invalidate on writes.
* Use cache tags where supported.
* Prefer event-driven invalidation.

# Cache Strategies

## Read-Through Cache

When a cache miss occurs, the application reads from the database and populates the cache automatically.

Pattern:

```text id="cstrat01"
Request
   │
   ▼
Check Cache
   │
   ├── Hit → Return
   │
   └── Miss → Query DB → Store in Cache → Return
```

Use for:

* Component detail pages
* User profiles
* Theme metadata
* Documentation pages

---

## Write-Through Cache

The application writes to both the cache and the database simultaneously.

Pattern:

```text id="cstrat02"
Write Request
   │
   ├── Write to DB
   │
   └── Write to Cache
   │
   ▼
Return Success
```

Use for:

* Session data
* Frequently updated counters
* Real-time metrics

---

## Write-Behind (Asynchronous) Cache

Writes go to cache first, then asynchronously flush to the database.

Pattern:

```text id="cstrat03"
Write Request
   │
   ▼
Write to Cache
   │
   ▼
Queue DB Write
   │
   ▼
Return Success
```

Use for:

* Analytics counters
* Activity logs
* Non-critical metrics

Risk: Data loss if cache fails before flush.

---

## Cache-Aside (Lazy Loading)

The most common pattern in GsmUi. Application code manages cache reads and writes explicitly.

Pattern:

```php id="cstrat04"
function GetComponent(int $id): Component
{
    $key = "gsmui:components:{$id}";

    return Cache::remember($key, now()->addHour(), function () use ($id) {
        return Component::with(['category', 'author', 'variants'])->findOrFail($id);
    });
}
```

This is the default strategy for all GsmUi domain models.

---

## Refresh-Ahead Cache

Proactively refresh cache entries before they expire.

Pattern:

```text id="cstrat05"
Background Job
   │
   ▼
Check TTL Remaining
   │
   ├── < 20% → Refresh Cache
   │
   └── ≥ 20% → Skip
```

Use for:

* Homepage content
* Navigation menus
* Popular component listings
* Pricing pages

Benefits:

* Reduces cache miss rate
* Smooths latency spikes
* Prevents stampede on popular keys

---

## Multi-Level Caching

GsmUi employs multiple cache layers for optimal performance.

```text id="cstrat06"
Browser Cache (HTTP headers)
   │
   ▼
CDN Cache (edge)
   │
   ▼
Application Cache (Redis)
   │
   ▼
Database Query Cache
```

Each layer serves a different purpose:

| Layer | TTL | Purpose | Example |
|-------|-----|---------|---------|
| Browser | Varies | Static assets, pages | CSS, JS, images |
| CDN | 5-60 min | Edge-cached HTML, API | Homepage, search results |
| Redis | 1-24 hr | Business data cache | Components, themes, docs |
| Query Cache | Indefinite | MySQL query cache | Schema metadata |

# Cache Stampede Prevention

## Problem

When a popular cache key expires, many concurrent requests hit the database simultaneously.

## Solutions

### Lock-Based Warming

```text id="cstamp01"
Request 1 → Acquire Lock → Refresh Cache → Release Lock
Request 2 → Wait for Lock → Read Cache
Request 3 → Wait for Lock → Read Cache
```

### Staggered TTLs

Add random jitter to TTLs to prevent synchronized expiration.

```php id="cstamp02"
$ttl = 3600 + random_int(0, 300); // 1 hour ± 5 minutes
Cache::remember($key, $ttl, $callback);
```

### Probabilistic Early Expiration

Randomly refresh before TTL expires under high load.

```php id="cstamp03"
$remainingTtl = Cache::store('redis')->ttl($key);
$totalTtl = 3600;
$probability = max(0, ($totalTtl - $remainingTtl) / $totalTtl);

if (rand() / getrandmax() < $probability * 0.1) {
    // Refresh cache in background
    RefreshCacheJob::dispatch($key);
}
```

### Background Refresh

Always refresh popular caches in the background rather than synchronously.

```php id="cstamp04"
// In a queued job
class RefreshPopularComponents implements ShouldQueue
{
    public function handle(): void
    {
        $components = Component::popular()->get();

        Cache::tags('components')->put(
            'gsmui:components:popular',
            $components,
            now()->addHour()
        );
    }
}
```

# Cache Implementation Patterns

## Repository Cache Pattern

Every repository implements a consistent caching approach.

```php id="cimp01"
class ComponentRepository
{
    public function find(int $id): Component
    {
        return Cache::tags(['components'])
            ->remember(
                "gsmui:components:{$id}",
                now()->addHour(),
                fn () => $this->model->with(['category', 'author'])->findOrFail($id)
            );
    }

    public function findMany(array $ids): Collection
    {
        $cacheKey = 'gsmui:components:batch:' . md5(implode(',', $ids));

        return Cache::tags(['components'])
            ->remember($cacheKey, now()->addHour(), function () use ($ids) {
                return $this->model->whereIn('id', $ids)->get();
            });
    }

    public function invalidate(int $id): void
    {
        Cache::tags(['components'])->forget("gsmui:components:{$id}");
        Cache::tags(['components'])->forget('gsmui:components:list');
    }
}
```

## Service Cache Pattern

Services coordinate cache invalidation across multiple repositories.

```php id="cimp02"
class ComponentService
{
    public function update(UpdateComponentData $data): Component
    {
        $component = $this->repository->find($data->id);

        // Update
        $component->update($data->toArray());

        // Invalidate
        $this->repository->invalidate($component->id);
        $this->cacheService->invalidateTag('components');

        // Event
        ComponentUpdated::dispatch($component);

        return $component->fresh();
    }
}
```

## Cache Decorator Pattern

Wrap repositories with caching as a transparent layer.

```php id="cimp03"
class CachedComponentRepository implements ComponentRepositoryInterface
{
    public function __construct(
        private ComponentRepository $repository,
        private CacheManager $cache
    ) {}

    public function find(int $id): Component
    {
        return $this->cache->tags(['components'])
            ->remember(
                "gsmui:components:{$id}",
                now()->addHour(),
                fn () => $this->repository->find($id)
            );
    }
}
```

# Cache Invalidation Patterns

## Event-Driven Invalidation

Domain events trigger cache invalidation.

```php id="cinv01"
class ComponentUpdatedListener
{
    public function handle(ComponentUpdated $event): void
    {
        $component = $event->component;

        // Invalidate specific component
        Cache::tags(['components'])->forget("gsmui:components:{$component->id}");

        // Invalidate lists
        Cache::tags(['components'])->forget('gsmui:components:list');
        Cache::tags(['components'])->forget('gsmui:components:popular');

        // Invalidate related
        Cache::tags(['categories'])->forget("gsmui:categories:{$component->category_id}");
    }
}
```

## Tag-Based Invalidation

Flush all caches for a domain at once.

```php id="cinv02"
// Invalidate all component caches
Cache::tags(['components'])->flush();

// Invalidate all theme caches
Cache::tags(['themes'])->flush();
```

## Version-Based Invalidation

Append version to cache keys. Bump version to invalidate all.

```php id="cinv03"
$version = Cache::get('gsmui:cache:version:components', 1);
$key = "gsmui:components:v{$version}:{$id}";
```

## Conditional Invalidation

Only invalidate when changes are significant.

```php id="cinv04"
class ComponentUpdatedListener
{
    public function handle(ComponentUpdated $event): void
    {
        $dirty = $event->component->getDirty();

        // Only invalidate search index if searchable fields changed
        if (array_intersect(['name', 'description', 'tags'], array_keys($dirty))) {
            $this->searchService->reindex($event->component);
        }

        // Always invalidate detail cache
        Cache::tags(['components'])->forget("gsmui:components:{$event->component->id}");
    }
}
```

# Cache Testing Strategies

## Unit Tests

Test cache behavior in isolation.

```php id="ctest01"
public function test_component_is_cached_after_first_fetch(): void
{
    $component = Component::factory()->create();

    // First fetch - cache miss
    $result = $this->repository->find($component->id);
    $this->assertNotNull($result);

    // Verify cache exists
    $this->assertTrue(
        Cache::tags(['components'])->has("gsmui:components:{$component->id}")
    );
}

public function test_cache_is_invalidated_on_update(): void
{
    $component = Component::factory()->create();

    // Populate cache
    $this->repository->find($component->id);

    // Update
    $component->update(['name' => 'Updated']);

    // Verify cache is gone
    $this->assertFalse(
        Cache::tags(['components'])->has("gsmui:components:{$component->id}")
    );
}
```

## Integration Tests

Test cache behavior across multiple services.

```php id="ctest02"
public function test_cache_invalidation_cascade(): void
{
    $theme = Theme::factory()->create();
    $component = Component::factory()->create(['theme_id' => $theme->id]);

    // Populate caches
    $this->componentRepo->find($component->id);
    $this->themeRepo->find($theme->id);

    // Update theme
    $this->themeService->update($theme->id, ['name' => 'New Name']);

    // Both caches should be invalidated
    $this->assertFalse(Cache::tags(['themes'])->has("gsmui:themes:{$theme->id}"));
    $this->assertFalse(Cache::tags(['components'])->has("gsmui:components:{$component->id}"));
}
```

## Performance Tests

Verify cache hit ratios under load.

```php id="ctest03"
public function test_cache_hit_ratio_under_load(): void
{
    $componentIds = Component::factory()->count(100)->create()->pluck('id');

    // Warm cache
    foreach ($componentIds as $id) {
        $this->repository->find($id);
    }

    // Simulate 1000 requests
    $hits = 0;
    for ($i = 0; $i < 1000; $i++) {
        $id = $componentIds->random();
        $key = "gsmui:components:{$id}";

        if (Cache::tags(['components'])->has($key)) {
            $hits++;
        }

        $this->repository->find($id);
    }

    $hitRatio = $hits / 1000;
    $this->assertGreaterThan(0.9, $hitRatio);
}
```

# Cache Monitoring

## Metrics to Track

| Metric | Description | Alert Threshold |
|--------|-------------|-----------------|
| Hit Ratio | Percentage of cache hits vs. total requests | < 85% |
| Miss Ratio | Percentage of cache misses | > 15% |
| Eviction Rate | Keys evicted per minute | > 100/min |
| Memory Usage | Redis memory consumption | > 80% of limit |
| Key Count | Total keys in Redis | > 100,000 |
| Connection Count | Active Redis connections | > 100 |
| Average Lookup Time | Time per cache operation | > 5ms |
| Lock Contention | Failed lock acquisitions | > 10/hour |

# Cache Disaster Recovery

## Scenarios

| Scenario | Impact | Recovery |
|----------|--------|----------|
| Redis crash | All cache misses | Application falls back to DB |
| Redis OOM | Partial cache loss | Eviction + warmup |
| Network partition | Stale reads possible | TTL ensures eventual freshness |
| Accidental flush | Cold cache | Trigger warmup job |
| Cache poisoning | Bad data served | Flush affected tags, re-validate |

## Recovery Steps

```text id="cdr01"
Redis Failure Detected
   │
   ▼
Log Incident
   │
   ▼
Application Fallback to DB
   │
   ▼
Alert Operations Team
   │
   ▼
Redis Restored / Restarted
   │
   ▼
Dispatch Cache Warmup Job
   │
   ▼
Verify Cache Hit Ratio
   │
   ▼
Resume Normal Operations
```

## Backup Strategy

* Redis snapshots (RDB) every 15 minutes
* Redis AOF (Append-Only File) for durability
* Test restoration monthly
* Monitor backup file integrity

# Cache API

## CacheService Interface

```php id="capio01"
interface CacheServiceInterface
{
    public function remember(string $key, int $ttl, callable $callback);
    public function forget(string $key): void;
    public function flush(string $tag): void;
    public function warm(string $tag, callable $callback, int $ttl): void;
    public function lock(string $name, int $timeout = 10): bool;
    public function release(string $name): void;
    public function tags(array $tags): static;
    public function get(string $key);
    public function put(string $key, $value, int $ttl): bool;
    public function increment(string $key, int $value = 1): int;
    public function decrement(string $key, int $value = 1): int;
}
```

## Usage in Services

```php id="capio02"
class SearchService
{
    public function __construct(
        private CacheServiceInterface $cache
    ) {}

    public function suggestions(string $query): array
    {
        return $this->cache
            ->tags(['search'])
            ->remember(
                "gsmui:search:suggestions:" . md5($query),
                now()->addMinutes(30),
                fn () => $this->computeSuggestions($query)
            );
    }
}
```

## Component Cache Implementation

Complete implementation for component caching.

```php id="cimpl01"
class ComponentCache
{
    private const TAG = 'components';
    private const TTL = 3600; // 1 hour

    public function remember(int $id, callable $callback): Component
    {
        return Cache::tags([self::TAG])
            ->remember(
                "gsmui:components:{$id}",
                self::TTL,
                $callback
            );
    }

    public function rememberList(string $key, callable $callback, int $ttl = 900): Collection
    {
        return Cache::tags([self::TAG])
            ->remember(
                "gsmui:components:list:{$key}",
                $ttl,
                $callback
            );
    }

    public function invalidate(int $id): void
    {
        Cache::tags([self::TAG])->forget("gsmui:components:{$id}");
        Cache::tags([self::TAG])->forget('gsmui:components:list:*');
    }

    public function invalidateAll(): void
    {
        Cache::tags([self::TAG])->flush();
    }
}
```

## Cache Warming Implementation

### Warming Service

```php id="cwarm03"
class CacheWarmingService
{
    public function warmAll(): void
    {
        $this->warmNavigation();
        $this->warmHomepage();
        $this->warmFeaturedComponents();
        $this->warmSettings();
        $this->warmSearchSuggestions();
        $this->warmPopularContent();
    }

    private function warmNavigation(): void
    {
        $navigation = Navigation::where('is_active', true)
            ->orderBy('order')
            ->get();

        Cache::tags(['navigation'])
            ->put('gsmui:navigation:main', $navigation, now()->addHours(6));
    }

    private function warmHomepage(): void
    {
        $featured = Component::where('is_featured', true)
            ->with(['category', 'author'])
            ->limit(6)
            ->get();

        Cache::tags(['homepage'])
            ->put('gsmui:homepage:featured', $featured, now()->addMinutes(15));
    }

    private function warmFeaturedComponents(): void
    {
        $components = Component::where('is_featured', true)
            ->orWhere('download_count', '>', 1000)
            ->with(['category', 'author'])
            ->limit(20)
            ->get();

        Cache::tags(['components'])
            ->put('gsmui:components:popular', $components, now()->addHour());
    }

    private function warmSettings(): void
    {
        $settings = Setting::pluck('value', 'key')->toArray();

        Cache::tags(['settings'])
            ->put('gsmui:settings:all', $settings, now()->addHours(24));
    }
}
```

### Custom Metrics

```php id="cmetric02"
class CustomCacheMetrics
{
    public function trackHitRatio(): void
    {
        $hits = Cache::get('metrics:hits', 0);
        $misses = Cache::get('metrics:misses', 0);
        $total = $hits + $misses;

        $ratio = $total > 0 ? ($hits / $total) * 100 : 0;

        Log::info('Cache hit ratio', [
            'hits' => $hits,
            'misses' => $misses,
            'ratio' => round($ratio, 2) . '%',
        ]);
    }

    public function trackLatency(string $operation, float $ms): void
    {
        Log::debug('Cache latency', [
            'operation' => $operation,
            'latency_ms' => $ms,
        ]);
    }
}
```

# Cache Best Practices Summary

## Do

* Cache read-heavy, write-infrequent data
* Use short TTLs for critical data
* Implement cache warming after deployment
* Monitor cache hit ratio continuously
* Use tags for grouped invalidation
* Test cache behavior in integration tests
* Document cache key conventions
* Implement graceful degradation

## Do Not

* Cache business transactions
* Cache authentication state
* Cache CSRF tokens
* Cache PII or sensitive data
* Cache without TTL (indefinite)
* Ignore cache invalidation
* Assume cache is always available
* Cache highly dynamic data

# Cache Operations Reference

## Read Operations

| Operation | Description | Return |
|-----------|-------------|--------|
| Cache::get() | Get value by key | Mixed or null |
| Cache::many() | Get multiple values | Array |
| Cache::has() | Check if key exists | Boolean |
| Cache::remember() | Get or compute and cache | Mixed |
| Cache::rememberForever() | Get or compute and cache forever | Mixed |

## Write Operations

| Operation | Description | Return |
|-----------|-------------|--------|
| Cache::put() | Store value with TTL | Boolean |
| Cache::add() | Store if key doesn't exist | Boolean |
| Cache::forever() | Store without TTL | Boolean |
| Cache::increment() | Increment numeric value | Integer |
| Cache::decrement() | Decrement numeric value | Integer |

## Delete Operations

| Operation | Description | Return |
|-----------|-------------|--------|
| Cache::forget() | Remove specific key | Boolean |
| Cache::flush() | Remove all keys | Boolean |
| Cache::tags()->flush() | Remove all keys with tag | Boolean |

## Lock Operations

| Operation | Description | Return |
|-----------|-------------|--------|
| Cache::lock() | Acquire named lock | Lock object |
| Lock::get() | Try to acquire lock | Boolean |
| Lock::release() | Release acquired lock | void |
| Lock::block() | Wait for lock | void |

# Risk

| Risk | Likelihood | Impact | Mitigation |
|------|-----------|--------|------------|
| Stale data served to users | Medium | High | Event-driven invalidation, short TTLs for critical data, manual purge capability |
| Redis memory exhaustion | Medium | High | Memory limits, eviction policies (allkeys-lru), monitoring alerts |
| Cache stampede on popular content | Low | High | Lock-based cache warming, staggered TTLs, background refresh |
| Cache poisoning via malicious input | Low | Critical | Key sanitization, input validation before caching, namespace isolation |
| Redis failure causing full cache miss | Low | High | Graceful degradation to database, automatic recovery, health checks |
| Over-caching sensitive data | Medium | High | Never cache PII, tokens, payment data; audit cache contents regularly |
| Invalidation logic bugs causing permanent staleness | Medium | Medium | Invalidation tests, cache versioning, TTL as safety net |

# Security

| Concern | Control |
|---------|---------|
| Sensitive data in cache | Never cache passwords, tokens, PII, payment details |
| Redis network exposure | Private network only, authentication enabled, no public access |
| Cache key injection | Sanitize all cache keys, use namespaced prefixes (`gsmui:`) |
| Cross-tenant data leakage | User-specific caches include user ID in key; tagged by user |
| Cache header security | Set appropriate `Cache-Control` and `Vary` headers on responses |
| Stale session data | Session cache TTL enforced, invalidation on logout and password change |
| Audit trail integrity | Audit logs never cached; always read from database |

Cache security rules:

1. **No PII in cache**: User emails, names, addresses, and preferences must not appear in cache keys or values
2. **No auth tokens**: API keys, recovery codes, and session tokens are excluded from caching
3. **No payment data**: Card details, invoices, and subscription tokens are never cached
4. **Redis authentication**: Require password authentication for all Redis connections
5. **TLS for Redis**: Use encrypted connections in production environments
6. **Cache isolation**: Separate cache prefixes for different environments (dev, staging, production)
