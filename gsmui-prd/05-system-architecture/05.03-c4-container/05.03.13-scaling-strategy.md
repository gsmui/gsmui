# 05.03.13 - Scaling Strategy

**Project:** GsmUi
**Architecture:** C4 Model – Level 2 (Container)
**Container:** Platform Infrastructure
**Framework:** Laravel 13 + Infrastructure as Code
**Version:** 1.0.0

# Purpose

This document describes the scaling strategy for the GsmUi platform, covering horizontal scaling, vertical scaling, autoscaling policies, capacity planning, and resource management. Scaling ensures that the platform can handle growth in users, content, and traffic while maintaining performance and cost efficiency.

---

# Responsibilities

Scaling strategy is responsible for:

* Defining scaling policies for each tier
* Planning capacity for growth
* Implementing autoscaling triggers
* Managing resource allocation
* Controlling infrastructure costs
* Ensuring SLO compliance under load

---

# Scaling Dimensions

```text
Horizontal:  Add more instances (scale out)
Vertical:    Increase instance size (scale up)
Temporal:    Scale based on time
Predictive:  Scale based on forecasts
```

---

# Scaling by Tier

### Web Tier

| Strategy | Method |
|----------|--------|
| Horizontal | Add web servers behind load balancer |
| Vertical | Increase instance size (CPU/memory) |
| Autoscaling | Scale based on CPU/memory/request count |
| CDN | Offload static assets |

Target: Handle 10,000+ concurrent users per web server.

### Queue Tier

| Strategy | Method |
|----------|--------|
| Horizontal | Add queue worker hosts |
| Vertical | Increase worker memory/timeout |
| Autoscaling | Scale based on queue depth/latency |
| Priority isolation | Separate workers per queue |

Target: Process 1,000+ jobs/minute across all queues.

### Database Tier

| Strategy | Method |
|----------|--------|
| Horizontal | Add read replicas |
| Vertical | Increase instance size (storage/CPU) |
| Sharding | Split data by domain (future) |
| CQRS | Separate read and write models (future) |

Target: 99.9% query performance, <100ms P95.

### Cache Tier

| Strategy | Method |
|----------|--------|
| Horizontal | Add Redis replicas/sharding |
| Vertical | Increase Redis memory |
| Caching | Reduce cache misses |

Target: >90% hit rate, <5ms P99 latency.

# Horizontal Scaling

Horizontal scaling adds more instances to distribute load.

### Web Tier

```text
Baseline: 3 web servers (t3.medium)
Peak: 6 web servers (t3.medium)

Scaling trigger:
- Average CPU > 60%
- Request latency P95 > 500ms
- Queue depth > 500
```

### Queue Tier

```text
Baseline: 2 queue hosts
Peak: 5 queue hosts

Scaling trigger:
- Queue depth > 200 for any queue
- Worker utilization > 80%
- Job latency P95 > 30s
```

### Database Tier

```text
Baseline: 1 primary + 1 replica
Peak: 1 primary + 3 replicas

Scaling trigger:
- Query latency P95 > 100ms
- Connection count > 80% of max
- Replication lag > 1 second
```

---

# Vertical Scaling

Vertical scaling increases resources per instance.

### When to Scale Vertically

* Instance consistently exceeds 70% resource utilization
* Scaling horizontally is not cost-effective
* Application requires more memory per process
* Database requires more I/O capacity

### Limits

Vertical scaling has practical limits:

* Largest instance may not be cost-effective
* Single point of failure risk
* Downtime required for resizing

Prefer horizontal scaling for stateless tiers (web, queue).

# Cost Optimization

### Rightsizing

Regularly review instance utilization and resize:

```text
Over-provisioned: t3.large (20% CPU) → t3.medium
Under-provisioned: t3.medium (85% CPU) → t3.large
```

### Scheduled Scaling

Scale down during off-peak hours:

```text
Web: 6 instances (peak) → 3 instances (off-peak)
Queue: Keep at baseline (jobs are asynchronous)
Database: No scaling down (always available)
```

### Spot Instances

Use spot instances for non-critical workloads:

```text
Queue workers: Spot instances (can tolerate interruption)
Web servers: On-demand (user-facing, must be stable)
Database: On-demand with reserved capacity
```

```php
// App\Services\DatabaseRouter
class DatabaseRouter
{
    public function read(Closure $callback): mixed
    {
        return DB::connection('mysql')->readOnly(function () use ($callback) {
            return $callback();
        });
    }
    
    public function write(Closure $callback): mixed
    {
        return DB::connection('mysql')->transaction(function () use ($callback) {
            return $callback();
        });
    }
    
    public function routeQuery(string $table, string $operation): string
    {
        $readTables = ['themes', 'components', 'posts', 'categories'];
        $writeTables = ['orders', 'payments', 'licenses'];
        
        if (in_array($table, $readTables) && $operation === 'read') {
            return 'mysql_read';
        }
        
        return 'mysql_write';
    }
}
```

### Cache Strategy

```php
// App\Services\CacheManager
class CacheManager
{
    public function remember(string $key, int $ttl, Closure $callback): mixed
    {
        return Cache::tags($this->getTags($key))
                    ->remember($key, $ttl, $callback);
    }
    
    public function invalidate(string $pattern): void
    {
        $keys = Cache::tags([$pattern])->keys();
        Cache::tags([$pattern])->flush();
    }
    
    public function warmCache(): void
    {
        $this->warmThemes();
        $this->warmComponents();
        $this->warmDocumentation();
    }
    
    private function warmThemes(): void
    {
        Theme::published()->chunk(100, function ($themes) {
            foreach ($themes as $theme) {
                Cache::tags(['themes'])->remember(
                    "theme:{$theme->slug}",
                    3600,
                    fn() => $theme->toArray()
                );
            }
        });
    }
    
    private function getTags(string $key): array
    {
        $parts = explode(':', $key);
        return [$parts[0] ?? 'general'];
    }
}
```

### Queue Metrics

```php
// App\Services\QueueMetrics
class QueueMetrics
{
    public function getMetrics(): array
    {
        return [
            'depth' => $this->getQueueDepths(),
            'latency' => $this->getJobLatency(),
            'throughput' => $this->getThroughput(),
            'failed' => $this->getFailedJobs(),
            'workers' => $this->getWorkerCount(),
        ];
    }
    
    private function getQueueDepths(): array
    {
        return [
            'high' => Queue::size('high'),
            'default' => Queue::size('default'),
            'low' => Queue::size('low'),
            'mail' => Queue::size('mail'),
        ];
    }
    
    private function getJobLatency(): array
    {
        return [
            'high' => $this->calculateLatency('high'),
            'default' => $this->calculateLatency('default'),
            'low' => $this->calculateLatency('low'),
        ];
    }
    
    private function calculateLatency(string $queue): float
    {
        $job = DB::table('jobs')
            ->where('queue', $queue)
            ->orderBy('created_at')
            ->first();
        
        if (!$job) {
            return 0;
        }
        
        return now()->diffInSeconds(Carbon::parse($job->created_at));
    }
    
    private function getThroughput(): array
    {
        return [
            'per_minute' => $this->getJobsPerMinute(),
            'per_hour' => $this->getJobsPerHour(),
        ];
    }
    
    private function getJobsPerMinute(): int
    {
        return DB::table('jobs')
            ->where('created_at', '>=', now()->subMinute())
            ->count();
    }
    
    private function getJobsPerHour(): int
    {
        return DB::table('jobs')
            ->where('created_at', '>=', now()->subHour())
            ->count();
    }
    
    private function getFailedJobs(): int
    {
        return DB::table('failed_jobs')->count();
    }
    
    private function getWorkerCount(): int
    {
        return Horizon::runningWorkers()->count();
    }
}
```

```php
class AutoScaler
{
    public function shouldScaleUp(string $tier): bool
    {
        $metrics = $this->getMetrics($tier);
        
        return match($tier) {
            'web' => $metrics['cpu'] > 70 || $metrics['memory'] > 80,
            'queue' => $metrics['queue_depth'] > 200,
            'database' => $metrics['query_latency'] > 100,
            default => false,
        };
    }

    {
        $metrics = $this->getMetrics($tier);
        
        return match($tier) {
            'web' => $metrics['cpu'] < 40 && $metrics['memory'] < 50,
            'queue' => $metrics['queue_depth'] < 50,
            'database' => $metrics['query_latency'] < 50,
            default => false,
        };
    }

    {
        return match($tier) {
            'web' => $this->getWebMetrics(),
            'queue' => $this->getQueueMetrics(),
            'database' => $this->getDatabaseMetrics(),
            default => [],
        };
    }

    {
        return [
            'cpu' => $this->getAverageCpu(),
            'memory' => $this->getAverageMemory(),
            'requests' => $this->getRequestsPerSecond(),

            'queue_depth' => $this->getQueueDepth(),
```

```php
        ];
    }
    
    private function getPercentile(int $percentile): float
    {
        $values = $this->getResponseTimes();
        $index = (int) ceil(($percentile / 100) * count($values)) - 1;
        
        return $values[$index] ?? 0;
    }
    
    private function calculateApdex(): float
    {
        $satisfied = $this->countRequestsUnder(200);
        $tolerating = $this->countRequestsBetween(200, 1200);
        $total = $this->countTotalRequests();
        
        return ($satisfied + ($tolerating / 2)) / $total;
    }
```

# Advanced Scaling Patterns

## Circuit Breaker Pattern

The circuit breaker pattern prevents cascading failures when external services become unavailable.

### Circuit Breaker States

```text
Closed State (Normal)
    │
    ├── Request succeeds → Stay closed
    │
    └── Request fails → Increment failure count
        │
        └── Failure count > threshold
            │
            └── Open State

Open State (Failing)
    │
    ├── All requests fail immediately (no call to service)
    │
    └── After timeout period
        │
        └── Half-Open State

Half-Open State (Testing)
    │
    ├── Test request succeeds → Closed State
    │
    └── Test request fails → Open State
```

### Circuit Breaker Implementation

```php
class CircuitBreaker
{
    private array $failures = [];
    private array $state = [];

    public function call(string $service, Closure $callback): mixed
    {
        if ($this->isOpen($service)) {
            throw new CircuitOpenException("Service {$service} is unavailable");
        }

        try {
            $result = $callback();
            $this->onSuccess($service);
            return $result;
        } catch (\Exception $e) {
            $this->onFailure($service);
            throw $e;
        }
    }

    private function isOpen(string $service): bool
    {
        return ($this->state[$service] ?? 'closed') === 'open'
            && !$this->timeoutExpired($service);
    }

    private function onSuccess(string $service): void
    {
        $this->failures[$service] = 0;
        $this->state[$service] = 'closed';
    }

    private function onFailure(string $service): void
    {
        $this->failures[$service] = ($this->failures[$service] ?? 0) + 1;

        if ($this->failures[$service] >= $this->getThreshold($service)) {
            $this->state[$service] = 'open';
            $this->openedAt[$service] = time();
        }
    }
}
```

```php
// Rate limiting middleware
class RateLimitMiddleware
{
    public function handle(Request $request, Closure $next)
    {
        $key = $this->resolveRateLimitKey($request);
        $limit = $this->getLimit($request->user());

        $current = Cache::increment("rate:{$key}");

        if ($current > $limit) {
            return response()->json([
                'error' => 'Rate limit exceeded',
                'retry_after' => $this->getRetryAfter($key),
            ], 429)->withHeaders([
                'X-RateLimit-Limit' => $limit,
                'X-RateLimit-Remaining' => 0,
                'X-RateLimit-Reset' => $this->getResetTime($key),
            ]);
        }

        $response = $next($request);

        return $response->withHeaders([
            'X-RateLimit-Limit' => $limit,
            'X-RateLimit-Remaining' => $limit - $current,
            'X-RateLimit-Reset' => $this->getResetTime($key),
        ]);
    }
}
```

- Single request needs more CPU
- Horizontal scaling is not cost-effective
- Application has single-node dependencies

### When to Scale Horizontally

- Stateless application servers
- Request volume exceeds single instance capacity
- Need high availability
- Cost-effective at scale

### When to Scale Out (Add Services)

- Separate concerns (web vs. queue vs. scheduler)
- Different resource requirements per service
- Independent scaling needed
- Fault isolation required
