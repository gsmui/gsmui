## Chart Data Contract

Chart widgets hydrate via controller endpoints returning ApexCharts-compatible series:

```json
{
  "chart": {
    "type": "line",
    "series": [{ "name": "Signups", "data": [{ "x": 1754006400000, "y": 128 }] }],
    "labels": [],
    "options": { "yaxis": { "min": 0, "tickAmount": 4 } }
  },
  "meta": { "range": "30d", "generated_at": "..." }
}
```

## Chart Interaction Rules

- Range change triggers re-fetch with loading overlay (no layout shift).
- Hover tooltips show exact values with locale-formatted numbers.
- Click on data point navigates to corresponding list page with date filter applied.
- Legend toggles series visibility; state not persisted.
- Empty data range shows dashed baseline and "No data in range" notice.

## Real-Time Update Flow (WebSocket Path)

1. Server broadcasts `dashboard:health` on private channel `private-dashboard.{userId}` scoped to permission holders.
2. Livewire component listening via Echo updates `SystemHealthWidget` without full poll.
3. If WebSocket disconnected, component silently falls back to 15s polling.
4. Broadcast payload limited to indicator state changes (not full snapshots).

# Permission Checks (Dashboard-Specific)

| Surface | Permission | Enforcement Point |
|---------|------------|-------------------|
| Dashboard page access | `overview.view` | Route middleware + page `canAccess()` |
| Stats cards | Per-stat permission | Card omitted if missing |
| Revenue/finance widgets | `finance.view` | Widget `canView()` |
| System widgets | `system.view` | Widget `canView()` |
| Analytics widgets | `analytics.view` | Widget `canView()` |
| Chart data endpoints | Matching view permission | Controller authorization |
| Quick actions | Per-action permission | Registry + job re-check |
| Layout customization | `overview.customize` | Editor UI hidden without |
| Export from dashboard | `exports.create` | Export request validation |
| Anomaly acknowledge | `overview.view` | Inline action |
| Anomaly false-positive marking | `overview.manage-alerts` | Inline action |

## Permission Edge Rules

- If a widget's data endpoint is called after permission loss mid-session, API returns 403 and widget degrades to placeholder with "Access revoked" note.
- Dashboard never shows widgets the user cannot view even if saved in their layout (layout hydration filters).
- Quick action button visibility = registry permission AND any sudo-mode requirement displayed via lock glyph only after click.

# Acceptance Criteria

## AC-1: Core Load

- **Given** warm cache
- **When** dashboard loads
- **Then** LCP < 2s, all permission-visible widgets rendered, no layout shift after hydration.

## AC-2: Permission Scoping

- **Given** admin without `finance.view`
- **When** dashboard renders
- **Then** no revenue widgets or cards; layout compacts without gaps.

## AC-3: Widget Reorder Persistence

- **Given** admin drags widgets into new order
- **When** page reloads
- **Then** order matches saved layout; version incremented.

## AC-4: Concurrent Layout Save

- **Given** two tabs saving layouts
- **When** second save lands with stale base version
- **Then** 409 returned; UI prompts refresh to latest.

## AC-5: Chart Empty Range

- **Given** range with zero data points
- **When** chart widget hydrates
- **Then** placeholder message shown; no broken axes or console errors.

## AC-6: Health Degradation

- **Given** queue backlog crosses warning threshold
- **When** health poll completes
- **Then** indicator turns warning color within one poll cycle; detail explains threshold.

## AC-7: Anomaly Notification

- **Given** metric deviates > 3σ from baseline for 2 consecutive checks
- **When** detector runs
- **Then** anomaly record created, notification dispatched, widget highlights metric.

## AC-8: False Positive Marking

- **Given** admin with `overview.manage-alerts`
- **When** marking anomaly false-positive
- **Then** record updated, no repeat alert for same window, tuning feedback logged.

## AC-9: Quick Action Audit

- **Given** any quick action executed
- **When** job completes
- **Then** audit entry includes actor, slug, duration, outcome.

## AC-10: Export From Dashboard

- **Given** 10 exports already this hour
- **When** 11th requested
- **Then** 429 with reset time displayed in UI.

# Anomaly Detection Engine

## Detection Pipeline

1. `AnomalyDetectionJob` runs every 10 minutes against configured metrics.
2. Baseline computed from trailing 28-day rolling window at same hour-of-day and day-of-week buckets.
3. Z-score computed against baseline mean/stddev.
4. Alert fires when |z| > 3 for 2 consecutive checks AND outside absolute deadband.
5. Flapping suppression: same metric re-alerts require 6h cooldown unless severity escalates.

## Configured Metrics

| Metric Key | Direction Concerns | Deadband |
|------------|--------------------|----------|
| `signups_hourly` | drop | ±10% |
| `error_rate_5xx` | rise | ±0.1% |
| `queue_wait_p95` | rise | ±30s |
| `api_latency_p95` | rise | ±100ms |
| `checkout_success_rate` | drop | ±2% |
| `download_rate_hourly` | drop | ±15% |
| `login_failure_rate` | rise | ±1% |

## Severity Assignment

| Condition | Severity |
|-----------|----------|
| 3σ ≤ |z| < 4σ | warning |
| |z| ≥ 4σ | critical |
| Outside deadband only | info (logged, no alert) |

## Notification Routing

| Severity | Database | Email | Webhook |
|----------|----------|-------|---------|
| info | no | no | no |
| warning | yes (digest) | no | optional |
| critical | yes (immediate) | yes | yes |

# Sample Filament Code Sketches (Dashboard)

## Widget Class Skeleton

```php
class RevenueChartWidget extends Widget
{
    protected static string $view = 'filament.admin.widgets.revenue-chart';
    protected static ?int $sort = 2;
    protected string $size = 'half';

    public static function canView(): bool
    {
        return Gate::allows('finance.view') || Gate::allows('finance.view-masked');
    }

    public function getData(): array
    {
        return ChartSeriesBuilder::for('revenue')
            ->range($this->config['range'] ?? '30d')
            ->masked(Gate::allows('finance.view-masked'))
            ->build();
    }
}
```

## Chart Series Builder Contract

```php
interface ChartSeriesBuilder
{
    public static function for(string $type): self;
    public function range(string $range): self;
    public function groupBy(string $group): self;
    public function masked(bool $masked): self;
    public function build(): array; // { chart: {...}, meta: {...} }
}
```

Builder reads from `dashboard_stats_cache` and raw event tables; never performs uncached joins on request path.

# Data Quality Rules

| Rule | Enforcement |
|------|-------------|
| Stats never computed from partial windows silently | Partial period flagged in `meta_json` |
| Chart missing points rendered as gaps | `series` omits missing days; gap interpolation off |
| Currency normalization at fixed daily rate | Rate table audited; missing rate → warning banner in widget |
| Timezone consistency | All bucketing UTC; display localized |
| Zero/negative guard | Negative counts impossible (counters monotonic; decrements logged) |
| Checksum on cache writes | Reader validates; mismatch triggers recompute |

# Appendix: Stat Aggregation Query Specifications

## Total Users Aggregation

```sql
SELECT COUNT(*) AS total_users
FROM users
WHERE deleted_at IS NULL
  AND status IN ('active', 'pending');
```

Notes: Suspended users counted in a separate stat key (`users_suspended`) for transparency; never silently excluded from totals.

## Active Subscriptions Aggregation

```sql
SELECT COUNT(DISTINCT user_id) AS active_subscriptions
FROM subscriptions
WHERE status = 'active'
  AND (trial_ends_at IS NULL OR converted_at IS NOT NULL)
  AND (ends_at IS NULL OR ends_at > NOW());
```

## MRR Aggregation

```sql
SELECT SUM(amount_normalized_usd) AS mrr
FROM subscriptions
WHERE status = 'active'
  AND is_trial = false
  AND (ends_at IS NULL OR ends_at > NOW());
```

`amount_normalized_usd` computed at subscription event time using daily FX table; recomputed only on plan change.

## Downloads Aggregation (lifetime)

```sql
SELECT COALESCE(SUM(count), 0) AS downloads_total
FROM component_download_rollups;
```

Backed by hourly rollup table; raw `component_downloads` events retained 90 days.

## API Requests 24h Aggregation

Sourced from gateway log ingestion table (pre-aggregated 5-minute buckets):

```sql
SELECT SUM(request_count) AS api_requests_24h
FROM api_request_buckets
WHERE bucket_at >= NOW() - INTERVAL 24 HOUR;
```

## Delta Period Queries

Each stat runs the same aggregation with a period-shifted window:

| Period | Window Shift |
|--------|--------------|
| wow | -7 days |
| mom | Start of prior calendar month |
| d24h | -24 hours |

Delta = (current − prior) / prior × 100 with zero-guard.

# Appendix: Dashboard Runbook Snippets

## Symptom: All widgets showing stale badges

1. Check `AggregatePlatformStatsJob` last run in Horizon.
2. Verify Redis connectivity (health probe).
3. Manual dispatch: `php artisan gsmui:stats-refresh`.
4. Confirm `calculated_at` advancing; badges clear within TTL.

## Symptom: Charts blank after deploy

1. Verify chart endpoint returns 200 (curl with admin token).
2. Check `BuildChartSnapshotsJob` for failures.
3. Verify `--gsmui-primary` token present in compiled CSS.
4. Clear `dashboard:chart:*` keys; force rebuild.

## Symptom: Anomaly flood

1. Check detector config diff (recent deploys).
2. Review `dashboard_anomalies` for repeated metric key.
3. Apply temporary suppression via settings (`gsmui.admin.alert_suppress`).
4. Tune baseline window or deadband; re-enable with monitoring.
