# Review Workflow (Deep Dive)

## States

```
draft (author) --> submitted --> in_review --> approved --> released
                                     |                        |
                                     +--> rejected ---------> resubmitted
                                     |
                                     +--> needs_changes ----> resubmitted
                     any --> archived (admin)
```

| State | Actor | Description |
|-------|-------|-------------|
| draft | Author | Private, not submitted |
| submitted | Author | Queued for review |
| in_review | Admin | Assigned to reviewer |
| approved | Admin | Passed review, publishable |
| needs_changes | Admin | Sent back with checklist |
| rejected | Admin | Final rejection with reason |
| released | System | Version tagged and public |
| archived | Admin | Removed from public, kept in history |

## Review Page Structure

| Section | Content |
|---------|---------|
| Checklist panel | Automated check results (see below) |
| Code preview | Sandboxed file tree (read-only) |
| Live preview | Iframe sandbox of demo page |
| Metadata card | Author info, license, dependencies, size |
| Feedback composer | Structured feedback with severity tags |
| Decision bar | Approve / Needs changes / Reject buttons |

## Automated Checks (Pre-Review)

On submission, a pipeline runs and populates the checklist:

| Check | Pass Criteria |
|-------|---------------|
| File structure | Required manifest, blade views, expected dirs |
| Manifest validation | JSON schema valid, version semver |
| Blade lint | No syntax errors, no `@php` abuse patterns |
| Static analysis | No dangerous functions (eval, exec, shell_exec) |
| Dependencies | Declared deps exist in registry, no version conflicts |
| Screenshot | At least one, dimensions ≥ 800x600 |
| Documentation | README + at least one usage example |
| Accessibility scan | axe-core on demo page: 0 critical violations |
| Size limits | Package < 25MB, files < 2MB each |
| Naming | Slug unique, no trademark conflicts with blocked list |

Check results display as pass/fail/warn with logs; reviewer can override warns with justification (audited).

## Reviewer Assignment

- Auto-assign via round-robin among `components.review` holders unless manually claimed.
- Claim button locks item to reviewer (15-min soft lock; others see "Jane is reviewing").
- Reassignment allowed by `components.review` holders with note.
- Unclaimed > 24h escalates notification to content lead.

## Decision Requirements

| Decision | Requirements |
|----------|--------------|
| Approve | Checklist complete (warns acknowledged); optional comment |
| Needs changes | At least 1 actionable item with severity; sets resubmission deadline (default 30 days) |
| Reject | Reason category required (quality/security/duplicate/scope) + free text |

Post-decision:

- Author notified by email + platform notification with decision summary.
- Approve triggers release pipeline (version tag, publish to library, CDN sync).
- Rejected items enter 90-day resubmission cooldown unless appeal granted.

## Appeal Process

1. Author files appeal within 14 days of rejection.
2. Appeal appears in dedicated "Appeals" queue (permission `components.review`).
3. Second reviewer (not original) decides: uphold / overturn / request resubmission.
4. All appeal history retained in audit timeline.

# Admin User Flows

## Flow: Daily Review Session

| Step | Action | Outcome |
|------|--------|---------|
| 1 | Open Review queue view | Oldest-first pending list with SLA badges |
| 2 | Claim a submission | Lock indicator, checklist loads |
| 3 | Review automated checks | Warns expanded with logs |
| 4 | Inspect code + live preview | Sandbox interactions safe |
| 5 | Compose feedback (if needed) | Severity-tagged, anchored |
| 6 | Decide | Approve / Needs changes / Reject |
| 7 | Release pipeline fires | Version tagged, author notified |
| 8 | Queue badge updates | Count decrements |

## Flow: Security Rejection

| Step | Action | Outcome |
|------|--------|---------|
| 1 | Static analysis flags `eval` usage | Checklist fails with highlighted file |
| 2 | Reviewer confirms finding | Code location linked |
| 3 | Reject with security template | Reason category `security` |
| 4 | Flag author profile | Security note added (visible to security role) |
| 5 | Resubmission cooldown | 90 days; appeal possible |
| 6 | Security center notified | Finding linked to component record |

## Flow: Feature a Popular Component

| Step | Action | Outcome |
|------|--------|---------|
| 1 | Analytics shows high downloads + rating | Admin identifies candidate |
| 2 | Verify quality (demo, docs) | Checklist spot check |
| 3 | Toggle featured | Confirmation with carousel impact |
| 4 | Homepage carousel updates | Cache invalidated |
| 5 | Author notified | "Your component was featured" |

## Flow: Bulk Category Migration

| Step | Action | Outcome |
|------|--------|---------|
| 1 | Filter components lacking category update | Selection |
| 2 | Bulk assign new category | Confirmation |
| 3 | Public categorization updates | Search facets refreshed |
| 4 | Audit | Bulk entry with count + actor |

## Flow: Handle Resubmission After Changes

| Step | Action | Outcome |
|------|--------|---------|
| 1 | Author uploads fix, resubmits | Status → submitted (resubmitted flag) |
| 2 | Reviewer sees diff vs prior version | Version timeline diff highlighted |
| 3 | Original feedback items tracked | Resolution checklist shows addressed items |
| 4 | Approve if resolved | Normal approval flow |
| 5 | If not resolved | Second needs-changes with escalation note |

# Security Detail

|---------|----------------|

| Sandbox preview | `sandbox="allow-scripts"` iframe, separate subdomain, no same-origin |

| Reviewer isolation | Reviewers see only assigned claims by default |
| Author identity | No cross-author draft visibility |
| Appeal integrity | Decision maker constraint + full timeline |

# Version & Release Pipeline

## Release Job Steps

| Step | Action | Failure Handling |
|------|--------|------------------|
| 1 | Tag version in database | Retry 3x |
| 2 | Verify checksum of approved artifact | Abort + alert |
| 3 | Copy to versioned path on private disk | Retry 3x |
| 4 | Sync to CDN edge locations | Async; degraded flag on partial |
| 5 | Update `components.latest_version` counter | Transactional with step 4 |
| 6 | Invalidate library caches | Always runs |
| 7 | Dispatch author notification | Queue |
| 8 | Write audit entry | Always runs |

## Rollback (Post-Release Issue)

1. Super-admin triggers `rollback` action on released version.
2. CDN serves previous version immediately (kept N-2 versions).
3. Status marked `degraded-release`; author notified.
4. Incident record created linking to rollback.
5. Investigation notes required before re-release.

# Component Runbooks

## Symptom: Release pipeline failing repeatedly

1. Inspect `ReleaseComponentJob` failures (checksum vs CDN step).
2. If checksum mismatch: artifact corruption suspected — re-run checks, quarantine file, security alert.
3. If CDN failure: check provider status; enable degraded-release flag; serve N-1 version.
4. Author communication via support template.

## Symptom: Spike in rejected submissions

1. Check rejection reasons distribution report.
2. If single author: review author history; possible policy violation.
3. If systemic (same check): inspect check pipeline recent changes.
4. Communicate guidance update to author docs.

## Symptom: Review queue SLA breached

1. Verify reviewer availability; reassign claims.
2. Enable fast-track for eligible items.
3. Notify content lead (automatic at threshold).
4. Post-hoc: review automation coverage gaps.

# Acceptance Criteria (Components, Extended)

## AC-CMP-1: Claim Lock Integrity

- **Given** Jane claimed a component
- **When** Bob attempts to claim
- **Then** blocked with visible lock owner and remaining soft-lock time.

## AC-CMP-2: Automated Check Evidence

- **Given** a submission completed checks
- **When** reviewer opens checklist
- **Then** each check shows pass/warn/fail with expandable logs and file anchors.

## AC-CMP-3: Fast-Track Eligibility

- **Given** eligible author's small diff submission
- **When** checks all pass
- **Then** fast-track confirmation available with audit flag.

## AC-CMP-4: Rejection Cooldown

- **Given** a rejected component
- **When** author attempts resubmission before 90 days
- **Then** blocked unless appeal overturn granted.

## AC-CMP-5: Release Rollback

- **Given** released version with issue
- **When** rollback executed
- **Then** CDN serves previous version within 60 seconds; degraded flag visible.

## AC-CMP-6: Appeal Independence

- **Given** an appeal filed
- **When** original reviewer assigned
- **Then** system refuses and requires different reviewer.

## AC-CMP-7: Download Integrity

- **Given** 100 concurrent downloads
- **When** reconciliation job runs
- **Then** counters match origin logs within tolerance; self/bot exclusions applied.

## AC-CMP-8: Review Moderation

- **Given** auto-flagged spam review
- **When** moderator rejects
- **Then** rating aggregate recalculates; user notified.

# Appendix: Complete Automated Check Specifications

## Check: File Structure

| Expected Entry | Requirement |
|----------------|-------------|
| `gsmui.component.json` | Root level, valid JSON |
| `README.md` | Root level, ≥ 200 chars |
| `LICENSE` | Root level |

| `demos/*.blade.php` | Per manifest demos |

Missing entries → fail with precise path message.

## Check: Manifest Validation

Validates against JSON Schema (`schemas/component.manifest.json` v1). Versioning: schema `v` field enforced; unknown versions fail with upgrade guidance.

## Check: Blade Lint

| Rule | Severity |
|------|----------|
| Unbalanced directives (@if without @endif) | fail |
| `@php` blocks > 50 lines | warn |
| Inline `<script>` tags | fail |
| Undefined component references (`<x-unknown>`) | warn |
| Deprecated directive usage | warn |

## Check: Static Analysis

Uses PHP-Parser AST with custom visitor set:

| Visitor | Detects | Severity |
|---------|---------|----------|
| `DangerousFunctionVisitor` | eval/exec/system/passthru/popen/proc_* | fail |
| `BacktickOperatorVisitor` | Shell backticks | fail |
| `UnserializeVisitor` | unserialize without allowed_classes option | fail |
| `RemoteFetchVisitor` | curl/file_get_contents with variable URL | warn |
| `Base64BlobVisitor` | base64_decode on literals > 1KB | warn |

## Check: Dependency Scan

- Declared composer deps matched against public registry metadata.
- Version conflicts against `gsmui_min_version` checked.
- Dependencies with known advisories (composer audit DB snapshot) → fail.

## Check: Accessibility Scan

Playwright run on isolated demo page:

| Rule Set | Threshold |
|----------|-----------|
| axe-core | 0 critical, ≤ 3 serious (warn) |
| Keyboard trap detection | 0 (fail) |
| Color contrast (text) | ≥ 4.5:1 (fail under) |

## Check: Size & Entropy

| Limit | Value |
|-------|-------|
| Package total | ≤ 25MB |
| Single file | ≤ 2MB |
| File count | ≤ 500 |
| High-entropy files (> 7.5 Shannon) | warn, reviewed manually |

# Appendix: Sandbox Preview Architecture

## Isolation Model

| Layer | Mechanism |
|-------|-----------|
| Origin isolation | Preview served from `preview-sandbox.gsmui.dev` (separate subdomain) |
| Iframe sandbox | `sandbox="allow-scripts"` only; no allow-same-origin |
| Network | CSP `connect-src 'none'` inside preview |
| Storage | Cookies/storage unavailable by sandbox attr |
| Input | Read-only demo state; no user accounts |
| Escape guards | No top navigation (`allow-top-navigation` absent) |

## Demo Boot Sequence

1. Admin clicks Preview tab → signed URL issued (5-min validity).
2. Sandbox origin renders demo blade with bundled `dist/gsmui.js`.
3. PostMessage protocol reports ready + console errors to parent viewer.
4. Viewer surfaces error badge if console errors captured.
5. Device toggle re-renders at 320/768/1280 widths.
