# Security

- All template files scanned for malware before approval
- Uploaded files stored outside web root with signed URLs
- Template PHP code sandboxed in preview environment
- License key validation on every template download
- Admin approval required before any template becomes public
- File type whitelist: only .blade.php, .php, .json, .css, .js, images
- Max upload size: 50MB per template package
- CSRF protection on all template management actions

# Template Review Workflow (Deep Dive)

## States

```
submitted --> in_review --> approved --> released
                  |                        |
                  +--> needs_changes ----> resubmitted
                  |
                  +--> rejected
      any --> archived
```

## Review Page Structure

| Section | Content |
|---------|---------|
| Checklist panel | Automated validation results |
| Screenshot gallery | Author-provided images |
| Live demo link | External or sandboxed iframe |
| File manifest | Extracted file tree (read-only) |
| Metadata card | Author, license, compatibility, dependencies |
| Pricing card | Current price, discount state |
| Feedback composer | Structured feedback |
| Decision bar | Approve / Needs changes / Reject |

## Automated Validation Checks

On version upload, pipeline validates:

| Check | Pass Criteria |
|-------|---------------|
| Package structure | Expected directories (views, config, assets) |
| Manifest valid | `gsmui.template.json` schema v1 |
| Blade lint | No syntax errors |
| Security scan | No eval/exec/obfuscated code |
| Size limits | ≤ 50MB total |
| Screenshots | ≥ 3 images, all ≥ 800x600 |
| Description | ≥ 200 chars + feature list |
| License present | LICENSE file matches manifest |
| Compatibility declared | ≥ 1 Laravel major, valid range |
| Component deps | All exist and approved |
| Demo URL reachable | HTTPS 200 (if provided) |

Fail/warn semantics identical to Components module (see 05.03.03.06).

## Review Criteria (Human)

| # | Criterion |
|---|-----------|
| 1 | Template runs cleanly with documented steps |
| 2 | Uses GsmUi components (not reinventing basics) |
| 3 | Responsive across documented breakpoints |
| 4 | Dark mode supported where applicable |
| 5 | No placeholder text (Lorem) in shipped state |
| 6 | README installation accurate |
| 7 | No external runtime dependencies (CDN scripts) |
| 8 | Accessibility basics (focus states, landmarks) |
| 9 | Code organization matches conventions |
| 10 | Screenshots represent actual output |

## Decision Requirements

| Decision | Requirements |
|----------|--------------|
| Approve | Checklist satisfied; optional comment; release pipeline |
| Needs changes | ≥ 1 actionable item; 30-day deadline |
| Reject | Category + feedback (min 20 chars) |

Post-decision notifications mirror Components module patterns.

# Version Management Detail

## Version Upload Flow

1. Author uploads zip via portal (or admin uploads on behalf with audit note).
2. Validation pipeline runs.
3. Version record created as `submitted`.
4. Review required for each version (fast-track for eligible authors).
5. Approval → release pipeline.

## Release Pipeline Steps

| Step | Action |
|------|--------|
| 1 | Checksum verify of artifact |
| 2 | Store versioned package (private disk) |
| 3 | Sync distribution to CDN |
| 4 | Update `templates.latest_version` |
| 5 | Invalidate marketplace caches |
| 6 | Notify buyers of update (opt-in setting) |
| 7 | Audit entry |

## Version Diff Viewer

- Compares file manifests between two versions.
- Shows added/removed/changed files with size deltas.
- Blade diffs rendered with syntax highlighting.
- Used during resubmission reviews.

## Update Delivery to Buyers

- Buy-once model: buyers get all updates free within license major.
- Download center shows "Update available" badges.
- Email digest of updates (per-user preference).

# Runbooks (Templates)

## Symptom: Release pipeline failures

1. Check `ReleaseTemplateJob` logs (checksum vs CDN step).
2. Artifact checksum mismatch → quarantine + security alert.
3. CDN partial → degraded flag; serve N-1.
4. Notify author with support template.

## Symptom: Coupon abuse spike

1. Identify code with anomalous redemption rate.
2. Pause code (status → disabled).
3. Review redemptions per-user; revoke suspicious entitlements.
4. Post-incident: tighten per-user limits.

## Symptom: Compatibility wave after Laravel release

1. Compat job flags untested templates.
2. Monitor author responses against deadline.
3. Enable public "untested" badges.
4. Archive abandoned templates after grace + warnings.

# Appendix: Template Refund Decision Tree

1. Request within 14 days of purchase? No -> standard denial template with policy link. Yes -> continue.
2. Technical defect confirmed by reproduction? Yes -> immediate refund + author defect ticket. No -> continue.
3. Significant mismatch vs listing description? Yes -> refund + listing review flag. No -> continue.
4. Download activity consistent with fair evaluation (single user, non-production)? Yes -> refund. No -> deny with evidence summary.
5. Author appeal within 5 business days? Yes -> review by marketplace lead; decision logged.

Every refund or denial emits `marketplace.refund_decided` with reason codes for analytics.
