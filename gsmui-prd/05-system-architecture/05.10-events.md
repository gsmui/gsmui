# 05.10 - Events & Listeners Architecture

**Project:** GsmUi
**Architecture:** Event-Driven Architecture (EDA)
**Framework:** Laravel 13 + Livewire 4
**Version:** 1.0.0

---

# Purpose

Events enable communication between GsmUi domains without creating direct dependencies. Instead of invoking another module directly, a domain publishes an event describing something that has already happened.

Listeners subscribe to these events and perform follow-up work.

This architecture provides:

* Loose coupling
* Better scalability
* Easier testing
* Background processing
* Future microservice compatibility

---

```text
↓

↓
```

---

# Event Payload

Events should carry only the data required by listeners.

Example:

```php
class ThemePublished
{
    public function __construct(
        public readonly int $themeId,
        public readonly int $userId,
        public readonly string $version,
    ) {}
}
```

Avoid passing entire HTTP requests or service instances.

---

# Transaction Rules

Events should be dispatched after successful database commits.

Recommended:

```php
DB::afterCommit(function () use ($event) {
    event($event);
});
```

This prevents listeners from acting on rolled-back data.

# Listener Responsibilities

Listeners may:

* Send emails
* Index search
* Generate files
* Update analytics
* Dispatch jobs
* Notify users
* Invalidate cache
* Synchronize external systems

Listeners should not contain core business rules.

# Queued Listeners

Expensive listeners must implement `ShouldQueue`.

Examples:

```text

SendNewsletter

SyncSearch

```

Benefits:

* Faster HTTP responses
* Automatic retries
* Failure isolation

# Synchronous Listeners

Allowed only for lightweight operations.

Examples:

* Cache invalidation
* Audit logging
* Internal metrics

Laravel's Event Dispatcher serves as the internal event bus.

Responsibilities:

* Register listeners
* Dispatch events
* Queue listeners

* Log failures

# Event Discovery

Enable automatic event discovery.

Each domain registers:

```text

```

# Failure Handling

Queued listeners should define:

* Retry attempts
* Backoff strategy
* Timeout
* Failure callback

Example:

```php
public int $tries = 3;

public int $timeout = 120;
```

Persistent failures are logged and surfaced in Horizon.

---

# Idempotency

Listeners must be safe to execute multiple times.

Techniques:

* Unique constraints
* Idempotency keys
* Processed event records
* Duplicate detection

Required for:

* Webhooks
* Payments
* Notifications
* Search indexing

---

# Event Versioning

Public events should evolve without breaking consumers.

Guidelines:

* Add optional properties
* Avoid removing existing properties
* Introduce new event classes for breaking changes

---

# Logging

All critical events are recorded using `spatie/laravel-activitylog`.

Examples:

* User registration
* Purchases
* Subscription changes
* Theme publication
* Component releases

---

# Monitoring

Track:

* Event throughput
* Queue length
* Listener failures
* Retry count
* Processing time

Use:

* Horizon
* Telescope
* Spatie Health

---

# Testing

Every event requires:

* Dispatch tests
* Listener tests
* Queue tests
* Failure tests
* Integration tests

Verify:

* Correct payload
* Correct listeners
* No duplicate execution

---

# Best Practices

* Keep events immutable.
* Use descriptive names in the past tense.
* Dispatch after successful persistence.
* Queue expensive listeners.
* Keep listeners focused on a single responsibility.
* Prefer multiple small listeners over one large listener.
* Never place business workflows inside listeners.

---

# Anti-Patterns

Avoid:

* Calling repositories from unrelated domains
* Business logic inside listeners
* Dispatching events before transactions commit
* Large event payloads
* Circular event chains
* Long-running synchronous listeners

---

# Future Evolution

As GsmUi grows, the event architecture can evolve into a distributed event bus (e.g., Kafka, RabbitMQ, AWS SNS/SQS) without changing domain code. Events remain the primary integration mechanism between bounded contexts, enabling future extraction of Billing, Search, AI, MCP, and Marketplace into independent services.

# Event Implementation Patterns

## Domain Event Base Classes

### Abstract Domain Event

```php
// app/Shared/Events/DomainEvent.php

declare(strict_types=1);

namespace App\Shared\Events;

use Illuminate\Broadcasting\Channel;
use Illuminate\Broadcasting\InteractsWithSockets;
use Illuminate\Contracts\Broadcasting\ShouldBroadcast;
use Illuminate\Foundation\Events\Dispatchable;
use Illuminate\Queue\SerializesModels;

abstract class DomainEvent implements ShouldBroadcast
{
    use Dispatchable, InteractsWithSockets, SerializesModels;

    public function __construct(
        public readonly string $eventId,
        public readonly string $eventType,
        public readonly \DateTimeImmutable $occurredAt,
        public readonly string $version,
        public readonly ?string $causedBy = null,
    ) {
        $this->eventId = $this->eventId ?? Uuid::uuid4()->toString();
        $this->occurredAt = new \DateTimeImmutable();
        $this->version = '1.0';
    }

    abstract public function toArray(): array;

    public function toPayload(): string
    {
        return json_encode($this->toArray());
    }

    public function broadcastOn(): array
    {
        return [
            new Channel("domain-events.{$this->eventType}"),
        ];
    }

    public function broadcastAs(): string
    {
        return 'domain.event';
    }

    public function broadcastWith(): array
    {
        return [
            'event_id' => $this->eventId,
            'event_type' => $this->eventType,
            'occurred_at' => $this->occurredAt->toIso8601String(),
            'payload' => $this->toArray(),
        ];
    }
}
```

## Event Listener Implementations

### Search Index Listener

```php
// app/Domains/Search/Listeners/UpdateSearchIndexOnComponentPublished.php

declare(strict_types=1);

namespace App\Domains\Search\Listeners;

use App\Domains\Search\Contracts\SearchServiceInterface;
use App\Domains\Components\Events\ComponentPublished;
use Illuminate\Contracts\Queue\ShouldQueue;
use Illuminate\Support\Facades\Log;

class UpdateSearchIndexOnComponentPublished implements ShouldQueue
{
    public function __construct(
        private readonly SearchServiceInterface $searchService,
    ) {}

    public function handle(ComponentPublished $event): void
    {
        try {
            $this->searchService->indexComponent(
                componentId: $event->componentId,
                data: [
                    'name' => $event->name,
                    'slug' => $event->componentSlug,
                    'categories' => $event->categories,
                    'tags' => $event->tags,
                    'published_at' => $event->occurredAt->toIso8601String(),
                ]
            );

            Log::info('Component indexed in search', [
                'component_id' => $event->componentId,
            ]);
        } catch (\Exception $e) {
            Log::error('Failed to index component in search', [
                'component_id' => $event->componentId,
                'error' => $e->getMessage(),
            ]);

            throw $e; // Re-throw for retry
        }
    }

    public function failed(\Throwable $exception): void
    {
        Log::error('Search indexing permanently failed', [
            'component_id' => $this->componentId,
            'error' => $exception->getMessage(),
        ]);
    }
}
```

### Notification Listener

```php
// app/Domains/Notifications/Listeners/SendEmailOnOrderPaid.php

declare(strict_types=1);

namespace App\Domains\Notifications\Listeners;

use App\Domains\Billing\Events\OrderPaid;
use App\Domains\Users\Contracts\UserRepositoryInterface;
use App\Domains\Notifications\Contracts\NotificationServiceInterface;
use App\Mail\OrderConfirmationMail;
use Illuminate\Contracts\Queue\ShouldQueue;
use Illuminate\Support\Facades\Mail;

class SendEmailOnOrderPaid implements ShouldQueue
{
    public function __construct(
        private readonly UserRepositoryInterface $userRepository,
        private readonly NotificationServiceInterface $notificationService,
    ) {}

    public function handle(OrderPaid $event): void
    {
        $user = $this->userRepository->findOrFail($event->userId);

        // Send email
        Mail::to($user->email)->send(new OrderConfirmationMail(
            order: $event->toArray(),
        ));

        // Create in-app notification
        $this->notificationService->create([
            'user_id' => $event->userId,
            'type' => 'order_confirmed',
            'title' => 'Order Confirmed',
            'message' => "Your order #{$event->orderId} has been confirmed.",
            'data' => $event->toArray(),
        ]);
    }
}
```

```php
declare(strict_types=1);

namespace Tests\Feature\Components;

use Tests\TestCase;
use App\Domains\Components\Models\{Component, ComponentVersion};
use App\Domains\Components\Events\ComponentPublished;
use App\Domains\Users\Models\User;
use Illuminate\Foundation\Testing\RefreshDatabase;
use Illuminate\Support\Facades\Event;

class ComponentPublishEventTest extends TestCase
{
    use RefreshDatabase;

    public function test_publishing_component_dispatches_event(): void
    {
        // Arrange
        $author = User::factory()->create();
        $component = Component::factory()->create([
            'author_id' => $author->id,
            'status' => 'draft',
            'description' => str_repeat('A', 50),
        ]);

        ComponentVersion::factory()->create([
            'component_id' => $component->id,
        ]);

        Event::fake([ComponentPublished::class]);

        // Act
        $component->update([
            'status' => 'published',
            'published_at' => now(),
        ]);

        // Assert
        Event::assertDispatched(ComponentPublished::class, function ($event) use ($component) {
            return $event->componentId === $component->id
                && $event->componentSlug === $component->slug
                && $event->authorId === $component->author_id;
        });
    }

    public function test_event_contains_correct_payload(): void
    {
        // Arrange
        $event = new ComponentPublished(
            componentId: 1,
            componentSlug: 'test-component',
            versionId: 1,
            authorId: 1,
            categories: ['buttons'],
            tags: ['primary', 'cta'],
        );

        // Act
        $payload = $event->toArray();

        // Assert
        $this->assertEquals(1, $payload['component_id']);
        $this->assertEquals('test-component', $payload['component_slug']);
        $this->assertEquals(['buttons'], $payload['categories']);
        $this->assertEquals(['primary', 'cta'], $payload['tags']);
    }
}
```

## Event Performance Optimization

### Event Batching

```php
// Batch event dispatch for bulk operations

class BulkComponentPublishAction
{
    public function execute(array $componentIds): array
    {
        return DB::transaction(function () use ($componentIds) {
            // Batch update
            Component::whereIn('id', $componentIds)
                ->update([
                    'status' => 'published',
                    'published_at' => now(),
                ]);

            // Dispatch batch event instead of individual events
            ComponentsBulkPublished::dispatch($componentIds);

            return $componentIds;
        });
    }
}
```

### Retry Strategies

```php
// Configurable retry strategies

class RetryableEvent implements ShouldRetry
{
    public function __construct(
        public readonly int $maxRetries = 3,
        public readonly int $retryDelay = 60,
        public readonly array $retryOn = [\Exception::class],
    ) {}

    public function retryFor(): array
    {
        return $this->retryOn;
    }

    public function backoff(): array
    {
        return array_map(
            fn($attempt) => $this->retryDelay * pow(2, $attempt),
            range(1, $this->maxRetries)
        );
    }
}
```

### Dead Letter Queue

```php
// Dead letter queue for failed events

class DeadLetterQueue
{
    public function __construct(
        private readonly string $queueName = 'events.dead_letter',
    ) {}

    public function handleFailedEvent(object $event, \Throwable $exception): void
    {
        $payload = [
            'event' => get_class($event),
            'payload' => $event->toArray(),
            'error' => $exception->getMessage(),
            'stack_trace' => $exception->getTraceAsString(),
            'failed_at' => now()->toIso8601String(),
            'attempts' => $event->attempts ?? 1,
        ];

        // Store in dead letter queue
        DB::table('dead_letter_events')->insert($payload);

        // Alert administrators
        if ($this->shouldAlert($event, $exception)) {
            $this->alertService->sendDeadLetterAlert($payload);
        }
    }

    private function shouldAlert(object $event, \Throwable $exception): bool
    {
        // Alert on critical events
        $criticalEvents = [
            PaymentProcessed::class,
            SubscriptionCancelled::class,
            OrderRefunded::class,
        ];

        return in_array(get_class($event), $criticalEvents);
    }
}
```

### Circuit Breaker Pattern

```php
// Circuit breaker for external service events

class CircuitBreaker
{
    private int $failureCount = 0;
    private int $threshold = 5;
    private int $resetTimeout = 60;

    public function call(callable $callback): mixed
    {
        if ($this->isOpen()) {
            throw new CircuitBreakerOpenException(
                'Circuit breaker is open. Service unavailable.'
            );
        }

        try {
            $result = $callback();
            $this->onSuccess();
            return $result;
        } catch (\Exception $e) {
            $this->onFailure();
            throw $e;
        }
    }

    private function isOpen(): bool
    {
        return $this->failureCount >= $this->threshold;
    }

    private function onSuccess(): void
    {
        $this->failureCount = 0;
    }

    private function onFailure(): void
    {
        $this->failureCount++;
    }
}
```

```php
// Validate event payloads

class EventValidator

    public function validate(DomainEvent $event): bool
    {
        // Validate event structure
        $this->validateStructure($event);

        // Validate payload size
        $this->validatePayloadSize($event);

        // Validate required fields
        $this->validateRequiredFields($event);

        if (strlen($payload) > $maxSize) {

            );
        }
    }
}
```

## Event System Evolution

### Migration Strategy

When evolving the event system:

1. **Version events** - Maintain backward compatibility
2. **Deprecate gradually** - Mark old events as deprecated
3. **Provide adapters** - Bridge old and new event formats
4. **Document changes** - Update event registry and documentation
5. **Monitor adoption** - Track usage of new vs old events

### Future Considerations

- **Distributed event bus**: Kafka, RabbitMQ, AWS SNS/SQS
- **Event sourcing**: Store all events for replay
- **CQRS integration**: Separate read/write models
- **Real-time events**: WebSocket integration
- **Event-driven microservices**: Service extraction
