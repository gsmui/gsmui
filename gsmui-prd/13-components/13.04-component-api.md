# 13.04 Component API — Standard Contract

## Overview

Every GsmUi component implements a consistent API contract. This document defines the standard props, slots, events, methods, and behaviors that all components must support.

## Base Component Interface

```php
<?php

namespace GsmUi\Contracts;

interface ComponentContract
{
    // Props
    public function getProps(): array;
    public function getProp(string $name, mixed $default = null): mixed;
    public function hasProp(string $name): bool;
    
    // Slots
    public function getSlots(): array;
    public function hasSlot(string $name): bool;
    public function renderSlot(string $name, array $data = []): string;
    
    // Events
    public function emit(string $event, mixed $payload = null): void;
    public function on(string $event, callable $handler): void;
    
    // Lifecycle
    public function mount(): void;
    public function hydrate(): void;
    public function dehydrate(): array;
    
    // Livewire Integration
    public function getWireModel(): ?string;
    public function setWireModel(?string $model): void;
    public function getValue(): mixed;
    public function setValue(mixed $value): void;
}
```

## Standard Props

Every component **must** support these base props:

| Prop | Type | Default | Description |
|------|------|---------|-------------|
| `id` | `string?` | `null` | Unique identifier |
| `class` | `string?` | `''` | Additional CSS classes |
| `attributes` | `array?` | `[]` | Additional HTML attributes |
| `variant` | `string?` | `'default'` | Visual variant |
| `size` | `string?` | `'md'` | Size variant |
| `color` | `string?` | `'primary'` | Color theme |
| `disabled` | `bool` | `false` | Disabled state |
| `loading` | `bool` | `false` | Loading state |
| `hidden` | `bool` | `false` | Hidden state |

```blade

        'class' => 'base-classes',
        'data-disabled' => $disabled ? 'true' : 'false',
        'data-invalid' => $invalid ? 'true' : 'false',
        'data-loading' => $loading ? 'true' : 'false',
```

```css
.component { /* ... */ }

.component[data-disabled="true"] { opacity: 0.5; cursor: not-allowed; }
.component[data-invalid="true"] { border-color: var(--gsmui-color-danger); }
.component[data-loading="true"] { position: relative; pointer-events: none; }
```

### Required Methods for Livewire Components

```php

{

    public function getValue(): mixed;
    
    // Set value (called by Livewire)

    // Called when wire:model updates
    public function updatedValue(mixed $value): void;

}
```

## Example: Complete Button API

```blade
<x-gsmui:button
    <!-- Base -->
    id="save-btn"
    class="mt-4"
    :attributes="['data-action' => 'save']"
    
    <!-- Variant/Size/Color -->
    variant="primary"
    size="md"
    color="primary"
    
    <!-- State -->
    disabled="{{ $saving }}"
    loading="{{ $saving }}"
    invalid="{{ $errors->has('name') }}"
    
    <!-- Livewire -->
    wire:model="form.action"
    wire:click="save"
    
    <!-- Accessibility -->
    aria-label="Save changes"
    aria-describedby="save-help"
    
    <!-- Responsive -->
    :full-width="['true', 'md:false']"
    
    <!-- Slots -->
>
    <x-slot name="icon">
        <x-gsmui:icon name="save" />
    </x-slot>
    
    Save Changes
</x-gsmui:button>

<x-gsmui:button id="save-help" class="sr-only">
    Saves the current form data
</x-gsmui:button>
```

## API Design Patterns

### Pattern 1: Declarative API

Components are configured via props, not imperative methods.

```blade
<!-- GOOD: Declarative -->
<x-gsmui:button 
    variant="primary" 
    size="lg" 
    :disabled="$isDisabled"
    icon="save"
>
    Save
</x-gsmui:button>

<!-- BAD: Imperative -->
<x-gsmui:button id="save-btn" />
<script>
    document.getElementById('save-btn').setVariant('primary');
    document.getElementById('save-btn').setSize('lg');
    document.getElementById('save-btn').setDisabled(true);
</script>
```

### Pattern 2: Composition Over Configuration

Use slots for complex content, props for simple values.

```blade
<!-- GOOD: Slot for complex content -->
<x-gsmui:card>
    <x-slot name="header">
        <div class="flex items-center justify-between">
            <h2>Title</h2>
            <x-gsmui:button variant="ghost" size="sm">Edit</x-gsmui:button>
        </div>
    </x-slot>
    
    <p>Content here</p>
</x-gsmui:card>

<!-- BAD: Props for complex content -->
<x-gsmui:card 
    headerTitle="Title" 
    headerAction="Edit" 
    headerActionVariant="ghost"
    content="<p>Content here</p>"
/>
```

### Pattern 3: Sensible Defaults

Every prop has a default that works for most use cases.

```blade
<!-- These all work with just content -->
<x-gsmui:button>Click me</x-gsmui:button>
<x-gsmui:input placeholder="Enter text" />
<x-gsmui:select :options="$options" />

<!-- Only override what you need -->
<x-gsmui:button variant="secondary" size="lg">Large secondary</x-gsmui:button>
```

## State Management

### Component State Machine

```
┌─────────────────────────────────────────────────────────┐
│                    STATE MACHINE                        │
├─────────────────────────────────────────────────────────┤
│                                                         │
│  ┌──────────┐     ┌──────────┐     ┌──────────┐       │
│  │  IDLE    │────>│ FOCUSED  │────>│ ACTIVE   │       │
│  └──────────┘     └──────────┘     └──────────┘       │
│       │               │                 │              │
│       │               │                 │              │
│       v               v                 v              │
│  ┌──────────┐     ┌──────────┐     ┌──────────┐       │
│  │ DISABLED │     │ LOADING  │     │ INVALID  │       │
│  └──────────┘     └──────────┘     └──────────┘       │
│                                                         │
└─────────────────────────────────────────────────────────┘
```

### State Transitions

| From | To | Trigger |
|------|----|---------|
| IDLE | FOCUSED | `focus` event |
| FOCUSED | IDLE | `blur` event |
| FOCUSED | ACTIVE | `mousedown`, `Enter`, `Space` |
| ACTIVE | FOCUSED | `mouseup`, key release |
| any | DISABLED | `disabled` prop = true |
| any | LOADING | `loading` prop = true |
| any | INVALID | `invalid` prop = true |

## Component API Patterns

### API Pattern 1: Simple Component

Minimal API for simple components:

```blade
<x-gsmui:badge>Label</x-gsmui:badge>
```

**Props:** `variant`, `size`, `color`
**Slots:** `default`
**Events:** none

### API Pattern 2: Interactive Component

API with state and events:

```blade
<x-gsmui:toggle wire:model="enabled" />
```

**Props:** `variant`, `size`, `color`, `disabled`, `value`, `wire:model`
**Slots:** none
**Events:** `input`, `change`

### API Pattern 3: Compound Component

API with sub-components:

```blade
<x-gsmui:select wire:model="selected">
    <x-gsmui:select.trigger />
    <x-gsmui:select.content>
        <x-gsmui:select.option value="1">One</x-gsmui:select.option>
    </x-gsmui:select.content>
</x-gsmui:select>
```

## API Summary

### Key Takeaways

1. **Consistent naming** — Use short, natural prop names
2. **Minimal props** — Ship with fewest props possible
3. **Sensible defaults** — Every prop has a default that works
4. **Composable slots** — Use slots for complex content
5. **Type-safe** — Use PHP 8.1+ features for type safety
6. **Accessible** — Include ARIA attributes by default
7. **Themeable** — Use CSS custom properties
8. **Testable** — Expose test selectors for testing

## API Best Practices

### Do's

- Use consistent naming
- Provide sensible defaults
- Support wire:model
- Include ARIA attributes
- Support keyboard navigation
- Document all props/events/slots
- Use slots for complex content
- Test all combinations

### Don'ts

- Use boolean props for variants
- Invent new patterns
- Skip accessibility
- Forget documentation
- Use props for complex content
- Ignore edge cases
- Forget dark mode
- Skip testing

## API Glossary

| Term | Definition |
|------|-----------|
| **Component** | A reusable UI element with props, events, and slots |
| **Prop** | A configuration option passed to a component |
| **Event** | A signal dispatched by a component |
| **Slot** | A content insertion point in a component |
| **Variant** | A visual style option for a component |
| **Size** | A dimension option for a component |
| **Theme** | A set of design tokens for components |
| **Token** | A CSS custom property for design values |
| **Wire:model** | A Livewire two-way binding directive |
| **ARIA** | Accessible Rich Internet Applications attributes |
| **Focus visible** | Keyboard focus indicator styling |
| **Responsive** | Adapting to different screen sizes |
| **Compound variant** | A combination of variant options |
| **Scoped slot** | A slot that passes data to parent |
| **Slot component** | A sub-component for slot content |

## API Component Registry

### Button Component

- **Tag**: `<x-gsmui:button>`
- **Props**: variant, size, color, disabled, loading, icon, iconPosition
- **Events**: click
- **Slots**: default, icon
- **ARIA**: role="button", aria-disabled, aria-busy

### Input Component

- **Tag**: `<x-gsmui:input>`
- **Props**: type, value, placeholder, size, disabled, invalid, clearable
- **Events**: input, change, focus, blur, clear
- **Slots**: prefix, suffix, label, description, error
- **ARIA**: aria-invalid, aria-describedby, aria-label

### Card Component

- **Tag**: `<x-gsmui:card>`
- **Props**: variant, size, padding
- **Events**: none
- **Slots**: default, header, body, footer
- **ARIA**: none (semantic HTML)

### Select Component

- **Tag**: `<x-gsmui:select>`
- **Props**: value, options, size, disabled, invalid, searchable, clearable
- **Events**: change, focus, blur, search, clear
- **Slots**: option, empty, label, description, error
- **ARIA**: role="combobox", aria-expanded, aria-haspopup, aria-activedescendant

### Dialog Component

- **Tag**: `<x-gsmui:dialog>`
- **Props**: open, size, closable, overlay
- **Events**: open, close, escape
- **Slots**: default, header, body, footer
- **ARIA**: role="dialog", aria-modal, aria-labelledby, aria-describedby
