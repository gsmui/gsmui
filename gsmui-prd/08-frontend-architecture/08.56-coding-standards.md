# 08.56 - Coding Standards

**Project:** GsmUi
**Section:** 08 - Frontend Architecture
**Framework:** Laravel 13 · Blade Components · Tailwind CSS v4 · Alpine.js · GsmUi Component Library
**Version:** 1.0.0

---

> See also: `07.59-coding-standards.md` (backend standards), `08.52-component-guidelines.md` (component-specific rules). This document generalizes the frontend conventions into enforceable standards and does NOT duplicate the component-level class strings (those live in `08.52`).

# Purpose

This document collects the frontend coding standards that apply across all `gsmui:` work — beyond the component-guideline specifics in `08.52`. It is the frontend companion to `07.59-coding-standards.md` and the `AGENTS.md` philosophy, focused on consistency, dead-code discipline, and verification gates.

---

## 1. Core Philosophy (from `AGENTS.md`)

- **Internal consistency > external best practices.** Match `gsmui:input` if it does something; don't "improve" one component into inconsistency.
- **Punt semi-aggressively.** Cut features with complexity > proportional value. Ship the simpler version.
- **Separate component when shape changes.** Inline mode is a new component, not an `inline` prop.
- **Most useful variant is the default.** Don't make users opt into the better experience.
- **Push back on feature creep.** "I'd keep it simple and ship."
- **Accept pragmatic imperfections.** Silent revert on invalid input; no shake animations.
- **Dead code is a liability.** Delete unused mixins/parsers; lean on the browser.

---

## 2. Language / Stack Standards

| Area | Standard |
| --- | --- |
| Blade | Use `gsmui:` prefix, `Gsmui::classes()` for merges, `__()` for all strings |
| CSS | Consume `--gsmui-*` tokens; Tailwind v4 utilities; no hard-coded theme colors |
| JS | `setAttribute`/`removeAttribute` from `utils.js`; MutationObserver on `value` + config |
| Alpine | RARELY; move to JS when disabled-awareness/coordination needed |
| Events | Fire `input` + `change` per range spec; `change` on pointer commit |

---

## 3. Naming & API Standards

- Short natural prop names (`dropper`); `-able` for boolean opt-ins; `type` for trigger variants (`08.52`).
- Reference prop order: wire:model, value, name, format, type, placeholder, size → behavioral → label/description/disabled/invalid.
- Facade is `Gsmui`, never the upstream fork name; CSS vars use the `--gsmui-*` prefix exclusively.

---

## 4. Verification Gate (Mandatory)

Per `AGENTS.md`, no component is "done" without:

1. Playwright screenshot after every CSS change.
2. State matrix verified: base, open, disabled, invalid, sizes, keyboard focus, empty.
3. DOM-state assertions (never `el.state.s` internals).
4. Headless runs unless explicitly asked otherwise.
5. No console errors.

---

## 5. Dead-Code & Browser-Offload Rules

- If the browser parses it natively (e.g. `<canvas>` for CSS colors), delete the lookup table.
- Remove unused JS mixins and Blade scaffolding before shipping (launch blocker).
- Don't force a mixin that doesn't fit — self-contained logic beats a bad abstraction.

---

## 6. Open Questions / Risks

- **Lint tooling:** confirm whether a frontend linter (Blade/JS) is wired in CI; if not, propose one that enforces `08.52` class strings.
- **`Gsmui::classes()` usage:** audit components that still hard-code class strings instead of using the facade helper.
- **Consistency backlog:** track components that predate `08.52` and need retrofitting.

### 7.2 Directory Structure Conventions

```
stubs/resources/views/gsmui/
    <component>/
        index.blade.php          # Primary component template
        button.blade.php         # Sub-component (if needed)
```

**Rules:**
- Every component lives in its own directory under `gsmui/`
- The primary template is always `index.blade.php`
- Sub-components are sibling files in the same directory, NOT nested directories
- No component has more than 5 sub-component files (split into a new component if it does)

```blade
{{-- 4. Conditional blocks --}}
@if ($condition)
    ...
@endif

@endsection
```

## 8. JavaScript Coding Standards

### 8.1 `setAttribute` / `removeAttribute` — Mandatory

Every DOM attribute modification MUST use the utility functions from `utils.js`, never native `el.setAttribute()`:

```js
// CORRECT
import { setAttribute, removeAttribute } from './utils.js';
setAttribute(el, 'aria-disabled', 'true');
removeAttribute(el, 'aria-disabled');

// INCORRECT — bypasses MutationObserver
el.setAttribute('aria-disabled', 'true');
el.removeAttribute('aria-disabled');
```

**Why:** The MutationObserver watches attribute changes to reconcile component state. Native `setAttribute` fires the observer, but the utility functions add additional bookkeeping (attribute normalization, event dispatch). Skipping them breaks the sync contract.

### 8.2 MutationObserver Patterns

Every component that reacts to attribute changes must register a MutationObserver in its constructor:

```js
class MyComponent {
    constructor(el) {
        this.el = el;
        this.observer = new MutationObserver((mutations) => {
            for (const mutation of mutations) {
                if (mutation.type === 'attributes') {
                    this.onAttributeChanged(mutation.attributeName, mutation);
                }
            }
        });

        this.observer.observe(el, {
            attributes: true,
            attributeFilter: ['value', 'disabled', 'invalid', 'data-config'],
        });
    }

    onAttributeChanged(name, mutation) {
        switch (name) {
            case 'value':
                this.reconcileValue();
                break;
            case 'disabled':
                this.reconcileDisabled();
                break;
            case 'invalid':
                this.reconcileInvalid();
                break;
        }
    }

    destroy() {
        this.observer.disconnect();
    }
}
```

**Rules:**
- Always use `attributeFilter` — observing all attributes is wasteful
- Always watch `value` in addition to config attributes (per AGENTS.md)
- Always provide a `destroy()` method that disconnects the observer
- Never call `observer.disconnect()` and re-observe without good reason

### 8.3 `detangle()` Usage

The `detangle()` utility prevents infinite sync loops between the Controllable mixin and internal state subscriptions:

```js
import { detangle } from './detangle.js';

// In a component method:
this.detangle = detangle();

// When updating from external source:
this.detangle('external', () => {
    this.el.value = newValue; // triggers MutationObserver
});

// When updating from internal source:
this.detangle('internal', () => {
    this.el.value = newValue; // triggers MutationObserver
});

// detangle prevents re-entry:
// If 'external' is executing, 'external' won't re-enter
// If 'internal' is executing, 'internal' won't re-enter
// Cross-entry (external↔internal) is allowed
```

**Rules:**
- Every `wire:model` sync point must use `detangle()`
- The detangle key must be descriptive (`'external'`, `'internal'`, `'livewire'`, `'user'`)
- Never use `detangle()` as a generic debounce — it is a re-entry guard

### 8.4 Event Firing Convention

For range-like components (sliders, color pickers, date pickers):

```js
// On user interaction (mouse/touch/keyboard):
el.dispatchEvent(new Event('input', { bubbles: true }));

// On pointer release (commit):
el.dispatchEvent(new Event('change', { bubbles: true }));
```

**Rules:**
- `input` fires continuously during interaction (mousemove, keydown)
- `change` fires only on commit (mouseup, touchend, keyup from a discrete step)
- `change` does NOT fire on popover close (per AGENTS.md)
- Both events must bubble (`bubbles: true`) for Livewire to catch them

### 8.5 Class vs Function Components

GsmUi JS uses class-based component definitions:

```js
// CORRECT — class-based
class Datepicker {
    constructor(el) {
        this.el = el;
        // ...
    }
}

// INCORRECT — function-based (inconsistent with codebase)
function datepicker(el) {
    // ...
}
```

**Rationale:** Classes provide natural `destroy()` methods for cleanup, consistent `this` context, and clear lifecycle boundaries. The codebase convention is class-based.

### 8.6 Error Handling in JS

```js
// CORRECT — defensive, silent degradation
try {
    this.parseValue(rawValue);
} catch {
    this.revertToPreviousValue();
}

// INCORRECT — throw in component code
try {
    this.parseValue(rawValue);
} catch (error) {
    throw new Error(`Failed to parse: ${error.message}`);
}
```

**Rules:**
- Component JS never throws — it degrades silently
- Invalid input reverts to the previous valid value
- Console warnings are acceptable for development debugging
- Production component code has zero `console.log` calls

### 8.7 Private Methods Convention

Prefix internal methods with `_` to signal they are not part of the public API:

```js
class Datepicker {
    // Public API
    open() { ... }
    close() { ... }
    select(date) { ... }

    // Private
    _parseDate(str) { ... }
    _buildCalendar(year, month) { ... }
    _attachKeyboardListeners() { ... }
}
```

### 8.8 Constants and Magic Numbers

```js
// CORRECT — named constant
const MAX_VISIBLE_MONTHS = 12;
const KEYBOARD_DEBOUNCE_MS = 150;

// INCORRECT — magic number
if (count > 12) { ... }
setTimeout(fn, 150);
```

## 9. Blade Template Standards

### 9.1 Component Attribute Order

Every `gsmui:` Blade component follows a strict attribute ordering (per AGENTS.md):

```blade
<gsmui:input
    wire:model="name"          {{-- 1. wire:model --}}
    value="{{ $value }}"        {{-- 2. value --}}
    name="field_name"           {{-- 3. name --}}
    format="hex"                {{-- 4. format --}}
    type="text"                 {{-- 5. type --}}
    placeholder="Enter..."     {{-- 6. placeholder --}}
    size="sm"                   {{-- 7. size --}}
    clearable                   {{-- 8. behavioral: clearable --}}
    searchable                  {{-- 9. behavioral: searchable --}}
    label="Name"                {{-- 10. label --}}
    description="Your name"     {{-- 11. description --}}
    disabled                    {{-- 12. disabled --}}
    invalid                     {{-- 13. invalid --}}
/>
```

### 9.2 `__()` for All User-Facing Strings

Every user-visible string MUST pass through `__()` for localization:

```blade
{{-- CORRECT --}}
<gsmui:button label="{{ __('Save changes') }}" />
<gsmui:input placeholder="{{ __('Enter your name') }}" />
<span>{{ __('No results found') }}</span>

{{-- INCORRECT — hard-coded English --}}
<gsmui:button label="Save changes" />
<gsmui:input placeholder="Enter your name" />
<span>No results found</span>
```

**Exception:** Technical strings (CSS class names, attribute values, ARIA roles) do not need translation.

### 9.3 ARIA Pattern Standards

| Component Pattern | ARIA Implementation |
| --- | --- |
| Input trigger (combobox) | `role="combobox"` on `<input>`, `aria-expanded`, `aria-controls` |
| Button trigger (dialog) | Native `<button>`, `aria-haspopup="dialog"`, `aria-expanded` |
| Dropdown menu | `role="listbox"` on container, `role="option"` on items |
| Modal/dialog | `role="dialog"`, `aria-modal="true"`, focus trap |
| Tab panel | `role="tablist"`, `role="tab"`, `role="tabpanel"`, `aria-selected` |
| Alert | `role="alert"`, `aria-live="assertive"` |
| Toast/notification | `role="status"`, `aria-live="polite"` |

**Rules:**
- Never invent new ARIA patterns — always reference ARIA APG or React Aria
- ARIA labels must use `__()` for localization
- Dynamic ARIA attributes (`aria-expanded`, `aria-selected`) must be updated via `setAttribute` from `utils.js`

### 9.4 Conditional Rendering

```blade
{{-- CORRECT — clean conditional --}}
@if ($items->isEmpty())
    <gsmui:feedback :title="__('No items')" />
@else
    @foreach ($items as $item)
        <gsmui:list-item :value="$item->id" :label="$item->name" />
    @endforeach
@endif

{{-- INCORRECT — nested ternary --}}
<div class="{{ $isEmpty ? 'hidden' : ($items->count() > 5 ? 'grid grid-cols-5' : 'grid grid-cols-3') }}">
```

### 9.5 Slot Patterns

```blade
{{-- Named slots for structured content --}}
@gsmui:button
    @slot('prefix')
        <x-gsmui::icon name="arrow-left" />
    @endslot

    {{ __('Back') }}

    @slot('suffix')
        <x-gsmui::icon name="arrow-right" />
    @endslot
@endgsmui:button

{{-- Default slot for simple content --}}
@gsmui:button
    {{ __('Submit') }}
@endgsmui:button
```

### 9.6 Blade Component Skeleton

Every new `gsmui:` component template follows this skeleton:

```blade
@props([
    'value' => null,
    'name' => null,
    'label' => null,
    'description' => null,
    'placeholder' => null,
    'size' => 'md',
    'disabled' => false,
    'invalid' => false,
])

@php
    $classes = Gsmui::classes('gsmui-component', [
        'gsmui-size-' . $size,
        $disabled ? 'gsmui-disabled' : '',
        $invalid ? 'gsmui-invalid' : '',
    ]);
@endphp

<div {{ $attributes->merge(['class' => $classes]) }}
     data-invalid="{{ $invalid ? 'true' : 'false' }}"
     @if ($disabled) disabled @endif
>
    @if ($label)
        <label class="gsmui-label">{{ __($label) }}</label>
    @endif

    {{-- Component content --}}

    @if ($description)
        <p class="gsmui-description">{{ __($description) }}</p>
    @endif

    @if ($invalid)
        <p class="gsmui-error" role="alert">{{ __('Invalid input') }}</p>
    @endif
</div>
```

## 10. CSS / Tailwind Standards

### 10.1 Utility-First, No Custom CSS

GsmUi uses Tailwind v4 utilities exclusively in component templates. Custom CSS is forbidden in Blade templates:

```blade
{{-- CORRECT — Tailwind utilities --}}
<div class="flex items-center gap-2 rounded-lg border border-zinc-200 px-3 py-2">

{{-- INCORRECT — custom CSS --}}
<style>
    .my-component { display: flex; align-items: center; }
</style>
<div class="my-component">
```

**Exception:** `adoptedStyleSheets` in JS for dynamic/runtime styles (e.g., editor component, color picker gradient).

### 10.2 Dark Mode Classes

Always use Tailwind's `dark:` prefix with the `dark` class on `<html>`:

```blade
{{-- CORRECT --}}
<div class="bg-white dark:bg-zinc-800 text-zinc-900 dark:text-zinc-100">

{{-- INCORRECT — media query based --}}
<style>
    @media (prefers-color-scheme: dark) { .my-component { background: #1f2937; } }
</style>
```

### 10.3 Focus Management Classes

```blade
{{-- Native focusable elements — NO focus classes --}}
<button class="...">{{ __('Click') }}</button>
<input class="...">

{{-- Custom focusable elements (tabindex=0) — use the slider thumb pattern --}}
<div tabindex="0"
     class="has-focus-visible:outline-2 has-focus-visible:outline-[-webkit-focus-ring-color]">

{{-- INCORRECT — forbidden pattern --}}
<div class="focus:outline-none focus:ring-2 focus:ring-(--color-accent)">
```

### 10.4 Disabled State Classes

```blade
{{-- Native form elements — CSS :disabled works --}}
<input disabled class="...">

{{-- Custom elements — need attribute selector --}}
<div disabled
     class="[&[disabled]]:shadow-none! [&[disabled]]:opacity-50 [&[disabled]]:pointer-events-none">
```

### 10.5 Invalid State Classes

Invalid styles are layered on top of base styles using `data-invalid:` selectors:

```blade
{{-- CORRECT — layered approach --}}
<div class="border-zinc-200 dark:border-white/10 data-invalid:border-red-500 data-invalid:ring-1 data-invalid:ring-red-500/20">

{{-- INCORRECT — ternary swap --}}
<div class="{{ $invalid ? 'border-red-500 ring-1 ring-red-500/20' : 'border-zinc-200 dark:border-white/10' }}">
```

### 10.6 Cursor Rules

| Element | Cursor | Rationale |
| --- | --- | --- |
| `<button>` | `cursor-default` | Native buttons do not have pointer cursor |
| `<a href>` | `cursor-pointer` | Navigation elements |
| `<input>` | `cursor-text` | Text input |
| `<select>` | `cursor-default` | Native selects |
| Custom interactive div | `cursor-pointer` only if it navigates | Clickable widgets without navigation keep default |
| Drag handle | `cursor-grab` / `cursor-grabbing` | Drag-and-drop affordance |

### 10.7 Responsive Design Classes

```blade
{{-- Mobile-first — base = mobile, sm: = desktop --}}
<div class="p-3 sm:p-6">

{{-- Avoid max-sm: unless absolutely necessary --}}
<div class="max-sm:max-h-full!">

{{-- Container queries over media queries when possible --}}
<div class="@container">
    <div class="@sm:flex @sm:gap-4">
```

### 10.8 Spacing and Sizing Standards

| Size Token | Default (md) | Small (sm) | Extra Small (xs) | Large (lg) |
| --- | --- | --- | --- | --- |
| Height | `h-10` | `h-8` | `h-6` | `h-12` |
| Padding | `px-4 py-2` | `px-3 py-1.5` | `px-2 py-1` | `px-5 py-3` |
| Font size | `text-base sm:text-sm` | `text-sm` | `text-xs` | `text-base` |
| Border radius | `rounded-lg` | `rounded-md` | `rounded-md` | `rounded-lg` |
| Gap | `gap-2` | `gap-1.5` | `gap-1` | `gap-2.5` |

### 10.9 Color Token Usage

```blade
{{-- CORRECT — use CSS variables --}}
<div class="text-(--gsmui-text-primary) bg-(--gsmui-bg-primary)">

{{-- CORRECT — Tailwind semantic colors --}}
<div class="text-zinc-900 dark:text-zinc-100 bg-white dark:bg-zinc-800">

{{-- INCORRECT — hard-coded hex --}}
<div class="text-[#1a1a1a] bg-[#ffffff]">
```

## 11. Testing Standards

### 11.1 Test Pyramid

```
                    ┌─────────┐
                    │ Browser │  ← Playwright (state matrix)
                    │  Tests  │     Fewest, highest value
                    ├─────────┤
                    │  PHP    │  ← PHPUnit / Orchestra Testbench
                    │  Tests  │     CSP headers, middleware
                    ├─────────┤
                    │  Unit   │  ← JS mixin tests (if any)
                    │  Tests  │     Fast, isolated
                    └─────────┘
```

### 11.2 Playwright Test Standards

Every component test must cover the state matrix:

```js
test.describe('Datepicker', () => {
    test('base state', async ({ page }) => { ... });
    test('open popover', async ({ page }) => { ... });
    test('disabled state', async ({ page }) => { ... });
    test('invalid state', async ({ page }) => { ... });
    test('size variants — sm', async ({ page }) => { ... });
    test('size variants — xs', async ({ page }) => { ... });
    test('keyboard focus', async ({ page }) => { ... });
    test('empty state', async ({ page }) => { ... });
    test('select a date', async ({ page }) => { ... });
    test('clear value', async ({ page }) => { ... });
    test('keyboard navigation', async ({ page }) => { ... });
});
```

### 11.3 Assertion Patterns

```js
// CORRECT — DOM-state assertions
expect(await page.getAttribute('[data-datepicker]', 'data-value')).toBe('2025-01-15');
expect(await page.isVisible('[role="listbox"]')).toBe(true);
expect(await page.getAttribute('input', 'aria-expanded')).toBe('true');

// INCORRECT — internal state assertions
expect(component.state.selectedDate).toBe('2025-01-15'); // DO NOT poke internals
```

### 11.4 Screenshot Standards

```js
// After every CSS change, take a screenshot:
await page.screenshot({ path: 'screenshots/datepicker-base.png' });

// Compare with baseline:
expect(await page.screenshot()).toMatchSnapshot('datepicker-base.png');
```

**Screenshot naming convention:** `<component>-<state>.png`

Examples:
- `datepicker-base.png`
- `datepicker-open.png`
- `datepicker-disabled.png`
- `datepicker-invalid.png`
- `datepicker-sm.png`
- `datepicker-xs.png`

### 11.5 PHP Test Standards

```php
<?php

namespace Tests\Browser;

use Orchestra\Testbench\TestCase;

class CspHeaderTest extends TestCase
{
    /** @test */
    public function csp_header_contains_script_src_self(): void
    {
        $response = $this->get('/gsmui-csp-test');
        $response->assertHeader('Content-Security-Policy');
        $response->assertHeaderContains(
            'Content-Security-Policy',
            "script-src 'self'"
        );
    }

    /** @test */
    public function csp_header_does_not_contain_unsafe_eval(): void
    {
        $response = $this->get('/gsmui-csp-test');
        $response->assertHeaderDoesNotContain(
            'Content-Security-Policy',
            'unsafe-eval'
        );
    }
}
```

## 12. Documentation Standards

### 12.1 Component Documentation Structure

Every `gsmui:` component must have documentation in `08.53-documentation-generation.md` format:

```blade
{{-- 1. Preview section — dressed up, shows real value --}}
<gsmui:input
    value="#0ea5e9"
    label="hex"
    format="hex"
/>

{{-- 2. Code section — minimal, clean copy-paste --}}
@gsmui:input
    wire:model="color"
@endgsmui:input
```

### 12.2 Props Reference Table

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `wire:model` | `string` | — | Livewire binding property |
| `value` | `string` | `null` | Initial value |
| `name` | `string` | `null` | HTML name attribute |
| `type` | `string` | `'text'` | Input type variant |
| `placeholder` | `string` | `null` | Placeholder text |
| `size` | `'sm' \| 'md' \| 'xs'` | `'md'` | Component size |
| `label` | `string` | `null` | Label text (localized) |
| `description` | `string` | `null` | Description text (localized) |
| `disabled` | `boolean` | `false` | Disabled state |
| `invalid` | `boolean` | `false` | Invalid/error state |

### 12.3 ARIA Documentation

Every component must document its ARIA pattern:

```markdown
## Accessibility

- **Role:** `combobox` on the `<input>` element
- **aria-expanded:** `true` when popover is open, `false` when closed
- **aria-controls:** points to the popover `id`
- **aria-label:** set via `label` prop, localized via `__()`
- **Keyboard:** Arrow keys navigate options, Enter selects, Escape closes
```

### 12.4 Limitations Documentation

Every component must honestly document its limitations:

```markdown
## Limitations

- `copyable` is not supported with `type="button"` (no text to copy)
- `clearable` requires `wire:model` binding (cannot clear a static `value`)
- Date picker does not support range selection (separate component needed)
```

## 13. Code Review Standards

### 13.1 Review Checklist

Every PR must be reviewed against this checklist:

**Security:**
- [ ] No `{!! !!}` in Blade without justification
- [ ] No `innerHTML` without DOMPurify
- [ ] No external CDN references
- [ ] No `eval()` or `Function()`
- [ ] CSP implications documented

**Consistency:**
- [ ] Follows `08.52` component guidelines (class strings, ARIA patterns)
- [ ] Uses `Gsmui::classes()` for class merging
- [ ] Uses `__()` for all user-facing strings
- [ ] Uses `setAttribute`/`removeAttribute` from `utils.js`
- [ ] Follows naming conventions (short prop names, `-able` suffix)

**Quality:**
- [ ] No dead code (unused imports, commented-out blocks)
- [ ] No magic numbers (use named constants)
- [ ] State matrix tested (base, open, disabled, invalid, sizes, focus, empty)
- [ ] No console errors in Playwright
- [ ] CSP header test passes

**Documentation:**
- [ ] Component docs updated (preview, code, props, ARIA, limitations)
- [ ] Breaking changes noted in changelog

### 13.2 Review Process

1. Author self-reviews against the checklist before requesting review
2. Reviewer verifies the checklist items and runs the test suite
3. Reviewer checks Playwright screenshots for visual regressions
4. Author addresses feedback, pushes updates

## 14. Performance Standards

### 14.1 Bundle Size Budgets

| Bundle | Max Size (gzipped) | Rationale |
| --- | --- | --- |
| `gsmui.js` | 50 KB | Core component runtime |
| `editor.js` | 30 KB | Playground only, lazy-loaded |
| `editor.css` | 10 KB | Playground styles |
| Total first paint | 90 KB | Acceptable for a component library |

### 14.2 Rendering Performance

- Components must not cause layout thrashing (no forced reflows in loops)
- `requestAnimationFrame` for visual updates (scroll, resize, drag)
- `debounce` on high-frequency events (input, resize): 150ms default
- `throttle` on event listeners that fire >60fps (mousemove): 16ms

### 14.3 Memory Management

- Every MutationObserver must have a `destroy()` method
- Event listeners added in `connectedCallback` or constructor must be removed in `disconnectedCallback` or `destroy()`
- No memory leaks from orphaned references in closures
- Playwright memory leak tests for long-lived pages

### 14.4 CSS Performance

- Use `contain: layout` on isolated components
- Avoid expensive CSS selectors (`:has()`, deep nesting)
- Use `will-change` sparingly (only for active animations)
- Prefer `transform` and `opacity` for animations (GPU-accelerated)

## 21. Component-Specific Coding Standards

### 21.1 Input Components

Input components (`gsmui:input`, `gsmui:textarea`, `gsmui:select`) must follow these standards:

**Attribute template:**

```blade
@gsmui:input
    wire:model="fieldName"
    name="field_name"
    type="text"
    placeholder="{{ __('Enter value') }}"
    size="md"
    label="{{ __('Field Label') }}"
    description="{{ __('Help text') }}"
    disabled="{{ $isDisabled }}"
    invalid="{{ $hasError }}"
@endgsmui:input
```

**Rules:**
- `wire:model` always comes first
- `name` must match the Livewire property name
- `type` must be one of: `text`, `email`, `password`, `number`, `tel`, `url`, `search`
- `placeholder` must use `__()` for localization
- `label` must use `__()` for localization
- `description` must use `__()` for localization
- `disabled` and `invalid` are boolean — pass the computed value, not a string

**JS mixin requirements:**
- Must use the `Controllable` mixin
- Must use the `Focusable` mixin for keyboard navigation
- Must fire `input` event on value change
- Must fire `change` event on blur or discrete commit
- Must use `setAttribute`/`removeAttribute` from `utils.js`

### 21.2 Button Components

Button components (`gsmui:button`) must follow these standards:

**Attribute template:**

```blade
<gsmui:button
    type="button"
    variant="primary"
    size="md"
    disabled="{{ $isDisabled }}"
    aria-label="{{ __('Save changes') }}"
>
    {{ __('Save') }}
</gsmui:button>
```

**Rules:**
- `type` must be one of: `button`, `submit`, `reset`
- `variant` must be one of: `primary`, `secondary`, `danger`, `ghost`
- `size` must be one of: `sm`, `md`, `xs`
- `aria-label` must use `__()` when the button has no visible text
- No `cursor-pointer` on buttons (per AGENTS.md styling conventions)
- No focus ring classes on native `<button>` elements (use browser default)

**When using `<gsmui:button as="div">`:**
- Only use when nested inside a `<button>` element (nested-button HTML constraint)
- Must have `role="button"` and `tabindex="0"`
- Must handle `Enter` and `Space` key events

### 21.3 Select/Dropdown Components

Select components (`gsmui:select`) must follow these standards:

**Attribute template:**

```blade
<gsmui:select
    wire:model="selectedOption"
    name="option"
    placeholder="{{ __('Choose an option') }}"
    size="md"
    searchable="{{ $isSearchable }}"
    clearable="{{ $isClearable }}"
    label="{{ __('Option') }}"
    disabled="{{ $isDisabled }}"
    invalid="{{ $hasError }}"
>
    @foreach ($options as $option)
        <gsmui:select-option
            value="{{ $option->value }}"
            label="{{ $option->label }}"
        />
    @endforeach
</gsmui:select>
```

**Rules:**
- `wire:model` always comes first
- `placeholder` must use `__()` for localization
- `searchable` and `clearable` are boolean opt-in behaviors (use `-able` suffix per AGENTS.md)
- Options must use `gsmui:select-option` sub-component (not raw HTML)
- Keyboard navigation: ArrowDown/Up to navigate, Enter to select, Escape to close, Home/End for first/last
- ARIA: `role="combobox"` on trigger, `role="listbox"` on dropdown, `role="option"` on items
- Focus management: focus moves to dropdown when open, returns to trigger when closed

### 21.4 Date Picker Components

Date picker components (`gsmui:date-picker`) must follow these standards:

**Attribute template:**

```blade
<gsmui:date-picker
    wire:model="selectedDate"
    name="date"
    format="YYYY-MM-DD"
    placeholder="{{ __('Select date') }}"
    size="md"
    label="{{ __('Date') }}"
    disabled="{{ $isDisabled }}"
    invalid="{{ $hasError }}"
/>
```

**Rules:**
- `format` must be a valid date-fns or Intl format string
- Calendar grid uses `role="grid"` with `role="gridcell"` for dates
- Keyboard: ArrowLeft/Right for days, ArrowUp/Down for weeks, Enter to select, Escape to close
- Month navigation: PageUp/PageDown or dedicated buttons
- Focus management: focus moves to calendar grid when open
- The dialog/popover follows the verbatim pattern from AGENTS.md

### 21.5 Table Components

Table components (`gsmui:table`) must follow these standards:

**Attribute template:**

```blade
<gsmui:table>
    <gsmui:table-header>
        <gsmui:table-row>
            <gsmui:table-head sortable="name" aria-sort="{{ $sortColumn === 'name' ? $sortDirection : 'none' }}">
```

- Responsive: horizontal scroll wrapper on mobile

## 22. Error Handling Standards

### 22.1 JavaScript Error Handling

```js
// CORRECT — silent degradation with logging
class MyComponent {
    constructor(el) {
        try {
            this.init(el);
        } catch (error) {
            console.error('[gsmui] Component init failed:', error);
            this.el.classList.add('gsmui-error');
        }
    }

    init(el) {
        // Component initialization logic
    }
}

// INCORRECT — throwing errors
class MyComponent {
    constructor(el) {
        this.init(el); // If this throws, the page breaks
    }
}
```

**Rules:**
- Component constructors never throw
- Invalid input reverts to previous valid value
- Console warnings acceptable in development
- Production code has zero `console.log` calls
- `console.error` only for unrecoverable component failures

### 22.2 Blade Template Error Handling

```blade
{{-- CORRECT — defensive rendering --}}
@php
    $items = $items ?? collect();
    $label = $label ?? null;
@endphp

@if ($items->isEmpty())
    <gsmui:feedback :title="__('No items found')" type="empty" />
@else
    @foreach ($items as $item)
        <gsmui:list-item :value="$item->id" :label="$item->label" />
    @endforeach
@endif

{{-- INCORRECT — no defensive rendering --}}
@foreach ($items as $item)
    <gsmui:list-item :value="$item->id" :label="$item->label" />
@endforeach
```

**Rules:**
- Always provide default values for optional props
- Handle empty states explicitly
- Never assume data is non-null without checking
- Use `@isset` or `?? ` for optional values

### 22.3 Livewire Error Handling

```php
// CORRECT — graceful error handling
public function save(): void
{
    try {
        $this->validate();
        $this->model->save();
        $this->dispatch('saved');
    } catch (ValidationException $e) {
        // Livewire handles this automatically — sets $errors bag
    } catch (\Exception $e) {
        Log::error('Save failed', ['error' => $e->getMessage()]);
        $this->dispatch('error', message: __('Something went wrong. Please try again.'));
    }
}

// INCORRECT — letting exceptions propagate
public function save(): void
{
    $this->validate();
    $this->model->save(); // If this throws, Livewire shows a generic error page
}
```

## 23. Performance Coding Standards

### 23.1 Bundle Size Awareness

Every import should be justified:

```js
// CORRECT — only import what's needed
import { setAttribute } from './utils.js';

// INCORRECT — importing an entire library for one function
import _ from 'lodash';
_.set(el, 'attribute.name', value);
```

**Rules:**
- No utility libraries (lodash, underscore) — write the specific function needed
- No full CSS frameworks — use Tailwind utilities
- Tree-shaking must work (use named exports, not default exports for utilities)
- Dead code must be removed before merge (launch blocker per AGENTS.md)

### 23.2 DOM Manipulation Efficiency

```js
// CORRECT — batch DOM reads, then batch DOM writes
const width = el.offsetWidth;
const height = el.offsetHeight;
el.style.width = width + 10 + 'px';
el.style.height = height + 10 + 'px';

// INCORRECT — interleaving reads and writes (causes layout thrashing)
el.style.width = el.offsetWidth + 10 + 'px';
el.style.height = el.offsetHeight + 10 + 'px';
```

**Rules:**
- Read before write (never interleave)
- Use `requestAnimationFrame` for visual updates
- Use `contain: layout` on isolated components
- Avoid forced reflows in loops

### 23.3 Event Listener Efficiency

```js
// CORRECT — debounced resize handler
import { debounce } from './utils.js';

const handleResize = debounce(() => {
    this.recalculateLayout();
}, 150);

window.addEventListener('resize', handleResize);

// Cleanup
window.removeEventListener('resize', handleResize);

// INCORRECT — unthrottled handler
window.addEventListener('resize', () => {
    this.recalculateLayout(); // Fires 60+ times per second during resize
});
```

**Rules:**
- `debounce` for input events (150ms default)
- `throttle` for scroll/resize (16ms = 60fps)
- Always clean up event listeners in `destroy()`
- Use `AbortController` for event listeners (modern pattern)

### 23.4 CSS Performance

```css
/* CORRECT — containment for isolated components */
.gsmui-component {
    contain: layout style;
}

/* CORRECT — GPU-accelerated animations */
.gsmui-animate {
    transition: transform 200ms ease-out, opacity 200ms ease-out;
    will-change: transform, opacity;
}

/* INCORRECT — expensive properties */
.gsmui-animate {
    transition: width 200ms, height 200ms, top 200ms, left 200ms; /* Triggers layout */
}
```


```bash
commit_msg=$(cat "$1")

# Must match: type(scope): description
if ! echo "$commit_msg" | grep -qE '^(feat|fix|security|refactor|docs|test|chore|perf)\(.+\): .+'; then
    echo "ERROR: Commit message must follow conventional format:"
    echo "  type(scope): description"
    echo ""
    echo "Types: feat, fix, security, refactor, docs, test, chore, perf"
    echo "Example: feat(datepicker): add range selection mode"
    exit 1
fi

# Description must not end with period
if echo "$commit_msg" | grep -q '\.$'; then
    echo "ERROR: Commit description must not end with a period"
    exit 1
fi

# Description must be under 72 characters
first_line=$(echo "$commit_msg" | head -n 1)
if [ ${#first_line} -gt 72 ]; then
    echo "ERROR: First line of commit message must be under 72 characters"
    exit 1
fi
```

### 29.1 Custom Blade Linting Rules

| Rule | Description | Severity |
| --- | --- | --- |
| `no-raw-output` | No `{!! !!}` without `@verbatim` or `@php` justification | Error |
| `no-inline-style` | No `style="..."` attribute on elements | Warning |
| `no-onclick` | No `onclick="..."` or other inline event handlers | Error |
| `use-gsmui-prefix` | All GsmUi components must use `gsmui:` prefix | Error |
| `use-translation` | All user-facing strings must use `__()` | Error |
| `aria-required` | Interactive elements must have ARIA attributes | Warning |
| `size-must-match` | Size prop must match component's size variant | Error |
| `disabled-must-be-computed` | Disabled prop must be a computed value, not string | Warning |

### 29.2 Blade Formatting Rules

```blade
{{-- CORRECT formatting --}}
<gsmui:input
    wire:model="name"
    value="{{ $value }}"
    label="{{ __('Name') }}"
    size="md"
    disabled="{{ $isDisabled }}"
/>

{{-- INCORRECT formatting — all on one line --}}
<gsmui:input wire:model="name" value="{{ $value }}" label="{{ __('Name') }}" size="md" disabled="{{ $isDisabled }}" />

{{-- INCORRECT formatting — mixed indentation --}}
<gsmui:input
        wire:model="name"
    value="{{ $value }}"
        label="{{ __('Name') }}"
/>
```

## 32. Appendix A — Coding Standards Checklist Card

This section provides a printable checklist card that developers can reference during development and code review.

### Before Writing Code

- [ ] Check if a similar component already exists (avoid duplication)
- [ ] Read the closest sibling component's code (copy patterns, don't invent)
- [ ] Identify the ARIA pattern (reference ARIA APG or React Aria)
- [ ] Plan the state machine (idle, focused, active, disabled, invalid)
- [ ] Identify keyboard interactions (Tab, Enter, Escape, arrows)

### While Writing Code

- [ ] Use `Gsmui::classes()` for class merging (never hard-code)
- [ ] Use `__()` for all user-facing strings
- [ ] Use `setAttribute`/`removeAttribute` from `utils.js`
- [ ] Use `detangle()` for Livewire sync points
- [ ] Fire both `input` and `change` events where appropriate
- [ ] Register MutationObserver with `attributeFilter`
- [ ] Provide `destroy()` method for cleanup
- [ ] Follow attribute ordering convention (wire:model first)
- [ ] Handle empty states explicitly
- [ ] Validate URLs before rendering

### Before Committing

- [ ] No `eval()`, `Function()`, `document.write()`
- [ ] No `innerHTML` without DOMPurify
- [ ] No `{!! !!}` without justification
- [ ] No external CDN references
- [ ] No console.log in production code
- [ ] No dead code (unused imports, commented-out blocks)
- [ ] No magic numbers (use named constants)
- [ ] All tests pass
- [ ] Bundle size within budget

### Before Requesting Review

- [ ] Playwright screenshots taken for all states
- [ ] State matrix verified (base, open, disabled, invalid, sizes, focus, empty)
- [ ] CSP implications documented
- [ ] Component documentation updated
- [ ] No console errors in any browser
- [ ] Keyboard navigation works correctly
- [ ] Screen reader announces correctly
