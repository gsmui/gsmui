**Project:** GsmUi
**Section:** 08 - Frontend Architecture

**Version:** 1.0.0

# Purpose

The modal system provides accessible dialogs and confirm sheets built on the exact date-picker dialog/popover pattern mandated by AGENTS.md. It guarantees scroll lock, focus trapping, `aria-modal` semantics, and CSP-safe self-hosted styling. All overlays share `<gsmui:modal>` so confirm dialogs, detail sheets, and form modals are visually consistent.

## 1. Modal Shell (verbatim date-picker pattern)

`stubs/resources/views/gsmui/modal/index.blade.php` uses the AGENTS.md dialog class verbatim:

```blade
<div x-data="{ open: @entangle($attributes->get('open')) }"
     x-show="open"
     class="relative z-50"
     role="dialog" aria-modal="true"
     :aria-label="__('Dialog')">

    {{-- backdrop --}}
    <div x-show="open" class="fixed inset-0 bg-black/40" @click="open = false"></div>

    {{-- panel: VERBATIM from AGENTS.md date-picker --}}
    <div class="max-sm:max-h-full! rounded-xl shadow-xl sm:shadow-2xs max-sm:fixed! max-sm:inset-0! sm:backdrop:bg-transparent bg-white dark:bg-zinc-700 sm:border border-zinc-200 dark:border-white/10 p-3">
        {{ $slot }}
    </div>
</div>
```

## 2. Scroll Lock

Copy the date-picker scroll-lock: on `open`, set `document.documentElement.style.overflow = 'hidden'` (or toggle a `data-scroll-locked` attribute via `setAttribute` from `utils.js`) and restore on close. Use `removeAttribute` on close.

## 3. Trigger & ARIA

- Button triggers use native `<button aria-haspopup="dialog">` (AGENTS.md ARIA rules).
- Within a trigger, nested action buttons must be `<gsmui:button as="div">` to respect the nested-button HTML constraint.
- Focus trap: on open, move focus into the panel; on Escape or backdrop click, `open = false` and return focus to the trigger.

## 4. Focus Ring

The panel is a custom `tabindex="0"` region when interactive; apply the AGENTS.md focus pattern: `has-focus-visible:outline-2 has-focus-visible:outline-[-webkit-focus-ring-color]`. Native `<button>`/`<input>` elements inside keep default focus (no added classes).

## 5. JavaScript

Use `setAttribute`/`removeAttribute` from `utils.js` for state; observe `value`/config with MutationObserver if the modal content is Livewire-morphed. Fire `input` + `change` on commit actions (e.g. confirm).

## 7. Focus Trap — Full Implementation

### 7.1 Focusable Elements

The focus trap scans the modal panel for all focusable elements: `a[href], button:not([disabled]), input:not([disabled]), select:not([disabled]), textarea:not([disabled]), [tabindex]:not([tabindex="-1"])`.

### 7.2 Trap Behavior

On open, focus moves to the first focusable element inside the panel (or the panel itself if no focusable elements exist). `Tab` and `Shift+Tab` cycle within the panel. `Escape` closes the modal (unless `persistent`).

```js
// assets/js/gsmui/modal.js
function createFocusTrap(panel) {
  const focusableSelector = 'a[href], button:not([disabled]), input:not([disabled]), select:not([disabled]), textarea:not([disabled]), [tabindex]:not([tabindex="-1"])'

  function getFocusable() {
    return [...panel.querySelectorAll(focusableSelector)].filter(el => {
      return el.offsetParent !== null // visible
    })
  }

  function handleKeydown(e) {
    if (e.key !== 'Tab') return
    const focusable = getFocusable()
    if (focusable.length === 0) return

    const first = focusable[0]
    const last = focusable[focusable.length - 1]

    if (e.shiftKey) {
      if (document.activeElement === first) {
        e.preventDefault()
        last.focus()
      }
    } else {
      if (document.activeElement === last) {
        e.preventDefault()
        first.focus()
      }
    }
  }

  return { activate: () => panel.addEventListener('keydown', handleKeydown),
           deactivate: () => panel.removeEventListener('keydown', handleKeydown) }
}
```

### 7.3 Focus Return

When the modal closes, focus returns to the element that triggered the modal open. The trigger element is captured at open time via `document.activeElement` and stored in the modal's state:

```js
let triggerElement = null

function open(trigger) {
  triggerElement = document.activeElement
  // ... open logic
}

function close() {
  // ... close logic
  if (triggerElement && triggerElement.offsetParent !== null) {
    triggerElement.focus()
  }
}
```

### 7.4 Nested Focus Traps

When a modal opens another modal (stacked modals), the inner modal's focus trap takes over. On inner close, the outer trap reactivates. Each modal manages its own `triggerElement` — the inner modal's trigger is typically a button inside the outer modal.

## 8. Scroll Lock — Full Implementation

### 8.1 Mechanism

Scroll lock prevents the page behind the modal from scrolling. The implementation follows the date-picker pattern:

```js
let scrollLockCount = 0 // supports nested modals

function lockScroll() {
  scrollLockCount++
  if (scrollLockCount === 1) {
    const scrollbarWidth = window.innerWidth - document.documentElement.clientWidth
    document.documentElement.style.overflow = 'hidden'
    document.documentElement.style.paddingRight = `${scrollbarWidth}px` // prevent layout shift
  }
}

function unlockScroll() {
  scrollLockCount--
  if (scrollLockCount === 0) {
    document.documentElement.style.overflow = ''
    document.documentElement.style.paddingRight = ''
  }
}
```

### 8.2 Layout Shift Prevention

When `overflow: hidden` is applied to the document, the scrollbar disappears, causing content to shift right. The `paddingRight` compensation adds padding equal to the scrollbar width. This value is measured at lock time and removed at unlock.

### 8.3 `data-scroll-locked` Attribute

Per AGENTS.md, state changes should use `setAttribute`/`removeAttribute` from `utils.js`. The scroll lock also sets a `data-scroll-locked` attribute on `<html>` for CSS hooks:

```js
import { setAttribute, removeAttribute } from './utils.js'

function lockScroll() {
  // ...
  setAttribute(document.documentElement, 'data-scroll-locked', '')
}

function unlockScroll() {
  // ...
  removeAttribute(document.documentElement, 'data-scroll-locked')
}
```

### 8.4 Mobile Considerations

On iOS, `overflow: hidden` on `<html>` does not prevent rubber-band scrolling. The fix is to also set `position: fixed` on `<body>` and restore it on unlock, with `top` offset equal to `window.scrollY`:

```js
function lockScrollIOS() {
  bodyStyle.position = 'fixed'
  bodyStyle.top = `-${window.scrollY}px`
  bodyStyle.width = '100%'
}

function unlockScrollIOS() {
  const scrollY = parseInt(bodyStyle.top || '0') * -1
  bodyStyle.position = ''
  bodyStyle.top = ''
  bodyStyle.width = ''
  window.scrollTo(0, scrollY)
}
```

## 9. Animation System

### 9.1 Backdrop Animation

The backdrop fades in/out using opacity transitions. Duration: 300ms enter (ease-out), 200ms leave (ease-in). The backdrop uses `bg-black/40` — not a separate element that could cause z-index issues.

### 9.2 Panel Animation

The panel uses a combined scale + opacity transition for a "pop" effect:

| Phase | Start | End |
| --- | --- | --- |
| Enter | `opacity-0 scale-95` | `opacity-100 scale-100` |
| Leave | `opacity-100 scale-100` | `opacity-0 scale-95` |

Duration: 300ms enter (ease-out), 200ms leave (ease-in).

### 9.3 Reduced Motion

Respects `prefers-reduced-motion: reduce` — all transitions become instant:

```js
const prefersReducedMotion = window.matchMedia('(prefers-reduced-motion: reduce)').matches
const transitionDuration = prefersReducedMotion ? '0ms' : '300ms'
```

### 9.4 CSS Architecture

All modal transitions use `adoptedStyleSheets` (not inline `<style>` per AGENTS.md CSP rule):

```js
const modalStyles = new CSSStyleSheet()
modalStyles.replaceSync(`
  [role="dialog"] {
    --gsmui-modal-backdrop-enter: 300ms ease-out;
    --gsmui-modal-backdrop-leave: 200ms ease-in;
    --gsmui-modal-panel-enter: 300ms ease-out;
    --gsmui-modal-panel-leave: 200ms ease-in;
  }
`)
document.adoptedStyleSheets = [...document.adoptedStyleSheets, modalStyles]
```

## 10. Confirmation Dialogs

### 10.1 `<gsmui:confirm-modal>`

A convenience wrapper for destructive-action confirmations:

```blade
<gsmui:confirm-modal
    wire:model="showDeleteConfirm"
    title="{{ __('Delete record?') }}"
    confirm-label="{{ __('Delete') }}"
    cancel-label="{{ __('Cancel') }}"
    variant="danger"
    wire:confirm="delete({{ $record->id }})"
>
    {{ __('This action cannot be undone. The record will be permanently removed.') }}
</gsmui:confirm-modal>
```

### 10.2 Variants

| Variant | Confirm button style | Use case |
| --- | --- | --- |
| `danger` | `bg-red-600 hover:bg-red-700 text-white` | Destructive actions (delete, archive) |
| `warning` | `bg-amber-600 hover:bg-amber-700 text-white` | Caution actions (revoke access) |
| `default` | `bg-zinc-900 hover:bg-zinc-800 text-white dark:bg-white dark:hover:bg-zinc-200 dark:text-zinc-900` | Neutral confirmations |

### 10.3 Keyboard Confirm

Pressing `Enter` while the confirm button is focused triggers confirm. Pressing `Escape` triggers cancel. The confirm button receives focus on open (not the cancel button) — this prevents accidental cancellation of destructive actions.

### 10.4 Double-Confirm

For highly destructive actions, a `danger` variant confirmation can require typing a confirmation string (e.g. the record name) before the confirm button becomes enabled:

```blade
<gsmui:confirm-modal
    wire:model="showDeleteConfirm"
    variant="danger"
    :require-typing="$record->name"
    :require-typing-label="__('Type :name to confirm', ['name' => $record->name])"
>
    {{ __('This will permanently delete :name.', ['name' => $record->name]) }}
</gsmui:confirm-modal>
```

The confirm button is disabled until the typed value matches exactly. This is implemented via Alpine state, not Livewire, to avoid round-trips.

## 11. Form Modals

### 11.1 Pattern

Form modals wrap a `<form>` inside `<gsmui:modal>` with proper ARIA labeling:

```blade
<gsmui:modal wire:model="showEditModal" size="lg" aria-label="{{ __('Edit record') }}">
    <form wire:submit="save">
        <div class="space-y-4">
            <gsmui:input wire:model="name" label="{{ __('Name') }}" :invalid="$errors->has('name')" />
            <gsmui:input wire:model="email" label="{{ __('Email') }}" type="email" :invalid="$errors->has('email')" />
        </div>

        <div class="flex justify-end gap-2 mt-6">
            <gsmui:button as="div" type="button" variant="ghost" @click="$wire.set('showEditModal', false)">
                {{ __('Cancel') }}
            </gsmui:button>
            <gsmui:button type="submit">
                {{ __('Save changes') }}
            </gsmui:button>
        </div>
    </form>
</gsmui:modal>
```

### 11.2 Validation Feedback

Validation errors are displayed inline using the `data-invalid:` layering pattern per AGENTS.md. Each `<gsmui:input>` receives `:invalid="$errors->has('field')"` and layers the invalid style on top of its base style.

### 11.3 Close Prevention

When a form modal has unsaved changes, closing via backdrop/Escape should warn the user. The modal checks a `dirty` flag (from Alpine state tracking form field changes) and shows a secondary confirmation:

```js
function handleClose() {
  if (dirty) {
    showUnsavedWarning = true
  } else {
    close()
  }
}
```

### 11.4 Submit Button State

The submit button shows a loading state while the form is being submitted. This is handled by Livewire's built-in `wire:loading` directive:

```blade
<gsmui:button type="submit" wire:loading.attr="disabled" wire:loading.class="opacity-50">
    <span wire:loading.remove>{{ __('Save changes') }}</span>
    <span wire:loading>{{ __('Saving…') }}</span>
</gsmui:button>
```

## 12. Sheet / Drawer Variant

### 12.1 Side Sheets

A sheet is a modal that slides in from a side edge rather than appearing centered. The sheet reuses the modal shell but replaces the centered positioning with fixed positioning on the right:

```blade
<gsmui:modal wire:model="showSheet" size="lg" variant="sheet">
    <div class="h-full flex flex-col">
        <div class="flex items-center justify-between p-3 border-b border-zinc-200 dark:border-white/10">
            <h2 class="text-base font-semibold">{{ __('Details') }}</h2>
            <gsmui:button as="div" size="xs" variant="ghost" @click="$wire.set('showSheet', false)">
                <x-gsmui.icon name="x-mark" class="w-4 h-4" />
            </gsmui:button>
        </div>
        <div class="flex-1 overflow-y-auto p-3">
            {{ $slot }}
        </div>
    </div>
</gsmui:modal>
```

### 12.2 Sheet Animation

Sheets slide in from the right (or left for RTL) instead of scaling:

| Phase | Start | End |
| --- | --- | --- |
| Enter (right sheet) | `translate-x-full opacity-0` | `translate-x-0 opacity-100` |
| Leave (right sheet) | `translate-x-0 opacity-100` | `translate-x-full opacity-0` |

### 12.3 Mobile Full-Screen

On `max-sm`, the sheet becomes full-screen (`max-sm:fixed! max-sm:inset-0!`) matching the date-picker pattern from AGENTS.md.

## 13. Stacked Modals

### 13.1 Z-Index Strategy

Stacked modals (a modal opening another modal) increment `z-index` by 10 for each level. The base modal is `z-50`, the second is `z-[60]`, the third `z-[70]`, etc. This ensures each modal's backdrop covers the previous modal.

```js
let modalDepth = 0

function openModal() {
  const panel = document.querySelector('[data-modal-panel]:last-child')
  panel.style.zIndex = 50 + (modalDepth * 10)
  modalDepth++
}

function closeModal() {
  modalDepth = Math.max(0, modalDepth - 1)
}
```

### 13.2 Focus Return Chain

Each modal stores its trigger element. When modal B (triggered from modal A) closes, focus returns to modal A. When modal A closes, focus returns to the original page trigger. This creates a LIFO focus chain:

```
Page trigger → Modal A trigger → Modal B trigger
                                   ↓ (close B)
                              Modal A regains focus
                                   ↓ (close A)
                           Page trigger regains focus
```

### 13.3 Backdrop Opacity

Each stacked modal's backdrop is slightly more opaque than the previous: `bg-black/40` for level 1, `bg-black/50` for level 2, `bg-black/60` for level 3. This creates a visual depth effect.

## 14. Mobile Full-Screen

### 14.1 Behavior

On screens narrower than `sm` (640px), modals become full-screen panels. The `max-sm:fixed! max-sm:inset-0!` rule from the AGENTS.md dialog pattern handles this:

```
max-sm:max-h-full! rounded-xl shadow-xl sm:shadow-2xs max-sm:fixed! max-sm:inset-0!
sm:backdrop:bg-transparent bg-white dark:bg-zinc-700 sm:border border-zinc-200
dark:border-white/10 p-3
```

### 14.2 Close Affordance

On mobile full-screen modals, the close button must be prominently visible. The close button is placed in the top-right corner with sufficient touch target size (minimum 44x44px per WCAG):

```blade
<gsmui:button as="div" size="sm" variant="ghost" @click="close()" class="min-w-[44px] min-h-[44px]">
    <x-gsmui.icon name="x-mark" class="w-5 h-5" />
</gsmui:button>
```

### 14.3 Swipe-to-Close

On mobile, a downward swipe gesture on the sheet/modal header dismisses the modal. The gesture threshold is > 100px downward within < 300ms. During the gesture, the panel follows the finger with `transform: translateY(delta)` and snaps closed on threshold.

### 14.4 Safe Area

Mobile full-screen modals respect `env(safe-area-inset-top)` and `env(safe-area-inset-bottom)` for notched devices:

```css
@media (max-width: 639px) {
  [role="dialog"] {
    padding-top: env(safe-area-inset-top);
    padding-bottom: env(safe-area-inset-bottom);
  }
}
```

## 15. ARIA Patterns

### 15.1 `role="dialog"` vs `role="alertdialog"`

- `role="dialog"`: standard modals, forms, sheets — the user can interact with the content
- `role="alertdialog"`: confirmation dialogs that require immediate attention — used for the `<gsmui:confirm-modal>` when the action is destructive

### 15.2 `aria-labelledby` vs `aria-label`

If the modal has a visible title heading, use `aria-labelledby` pointing to the heading's ID:

```blade
<div role="dialog" aria-labelledby="modal-title-{{ $id }}">
    <h2 id="modal-title-{{ $id }}">{{ __('Edit record') }}</h2>
</div>
```

If no visible title, use `aria-label` directly:

```blade
<div role="dialog" aria-label="{{ __('Quick settings') }}">
```

### 15.3 `aria-modal="true"`

All modals set `aria-modal="true"` to inform assistive technology that the rest of the page is inert while the modal is open.

### 15.4 Inert Background

When a modal opens, the rest of the page should be marked as `inert` (the HTML `inert` attribute). This prevents screen readers from navigating to background content:

```js
function markBackgroundInert(panel) {
  const main = document.querySelector('main, [role="main"]')
  if (main) setAttribute(main, 'inert', '')
  // Also set aria-hidden="true" on the main content
}

function unmarkBackgroundInert() {
  const main = document.querySelector('main, [role="main"]')
  if (main) removeAttribute(main, 'inert')
}
```

### 15.5 Live Region Announcements

When a modal opens, an `aria-live` region announces the modal title:

```html
<div aria-live="polite" class="sr-only">
    {{ __('Dialog opened: Edit record') }}
</div>
```

## 16. Keyboard Navigation

### 16.1 Key Bindings

| Key | Action |
| --- | --- |
| `Escape` | Close modal (unless `persistent`) |
| `Tab` | Move to next focusable element within trap |
| `Shift+Tab` | Move to previous focusable element within trap |
| `Enter` | Submit form / activate focused button |
| `Space` | Toggle focused checkbox/button |

### 16.2 Roving Tabindex

For modals with multiple interactive sections (e.g. tabs inside a modal), use roving tabindex to manage focus within sections. Only the active section's elements are in the tab order.

### 16.3 Shortcuts

Common shortcuts inside modals:
- `Ctrl+Enter` / `Cmd+Enter`: Submit the form (if a form is present)
- `Ctrl+S` / `Cmd+S`: Save (if a save action exists)

These are registered on the modal panel and dispatched as Livewire events:

```js
panel.addEventListener('keydown', (e) => {
  if ((e.ctrlKey || e.metaKey) && e.key === 's') {
    e.preventDefault()
    panel.dispatchEvent(new CustomEvent('gsmui:modal-save'))
  }
})
```

## 17. Backdrop Behavior

### 17.1 Click-to-Close

By default, clicking the backdrop closes the modal. This is implemented via `@click="close()"` on the backdrop `<div>`. When `persistent="true"`, the backdrop click handler is suppressed.

### 17.2 Backdrop Hover

Some designs change the cursor to `cursor-pointer` on the backdrop to indicate clickability. This is optional and controlled by the `backdrop-cursor` prop.

### 17.3 Backdrop Blur

An optional blur effect on the backdrop can be added with `backdrop-blur-sm`. This creates a frosted-glass effect behind the modal:

```blade
<div class="fixed inset-0 bg-black/40 backdrop-blur-sm" @click="close()"></div>
```

## 18. Content Overflow Handling

### 18.1 Scrollable Content

When modal content exceeds the viewport height, the panel scrolls internally. The panel has `max-h-[calc(100vh-2rem)]` on desktop and `max-h-full!` on mobile (per AGENTS.md pattern). The `overflow-y-auto` class enables scroll.

### 18.2 Sticky Header/Footer

For modals with a sticky header (title) or footer (action buttons), use `sticky top-0` and `sticky bottom-0` with `bg-white dark:bg-zinc-700` and a subtle border:

```blade
<div class="sticky top-0 bg-white dark:bg-zinc-700 border-b border-zinc-200 dark:border-white/10 p-3">
    <h2>{{ __('Title') }}</h2>
</div>
<div class="p-3 overflow-y-auto">{{ $slot }}</div>
<div class="sticky bottom-0 bg-white dark:bg-zinc-700 border-t border-zinc-200 dark:border-white/10 p-3 flex justify-end gap-2">
    <gsmui:button as="div" variant="ghost">Cancel</gsmui:button>
    <gsmui:button>Save</gsmui:button>
</div>
```

### 18.3 Dynamic Height

When modal content changes height (e.g. expanding sections, validation errors appearing), the panel transitions smoothly. The `transition: max-height 300ms ease` prevents jarring jumps.

## 19. JavaScript Architecture

### 19.1 Modal Class

```js
// assets/js/gsmui/modal.js
import { setAttribute, removeAttribute } from './utils.js'

class GsmuiModal {
  constructor(el) {
    this.el = el
    this.panel = el.querySelector('[role="dialog"] > div')
    this.backdrop = el.querySelector('.fixed.inset-0.bg-black\\/40')
    this.isOpen = false
    this.triggerElement = null
    this.focusTrap = createFocusTrap(this.panel)

    this.setupMutationObserver()
    this.setupEventListeners()
  }

  setupMutationObserver() {
    const observer = new MutationObserver((mutations) => {
      for (const mutation of mutations) {
        if (mutation.attributeName === 'value') {
          const newValue = this.el.getAttribute('value') === 'true'
          if (newValue !== this.isOpen) {
            newValue ? this.open() : this.close()
          }
        }
      }
    })
    observer.observe(this.el, { attributes: true, attributeFilter: ['value'] })
  }

  open() {
    this.triggerElement = document.activeElement
    this.isOpen = true
    setAttribute(this.el, 'value', 'true')
    lockScroll()
    this.focusTrap.activate()
    this.panel.focus()
  }

  close() {
    this.isOpen = false
    removeAttribute(this.el, 'value')
    unlockScroll()
    this.focusTrap.deactivate()
    if (this.triggerElement) {
      this.triggerElement.focus()
      this.triggerElement = null
    }
  }

  setupEventListeners() {
    this.el.addEventListener('keydown', (e) => {
      if (e.key === 'Escape' && this.isOpen && this.el.getAttribute('closable') !== 'false') {
        this.close()
      }
    })
  }
}
```

### 19.2 Detangle Pattern

When the modal is used inside a Livewire component with `wire:model`, the Controllable mixin and internal state can create sync loops. The `detangle()` pattern prevents this:

```js
import { detangle } from './utils.js'

// Inside the modal init
this.isTangled = false

syncFromServer(value) {
  detangle('server', () => {
    this.isOpen = value
    this.el.setAttribute('value', String(value))
  })
}

syncFromLocal(isOpen) {
  detangle('local', () => {
    this.isOpen = isOpen
    this.el.dispatchEvent(new CustomEvent('input', { detail: { value: isOpen } }))
  })
}
```

## 24. Modal Lifecycle State Machine

```
                    ┌─────────────┐
                    │  CREATED    │
                    └──────┬──────┘
                           │ open() called
                           ▼
                    ┌─────────────┐
                    │  OPENING    │
                    └──────┬──────┘
                           │ enter transition complete
                           ▼
                    ┌─────────────┐
           ┌───────│    OPEN     │───────┐
           │       └──────┬──────┘       │
           │              │              │
     close()│        backdrop click      │ Escape
           │              │              │
           ▼              ▼              ▼
    ┌─────────────┐             (if closable)
    │  CLOSING    │
    └──────┬──────┘
           │ leave transition complete
           ▼
    ┌─────────────┐
    │   CLOSED    │
    └─────────────┘
```

### 24.1 State Transitions

| From | To | Trigger | DOM change |
| --- | --- | --- | --- |
| `CREATED` | `OPENING` | `open()` called | `data-state="open"`, scroll lock |
| `OPENING` | `OPEN` | Enter transition complete | Focus trap activated |
| `OPEN` | `CLOSING` | `close()` called | `data-state="closed"` |
| `CLOSING` | `CLOSED` | Leave transition complete | Scroll unlock, focus return |

### 24.2 Scroll Lock Counter

Because modals can be stacked, scroll lock uses a counter:

```
Lock count: 0 → Modal A opens → 1
Lock count: 1 → Modal B opens → 2
Lock count: 2 → Modal B closes → 1 (scroll still locked)
Lock count: 1 → Modal A closes → 0 (scroll restored)
```

## 27. Advanced Focus Management

### 27.1 Focusable Element Scanner

The focus trap scans for all focusable elements within the panel:

```js
const FOCUSABLE_SELECTORS = [
  'a[href]:not([disabled]):not([tabindex="-1"])',
  'button:not([disabled]):not([tabindex="-1"])',
  'input:not([disabled]):not([type="hidden"]):not([tabindex="-1"])',
  'select:not([disabled]):not([tabindex="-1"])',
  'textarea:not([disabled]):not([tabindex="-1"])',
  '[tabindex]:not([tabindex="-1"]):not([disabled])',
  'details>summary:not([disabled]):not([tabindex="-1"])',
].join(', ')
```

### 27.2 Focus First Strategy

On open, focus moves to the first focusable element using this priority:
1. Element with `data-modal-focus` attribute (explicit auto-focus)
2. First `<input>` or `<textarea>` in the panel
3. First `<button>` in the panel
4. The panel itself (if `tabindex="0"`)

### 27.3 Focus Restoration on Close

```js
function close() {
  const previousActiveElement = this.triggerElement
  // ... close animation ...
  this.$nextTick(() => {
    if (previousActiveElement && previousActiveElement.isConnected) {
      previousActiveElement.focus()
    } else {
      // Fallback: focus the first focusable element in the main content
      document.querySelector('main a, main button, main input')?.focus()
    }
  })
}
```

### 27.4 Nested Modal Focus Chain

When modal B opens from within modal A:
1. Modal A's focus trap is deactivated
2. Modal B's focus trap is activated
3. Modal B stores modal A's panel as its trigger element
4. When modal B closes, focus returns to modal A's panel
5. Modal A's focus trap is reactivated

## 29. Mobile Swipe-to-Close — Complete Implementation

### 29.1 Gesture Detection

```js
class SwipeToClose {
  constructor(panel, onClose) {
    this.panel = panel
    this.onClose = onClose
    this.startY = 0
    this.startTime = 0
    this.isDragging = false

    panel.addEventListener('touchstart', this.handleTouchStart.bind(this), { passive: true })
    panel.addEventListener('touchmove', this.handleTouchMove.bind(this), { passive: false })
    panel.addEventListener('touchend', this.handleTouchEnd.bind(this), { passive: true })
  }

  handleTouchStart(e) {
    // Only start if at scroll top
    if (this.panel.scrollTop > 0) return
    this.startY = e.touches[0].clientY
    this.startTime = Date.now()
    this.isDragging = true
  }

  handleTouchMove(e) {
    if (!this.isDragging) return
    const dy = e.touches[0].clientY - this.startY
    if (dy < 0) return // only downward swipe
    e.preventDefault() // prevent scroll while swiping
    const progress = Math.min(1, dy / 150)
    this.panel.style.transform = `translateY(${dy}px)`
    this.panel.style.opacity = 1 - (progress * 0.5)
  }

  handleTouchEnd(e) {
    if (!this.isDragging) return
    this.isDragging = false
    const dy = e.changedTouches[0].clientY - this.startY
    const dt = Date.now() - this.startTime

    if (dy > 100 && dt < 300) {
      this.onClose()
    } else {
      this.panel.style.transform = ''
      this.panel.style.opacity = ''
    }
  }
}
```

### 29.2 Scroll Position Guard

The swipe gesture only activates when the content is scrolled to the very top. If the user is scrolled down, the swipe gesture is ignored to prevent conflicts with vertical scrolling:

```js
handleTouchStart(e) {
  if (this.panel.scrollTop > 5) return // small threshold for scroll bounce
  // ... proceed with swipe
}
```

## 30. Performance Considerations

### 30.1 Animation Performance

All modal animations use GPU-accelerated properties only:
- `opacity` (composited, no layout)
- `transform: scale()` (composited, no layout)
- `transform: translateX()` for sheets (composited, no layout)

Never animate: `width`, `height`, `top`, `left`, `margin`, `padding` — these trigger layout recalculation.

### 30.2 Focus Trap Caching

For modals with many focusable elements, the focusable list is cached and updated via MutationObserver rather than re-scanning on every Tab press:

```js
class CachedFocusTrap {
  constructor(panel) {
    this.panel = panel
    this.focusable = []
    this.rebuild()

    const observer = new MutationObserver(() => this.rebuild())
    observer.observe(panel, { childList: true, subtree: true, attributes: true, attributeFilter: ['disabled', 'tabindex'] })
  }

  rebuild() {
    this.focusable = [...this.panel.querySelectorAll(FOCUSABLE_SELECTORS)]
      .filter(el => el.offsetParent !== null)
  }
}
```

### 30.3 Memory Management

Modal instances are garbage-collected when removed from the DOM. Event listeners are cleaned up in `disconnectedCallback()` (for custom elements) or via Alpine's `destroy()` lifecycle.

## 33. Security Considerations

### 33.1 XSS Prevention

Modal content is rendered via Blade `{{ $slot }}` which escapes HTML by default. User-generated content should be escaped before passing to the modal. Never use `{!! !!}` for untrusted content.

### 33.2 Clickjacking Prevention

The `aria-modal="true"` attribute and the backdrop click handler prevent clickjacking within the modal. The modal does not use `<iframe>` elements.

### 33.3 CSP Compliance

- All modal styles use `adoptedStyleSheets` (no inline `<style>` tags)
- No `eval()` or `Function()` calls in the modal runtime
- No external scripts or styles loaded
- Focus trap uses native DOM methods only

## 34. Open Questions / Risks

- **Stacked modals:** decide z-index and focus-return ownership for modal-on-modal.
- **Mobile full-screen:** the `max-sm:inset-0!` rule makes panels full-screen on small screens — verify the close affordance is visible.
- **Inert support:** the `inert` attribute is not supported in older browsers; provide a fallback with `aria-hidden="true"` + `tabindex="-1"` on all background elements.
- **Focus trap performance:** scanning for focusable elements on every `Tab` press may be slow in modals with many elements; consider caching the focusable list with a MutationObserver.
- **Sheet swipe-to-close:** the swipe gesture may conflict with scroll within the sheet content; need to detect scroll position at the top before allowing swipe.
- **Content Security:** ensure `adoptedStyleSheets` is used for all dynamic modal styles; never inject `<style>` tags.
- **Touch target sizes:** verify all interactive elements in modals meet the 44x44px minimum on mobile per WCAG 2.5.5.
- **Animation performance:** ensure scale transitions on the panel use `transform` and `opacity` only (GPU-accelerated) — never animate `width`, `height`, or `top/left`.
- **iOS rubber-band scrolling:** the `overflow: hidden` on `<html>` fix may cause issues on iOS Safari; test on real devices.
- **Z-index management:** confirm that stacked modals don't conflict with notification toasts or popovers.
- **Form dirty state:** the unsaved-changes warning needs to handle Livewire morphs correctly.
- **Accessibility audit:** confirm WCAG 2.1 AA compliance for all modal patterns, including `alertdialog` role.
- **Backdrop click vs scroll:** on mobile, a tap on the backdrop that started as a scroll gesture should not close the modal.
- **Dynamic content height:** when modal content changes height (e.g. validation errors appearing), the panel should transition smoothly without layout jumps.
- **Keyboard shortcuts:** `Ctrl+S` / `Cmd+S` save shortcuts inside form modals need to be documented and tested.
- **Modal open on page load:** if a modal opens on page load (e.g. from a redirect with flash data), confirm the scroll lock and focus trap activate correctly.
- **Livewire morph compatibility:** confirm that Livewire's morph-based DOM updates don't break the modal's internal state (open/close, focus trap, scroll lock).
- **Content overflow with dynamic heights:** when modal content changes height (e.g. expanding sections), confirm the `max-height` transition works smoothly.
- **RTL sheet animation:** the sheet variant's slide-in animation needs to flip direction in RTL mode.
- **Nested scroll containers:** if the modal panel contains a scrollable inner container, confirm the swipe-to-close gesture only activates when the inner container is at scroll top.

## 37. Troubleshooting Guide

### 37.1 Modal Not Opening

1. Check that `wire:model` is bound to a boolean Livewire property
2. Verify the Livewire property is being set correctly
3. Check browser console for JavaScript errors
4. Ensure `gsmui.js` is loaded
5. Verify the `x-cloak` attribute is present (prevents flash of unstyled content)

### 37.2 Focus Trap Not Working

1. Check that the panel has `tabindex="0"`
2. Verify focusable elements inside the panel are not disabled
3. Check that `inert` is not set on the panel itself
4. Test with keyboard only (no mouse) to confirm Tab cycling

### 37.3 Scroll Lock Not Working

1. Check that `scrollable="true"` is set
2. Verify `document.documentElement.style.overflow` is being set
3. Check for conflicting CSS that overrides `overflow: hidden`
4. On iOS, verify the `position: fixed` fallback is active

### 37.4 Sheet Not Sliding In

1. Check that `variant="sheet"` is set
2. Verify the sheet animation CSS is loaded via `adoptedStyleSheets`
3. Check that `prefers-reduced-motion` is not active
4. Inspect the panel element for correct `transform` values

### 37.5 Stacked Modals Z-Index Issue

1. Check that each modal increments its z-index by 10
2. Verify no other element has a z-index between 50 and the modal's z-index
3. Use browser DevTools to inspect the z-index cascade
4. Check that the backdrop covers the previous modal's panel
