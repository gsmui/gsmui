# Purpose

The file upload UI provides a drag-and-drop and click-to-select surface with visible per-file progress, chunked uploads, and cancel/retry. It uses `<gsmui:file-upload>` as the dropzone and `<gsmui:file-item>` for each queued file, reusing surface tokens, focus patterns, and the action-button rules from AGENTS.md. Progress is reported to Livewire 4 which dispatches processing to the job queue (05.11).

## 2. Chunking & Progress

```js
// assets/js/gsmui/file-upload.js
async upload(file, chunkSize, onProgress) {
  for (let start = 0; start < file.size; start += chunkSize) {
    const chunk = file.slice(start, start + chunkSize);
    await this.root.dispatchEvent(new CustomEvent('chunk', { detail: { chunk, start } }));
    onProgress(Math.min(100, ((start + chunkSize) / file.size) * 100));
    this.root.setAttribute('value', String(onProgress.value)); // observed by MutationObserver
  }
  this.root.dispatchEvent(new Event('input'));
  this.root.dispatchEvent(new Event('change'));
}
```

- Progress bar uses `--gsmui-*` width token (e.g. `style="width: {{ $progress }}%"`), updating via the observed `value` attribute.
- ARIA: dropzone has `role="button"` with `aria-label="{{ __('Upload files') }}"` set via `__()`; each `file-item` exposes `aria-valuenow`/`aria-valuemax` progress.

## 3. CSP & Network

Uploads use `fetch()`/`XHR` to `connect-src 'self'` only. These are first-party requests, so no CSP change is needed beyond the existing `'self'` allow. No `blob:`/`data:` executable content.

## 6. File Validation — Client-Side

### 6.1 Validation Rules

| Rule | Check | Error message |
| --- | --- | --- |
| File type | `file.type` matches `accept` pattern | "File type not allowed" |
| File size | `file.size <= maxSize * 1024` | "File exceeds maximum size" |
| Max files | `files.length + newFiles.length <= maxFiles` | "Too many files" |
| Duplicate | Check `file.name + file.size` against existing | "File already selected" |
| Empty file | `file.size > 0` | "File is empty" |

### 6.2 Accept Pattern Matching

The `accept` prop supports:
- MIME types: `image/*`, `application/pdf`
- Extensions: `.jpg`, `.png`, `.pdf`
- Combined: `image/*,.pdf,.docx`

```js
function matchesAccept(file, accept) {
  if (!accept) return true
  const patterns = accept.split(',').map(p => p.trim())
  return patterns.some(pattern => {
    if (pattern.startsWith('.')) {
      return file.name.toLowerCase().endsWith(pattern.toLowerCase())
    }
    if (pattern.endsWith('/*')) {
      const base = pattern.replace('/*', '')
      return file.type.startsWith(base)
    }
    return file.type === pattern
  })
}
```

### 6.4 Client-Side File Size Formatting

```js
function formatSize(bytes) {
  if (bytes === 0) return '0 B'
  const units = ['B', 'KB', 'MB', 'GB']
  const i = Math.floor(Math.log(bytes) / Math.log(1024))
  return `${(bytes / Math.pow(1024, i)).toFixed(i > 0 ? 1 : 0)} ${units[i]}`
}
```

## 7. Chunking Protocol — Complete Implementation

### 7.1 Chunk Size Configuration

The `chunk-size` prop specifies the chunk size in KB. Default: 1024 KB (1 MB).

| File size | Recommended chunk size | Rationale |
| --- | --- | --- |
| < 1 MB | No chunking | Single request |
| 1-10 MB | 512 KB | Balance speed and reliability |
| 10-100 MB | 1024 KB (1 MB) | Standard |
| > 100 MB | 2048 KB (2 MB) | Reduce overhead |

### 7.2 Chunk Upload Flow

```
1. Client slices file into chunks
2. For each chunk:
   a. Send chunk via fetch() to /upload/chunk
   b. Server acknowledges with offset
   c. Update progress: (currentOffset / fileSize) * 100
   d. Store server offset for resume capability
3. When all chunks complete:
   a. Send /upload/complete with file ID
   b. Server assembles chunks
   c. Set file state to 'done'
```

### 7.3 Upload Implementation

```js
async uploadFile(fileEntry) {
  const file = fileEntry.file
  const chunkSize = this.chunkSize * 1024 // convert KB to bytes
  const totalChunks = Math.ceil(file.size / chunkSize)

  fileEntry.state = 'uploading'
  fileEntry.progress = 0

  for (let chunkIndex = 0; chunkIndex < totalChunks; chunkIndex++) {
    const start = chunkIndex * chunkSize
    const end = Math.min(start + chunkSize, file.size)
    const chunk = file.slice(start, end)

    try {
      const response = await fetch('/upload/chunk', {
        method: 'POST',
        headers: {
          'X-File-Id': fileEntry.id,
          'X-Chunk-Index': chunkIndex,
          'X-Total-Chunks': totalChunks,
          'X-File-Size': file.size,
          'X-File-Name': file.name,
          'X-CSRF-TOKEN': document.querySelector('meta[name="csrf-token"]').content,
        },
        body: chunk,
      })

      if (!response.ok) throw new Error(`Chunk ${chunkIndex} failed`)

      const result = await response.json()
      fileEntry.serverOffset = result.offset
      fileEntry.progress = Math.round(((chunkIndex + 1) / totalChunks) * 100)

    } catch (error) {
      fileEntry.state = 'error'
      fileEntry.error = error.message
      fileEntry.failedChunkIndex = chunkIndex
      throw error
    }
  }

  // Complete upload
  await fetch('/upload/complete', {
    method: 'POST',
    headers: {
      'Content-Type': 'application/json',
      'X-CSRF-TOKEN': document.querySelector('meta[name="csrf-token"]').content,
    },
    body: JSON.stringify({
      fileId: fileEntry.id,
      fileName: file.name,
      fileSize: file.size,
      totalChunks: totalChunks,
    }),
  })

  fileEntry.state = 'done'
  fileEntry.progress = 100
}
```

### 7.4 Progress Tracking

Progress is tracked per-file and displayed as:

The progress bar uses `transition: width 300ms ease` for smooth animation.

```js
  }
```

## 8. Cancel & Retry Mechanism

### 8.1 Cancel Single File

```js
cancelFile(index) {
  const file = this.files[index]
  if (file.abortController) {
    file.abortController.abort()
  }
  file.state = 'cancelled'
  this.files.splice(index, 1)
}
```

### 8.2 Cancel All

```js
cancelAll() {
  this.files.forEach(file => {
    if (file.abortController) {
      file.abortController.abort()
    }
  })
  this.files = []
}
```

### 8.3 Retry Failed File

```js
retryFile(index) {
  const file = this.files[index]
  file.state = 'queued'
  file.error = null
  file.progress = 0
  this.uploadFile(file)
}
```

### 8.4 Retry All Failed

```js
retryAllFailed() {
  this.files
    .filter(f => f.state === 'error')
    .forEach(f => {
      f.state = 'queued'
      f.error = null
      f.progress = 0
      this.uploadFile(f)
    })
}
```

### 8.5 AbortController Integration

Each file upload uses an `AbortController` for cancellation:

```js
async uploadFile(fileEntry) {
  const abortController = new AbortController()
  fileEntry.abortController = abortController

  try {
    const response = await fetch('/upload/chunk', {
      signal: abortController.signal,
      // ... other options
    })
  } catch (error) {
    if (error.name === 'AbortError') {
      // Upload was cancelled — don't set error state
      return
    }
    throw error
  }
}
```

## 9. Concurrent Upload Management

### 9.1 Upload Queue

Files are uploaded sequentially by default. For parallel uploads, use `concurrent-uploads`:

```blade
<gsmui:file-upload wire:model="files" :concurrent-uploads="3" />
```

### 9.2 Concurrency Control

```js
class UploadQueue {
  constructor(concurrency = 1) {
    this.concurrency = concurrency
    this.running = 0
    this.queue = []
  }

  async add(fileEntry) {
    this.queue.push(fileEntry)
    this.processNext()
  }

  async processNext() {
    if (this.running >= this.concurrency || this.queue.length === 0) return

    const fileEntry = this.queue.shift()
    this.running++

    try {
      await this.uploadFile(fileEntry)
    } finally {
      this.running--
      this.processNext()
    }
  }
}
```

### 9.3 Bandwidth Management

To prevent overwhelming the network, the upload queue implements backoff:

```js
// If upload speed drops below 100KB/s, reduce concurrency
if (averageSpeed < 100 * 1024) {
  this.concurrency = Math.max(1, this.concurrency - 1)
}
```

## 11. Error Handling & Recovery

### 11.1 Error Types

| Error | Cause | Recovery |
| --- | --- |--- |
| `FILE_TOO_LARGE` | Exceeds `max-size` | Remove file, show error |
| `INVALID_TYPE` | Not in `accept` list | Remove file, show error |
| `TOO_MANY_FILES` | Exceeds `max-files` | Don't add new files |
| `NETWORK_ERROR` | Connection lost | Auto-retry with backoff |
| `CHUNK_FAILED` | Server rejected chunk | Retry from failed chunk |
| `SERVER_ERROR` | 5xx response | Retry with exponential backoff |
| `DUPLICATE` | Same name+size exists | Skip, show warning |

### 11.2 Exponential Backoff

```js
async retryWithBackoff(fn, maxRetries = 3) {
  for (let attempt = 0; attempt < maxRetries; attempt++) {
    try {
      return await fn()
    } catch (error) {
      if (attempt === maxRetries - 1) throw error
      const delay = Math.pow(2, attempt) * 1000 // 1s, 2s, 4s
      await new Promise(resolve => setTimeout(resolve, delay))
    }
  }
}
```

### 11.3 Error Display

Errors are displayed per-file in the file item:


### 12.1 Upload Endpoint

## 15. JavaScript Architecture

### 15.1 FileUpload Class

```js
// assets/js/gsmui/file-upload.js
import { setAttribute, removeAttribute } from './utils.js'

class GsmuiFileUpload {
  constructor(el) {
    this.el = el
    this.files = []
    this.isDragging = false
    this.chunkSize = parseInt(el.getAttribute('chunk-size') || '1024', 10)
    this.maxSize = parseInt(el.getAttribute('max-size') || '10240', 10)
    this.maxFiles = parseInt(el.getAttribute('max-files') || '10', 10)
    this.accept = el.getAttribute('accept')

    this.setupMutationObserver()
  }

  setupMutationObserver() {
    const observer = new MutationObserver((mutations) => {
      for (const mutation of mutations) {
        if (mutation.attributeName === 'value') {
          this.syncFromServer(JSON.parse(this.el.getAttribute('value') || '[]'))
        }
        if (mutation.attributeName === 'disabled') {
          this.toggleDisabled()
        }
      }
    })
    observer.observe(this.el, { attributes: true, attributeFilter: ['value', 'disabled'] })
  }

  processFiles(fileList) {
    const newFiles = [...fileList]
      .filter(f => this.validateFile(f))
      .slice(0, this.maxFiles - this.files.length)

    newFiles.forEach(file => {
      this.files.push({
        id: crypto.randomUUID(),
        file: file,
        name: file.name,
        size: file.size,
        type: file.type,
        state: 'queued',
        progress: 0,
        error: null,
        preview: this.generatePreview(file),
        abortController: null,
        serverOffset: 0,
        failedChunkIndex: null,
      })
    })

    this.uploadQueue()
  }

  validateFile(file) {
    if (this.accept && !this.matchesAccept(file, this.accept)) {
      this.addError(file, 'Invalid file type')
      return false
    }
    if (file.size > this.maxSize * 1024) {
      this.addError(file, 'File too large')
      return false
    }
    if (file.size === 0) {
      this.addError(file, 'File is empty')
      return false
    }
    if (this.isDuplicate(file)) {
      this.addError(file, 'File already selected')
      return false
    }
    return true
  }

  // ... additional methods
}
```

## 17. Integration with Livewire

### 17.1 Livewire Component

```php
class FileUpload extends Component
{
    public $files = [];
    public $uploadedFiles = [];

    public function updatedFiles()
    {
        // Process uploaded files
        foreach ($this->files as $file) {
            $path = $file->store('uploads', 'public');
            $this->uploadedFiles[] = [
                'path' => $path,
                'name' => $file->getClientOriginalName(),
                'size' => $file->getSize(),
            ];
        }
    }

    public function cancel($fileId)
    {
        $this->files = collect($this->files)
            ->filter(fn($f) => $f->getClientOriginalName() !== $fileId)
            ->toArray();
    }
}
```

### 17.2 Chunk Upload Handler

```php
public function uploadChunk(Request $request)
{
    $fileId = $request->header('X-File-Id');
    $chunkIndex = $request->header('X-Chunk-Index');
    $totalChunks = $request->header('X-Total-Chunks');

    $chunkPath = storage_path("app/chunks/{$fileId}/{$chunkIndex}");
    file_put_contents($chunkPath, $request->getContent());

    return response()->json([
        'ok' => true,
        'offset' => $request->header('X-Chunk-Index') * $request->header('X-Chunk-Size'),
    ]);
}
```

### 17.3 Complete Upload Handler

```php
public function uploadComplete(Request $request)
{
    $fileId = $request->input('fileId');
    $fileName = $request->input('fileName');
    $totalChunks = $request->input('totalChunks');

    $finalPath = storage_path("app/uploads/{$fileName}");
    $chunkDir = storage_path("app/chunks/{$fileId}");

    // Assemble chunks
    for ($i = 0; $i < $totalChunks; $i++) {
        $chunkPath = "{$chunkDir}/{$i}";
        if (!file_exists($chunkPath)) {
            throw new \Exception("Chunk {$i} missing");
        }
        file_put_contents($finalPath, file_get_contents($chunkPath), FILE_APPEND);
    }

    // Clean up chunks
    $this->deleteDirectory($chunkDir);

    return response()->json(['ok' => true, 'path' => $finalPath]);
}
```

## 18. Performance Considerations

### 18.1 Memory Management

- Revoke object URLs when files are removed
- Don't store full file content in JS — use `File.slice()` for chunks
- Limit concurrent file previews to prevent memory bloat

### 18.2 Network Optimization

- Use `fetch()` with streaming for better performance than XHR
- Implement chunk size auto-tuning based on network speed
- Compress chunks on-the-fly if the server supports it

### 18.3 DOM Efficiency

- Use `x-for` with `:key` for efficient file list rendering
- Don't re-render the entire list on progress updates — update individual items
- Use `requestAnimationFrame` for progress bar animations

## 23. Troubleshooting Guide

### 23.1 Files Not Appearing

1. Check that `wire:model` is bound to a public Livewire property
2. Verify the file input `accept` attribute matches the file type
3. Check browser console for JavaScript errors
4. Verify `gsmui.js` is loaded

### 23.2 Upload Stalling

1. Check network connection
2. Verify the upload endpoint is accessible
3. Check server logs for errors
4. Verify CSRF token is valid

### 23.3 Progress Not Updating

1. Check that the `value` attribute is being set on the file element
2. Verify the MutationObserver is active
3. Check that the progress bar CSS transitions are working

### 23.4 Large File Failures

1. Check server `upload_max_filesize` and `post_max_size` settings
2. Verify chunk size is appropriate for the file size
3. Check server memory limits
4. Verify the chunk assembly endpoint handles large files

### 23.5 Mobile Camera Not Working

1. Check that `accept="image/*"` is set
2. Verify `capture="environment"` is set for rear camera
3. Test on actual mobile device (not just responsive mode)
4. Check that the file input is not hidden by CSS

## 29. Drag-and-Drop Edge Cases

### 29.1 Nested Drop Zones

When the file upload is inside a modal or another drop zone, the drag events must not bubble up:

```js
handleDragEnter(e) {
  e.stopPropagation()
  this.isDragging = true
}
```

### 29.2 External Drag from Desktop

Dragging files from the desktop works via the standard `drop` event. The `dataTransfer.files` contains the dropped files.

### 29.3 Drag from Application

Dragging files from other applications (e.g. Finder, Explorer) works the same as desktop drag. The `dataTransfer.types` includes `Files`.

### 29.4 Drag from Email

Dragging an image from an email client may provide a URL instead of a file. The handler should check for both:

```js
handleDrop(e) {
  e.preventDefault()
  this.isDragging = false

  if (e.dataTransfer.files.length > 0) {
    this.processFiles(e.dataTransfer.files)
  } else if (e.dataTransfer.getData('text/uri-list')) {
    // Handle URL drops (optional)
    this.handleUrlDrop(e.dataTransfer.getData('text/uri-list'))
  }
}
```

## 30. Upload Speed & ETA Calculation

### 30.1 Speed Measurement

Upload speed is calculated using a sliding window of the last 5 seconds:

```js
calculateSpeed(fileEntry) {
  const now = Date.now()
  const elapsed = (now - fileEntry.startTime) / 1000
  if (elapsed < 1) return 0
  return fileEntry.serverOffset / elapsed // bytes per second
}
```

### 30.2 ETA Calculation

```js
calculateETA(fileEntry) {
  const speed = fileEntry.uploadSpeed
  if (speed === 0) return null
  const remaining = fileEntry.file.size - fileEntry.serverOffset
  return Math.ceil(remaining / speed) // seconds
}
```

### 30.3 Display

```blade
    <span class="mx-1">·</span>

</div>
```

### 30.4 Formatting Helpers

```js
function formatSpeed(bytesPerSecond) {
  if (bytesPerSecond === 0) return '—'
  if (bytesPerSecond < 1024) return `${bytesPerSecond} B/s`
  if (bytesPerSecond < 1024 * 1024) return `${(bytesPerSecond / 1024).toFixed(1)} KB/s`
  return `${(bytesPerSecond / (1024 * 1024)).toFixed(1)} MB/s`
}

function formatETA(seconds) {
  if (seconds === null) return '—'
  if (seconds < 60) return `${seconds}s`
  if (seconds < 3600) return `${Math.floor(seconds / 60)}m ${seconds % 60}s`
  return `${Math.floor(seconds / 3600)}h ${Math.floor((seconds % 3600) / 60)}m`
}
```

## 31. Image Compression (Planned)

### 31.1 Client-Side Compression

For image files, client-side compression reduces upload size:

```js
async function compressImage(file, maxWidth = 1920, quality = 0.8) {
  return new Promise((resolve) => {
    const canvas = document.createElement('canvas')
    const ctx = canvas.getContext('2d')
    const img = new Image()

    img.onload = () => {
      const ratio = Math.min(maxWidth / img.width, 1)
      canvas.width = img.width * ratio
      canvas.height = img.height * ratio
      ctx.drawImage(img, 0, 0, canvas.width, canvas.height)
      canvas.toBlob(resolve, 'image/jpeg', quality)
    }

    img.src = URL.createObjectURL(file)
  })
}
```

### 31.2 Compression Toggle

Compression is opt-in via a `compress` prop:

```blade
<gsmui:file-upload wire:model="images" accept="image/*" :compress="true" :max-width="1920" :quality="0.8" />
```

### 31.3 Compression Feedback

When compression is active, the file item shows the compressed size:

```blade
<p class="text-xs text-zinc-500">
    <span x-text="formatSize(file.size)"></span>
    <span x-show="file.compressedSize" class="text-emerald-500">
        → <span x-text="formatSize(file.compressedSize)"></span>
    </span>
</p>
```

## 32. Service Worker Background Uploads (Planned)

### 32.1 Concept

Service Workers enable upload continuation even when the user navigates away from the page. The upload queue is persisted to IndexedDB and managed by the Service Worker.

### 32.2 Implementation Sketch

```js
// Register service worker
navigator.serviceWorker.register('/sw.js')

// Offload upload to service worker
navigator.serviceWorker.controller.postMessage({
  type: 'upload-file',
  fileId: fileEntry.id,
  chunks: chunks,
  endpoint: '/upload/chunk',
})
```

### 32.3 Limitations

- Service Workers don't have direct access to `File` objects — file content must be serialized
- Background uploads are limited to a few minutes on mobile browsers
- Not supported in all browsers (check compatibility)

## 39. Performance Benchmarks

### 39.1 Target Metrics

| Metric | Target | Measurement |
| --- | --- | --- |
| Dropzone render | < 16ms | Playwright `performance.mark()` |
| File validation | < 5ms per file | `performance.measure()` |
| Thumbnail generation | < 100ms per image | `performance.measure()` |
| Chunk upload (1MB) | < 2s on broadband | Network throttled Playwright |
| Progress bar update | 60fps | `requestAnimationFrame` counter |

### 39.2 Performance Anti-Patterns

- Do NOT store full file content in JS memory — use `File.slice()` for chunks
- Do NOT generate thumbnails for every file simultaneously — batch and defer
- Do NOT use `setInterval` for progress updates — use MutationObserver
- Do NOT re-render the entire file list on progress updates — update individual items
- Do NOT use `document.querySelectorAll` with complex selectors — cache node lists
