> See also: `05.21-admin.md` (admin/billing domain), `06.53-orders.md` (orders),

> and does NOT re-document the payment-provider integration or invoice schema — those live in 05/06.

# Purpose

This document defines the billing UI: the public pricing page, the plan-comparison table, the
checkout form (card capture via `gsmui:credit-card`), and the authenticated subscription/
invoices management screen. It receives the cart hand-off from the marketplace (`08.28`).

---

## 1. Page Composition

| Screen | GsmUi Components | Livewire |
| --- | --- | --- |
| Pricing | `gsmui:card` (plan), `gsmui:tabs` (monthly/yr), `gsmui:button` | `Pricing::plans()` |
| Checkout | `gsmui:credit-card`, `gsmui:input`, `gsmui:button` | `Checkout::pay()` |
| Subscriptions | `gsmui:table`, `gsmui:badge`, `gsmui:button` (manage) | `Billing::subs()` |
| Invoices | `gsmui:table`, `gsmui:button` (download) | `Billing::invoices()` |

## 2. Component Tree

```text
<public> gsmui:layouts.marketing
└── <pricing>
    ├── gsmui:tabs (billing period)
    └── gsmui:card × N (plan)
        ├── gsmui:heading (price, tabular-nums)
        ├── gsmui:badge (popular)
        └── gsmui:button (choose → checkout)

gsmui:modal (checkout)
└── <form wire:submit="pay">
    ├── gsmui:credit-card (wire:model="card")
    ├── gsmui:input (wire:model="email")  (data-invalid: on error)
    └── gsmui:button (pay)
```

## 3. Data Flow — Plan → Paid

```text
gsmui:button "Choose plan"
        │  wire:click="start(planId)"
        ▼
Checkout::$plan  ──▶  gsmui:modal opens

gsmui:credit-card wire:model="card"
        │  input + change events
        ▼
<form wire:submit="pay">
        │
        ▼
Checkout::pay()  ──▶  SubscriptionEngine (06.60)  ──▶  gsmui:toast
```

- `gsmui:credit-card` renders self-hosted payment icons (`gsmui:payment-icon-card`) — no external
  card-art CDN (CSP-safe).
- Card input invalid state layered with `data-invalid:` classes; silent revert on gateway decline.
- The whole trigger-strip keeps `cursor: text` except over action buttons.

## 4. CSP & Styling

- No external fonts/scripts; checkout CSS via `adoptedStyleSheets`.
- ARIA labels via `__()` (e.g. `__('Card number')`), English fallback in JS.

---

## Open Questions / Risks

- 3-D Secure / redirect flow — inline modal vs full-page redirect? Payment provider decision.
- Invoice download must stay `img-src 'self' data:` / same-origin.

## 11. Billing Data Flow

### 11.1 Plan Selection

```php
public function selectPlan(string $planId): void
{
    $plan = Plan::findOrFail($planId);
    $this->selectedPlan = $plan;
    $this->checkoutOpen = true;
}
```

### 11.2 Payment Processing

```php
public function processPayment(): void
{
    $this->validate($this->validateCheckout());

    $user = auth()->user();

    // Create or update Stripe customer
    if (!$user->stripe_id) {
        $customer = $user->createAsStripeCustomer([
            'email' => $this->email,
            'name' => $this->name,
        ]);
    }

    // Charge the customer
    $payment = $user->charge($this->selectedPlan->price * 100, $this->cardToken, [
        'description' => "{$this->selectedPlan->name} subscription",
    ]);

    if ($payment->succeeded) {
        // Create subscription
        $user->newSubscription('default', $this->selectedPlan->stripe_price_id)
            ->create($this->cardToken, [
                'email' => $this->email,
            ]);

        $this->dispatch('show-toast', ['message' => 'Subscription created successfully']);
        $this->redirect()->route('billing.index');
    } else {
        $this->dispatch('show-toast', ['message' => 'Payment failed']);
    }
}
```

### 11.3 Subscription Cancellation

```php
public function cancelSubscription(): void
{
    $user = auth()->user();
    $user->subscription('default')->cancel();

    $this->dispatch('show-toast', ['message' => 'Subscription cancelled']);
    $this->redirect()->route('billing.index');
}
```

### 19.2 Stripe Elements Integration

```javascript
// Initialize Stripe Elements
const stripe = Stripe('pk_test_...');
const elements = stripe.elements();
const cardElement = elements.create('card', {
    style: {
        base: {
            fontSize: '16px',
            color: '#32325d',
        },
    },
});
cardElement.mount('#card-element');

// Handle card tokenization
cardElement.on('change', (event) => {
    if (event.error) {
        document.querySelector('.gsmui-credit-card-error').textContent = event.error.message;
    } else {
        document.querySelector('.gsmui-credit-card-error').textContent = '';
    }
});

// Tokenize card on form submit
document.querySelector('form').addEventListener('submit', async (e) => {
    e.preventDefault();
    const { token, error } = await stripe.createToken(cardElement);
    if (error) {
        document.querySelector('.gsmui-credit-card-error').textContent = error.message;
    } else {
        Livewire.dispatch('card-tokenized', { token: token.id });
    }
});
```

    a.click();

## 20. Billing Database Schema

### 20.1 Plans Table

```sql
CREATE TABLE billing_plans (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    name VARCHAR(100) NOT NULL,
    slug VARCHAR(100) UNIQUE NOT NULL,
    description TEXT,
    price_monthly DECIMAL(10,2) NOT NULL,
    price_yearly DECIMAL(10,2) NOT NULL,
    stripe_price_monthly VARCHAR(255),
    stripe_price_yearly VARCHAR(255),
    features JSON NOT NULL,
    limits JSON NOT NULL,
    is_popular BOOLEAN DEFAULT FALSE,
    is_active BOOLEAN DEFAULT TRUE,
    sort_order INT DEFAULT 0,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP
);
```

### 20.2 Subscriptions Table

```sql
CREATE TABLE billing_subscriptions (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    user_id BIGINT NOT NULL,
    plan_id BIGINT NOT NULL,
    stripe_id VARCHAR(255) UNIQUE,
    stripe_status VARCHAR(50),
    stripe_price VARCHAR(255),
    quantity INT DEFAULT 1,
    trial_ends_at TIMESTAMP NULL,
    ends_at TIMESTAMP NULL,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    FOREIGN KEY (user_id) REFERENCES users(id) ON DELETE CASCADE,
    FOREIGN KEY (plan_id) REFERENCES billing_plans(id)
);
```

### 20.3 Invoices Table

```sql
CREATE TABLE billing_invoices (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    user_id BIGINT NOT NULL,
    stripe_id VARCHAR(255) UNIQUE,
    number VARCHAR(50) NOT NULL,
    total DECIMAL(10,2) NOT NULL,
    discount DECIMAL(10,2) DEFAULT 0,

    period_end TIMESTAMP NOT NULL,
    paid_at TIMESTAMP NULL,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    FOREIGN KEY (user_id) REFERENCES users(id) ON DELETE CASCADE
);
```

## 22. Billing Error Handling

### 22.1 Error States

| Error | Display | Action |
| --- | --- | --- |
| Card declined | "Card declined" | Retry with different card |
| Insufficient funds | "Insufficient funds" | Retry with different card |
| Expired card | "Card expired" | Update card details |
| Invalid CVC | "Invalid CVC" | Re-enter CVC |
| Invalid card number | "Invalid card number" | Re-enter card number |
| Coupon invalid | "Invalid coupon" | Clear coupon input |
| Subscription inactive | "Subscription inactive" | Reactivate subscription |
| Payment failed | "Payment failed" | Retry payment |

### 22.2 Error Recovery

- Auto-retry failed payments (up to 3 times)
- Fallback to cached plan data
- Graceful degradation for missing features
- User-friendly error messages

### 22.3 Error Logging

- Log all payment failures to Sentry
- Log Stripe webhook errors
- Track error rates per plan
- Alert on error rate spikes

## 32. Billing Accessibility

### 32.1 Keyboard Navigation

| Key | Action |
| --- | --- |
| `Tab` | Navigate through interactive elements |
| `Shift+Tab` | Navigate backwards |
| `Enter` | Activate button/link |
| `Space` | Toggle checkbox/radio |
| `Arrow keys` | Navigate within radio group |
| `Escape` | Close modal |

### 32.2 Screen Reader Support

- All form inputs have associated labels
- All buttons have descriptive text
- All error messages are announced via `aria-live`
- All progress indicators have `role="progressbar"`
- All modals have `aria-label` and `aria-modal="true"`

### 32.3 Focus Management

- Focus ring: `outline: 2px solid -webkit-focus-ring-color`
- Focus offset: `outline-offset: 2px`
- Focus trap in modals
- Focus restoration on modal close

### 32.4 Error Announcements

```html
<!-- Live region for error messages -->
<div aria-live="assertive" class="sr-only">
  <p>Error: Card declined. Please try a different card.</p>
</div>
```
