# Purpose

Forms in GsmUi are Livewire-bound, accessible, and consistent. `gsmui:input` is the reference implementation; every field component (`checkbox`, `radio`, `switch`, `textarea`, `select`, `file-upload`, …) mirrors its `wire:model`, `label`/`description`, `invalid`, and `disabled` contracts. Validation messages surface from Laravel's `$errors` bag and render through `data-invalid` styling per `08.16`.

---

## 1. Core Binding Contract

All fields accept:

| Prop | Purpose |
| --- | --- |
| `wire:model` | Livewire binding (passed through to the native control) |
| `name` | Falls back to the `wire:model` name for error lookup |
| `value` | Initial/unbound value |
| `invalid` | bool — forces invalid UI; auto-set when `$errors->has($name)` |
| `disabled` / `readonly` | state flags |
| `label` / `description` | accessible labeling |

```blade
<gsmui:input wire:model="email" label="{{ __('Email') }}"
            description="{{ __('We never share it.') }}" type="email" />
```

## 2. `gsmui:input` Reference Implementation

From `stubs/resources/views/gsmui/input/index.blade.php`:

- `name ??= $attributes->whereStartsWith('wire:model')->first();`
- `$invalid = $invalid ?: ($name && $errors->has($name));`
- Size progression (must match siblings): `sm`=`h-8 text-sm rounded-md px-3`, `xs`=`h-6 text-xs rounded-md px-3`, default=`h-10 text-base sm:text-sm rounded-lg px-3`.
- Base surface: `bg-white dark:bg-white/10`, `shadow-xs`, border `border-zinc-200 border-b-zinc-300/80 dark:border-white/10`.
- Invalid: `border border-red-500` + `aria-invalid="true" data-invalid` on the `<input>`.
- Disabled: `disabled:shadow-none` + `disabled:text-zinc-500`.

### 2.1 Whole-Trigger-One-Input

When the input is a trigger (e.g. date-picker), clicking whitespace focuses the text input; `cursor: text` across the container except over action buttons (`clearable`/`copyable` use `<gsmui:button as="div">` with `cursor-pointer`).

## 3. Label & Description Wrapper

Fields compose via `gsmui:with-field` / `gsmui:field` so label, control, description, and error align:

```blade
<gsmui:field label="{{ __('Email') }}" description="{{ $message }}">
    <gsmui:input wire:model="email" :invalid="$errors->has('email')" />
</gsmui:field>
```

- Label is associated via `<label for>` or wrapping; description uses `aria-describedby`.
- Error text uses `__()` and is linked with `aria-describedby` + `role="alert"` for the live region (`08.16`, `08.19`).

## 4. Validation Display

| State | Visual | ARIA |
| --- | --- | --- |
| Valid | base border | — |
| Invalid | `data-invalid` red border + error icon | `aria-invalid="true"` + message `aria-describedby` |
| Disabled | `shadow-none`, muted text | `disabled` attr, removed from tab order |
| Empty | placeholder visible, normal | — |

Invalid messages render from `error:name`/`error:bag` slots in `gsmui:input` (see its `@blaze(unsafe: [...])` slot allow-list). Never show a shake animation on invalid — silent revert per AGENTS.md philosophy.

## 5. Trigger Variants & ARIA

| Trigger type | Role | Notes |
| --- | --- | --- |
| `type="input"` | `role="combobox"` on `<input>` | `aria-expanded`, `aria-controls` |
| `type="button"` | native `<button>` + `aria-haspopup="dialog"` | used by date-picker/select |

Use `<gsmui:button>` for clear/copy/dropper actions inside triggers; `<gsmui:button as="div">` only when nested in a `<button>`.

## 6. Behavioral Props (naming)

Follow AGENTS.md naming: short props, `-able` suffix for opt-in behaviors, `type` for trigger variants:
`clearable`, `copyable`, `searchable`, `viewable`, `multiple`, `readonly`. Prop order in docs: `wire:model, value, name, type, placeholder, size → clearable/copyable/... → label, description, disabled, invalid`.

## 7. Component Specifications

### 7.1 `gsmui:input` Full Specification

The `gsmui:input` component is the canonical text input for GsmUi. It serves as both a standalone input and the foundation for trigger-based components (date-picker, select, color-picker).

#### 7.1.1 HTML Structure

```html
<div data-gsmui-input class="relative">
  <input
    type="text"
    wire:model="email"
    name="email"
    id="email"
    class="block w-full rounded-lg border border-zinc-200 border-b-zinc-300/80 bg-white
           px-3 py-2 text-base shadow-xs transition
           dark:border-white/10 dark:bg-white/10
           sm:text-sm
           disabled:shadow-none disabled:text-zinc-500
           data-invalid:border-red-500"
    aria-invalid="true"
    aria-describedby="email-error"
    data-invalid
  />
</div>
```

#### 7.1.2 Size Variants

| Size | Height | Text | Padding | Border Radius | Use Case |
|------|--------|------|---------|---------------|----------|
| `xs` | `h-6` | `text-xs` | `px-3 py-1` | `rounded-md` | Compact tables, inline edits |
| `sm` | `h-8` | `text-sm` | `px-3 py-1.5` | `rounded-md` | Dense forms, sidebar panels |
| default | `h-10` | `text-base sm:text-sm` | `px-3 py-2` | `rounded-lg` | Standard forms |
| `lg` | `h-12` | `text-base` | `px-4 py-3` | `rounded-lg` | Hero forms, landing pages |

Each size variant must be verified against sibling components (select, date-picker) to ensure pixel-level parity across the form system. Use Playwright to measure actual rendered heights before shipping.

#### 7.2.2 Auto-Resize Behavior

When `auto-resize` prop is set, the textarea grows/shrinks with content:

```javascript
function autoResize(textarea) {
  textarea.style.height = 'auto'
  textarea.style.height = textarea.scrollHeight + 'px'
}
```

- Bound to `input` event, debounced 16ms (one frame)
- Min height: `h-10` (single line)
- Max height: `max-h-48` (6 lines)
- Under reduced motion, skip height transition

### 7.8 `gsmui:color-picker` Specification

#### 7.8.1 Architecture

The color picker composes `gsmui:input` (text trigger) + `gsmui:popover` + `ui-slider` (hue) + `ui-slider` (saturation/lightness). Uses HSL internally, converts to hex/rgb on output.

```text
gsmui:input (trigger, type="text")
└── gsmui:popover (shared dialog surface)
    ├── <canvas> (saturation/lightness picker)
    ├── ui-slider (hue, 0-360)
    ├── ui-slider (alpha, 0-1)
    ├── gsmui:input (hex input)
    └── gsmui:button (dropper/clear)
```

#### 7.8.2 Props

| Prop | Type | Default | Purpose |
|------|------|---------|---------|
| `wire:model` | string | — | Color value binding |
| `name` | string | derived | Form field name |
| `format` | string | `hex` | Output format: `hex`/`rgb`/`hsl` |
| `value` | string | `#000000` | Initial color |
| `swatches` | bool | `false` | Show preset swatches |
| `dropper` | bool | `false` | Show eye-dropper button |
| `clearable` | bool | `false` | Show clear button |
| `copyable` | bool | `false` | Show copy button |
| `label` | string | — | Accessible label |
| `disabled` | bool | `false` | Disable |
| `invalid` | bool | `false` | Invalid state |
| `size` | string | `default` | `sm`/default/`lg` |

#### 7.8.3 Keyboard Navigation (2D Area)

| Key | Action |
|-----|--------|
| Arrow keys | Move 1px in the saturation/lightness canvas |
| Shift + Arrow | Move 10px |
| Home | Left edge (min saturation) |
| End | Right edge (max saturation) |
| PageUp | Top edge (max lightness) |
| PageDown | Bottom edge (min lightness) |

#### 7.8.4 Canvas Rendering

The saturation/lightness canvas uses a 2D gradient:

```javascript
function drawSaturationLightness(ctx, hue, width, height) {
  // Horizontal: saturation 0-100%
  // Vertical: lightness 100% (top) to 0% (bottom)
  for (let x = 0; x < width; x++) {
    for (let y = 0; y < height; y++) {
      const s = x / width * 100
      const l = 100 - (y / height * 100)
      ctx.fillStyle = `hsl(${hue}, ${s}%, ${l}%)`
      ctx.fillRect(x, y, 1, 1)
    }
  }
}
```

Use `<canvas>` context — no color parsing libraries per AGENTS.md. The browser handles CSS color parsing natively.

## 8. State Management Patterns

### 8.1 Livewire Component State

```php
class UserForm extends Component
{
    public string $name = '';
    public string $email = '';
    public bool $terms = false;

    public function save(): void
    {
        $validated = $this->validate([
            'name' => 'required|string|max:255',
            'email' => 'required|email|unique:users',
            'terms' => 'accepted',
        ]);

        User::create($validated);
        $this->toast(__('User created.'));
    }
}
```

### 8.2 Optimistic Updates

For fields that don't require server round-trips (toggle switches, checkboxes):

```php
public function toggleActive(): void
{
    $this->user->update(['active' => !$this->user->active]);
    // No redirect — Livewire updates DOM via morph
}
```

### 8.3 Debounced Inputs

For search/filter fields, use `wire:model.live.debounce.300ms` to avoid excessive requests:

```blade
<gsmui:input wire:model.live.debounce.300ms="search" placeholder="{{ __('Search...') }}" />
```

### 8.4 Form Reset Pattern

```php
public function resetForm(): void
{
    $this->reset(['name', 'email', 'terms']);
    $this->resetValidation();
}
```

### 8.5 Dirty State Detection

```blade
<div data-dirty="wire:model.isDirty('name')">
    @if ($this->isDirty('name'))
        <span class="text-xs text-amber-600">{{ __('Unsaved changes') }}</span>
    @endif
</div>
```

## 10. Accessibility Deep-Dive

### 10.1 Label Association Rules

| Pattern | HTML | When to Use |
|---------|------|-------------|
| Explicit `<label for>` | `<label for="email">Email</label><input id="email">` | Standard fields |
| Wrapping `<label>` | `<label><input> Text</label>` | Checkbox/radio |
| `aria-label` | `<input aria-label="Email">` | No visible label (search) |
| `aria-labelledby` | `<input aria-labelledby="heading">` | Label in different DOM node |

### 10.2 Error Message Linking

Every error message must be linked to its input via `aria-describedby`:

```html
<input
  id="email"
  aria-invalid="true"
  aria-describedby="email-error"
/>
<span id="email-error" role="alert" class="text-sm text-red-600">
  The email field is required.
</span>
```

### 10.3 Required Fields

- Use `aria-required="true"` on the input (not `required` attribute alone)
- Visually indicate required with `*` after the label text
- Screen readers announce "required" via `aria-required`

### 10.4 Fieldset & Legend

Group related fields (radio groups, checkbox groups) in `<fieldset>` with `<legend>`:

```html
<fieldset>
  <legend class="text-sm font-medium text-zinc-900">Notification preferences</legend>
  <!-- radio/checkbox group here -->
</fieldset>
```

### 10.5 Autocomplete Attributes

Map `wire:model` fields to HTML autocomplete values for autofill support:

| Field | Autocomplete |
|-------|--------------|
| name | `name` |
| email | `email` |
| password | `current-password` / `new-password` |
| phone | `tel` |
| address | `street-address` |
| city | `address-level2` |
| state | `address-level1` |
| zip | `postal-code` |
| country | `country` |

### 10.6 Form Error Summary

For forms with multiple errors, provide an error summary at the top:

```html
<div role="alert" tabindex="-1" class="rounded-lg border border-red-200 bg-red-50 p-4">
  <h3 class="text-sm font-medium text-red-800">There were 2 errors with your submission</h3>
  <ul class="mt-2 list-disc list-inside text-sm text-red-700">
    <li><a href="#email" class="underline">Email is required</a></li>
    <li><a href="#password" class="underline">Password must be at least 8 characters</a></li>
  </ul>
</div>
```

Move focus to the summary on form submission failure. On success, announce via `role="status"`.

### 10.7 Keyboard Shortcuts

For power-user forms, support keyboard shortcuts:

| Shortcut | Action |
|----------|--------|
| `Ctrl/Cmd + Enter` | Submit form |
| `Ctrl/Cmd + S` | Save (same as submit) |
| `Escape` | Cancel / close modal |
| `Ctrl/Cmd + Z` | Undo last change |
| `Tab` | Next field |
| `Shift + Tab` | Previous field |

Document shortcuts in tooltips and help text. Provide visible keyboard hints via `gsmui:kbd`.

## 11. Validation Display Contract

### 11.1 Validation Timing

| Trigger | Behavior |
|---------|----------|
| On blur | Validate single field, show error |
| On submit | Validate all fields, show all errors |
| On change (live) | Only validate if field was previously invalid |
| On server response | Update all error bags |

### 11.2 Error Message Formatting

- Use `__()` for all error messages (localization)
- Keep messages under 120 characters
- Start with the field name: "Email is required" not "is required"
- Use present tense: "Email is invalid" not "Email was invalid"

### 11.3 Error Bag Structure

```php
// Laravel validation returns:
[
  'email' => ['The email field is required.'],
  'password' => ['The password must be at least 8 characters.'],
]
```

### 11.4 Server-Side Error Rendering

```blade
@if ($errors->has('email'))
    <p id="email-error" class="mt-1 text-sm text-red-600" role="alert">
        {{ $errors->first('email') }}
    </p>
@endif
```

### 11.5 Client-Side Validation

For immediate feedback before server round-trip, implement client-side constraints:

```javascript
const validators = {
  email: (value) => /^[^\s@]+@[^\s@]+\.[^\s@]+$/.test(value),
  required: (value) => value !== '' && value !== null,
  minLength: (min) => (value) => value.length >= min,
  maxLength: (max) => (value) => value.length <= max,
  pattern: (regex) => (value) => regex.test(value),
}
```

Client-side validation is a UX enhancement, not a security measure. Always validate server-side.

### 11.6 Live Validation Integration

```blade
<gsmui:input
    wire:model.live="email"
    wire:blur="validate('email')"
    name="email"
    label="{{ __('Email') }}"
    :invalid="$errors->has('email')"
/>
```

The `wire:blur` triggers validation on blur. The `:invalid` prop binds to the error state and applies `data-invalid` styling.

## 14. Performance Considerations

### 14.1 Debounce Strategy

| Field Type | Debounce | Rationale |
|------------|----------|-----------|
| Search | 300ms | Avoid excessive queries |
| Text input | 500ms | Balance responsiveness vs server load |
| Textarea | 500ms | Same as text |
| Select | immediate | No debounce needed |
| Checkbox/radio | immediate | Boolean toggle, cheap |
| Switch | immediate | Boolean toggle, cheap |
| File upload | immediate | File objects, no debounce |

### 14.2 Lazy Loading

For forms with many fields, lazy-load sections:

```blade
<div wire:init="loadSection('billing')">
    @if ($billingLoaded)
        {{-- billing fields --}}
    @else
        <gsmui:skeleton class="h-10 w-full" count="3" />
    @endif
</div>
```

### 14.3 Server-Side Rendering

Forms should render server-side for initial load. Use `wire:ignore` only for sections that are purely client-side (e.g., rich text editor content).

### 14.4 Caching Strategies

- Cache option lists (selects) in `cache()` method
- Use `wire:poll` for real-time validation feedback on critical fields
- Cache form state in `session()` for multi-step forms

## 35. Form Validation Patterns

### 35.1 Client-Side Validation Library

```javascript
const validators = {
  required: (v) => v !== '' && v !== null && v !== undefined || 'This field is required',
  email: (v) => /^[^\s@]+@[^\s@]+\.[^\s@]+$/.test(v) || 'Invalid email address',
  min: (min) => (v) => v.length >= min || `Must be at least ${min} characters`,
  max: (max) => (v) => v.length <= max || `Must be no more than ${max} characters`,
  pattern: (re) => (v) => re.test(v) || 'Invalid format',
  numeric: (v) => !isNaN(v) || 'Must be a number',
  integer: (v) => Number.isInteger(Number(v)) || 'Must be a whole number',
  url: (v) => {
    try { new URL(v); return true }
    catch { return 'Invalid URL' }
  },
  phone: (v) => /^\+?[\d\s()-]{7,}$/.test(v) || 'Invalid phone number',
  same: (field) => (v, form) => v === form[field] || `Must match ${field}`,
  different: (field) => (v, form) => v !== form[field] || `Must be different from ${field}`,
}
```

## 38. Offline Support

### 38.1 Pending Changes Queue

// Store unsaved changes in localStorage
function queueChange(formId, field, value) {
  const pending = JSON.parse(localStorage.getItem('pending-changes') || '{}')
  pending[formId] = pending[formId] || {}
  pending[formId][field] = value
  localStorage.setItem('pending-changes', JSON.stringify(pending))
}

// Sync on reconnection
window.addEventListener('online', async () => {
  const pending = JSON.parse(localStorage.getItem('pending-changes') || '{}')
  for (const [formId, changes] of Object.entries(pending)) {
    await fetch(`/api/forms/${formId}`, {
      method: 'PATCH',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify(changes),
    })
  }
  localStorage.removeItem('pending-changes')
})

## 41. Open Questions / Risks

- `gsmui:input` uses Alpine (`x-on:click`) for clear/copy — AGENTS.md says move such logic to JS when it needs disabled-awareness. Consider porting clear/copy to `dist/` JS.
- Confirm `wire:model` + `value` coexistence rules with `07.19-livewire-architecture.md` to avoid double-source conflicts.
- File input (`type="file"`) variant needs its own `invalid`/`disabled` parity pass.
- Multi-select dropdown needs keyboard navigation parity with single-select.
- Rich text editor integration (Tiptap/ProseMirror) needs its own spec section.
- Form serialization edge cases: nested objects, arrays, file objects.
- Date/time pickers need locale-aware formatting rules.
- Password strength meter needs accessibility testing with screen readers.
- International phone input needs country code selection and validation.
