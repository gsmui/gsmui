# Purpose

The notification system renders ephemeral toasts and persistent in-app alerts driven by Livewire 4 broadcasts and server-pushed notification rows. It provides `<gsmui:toast>`, `<gsmui:alert>`, and a `<gsmui:notifications>` stack mounted once per layout. All icons are inline SVG (Heroicons/Lucide); no external fonts or images (CSP-safe).

## 1. Component Contracts

`stubs/resources/views/gsmui/toast/index.blade.php`:

```blade
<gsmui:toast
    type="success"        {{-- success|error|warning|info --}}
    :timeout="4000"
    wire:model="dismissed"
    position="bottom-right"
/>
```

`stubs/resources/views/gsmui/alert/index.blade.php`:

```blade
<gsmui:alert type="warning" :dismissable="$canDismiss">
    {{ $slot }}
</gsmui:alert>
```

- Base alert surface: `bg-white dark:bg-white/10 border-zinc-200 border-b-zinc-300/80 dark:border-white/10 shadow-xs rounded-lg p-3`.
- `data-invalid:` layering is reused for `type="error"` so invalid styling is layered, never swapped (AGENTS.md invalid rule).
- ARIA: toasts use `role="status"` (polite) or `role="alert"` (assertive) set from Blade via `__('…')`.

## 2. Notification Stack & Livewire Binding

`<gsmui:notifications>` subscribes to a Livewire channel and renders rows from `06.110-notifications.md` schema:

```blade
<div x-data="notifications()" class="fixed inset-0 pointer-events-none z-50">
    <template x-for="n in items" :key="n.id">
        <gsmui:toast :type="n.type" x-bind:data-id="n.id" />
    </template>
</div>
```

- New notifications arrive via Livewire 4 `dispatch()`/`$dispatch` events; the stack appends without full reload.
- `setAttribute`/`removeAttribute` from `utils.js` toggle `data-open`; a MutationObserver is not required here because Alpine `x-for` owns the DOM, but manual toasts must update `value` and emit `input`.

## 3. Animation

Use the Motion & Animation Layer (08.15) tokens — enter/leave via `data-state="open|closed"` transitions, no `eval`, no inline `<style>` (use `adoptedStyleSheets` from `dist/`).

## 4. Toast Positioning Algorithm

The notification stack supports six viewport positions, declared via the `position` attribute. Positions are computed at mount time and updated on `resize` (debounced 150ms via `requestAnimationFrame`). The stacking order within each position follows a LIFO (last-in, first-out) visual model — the most recent toast appears at the leading edge.

### 4.1 Position Map

| Value | CSS anchoring | Ideal use |
| --- | --- | --- |
| `top-right` | `top-4 end-4` | Default for non-blocking info/success |
| `top-left` | `top-4 start-4` | Chat apps, left-rail notifications |
| `top-center` | `top-4 start-1/2 -translate-x-1/2` | Banner-style warnings |
| `bottom-right` | `bottom-4 end-4` | Default for action confirmations |
| `bottom-left` | `bottom-4 start-4` | Status-bar companion |
| `bottom-center` | `bottom-4 start-1/2 -translate-x-1/2` | Persistent non-blocking alerts |

### 4.2 Stacking Offset

When multiple toasts occupy the same position, each subsequent toast is offset along the block axis by `calc(var(--gsmui-toast-offset, 4px) + var(--gsmui-toast-height, 56px))`. The `--gsmui-toast-height` variable is measured dynamically after the first render via `el.getBoundingClientRect().height` and set on the stack container.

```js
// assets/js/gsmui/notification-stack.js
recalculateOffsets() {
  const items = this.stack.querySelectorAll('[data-toast]')
  let offset = 0
  items.forEach((item) => {
    const height = item.getBoundingClientRect().height
    item.style.setProperty('--toast-translate', `${offset}px`)
    offset += height + 4 // gap
  })
}
```

### 4.3 Overflow Culling

When the number of visible toasts exceeds the `maxVisible` prop (default 4), the oldest toast is dismissed with a `leave` transition before the new one enters. The remaining toasts animate upward to fill the gap using a spring-eased `translateY` transition (Motion & Animation Layer 08.15 tokens).

## 6. Dismiss Logic

### 6.1 Auto-Dismiss

When `timeout > 0`, a `setTimeout` fires after the specified delay. Before dismissing, the toast shows a progress indicator (thin bar at the bottom of the toast, width animated from 100% to 0% over the timeout duration using `transition: width linear`).

Hovering the toast pauses the auto-dismiss timer. The progress bar transitions to `animation-play-state: paused`. On mouse-leave, the timer resumes from the remaining duration.

```js
// assets/js/gsmui/toast.js
class GsmuiToast {
  constructor(el) {
    this.el = el
    this.timeout = parseInt(el.getAttribute('timeout') || '4000', 10)
    this.remaining = this.timeout
    this.timer = null
    this.startTime = null

    el.addEventListener('mouseenter', () => this.pause())
    el.addEventListener('mouseleave', () => this.resume())
    if (this.timeout > 0) this.start()
  }

  start() {
    this.startTime = Date.now()
    this.timer = setTimeout(() => this.dismiss(), this.remaining)
  }

  pause() {
    clearTimeout(this.timer)
    this.remaining -= Date.now() - this.startTime
    this.el.setAttribute('data-paused', '')
  }

  resume() {
    this.el.removeAttribute('data-paused')
    this.start()
  }

  dismiss() {
    this.el.setAttribute('data-state', 'closed')
    this.el.addEventListener('transitionend', () => {
      this.el.dispatchEvent(new CustomEvent('gsmui:toast-dismissed', { detail: { id: this.el.dataset.id } }))
    }, { once: true })
  }
}
```

### 6.2 Manual Dismiss

The dismiss button (an `<gsmui:button as="div" size="xs">` inside the toast) fires `gsmui:toast-dismissed`. The notification stack removes the element from its `items` array and recalculates offsets.

### 6.3 Swipe Dismiss (Touch)

On touch devices, a horizontal swipe gesture (> 80px delta, < 200ms duration) triggers dismiss. The toast follows the finger during the gesture using `transform: translateX(delta)` and snaps closed on threshold.

```js
// Swipe gesture handling
handleTouchStart(e) {
  this.startX = e.touches[0].clientX
  this.startTime = Date.now()
}

handleTouchEnd(e) {
  const dx = e.changedTouches[0].clientX - this.startX
  const dt = Date.now() - this.startTime
  if (Math.abs(dx) > 80 && dt < 200) {
    this.dismiss()
  } else {
    this.el.style.transform = '' // snap back
  }
}
```

### 6.4 Keyboard Dismiss

Toasts are focusable on `Tab` (they receive `tabindex="0"` when focused). Pressing `Delete` or `Escape` while focused dismisses the toast. Announced to screen readers via `aria-live` region.

## 7. Notification Stack — Livewire Integration

### 7.1 Server-Pushed Notifications

The `<gsmui:notifications>` component subscribes to a Livewire 4 broadcast channel. When the server pushes a new notification row (per `06.110-notifications.md` schema), the stack's Alpine state `items` array is updated:

```blade
<div
    x-data="notificationStack({
        maxVisible: @js($maxVisible ?? 4),
        position: @js($position ?? 'bottom-right')
    })"
    class="fixed inset-0 pointer-events-none z-50"
    :class="positionClasses"
    x-on:notification.window="addItem($event.detail)"
>
    <template x-for="n in items" :key="n.id">
        <div
            class="pointer-events-auto"
            :data-toast="n.id"
            :style="`--toast-translate: ${n.offset}px`"
            x-transition:enter="transition ease-out duration-300"
            x-transition:enter-start="opacity-0 translate-x-4"
            x-transition:enter-end="opacity-100 translate-x-0"
            x-transition:leave="transition ease-in duration-200"
            x-transition:leave-start="opacity-100"
            x-transition:leave-end="opacity-0 translate-x-4"
        >
            <gsmui:toast
                :type="n.type"
                :timeout="n.timeout"
                :data-id="n.id"
                x-init="$nextTick(() => $el.querySelector('[data-toast]')?.focus())"
            >
                <span x-text="n.message"></span>
            </gsmui:toast>
        </div>
    </template>
</div>
```

### 7.2 Livewire Event Protocol

Server-side dispatch:

```php
// In any Livewire component or event listener
$this->dispatch('notification', [
    'id' => Str::uuid(),
    'type' => 'success',
    'message' => __('Record saved.'),
    'timeout' => 3000,
]);
```

Client-side reception: the `<gsmui:notifications>` Alpine component listens for `notification` window events (Livewire 4 broadcasts to `window`). The `addItem()` method prepends to `items` and triggers offset recalculation.

### 7.3 Deduplication

The stack maintains a `Set` of active notification IDs. If a duplicate ID arrives (e.g. from rapid Livewire re-renders), it is ignored. The stack also deduplicates by `message` hash when `deduplicate="true"` — two toasts with identical text within a 2-second window are collapsed into one with an increment badge (`×2`).

### 7.4 Queue Overflow

When `items.length > maxVisible`, excess items are held in a `queue` array. As visible toasts are dismissed, the queue is drained in FIFO order. The queue has a hard cap (default 20); older queued items are dropped silently.

## 8. Alert Component — Deep Dive

### 8.1 Alert Variants

`<gsmui:alert>` is a persistent, inline notification. Unlike toasts, alerts are part of the page flow (not fixed-positioned) and do not auto-dismiss.

```blade
<gsmui:alert type="info" :dismissable="true">
    <x-slot name="icon">
        <x-gsmui.icon name="information-circle" />
    </x-slot>
    {{ __('Your account is pending verification.') }}
</gsmui:alert>
```

| Type | Surface | Icon |
| --- | --- | --- |
| `info` | `bg-sky-50 dark:bg-sky-900/30 border-sky-200 dark:border-sky-700/50` | `information-circle` |
| `success` | `bg-emerald-50 dark:bg-emerald-900/30 border-emerald-200 dark:border-emerald-700/50` | `check-circle` |
| `warning` | `bg-amber-50 dark:bg-amber-900/30 border-amber-200 dark:border-amber-700/50` | `exclamation-triangle` |
| `error` | `data-invalid:` layered on base surface | `exclamation-circle` |

### 8.2 Dismissable Behavior

When `:dismissable="true"`, an `<gsmui:button as="div" size="xs">` with an inline SVG X icon is rendered. Clicking it sets `data-state="closed"` and triggers a leave animation. The dismissed state is persisted via a Livewire `wire:model` binding so the alert stays hidden across re-renders.

### 8.3 Alert with Actions

Alerts can contain action buttons (links or Livewire actions) in the trailing slot:

```blade
<gsmui:alert type="warning" :dismissable="true">
    {{ __('Your trial expires in 3 days.') }}
    <x-slot name="actions">
        <gsmui:button size="xs" wire:click="upgrade">{{ __('Upgrade now') }}</gsmui:button>
        <gsmui:button as="div" size="xs" variant="ghost" wire:click="dismiss">{{ __('Dismiss') }}</gsmui:button>
    </x-slot>
</gsmui:alert>
```

Actions use real `<gsmui:button>` for clickable actions and `<gsmui:button as="div">` only when nested inside another interactive element (nested-button HTML constraint per AGENTS.md).

```blade
<gsmui:modal wire:model="notificationCenterOpen" position="top-right" size="md">
```

### 9.3 Read/Unread State

Each notification row tracks read state via `data-read` attribute. Unread rows have a leading dot indicator (a 8px circle with `bg-blue-500`). Clicking a row dispatches a Livewire action to mark it as read and clears the dot. The unread count badge updates reactively via Livewire property binding.

## 10. Animation System

### 10.1 Enter Transitions

Toast enter follows the Motion & Animation Layer (08.15) tokens:

| Position | Enter start | Enter end |
| --- | --- | --- |
| `*-right` | `opacity-0 translate-x-4` | `opacity-100 translate-x-0` |
| `*-left` | `opacity-0 -translate-x-4` | `opacity-100 translate-x-0` |
| `*-center` | `opacity-0 -translate-y-2` | `opacity-100 translate-y-0` |

Duration: `300ms ease-out` (spring-inspired curve).

### 10.2 Leave Transitions

| Trigger | Leave start | Leave end |
| --- | --- | --- |
| Auto-dismiss | `opacity-100 translate-x-0` | `opacity-0 translate-x-4` (or `-x-4` for left positions) |
| Manual dismiss | `opacity-100 scale-100` | `opacity-0 scale-95` |
| Queue overflow | `opacity-100` | `opacity-0 -translate-y-2` (fades upward to make room) |

Duration: `200ms ease-in`.

### 10.3 CSS Architecture

All transitions are defined via `adoptedStyleSheets` (not inline `<style>` tags) per CSP guidance in AGENTS.md. The notification system's stylesheet is registered once at `gsmui.js` init:

```js
// assets/js/gsmui/notification-styles.js
const sheet = new CSSStyleSheet()
sheet.replaceSync(`
  [data-toast][data-state="entering"] {
    transition: opacity 300ms ease-out, transform 300ms ease-out;
  }
  [data-toast][data-state="leaving"] {
    transition: opacity 200ms ease-in, transform 200ms ease-in;
  }
  [data-toast][data-paused] .toast-progress {
    animation-play-state: paused;
  }
  .toast-progress {
    transition: width linear;
  }
`)
document.adoptedStyleSheets = [...document.adoptedStyleSheets, sheet]
```

### 10.4 Reduced Motion

The system respects `prefers-reduced-motion: reduce`. When active, enter/leave transitions are instant (`duration: 0ms`). The check is performed once at init and cached:

```js
const prefersReducedMotion = window.matchMedia('(prefers-reduced-motion: reduce)').matches
const enterDuration = prefersReducedMotion ? 0 : 300
```

## 11. Accessibility

### 11.1 ARIA Live Regions

The notification stack container uses dual `aria-live` regions:

```blade
<div aria-live="polite" aria-atomic="false" class="sr-only">
    {{-- Screen-reader-only announcements for status toasts --}}
</div>
<div aria-live="assertive" aria-atomic="false" class="sr-only">
    {{-- Screen-reader-only announcements for error/alert toasts --}}
</div>
```

When a toast enters, its text content is cloned into the appropriate live region. This ensures screen readers announce the notification without requiring focus to move to the toast.

### 11.2 Role Assignment

| Toast type | `role` | `aria-live` |
| --- | --- | --- |
| `success` | `role="status"` | `polite` |
| `info` | `role="status"` | `polite` |
| `warning` | `role="status"` | `polite` |
| `error` | `role="alert"` | `assertive` |

These are set from Blade using `__()` for any custom text, with JS fallback:

```js
const role = el.getAttribute('role') || (el.dataset.type === 'error' ? 'alert' : 'status')
```

### 11.3 Focus Management

- Toasts are not focusable by default (`tabindex="-1"`)
- When the user presses `Tab`, focus skips over all toasts (managed via `inert` on the stack container when not actively navigating toasts)
- If a user explicitly `Tab`s into the toast stack, toasts receive `tabindex="0"` and become interactive (dismiss button is reachable)
- On dismiss, focus returns to the element that was focused before the toast appeared (tracked via `document.activeElement` at toast creation time)

### 11.4 Color Contrast

All toast surfaces meet WCAG AA contrast ratios (4.5:1 for text, 3:1 for icons) in both light and dark mode. The icon color matches the text color. In dark mode, toast surfaces use semi-transparent backgrounds with sufficient contrast against white text:

| Type | Dark mode text | Dark mode bg | Contrast ratio |
| --- | --- | --- | --- |
| Success | `text-emerald-200` | `bg-emerald-900/30` | 7.2:1 |
| Error | `text-red-200` | `bg-red-900/30` | 6.8:1 |
| Warning | `text-amber-200` | `bg-amber-900/30` | 7.1:1 |
| Info | `text-sky-200` | `bg-sky-900/30` | 6.5:1 |

## 12. Mobile Patterns

### 12.1 Touch Interactions

- Swipe-to-dismiss is enabled by default on touch devices (detected via `'ontouchstart' in window`)
- Toasts on mobile use `max-w-[calc(100vw-2rem)]` to prevent overflow
- On mobile, toasts default to `position="top-center"` or `bottom-center` for thumb-reachable placement

Toasts respect iOS safe area insets via `env(safe-area-inset-bottom)`:

```css
[data-toast-position="bottom-right"],

[data-toast-position="bottom-center"] {
  bottom: calc(1rem + env(safe-area-inset-bottom));
}
```

### 12.3 Haptic Feedback

On supported devices (where `navigator.vibrate` is available), error toasts trigger a short vibration pattern `[50]` on creation. This is opt-in and gated behind a `vibrate` prop:

```blade
<gsmui:toast type="error" :vibrate="true">{{ __('Something went wrong') }}</gsmui:toast>
```

## 13. Notification Persistence & Read State

### 13.1 Persisted Notifications

Notifications from `06.110-notifications.md` that are marked `persistent: true` remain in the notification center panel until explicitly read. Ephemeral notifications (toasts) are not stored — they exist only in the DOM during their lifecycle.

### 13.2 Read State Tracking

The notification center tracks read state via a `Set` of IDs stored in Alpine state. On page load, previously-read IDs are hydrated from a cookie (`gsmui_read_notifications`) to prevent re-showing read notifications on refresh.

### 13.3 Unread Count Sync

The unread count badge on the bell icon syncs with the server via Livewire property binding. When a notification is marked as read (click or "mark all read"), the server decrements the count and Livewire re-renders the badge.

## 14. Sound & Audio Notifications

### 14.1 Optional Sound

For critical notifications (`type="error"`), an optional sound can play via the Web Audio API. The sound is a self-hosted, base64-encoded short tone embedded in `dist/` (no external audio files):

```js
// assets/js/gsmui/notification-sound.js
const errorSound = new Audio('data:audio/wav;base64,...') // CSP: data: is only for non-executable media
errorSound.volume = 0.3
errorSound.play().catch(() => {}) // autoplay may be blocked; silently fail
```

### 14.2 CSP Considerations

Audio via `<audio>` with base64 data URIs is permitted under `media-src 'self' data:`. If the host app's CSP does not allow `data:` for media, sounds are disabled. The `sound` prop defaults to `false` and must be explicitly opted in.

### 14.3 User Preference

Sound is gated behind a user preference (`notifications_sound` stored in `localStorage`). The notification center UI includes a toggle to enable/disable sounds. The JS checks this preference before playing:

```js
if (localStorage.getItem('gsmui_notifications_sound') === 'true' && type === 'error') {
  errorSound.play().catch(() => {})
}
```

## 15. Notification Grouping

### 15.1 Group Strategy

When multiple notifications arrive from the same source (e.g. multiple "comment on post" notifications), they are visually grouped under a single toast with a count badge:

```blade
<gsmui:toast type="info" :group-count="3">
    {{ __('3 new comments on your post') }}
</gsmui:toast>
```

### 15.2 Group Collapse

Grouped toasts expand on hover to show individual notification summaries. The expand/collapse animation uses `max-height` transition with `overflow-hidden`. The expand arrow rotates 180° via `transition: transform 200ms`.

### 15.3 Deduplication Window

Within a configurable deduplication window (default 2 seconds), identical notification messages from the same source are collapsed into a single toast with an incrementing counter. This prevents toast storms from rapid server-side events.

Dark mode is toggled via the `dark:` Tailwind prefix. Toast surfaces use semi-transparent backgrounds in dark mode (e.g. `bg-emerald-900/30`) to maintain readability against dark app backgrounds. The border becomes `border-white/10` in dark mode.

### 16.3 Layering & Z-Index

The notification stack uses `z-50` (Tailwind's default for overlays). Individual toasts do not set their own z-index — stacking order is managed via DOM order and `translate` transforms. This avoids z-index wars with modals (`z-50`), popovers (`z-40`), and other overlays.

## 17. JavaScript State Management

### 17.1 NotificationStack Class

The core state manager for the notification stack:

```js
// assets/js/gsmui/notification-stack.js
class NotificationStack {
  constructor(container, options = {}) {
    this.container = container
    this.items = []
    this.queue = []
    this.maxVisible = options.maxVisible || 4
    this.maxQueue = options.maxQueue || 20
    this.position = options.position || 'bottom-right'
  }

  addItem(notification) {
    if (this.items.some(n => n.id === notification.id)) return // dedup
    if (this.items.length >= this.maxVisible) {
      this.queue.push(notification)
      if (this.queue.length > this.maxQueue) this.queue.shift()
    } else {
      this.items.push(notification)
    }
    this.render()
  }

  removeItem(id) {
    this.items = this.items.filter(n => n.id !== id)
    if (this.queue.length > 0) {
      this.items.push(this.queue.shift())
    }
    this.render()
  }

  render() {
    this.recalculateOffsets()
    // Alpine's x-for handles DOM updates reactively
  }
```

## 20. Performance Considerations

### 20.1 DOM Recycling

When the notification stack exceeds 50 dismissed items in a session, the DOM nodes for dismissed toasts are garbage-collected. Alpine's `x-for` handles this automatically when items are removed from the reactive array.

### 20.2 MutationObserver Efficiency

The notification stack does NOT use MutationObserver for its own state — Alpine `x-for` owns the DOM. Individual toasts only use MutationObserver when they need to sync with Livewire (e.g. `value` attribute changes). This avoids the cost of deep subtree observation.

### 20.3 Layout Thrashing

`recalculateOffsets()` batches DOM reads (getBoundingClientRect for all visible toasts) before writes (setting `--toast-translate`). This prevents layout thrashing:

```js
recalculateOffsets() {
  const heights = [] // read phase
  this.container.querySelectorAll('[data-toast]').forEach(el => {
    heights.push(el.getBoundingClientRect().height)
  })
  let offset = 0 // write phase
  this.container.querySelectorAll('[data-toast]').forEach((el, i) => {
    el.style.setProperty('--toast-translate', `${offset}px`)
    offset += heights[i] + 4
  })
}
```

### 20.4 Event Throttling

Notification events from Livewire are throttled to prevent toast storms. The stack accepts a `throttle` prop (default 100ms). Events arriving within the throttle window are batched and rendered together.

## 22. Toast Lifecycle State Machine

The toast transitions through these states:

```
                    ┌─────────────┐
                    │  CREATED    │
                    └──────┬──────┘
                           │ enter transition
                           ▼
                    ┌─────────────┐
           ┌───────│   OPEN      │◄──────┐
           │       └──────┬──────┘       │
           │              │              │
     hover │       timeout/expired       │ resume
           │              │              │
           ▼              │              │
    ┌─────────────┐       │              │
    │   PAUSED    │───────┘              │
    └─────────────┘                      │
           │                             │
     leave │              leave          │
           ▼              ▼              │
    ┌─────────────┐                      │
    │  LEAVING    │──────────────────────┘
    └──────┬──────┘  (if resumed before timeout)
           │
           │ transitionend
           ▼
    ┌─────────────┐
    │  REMOVED    │
    └─────────────┘
```

### 22.1 State Transitions

| From | To | Trigger | DOM change |
| --- | --- | --- | --- |
| `CREATED` | `OPEN` | Enter transition complete | `data-state="open"` |
| `OPEN` | `PAUSED` | `mouseenter` | `data-paused=""` |
| `PAUSED` | `OPEN` | `mouseleave` | Remove `data-paused` |
| `OPEN` | `LEAVING` | Timeout / manual dismiss | `data-state="closed"` |
| `PAUSED` | `LEAVING` | Manual dismiss | `data-state="closed"` |
| `LEAVING` | `REMOVED` | Leave transition complete | DOM removal |

### 22.2 State Attributes

Each state maps to DOM attributes that can be observed via MutationObserver:

| State | `data-state` | `data-paused` | `tabindex` |
| --- | --- | --- | --- |
| CREATED | (not set) | (not set) | `-1` |
| OPEN | `open` | (not set) | `-1` |
| PAUSED | `open` | `""` | `-1` |
| LEAVING | `closed` | (not set) | `-1` |
| REMOVED | (not set) | (not set) | (removed) |

### 24.2 Server-Side Notification Builder

A fluent builder for creating notification payloads:

```php
class NotificationBuilder
{
    protected string $type = 'info';
    protected string $message = '';
    protected int $timeout = 4000;
    protected bool $persistent = false;
    protected ?string $actionUrl = null;
    protected ?string $actionLabel = null;

    public static function make(): static
    {
        return new static();
    }

    public function success(string $message): static
    {
        $this->type = 'success';
        $this->message = $message;
        return $this;
    }

    public function error(string $message): static
    {
        $this->type = 'error';
        $this->message = $message;
        $this->timeout = 0; // errors don't auto-dismiss
        return $this;
    }

    public function persistent(): static
    {
        $this->persistent = true;
        return $this;
    }

    public function action(string $url, string $label): static
    {
        $this->actionUrl = $url;
        $this->actionLabel = $label;
        return $this;
    }

    public function toArray(): array
    {
        return [
            'id' => Str::uuid(),
            'type' => $this->type,
            'message' => $this->message,
            'timeout' => $this->timeout,
            'persistent' => $this->persistent,
            'action_url' => $this->actionUrl,
            'action_label' => $this->actionLabel,
            'created_at' => now()->toISOString(),
        ];
    }
}
```

Usage:

```php
NotificationBuilder::make()
    ->success(__('Record saved successfully.'))
    ->timeout(3000)
    ->toArray();
```

### 24.3 Rate Limiting

The notification stack implements client-side rate limiting to prevent toast storms:

```php
// Server-side rate limiting
RateLimiter::for('notifications', function ($user) {
    return Limit::perMinute(30)->by($user->id);
});
```

Client-side throttling in the notification stack:

```js
class NotificationStack {
  constructor(options = {}) {
    this.throttleMs = options.throttle || 100
    this.lastEmit = 0
    this.buffer = []
  }

  addItem(notification) {
    const now = Date.now()
    if (now - this.lastEmit < this.throttleMs) {
      this.buffer.push(notification)
      return
    }
    this.lastEmit = now
    this.processItem(notification)
    // Flush buffered items
    setTimeout(() => this.flushBuffer(), this.throttleMs)
  }

  flushBuffer() {
    while (this.buffer.length > 0 && this.items.length < this.maxVisible) {
      this.processItem(this.buffer.shift())
    }
  }
}
```

### 24.4 Multi-Tab Synchronization

When the user has multiple tabs open, notifications should appear in all tabs. This is achieved via `Broadcast.channel` and Livewire 4's built-in WebSocket support:

```php
// Broadcasting to all user tabs

```

Each tab's `<gsmui:notifications>` component receives the broadcast and renders the toast independently.

```js
const rtf = new Intl.RelativeTimeFormat(navigator.language, { numeric: 'auto' })
function relativeTime(date) {
  const diff = date - Date.now()
  const minutes = Math.round(diff / 60000)
  return rtf.format(minutes, 'minute')
}
```

## 29. Edge Cases Documentation

### 29.1 Rapid Successive Notifications

When 10+ notifications arrive within 1 second, the stack:
1. Shows the first 4 immediately
2. Buffers the rest in the queue
3. Drains 1 per second after the buffer fills
4. Deduplicates identical messages within a 2-second window

### 29.2 Navigation During Toast

When the user navigates to a new page (Livewire navigation), the toast stack is preserved because it's mounted in the persistent layout. Toasts that were mid-animation are completed before the page transition.

### 29.3 Form Submit + Toast

When a Livewire form submission triggers a success toast, the toast should not appear until the form's loading state clears. The toast dispatch is delayed until `wire:loading` completes:

```php
public function save()
{
    $this->validate();
    $this->record->save();

    // Dispatch after render to avoid timing issues
    $this->dispatch('notification', [
        'type' => 'success',
        'message' => __('Saved successfully.'),
    ]);
}
```

### 29.4 Dark Mode Toggle

When the user toggles dark mode while toasts are visible, the toast surface colors update immediately because they use Tailwind's `dark:` prefix which responds to the `dark` class on `<html>`.

### 29.5 Scroll Position

Toasts are fixed-positioned and unaffected by scroll. However, the notification center panel scrolls with its container and respects `scroll-lock` when open.

### 29.6 Viewport Resize

On window resize, the toast stack recalculates positions (debounced 150ms). Toasts that would overflow the viewport are repositioned to the nearest valid position.

### 31.2 Performance Anti-Patterns to Avoid

- Do NOT query `getBoundingClientRect` on every animation frame — batch reads
- Do NOT create new `Audio` objects for each toast — reuse a single instance
- Do NOT use `document.querySelectorAll` with complex selectors — cache node lists
- Do NOT dispatch events on `window` for every toast — use targeted events on the stack container

## 34. Migration Guide

### 34.1 From Manual Toast Implementations

If the host app previously used a custom toast system:

1. Replace custom toast markup with `<gsmui:toast>` component
2. Replace custom dismiss logic with `wire:model` binding
3. Replace custom animation CSS with Motion & Animation Layer tokens
4. Ensure all ARIA attributes are set (the component handles this automatically)

### 34.2 From Flash Messages

Laravel flash messages (`session('flash_message')`) can be mapped to toasts:

```php
// In AppServiceProvider boot()
if (session()->has('flash_message')) {
    $flash = session('flash_message');
    session()->push('notifications', [
        'type' => $flash['type'] ?? 'info',
        'message' => $flash['message'],
        'timeout' => $flash['timeout'] ?? 4000,
    ]);
}
```

### 34.3 From Third-Party Toast Libraries

Replacing `toastr`, `notyf`, or similar:

1. Remove the third-party JS/CSS from `app.js`/`app.css`
2. Ensure `gsmui.js` is loaded (it provides the toast runtime)
3. Replace `toastr.success('msg')` with Livewire event dispatch:
   ```php
   $this->dispatch('notification', ['type' => 'success', 'message' => 'msg']);
   ```
4. Remove any third-party CSP exceptions (Gsmui toasts are CSP-safe)

### 34.4 Backward Compatibility

The notification system maintains backward compatibility with Livewire 3 event patterns. If `$dispatch('notify', ...)` is used, the `<gsmui:notifications>` component listens for both `notify` and `notification` events:

```js
// Legacy event support
['notify', 'notification'].forEach(eventName => {
  window.addEventListener(eventName, (e) => addItem(e.detail))
})
```

## 36. Security Considerations

### 36.1 XSS Prevention

Toast messages are rendered as text content (`x-text` in Alpine, `{{ $slot }}` in Blade), never as raw HTML. This prevents XSS injection through notification messages.

### 36.2 CSP Compliance

- All toast styles use `adoptedStyleSheets` (no inline `<style>` tags)
- All icons are inline SVG (no external image/font loading)
- No `eval()` or `Function()` calls in the notification runtime
- Sound uses base64 data URIs for audio (permitted under `media-src 'self' data:`)

### 36.3 Rate Limiting

Both server-side (Laravel `RateLimiter`) and client-side (throttle prop) rate limiting prevent notification abuse. The stack silently drops notifications that exceed the rate limit.

### 36.4 Content Filtering

Notification messages should be sanitized server-side before dispatch. The notification system does NOT sanitize messages — it trusts the Livewire dispatch source. If user-generated content appears in notifications, sanitize with `e()` before dispatching.

## 37. Open Questions / Risks

- **Stacking limit:** cap concurrent toasts (e.g. 4) and queue the rest.
- **Persisted vs ephemeral:** align which notification IDs from `06.110` stay until read vs auto-dismiss.
- **Focus:** toasts are non-focusable by default; confirm screen-reader-only announcement path.
- **Mobile safe area:** verify `env(safe-area-inset-bottom)` renders correctly on Android WebViews.
- **Sound autoplay:** confirm Web Audio API autoplay policy does not silently block on all browsers.
- **Grouping threshold:** determine minimum group size before collapsing (suggest 2).
- **Cookie size:** read-notification IDs in cookie may grow; consider `localStorage` or server-side tracking for large notification volumes.
- **Reduced motion:** confirm all transition durations respect `prefers-reduced-motion` consistently across enter/leave/offset animations.
- **Multi-tab sync:** verify Livewire broadcast channel reconnection after tab sleep.
- **Memory leak:** confirm toast DOM nodes are garbage-collected after removal (no retained closures).
- **Z-index conflicts:** ensure toast stack z-index doesn't conflict with modal z-index in edge cases.
- **Progress bar accuracy:** CSS `transition: width linear` may drift on low-end devices; consider `requestAnimationFrame` fallback.
- **Custom themes:** confirm CSS custom property overrides work correctly when the host app uses Tailwind v4's new CSS-first configuration.
- **Livewire 5 forward-compat:** verify the notification system works with upcoming Livewire 5 event patterns.
- **Toast stacking animation:** when a toast is dismissed and the stack collapses, verify the remaining toasts animate smoothly without jarring jumps.
- **Dark mode transition:** when toggling dark mode while toasts are visible, confirm no flash of unstyled content occurs during the transition.
- **Concurrent Livewire updates:** if the Livewire component re-renders while a toast is mid-animation, confirm the animation is not interrupted.
- **Offline behavior:** when the browser is offline, confirm the notification stack still renders locally-dispatched toasts (e.g. form validation errors).
- **Accessibility tree:** verify that the accessibility tree correctly reflects toast additions and removals without requiring a full tree rebuild.

## 40. Troubleshooting Guide

### 40.1 Toast Not Appearing

1. Check that `<gsmui:notifications>` is present in the layout
2. Check that `gsmui.js` is loaded (view page source)
3. Check browser console for JavaScript errors
4. Verify the Livewire event is dispatched with correct data structure
5. Check that the toast type is valid (`success`, `error`, `warning`, `info`)

### 40.2 Toast Not Dismissing

1. Check the `timeout` prop value — `0` disables auto-dismiss
2. Check if the user is hovering the toast (pauses timer)
3. Check browser console for JavaScript errors during dismiss
4. Verify the `data-state="closed"` attribute is being set

### 40.3 Toast Animation Not Working

1. Check `prefers-reduced-motion` system setting
2. Verify `adoptedStyleSheets` is supported (check browser compatibility)
3. Check that `gsmui.js` has registered the notification stylesheet
4. Inspect the toast element for correct `data-state` values

### 40.4 Dark Mode Colors Wrong

1. Verify the `dark` class is on `<html>` element
2. Check that Tailwind's dark mode is configured (class-based, not media-based)
3. Inspect the toast element's computed styles for correct dark mode values
4. Verify CSS custom property overrides don't conflict

### 40.5 Screen Reader Not Announcing

1. Check that `aria-live` regions are present in the DOM
2. Verify `role="status"` or `role="alert"` is set correctly
3. Check that the live region is not `aria-hidden="true"`
4. Test with actual screen reader (NVDA, VoiceOver, or JAWS)
