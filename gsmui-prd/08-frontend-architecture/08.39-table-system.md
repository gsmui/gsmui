# 08.39 - Table System

**Project:** GsmUi
**Section:** 08 - Frontend Architecture
**Framework:** Laravel 13 · Livewire 4 · Blade Components · GsmUi Component Library · Tailwind CSS v4 · Alpine.js
**Version:** 1.0.0

---

> See also: `06.20-components.md` (component registry and `gsmui:table` registration). This document specifies the *frontend table contract, sorting, and pagination rendering*, and does NOT re-document component registration from 06.20.

# Purpose

The table system renders sortable, paginated data tables through `<gsmui:table>`, `<gsmui:table.head>`, `<gsmui:table.row>`, and `<gsmui:table.cell>`. It integrates with Livewire 4 pagination and column sorting while reusing input/surface tokens and the invalid-state layering for cell-level validation feedback.

---

## 1. Component Contracts

`stubs/resources/views/gsmui/table/index.blade.php`:

```blade
<gsmui:table wire:model="sort" :rows="$rows" :columns="$columns">
    <gsmui:table.head :sortable="$col->sortable" wire:click="sort('{{ $col->key }}')">
        {{ $col->label }}
    </gsmui:table.head>
    @foreach ($rows as $row)
        <gsmui:table.row>
            <gsmui:table.cell :invalid="$row->hasError('name')">{{ $row->name }}</gsmui:table.cell>
        </gsmui:table.row>
    @endforeach
</gsmui:table>
```

- Table shell: `bg-white dark:bg-white/10 border-zinc-200 border-b-zinc-300/80 dark:border-white/10 shadow-xs rounded-lg overflow-hidden`.
- Header sort control is a native `<button>` with `aria-sort` reflecting `ascending|descending|none` on the `<th>`.
- Invalid cells layer `data-invalid:` classes on top of base (AGENTS.md invalid rule) — never ternary-swap the whole cell.

## 2. Sorting & Pagination

- Sorting is driven by Livewire `wire:click` handlers; the active column shows an inline Heroicons/Lucide chevron (inline SVG, CSP-safe).
- Pagination uses Livewire 4 paginator; the pager reuses `<gsmui:button>` for prev/next and page numbers, keeping default cursor (not `cursor-pointer`) per AGENTS.md.

## 3. Empty & Loading States

- Empty state: render a dedicated row with a muted message; verify it is not white-on-white in dark mode (AGENTS.md critical visual states).
- Loading: overlay `data-loading` attribute toggled via `setAttribute` from `utils.js`; observe with MutationObserver if morphed.

## 4. JavaScript

Minimal Alpine only (AGENTS.md prefers JS over Alpine when disabled-state awareness is needed). Use `setAttribute`/`removeAttribute`; emit `input` + `change` on sort/pagination commits when bound to `wire:model`.

## 5. Column Definition System

### 5.1 Column Schema

Each column is defined as an object with these properties:

| Property | Type | Default | Description |
| --- | --- | --- | --- |
| `key` | `string` | required | Data field key |
| `label` | `string` | required | Display header text |
| `sortable` | `boolean` | `false` | Enable sort on this column |
| `width` | `string` | `auto` | CSS width (e.g. `w-48`, `w-1/4`) |
| `align` | `left\|center\|right` | `left` | Text alignment |
| `type` | `text\|number\|date\|badge\|actions\|custom` | `text` | Cell rendering type |
| `format` | `string\|function` | `null` | Display format (e.g. `currency`, `date`) |
| `truncate` | `number\|null` | `null` | Max characters before truncation |
| `sortable` | `boolean` | `false` | Column is sortable |
| `sticky` | `boolean` | `false` | Column sticks to left edge |

### 5.2 Blade Column Registration

```blade
<gsmui:table wire:model="sort" :rows="$rows">
    <x-slot name="head">
        <gsmui:table.head key="name" :sortable="true" wire:click="sort('name')">
            {{ __('Name') }}
        </gsmui:table.head>
        <gsmui:table.head key="email" :sortable="true" wire:click="sort('email')">
            {{ __('Email') }}
        </gsmui:table.head>
        <gsmui:table.head key="role">
            {{ __('Role') }}
        </gsmui:table.head>
        <gsmui:table.head key="actions" align="right">
            {{ __('Actions') }}
        </gsmui:table.head>
    </x-slot>

    @foreach ($rows as $row)
        <gsmui:table.row :data-id="$row->id">
            <gsmui:table.cell>{{ $row->name }}</gsmui:table.cell>
            <gsmui:table.cell>{{ $row->email }}</gsmui:table.cell>
            <gsmui:table.cell>
                <gsmui:badge :type="$row->role === 'admin' ? 'success' : 'info'">
                    {{ $row->role }}
                </gsmui:badge>
            </gsmui:table.cell>
            <gsmui:table.cell align="right">
                <gsmui:button as="div" size="xs" wire:click="edit({{ $row->id }})">
                    {{ __('Edit') }}
                </gsmui:button>
            </gsmui:table.cell>
        </gsmui:table.row>
    @endforeach
</gsmui:table>
```

### 5.3 Column Type Renderers

| Type | Rendering | Example |
| --- | --- | --- |
| `text` | Plain text, optional truncation | `{{ $row->name }}` |
| `number` | Right-aligned, `tabular-nums` | `<span class="tabular-nums">{{ number_format($value) }}</span>` |
| `date` | Platform `Intl.DateTimeFormat` | `<time>{{ $row->created_at->format('M j, Y') }}</time>` |
| `badge` | Inline badge with type variant | `<gsmui:badge>{{ $value }}</gsmui:badge>` |
| `actions` | Action button group, right-aligned | Edit / Delete / More |
| `custom` | User-provided Blade snippet | Any custom markup |

## 6. Sorting Mechanism

### 6.1 Sort State

The sort state is managed via Livewire `wire:model="sort"`:

```php
// Livewire component
public string $sortField = 'name'
public string $sortDirection = 'asc'

public function sort(string $field)
{
    if ($this->sortField === $field) {
        $this->sortDirection = $this->sortDirection === 'asc' ? 'desc' : 'asc';
    } else {
        $this->sortField = $field;
        $this->sortDirection = 'asc';
    }
}
```

### 6.2 Sort Indicator

The active sort column shows an inline SVG chevron indicating direction:

```blade
<gsmui:table.head key="name" :sortable="true" :sort-direction="$sortField === 'name' ? $sortDirection : null">
    {{ __('Name') }}
</gsmui:table.head>
```

Inside `table.head`, when `sort-direction` is not null:

```blade
@if ($sortable && $sortDirection)
    <span class="ml-1 inline-flex">
        @if ($sortDirection === 'asc')
            <x-gsmui.icon name="chevron-up" class="w-4 h-4" />
        @else
            <x-gsmui.icon name="chevron-down" class="w-4 h-4" />
        @endif
    </span>
@endif
```

### 6.3 `aria-sort` Attribute

The `<th>` element receives `aria-sort` reflecting the current state:

```html
<th aria-sort="ascending">Name ↗</th>
<th aria-sort="descending">Email ↘</th>
<th>Role</th> <!-- no aria-sort -->
```

### 6.4 Multi-Column Sort

Optional multi-column sort is supported by passing an array to `wire:model`:

```php
public array $sort = [
    ['field' => 'role', 'direction' => 'asc'],
    ['field' => 'name', 'direction' => 'asc'],
]
```

The sort indicator shows a small number badge (1, 2) next to the chevron for multi-column sort priority.

## 7. Pagination

### 7.1 Livewire 4 Paginator

The table integrates with Livewire 4's built-in paginator. The pager renders below the table:

```blade
<gsmui:table :rows="$rows">
    {{-- ... rows ... --}}

    <x-slot name="pagination">
        {{ $rows->links('gsmui::pagination') }}
    </x-slot>
</gsmui:table>
```

### 7.2 Pager Component

The pager uses `<gsmui:button>` for all interactive elements:

```blade
{{-- Previous button --}}
<gsmui:button
    as="div"
    size="sm"
    wire:click="previousPage"
    :disabled="!$rows->hasMorePages()"
    :aria-label="__('Previous page')"
>
    <x-gsmui.icon name="chevron-left" class="w-4 h-4" />
</gsmui:button>

{{-- Page numbers --}}
@foreach ($rows->getUrlRange(max(1, $currentPage - 2), min($totalPages, $currentPage + 2)) as $page => $url)
    <gsmui:button
        as="div"
        size="sm"
        :variant="$page === $currentPage ? 'primary' : 'ghost'"
        wire:click="goToPage({{ $page }})"
        :aria-label="__('Page :number', ['number' => $page])"
        :aria-current="$page === $currentPage ? 'page' : false"
    >
        {{ $page }}
    </gsmui:button>
@endforeach

{{-- Next button --}}
<gsmui:button
    as="div"
    size="sm"
    wire:click="nextPage"
    :disabled="!$rows->hasMorePages()"
    :aria-label="__('Next page')"
>
    <x-gsmui.icon name="chevron-right" class="w-4 h-4" />
</gsmui:button>
```

### 7.3 Cursor vs Offset Pagination

| Type | When to use | Livewire integration |
| --- | --- | --- |
| Offset (page numbers) | Small datasets, known total | `$rows->links()` |
| Cursor-based | Large/infinite datasets | Custom cursor via `wire:model="cursor"` |

For cursor pagination, the pager shows only prev/next buttons (no page numbers) and uses a "Load more" pattern:

```blade
@if ($rows->hasMorePages())
    <div class="text-center py-4">
        <gsmui:button wire:click="loadMore" variant="ghost">
            {{ __('Load more') }}
        </gsmui:button>
    </div>
@endif
```

### 7.4 Page Size Selector

An optional page-size dropdown allows users to change how many rows per page:

```blade
<gsmui:select wire:model="perPage" size="xs" class="w-20">
    <option value="10">10</option>
    <option value="25">25</option>
    <option value="50">50</option>
    <option value="100">100</option>
</gsmui:select>
```

## 8. Row Selection & Bulk Actions

### 8.1 Checkbox Column

When `selectable="true"`, a checkbox column is prepended to the table:

```blade
<gsmui:table :rows="$rows" selectable wire:model="selected">
    <x-slot name="head">
        <gsmui:table.head>
            <gsmui:checkbox
                wire:model="selectAll"
                :checked="count($selected) === count($rows)"
                :indeterminate="count($selected) > 0 && count($selected) < count($rows)"
            />
        </gsmui:table.head>
        {{-- ... other columns ... --}}
    </x-slot>

    @foreach ($rows as $row)
        <gsmui:table.row :data-id="$row->id">
            <gsmui:table.cell>
                <gsmui:checkbox wire:model="selected" value="{{ $row->id }}" />
            </gsmui:table.cell>
            {{-- ... other cells ... --}}
        </gsmui:table.row>
    @endforeach
</gsmui:table>
```

### 8.2 Bulk Action Toolbar

The toolbar appears above the table when items are selected:

```blade
<div x-data x-show="$wire.selected.length > 0"
     x-transition
     class="flex items-center gap-3 p-3 bg-zinc-50 dark:bg-white/5 rounded-lg mb-3">
    <span class="text-sm text-zinc-600 dark:text-zinc-400">
        {{ __(':count selected', ['count' => count($selected)]) }}
    </span>
    <gsmui:button as="div" size="xs" variant="danger" wire:click="bulkDelete">
        {{ __('Delete selected') }}
    </gsmui:button>
    <gsmui:button as="div" size="xs" variant="ghost" wire:click="bulkExport">
        {{ __('Export selected') }}
    </gsmui:button>
    <gsmui:button as="div" size="xs" variant="ghost" wire:click="$set('selected', [])">
        {{ __('Clear selection') }}
    </gsmui:button>
</div>
```

### 8.3 Select All Pages

When pagination is active, "Select all" selects only the current page. A secondary option "Select all :total records" selects across all pages:

```blade
<gsmui:button as="div" size="xs" variant="ghost" wire:click="selectAllPages"
    x-show="$wire.selected.length === {{ count($rows) }}">
    {{ __('Select all :total records', ['total' => $totalRows]) }}
</gsmui:button>
```

## 9. Sticky Header

### 9.1 Implementation

The table header uses `position: sticky; top: 0` with a background color and subtle bottom border:

```blade
<thead class="sticky top-0 bg-white dark:bg-zinc-800 z-10">
    <tr class="border-b border-zinc-200 dark:border-white/10">
        {{ $head }}
    </tr>
</thead>
```

### 9.2 Container Considerations

The table is wrapped in a scrollable container with `overflow-auto` and a fixed height. The sticky header sticks to the top of this container, not the viewport:

```blade
<div class="overflow-auto max-h-[70vh] rounded-lg border border-zinc-200 dark:border-white/10">
    <table class="w-full">
        <thead class="sticky top-0 bg-white dark:bg-zinc-800 z-10">...</thead>
        <tbody>...</tbody>
    </table>
</div>
```

### 9.3 Mobile Sticky Header

On mobile, the sticky header works within the scrollable container. The rounded corners of the container are preserved because `overflow: hidden` is on the outer wrapper, not the scrollable div. Verify with Playwright that the header background covers scrolled content without visual artifacts.

### 9.4 Sticky Columns

Optional left-sticky columns (for the row label or checkbox) use `position: sticky; left: 0` with a right border shadow to indicate scroll:

```css
.sticky-col {
  position: sticky;
  left: 0;
  background: inherit;
  z-index: 5;
  box-shadow: 4px 0 8px -4px rgba(0,0,0,0.1);
}
```

## 10. Empty & Loading States

### 10.1 Empty State

When `rows` is empty, the table renders a centered message:

```blade
@if ($rows->isEmpty())
    <tr>
        <td colspan="{{ count($columns) }}" class="text-center py-12">
            <div class="flex flex-col items-center gap-2">
                <x-gsmui.icon name="inbox" class="w-10 h-10 text-zinc-400 dark:text-zinc-500" />
                <p class="text-sm text-zinc-500 dark:text-zinc-400">{{ __('No records found') }}</p>
            </div>
        </td>
    </tr>
@endif
```

### 10.2 Empty State Visual Verification

Per AGENTS.md, the empty state must not be white-on-white in dark mode. Verify:
- Background of the empty cell is the table body background (`bg-white dark:bg-zinc-800`)
- Icon uses `text-zinc-400 dark:text-zinc-500` (visible in both modes)
- Text uses `text-zinc-500 dark:text-zinc-400` (sufficient contrast)

### 10.3 Loading State

When the table is fetching data (Livewire loading), an overlay with a spinner is shown:

```blade
<tbody wire:loading.class.delay="opacity-50">
    @forelse ($rows as $row)
        {{-- ... rows ... --}}
    @empty
        {{-- ... empty state ... --}}
    @endforelse
</tbody>

<div wire:loading.flex wire:target="sort, nextPage, previousPage"
     class="absolute inset-0 items-center justify-center bg-white/50 dark:bg-zinc-800/50 z-20">
    <x-gsmui.icon name="arrow-path" class="w-6 h-6 animate-spin text-zinc-500" />
</div>
```

### 10.4 Skeleton Loading

For initial page load, a skeleton table shows placeholder rows:

```blade
@if ($loading)
    @foreach (range(1, 5) as $i)
        <tr class="animate-pulse">
            <td class="p-3"><div class="h-4 bg-zinc-200 dark:bg-zinc-700 rounded w-3/4"></div></td>
            <td class="p-3"><div class="h-4 bg-zinc-200 dark:bg-zinc-700 rounded w-1/2"></div></td>
            <td class="p-3"><div class="h-4 bg-zinc-200 dark:bg-zinc-700 rounded w-1/4"></div></td>
        </tr>
    @endforeach
@endif
```

## 11. Cell-Level Features

### 11.1 Inline Editing

Cells can be editable when `editable="true"` on `<gsmui:table.cell>`. On click, the cell content is replaced with an input:

```blade
<gsmui:table.cell :editable="true" wire:model="rows.{{ $index }}.name">
    {{ $row->name }}
</gsmui:table.cell>
```

The cell toggles between display and edit mode via `data-editing` attribute. On `Enter` or `Blur`, the edit is committed via Livewire. On `Escape`, the edit is cancelled.

### 11.2 Truncation with Tooltip

When `truncate="30"` is set on a cell, text exceeding 30 characters is truncated with an ellipsis. Hovering reveals a tooltip with the full text:

```blade
<gsmui:table.cell :truncate="30" :title="$row->description">
    {{ $row->description }}
</gsmui:table.cell>
```

### 11.3 Cell Alignment

Each cell respects the column's `align` property:

| Align | Classes |
| --- | --- |
| `left` | `text-left` (default) |
| `center` | `text-center` |
| `right` | `text-right tabular-nums` (right-aligned numbers) |

### 11.4 Cell Validation

Cells with validation errors use the AGENTS.md invalid-state layering:

```blade
<gsmui:table.cell :invalid="$errors->has("rows.$index.name")">
    {{ $row->name }}
</gsmui:table.cell>
```

The `data-invalid:` class is layered on top of the base cell style — never ternary-swapped.

### 12.2 Expand Trigger

The expand trigger is a chevron button in the first column. Clicking it toggles `data-expanded` on the row. The expanded content slides down with `max-height` transition.

### 12.3 Accordion Behavior

When `accordion="true"` on the table, only one row can be expanded at a time. Expanding a new row collapses the previous one.

## 13. Column Resizing

### 13.1 Drag-to-Resize

Column headers show a resize handle on hover (a 4px-wide transparent strip at the column's right edge). Dragging the handle resizes the column:

```blade
<gsmui:table.head key="name" :resizable="true">
    {{ __('Name') }}
    <div class="absolute right-0 top-0 bottom-0 w-1 cursor-col-resize opacity-0 hover:opacity-100 hover:bg-zinc-300 dark:hover:bg-zinc-600"
         x-data="{ dragging: false }"
         @mousedown="dragging = true"
         @mousemove.window="if (dragging) { /* update column width */ }"
         @mouseup.window="dragging = false">
    </div>
</gsmui:table.head>
```

### 13.2 Minimum Width

Columns have a minimum width of `100px` to prevent them from being resized to nothing. The resize handler clamps the width accordingly.

### 13.3 Persisted Widths

Column widths are saved to `localStorage` under `gsmui_table_column_widths` so they persist across sessions.

## 14. Responsive Patterns

### 14.1 Horizontal Scroll

On mobile, the table scrolls horizontally within its container. The scroll container has `overflow-x-auto` and shows a subtle gradient shadow on the right edge to indicate scrollability:

On very narrow screens (< 480px), the table can switch to a card-based layout where each row becomes a card:

```blade
<div class="sm:hidden space-y-3">
    @foreach ($rows as $row)
        <div class="bg-white dark:bg-zinc-800 border border-zinc-200 dark:border-white/10 rounded-lg p-3">

            <p class="text-xs text-zinc-500 mt-1">{{ $row->email }}</p>
        </div>
    @endforeach
</div>
```

### 14.3 Hidden Columns

Columns can be hidden on small screens via the `hide-on` prop:

```blade
<gsmui:table.head key="email" :hide-on="['sm']">
    {{ __('Email') }}

```

This applies `hidden sm:table-cell` to both the `<th>` and all corresponding `<td>` elements.

## 15. JavaScript Architecture

### 15.1 Table Class

```js
// assets/js/gsmui/table.js
import { setAttribute, removeAttribute } from './utils.js'

class GsmuiTable {
  constructor(el) {
    this.el = el
    this.sortField = null
    this.sortDirection = 'asc'
    this.selectedRows = new Set()
    this.setupMutationObserver()
    this.setupKeyboardNav()
  }

  setupMutationObserver() {
    const observer = new MutationObserver((mutations) => {
      for (const mutation of mutations) {
        if (mutation.attributeName === 'data-sort') {
          this.updateSortUI()
        }
        if (mutation.attributeName === 'data-loading') {
          this.toggleLoadingState()
        }
      }
    })
    observer.observe(this.el, { attributes: true, attributeFilter: ['data-sort', 'data-loading'] })
  }

  setupKeyboardNav() {
    this.el.addEventListener('keydown', (e) => {
      const row = e.target.closest('tr[data-row]')
      if (!row) return

      if (e.key === 'ArrowDown') {
        e.preventDefault()
        row.nextElementSibling?.querySelector('td')?.focus()
      } else if (e.key === 'ArrowUp') {
        e.preventDefault()
        row.previousElementSibling?.querySelector('td')?.focus()
      } else if (e.key === ' ' && e.target.closest('[data-selectable]')) {
        e.preventDefault()
        this.toggleRowSelect(row.dataset.id)
      }
    })
  }

  toggleRowSelect(id) {
    if (this.selectedRows.has(id)) {
      this.selectedRows.delete(id)
    } else {
      this.selectedRows.add(id)
    }
    this.el.dispatchEvent(new CustomEvent('gsmui:table-selection-change', {
      detail: { selected: [...this.selectedRows] }
    }))
  }
}
```

### 15.2 Event Protocol

| Event | Detail | When |
| --- | --- | ---|
| `gsmui:table-sort` | `{ field, direction }` | Column sort changed |
| `gsmui:table-selection-change` | `{ selected: string[] }` | Row selection changed |
| `gsmui:table-row-expand` | `{ id }` | Row expanded |
| `gsmui:table-row-collapse` | `{ id }` | Row collapsed |
| `gsmui:table-page-change` | `{ page, perPage }` | Page changed |

## 16. Integration with Livewire

### 16.1 Sort Handler

```php
public function sort(string $field)
{
    if ($this->sortField === $field) {
        $this->sortDirection = $this->sortDirection === 'asc' ? 'desc' : 'asc';
    } else {
        $this->sortField = $field;
        $this->sortDirection = 'asc';
    }

    $this->dispatch('gsmui:table-sort', [
        'field' => $this->sortField,
        'direction' => $this->sortDirection,
    ]);
}
```

### 16.2 Paginate Handler

```php
public function goToPage(int $page)
{
    $this->currentPage = $page;
}

public function nextPage()
{
    if ($this->currentPage < $this->totalPages) {
        $this->currentPage++;
    }
}

public function previousPage()
{
    if ($this->currentPage > 1) {
        $this->currentPage--;
    }
}
```

### 16.3 Bulk Action Handler

```php
public function bulkDelete()
{
    User::whereIn('id', $this->selected)->delete();
    $this->selected = [];
    $this->dispatch('notification', [
        'type' => 'success',
        'message' => __('Records deleted successfully.'),
    ]);
}

public function bulkExport()
{
    $users = User::whereIn('id', $this->selected)->get();
    return response()->streamDownload(function () use ($users) {
        echo $users->toCsv();
    }, 'users-export.csv');
}
```

## 17. Performance Considerations

### 17.1 Large Datasets

For datasets exceeding 1000 rows, consider:
- Server-side pagination (never render 1000+ DOM rows)
- Virtual scrolling (render only visible rows)
- Cursor-based pagination (avoid `OFFSET` in SQL)

### 17.2 Debounced Sort

Rapid column clicks are debounced (200ms) to prevent excessive Livewire requests:

```js
const debouncedSort = debounce((field) => {
  this.el.dispatchEvent(new CustomEvent('gsmui:table-sort', { detail: { field } }))
}, 200)
```

### 17.3 Layout Thrashing Prevention

Cell rendering batches DOM reads and writes. When measuring column widths for resize, all widths are read first, then all updates are applied:

```js
const widths = [...this.el.querySelectorAll('th')].map(th => th.getBoundingClientRect().width)
// Apply widths after all reads complete
```

## 18. Accessibility

### 18.1 Table Semantics

- The table uses semantic `<table>`, `<thead>`, `<tbody>`, `<tr>`, `<th>`, `<td>` elements
- `<th>` elements use `scope="col"` for column headers
- Sortable headers use `aria-sort` and are `<button>` elements (not `<a>`)

### 18.2 Row Focus

Each row is focusable via `tabindex="0"` on the `<tr>` element. Keyboard navigation uses `Arrow Up/Down` to move between rows and `Space` to toggle selection.

### 18.3 Live Region

Table updates (sort, page change) are announced to screen readers via an `aria-live` region:

```html
<div aria-live="polite" class="sr-only">
    {{ __('Sorted by name ascending') }}
</div>
```

```php
public function sort(string $field)
{

    $this->sortDirection = $this->sortDirection === 'asc' ? 'desc' : 'asc';

    $this->rows = $this->rows->sortBy(function ($row) use ($field) {
```

For infinite scroll pagination, the table detects when the user scrolls near the bottom and loads more rows:

```js
class InfiniteScrollTable {
  constructor(container, loadMore) {
    this.container = container
    this.loadMore = loadMore
    this.loading = false
```

## 28. Virtual Scrolling

### 28.1 When to Use

Virtual scrolling is used when the table has > 1000 rows and all rows need to be accessible without pagination. Only visible rows (plus a buffer) are rendered in the DOM.

### 28.2 Implementation

```js
class VirtualScrollTable {
  constructor(container, options = {}) {
    this.container = container
    this.rowHeight = options.rowHeight || 40
    this.buffer = options.buffer || 5
    this.totalRows = options.totalRows || 0
    this.visibleStart = 0
    this.visibleEnd = 0

    container.addEventListener('scroll', () => this.updateVisibleRange())
    this.updateVisibleRange()
  }

  updateVisibleRange() {
    const scrollTop = this.container.scrollTop
    const viewportHeight = this.container.clientHeight

    this.visibleStart = Math.max(0, Math.floor(scrollTop / this.rowHeight) - this.buffer)
    this.visibleEnd = Math.min(
      this.totalRows,
      Math.ceil((scrollTop + viewportHeight) / this.rowHeight) + this.buffer
    )

    this.render()
  }

  render() {
    // Only render rows in [visibleStart, visibleEnd]
    // Use a spacer div to maintain correct total height
  }
}
```

### 28.3 Spacer Element

A spacer div at the top and bottom of the table body maintains correct scroll height:

```blade
<tbody>
    <tr style="height: {{ $visibleStart * $rowHeight }}px"><td colspan="{{ $columnCount }}"></td></tr>
    @foreach ($visibleRows as $row)
        <tr>{{ $row }}</tr>
    @endforeach
    <tr style="height: {{ ($totalRows - $visibleEnd) * $rowHeight }}px"><td colspan="{{ $columnCount }}"></td></tr>
</tbody>
```

## 29. Export Functionality

### 29.1 Client-Side Export

For small datasets, export is handled client-side:

```js
function exportToCSV(rows, columns) {
  const headers = columns.map(c => c.label).join(',')
  const data = rows.map(row =>
    columns.map(c => `"${String(row[c.key]).replace(/"/g, '""')}"`).join(',')
  ).join('\n')

  const blob = new Blob([headers + '\n' + data], { type: 'text/csv' })
  const url = URL.createObjectURL(blob)
  const a = document.createElement('a')
  a.href = url
  a.download = 'export.csv'
  a.click()
  URL.revokeObjectURL(url)
}
```

### 29.2 Server-Side Export

For large datasets, export is handled server-side via Livewire:

```php
public function export()
{
    $query = $this->buildQuery(); // applies filters, sorts
    return response()->streamDownload(function () use ($query) {
        $handle = fopen('php://output', 'w');
        fputcsv($handle, ['Name', 'Email', 'Role']);
        $query->chunk(1000, function ($rows) use ($handle) {
            foreach ($rows as $row) {
                fputcsv($handle, [$row->name, $row->email, $row->role]);
            }
        });
        fclose($handle);
    }, 'users-export.csv');
}
```

## 32. Performance Considerations

### 32.1 DOM Efficiency

- Only render visible rows (virtual scrolling for > 1000 rows)
- Use `key` attributes on `<tr>` elements for efficient DOM updates
- Debounce sort/pagination requests (200ms)
- Batch DOM reads before writes (measure column widths before applying)

### 32.2 Memory Management

- Row data is stored in Livewire, not in JS — the table component is stateless
- Selection state is a simple array, not a complex data structure
- Column widths are cached in `localStorage`, not recomputed on every render

### 32.3 Network Optimization

- Sort/pagination requests are Livewire partial updates, not full page reloads
- Server-side pagination uses `LIMIT`/`OFFSET` (or cursor) for efficient queries
- Export uses streaming for large datasets

## 36. Troubleshooting Guide

### 36.1 Table Not Rendering Rows

1. Check that `$rows` is a non-empty Collection or Array
2. Verify `@foreach` is used correctly with `$rows`
3. Check that `{{ $slot }}` is inside the `<gsmui:table.row>` component
4. Verify the Livewire component is passing data correctly

### 36.2 Sort Not Working

1. Check that `sortable="true"` is set on the table and column
2. Verify `wire:click="sort('column')"` is on the `<gsmui:table.head>`
3. Check that the Livewire `sort()` method is defined
4. Verify the `wire:model="sort"` binding is correct

### 36.3 Pagination Not Showing

1. Check that `$users->links()` is in the `$pagination` slot
2. Verify the Livewire paginator is configured correctly
3. Check that `perPage` is set on the query
4. Verify the pagination view exists (`gsmui::pagination`)

### 36.4 Sticky Header Not Working

1. Check that `sticky-header="true"` is set
2. Verify the table is inside a scrollable container with `overflow: auto`
3. Check that the container has a defined height or `max-height`
4. Verify no parent element has `overflow: hidden` that prevents sticky positioning

### 36.5 Selection Not Persisting

1. Check that `wire:model="selected"` is bound to a Livewire array property
2. Verify the checkbox `value` matches the row's primary key
3. Check that the Livewire property is public
4. Verify Livewire is not resetting the property on re-render
