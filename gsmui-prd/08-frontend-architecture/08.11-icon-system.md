# Purpose

The GsmUi icon system is **inline-SVG only**: no icon fonts, no `@font-face`, no sprite CDN. Icons ship as Blade-rendered `<svg>` (Heroicons) or are bridged from Lucide, are colored via `currentColor`, and therefore inherit theme tokens through `--gsmui-*` CSS variables. This keeps the bundle fully CSP-safe (per `07.57-security.md` and `src/Http/Middleware/CspMiddleware.php`) with zero external requests and zero `eval()`.

## 1. Component Contract — `gsmui:icon`

The canonical component lives at `stubs/resources/views/gsmui/icon/index.blade.php`.

| Prop | Type | Default | Purpose |
| --- | --- | --- | --- |
| `name` | string | `null` | Icon key, e.g. `x-mark`, `check`, `chevron-down`. |
| `icon` | string | `null` | Alias for `name` (kept for sibling parity). |
| `variant` | `mini`\|`outline`\|`solid`\|`micro` | `mini` | Controls `viewBox`/path set and default size. |
| `class` | string | `''` | Merged via `Gsmui::classes()`. |

Contract rules:

- Output is an `<svg xmlns="http://www.w3.org/2000/svg" ... aria-hidden="true">`. Icons are decorative by default; never add `role="img"` unless `aria-label` is supplied by the caller.
- Heroicons paths use `viewBox="0 0 20 20"` (mini/solid/micro) or `0 0 24 24` (outline) and `fill="currentColor"`.
- The `loading` sentinel renders a spinner SVG and must be used inside busy triggers instead of a font spinner.
- Unknown names render a neutral `<span data-gsmui-icon>` placeholder — never an external 404.

```blade
<gsmui:icon name="check-circle" variant="mini" class="text-green-500" />
<gsmui:button aria-label="{{ __('Save') }}">
    <gsmui:icon name="check" variant="micro" />
</gsmui:button>
```

## 2. Sizing & Variant Matrix

Sizes come from the `variant` match in the component, not from wrapper classes:

| `variant` | Default size utility | Use |
| --- | --- | --- |
| `micro` | `size-4` | Inside badges, buttons (trailing), dense rows |
| `mini` | `size-5` | Leading/trailing in inputs, list items |
| `solid` / `outline` | `size-6` | Standalone, section headers |

All icons append `shrink-0` so they never compress inside flex containers. Color is applied exclusively through text utilities (`text-zinc-400`, `text-(--gsmui-color-accent)`); never hardcode `fill` colors in markup.

## 3. Icon Registry & Naming

- Heroicons keys live in a `match ($iconName) { ... }` map inside `icon/index.blade.php`. New icons are added to that map — do **not** introduce a separate icon service or JS registry (dead-code smell per AGENTS.md philosophy).
- Payment marks (`paypal`, `stripe`, `visa`, …) already embed brand colors via `fill="#..."` literals; these are intentional and exempt from `currentColor` theming because they are brand-identity, not themeable UI.
- Group keys by domain (`chevron-*`, `arrow-*`, `user-*`) so the map stays grep-able.

## 4. Lucide Bridging

Lucide ships as inline SVG. To support `name="lucide:settings"`:

- Detect the `lucide:` prefix in `icon/index.blade.php`, strip it, and resolve against a `lucidePaths` map using the same `match` pattern.
- Reuse the exact same `<svg>` shell, `aria-hidden`, and size utilities so Heroicons and Lucide are visually interchangeable.
- Never load Lucide from a CDN; the path data is bundled in PHP (consistent with the `dist/` self-hosting model and CSP profile).

## 5. CSP, Theming, and Accessibility

- **No `@font-face`, no icon fonts.** The CSP profile (`img-src 'self' data:`, no external fonts) is satisfied because every glyph is inline SVG.
- Theming flows through `--gsmui-*` variables: wrap an icon in a token-colored parent (e.g. `text-(--gsmui-color-danger)`) and `fill="currentColor"` resolves automatically. Dark mode is handled by Tailwind `dark:` variants on the text utility.
- Decorative icons keep `aria-hidden="true"`. When an icon *conveys meaning* (status, error), pair it with a visually-hidden `<span class="sr-only">` label or a `title`/`aria-label` on the host control — never rely on the icon alone (see `08.16-accessibility.md`).

## 6. Open Questions / Risks

- Should Lucide be lazy-resolved (map split) to keep `icon.blade.php` from growing unbounded? Trade-off vs. the AGENTS.md "no extra abstraction" rule.
- Brand-color payment marks bypass `--gsmui-*` theming; document this limitation in `08.18-data-display.md`.
- Consider a `size` prop override distinct from `variant` for consumers that need `size-3` micro icons.

## 7. Icon Grid System & Design Tokens

### 7.1 Grid Reference

All GsmUi icons conform to a consistent grid that ensures visual balance across the icon set:

| Grid | viewBox | Cell size | Stroke width | Padding |
| --- | --- | --- | --- | --- |
| Mini (Heroicons) | `0 0 20 20` | 20×20 | 1.5px | 2px optical |
| Solid (Heroicons) | `0 0 24 24` | 24×24 | 0 (filled) | 2px optical |
| Outline (Heroicons) | `0 0 24 24` | 24×24 | 1.5px | 2px optical |
| Micro (Heroicons) | `0 0 16 16` | 16×16 | 1px | 1px optical |
| Lucide (bridged) | `0 0 24 24` | 24×24 | 2px | 2px optical |

### 7.2 Optical Alignment Rules

Icons are visually centered, not mathematically centered. The 2px optical padding ensures icons don't appear "cramped" at their edges:

- **Asymmetric icons** (e.g., `arrow-right`) are shifted slightly toward the center of the grid to appear balanced.
- **Rounded shapes** (e.g., `check-circle`) are slightly larger than the grid to compensate for the visual weight loss from rounding.
- **Thin icons** (e.g., `minus`) use slightly thicker strokes at micro size to maintain legibility.

### 7.3 Icon Size Tokens

The icon system provides size tokens that map to the grid variants:

| Token | px value | Tailwind utility | Use case |
| --- | --- | --- | --- |
| `--gsmui-icon-micro` | 16px | `size-4` | Inline badges, tags, tight spaces |
| `--gsmui-icon-mini` | 20px | `size-5` | Buttons (default), input adornments |
| `--gsmui-icon-sm` | 24px | `size-6` | Section headers, standalone |
| `--gsmui-icon-md` | 32px | `size-8` | Feature cards, empty states |
| `--gsmui-icon-lg` | 48px | `size-12` | Hero sections, onboarding |
| `--gsmui-icon-xl` | 64px | `size-16` | Marketing, splash screens |

### 7.4 Icon Color Tokens

Icons inherit color via `currentColor` from their parent's text utility. The token mapping:

| Semantic | Light mode | Dark mode | Tailwind class |
| --- | --- | --- | --- |
| Default | `zinc-500` | `zinc-400` | `text-zinc-500 dark:text-zinc-400` |
| Muted | `zinc-400` | `zinc-500` | `text-zinc-400 dark:text-zinc-500` |
| Strong | `zinc-900` | `white` | `text-zinc-900 dark:text-white` |
| Accent | `--gsmui-color-accent` | `--gsmui-color-accent` | `text-(--gsmui-color-accent)` |
| Success | `green-500` | `green-400` | `text-green-500 dark:text-green-400` |
| Danger | `red-500` | `red-400` | `text-red-500 dark:text-red-400` |
| Warning | `amber-500` | `amber-400` | `text-amber-500 dark:text-amber-400` |
| Info | `blue-500` | `blue-400` | `text-blue-500 dark:text-blue-400` |

### 7.5 Icon Spacing Tokens

Icons inside containers use consistent spacing:

| Context | Gap | Tailwind class |
| --- | --- | --- |
| Icon + label (button) | 8px | `gap-2` |
| Icon + label (input adornment) | 8px | `gap-2` |
| Icon + label (nav item) | 8px | `gap-2` |
| Icon only (icon button) | 0 | N/A |
| Icon + badge | -4px (overlap) | `-ml-1` |
| Icon in table cell | 8px | `gap-2` |

### 8.2 Outline Variant (24×24)

Outline uses the same icon keys as mini but with stroke-based paths instead of filled paths. The outline variant is used for:

- Standalone icons in section headers.
- Empty state illustrations.
- Marketing page feature callouts.
- Any context where the icon is the primary visual element.

### 8.3 Loading Spinner

The `loading` sentinel icon is a special case:

```svg
<svg xmlns="http://www.w3.org/2000/svg" fill="none" viewBox="0 0 24 24"
     class="animate-spin" aria-hidden="true">
  <circle cx="12" cy="12" r="10" stroke="currentColor" stroke-width="4" opacity="0.25" />
  <path fill="currentColor" d="M4 12a8 8 0 018-8V0C5.373 0 0 5.373 0 12h4z" />
</svg>
```

Rules:
- Only used inside busy triggers (buttons with `aria-busy="true"`).
- Never used as a standalone page loader (use `gsmui:skeleton` instead).
- Under `prefers-reduced-motion: reduce`, the spinner stops animating and shows a static circle.

### 9.2 Lucide Naming Convention

Lucide icon names use kebab-case (same as Heroicons):

| Lucide name | GsmUi key | Notes |
| --- | --- | --- |
| `lucide:settings` | `settings` | Lucide prefix stripped |

### 9.3 Heroicons vs Lucide Selection Guide

When choosing between Heroicons and Lucide for a new icon:

| Criterion | Heroicons | Lucide |
| --- | --- | --- |
| Filled variants | ✅ `solid` variant | ❌ Outline only |
| Consistency | More uniform stroke weight | Slightly more varied |
| Coverage | ~300 icons | ~1500 icons |
| Use when | Need filled variant, standard UI icons | Need specialized icon not in Heroicons |

### 9.4 Adding a New Lucide Icon

Process for adding a Lucide icon to the registry:

1. Find the icon on [lucide.dev](https://lucide.dev).
2. Copy the SVG path data.
3. Add to `$lucidePaths` in `icon/index.blade.php`.
4. Group alphabetically within the domain group.
5. Test with `<gsmui:icon name="lucide:new-icon" />` in the test page.
6. Verify CSP compliance (no external requests, no eval).

## 10. Icon Component Blade Implementation

### 10.1 Full Blade Template Structure

```blade
{{-- stubs/resources/views/gsmui/icon/index.blade.php --}}
@props([
    'name' => null,
    'icon' => null,
    'variant' => 'mini',
    'class' => '',
    'title' => null,
])

@php
    $iconName = $icon ?? $name;
    $isLucide = str_starts_with($iconName, 'lucide:');
    $heroiconName = $isLucide ? substr($iconName, 7) : $iconName;

    $sizeClass = match($variant) {
        'micro' => 'size-4',
        'mini' => 'size-5',
        'solid', 'outline' => 'size-6',
        default => 'size-5',
    };

    $classes = Gsmui::classes()
        ->add($sizeClass)
        ->add('shrink-0')
        ->add($class);
@endphp

@if($isLucide)
    @php $paths = $lucidePaths[$heroiconName] ?? null; @endphp
    @if($paths)
        <svg xmlns="http://www.w3.org/2000/svg" {{ $attributes->merge(['class' => $classes])->merge(['fill' => 'none', 'viewBox' => '0 0 24 24', 'stroke-width' => '2', 'stroke' => 'currentColor']) }}
             aria-hidden="true">
            @if($title)<title>{{ $title }}</title>@endif
            {!! $paths !!}
        </svg>
    @else
        <span data-gsmui-icon data-gsmui-icon-missing="lucide:{{ $heroiconName }}"></span>
    @endif
@else
    @php
        $variantViewBox = match($variant) {
            'micro' => '0 0 16 16',
            'mini', 'solid' => '0 0 20 20',
            'outline' => '0 0 24 24',
            default => '0 0 20 20',
        };
    @endphp
    {{-- Heroicons match block --}}
    @switch($heroiconName)
        @case('check')
            <svg xmlns="http://www.w3.org/2000/svg" {{ $attributes->merge(['class' => $classes])->merge(['fill' => 'currentColor', 'viewBox' => $variantViewBox]) }} aria-hidden="true">
                @if($title)<title>{{ $title }}</title>@endif
                <path fill-rule="evenodd" d="M16.704 4.153a.75.75 0 01.143 1.052l-8 10.5a.75.75 0 01-1.127.075l-4.5-4.5a.75.75 0 011.06-1.06l3.894 3.893 7.48-9.817a.75.75 0 011.05-.143z" clip-rule="evenodd"/>
            </svg>
            @break
        {{-- ... more cases --}}
        @default
            <span data-gsmui-icon data-gsmui-icon-missing="{{ $heroiconName }}"></span>
    @endswitch
@endif
```

### 10.2 Class Merging with Gsmui::classes()

The `Gsmui::classes()` call ensures that:
- Consumer-provided `class` prop is merged, not replaced.
- Internal size classes (`size-5`) can be overridden by the consumer.
- The `shrink-0` class is always present (prevents flex compression).

### 10.3 Title Attribute for Accessible Names

When an icon conveys meaning (not decorative), use the `title` prop:

```blade
<gsmui:icon name="info-circle" title="{{ __('This field is required') }}" />
```

This renders a `<title>` element inside the SVG, which screen readers announce. However, for most use cases, a visually-hidden `<span class="sr-only">` on the parent control is preferred (see section 11).

## 11. Icon Accessibility Deep Dive

### 11.1 Decorative Icons (Default)

Most icons are decorative — they reinforce adjacent text:

```blade
<gsmui:button>
    <gsmui:icon name="check" variant="micro" />  {{-- aria-hidden="true" --}}
    {{ __('Save') }}
</gsmui:button>
```

The screen reader reads "Save" and ignores the icon. No additional markup needed.

### 11.2 Meaningful Icons

When an icon stands alone (no adjacent text), it must have an accessible name:

**Option A: `aria-label` on the parent control (preferred):**

```blade
<gsmui:button aria-label="{{ __('Close') }}">
    <gsmui:icon name="x-mark" variant="micro" />
</gsmui:button>
```

**Option B: `sr-only` text (when no parent control):**

```blade
<gsmui:icon name="exclamation-triangle" variant="mini" />
<span class="sr-only">{{ __('Warning') }}</span>
```

**Option C: `title` attribute (least preferred):**

```blade
<gsmui:icon name="info-circle" title="{{ __('More information') }}" />
```

### 11.3 Status Icons

Status icons that communicate state must be paired with text:

```blade
{{-- ✅ Correct: icon + text together --}}
<span class="flex items-center gap-2">
    <gsmui:icon name="check-circle" variant="mini" class="text-green-500" />
    <span>{{ __('Active') }}</span>
</span>

{{-- ❌ Wrong: icon alone --}}
<gsmui:icon name="check-circle" variant="mini" class="text-green-500" />
```

### 11.4 Icon in Form Validation

When an icon indicates valid/invalid state:

```blade
<div class="relative">
    <input type="text" aria-invalid="true" aria-describedby="email-error" />
    <gsmui:icon name="exclamation-circle" variant="mini"
                class="absolute right-3 top-1/2 -translate-y-1/2 text-red-500" />
</div>
<span id="email-error" class="text-sm text-red-500">{{ __('Email is required') }}</span>
```

The icon is decorative (aria-hidden); the error message provides the accessible information.

## 12. Icon Animation

### 12.1 Animated Icons

Some icons have animated variants for feedback:

| Icon | Animation | Use case |
| --- | --- | --- |
| `loading` | `animate-spin` (continuous rotation) | Button busy state |
| `check-circle` | Scale-in + color change | Success confirmation |
| `exclamation-circle` | Shake | Error emphasis |
| `arrow-path` | `animate-spin` (rotation) | Refresh, sync |

### 12.2 Animation Classes

```blade
{{-- Loading spinner --}}
<gsmui:icon name="loading" class="animate-spin" />

{{-- Success check (with transition) --}}
<gsmui:icon name="check-circle" class="text-green-500 scale-0 animate-[scale-in_200ms_ease-out_forwards]" />

{{-- Error shake --}}
<gsmui:icon name="exclamation-circle" class="text-red-500 animate-[shake_300ms_ease-in-out]" />
```

### 12.3 Reduced Motion

Under `prefers-reduced-motion: reduce`:
- `animate-spin` becomes a static circle (animation stops).
- `scale-in` becomes instant (no visual tween).
- `shake` is suppressed entirely.

This is handled by the global reduced-motion rule in `08.15-animation-system.md`.

## 13. Icon Theming Integration

### 13.1 CSS Variable Theming

Icons inherit color from their parent's text color, which can be driven by `--gsmui-*` tokens:

```blade
{{-- Accent-colored icon --}}
<span class="text-(--gsmui-color-accent)">
    <gsmui:icon name="star" variant="mini" />
</span>

{{-- Success-colored icon --}}
<span class="text-(--gsmui-color-success)">
    <gsmui:icon name="check-circle" variant="mini" />
</span>
```

### 13.2 Dark Mode Adaptation

Tailwind's `dark:` variant handles icon color in dark mode:

```blade
<gsmui:icon name="home" class="text-zinc-500 dark:text-zinc-400" />
```

### 13.3 Brand-Color Exceptions

Payment brand icons (PayPal, Stripe, Visa) use hardcoded fill colors:

```blade
{{-- These bypass currentColor — intentional brand identity --}}
<gsmui:icon name="paypal" class="size-8" />  {{-- fill="#003087" --}}
<gsmui:icon name="stripe" class="size-8" />  {{-- fill="#635BFF" --}}
```

This is documented as a known limitation: brand icons do not respond to theme tokens.

## 14. Icon Performance

### 14.1 Inline SVG vs External

Inline SVG is used because:
1. **No additional HTTP requests** — the SVG markup is rendered server-side by Blade.
2. **CSP-safe** — no external resource loading.
3. **Themeable** — `currentColor` inherits from CSS.
4. **Accessible** — `aria-hidden` is set directly on the element.

### 14.2 Bundle Size Impact

Each icon path adds approximately 200-500 bytes to the Blade template cache. With ~100 icons in the Heroicons registry and ~50 in Lucide:

| Component | Size (approx) |
| --- | --- |
| Heroicons registry (PHP match block) | ~30KB |
| Lucide registry (PHP $lucidePaths array) | ~25KB |
| Total icon system (Blade cache) | ~55KB |

This is acceptable because:
- It's server-side rendered (no client-side JS overhead).
- It's cached by Laravel's Blade compiler.
- It's zero client-side bytes (no JS bundle increase).

### 14.3 Lazy Icon Rendering

For pages with many icons (e.g., a data table with 100 rows × 3 icons each):

- Icons are server-rendered as inline SVG — no lazy loading needed.
- The browser handles 300 inline SVGs efficiently because they share the same DOM rendering pipeline as text.
- No `loading="lazy"` is applicable to inline SVG (only `<img>` elements).

## 17. Icon Design Principles

### 17.1 Visual Consistency Rules

All icons in the GsmUi set must follow these consistency principles:

| Principle | Rule | Example |
| --- | --- | --- |
| Consistent stroke weight | 1.5px for mini/outline, 2px for Lucide, 1px for micro | All outlines use the same thickness |
| Consistent corner radius | 1px for small shapes, 2px for larger | No sharp corners mixed with rounded |
| Consistent optical sizing | Icons appear same visual weight regardless of shape | `check` is slightly larger than `minus` |
| Consistent padding | 2px optical padding in the viewBox | No icon touches the edge of the viewBox |
| Consistent alignment | Center of visual mass aligns to center of grid | Asymmetric icons shift toward center |

### 17.2 Stroke vs Fill Decision

| When to use stroke (outline) | When to use fill (solid) |
| --- | --- |
| Navigation icons (arrows, chevrons) | Status indicators (check-circle, x-circle) |
| Action icons (edit, copy, trash) | Selected state (filled heart, star) |
| Tool icons (settings, search) | Brand logos |
| UI chrome (menu, expand) | Emphasis/prominence needed |

### 17.3 Icon Simplicity Budget

Each icon should have no more than:
- 2 distinct paths (for outline variant)
- 3 distinct shapes (for solid variant)
- 1 color (currentColor, except brand marks)

Icons exceeding this budget are too complex for small sizes and should be simplified.

### 17.4 Perceived Size Correction

Different shapes have different visual weights at the same mathematical size:

| Shape | Size adjustment | Rationale |
| --- | --- | --- |
| Circle (check-circle) | No adjustment needed | Circles fill the viewBox well |
| Square (document) | Slightly smaller than circle | Squares feel heavier than circles |
| Triangle (warning) | Slightly larger than circle | Triangles feel lighter than circles |
| Thin lines (minus, separator) | Increase stroke weight at small sizes | Thin lines disappear at micro size |
| Wide shapes (arrow-right) | Shift toward center | Asymmetric shapes need optical centering |

## 18. Icon Composition Patterns

### 18.1 Icon + Text Composition

The most common icon usage pairs an icon with text:

```blade
{{-- Standard pattern: icon left, text right --}}
<span class="inline-flex items-center gap-2">
    <gsmui:icon name="check" variant="micro" />
    <span>{{ __('Completed') }}</span>
</span>

{{-- Button with icon --}}
<gsmui:button>
    <gsmui:icon name="plus" variant="micro" />
    {{ __('Add item') }}
</gsmui:button>

{{-- Button with trailing icon --}}
<gsmui:button>
    {{ __('View all') }}
    <gsmui:icon name="arrow-right" variant="micro" />
</gsmui:button>
```

### 18.2 Icon-Only Composition

When an icon stands alone without text, it MUST have an accessible name:

```blade
{{-- Icon button (preferred — uses gsmui:button) --}}
<gsmui:button aria-label="{{ __('Delete') }}" variant="ghost" size="xs">
    <gsmui:icon name="trash" variant="micro" />
</gsmui:button>

{{-- Icon link --}}
<a href="/settings" aria-label="{{ __('Settings') }}">
    <gsmui:icon name="cog" variant="mini" />
</a>

{{-- Status indicator (icon + sr-only text) --}}
<span class="inline-flex items-center gap-1">
    <gsmui:icon name="check-circle" variant="micro" class="text-green-500" />
    <span class="sr-only">{{ __('Active') }}</span>
</span>
```

### 18.3 Icon in Input Adornment

Icons inside input triggers use the mini variant and specific spacing:

```blade
{{-- Leading icon --}}
<gsmui:input icon="magnifying-glass" placeholder="{{ __('Search…') }}" />

{{-- Trailing icon (clear button) --}}
<gsmui:input clearable>
    <x-slot:trailing>
        <gsmui:button as="div" variant="ghost" size="xs" aria-label="{{ __('Clear') }}">
            <gsmui:icon name="x-mark" variant="micro" />
        </gsmui:button>
    </x-slot:trailing>
</gsmui:input>
```

### 18.4 Icon in Badge/Tag

Icons in badges use the micro variant to fit the compact space:

```blade
<gsmui:badge variant="success">
    <gsmui:icon name="check" variant="micro" class="size-3" />
    {{ __('Active') }}
</gsmui:badge>
```

### 18.5 Icon Stack (Layered Icons)

When two icons are composed to indicate state:

```blade
{{-- Notification bell with badge --}}
<span class="relative inline-flex">
    <gsmui:icon name="bell" variant="mini" />

</span>
```

## 19. Icon Rendering Performance

### 19.1 Server-Side Rendering Benefits

Inline SVG icons are rendered server-side by Blade, providing:

| Benefit | Impact |
| --- | --- |
| Zero client-side JS | No icon library to load, parse, or execute |
| Zero FOUC | Icons appear immediately with the HTML |
| CSP-safe | No external resources, no eval |
| SEO-friendly | Icons are part of the DOM, indexable |
| Accessible | `aria-hidden` set at render time |

### 19.2 Template Caching

Laravel's Blade compiler caches the icon template. The `@switch` / `match` block in `icon/index.blade.php` is compiled to efficient PHP:

```php
// Compiled PHP (simplified)
switch ($heroiconName) {
    case 'check':
        return '<svg ...>...</svg>';
    case 'x-mark':
        return '<svg ...>...</svg>';
    // ...
    default:
        return '<span data-gsmui-icon data-gsmui-icon-missing="' . e($heroiconName) . '"></span>';
}
```

This is a single `switch` statement — O(1) lookup time.

### 19.3 Browser Rendering Performance

Inline SVGs are rendered by the browser's SVG engine. Performance considerations:

| Factor | Impact | Mitigation |
| --- | --- | --- |
| Number of SVGs on page | More SVGs = more DOM nodes | Limit to ~200 per page (typical dashboard) |
| Path complexity | Complex paths = longer paint time | Keep path data minimal |
| CSS animations on SVGs | Animated SVGs = more repaints | Use `will-change: transform` for animated icons |
| Color changes | `currentColor` is efficient | No re-render needed for color changes |

### 19.4 SVG Rendering Optimization

```css
/* Hint to browser that SVG is static */
svg[aria-hidden="true"] {
  content-visibility: auto; /* Skip rendering off-screen SVGs */
}

/* Prevent layout shifts from icon loading */
svg {
  display: inline-block;
  vertical-align: middle;
}
```

## 21. Icon Theming Deep Dive

### 21.1 Theme Token Integration

Icons inherit color through `currentColor` from their parent's text color. The theme integration chain:

```text
--gsmui-color-accent (CSS variable)
    ↓
text-(--gsmui-color-accent) (Tailwind utility on parent)
    ↓
color: var(--gsmui-color-accent) (computed CSS)
    ↓
currentColor (SVG fill/stroke value)
    ↓
Icon renders in accent color
```

### 21.2 Dark Mode Icon Colors

| Context | Light mode class | Dark mode class |
| --- | --- | --- |
| Default icon | `text-zinc-500` | `dark:text-zinc-400` |
| Active icon | `text-zinc-900` | `dark:text-white` |
| Muted icon | `text-zinc-400` | `dark:text-zinc-500` |
| Accent icon | `text-(--gsmui-color-accent)` | `text-(--gsmui-color-accent)` |
| Success icon | `text-green-500` | `dark:text-green-400` |
| Danger icon | `text-red-500` | `dark:text-red-400` |

### 21.3 High Contrast Mode

Under Windows High Contrast Mode, `currentColor` maps to the system text color, ensuring icons remain visible:

## 22. Icon Accessibility Deep Dive

### 22.1 Screen Reader Behavior by Icon Type

| Icon type | Screen reader behavior | Implementation |
| --- | --- | --- |
| Decorative (default) | Skipped entirely | `aria-hidden="true"` |
| Meaningful + labeled parent | Parent label announced | `aria-label` on parent `<button>` |
| Meaningful + sr-only text | sr-only text announced | `<span class="sr-only">` sibling |
| Meaningful + title | Title announced (less reliable) | `<title>` inside SVG |
| Status indicator | Combined with adjacent text | Text provides the meaning |

### 22.2 Focus Indicator for Icon Buttons

Icon buttons must have visible focus indicators:

```blade
<gsmui:button aria-label="{{ __('Close') }}"
              class="focus-visible:outline-2 focus-visible:outline-[-webkit-focus-ring-color]">
    <gsmui:icon name="x-mark" variant="micro" />
</gsmui:button>
```

### 22.3 Touch Target for Icon Buttons

Icon buttons must meet the 44×44px minimum touch target:

```blade
<gsmui:button aria-label="{{ __('Delete') }}"
              class="min-h-11 min-w-11 flex items-center justify-center">
    <gsmui:icon name="trash" variant="micro" />
</gsmui:button>
```

### 22.4 Icon in Form Validation

Status icons in form validation must not be the only indicator:

```blade
{{-- ✅ Correct: icon + text + color --}}
<div class="flex items-center gap-2 text-sm text-red-500" role="alert">
    <gsmui:icon name="exclamation-circle" variant="micro" />
    <span>{{ __('Email is required') }}</span>
</div>

{{-- ❌ Wrong: icon + color only --}}
<gsmui:icon name="exclamation-circle" variant="micro" class="text-red-500" />
```

## 25. Icon System Architecture

### 25.1 Server-Side Rendering Pipeline

The icon rendering pipeline flows entirely through Blade:

```text
Blade template
    ↓ @props(['name', 'variant'])
    ↓ PHP match/switch on icon name
    ↓ SVG path data resolved from registry
    ↓ SVG element constructed with attributes
    ↓ HTML output (inline SVG)
    ↓ Browser renders SVG
```

### 25.2 Icon Registry Architecture

The icon registry is a PHP array defined within the Blade component:

```php
// Inside icon/index.blade.php
$heroiconsMini = [
    'check' => '<path fill-rule="evenodd" d="M16.704 4.153a.75.75 0 01.143 1.052l-8 10.5a.75.75 0 01-1.127.075l-4.5-4.5a.75.75 0 011.06-1.06l3.894 3.893 7.48-9.817a.75.75 0 011.05-.143z" clip-rule="evenodd"/>',
    'x-mark' => '<path d="M6.28 5.22a.75.75 0 00-1.06 1.06L8.94 10l-3.72 3.72a.75.75 0 101.06 1.06L10 11.06l3.72 3.72a.75.75 0 101.06-1.06L11.06 10l3.72-3.72a.75.75 0 00-1.06-1.06L10 8.94 6.28 5.22z"/>',
    // ... more icons
];

$heroiconsOutline = [
    'check' => '<path stroke-linecap="round" stroke-linejoin="round" d="M4.5 12.75l6 6 9-13.5" />',
    'x-mark' => '<path stroke-linecap="round" stroke-linejoin="round" d="M6 18L18 6M6 6l12 12" />',
    // ... more icons
];

$lucidePaths = [
    'settings' => '<path d="M12.22 2h-.44a2 2 0 0 0-2 2v.18a2 2 0 0 1-1 1.73l-.43.25a2 2 0 0 1-2 0l-.15-.08a2 2 0 0 0-2.73.73l-.22.38a2 2 0 0 0 .73 2.73l.15.1a2 2 0 0 1 1 1.72v.51a2 2 0 0 1-1 1.74l-.15.09a2 2 0 0 0-.73 2.73l.22.38a2 2 0 0 0 2.73.73l.15-.08a2 2 0 0 1 2 0l.43.25a2 2 0 0 1 1 1.73V20a2 2 0 0 0 2 2h.44a2 2 0 0 0 2-2v-.18a2 2 0 0 1 1-1.73l.43-.25a2 2 0 0 1 2 0l.15.08a2 2 0 0 0 2.73-.73l.22-.39a2 2 0 0 0-.73-2.73l-.15-.08a2 2 0 0 1-1-1.74v-.5a2 2 0 0 1 1-1.74l.15-.09a2 2 0 0 0 .73-2.73l-.22-.38a2 2 0 0 0-2.73-.73l-.15.08a2 2 0 0 1-2 0l-.43-.25a2 2 0 0 1-1-1.73V4a2 2 0 0 0-2-2z"/>',
    // ... more Lucide paths
];
```

### 25.3 Icon Resolution Order

When `<gsmui:icon name="check" />` is called:

1. Check if name starts with `lucide:` → resolve from `$lucidePaths`.
2. Otherwise, resolve from `$heroiconsMini` (default variant).
3. If `variant="outline"` → resolve from `$heroiconsOutline`.
4. If not found in any registry → render `<span data-gsmui-icon-missing>`.

### 25.4 Icon Caching Strategy

| Cache layer | Mechanism | TTL |
| --- | --- | --- |
| Blade template cache | Laravel's `php artisan view:cache` | Until cache cleared |
| PHP opcache | PHP's opcache | Server restart |
| HTTP cache | CDN/browser cache | 1 year (immutable assets) |
| No client-side cache needed | Inline SVG is part of HTML | N/A |

## 26. Icon Contribution Process

## 43. Icon System Contribution Guide

### 43.1 Adding a New Heroicons Icon

1. **Check availability:** Visit heroicons.com and verify the icon exists.
2. **Select variant:** Choose mini (20×20) for dense UI, outline (24×24) for standalone.
3. **Copy SVG data:** Get the `<path>` elements from the Heroicons source.
4. **Add to registry:** Add a new `@case` block in `icon/index.blade.php`.
5. **Group by domain:** Place near related icons (e.g., `user-*` icons together).
6. **Test rendering:** Use `<gsmui:icon name="new-icon" />` in the test page.
7. **Verify accessibility:** Confirm decorative (aria-hidden) or meaningful (paired with text).
8. **Test all sizes:** Verify at micro, mini, and default sizes.
9. **Test dark mode:** Verify icon is visible in both light and dark themes.
10. **Run Playwright:** Visual regression test at defined breakpoints.

### 43.2 Adding a New Lucide Icon

1. **Check availability:** Visit lucide.dev and verify the icon exists.
2. **Copy SVG path data:** Get the raw SVG content.
3. **Add to registry:** Add to the `$lucidePaths` array.
4. **Use kebab-case:** Follow Lucide's naming convention.
5. **Test with prefix:** Use `<gsmui:icon name="lucide:new-icon" />`.
6. **Verify CSP:** No external requests, no eval.
7. **Test visual parity:** Ensure it looks consistent with Heroicons icons.

## 44. Icon System Summary

### 44.1 Key Architectural Decisions

| Decision | Rationale |
| --- | --- |
| Inline SVG (not icon font) | CSP-safe, no external resources |
| Heroicons (primary) + Lucide (extended) | Comprehensive coverage |
| Blade component rendering | Server-side, no JS dependency |
| `currentColor` inheritance | Theme integration |
| Mini variant default | Dense UI optimization |
| `aria-hidden="true"` default | Accessibility by default |
| Path data in PHP arrays | Fast server-side lookup |

### 44.2 Icon System Metrics

| Metric | Value | Target |
| --- | --- | --- |
| Total icons available | ~1800+ | Sufficient for all UI patterns |
| Heroicons icons | ~900+ | Primary UI icons |
| Lucide icons | ~900+ | Extended/specialized icons |
| HTTP requests for icons | 0 | Zero external resources |
| JS dependency | None | Pure HTML/CSS |
| Font files | None | No icon font |
| CSP compliance | Full | No eval, no CDN, no external |
| Dark mode support | Full | currentColor inheritance |
| RTL support | Full | SVGs are direction-neutral |
| Average SVG path size | < 300 bytes | Efficient rendering |

### 44.3 Icon System Architecture

```text
Blade template
    ↓
<gsmui:icon name="..." variant="..." />
    ↓
PHP match on name → SVG path data
    ↓
Construct <svg> element with attributes
    ↓
Output HTML with inline SVG
    ↓
Browser renders vector graphic
    ↓
currentColor inherits from parent
```
