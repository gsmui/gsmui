# Purpose

GsmUi targets **WCAG 2.2 AA**. Accessibility is built into component contracts, not bolted on: correct ARIA APG roles, native focus rings, visible `data-invalid` states, keyboard operability for every interactive widget, and AA contrast in both themes. This document is the single source of truth for those rules and must be cited by every component PRD.

## 1. ARIA APG Patterns

Each interactive component follows the closest ARIA Authoring Practices pattern:

| Component | Pattern | Key attributes |
| --- | --- | --- |
| `gsmui:input` (trigger) | Combobox | `role="combobox"` on `<input>`, `aria-expanded`, `aria-controls` |
| `gsmui:button` trigger | Dialog button | native `<button>` + `aria-haspopup="dialog"` |
| `gsmui:modal` | Dialog | `role="dialog" aria-modal="true"` |
| `gsmui:popover`/`tooltip` | Popover/Tooltip | `popover="manual"`, `role="tooltip"` when interactive |
| `gsmui:navlist` | Navigation | `<nav>`, `aria-current="page"` on active |
| `gsmui:breadcrumbs` | Breadcrumb | `aria-label="Breadcrumb"` + `<ol>` |
| `gsmui:progress` | Progressbar | `role="progressbar"` + `aria-valuenow/min/max` |

Do **not** invent new ARIA patterns — check APG/React Aria first (AGENTS.md).

## 2. Focus Rings (verbatim from AGENTS.md)

- **Native focusable elements** (`<button>`, `<input>`, `<a>`, `<select>`): prefer the browser's native outline. **Add NO focus classes.**
- **Custom elements** (custom tag with `tabindex="0"`, or wrapper around `<input type="range">`): use the slider-thumb pattern — never `focus:ring-2`:

```css
has-focus-visible:outline-2 has-focus-visible:outline-[-webkit-focus-ring-color]
```

- Never use `focus:outline-none focus:ring-2 focus:ring-(--color-accent)`.

## 3. Cursors (verbatim from AGENTS.md)

- `cursor-pointer` belongs **only** on interactive elements that perform navigation.
- Buttons and other clickable widgets keep the default cursor.
- A trigger that is "whole = one input" (`gsmui:input`) uses `cursor: text` across the container except over action buttons (`clearable`/`copyable`).

## 4. Invalid State Pattern (verbatim from AGENTS.md)

Layer `data-invalid:` classes **on top** of base styles. **Never** ternary-swap the entire class block (match `gsmui:input`):

```blade
@php
$classes = Gsmui::classes()
    ->add($invalid
        ? 'border border-red-500'
        : 'border border-zinc-200 border-b-zinc-300/80 dark:border-white/10');
@endphp

<input @if ($invalid) aria-invalid="true" data-invalid @endif ... />
```

Invalid styling must be visible in both light and dark themes and must not rely on color alone (pair with an error icon + message, `08.17`).

## 5. Focus Management & Keyboard Nav

- **Modal/popover/drawer** (`08.20`): on open, move focus to the first focusable element; on close, restore focus to the trigger. Trap Tab within the surface; `Escape` closes.
- **2D area nav** (grids, color picker): Arrow keys move; `Home`/`End` = horizontal edges; `PageUp`/`PageDown` = vertical edges (AGENTS.md).
- **Disabled custom elements**: CSS `:disabled` only works on native form elements. Custom elements need `[&[disabled]]:shadow-none!` and must be removed from the tab order (`tabindex="-1"` or omitted).
- All interactive widgets are fully keyboard-operable; never ship mouse-only interactions.

## 6. Localization & Semantics

- Aria-labels use `__()` (set in Blade where it runs). JS uses the Blade-set value as primary, a hardcoded English string only as fallback (AGENTS.md).
- Decorative icons: `aria-hidden="true"`; meaningful icons paired with `sr-only` text (`08.11`).
- Real `<gsmui:button>` for action buttons inside triggers; only `<gsmui:button as="div">` when nested in a `<button>` (HTML constraint).

## 7. Contrast & Theming

- All text/icon pairs meet ≥ 4.5:1 (AA) in light and dark via `--gsmui-*` tokens.
- Watch white-on-white states (empty states, disabled, focus) — explicit Playwright checks per AGENTS.md.
- `dark:bg-zinc-700` surfaces (dialogs/popovers) must keep AA against their text tokens.

## 8. Open Questions / Risks

- Need an automated a11y gate (axe/Playwright) in `08.49-testing.md` to enforce focus-ring and `data-invalid` rules pre-merge.
- Custom-element focus-visible polyfill: rely on `:focus-visible` natively; confirm browser matrix in `08.46`.
- Live region strategy for toasts/alerts (`08.19`) — `role="alert"` + `aria-live="polite"` needs a single global announcer to avoid duplicate reads.

## 9. Color Contrast Deep Dive

### 9.1 AA Contrast Requirements

WCAG 2.2 AA requires minimum contrast ratios:

| Element type | Minimum ratio | Example |
| --- | --- | --- |
| Normal text (< 18px) | 4.5:1 | Body text, labels, captions |
| Large text (≥ 18px or 14px bold) | 3:1 | Headings, button text |
| UI components / icons | 3:1 | Borders, icons, focus rings |
| Decorative elements | None | Decorative borders, backgrounds |

### 9.2 GsmUi Theme Contrast Matrix

| Pair | Light mode | Ratio | Dark mode | Ratio |
| --- | --- | --- | --- | --- |
| Body text on surface | `zinc-900` on `white` | 15.4:1 | `white` on `zinc-800` | 10.3:1 |
| Secondary text on surface | `zinc-500` on `white` | 4.6:1 | `zinc-400` on `zinc-800` | 3.8:1 |
| Muted text on surface | `zinc-400` on `white` | 3.0:1 | `zinc-500` on `zinc-800` | 3.0:1 |
| Link text on surface | `blue-600` on `white` | 5.9:1 | `blue-400` on `zinc-800` | 4.7:1 |
| Icon on surface | `zinc-400` on `white` | 3.0:1 | `zinc-500` on `zinc-800` | 3.0:1 |
| Border on surface | `zinc-200` on `white` | 1.6:1 | `white/10` on `zinc-800` | 1.2:1 |
| Focus ring on surface | `blue-500` on `white` | 4.7:1 | `blue-400` on `zinc-800` | 4.7:1 |

### 9.3 Border Contrast Exception

UI component borders (e.g., `border-zinc-200`) intentionally fall below 3:1 because they serve as visual separators, not interactive indicators. The interactive affordance is communicated through other means (hover state, cursor, label). This is a common and accepted pattern in Material Design, Apple HIG, and WCAG advisory notes.

### 9.4 Contrast Testing with Playwright

```javascript
test('all text meets AA contrast', async ({ page }) => {
  await page.goto('/dashboard');
  
  const results = await page.evaluate(async () => {
    // Import axe-core for contrast checks
    const axe = await import('axe-core');
    const results = await axe.run(document, {
      rules: { 'color-contrast': { enabled: true } },
    });
    return results.violations;
  });

  expect(results).toHaveLength(0);
});
```

### 9.5 Dark Mode Contrast Adjustments

Dark mode requires different color choices because luminance relationships invert:

| Light mode | Dark mode | Rationale |
| --- | --- | --- |
| `zinc-900` text | `white` text | High contrast on dark surface |
| `zinc-600` secondary | `zinc-400` secondary | Medium contrast, not too bright |
| `zinc-400` muted | `zinc-500` muted | Just above 3:1 on dark surface |
| `white` surface | `zinc-800` surface | Not pure black (less eye strain) |
| `zinc-200` border | `white/10` border | Subtle separator, not high contrast |

## 10. Keyboard Navigation Patterns

### 10.1 Tab Order Rules

| Rule | Rationale |
| --- | --- |
| Logical left-to-right, top-to-bottom | Matches reading order in LTR languages |
| Skip hidden elements | `display: none` and `aria-hidden="true"` elements are skipped |
| Skip disabled elements | `aria-disabled="true"` or `disabled` elements are skipped |
| Skip `-1` tabindex elements | `tabindex="-1"` is programmatically focusable but not tabbable |
| Modal traps Tab | Focus cannot escape a modal dialog |
| Roving tabindex in toolbars | Arrow keys move between items; Tab moves in/out |

### 10.2 Arrow Key Patterns

| Pattern | Keys | Behavior |
| --- | --- | --- |
| Listbox / select | `↑` `↓` | Move between options |
| Menu / menubar | `↑` `↓` (vertical), `←` `→` (horizontal) | Move between items |
| Tabs | `←` `→` | Switch between tabs |
| Toolbar | `←` `→` or `↑` `↓` | Move between toolbar items |
| Grid (2D) | `↑` `↓` `←` `→` | Move in grid direction |
| Tree | `↑` `↓` (siblings), `→` (expand), `←` (collapse) | Navigate tree |

### 10.3 Home/End Key Patterns

| Context | Home | End |
| --- | --- | --- |
| Listbox | First option | Last option |
| Menu | First item | Last item |
| Grid | First cell in row | Last cell in row |
| Text input | Beginning of line | End of line |
| Tree | First node | Last visible node |

### 10.4 Escape Key Behavior

| Context | Escape action |
| --- | --- |
| Modal dialog | Close modal, return focus to trigger |
| Popover/dropdown | Close popover, return focus to trigger |
| Command palette | Close palette, return focus to trigger |
| Drawer | Close drawer, return focus to hamburger button |
| Tooltip | Dismiss tooltip |
| Multi-select | Deselect last selected item |
| Text input | Clear input (optional, component-specific) |

### 10.5 Enter/Space Behavior

| Context | Enter | Space |
| --- | --- | --- |
| Button | Activate button | Activate button |
| Link | Follow link | N/A (links don't respond to Space) |
| Checkbox | Toggle | Toggle |
| Radio | Select | N/A |
| Select/combobox | Open/close dropdown | Open/close dropdown |
| Tab | N/A | N/A (arrow keys navigate) |
| Menu item | Activate item | Activate item |

## 11. Screen Reader Patterns

### 11.1 Live Regions

GsmUi uses ARIA live regions to announce dynamic content changes:

| Pattern | `aria-live` | Use case |
| --- | --- | --- |
| Toast notifications | `polite` | Non-urgent updates |
| Error messages | `assertive` | Validation errors |
| Loading states | `polite` | "Loading complete" announcements |
| Search results count | `polite` | "5 results found" |
| Cart total change | `polite` | Price updates |

### 11.2 Global Announcer

A single live region at the root avoids duplicate announcements:

```html
<!-- In base layout -->
<div aria-live="polite" aria-atomic="true" class="sr-only"
     data-gsmui-announcer></div>

<div aria-live="assertive" aria-atomic="true" class="sr-only"
     data-gsmui-announcer-urgent></div>
```

```js
// Announce to screen readers
function announce(message, urgent = false) {
  const region = document.querySelector(
    urgent ? '[data-gsmui-announcer-urgent]' : '[data-gsmui-announcer]'
  );
  if (region) {
    region.textContent = '';
    // Force re-announcement by clearing then setting
    requestAnimationFrame(() => { region.textContent = message; });
  }
}
```

### 11.3 Landmark Regions

| Landmark | HTML element | Label |
| --- | --- | --- |
| Banner | `<header>` | None (implicit) |
| Navigation | `<nav>` | `aria-label="{{ __('Main navigation') }}"` |
| Main content | `<main>` | None (implicit) |
| Complementary | `<aside>` | `aria-label="{{ __('Sidebar') }}"` |
| Content info | `<footer>` | None (implicit) |
| Search | `<form role="search">` | None (implicit) |
| Region | `<section aria-label>` | Named sections |

### 11.4 Table Accessibility

```blade
<div class="overflow-x-auto" role="region" aria-label="{{ __('Data table') }}" tabindex="0">
    <table>
        <caption class="sr-only">{{ __('User list') }}</caption>
        <thead>
            <tr>
                <th scope="col" aria-sort="none">{{ __('Name') }}</th>
                <th scope="col" aria-sort="ascending">{{ __('Email') }} ▲</th>
            </tr>
        </thead>
        <tbody>
            <tr>
                <td>John Doe</td>
                <td>john@example.com</td>
            </tr>
        </tbody>
    </table>
</div>
```

### 11.5 Form Accessibility

```blade
<div>
    <label for="email" class="block text-sm font-medium text-zinc-700 dark:text-zinc-300">
        {{ __('Email address') }}
        <span class="text-red-500" aria-hidden="true">*</span>
    </label>
    <input id="email" type="email" required
           aria-required="true"
           aria-describedby="email-hint email-error"
           aria-invalid="{{ $errors->has('email') ? 'true' : 'false' }}" />
    <p id="email-hint" class="text-sm text-zinc-500">{{ __('We will never share your email.') }}</p>
    @error('email')
        <p id="email-error" class="text-sm text-red-500" role="alert">{{ $message }}</p>
    @enderror
</div>
```

## 12. Touch & Pointer Accessibility

### 12.1 Touch Target Sizes

WCAG 2.2 Target Size (Minimum) requires interactive targets to be at least 24×24px (Level AA). GsmUi targets 44×44px (Level AAA) for primary actions:

| Element | Minimum size | GsmUi target |
| --- | --- | --- |
| Button (default) | 44×44px | `h-10 px-4` = 40×44px |
| Button (xs) | 24×24px | `h-6 px-2` = 24px height |
| Icon button | 44×44px | `min-h-11 min-w-11` |
| Link in text | 24×24px | Inherited from line-height |
| Checkbox/Radio | 24×24px | `size-5` = 20px + padding |
| Table row | N/A | Not interactive target |

### 12.2 Pointer Input Modes

GsmUi components handle multiple pointer types:

| Input | Behavior |
| --- | --- |
| Mouse click | Standard activation |
| Mouse hover | Show tooltip, highlight row |
| Touch tap | Standard activation (no hover state) |
| Touch long-press | Context menu (where applicable) |
| Stylus | Standard activation |
| Keyboard | Standard activation (Enter/Space) |

### 12.3 Hover-Dependent Content

Content that appears on hover must also be accessible via keyboard:

```blade
{{-- Tooltip on hover AND focus --}}
<gsmui:tooltip>
    <x-slot:trigger>
        <gsmui:button aria-label="{{ __('Delete item') }}">
            <gsmui:icon name="trash" variant="micro" />
        </gsmui:button>
    </x-slot:trigger>
    {{ __('Delete this item permanently') }}
</gsmui:tooltip>
```

The tooltip appears on both `mouseenter` and `focus`, disappears on `mouseleave` and `blur`.

## 13. Reduced Motion & Animation Safety

### 13.1 Global Reduced Motion Rule

```css
@media (prefers-reduced-motion: reduce) {
  *, *::before, *::after {
    animation-duration: 0.01ms !important;
    animation-iteration-count: 1 !important;
    transition-duration: 0.01ms !important;
    scroll-behavior: auto !important;
  }
}
```

### 13.2 What Changes Under Reduced Motion

| Feature | Normal | Reduced motion |
| --- | --- | --- |
| Modal enter | Scale + fade (200ms) | Instant appear |
| Modal exit | Scale + fade (150ms) | Instant disappear |
| Tooltip | Fade (100ms) | Instant appear |
| Drawer slide | Slide (200ms) | Instant appear |
| Loading spinner | Continuous rotation | Static circle or pulse |
| Page scroll | Smooth scroll | Instant jump |
| Staggered items | 50ms stagger | All appear instantly |
| Accordion expand | Height tween (200ms) | Instant expand |
| Progress bar | Width tween (500ms) | Instant fill |
| Counter animation | Number count-up | Final number displayed |

### 13.3 Spinner Alternatives

Under reduced motion, the loading spinner must not rotate continuously:

```css
@media (prefers-reduced-motion: reduce) {
  .animate-spin {
    animation: gsmui-pulse 1.5s ease-in-out infinite;
  }

  @keyframes gsmui-pulse {
    0%, 100% { opacity: 0.4; }
    50% { opacity: 1; }
  }
}
```

This replaces the spin with a pulse, which communicates "loading" without vestibular triggers.

## 14. Internationalization & RTL

### 14.1 RTL Layout Support

GsmUi supports right-to-left (RTL) layouts via `dir="rtl"` on the `<html>` element:

```css
/* RTL-aware directional utilities */
[dir="rtl"] .gsmui-navlist-item {
  /* Border on the right instead of left */
}

[dir="rtl"] .gsmui-breadcrumb-separator {
  /* Flip chevron direction */
  transform: scaleX(-1);
}
```

### 14.2 Logical Properties

Use CSS logical properties instead of physical properties for RTL support:

| Physical | Logical | RTL-safe |
| --- | --- | --- |
| `margin-left` | `margin-inline-start` | Yes |
| `margin-right` | `margin-inline-end` | Yes |
| `padding-left` | `padding-inline-start` | Yes |
| `border-left` | `border-inline-start` | Yes |
| `text-align: left` | `text-align: start` | Yes |
| `left: 0` | `inset-inline-start: 0` | Yes |

### 14.3 Localized Aria-Labels

All `aria-label` values use `__()` for translation:

```blade
<gsmui:button aria-label="{{ __('Close') }}">
<gsmui:button aria-label="{{ __('Expand submenu') }}">
<nav aria-label="{{ __('Main navigation') }}">
<nav aria-label="{{ __('Breadcrumb') }}">
<div role="search" aria-label="{{ __('Site search') }}">
```

### 14.4 Reading Order

In RTL layouts, the visual reading order reverses but DOM order must remain logical:

```blade
{{-- This renders right-to-left in RTL --}}
<div class="flex items-center gap-2">
    <gsmui:icon name="chevron-right" />  {{-- Flips to left in RTL --}}
    <span>{{ __('Back') }}</span>
</div>
```

## 15. Accessibility Testing Strategy

### 15.1 Automated Testing (axe-core)

Run axe-core on every page to catch common violations:

```javascript
import AxeBuilder from '@axe-core/playwright';

test('dashboard page has no a11y violations', async ({ page }) => {
  await page.goto('/dashboard');
  const results = await new AxeBuilder({ page })
    .withTags(['wcag2a', 'wcag2aa', 'wcag22aa'])
    .analyze();

  expect(results.violations).toEqual([]);
});
```

### 15.2 Manual Testing Checklist

| Test | How | Frequency |
| --- | --- |---|
| Tab through entire page | Press Tab repeatedly | Every PR |
| Keyboard activate all controls | Enter/Space on every button/link | Every PR |
| Screen reader walkthrough | NVDA/VoiceOver on macOS | Every release |
| Zoom to 200% | Browser zoom, check layout | Every PR |
| Zoom to 400% | Browser zoom, check reflow | Every release |
| Windows High Contrast | Enable HC mode | Every release |
| Reduced motion | Enable in OS settings | Every PR |
| RTL layout | Set `dir="rtl"` on `<html>` | Every release |

### 15.3 Playwright A11y Tests

```javascript
test('focus ring visible on keyboard navigation', async ({ page }) => {
  await page.goto('/dashboard');
  await page.keyboard.press('Tab'); // Focus first element

  const focused = await page.evaluate(() => {
    const el = document.activeElement;
    const styles = getComputedStyle(el);
    return {
      outlineStyle: styles.outlineStyle,
      outlineWidth: styles.outlineWidth,
    };
  });

  expect(focused.outlineStyle).not.toBe('none');
  expect(parseInt(focused.outlineWidth)).toBeGreaterThanOrEqual(2);
});

test('all images have alt text', async ({ page }) => {
  await page.goto('/dashboard');
  const images = page.locator('img');
  for (const img of await images.all()) {
    await expect(img).toHaveAttribute('alt');
  }
});

test('all form inputs have labels', async ({ page }) => {
  await page.goto('/forms');
  const inputs = page.locator('input:not([type="hidden"]):not([type="submit"])');
  for (const input of await inputs.all()) {
    const hasLabel = await input.evaluate((el) => {
      return !!(
        el.labels?.length ||
        el.getAttribute('aria-label') ||
        el.getAttribute('aria-labelledby')
      );
    });
    expect(hasLabel).toBe(true);
  }
});
```

## 17. Common Accessibility Anti-Patterns

### 17.1 Div as Button

```html
<!-- ❌ WRONG: div pretending to be a button -->
<div class="btn" onclick="submit()">Submit</div>

<!-- ✅ CORRECT: native button -->
<button type="submit" class="btn">Submit</button>
```

### 17.2 Missing Alt Text

```html
<!-- ❌ WRONG: empty alt on meaningful image -->
<img src="/chart.png" alt="" />

<!-- ✅ CORRECT: descriptive alt -->
<img src="/chart.png" alt="Revenue chart showing 15% growth over Q3" />
```

### 17.3 Color-Only Indication

```html
<!-- ❌ WRONG: color is the only status indicator -->
<span class="text-red-500">Error</span>

<!-- ✅ CORRECT: color + icon + text -->
<span class="text-red-500 flex items-center gap-1">
    <gsmui:icon name="exclamation-circle" variant="micro" />
    Error
</span>
```

### 17.4 Missing Form Labels

```html
<!-- ❌ WRONG: placeholder as label -->
<input type="email" placeholder="Email" />

<!-- ✅ CORRECT: explicit label -->
<label for="email">Email</label>
<input id="email" type="email" placeholder="you@example.com" />
```

### 17.5 Inaccessible Custom Dropdown

```html
<!-- ❌ WRONG: div with click handler -->
<div class="dropdown" onclick="toggleMenu()">
    <span>Select option</span>
    <div class="menu" style="display: none">...</div>
</div>

<!-- ✅ CORRECT: ARIA listbox or use gsmui:select -->
<gsmui:select wire:model="option">
    <option value="a">Option A</option>
</gsmui:select>
```

### 17.6 Auto-Playing Media

```html
<!-- ❌ WRONG: autoplay video with sound -->
<video autoplay src="/intro.mp4"></video>

<!-- ✅ CORRECT: paused by default, user-controlled -->
<video controls preload="none" poster="/intro-poster.jpg">
    <source src="/intro.mp4" type="video/mp4" />
</video>
```

## 18. Accessibility Documentation Requirements

### 18.1 Component PRD Accessibility Section

Every component PRD must include:

## 20. Focus Management Deep Dive

### 20.1 Focus Trapping

Modal dialogs, drawers, and the command palette trap focus within their boundaries:

```js
function trapFocus(container) {
  const focusableElements = container.querySelectorAll(
    'button, [href], input, select, textarea, [tabindex]:not([tabindex="-1"])'
  );

  if (focusableElements.length === 0) return;

  const firstElement = focusableElements[0];
  const lastElement = focusableElements[focusableElements.length - 1];

  container.addEventListener('keydown', (e) => {
    if (e.key !== 'Tab') return;

    if (e.shiftKey) {
      if (document.activeElement === firstElement) {
        e.preventDefault();
        lastElement.focus();
      }
    } else {
      if (document.activeElement === lastElement) {
        e.preventDefault();
        firstElement.focus();
      }
    }
  });
}
```

### 20.2 Focus Restoration

When a modal or drawer closes, focus MUST return to the element that triggered it:

```js
function openModal(triggerElement) {
  const modal = document.querySelector('[role="dialog"]');
  modal.dataset.previousFocus = ''; // Store reference

  // Move focus to first focusable in modal
  const firstFocusable = modal.querySelector('button, input, [tabindex="0"]');
  firstFocusable?.focus();
}

function closeModal() {
  const modal = document.querySelector('[role="dialog"]');
  const trigger = document.querySelector(modal.dataset.previousFocus);
  trigger?.focus(); // Restore focus
}
```

### 20.3 Focus Management in Livewire

When Livewire replaces DOM content, focus may be lost. Use `wire:anchor` or explicit focus management:

```blade
<div wire:focus="submit">
    <x-input label="{{ __('Email') }}" wire:model="email" />
    <gsmui:button wire:click="submit">{{ __('Submit') }}</gsmui:button>
</div>
```

### 20.4 Roving Tabindex

For component groups (tab bars, toolbars, listboxes), use roving tabindex:

```text
Initial state:
  Tab 1: tabindex="0"    (tabbable)
  Tab 2: tabindex="-1"   (not tabbable)
  Tab 3: tabindex="-1"   (not tabbable)

After pressing ArrowRight on Tab 1:
  Tab 1: tabindex="-1"   (not tabbable)
  Tab 2: tabindex="0"    (tabbable — now has focus)
  Tab 3: tabindex="-1"   (not tabbable)
```

### 20.5 Focus Indicator Styles

| Element type | Focus style | Implementation |
| --- | --- | --- |
| Native `<button>` | Browser default outline | No CSS override needed |
| Native `<input>` | Browser default outline | No CSS override needed |
| Custom element (`tabindex="0"`) | `outline: 2px solid -webkit-focus-ring-color` | `has-focus-visible:outline-2` |
| Link (`<a>`) | Browser default outline | No CSS override needed |
| Tab in tab bar | `outline: 2px solid accent` | `has-focus-visible:outline-2` |

## 23. Keyboard Testing Guide

### 23.1 Keyboard-Only Test Procedure

1. Disconnect mouse / disable trackpad.
2. Navigate using only keyboard:
   - `Tab` to move forward.
   - `Shift+Tab` to move backward.
   - `Enter`/`Space` to activate.
   - `Arrow keys` for directional navigation.
   - `Escape` to close/cancel.
   - `Home`/`End` for first/last.
3. Verify every interactive element is reachable.
4. Verify every interactive element is operable.
5. Verify focus indicator is visible at all times.
6. Verify no keyboard traps (can always Tab away).

### 23.3 Keyboard Trap Testing

```javascript
test('no keyboard traps on page', async ({ page }) => {
  await page.goto('/dashboard');

  // Tab through entire page
  const focusableCount = await page.evaluate(() => {
    return document.querySelectorAll(
      'button, [href], input, select, textarea, [tabindex]:not([tabindex="-1"])'
    ).length;
  });

  // Focus should move through all elements and back to body
  for (let i = 0; i < focusableCount + 5; i++) {
    await page.keyboard.press('Tab');
  }

  // Focus should not be stuck anywhere
  const focused = await page.evaluate(() => document.activeElement.tagName);
  expect(focused).toBe('BODY'); // Or back to start
});
```

## 38. Accessibility Anti-Patterns

### 38.1 Common Anti-Patterns

| Anti-pattern | Problem | Correct approach |
| --- | --- | --- |
| `<div onclick="...">` | Not keyboard accessible | Use `<button>` |
| `tabindex="5"` | Creates unexpected tab order | Use `tabindex="0"` or `-1` |
| `role="button"` on `<div>` | Not natively focusable | Use `<button>` |
| `aria-label` on `<div>` | Not announced if no role | Add role or use native element |
| `aria-hidden="true"` on focusable | Focus goes nowhere | Remove from tab order |
| `outline: none` | Removes focus indicator | Use `focus-visible` instead |
| `title` for tooltip | Not accessible to all users | Use `gsmui:tooltip` |
| Placeholder as label | Label disappears on input | Use `gsmui:label` |
| `autocomplete="off"` | Prevents browser autofill | Use appropriate `autocomplete` value |
| Color as only indicator | Colorblind users miss meaning | Add icon or text indicator |

### 38.2 Anti-Pattern Detection

```javascript
test('no accessibility anti-patterns', async ({ page }) => {
    await page.goto('/dashboard');

    const divsWithClick = await page.$$eval('div[onclick]', (els) => els.length);
    expect(divsWithClick).toBe(0);

    const badTabindex = await page.$$eval(
        '[tabindex]:not([tabindex="0"]):not([tabindex="-1"])',
        (els) => els.map(el => ({
            tag: el.tagName,
            tabindex: el.getAttribute('tabindex'),
        }))
    );
    expect(badTabindex).toHaveLength(0);
});
```
