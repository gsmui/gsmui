# 08.54 - Storybook Strategy

**Project:** GsmUi
**Section:** 08 - Frontend Architecture
**Framework:** GsmUi Component Library · Blade Components · Playwright · Vite
**Version:** 1.0.0

---

> See also: `08.49-testing.md` (Playwright verification), `08.52-component-guidelines.md` (state matrix), `08.55-frontend-security.md` (CSP constraints). This document specifies the *component-isolation / visual-review strategy* and does NOT re-document the test runner.

# Purpose

GsmUi does not ship a Node-driven Storybook (no root `package.json`, CSP forbids external tooling). Instead, "stories" are **self-hosted Blade routes** rendered through the same `gsmui:` namespace and verified with Playwright. This document defines that CSP-safe isolation strategy, the required state matrix, and how it replaces a classic Storybook workflow.

---

## 1. Story = Isolated Blade Route

Each component gets an isolated route rendering only that component across its states — analogous to a Storybook story, but server-rendered and CSP-clean.

```blade
{{-- routes/gsmui-stories/color-picker.blade.php --}}
<gsmui:color-picker value="#0ea5e9" />
<gsmui:color-picker value="#0ea5e9" disabled />
<gsmui:color-picker value="#0ea5e9" invalid />
<gsmui:color-picker value="#0ea5e9" size="xs" />
```

No external Storybook CDN — fully `script-src 'self'` compliant.

---

## 2. Required State Matrix

Per `AGENTS.md`, every component story must cover the same baseline states before it ships:

| State | Why it matters |
| --- | --- |
| Base | default render |
| Open (popover/trigger) | interaction surface |
| Disabled | `disabled` / `[&[disabled]]` |
| Invalid | `data-invalid:` layering |
| Sizes | `default / sm / xs` height progression |
| Keyboard focus | `has-focus-visible` ring |
| Empty | white-on-white / placeholder risk |

---

## 3. Visual Verification with Playwright

Stories are the subjects of the mandatory Playwright pass (`08.49-testing.md`):

- Screenshot each state after any CSS change.
- Measure pixel gaps with Playwright rather than guessing (`pe-[9px]` magic numbers allowed only when no Tailwind value fits).
- Assert zero console errors and correct ARIA (`role="combobox"`, `aria-haspopup="dialog"`).

---

## 4. Why Not Classic Storybook

| Concern | Classic Storybook | GsmUi approach |
| --- | --- | --- |
| External deps | Requires CDN/npm runtime | Zero external (CSP) |
| Build config | Needs root tooling | None in repo (`08.51`) |
| Fidelity | Separate React-style env | Real `gsmui:` + `dist/` |

---

## 5. Open Questions / Risks

- **Story route hygiene:** ensure story routes are excluded from production/sitemap (`08.47`).
- **State combinator explosion:** for components with many props, define a minimal representative matrix rather than every combination (punt semi-aggressively, `AGENTS.md`).
- **Dark-mode stories:** add `.dark` variants to the matrix so theme parity is verified (`08.43`).

# 6. Story Route Generation

Each component story route is auto-generated from the component registry. The docs engine scans `stubs/resources/views/gsmui/` and produces a story route for every component found.

### 6.1 Route Definition

```php
// routes/gsmui-stories.php
Route::prefix('gsmui-stories')->group(function () {
    Route::get('/{component}', [StoryController::class, 'show'])
        ->where('component', '[a-z0-9\-]+')
        ->name('gsmui.story');
});
```

### 6.2 Story Controller

```php
class StoryController extends Controller
{
    public function show(string $component)
    {
        // Resolve the component view
        $view = "gsmui::{$component}.story";

        if (!view()->exists($view)) {
            abort(404);
        }

        return view($view, [
            'component' => $component,
            'states' => $this->getStatesForComponent($component),
        ]);
    }

    private function getStatesForComponent(string $component): array
    {
        return match ($component) {
            'button' => ['base', 'sizes', 'variants', 'disabled', 'loading'],
            'input' => ['base', 'sizes', 'disabled', 'invalid', 'with-label', 'with-placeholder'],
            'select' => ['base', 'sizes', 'disabled', 'invalid', 'searchable', 'multiple'],
            'date-picker' => ['base', 'sizes', 'disabled', 'invalid', 'with-value', 'range'],
            'color-picker' => ['base', 'sizes', 'disabled', 'invalid', 'with-swatches', 'formats'],
            'modal' => ['base', 'sizes', 'scrollable', 'form'],
            'table' => ['base', 'sortable', 'paginated', 'selectable', 'empty', 'loading'],
            'toast' => ['base', 'types', 'dismissible', 'with-actions'],
            default => ['base', 'disabled', 'invalid', 'sizes'],
        };
    }
}
```

### 6.3 Story View Template

```blade
{{-- resources/views/gsmui/{$component}/story.blade.php --}}
@extends('gsmui::layouts.story')

@section('story-content')
    <div class="max-w-6xl mx-auto px-8 py-12">
        <h1 class="text-2xl font-bold text-zinc-900 dark:text-white mb-8">
            {{ ucfirst(str_replace('-', ' ', $component)) }} — Storybook
        </h1>

        @foreach ($states as $state)
            <section class="mb-12">
                <h2 class="text-lg font-semibold text-zinc-700 dark:text-zinc-300 mb-4">
                    {{ ucfirst(str_replace('-', ' ', $state)) }}
                </h2>

                <div class="p-6 rounded-xl border border-zinc-200 dark:border-white/10 bg-white dark:bg-zinc-800">
                    @include("gsmui::{$component}.stories.{$state}")
                </div>
            </section>
        @endforeach
    </div>
@endsection
```

# 7. Story File Convention

Each component has a `stories/` directory containing one Blade file per state. These files render only `gsmui:` tags — no test scaffolding, no dev-only wrappers.

### 7.1 Example: Button Stories

```
├── index.blade.php          # Production component
└── stories/
```

# 9. Playwright Story Verification

Stories are the primary subjects of Playwright visual verification. Each story state gets a screenshot test.

### 9.1 Screenshot Test Per State

```javascript
// tests/Browser/stories/button.spec.js
const { test, expect } = require('@playwright/test');

const states = ['base', 'sizes', 'variants', 'disabled', 'loading'];

test.describe('Button stories', () => {
    states.forEach(state => {
        test(`button ${state} state renders correctly`, async ({ page }) => {
            await page.goto(`/gsmui-stories/button`);
            const section = page.locator(`text=${state}`).first();
            await expect(section).toBeVisible();

            // Screenshot the specific state section
            const stateSection = section.locator('..').locator('.p-6').first();
            await expect(stateSection).toHaveScreenshot(`button-${state}.png`);
        });
    });
});
```

### 9.2 Dark Mode Screenshot Test

```javascript
test('button renders correctly in dark mode', async ({ page }) => {
    await page.goto('/gsmui-stories/button');
    await page.evaluate(() => document.documentElement.classList.add('dark'));
    await page.waitForTimeout(100); // Allow theme transition

    await expect(page.locator('.p-6').first()).toHaveScreenshot('button-dark.png');
});
```

### 9.3 Pixel Measurement Test

```javascript
test('button sizes match expected heights', async ({ page }) => {
    await page.goto('/gsmui-stories/button');

    const defaultBtn = page.locator('button:has-text("Default")').first();
    const smBtn = page.locator('button:has-text("Small")').first();
    const xsBtn = page.locator('button:has-text("Extra Small")').first();

    // Expected: default=40px, sm=32px, xs=24px
    await expect(defaultBtn).toHaveCSS('height', '40px');
    await expect(smBtn).toHaveCSS('height', '32px');
    await expect(xsBtn).toHaveCSS('height', '24px');
});
```

### 9.4 ARIA Verification Test

```javascript
test('button has correct ARIA attributes', async ({ page }) => {
    await page.goto('/gsmui-stories/button');

    const buttons = page.locator('button.gsmui-button');
    const count = await buttons.count();

    for (let i = 0; i < count; i++) {
        const btn = buttons.nth(i);
        // Verify button role is native
        await expect(btn).toHaveJSProperty('tagName', 'BUTTON');
    }
});
```

### 9.5 Focus-Visible Test

```javascript
test('button shows focus-visible ring on keyboard focus', async ({ page }) => {
    await page.goto('/gsmui-stories/button');

    const btn = page.locator('button:has-text("Default")').first();
    await btn.focus();

    // Verify focus-visible styles are applied
    await expect(btn).toHaveCSS('outline-style', 'solid');
});
```

### 9.6 Complete Story Verification Suite

```javascript
// tests/Browser/stories/verify-all.spec.js
const { test, expect } = require('@playwright/test');
const fs = require('fs');
const path = require('path');

// Auto-discover all story routes
const storyDir = path.join(__dirname, '../../../stubs/resources/views/gsmui');
const components = fs.readdirSync(storyDir).filter(f => {
    return fs.statSync(path.join(storyDir, f)).isDirectory()
        && fs.existsSync(path.join(storyDir, f, 'stories'));
});

test.describe('All component stories', () => {
    components.forEach(component => {
        test(`${component} story renders without errors`, async ({ page }) => {
            const errors = [];
            page.on('console', msg => {
                if (msg.type() === 'error') errors.push(msg.text());
            });

            await page.goto(`/gsmui-stories/${component}`);
            await page.waitForLoadState('networkidle');

            // Verify no console errors
            expect(errors).toHaveLength(0);

            // Verify page has content
            const content = await page.textContent('body');
            expect(content.length).toBeGreaterThan(0);

            // Screenshot the full story page
            await expect(page).toHaveScreenshot(`${component}-story.png`);
        });
    });
});
```

# 10. Component State Matrix — Complete Reference

Every component must have stories covering these states. The matrix drives both visual review and Playwright testing.

### 10.1 Universal States

| State | Description | CSS class / attribute | Why it matters |
| --- | --- | --- | --- |
| Base | Default render with no optional props | — | Establishes visual baseline |
| Disabled | `disabled` attribute or `[&[disabled]]` | `disabled`, `[&[disabled]]:shadow-none!` | Verifies disabled styling + pointer-events |
| Invalid | `data-invalid:` layering | `data-invalid:` | Verifies error state doesn't break layout |
| Sizes | `default / sm / xs` height progression | `h-10 / h-8 / h-6` | Verifies size system consistency |
| Keyboard focus | `has-focus-visible` ring | `has-focus-visible:outline-2` | Verifies accessible focus indicator |
| Empty | No content / placeholder | — | Catches white-on-white / invisible states |

### 10.2 Trigger/Popover Components

| State | Description | ARIA pattern |
| --- | --- | --- |
| Base (closed) | Trigger only, popover hidden | `role="combobox"` or `aria-haspopup="dialog"` |
| Open | Popover/dropdown visible | `aria-expanded="true"` |
| Disabled trigger | Trigger is non-interactive | `aria-disabled="true"` |
| Invalid trigger | Error state on trigger | `data-invalid` |

### 10.3 Form Components

| State | Description | Verification |
| --- | --- | --- |
| Base | Empty input with placeholder | Placeholder text visible |
| With value | Pre-filled value | Value displayed correctly |
| Focused | Input has focus | Focus ring visible |
| Disabled | Non-interactive | Grayed out, no pointer events |
| Invalid | Error state | Red border, error message |
| Sizes | default / sm / xs | Height + text size progression |

### 10.4 Data Display Components

| State | Description | Verification |
| --- | --- | --- |
| Base | Normal data render | Data visible, correct alignment |
| Empty | No data | Empty state message/slot |
| Loading | Data is loading | Loading indicator visible |
| Overflow | Data exceeds container | Truncation or scroll |

### 10.5 Feedback Components

| State | Description | Verification |
| --- | --- | --- |
| Base | Default appearance | Visible, correct color |
| Variants | success / warning / error / info | Color differentiation |
| Dismissible | Close button visible | Click dismisses |
| With action | Action button present | Button clickable |
| Auto-dismiss | Timer-based dismissal | Disappears after timeout |

# 14. Story Performance Budget

Stories themselves must be lightweight. They are development tools, not production pages.

### 14.1 Story Page Budget

| Metric | Target | Tool |
| --- | --- | --- |
| Page weight (HTML) | < 10KB | `wc -c` on rendered HTML |
| Component count per story | < 20 | Manual count |
| External requests | 0 (self-hosted) | Network tab |
| Console errors | 0 | `browser_console_messages` |
| Time to interactive | < 500ms | Playwright |

### 14.2 Story Route Exclusion

Story routes must be excluded from production:

```php
// routes/web.php
if (app()->environment('local', 'testing')) {
    require __DIR__ . '/gsmui-stories.php';
}
```

### 14.3 Sitemap Exclusion

Story routes are excluded from the sitemap:

```php
// In the sitemap generator
$sitemap->remove('/gsmui-stories/*');
```

# 16. Story Generation Artisan Command

### 16.1 Generate Story for a Component

```bash
php artisan gsmui:story:generate button
```

This command:
1. Reads the component's Blade template for available props
2. Generates a `stories/` directory with state files
3. Creates a story route entry
4. Generates Playwright test scaffolding

### 16.2 Generate All Stories

```bash
php artisan gsmui:story:generate --all
```

### 16.3 Story Generation Template

```php
// app/Console/Commands/GenerateStory.php
class GenerateStory extends Command
{
    protected $signature = 'gsmui:story:generate {component?} {--all}';

    public function handle(): void
    {
        if ($this->option('all')) {
            $components = $this->discoverComponents();
        } else {
            $components = [$this->argument('component')];
        }

        foreach ($components as $component) {
            $this->generateStory($component);
        }
    }

    private function generateStory(string $component): void
    {
        $storyDir = resource_path("views/gsmui/{$component}/stories");
        $states = $this->getDefaultStates($component);

        foreach ($states as $state) {
            $stub = $this->getStub($state);
            $content = $this->fillStub($stub, $component, $state);

            file_put_contents(
                "{$storyDir}/{$state}.blade.php",
                $content
            );
        }

        $this->info("Story generated for {$component}");
    }
}
```

# 17. Story CI Integration

### 17.1 CI Pipeline for Stories

```yaml
# .github/workflows/stories.yml
name: Story Verification

on:
  push:
    branches: [main]
    paths:
      - 'stubs/resources/views/gsmui/**'
      - 'dist/**'

jobs:
  verify-stories:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - name: Setup PHP

        with:
          php-version: '8.3'

      - name: Install dependencies
        run: composer install

      - name: Start server
        run: php artisan serve --port=8000 &

      - name: Wait for server
        run: sleep 5

      - name: Run Playwright story tests

      - name: Upload screenshots
        if: failure()
```

# 18. Story Workflow

### 18.1 Development Workflow

1. **Create component** in `stubs/resources/views/gsmui/{component}/index.blade.php`
2. **Generate story** via `php artisan gsmui:story:generate {component}`
3. **Open story** at `/gsmui-stories/{component}`
4. **Verify states** visually in browser (light + dark mode)
5. **Run Playwright** to capture screenshots and verify ARIA
6. **Fix issues** found during visual review
7. **Commit** story files alongside component files

### 18.2 Review Workflow

1. **PR includes story files** — reviewers can see all states
2. **CI runs Playwright** — screenshots are captured and compared
3. **Reviewer checks screenshots** — visual parity is verified
4. **Merge** — story files are part of the codebase

### 18.3 Release Workflow

1. **All stories pass** — CI is green
2. **Story routes excluded from production** — no dev tools in prod
3. **Screenshots archived** — for historical reference

# 19. Story Anti-Patterns

### 19.1 Don't Put Test Logic in Stories

```blade
{{-- BAD: Test scaffolding in story --}}
<div data-test="button-state">
    @if($isDisabled)
        <gsmui:button disabled>Disabled</gsmui:button>
    @else
        <gsmui:button>Enabled</gsmui:button>
    @endif
</div>

{{-- GOOD: Pure component render --}}
<gsmui:button disabled>Disabled</gsmui:button>
```

### 19.2 Don't Use Mock Data

```blade
{{-- BAD: Mock data in story --}}
@gsmui:button wire:click="submit({{ json_encode($mockData) }})">Submit</gsmui:button>

{{-- GOOD: Real component usage --}}
<gsmui:button>Submit</gsmui:button>
```

### 19.3 Don't Add External Dependencies

```blade
{{-- BAD: External CDN in story --}}
<script src="https://cdn.example.com/chart.js"></script>

{{-- GOOD: Self-hosted only --}}
<script defer src="/dist/gsmui.js"></script>
```

### 19.4 Don't Ship Scaffolding Sections

Per AGENTS.md: "Remove all scaffolding/testing sections before shipping. This is a launch blocker."

Stories must not contain:
- Test IDs (`data-test`)
- Debug output
- Console.log statements
- Development-only wrappers

# 21. Story Accessibility Verification

### 21.1 ARIA Attribute Audit

Every story is audited for correct ARIA attributes:

```javascript
test('button story has correct ARIA', async ({ page }) => {
    await page.goto('/gsmui-stories/button');

    // Native buttons don't need role="button"
    const buttons = page.locator('button.gsmui-button');
    for (const btn of await buttons.all()) {
        await expect(btn).toHaveJSProperty('tagName', 'BUTTON');
    }
});
```

### 21.2 Keyboard Navigation Test

```javascript
test('select story is keyboard navigable', async ({ page }) => {
    await page.goto('/gsmui-stories/select');

    // Focus the trigger
    await page.keyboard.press('Tab');
    await page.keyboard.press('Enter'); // Open dropdown

    // Navigate options
    await page.keyboard.press('ArrowDown');
    await page.keyboard.press('ArrowDown');
    await page.keyboard.press('Enter'); // Select option

    // Verify selection
    await expect(page.locator('[role="listbox"]')).not.toBeVisible();
});
```

### 21.3 Screen Reader Test

```javascript
test('modal story has correct screen reader announcements', async ({ page }) => {
    await page.goto('/gsmui-stories/modal');

    await page.click('[data-test="open-modal"]');
    const dialog = page.locator('[role="dialog"]');

    // Verify aria-label
    await expect(dialog).toHaveAttribute('aria-label');

    // Verify aria-modal
    await expect(dialog).toHaveAttribute('aria-modal', 'true');
});
```

### 21.4 Color Contrast Test

```javascript
test('button story meets color contrast requirements', async ({ page }) => {
    await page.goto('/gsmui-stories/button');

    const btn = page.locator('button:has-text("Default")').first();
    const color = await btn.evaluate(el => {
        const style = window.getComputedStyle(el);
        return {
            color: style.color,
            backgroundColor: style.backgroundColor,
        };
    });

    // Verify contrast ratio >= 4.5:1
    const ratio = calculateContrastRatio(color.color, color.backgroundColor);
    expect(ratio).toBeGreaterThanOrEqual(4.5);
});
```

# 26. Story Comparison with External Tools

### 26.1 GsmUi Stories vs Storybook (React)

| Feature | Storybook (React) | GsmUi Stories |
| --- | --- | --- |
| Framework | React-specific | Blade/Livewire |
| Runtime | Node.js dev server | Laravel routes |
| CSP | External CDN deps | Fully self-hosted |
| Build config | Required | None |
| Fidelity | Separate rendering env | Real production components |
| Testing | Chromatic / Playwright | Playwright only |
| Dark mode | Addon-based | Built-in |
| Interactive controls | Args/Controls | Manual state files |
| Docs generation | Auto from JSDoc | Manual Blade templates |

### 26.2 GsmUi Stories vs Ladle (React)

| Feature | Ladle | GsmUi Stories |
| --- | --- | --- |
| Speed | Fast (esbuild) | Fast (server-rendered) |
| Bundle | Single entry point | Per-component routes |
| Config | `ladle.config.ts` | Zero config |
| Story format | CSF (JS/TS) | Blade templates |
| Testing | Playwright | Playwright |

### 26.3 GsmUi Stories vs Histoire (Vue)

| Feature | Histoire | GsmUi Stories |
| --- | --- | --- |
| Framework | Vue-specific | Blade/Livewire |
| State management | Vue reactivity | Blade props |
| Testing | Vitest + Playwright | Playwright only |
| Build | Vite-based | No build step |

### 26.4 Why GsmUi's Approach Fits

GsmUi's story system is purpose-built for its constraints:
1. **CSP compliance** — no external deps, no eval, no CDN
2. **Server-rendered** — stories are real Blade routes, not client-side rendering
3. **Zero config** — no `package.json` at root, no build tooling in repo
4. **Production fidelity** — stories use the same `gsmui:` namespace as production
5. **Livewire integration** — stories can include `wire:model` bindings

# 27. Story System Architecture

### 27.1 Architecture Diagram

```
┌─────────────────────────────────────────────────────┐
│                  Story System                        │
│                                                     │
│  ┌──────────────┐    ┌──────────────┐               │
│  │  Artisan     │    │  Route       │               │
│  │  Generator   │───▶│  Registration│               │
│  └──────────────┘    └──────┬───────┘               │
│                             │                       │
│                             ▼                       │
│  ┌──────────────┐    ┌──────────────┐               │
│  │  Story       │    │  Story       │               │
│  │  Controller  │───▶│  Views       │               │
│  └──────────────┘    └──────┬───────┘               │
│                             │                       │
│                             ▼                       │
│  ┌──────────────┐    ┌──────────────┐               │
│  │  gsmui:      │    │  Playwright  │               │
│  │  Components  │───▶│  Tests       │               │
│  └──────────────┘    └──────────────┘               │
│                                                     │
└─────────────────────────────────────────────────────┘
```

### 27.2 Data Flow

1. **Generator** creates story files from component metadata
2. **Route registration** maps `/gsmui-stories/{component}` to controller
3. **Controller** resolves the story view and states
4. **Story views** render `gsmui:` components across states
5. **Playwright** verifies visual appearance and accessibility

# 37. Story Best Practices

### 37.1 Do

- Keep stories simple — one component per story file
- Use real `gsmui:` components, not mockups
- Include all required states from the state matrix
- Test in both light and dark modes
- Verify ARIA attributes with Playwright
- Keep stories self-contained (no external deps)

### 37.2 Don't

- Put test scaffolding in stories
- Use mock data or fixtures
- Add external CDN scripts
- Include `data-test` attributes
- Ship scaffolding sections
- Skip dark mode verification
- Forget to exclude stories from production

### 37.3 Story File Size

| Metric | Target |
| --- | --- |
| Lines per story file | < 50 |
| Components per story | < 10 |
| Story page total weight | < 10KB HTML |

# 39. Open Questions / Risks

- **Story route hygiene:** ensure story routes are excluded from production/sitemap (`08.47`).
- **State combinator explosion:** for components with many props, define a minimal representative matrix rather than every combination (punt semi-aggressively, `AGENTS.md`).
- **Dark-mode stories:** add `.dark` variants to the matrix so theme parity is verified (`08.43`).
- **Story screenshot storage:** decide whether screenshots are stored in the repo or as CI artifacts.
- **Story route prefix:** confirm `/gsmui-stories/` doesn't conflict with existing routes.
- **Story page caching:** confirm story pages are not cached in production (dev-only routes).
- **Story iframe embedding:** confirm iframe embedding works with CSP (`frame-src` directive).
- **Story generation stubs:** decide whether story stubs are generated from component metadata or manually maintained.
- **Story CI run time:** confirm Playwright story tests complete within CI budget (< 5 minutes).
- **Story screenshot diffing:** decide on pixel-diff threshold for visual regression (0.1%? 1%?).
- **Story dark mode toggle:** confirm the dark mode toggle works with the host app's theme system.
- **Story locale testing:** confirm story locale switching works with the i18n system (`08.45`).
- **Story accessibility audit:** confirm all stories pass axe-core accessibility audit.
- **Story responsive testing:** consider adding viewport size variants to the story matrix.
- **Story interaction coverage:** decide which interactions to test in Playwright vs. manual review.
