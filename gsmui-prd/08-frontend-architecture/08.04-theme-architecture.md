# 08.04 - Theme Architecture

**Project:** GsmUi
**Section:** 08 - Frontend Architecture
**Framework:** Design Token Engine · CSS Variables · Tailwind CSS v4 · Livewire 4
**Version:** 1.0.0

---

> See also: `05.16-theme-engine.md` (theme generation), `06.31-theme-tokens.md` (token persistence), `08.03-design-tokens.md` (token taxonomy). This document specifies the *runtime theme model and builder data flow* and does NOT re-document token schema.

# Purpose

This document defines how a theme is modeled at runtime, how light/dark modes are selected, how the visual theme builder pushes changes to the live preview, and the boundary between *design tokens* (authoring-time, in the engine) and *runtime tokens* (the `--gsmui-*` values applied to the DOM). It gives implementers a single contract for theme switching and preview.

---

## 1. Theme Model

A theme is a named, persisted set of resolved token values. The browser only ever sees runtime tokens; the engine owns design tokens.

| Concept | Owner | Lifetime |
| --- | --- | --- |
| Design tokens | Token Engine (`05.16-theme-engine.md`) | Authoring/compile time |
| Runtime tokens | `--gsmui-*` on `:root` / `adoptedStyleSheets` | Applied at render + preview |
| Active theme id | Persisted (`06.31-theme-tokens.md`) | Session + user preference |

```text
Theme (DB) ──resolve──▶ Design Tokens ──compile──▶ Runtime Tokens (--gsmui-*) ──apply──▶ DOM
```

---

## 2. Light / Dark Selection

Mode is selected by a scope attribute, not a class toggle on every element. Components read tokens; they don't branch on mode.

| Mechanism | Rule |
| --- | --- |
| Scope | `:root[data-theme="dark"]` or `.dark` on `<html>` |
| Default | System preference via `prefers-color-scheme` when no explicit choice |
| Persistence | Stored user choice overrides system; emitted before paint to avoid FOUC |
| Tailwind | `dark:` variant bound to the scope attribute (see `08.06-css-architecture.md`) |

---

## 3. Theme Builder Data Flow

The visual builder (`05.16-theme-engine.md`, `08.25-theme-builder-ui.md`) updates the live preview without a round-trip per keystroke.

```text
Builder control (Livewire) ──wire:model──▶ Token value
        │                                        │
        ▼                                        ▼
   (debounced) ──▶ resolve token ──▶ push --gsmui-* via adoptedStyleSheets
        │
        ▼
   Optional "Save" ──▶ persist to 06.31-theme-tokens.md schema
```

Contract:

- Preview updates use `adoptedStyleSheets` (`08.06-css-architecture.md`) — never inline `<style>` tags (CSP-safe per AGENTS.md).
- Persistence is explicit (Save action), not automatic on every change.
- Invalid token values silently revert — no shake animations, no error toasts (AGENTS.md "Accept pragmatic imperfections").

---

## 4. Design Tokens vs Runtime Tokens

| Aspect | Design Tokens | Runtime Tokens |
| --- | --- | --- |
| Form | Semantic scales, references, aliases | Flat `--gsmui-*` custom properties |
| Mutability | Engine-owned, versioned | Replaced wholesale on theme switch |
| Consumer | Token Engine, builder | All `gsmui:` components + Tailwind `@theme` |
| Storage | `06.31-theme-tokens.md` | `:root` / `adoptedStyleSheets` |

Rule: components and pages MUST consume runtime tokens (CSS variables / Tailwind utilities bound to them). They MUST NOT read design-token JSON directly.

---

## 5. Theme Switching Contract

| Step | Action |
| --- | --- |
| 1 | Fetch resolved runtime token map for target theme |
| 2 | Replace `:root` `--gsmui-*` set (or swap `adoptedStyleSheets` entry) |
| 3 | Toggle scope attribute for dark/light |
| 4 | Re-evaluate `color-scheme` for native form controls |

No full page reload is required; switching is instant and hydration-safe under Livewire 4 (`08.08-livewire-architecture.md`).

### 7.2 Theme Resolution Process

The theme resolution process transforms design tokens into runtime tokens:

```text
1. Load theme definition (from DB or JSON file)
2. Resolve all token references (palette → semantic → component)
3. Validate all token values (color, spacing, etc.)
4. Generate CSS custom properties
5. Inject into DOM via adoptedStyleSheets
```

| Step | Input | Output | Time |
| --- | --- | --- | --- |
| Load | Theme ID | Theme definition | < 10ms |
| Resolve | Design tokens | Flat token map | < 5ms |
| Validate | Token map | Validated map | < 5ms |
| Generate | Validated map | CSS string | < 5ms |
| Inject | CSS string | DOM update | < 5ms |

### 7.3 Theme Storage

| Storage | Use Case | Lifetime |
| --- | --- | --- |
| Database | User-created themes | Permanent |
| JSON file | Default/bundled themes | App lifetime |
| localStorage | Theme preference | Session |
| Cookie | Server-side detection | 1 year |

## 8. Light/Dark Mode Implementation

### 8.1 Mode Selection Priority

```text
1. User explicit choice (stored in DB/localStorage)
   │
   ├── If found → apply user choice
   │
   ▼
2. System preference (prefers-color-scheme)
   │
   ├── If dark → apply dark theme
   │
   ▼
3. Default theme (light)
   │
   └── Apply light theme
```

### 8.2 Mode Detection Code

```js
// Conceptual: Mode detection (lives in dist/gsmui.js)
function detectThemeMode() {
    // 1. Check localStorage
    const stored = localStorage.getItem("gsmui-theme-mode");
    if (stored) return stored;

    // 2. Check system preference
    if (window.matchMedia("(prefers-color-scheme: dark)").matches) {
        return "dark";
    }

    // 3. Default
    return "light";
}
```

### 8.3 Mode Switching

```js
function switchThemeMode(mode) {
    // 1. Update localStorage
    localStorage.setItem("gsmui-theme-mode", mode);

    // 2. Update DOM attribute
    document.documentElement.setAttribute("data-theme", mode);

    // 3. Update color-scheme
    document.documentElement.style.colorScheme = mode;

    // 4. Dispatch event for components
    window.dispatchEvent(new CustomEvent("gsmui:theme-changed", {
        detail: { mode }
    }));
}
```

### 8.4 System Preference Monitoring

```js
// Watch for system preference changes
window.matchMedia("(prefers-color-scheme: dark)")
    .addEventListener("change", (e) => {
        if (!localStorage.getItem("gsmui-theme-mode")) {
            const mode = e.matches ? "dark" : "light";
            document.documentElement.setAttribute("data-theme", mode);
        }
    });
```

### 9.4 Builder Undo/Redo

```js
// Conceptual: Theme builder state management
class ThemeBuilderState {
    constructor() {
        this.history = [];
        this.currentIndex = -1;
    }

    push(state) {
        this.history = this.history.slice(0, this.currentIndex + 1);
        this.history.push(state);
        this.currentIndex++;
    }

    undo() {
        if (this.currentIndex > 0) {
            this.currentIndex--;
            return this.history[this.currentIndex];
        }
        return null;
    }

    redo() {
        if (this.currentIndex < this.history.length - 1) {
            this.currentIndex++;
            return this.history[this.currentIndex];
        }
        return null;
    }
}
```

## 10. Theme Persistence

### 10.1 Persistence Strategy

| Data | Storage | Sync |
| --- | --- | --- |
| Theme definition | Server DB | On save |
| Active theme ID | localStorage + DB | On switch |
| Mode preference | localStorage + cookie | On toggle |
| Custom tokens | Server DB | On save |

### 10.2 Persistence Code

```js
// Save theme preference
function saveThemePreference(themeId, mode) {
    // Client-side (immediate)
    localStorage.setItem("gsmui-theme-id", themeId);
    localStorage.setItem("gsmui-theme-mode", mode);

    // Server-side (async)
    fetch("/api/theme/preference", {
        method: "POST",
        headers: { "Content-Type": "application/json" },
        body: JSON.stringify({ themeId, mode }),
    });
}

// Load theme preference
function loadThemePreference() {
    return {
        themeId: localStorage.getItem("gsmui-theme-id") || "default",
        mode: localStorage.getItem("gsmui-theme-mode") || "system",
    };
}
```

### 10.3 Persistence Conflict Resolution

| Conflict | Resolution |
| --- | --- |
| localStorage vs DB | DB wins (server is source of truth) |
| User choice vs system | User choice wins |
| Theme not found | Fall back to default theme |
| Token undefined | Use Tailwind default value |

## 11. Scoped Theming

### 11.1 Global Theme

The default theme applies to the entire page:

```css
:root {
    --gsmui-color-bg: #ffffff;
    --gsmui-color-accent: #2563eb;
}
```

### 11.2 Section Theme Override

For sections that need different theming (e.g., embedded playground):

```css
/* Override theme for a specific section */
[data-theme="dark"] .gsmui-playground {
    --gsmui-color-bg: #0a0a0a;
    --gsmui-color-surface: #1a1a1a;
}
```

### 11.3 Scoped Theme Implementation

```blade
{{-- Section with its own theme --}}
<div data-theme="dark" class="gsmui-playground">
    {{-- This section uses dark theme regardless of global theme --}}
    <gsmui:input wire:model="code" />
    <gsmui:button>Run</gsmui:button>
</div>
```

### 11.4 Scoped Theme Rules

| Rule | Implementation |
| --- | --- |
| Use `data-theme` attribute | `data-theme="dark"` on container |
| Inherit from parent | No token redefinition needed |
| Override specific tokens | Only redefine changed tokens |
| Isolate with containment | `contain: layout style paint` |

## 14. Theme Security

### 14.1 Token Validation

All token values are validated before injection:

```php
function validateToken($name, $value) {
    // Color tokens must be valid CSS color
    if (str_contains($name, 'color')) {
        $validated = validateColor($value);
        if (!$validated) return getDefaultValue($name);
        return $validated;
    }

    // Spacing tokens must be valid CSS length
    if (str_contains($name, 'space')) {
        $validated = validateLength($value);
        if (!$validated) return getDefaultValue($name);
        return $validated;
    }

    return $value;
}
```

### 14.2 Injection Prevention

| Attack Vector | Protection |
| --- | --- |
| CSS injection via token | Validate all token values |
| XSS via token name | Sanitize token names |
| Overwrite critical tokens | Blocklist critical tokens from user override |
| Excessive token count | Limit token count per theme |

### 14.3 CSP Compliance

| Requirement | Implementation |
| --- | --- |
| No inline styles | Use `adoptedStyleSheets` |
| No `eval()` | Standard JS only |
| No external resources | All tokens self-hosted |
| No `Function()` | Standard functions only |

## 16. Theme Accessibility

### 16.1 Contrast Requirements

All theme token pairs must meet WCAG 2.2 AA contrast ratios:

| Text Size | Minimum Ratio | Token Examples |
| --- | --- | --- |
| Normal text (< 24px) | 4.5:1 | `color-text` on `color-bg` |
| Large text (≥ 24px) | 3:1 | `text-2xl` headings on `color-bg` |
| UI components | 3:1 | `color-border` on `color-bg` |
| Focus indicators | 3:1 | `color-accent` focus ring on `color-bg` |

### 16.2 Color Independence

Themes must not rely on color alone:

| Scenario | Requirement |
| --- | --- |
| Error state | Red border + error icon + error text |
| Success state | Green checkmark + success text |
| Required field | Asterisk + "required" text |
| Disabled state | Reduced opacity + `aria-disabled` |

### 16.3 High Contrast Mode

Themes should work in Windows High Contrast Mode:

```css
@media (forced-colors: active) {
    :root {
        --gsmui-color-accent: Highlight;
        --gsmui-color-text: CanvasText;
        --gsmui-color-bg: Canvas;
    }
}
```

## 20. Theme Architecture Decisions

### 20.1 Why CSS Custom Properties

| Reason | Benefit |
| --- | --- |
| Runtime updates | Live theme preview without reload |
| Cascade integration | Works with Tailwind utilities |
| Browser native | Zero-cost reads |
| CSP compatible | No JavaScript for styling |

### 20.2 Why Scope Attribute for Dark Mode

| Reason | Benefit |
| --- | --- |
| Granular control | Can scope to specific elements |
| No class toggling | Attribute change only |
| Server rendering | Easy to set on initial HTML |
| CSS integration | Works with `@custom-variant` |

### 20.3 Why `adoptedStyleSheets` for Runtime

| Reason | Benefit |
| --- | --- |
| CSP safe | No inline `<style>` needed |
| Performance | Single DOM operation |
| Atomic updates | `replaceSync()` for instant changes |
| Memory efficient | Sheet reference, not DOM nodes |

## 23. Light/Dark Mode Implementation

### 23.1 Mode Selection Priority

```text
1. User explicit choice (stored in DB/localStorage)
   │
   ├── If found → apply user choice
   │
   ▼
2. System preference (prefers-color-scheme)
   │
   ├── If dark → apply dark theme
   │
   ▼
3. Default theme (light)
   │
   └── Apply light theme
```

### 23.2 Mode Detection Code

```js
// Conceptual: Mode detection (lives in dist/gsmui.js)
function detectThemeMode() {
    // 1. Check localStorage
    const stored = localStorage.getItem("gsmui-theme-mode");
    if (stored) return stored;

    // 2. Check system preference
    if (window.matchMedia("(prefers-color-scheme: dark)").matches) {
        return "dark";
    }

    // 3. Default
    return "light";
}
```

### 23.3 Mode Switching

```js
function switchThemeMode(mode) {
    // 1. Update localStorage
    localStorage.setItem("gsmui-theme-mode", mode);

    // 2. Update DOM attribute
    document.documentElement.setAttribute("data-theme", mode);

    // 3. Update color-scheme
    document.documentElement.style.colorScheme = mode;

    // 4. Dispatch event for components
    window.dispatchEvent(new CustomEvent("gsmui:theme-changed", {
        detail: { mode }
    }));
}
```

### 23.4 System Preference Monitoring

```js
// Watch for system preference changes
window.matchMedia("(prefers-color-scheme: dark)")
    .addEventListener("change", (e) => {
        if (!localStorage.getItem("gsmui-theme-mode")) {
            const mode = e.matches ? "dark" : "light";
            document.documentElement.setAttribute("data-theme", mode);
        }
    });
```

### 24.4 Builder Undo/Redo

```js
// Conceptual: Theme builder state management
class ThemeBuilderState {
    constructor() {
        this.history = [];
        this.currentIndex = -1;
    }

    push(state) {
        this.history = this.history.slice(0, this.currentIndex + 1);
        this.history.push(state);
        this.currentIndex++;
    }

    undo() {
        if (this.currentIndex > 0) {
            this.currentIndex--;
            return this.history[this.currentIndex];
        }
        return null;
    }

    redo() {
        if (this.currentIndex < this.history.length - 1) {
            this.currentIndex++;
            return this.history[this.currentIndex];
        }
        return null;
    }
}
```

## 29. Theme Security

### 29.1 Token Validation

All token values are validated before injection:

```php
function validateToken($name, $value) {
    // Color tokens must be valid CSS color
    if (str_contains($name, 'color')) {
        $validated = validateColor($value);
        if (!$validated) return getDefaultValue($name);
        return $validated;
    }

    // Spacing tokens must be valid CSS length
    if (str_contains($name, 'space')) {
        $validated = validateLength($value);
        if (!$validated) return getDefaultValue($name);
        return $validated;
    }

    return $value;
}
```

### 29.2 Injection Prevention

| Attack Vector | Protection |
| --- | --- |
| CSS injection via token | Validate all token values |
| XSS via token name | Sanitize token names |
| Overwrite critical tokens | Blocklist critical tokens from user override |
| Excessive token count | Limit token count per theme |

| Requirement | Implementation |
| --- | --- |
| No inline styles | Use `adoptedStyleSheets` |
| No `eval()` | Standard JS only |
| No external resources | All tokens self-hosted |
| No `Function()` | Standard functions only |

## 36. Theme Composition Architecture

### 36.1 Theme Inheritance Model

Themes support hierarchical inheritance, allowing child themes to extend parent themes:

```text
Base Theme (gsmui)
├── Brand Theme (acme-corp)
│   ├── Marketing Theme
│   └── Dashboard Theme
└── Partner Theme (partner-xyz)
    └── Whitelabel Theme
```

### 36.2 Token Override Resolution

When a child theme defines tokens that also exist in the parent, the child value wins:

```php
// Parent theme defines:
'primary' => '#3b82f6',

// Child theme overrides:
'primary' => '#10b981',

// Result: child's '#10b981' is used
// Parent tokens NOT overridden remain intact
```

### 36.3 Partial Theme Application

Themes can define partial overrides — only specified tokens change:

```json
{
    "name": "dark-variant",
    "extends": "default",
    "tokens": {
        "color": {
            "bg": "#0f172a",
            "surface": "#1e293b"
        }
    }
}
```

All tokens not in the `tokens` key inherit from the parent.

    await page.click("[data-theme-toggle]");
    await page.waitForFunction(() => {
        const bg = getComputedStyle(document.documentElement)
            .getPropertyValue("--gsmui-color-bg");
        return bg.includes("#0f172a"); // dark bg
    });
    const duration = Date.now() - startTime;

    expect(duration).toBeLessThan(50); // 50ms budget

## 44. Theme Architecture Decision Records

### 44.1 ADR: CSS Custom Properties over CSS-in-JS

**Decision**: Use CSS custom properties (`--gsmui-*`) for runtime theming.

**Rationale**:
- CSP-safe (no `unsafe-eval`)
- Zero JavaScript overhead for token resolution
- Native browser performance
- Cacheable and debuggable
- Works with server-rendered HTML

### 44.2 ADR: Attribute-based Theme Selection

**Decision**: Use `data-theme` attribute on `<html>` for theme selection.

**Rationale**:
- Works with CSS selectors (`[data-theme="dark"]`)
- No JavaScript required for initial theme
- Compatible with SSR (server can set attribute)
- SEO-friendly (no flash)

### 44.3 ADR: Single Theme Object vs Multiple Token Files

**Decision**: Single theme JSON object per theme, compiled to CSS at build time.

**Rationale**:
- Atomic updates (no partial state)
- Easier versioning and rollback
- Simpler cache invalidation
- Better developer experience
