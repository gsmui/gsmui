# 06.03 - Common Columns

**Project:** GsmUi
**Domain:** Database Design - Foundation
**Version:** 1.0.0

---

# Purpose

This document catalogs reusable column definitions used across multiple tables. Domain documents (06.10 through 06.131) reference these definitions rather than re-specifying them.

---

# 1. Primary Key

```
id BIGINT UNSIGNED AUTO_INCREMENT PRIMARY KEY
```

Used in every table. Never omitted.

---

# 2. Timestamps

```
created_at DATETIME(3) NOT NULL DEFAULT CURRENT_TIMESTAMP(3)
updated_at DATETIME(3) NOT NULL DEFAULT CURRENT_TIMESTAMP(3) ON UPDATE CURRENT_TIMESTAMP(3)
```

Present in every table.

---

# 3. Soft Delete

```
deleted_at DATETIME(3) NULL
```

Present only in tables marked as soft-deletable (see 06.01-design-principles.md §3).

---

# 4. User Reference

```
user_id BIGINT UNSIGNED NOT NULL
```

References `users.id`. Used when a record is directly owned by a user. NOT used on billable tables — those use `morphTo` (`billable_type` / `billable_id`).

---

# 5. Team Reference

```
team_id BIGINT UNSIGNED NULL
```

References `teams.id`. Nullable because personal accounts have no team. When present, the record belongs to a team workspace.

---

# 6. MorphTo Ownership

```
billable_type VARCHAR(255) NOT NULL  -- 'App\Models\User' | 'App\Models\Team'
billable_id   BIGINT UNSIGNED NOT NULL
```

Used on billing tables (`orders`, `subscriptions`, `invoices`). No database FK. Application validates that `billable_type` + `billable_id` resolves to an existing record.

---

# 7. Slug

```
slug VARCHAR(255) NOT NULL UNIQUE
```

Used on publicly addressable entities (`products`, `components`, `themes`, `templates`, `content_entries`, `doc_spaces`). Generated from `name` on creation. Immutable after creation.

---

# 8. Name

```
name VARCHAR(255) NOT NULL
```

Human-readable display name. Present on most content tables.

---

# 9. Description

```
description TEXT NULL
```

Long-form description. Nullable because not all entities require one.

---

# 10. Status

```
status VARCHAR(50) NOT NULL DEFAULT 'draft'
```

Generic status field. Specific tables define their own ENUM or allowed values. Default `draft` for content, `pending` for transactions.

---

# 11. Sort Order

```
sort_order INT NOT NULL DEFAULT 0
```

Used on ordered collections (`cms_menu_items`, `component_variants`, `theme_tokens`). Lower values appear first.

---

# 12. Metadata (JSON)

```
metadata JSON NULL
```

Catch-all semi-structured data. Used on `content_entries`, `products`, `components`, `themes` for SEO, OpenGraph, custom attributes, and extensibility.

---

# 13. IP Address

```
ip_address VARCHAR(45) NULL  -- IPv4 or IPv6
```

Stored on `audit_logs`, `login_attempts`, `download_attempts`, `webhook_deliveries`. `VARCHAR(45)` accommodates IPv6.

---

# 14. User Agent

```
user_agent VARCHAR(255) NULL
```

Stored alongside `ip_address` for audit and analytics purposes.

---

# 15. External Provider IDs

```
stripe_id       VARCHAR(255) NULL UNIQUE
paddle_id       VARCHAR(255) NULL UNIQUE
lemon_squeezy_id VARCHAR(255) NULL UNIQUE
```

Present on `subscriptions` and `payments`. At most one is populated per record. Unique to prevent duplicate external records.

---

# 16. Currency

```
currency CHAR(3) NOT NULL DEFAULT 'USD'  -- ISO 4217
```

Used on all monetary tables (`products`, `orders`, `invoices`, `payments`, `credits`). Three-letter uppercase ISO 4217 code.

---

# 17. Money Amounts

```
amount        BIGINT UNSIGNED NOT NULL  -- minor units (cents)
tax_amount    BIGINT UNSIGNED NOT NULL DEFAULT 0
total_amount  BIGINT UNSIGNED NOT NULL
```

All monetary values are stored as integers in minor units (cents) to avoid floating-point rounding errors. Display layer converts to major units.

---

# 18. URL / Path

```
url     VARCHAR(2048) NULL
path    VARCHAR(1024) NULL
```

`url` for absolute URLs (media, download links). `path` for storage paths relative to disk.

---

# 19. Version

```
version VARCHAR(50) NOT NULL
```

Semantic version string on `products`, `components`, `themes`, `templates`, `doc_versions`. Format: `MAJOR.MINOR.PATCH`.

---

# 20. License Key (Encrypted)

```
key_encrypted TEXT NOT NULL  -- AES-256 encrypted via Laravel cast
key_hash     CHAR(64) NOT NULL  -- SHA-256 for lookups
```

`license_keys` table. `key_encrypted` stores the full key. `key_hash` stores a deterministic hash for equality lookups (encrypted columns cannot be queried directly).

---

# 21. Idempotency Key

```
idempotency_key VARCHAR(255) NOT NULL UNIQUE
```

Used on `mcp_tool_calls`, `payments`, `webhook_deliveries`. Guarantees exactly-once execution.

---

# 22. Event Type

```
event_type VARCHAR(100) NOT NULL
```

Webhook event types: `invoice.created`, `invoice.payment_succeeded`, `customer.subscription.created`, etc. Stored on `webhook_events` columns matching the exact Stripe/Paddle event names.

---

# 23. Quiet Hours (JSON)

```
quiet_hours JSON NULL  -- {"start": "22:00", "end": "08:00", "timezone": "America/New_York"}
```

Notification preference configuration. Nullable — not all users configure quiet hours.

---

# 24. Digest Frequency

```
digest_frequency ENUM('realtime', 'hourly', 'daily', 'weekly') NOT NULL DEFAULT 'realtime'
```

Controls notification batching. Default is immediate delivery.

---

# 25. Search Vector (Fulltext)

```
search_vector TEXT NULL
```

Denormalized full-text search vector. Populated by observer/event when content changes. Used by Meilisearch sync jobs and fallback database search.

# 26. Extended Column Definitions

## 26a. UUID Public Identifier

```
uuid CHAR(36) NOT NULL DEFAULT (UUID())
```

Used on `users`, `teams`, `products`, `subscriptions` — any entity exposed in public URLs or API responses. Generated via UUIDv4 on creation. Immutable after creation. The `uuid` column is used in API responses and public-facing URLs instead of auto-incrementing `id` values to prevent enumeration attacks.

```sql
CREATE TABLE users (
    uuid CHAR(36) NOT NULL DEFAULT (UUID()),
    UNIQUE KEY users_uuid_unique (uuid)
);

CREATE TABLE products (
    uuid CHAR(36) NOT NULL DEFAULT (UUID()),
    UNIQUE KEY products_uuid_unique (uuid)
);

CREATE TABLE teams (
    uuid CHAR(36) NOT NULL DEFAULT (UUID()),
    UNIQUE KEY teams_uuid_unique (uuid)
);

CREATE TABLE subscriptions (
    uuid CHAR(36) NOT NULL DEFAULT (UUID()),
    UNIQUE KEY subscriptions_uuid_unique (uuid)
);
```

---

## 26b. Encrypted Key Pairs

```
key_encrypted TEXT NOT NULL          -- AES-256 encrypted via Laravel Encrypted casts
key_hash      CHAR(64) NOT NULL     -- SHA-256 for equality lookups
key_prefix    VARCHAR(10) NOT NULL  -- First 6-8 chars for visual identification
```

Used on `license_keys`, `api_keys`, `webhook_signing_keys`. The encrypted value cannot be queried directly in SQL, so `key_hash` provides a deterministic lookup mechanism. `key_prefix` allows users to identify which key they're referencing without revealing the full secret.

```sql
CREATE TABLE license_keys (
    id BIGINT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
    key_encrypted TEXT NOT NULL,
    key_hash CHAR(64) NOT NULL,
    key_prefix VARCHAR(10) NOT NULL,
    UNIQUE KEY license_keys_key_hash_unique (key_hash),
    INDEX license_keys_key_prefix_index (key_prefix)
);

CREATE TABLE api_keys (
    id BIGINT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
    user_id BIGINT UNSIGNED NOT NULL,
    name VARCHAR(255) NOT NULL,
    key_encrypted TEXT NOT NULL,
    key_hash CHAR(64) NOT NULL,
    key_prefix VARCHAR(10) NOT NULL,
    abilities JSON NULL,
    last_used_at DATETIME(3) NULL,
    expires_at DATETIME(3) NULL,
    created_at DATETIME(3) NOT NULL DEFAULT CURRENT_TIMESTAMP(3),
    updated_at DATETIME(3) NOT NULL DEFAULT CURRENT_TIMESTAMP(3) ON UPDATE CURRENT_TIMESTAMP(3),
    deleted_at DATETIME(3) NULL,
    UNIQUE KEY api_keys_key_hash_unique (key_hash),
    INDEX api_keys_user_id_index (user_id),
    INDEX api_keys_expires_at_index (expires_at),
    INDEX api_keys_deleted_at_index (deleted_at)
);
```

# 28. Default Value Patterns

| Pattern | Default | SQL |
|---|---|---|
| Auto-increment PK | `AUTO_INCREMENT` | `$table->id()` |
| Boolean false | `0` / `false` | `$table->boolean('col')->default(false)` |
| Boolean true | `1` / `true` | `$table->boolean('col')->default(true)` |
| Sort order | `0` | `$table->integer('sort_order')->default(0)` |
| Count | `0` | `$table->unsignedInteger('download_count')->default(0)` |
| Status draft | `'draft'` | `$table->string('status', 50)->default('draft')` |
| Status pending | `'pending'` | `$table->string('status', 50)->default('pending')` |
| Currency | `'USD'` | `$table->char('currency', 3)->default('USD')` |
| Amount zero | `0` | `$table->unsignedBigInteger('tax_amount')->default(0)` |
| Quantity | `1` | `$table->unsignedInteger('quantity')->default(1)` |
| NULL | `NULL` | `$table->text('description')->nullable()` |
| Current timestamp | `CURRENT_TIMESTAMP(3)` | `$table->timestamps()` |
| Empty JSON | `NULL` | `$table->json('metadata')->nullable()` |
| License type | `'single'` | `$table->enum('license_type', [...])->default('single')` |
| Digest frequency | `'realtime'` | `$table->enum('digest_frequency', [...])->default('realtime')` |

# 32. Money and Currency Patterns

```sql

-- Orders
subtotal BIGINT UNSIGNED NOT NULL

discount_amount BIGINT UNSIGNED NOT NULL DEFAULT 0
total BIGINT UNSIGNED NOT NULL

-- Invoices
subtotal BIGINT UNSIGNED NOT NULL DEFAULT 0
tax BIGINT UNSIGNED NOT NULL DEFAULT 0
total BIGINT UNSIGNED NOT NULL DEFAULT 0

-- Payments
amount BIGINT UNSIGNED NOT NULL
refunded_amount BIGINT UNSIGNED NOT NULL DEFAULT 0

-- Credits
amount BIGINT UNSIGNED NOT NULL
balance BIGINT UNSIGNED NOT NULL DEFAULT 0

-- Subscriptions
price BIGINT UNSIGNED NOT NULL
```

# 34. Index Creation Timing

Indexes are created at specific points in the migration lifecycle:

```
1. Table creation → primary key auto-created
2. Table creation → unique indexes defined inline
3. Table creation → composite indexes added at end of create()
4. Alter table → new column + index in same migration
5. Separate migration → add index to existing column
6. Separate migration → drop index before dropping column
```

Index creation order within a migration:

```php
Schema::create('orders', function (Blueprint $table) {
    // 1. Primary key (auto)
    $table->id();

    // 2. Foreign keys
    $table->foreignId('user_id')->constrained();
    $table->foreignId('coupon_id')->nullable()->constrained();

    // 3. Business columns
    $table->string('order_number', 50)->unique();
    $table->enum('status', [...]);

    // 4. Monetary columns
    $table->unsignedBigInteger('subtotal');
    $table->unsignedBigInteger('total');

    // 5. Timestamps
    $table->timestamps();

    // 6. Indexes (at end of create())
    $table->index('status');
    $table->index('created_at');
    $table->index(['billable_type', 'billable_id']);
});
```

# 35. Column Ordering Convention

Columns within a table follow this standard ordering:

```
1. Primary key (id)
2. Public identifier (uuid)
3. Owner references (user_id, team_id, billable_type, billable_id)
4. Parent references (parent_id, author_id)
5. Name and slug
6. Description and content fields
7. Classification (type, status, category)
8. Boolean flags (is_*, has_*)
9. Pricing and monetary fields
10. Version and versioning fields
11. URLs and paths
12. Media references
13. SEO fields
14. Statistics and counters
15. JSON metadata and settings
16. Search vectors
17. External IDs (stripe_id, paddle_id)
18. Timestamps (created_at, updated_at)
19. Soft delete (deleted_at)
20. Indexes (in migration code, at end)
```

All foreign key columns must match the referenced column type exactly:

# 45. Database Migration Best Practices

1. **Always wrap in transactions** — Schema operations are transactional in MySQL/InnoDB.
2. **Never modify production data in migrations** — Use seeders or commands for data changes.
3. **Test rollback** — Every `down()` method should exactly reverse `up()`.
4. **Use timestamps for ordering** — `2026_01_01_000001_` prefix ensures correct execution order.
5. **Name descriptively** — `create_orders_table` not `create_table_1`.
6. **Add indexes explicitly** — Don't rely on Eloquent or ORM auto-creation.
7. **Verify column types match FK references** — BIGINT UNSIGNED must match BIGINT UNSIGNED.
8. **Use `nullable()` for optional FKs** — Not all relationships are required.
9. **Prefer `constrained()` over raw `references()`** — Laravel infers the referenced table.
10. **Use `cascadeOnDelete()` for child data** — Use `restrictOnDelete()` for financial records.
11. **Add `softDeletes()` only where needed** — Financial/audit tables should NOT use soft deletes.
12. **Use `$table->timestamps(3)` for millisecond precision** — Required for concurrent operations.
13. **Document column purposes** — Add comments in migration code for complex columns.
14. **Keep migrations small** — One table per migration file (or closely related tables).
15. **Never commit dist files** — Only commit migration, model, and seed files.

# 47. Migration Testing Checklist

Before running any migration in production:

```
□ Test on a fresh database (no existing data)
□ Test on a database with representative data volume
□ Verify rollback works correctly
□ Verify all indexes are created
□ Verify all foreign key constraints are applied
□ Verify column types match FK reference types
□ Verify default values are correct
□ Verify nullable columns are correctly configured
□ Verify unique constraints prevent duplicates
□ Verify soft delete columns are created for soft-deletable tables
□ Verify timestamps (created_at, updated_at) use DATETIME(3) precision
□ Verify ENUM values match the documented list
□ Verify JSON columns accept valid JSON
□ Verify no migration conflicts with existing migrations
□ Verify migration timestamp ordering is correct
□ Verify no raw SQL breaks on different MySQL/MariaDB versions
□ Verify fulltext indexes work with the configured storage engine
□ Verify character set is utf8mb4 for all text columns
```
