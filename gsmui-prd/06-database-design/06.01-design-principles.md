# 06.01 - Design Principles

**Project:** GsmUi
**Domain:** Database Design - Foundation
**Version:** 1.0.0

---

# Purpose

This document defines the foundational design principles that govern every table in the GsmUi database. All subsequent database design documents (06.10 through 06.131) must adhere to these principles.

---

# 1. Domain-Driven Ownership

Each table belongs to exactly one business domain. Domains are aligned with the application structure defined in `05.06-folder-structure.md`:

- `Authentication/` → 06.11-authentication.md
- `Users/` → 06.10-users.md
- `Components/` → 06.20 through 06.23
- `Themes/` → 06.30 through 06.32
- `Templates/` → 06.40 through 06.41
- `Marketplace/` → 06.50 through 06.58
- `Billing/` → 06.60 through 06.62
- `Documentation/` → 06.70 through 06.72
- `Playground/` → 06.80 through 06.82
- `Blog/` + `CMS/` → 06.90 through 06.91
- `Admin/` → 06.100 through 06.102
- `Notifications/` → 06.110 through 06.111
- `Search/` + `Analytics/` → 06.120 through 06.121
- `AI/` + `MCP/` → 06.130 through 06.131

No cross-domain table sharing. Shared concepts (e.g., content entries used by both Blog and CMS) use a single table with a type discriminator, not two tables.

# 2. Immutability for Financial Records

Financial and legal records are immutable once created. The following tables never use soft deletes:

- `audit_logs`
- `payments`
- `payment_refunds`
- `payment_status_histories`
- `invoices`
- `invoice_lines`
- `invoice_payments`
- `subscriptions`
- `subscription_status_histories`
- `subscription_usage_records`
- `webhook_events`
- `webhook_deliveries`
- `downloads`
- `download_attempts`
- `license_keys`
- `license_activations`
- `license_revocations`
- `credits`
- `credit_applications`

Correction or reversal of financial data is accomplished by inserting a new compensating record, not by modifying or deleting existing records.

---

# 3. Soft Deletes for User Content

All user-editable content supports soft deletes:

- `products`, `product_media`, `product_versions`
- `product_changelogs`, `product_compatibility`
- `components`, `component_variants`, `variant_options`, `variant_props`
- `component_examples`, `example_screenshots`
- `component_docs`, `component_doc_sections`
- `themes`, `theme_tokens`, `theme_token_groups`
- `theme_exports`, `theme_export_assets`
- `templates`, `template_files`, `template_assets`
- `content_entries` (blog/cms/announcements)
- `content_entry_revisions`, `content_media`
- `cms_menus`, `cms_menu_items`, `cms_blocks`
- `reviews`, `review_votes`
- `snippets`, `snippet_executions`
- `playground_projects`, `playground_snapshots`
- `doc_pages`, `doc_page_revisions`, `doc_page_blocks`, `doc_page_media`
- `admin_notes`, `content_flags`, `moderation_queue`
- `feature_flag_overrides`, `feature_flag_history`
- `activity_logs`, `notifications`
- `ai_conversations`, `ai_messages`, `ai_prompt_templates`
- `mcp_tool_calls`, `mcp_tool_results`, `mcp_sessions`

Soft deletes are NOT applied to settings, feature flags, or notification channels — these are configuration tables.

---

# 4. Audit Fields Policy

Every table includes `created_at` and `updated_at` timestamps.

Soft-deletable tables include `deleted_at`.

No per-table `created_by` / `updated_by` / `deleted_by` columns. Instead, all audit attribution is captured centrally in `audit_logs` (06.100-admin.md) via model events. This avoids schema sprawl and keeps table definitions clean.

---

# 5. Centralized Audit Logging

The single `audit_logs` table records all significant state changes:

- Admin actions (user bans, content moderation, settings changes)
- License key creation and revocation
- Refund initiation and completion
- Payment failures and retries
- Subscription status transitions
- Webhook delivery failures
- Content flagging and moderation decisions

Each audit entry captures: `user_id` (actor), `action`, `entity_type`, `entity_id`, `old_values`, `new_values`, `ip_address`, `user_agent`, `occurred_at`.

---

# 6. Polymorphic Ownership (morphTo)

Billing-related tables (`orders`, `subscriptions`, `invoices`) use `morphTo` for ownership, allowing both `users` and `teams` to be billable entities:

```
billable_type → 'App\Models\User' | 'App\Models\Team'
billable_id   → corresponding record id
```

No database-level foreign key constraints exist on `billable_type` / `billable_id`. Application-level validation ensures referential integrity.

---

# 7. Indexing Strategy

Every table follows this indexing pattern:

- **PRIMARY KEY:** Always `id` (BIGINT UNSIGNED AUTO_INCREMENT).
- **UNIQUE indexes:** On natural keys (`slug`, `email`, `stripe_id`, `paddle_id`, `idempotency_key`).
- **INDEX:** On foreign keys and frequently filtered columns (`user_id`, `team_id`, `status`, `created_at`).
- **FULLTEXT indexes:** On searchable text fields (`name`, `description`, `content`) where Meilisearch is not the primary search path.

Composite indexes are used sparingly and only when query plans demonstrate benefit.

---

# 8. Encryption at Rest

Sensitive data is encrypted using Laravel's `encrypted` cast (AES-256-CBC):

- `license_keys.key` — full key value
- `payment_methods.token` — stored payment token
- `personal_access_tokens.token` — plaintext token (hashed in `tokenable_id` relationship via `plainTextToken`)
- `two_factor_auth.secret` — TOTP secret

Never store plaintext secrets, tokens, or keys.

---

# 9. Character Set and Collation

All tables use:

```
CHARSET = utf8mb4
COLLATE = utf8mb4_unicode_ci
```

This ensures full Unicode support including emoji and multi-byte characters in user-generated content.

---

# 10. Timestamp Behavior

- `created_at` and `updated_at` are managed by Eloquent.
- `deleted_at` is managed by Eloquent soft deletes where applicable.
- No manual timestamp manipulation in application code.
- All timestamps stored in UTC. Application layer handles timezone conversion for display.

---

# 11. Nullable vs Non-Nullable

Columns are non-nullable unless the business rule explicitly allows absence:

- Foreign keys are nullable only when the relationship is optional (e.g., `parent_id` in a hierarchical table).
- Business data fields (`name`, `email`, `status`) are non-nullable with sensible defaults.
- JSON columns are nullable with default `JSON` (empty object/array as appropriate).
- Boolean flags default to `false` rather than `NULL`.

---

# 12. ENUM Strategy

ENUMs are used for constrained string sets with low churn:

- `product_type`: 12 fixed marketplace product types
- `subscriptions.status`: 6 fixed billing states
- `content_entries.content_type`: 3 content types
- `team_members.role`: 3 workspace roles
- `notification_channels.type`: 5 channel types

Adding a new ENUM value requires a migration. String ENUMs (not integer ENUMs) are used so the values remain readable in queries and logs.

# 14. JSON Columns

JSON columns are used for semi-structured data where schema rigidity would hinder evolution:

- `user_preferences.preferences` — user-specific UI settings
- `notification_preferences.quiet_hours` — time-range configuration
- `cms_menus.items` — ordered menu structure with drag-drop support
- `content_entries.metadata` — SEO, OpenGraph, and custom fields
- `ai_conversations.context` — conversation memory and system prompts
- `mcp_tool_calls.arguments` — dynamic tool parameters
- `feature_flags.rules` — rollout percentage and targeting criteria
- `theme_token_overrides.value` — arbitrary token value types (color, spacing, font)

JSON columns are never indexed individually. If a JSON field requires frequent filtering, extract it to a dedicated column.

---

# 15. Idempotency

Critical write operations use idempotency keys to prevent duplicate execution:

- `mcp_tool_calls.idempotency_key` — unique, prevents duplicate tool invocations
- `payments.idempotency_key` — unique per payment attempt
- `webhook_deliveries.idempotency_key` — unique per webhook dispatch

Idempotency keys are scoped to the operation type and generating service.

# 16. Data Partitioning Strategy

## Horizontal Partitioning (Sharding)

GsmUi employs a logical partitioning strategy aligned with team isolation:

| Partition Key | Tables | Strategy |
|---|---|---|
| `team_id` | All team-scoped content tables | Logical separation via query scopes; physical sharding planned for >10M records |
| `user_id` | User-owned content (`products`, `components`, `themes`) | Query-scoped; no physical sharding required at current scale |
| `billing_period` | Financial tables (`invoices`, `payments`, `subscription_usage_records`) | Partition by month (MySQL native partitioning) |

### Team-Based Logical Sharding

All team-scoped tables include `team_id` with a composite index `(team_id, created_at)` enabling efficient tenant isolation:

```sql
-- Example query pattern for team isolation
SELECT * FROM components 
WHERE team_id = ? AND deleted_at IS NULL 
ORDER BY created_at DESC 
LIMIT 20;
```

Application-level middleware injects `team_id` into all queries for authenticated team contexts, preventing cross-tenant data access.

### Billing Table Partitioning

Monthly partitions for high-volume financial tables:

```sql
ALTER TABLE invoices PARTITION BY RANGE (YEAR(created_at) * 100 + MONTH(created_at)) (
    PARTITION p202401 VALUES LESS THAN (202402),
    PARTITION p202402 VALUES LESS THAN (202403),
    -- ... monthly partitions
    PARTITION p_future VALUES LESS THAN MAXVALUE
);
```

Partitions older than 24 months are archived to cold storage.

## Vertical Partitioning

Wide tables with frequently accessed and rarely accessed columns are split:

| Parent Table | Hot Columns (Frequent Access) | Cold Columns (Rare Access) | Cold Table |
|---|---|---|---|
| `products` | id, name, slug, status, price, author_id | description, changelog, metadata, search_vector | `product_details` |
| `components` | id, name, slug, category_id, version, status | description, code, metadata, search_vector | `component_details` |
| `users` | id, name, email, status, email_verified_at | bio, avatar_url, website, location, timezone | `user_profiles` (existing) |

# 17. Data Retention and Archival

## Retention Policies

| Table Category | Retention Period | Action | Archive Destination |
|---|---|---|---|
| Financial records (invoices, payments, subscriptions) | 7 years (legal) | Immutable, never deleted | Cold storage (S3 Glacier) |
| Audit logs | 3 years | Immutable, never deleted | Compressed Parquet in S3 |
| User activity logs | 1 year | Archive after 90 days hot | ClickHouse / Athena |
| Sessions | 30 days | Auto-purge via scheduler | N/A |
| Login attempts | 90 days | Auto-purge | N/A |
| Webhook deliveries | 30 days | Auto-purge after delivery | N/A |
| Failed jobs | 7 days | Retry then archive | Dead letter queue |
| Notification history | 90 days | User can delete individually | N/A |
| Search analytics | 2 years | Aggregate after 30 days | Data warehouse |
| AI conversations | 1 year | User can export/delete | User export bundle |
| Playground snapshots | 30 days | Auto-cleanup | N/A |

## Archival Process

```php
<?php

namespace App\Domains\Admin\Jobs;

use Illuminate\Bus\Queueable;
use Illuminate\Contracts\Queue\ShouldQueue;
use Illuminate\Foundation\Bus\Dispatchable;
use Illuminate\Queue\InteractsWithQueue;
use Illuminate\Queue\SerializesModels;
use Illuminate\Support\Facades\DB;
use Illuminate\Support\Facades\Storage;
use Illuminate\Support\Str;

class ArchiveOldRecords implements ShouldQueue
{
    use Dispatchable, InteractsWithQueue, Queueable, SerializesModels;

    public function handle(): void
    {
        $this->archiveUserActivityLogs();
        $this->archiveSearchAnalytics();
        $this->archiveNotifications();
        $this->purgeExpiredSessions();
    }

    private function archiveUserActivityLogs(): void
    {
        $cutoff = now()->subDays(90);
        
        $records = DB::table('user_activity_logs')
            ->where('created_at', '<', $cutoff)
            ->where('archived_at', null)
            ->chunk(10000, function ($chunk) {
                $data = $chunk->map(fn ($r) => (array) $r)->toArray();
                $filename = 'activity-logs/' . now()->format('Y/m/d') . '/' . Str::uuid() . '.parquet';
                
                Storage::disk('archive')->put($filename, Parquet::encode($data));
                
                DB::table('user_activity_logs')
                    ->whereIn('id', array_column($data, 'id'))
                    ->update(['archived_at' => now()]);
            });
    }

    private function archiveSearchAnalytics(): void
    {
        $cutoff = now()->subDays(30);
        
        DB::table('search_analytics')
            ->where('created_at', '<', $cutoff)
            ->chunk(5000, function ($chunk) {
                // Aggregate to daily summaries before archiving
                $aggregated = $chunk->groupBy(fn ($r) => date('Y-m-d', strtotime($r->created_at)))
                    ->map(function ($dayRecords, $date) {
                        return [
                            'date' => $date,
                            'total_searches' => $dayRecords->count(),
                            'unique_users' => $dayRecords->pluck('user_id')->unique()->count(),
                            'zero_results' => $dayRecords->where('results_count', 0)->count(),
                            'avg_results' => $dayRecords->avg('results_count'),
                            'top_queries' => $dayRecords->pluck('query')
                                ->filter()
                                ->countBy()
                                ->sortDesc()
                                ->take(100)
                                ->toArray(),
                        ];
                    });

                $filename = 'search-analytics/' . now()->format('Y/m') . '/aggregated.parquet';
                Storage::disk('archive')->put($filename, Parquet::encode($aggregated->values()->toArray()));
                
                DB::table('search_analytics')
                    ->whereIn('id', $chunk->pluck('id'))
                    ->delete();
            });
    }
}
```

# 18. Referential Integrity Strategy

## Foreign Key Philosophy

GsmUi uses a **pragmatic referential integrity** approach:

1. **Database-level FKs** for core structural relationships (user → team, product → author)
2. **Application-level validation** for polymorphic, billing, and high-churn relationships
3. **No FKs** on tables with >10M rows where lock contention during ALTER is prohibitive

### Enforced Database Foreign Keys

| Child Table | Parent Table | Columns | On Delete |
|---|---|---|---|
| `team_members` | `teams` | `team_id` | CASCADE |
| `team_members` | `users` | `user_id` | CASCADE |
| `team_invitations` | `teams` | `team_id` | CASCADE |
| `user_profiles` | `users` | `user_id` | CASCADE |
| `user_preferences` | `users` | `user_id` | CASCADE |
| `products` | `users` | `user_id` | CASCADE |
| `components` | `users` | `user_id` | CASCADE |
| `themes` | `users` | `user_id` | CASCADE |
| `orders` | `users` | `user_id` (nullable) | SET NULL |
| `subscriptions` | `users` | `user_id` (nullable) | SET NULL |

### Application-Enforced Relationships

| Relationship | Validation Point | Failure Handling |
|---|---|---|
| `orders.billable` → User/Team | Repository `create()` | Throw `InvalidBillableException` |
| `webhook_events.delivery` → WebhookEndpoint | Job `handle()` | Log, mark delivery failed |
| `license_keys.product` → Product | Observer `creating` | Abort creation, log error |
| `downloads.product_version` → ProductVersion | Controller `store()` | Return 404, track missing reference |

## Migration Safety Checklist

Every migration must pass these checks before deployment:

```php
<?php

// Migration base class with safety checks
abstract class SafeMigration extends Migration
{
    public function up(): void
    {
        $this->validatePreconditions();
        $this->executeMigration();
        $this->validatePostconditions();
    }

    protected function validatePreconditions(): void
    {
        // 1. Check table doesn't already exist (idempotency)
        if ($this->tableExists($this->targetTable)) {
            $this->warn("Table {$this->targetTable} already exists, skipping");
            return;
        }

        // 2. Verify referenced tables exist
        foreach ($this->foreignKeys as $fk) {
            if (!$this->tableExists($fk['table'])) {
                throw new \Exception("Referenced table {$fk['table']} does not exist");
            }
        }

        // 3. Check disk space (require 2x estimated table size)
        $this->assertDiskSpace($this->estimatedTableSizeBytes() * 2);

        // 4. Verify no long-running transactions
        $this->assertNoLongRunningTransactions();
    }

    protected function validatePostconditions(): void
    {
        // 1. Verify indexes created
        foreach ($this->expectedIndexes as $index) {
            if (!$this->indexExists($this->targetTable, $index)) {
                throw new \Exception("Index {$index} was not created on {$this->targetTable}");
            }
        }

        // 2. Verify foreign keys enforced
        foreach ($this->foreignKeys as $fk) {
            $this->assertForeignKeyWorks($this->targetTable, $fk);
        }

        // 3. Spot-check data integrity
        $this->assertRowCount($this->targetTable, 0); // New tables should be empty
    }

    protected function rollbackStrategy(): string
    {
        return 'drop_table'; // Default: drop table on rollback
    }
}
```

# 20. Testing Strategy for Database Layer

## Migration Testing

```php
<?php

namespace Tests\Database\Migrations;

use Illuminate\Foundation\Testing\RefreshDatabase;
use Illuminate\Support\Facades\Schema;
use Tests\TestCase;

class MigrationTestCase extends TestCase
{
    use RefreshDatabase;

    protected function assertMigrationCreatesTable(string $table, array $expectedColumns): void
    {
        $this->artisan('migrate', ['--path' => "database/migrations/{$this->migrationPath}"]);
        
        $this->assertTrue(Schema::hasTable($table), "Table {$table} should exist");
        
        foreach ($expectedColumns as $column => $type) {
            $this->assertTrue(
                Schema::hasColumn($table, $column),
                "Column {$column} should exist on {$table}"
            );
        }
    }

    protected function assertMigrationCreatesIndexes(string $table, array $expectedIndexes): void
    {
        $indexes = DB::select("SHOW INDEXES FROM {$table}");
        $indexNames = array_column($indexes, 'Key_name');
        
        foreach ($expectedIndexes as $index) {
            $this->assertContains($index, $indexNames, "Index {$index} should exist on {$table}");
        }
    }

    protected function assertMigrationCreatesForeignKeys(string $table, array $expectedFks): void
    {
        $fks = DB::select("
            SELECT CONSTRAINT_NAME, COLUMN_NAME, REFERENCED_TABLE_NAME, REFERENCED_COLUMN_NAME
            FROM INFORMATION_SCHEMA.KEY_COLUMN_USAGE
            WHERE TABLE_NAME = ? AND REFERENCED_TABLE_NAME IS NOT NULL
            AND TABLE_SCHEMA = DATABASE()
        ", [$table]);

        foreach ($expectedFks as $fk) {
            $this->assertNotEmpty(
                array_filter($fks, fn ($k) => $k->COLUMN_NAME === $fk['column'] 
                    && $k->REFERENCED_TABLE_NAME === $fk['references']),
                "Foreign key {$fk['column']} -> {$fk['references']} should exist on {$table}"
            );
        }
    }
}
```

# 22. Disaster Recovery

## Backup Strategy

| Backup Type | Frequency | Retention | Storage | RPO | RTO |
|---|---|---|---|---|---|
| Full physical (Percona XtraBackup) | Daily 02:00 UTC | 30 days | S3 (cross-region) | 24h | 2h |
| Incremental physical | Every 6 hours | 7 days | S3 (cross-region) | 6h | 1h |
| Logical (mysqldump --single-transaction) | Hourly | 48 hours | S3 (same region) | 1h | 30m |
| Binlog shipping | Continuous | 7 days | S3 (cross-region) | < 1s | 15m |

## Point-in-Time Recovery Procedure

```bash
#!/bin/bash
# scripts/pitr-recovery.sh

TARGET_TIME="$1"  # e.g., "2025-01-15 14:30:00"
RESTORE_DIR="/mnt/restore"
LATEST_FULL=$(aws s3 ls s3://gsmui-backups/full/ | sort | tail -1 | awk '{print $4}')
LATEST_INCR=$(aws s3 ls s3://gsmui-backups/incr/ | grep "$(date -d "$TARGET_TIME" +%Y%m%d)" | sort | tail -1 | awk '{print $4}')

# 1. Restore latest full backup before target time
xtrabackup --copy-back --target-dir=$RESTORE_DIR --backup-dir=s3://gsmui-backups/full/$LATEST_FULL

# 2. Apply incremental backups up to target
for incr in $(aws s3 ls s3://gsmui-backups/incr/ | awk '{print $4}' | sort); do
    if [[ "$incr" > "$LATEST_FULL" && "$incr" <= "$(date -d "$TARGET_TIME" +%Y%m%d%H%M)" ]]; then
        xtrabackup --prepare --apply-log-only --target-dir=$RESTORE_DIR --incremental-dir=s3://gsmui-backups/incr/$incr
    fi
done

# 3. Apply binlogs up to target timestamp
mysqlbinlog --start-datetime="$(date -d "$TARGET_TIME - 1 hour" +%Y-%m-%d\ %H:%M:%S)" \
            --stop-datetime="$TARGET_TIME" \
            s3://gsmui-backups/binlogs/ | mysql -u root

# 4. Verify data integrity
mysqlcheck --all-databases --auto-repair
```

# 23. Schema Evolution Guidelines

## Adding Columns

1. **Always nullable** or with **explicit default** — never NOT NULL without default
2. **Add index in same migration** if column will be filtered
3. **Backfill in background job** for large tables (>100k rows)

```php
// ✅ Good: Nullable with default
$table->json('settings')->nullable()->default('{}');

// ✅ Good: Non-nullable with default
$table->boolean('is_active')->default(true);

// ❌ Bad: Non-nullable without default (blocks writes on large tables)
$table->string('status')->default('draft'); // Still requires table rebuild on MySQL < 8.0
```

## Removing Columns

1. **Mark deprecated** in model casts/accessors
2. **Stop writing** to column in application code
3. **Wait 2 releases** (verify no reads)
4. **Drop column** in migration with `ifExists`

```php
// Migration to drop deprecated column
Schema::table('users', function (Blueprint $table) {
    $table->dropColumnIfExists('legacy_field');
});
```

## Changing Column Types

MySQL 8.0+ supports instant `CHANGE COLUMN` for compatible types:

| From → To | Instant? | Notes |
|---|---|---|
| `VARCHAR(255)` → `VARCHAR(500)` | Yes | Length increase |
| `INT` → `BIGINT` | Yes | Safe widening |
| `DATETIME` → `DATETIME(3)` | Yes | Precision increase |
| `VARCHAR` → `TEXT` | No | Requires table rebuild |
| `ENUM` → `VARCHAR` | No | Requires table rebuild |

Always test on staging with production-scale data before deploying type changes.

## Renaming Tables/Columns

Use **dual-write pattern** for zero-downtime renames:

```php
// Migration 1: Add new column, dual-write in app
$table->string('new_name')->nullable();

// Migration 2 (next release): Backfill
DB::statement('UPDATE users SET new_name = old_name WHERE new_name IS NULL');

// Migration 3 (next release): Drop old, rename new
$table->dropColumn('old_name');
$table->renameColumn('new_name', 'old_name'); // If needed
```

# 25. Cross-Domain Data Access Patterns

## Repository Pattern

Each domain exposes a repository interface. Cross-domain queries use **read models** (materialized views) rather than joining across domains.

```php
<?php

namespace App\Domains\Marketplace\Repositories;

use App\Domains\Marketplace\Models\Product;
use App\Domains\Marketplace\DataTransferObjects\ProductListItem;

interface ProductRepository
{
    public function findBySlug(string $slug): ?Product;
    public function getPublishedForTeam(int $teamId, int $perPage = 20): \Illuminate\Pagination\LengthAwarePaginator;
    public function search(string $query, array $filters = []): \Illuminate\Support\Collection;
    public function getListItems(array $filters = []): \Illuminate\Support\Collection; // Returns ProductListItem DTOs
}

// Read model for cross-domain listing (Marketplace + Components + Themes)
class MarketplaceListingRepository
{
    public function getAllListings(array $filters = []): \Illuminate\Pagination\LengthAwarePaginator
    {
        // Queries materialized view `marketplace_listings_mv`
        // Refreshed every 5 minutes via scheduler
        return DB::table('marketplace_listings_mv')
            ->when($filters['category'] ?? null, fn ($q, $c) => $q->where('category', $c))
            ->when($filters['type'] ?? null, fn ($q, $t) => $q->where('type', $t))
            ->when($filters['search'] ?? null, fn ($q, $s) => $q->whereRaw('MATCH(search_vector) AGAINST(? IN BOOLEAN MODE)', [$s]))
            ->orderBy('created_at', 'desc')
            ->paginate($filters['per_page'] ?? 24);
    }
}
```

# 29. Query Patterns and Anti-Patterns

## Recommended Query Patterns

### 1. Scoped Queries for Soft Deletes

Always apply soft delete scope to prevent accidental exposure of deleted records:

```php
// ✅ Good: Uses the global scope
Component::where('team_id', $teamId)->get();

// ❌ Bad: Bypasses soft delete scope
Component::withoutGlobalScope(SoftDeletingScope::class)->get();
```

### 2. Eager Loading for Relationships

Prevent N+1 queries by eager loading relationships:

```php
// ✅ Good: Single query with eager load
Product::with(['author.profile', 'category', 'media'])
    ->where('team_id', $teamId)
    ->get();

// ❌ Bad: N+1 query — fires separate query per product for each relation
Product::where('team_id', $teamId)->get()->each(fn ($p) => $p->author);
```

### 3. Cursor for Large Datasets

Use `cursor()` for memory-efficient iteration over large result sets:

```php
// ✅ Good: Memory-efficient iteration
foreach (Component::where('team_id', $teamId)->cursor() as $component) {
    $this->process($component);
}

// ❌ Bad: Loads entire dataset into memory
$components = Component::where('team_id', $teamId)->get();
foreach ($components as $component) { ... }
```

### 4. Chunking for Batch Operations

Use `chunk()` or `chunkById()` for batch processing:

```php
// ✅ Good: Processes in batches of 1000
Component::where('status', 'draft')
    ->chunkById(100, function ($components) {
        foreach ($components as $component) {
            $this->publish($component);
        }
    });

// ❌ Bad: Processes entire table at once
Component::where('status', 'draft')->get()->each(fn ($c) => $this->publish($c));
```

### 5. Pluck for Single-Column Selection

Use `pluck()` when only one column is needed:

```php
// ✅ Good: Returns Collection of IDs
$userIds = User::where('status', 'active')->pluck('id');

// ❌ Bad: Loads full models just for IDs
$userIds = User::where('status', 'active')->get()->pluck('id');
```

### 6. Exists Over Count

Use `exists()` instead of `count() > 0` for boolean checks:

```php
// ✅ Good: Stops at first match
if (Order::where('user_id', $userId)->where('status', 'pending')->exists()) {
    // ...
}

// ❌ Bad: Counts all matching rows
if (Order::where('user_id', $userId)->where('status', 'pending')->count() > 0) {
    // ...
}
```

## Anti-Patterns to Avoid

| Anti-Pattern | Problem | Solution |
|---|---|---|
| SELECT * | Fetches unused columns, slows I/O | Select only needed columns |
| LIKE '%term%' | Prevents index usage | Use FULLTEXT search or prefix search `LIKE 'term%'` |
| Subqueries in SELECT | N+1 execution per row | Use JOINs or eager loading |
| Implicit type casting | Indexes bypassed | Match column types in WHERE |
| WithoutSoftDeletes bypass | Exposes deleted data | Use soft delete scope |

## Migration Diff Detection

```php
<?php

namespace App\Domains\Admin\Commands;

use Illuminate\Console\Command;
use Illuminate\Support\Facades\DB;
use Illuminate\Support\Facades\File;

class DetectSchemaDrift extends Command
{
    protected $signature = 'db:detect-drift';
    protected $description = 'Compare live schema against migrations to detect drift';

    public function handle(): int
    {
        $expected = $this->getExpectedSchema();
        $actual = $this->getActualSchema();
        $diff = $this->compareSchemas($expected, $actual);

        if (empty($diff)) {
            $this->info('No schema drift detected.');
            return self::SUCCESS;
        }

        $this->error('Schema drift detected:');
        foreach ($diff as $change) {
            $this->line("  {$change['type']}: {$change['table']}.{$change['column']}");
        }

        return self::FAILURE;
    }

    private function getExpectedSchema(): array
    {
        // Parse migration files to build expected schema
        $migrations = glob(database_path('migrations/*.php'));
        $schema = [];

        foreach ($migrations as $file) {
            require $file;
            // Extract table structure from Blueprint closures
        }

        return $schema;
    }

    private function getActualSchema(): array
    {
        $tables = DB::select('SHOW TABLES');
        $schema = [];

        foreach ($tables as $table) {
            $tableName = reset($table);
            $columns = DB::select("DESCRIBE {$tableName}");
            $indexes = DB::select("SHOW INDEXES FROM {$tableName}");
            $schema[$tableName] = [
                'columns' => collect($columns)->pluck('Field')->toArray(),
                'indexes' => collect($indexes)->pluck('Key_name')->unique()->toArray(),
            ];
        }

        return $schema;
    }
}
```

```sql
FROM performance_schema.table_io_waits_summary_by_index_usage
WHERE object_schema = DATABASE()
  AND index_name IS NOT NULL
  AND count_star = 0
  AND index_name != 'PRIMARY';
```

## Partition Management

```php
// Automated partition creation
class MaintainPartitions extends Command
{
    protected $signature = 'db:maintain-partitions';

    public function handle(): void
    {
        $tables = ['invoices', 'payments', 'analytics_events'];
        
        foreach ($tables as $table) {
            $this->addNextMonthPartition($table);
            $this->dropOldPartitions($table, 24); // Keep 24 months
        }
    }

    private function addNextMonthPartition(string $table): void
    {
        $nextMonth = now()->addMonth();
        $partitionName = 'p' . $nextMonth->format('Ym');
        $value = $nextMonth->copy()->addMonth()->format('Ym');
        
        DB::statement("
            ALTER TABLE {$table} REORGANIZE PARTITION p_future INTO (
                PARTITION {$partitionName} VALUES LESS THAN ({$value}),
                PARTITION p_future VALUES LESS THAN MAXVALUE
            )
        ");
    }
}
```

# 36. Backup and Recovery Procedures

## Automated Backup Pipeline

```php
<?php

namespace App\Domains\Admin\Jobs;

use Illuminate\Bus\Queueable;
use Illuminate\Contracts\Queue\ShouldQueue;
use Illuminate\Foundation\Bus\Dispatchable;
use Illuminate\Queue\InteractsWithQueue;
use Illuminate\Support\Facades\DB;
use Illuminate\Support\Facades\Log;
use Illuminate\Support\Facades\Storage;

class DatabaseBackupJob implements ShouldQueue
{
    use Dispatchable, InteractsWithQueue, Queueable;

    public function __construct(
        private string $type = 'incremental',
        private int $retentionDays = 30,
    ) {}

    public function handle(): void
    {
        $filename = $this->generateFilename();
        $filepath = storage_path("app/backups/{$filename}");

        match ($this->type) {
            'full' => $this->fullBackup($filepath),
            'incremental' => $this->incrementalBackup($filepath),
            'logical' => $this->logicalBackup($filepath),
        };

        // Encrypt and upload
        $encrypted = $this->encrypt($filepath);
        Storage::disk('s3')->put("backups/{$filename}.gpg", $encrypted);

        // Cleanup old backups
        $this->cleanup();

        Log::info("Backup completed: {$filename}");
    }

    private function fullBackup(string $filepath): void
    {
        $command = sprintf(
            'xtrabackup --backup --target-dir=%s --user=%s --password=%s 2>&1',
            escapeshellarg($filepath),
            escapeshellarg(config('database.connections.mysql.username')),
            escapeshellarg(config('database.connections.mysql.password'))
        );

        exec($command, $output, $exitCode);
        if ($exitCode !== 0) {
            throw new \RuntimeException("Full backup failed: " . implode("\n", $output));
        }
    }

    private function logicalBackup(string $filepath): void
    {
        $command = sprintf(
            'mysqldump --single-transaction --routines --triggers --quick %s > %s 2>&1',
            escapeshellarg(config('database.connections.mysql.database')),
            escapeshellarg($filepath)
        );

        exec($command, $output, $exitCode);
        if ($exitCode !== 0) {
            throw new \RuntimeException("Logical backup failed: " . implode("\n", $output));
        }
    }

    private function cleanup(): void
    {
        $cutoff = now()->subDays($this->retentionDays);
        $files = Storage::disk('s3')->allFiles('backups');
        
        foreach ($files as $file) {
            $lastModified = Storage::disk('s3')->lastModified($file);
            if ($lastModified < $cutoff) {
                Storage::disk('s3')->delete($file);
            }
        }
    }
}
```

# 38. Glossary (Extended)

| Term | Definition |
|---|---|
| **Billable** | Polymorphic entity (User or Team) that can own subscriptions, invoices, orders |
| **Soft Delete** | Logical deletion via `deleted_at` timestamp; records excluded from default queries |
| **Idempotency Key** | Client-generated unique key preventing duplicate execution of non-idempotent operations |
| **MorphTo** | Laravel polymorphic relationship allowing a model to belong to multiple parent types |
| **Materialized View** | Pre-computed query result stored as a table, refreshed periodically |
| **Partition Pruning** | Query optimizer skipping irrelevant partitions based on WHERE clause |
| **Covering Index** | Index containing all columns needed by a query, avoiding table lookup |
| **RPO** | Recovery Point Objective — maximum acceptable data loss |
| **RTO** | Recovery Time Objective — maximum acceptable downtime |
| **CTE** | Common Table Expression — temporary result set for complex queries |
| **AAGUID** | Authenticator Attestation GUID — identifies passkey authenticator model |
| **Online DDL** | Schema change that allows concurrent reads/writes during modification |
| **PITR** | Point-in-Time Recovery — restoring database to specific timestamp |
| **Lock Contention** | Performance degradation when multiple transactions compete for same locks |
| **Buffer Pool** | InnoDB memory cache for data and index pages |
| **Query Plan** | Database optimizer's execution strategy for a given SQL statement |
| **Deadlock** | Circular lock dependency causing transactions to wait indefinitely |
| **Sticky Connection** | Request-scoped connection that routes both reads and writes to same server |
| **Cold Storage** | Low-cost, high-latency storage for archival data (e.g., S3 Glacier) |
| **Hot Data** | Frequently accessed data requiring low-latency retrieval |
