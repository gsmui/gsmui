# 06.02 - Naming Conventions

**Project:** GsmUi
**Domain:** Database Design - Foundation
**Version:** 1.0.0

---

# Purpose

This document defines naming conventions for all database objects. Consistent naming eliminates ambiguity, reduces onboarding time, and enables automated tooling (migrations, factories, seeders).

All domain documents (06.10 through 06.131) must follow these rules without exception.

---

```
users
team_members
component_variants
theme_token_groups
```

# 2. Columns

Columns use `snake_case`:

```
user_id
team_id
is_published
created_at
deleted_at
sort_order
max_downloads
is_physical
tax_rate_id
quiet_hours
idempotency_key
plain_text_token
full_text_search
```

Prefix foreign keys with the singular table name they reference:

- `user_id` → references `users.id`
- `team_id` → references `teams.id`
- `parent_id` → references the same table
- `license_key_id` → references `license_keys.id`

---

# 3. Indexes

Index names follow the pattern `{table}_{columns}_index`:

```
users_email_index
users_email_unique
component_variants_component_id_sort_order_index
orders_billable_type_billable_id_index
subscriptions_user_id_status_index
invoices_number_unique
```

Unique indexes use `_unique` suffix. Primary keys use the Laravel default `{table}_pk`.

---

# 4. Primary Keys

Every table uses `id` as the primary key column name:

```
id BIGINT UNSIGNED AUTO_INCREMENT PRIMARY KEY
```

No natural primary keys or composite primary keys are used.

---

# 5. Foreign Keys

Foreign key constraints use the naming pattern `{table}_{column}_foreign`:

```
users_team_id_foreign
team_members_user_id_foreign
component_variants_component_id_foreign
orders_billable_type_billable_id_foreign
invoices_subscription_id_foreign
```

Polymorphic foreign keys (`billable_type` / `billable_id`) never receive database-level foreign key constraints.

---

# 6. Timestamps

All timestamps use these exact column names:

```
created_at  DATETIME(3)  NOT NULL  DEFAULT CURRENT_TIMESTAMP(3)
updated_at  DATETIME(3)  NOT NULL  DEFAULT CURRENT_TIMESTAMP(3) ON UPDATE CURRENT_TIMESTAMP(3)
deleted_at  DATETIME(3)  NULL
```

Millisecond precision (`DATETIME(3)`) is used for all timestamp columns.

---

# 7. Soft Delete Column

Soft deletes use `deleted_at` with the exact type above. No alternative column names (`removed_at`, `archived_at`) are permitted.

---

# 8. Boolean Columns

Boolean columns use `is_` or `has_` prefixes:

```
is_published
is_physical
is_default
is_enabled
is_verified
is_featured
is_deleted  (reserved for application logic, NOT a soft delete column)
has_downloads
has_activations
```

Boolean defaults: `false` (never `NULL` for boolean state).

---

# 9. Enum Columns

ENUM column names match the domain concept:

```
product_type         ENUM('components', 'themes', ...)
subscription_status  ENUM('active', 'past_due', ...)
content_type         ENUM('blog_post', 'cms_page', 'announcement')
team_role            ENUM('owner', 'admin', 'member')
channel_type         ENUM('email', 'in_app', 'sms', 'push', 'webhook')
```

The column name describes what the enum represents, not the values it holds.

---

# 10. JSON Columns

JSON columns use descriptive names that indicate the data shape:

```
items                  JSON   (cms_menus — ordered menu nodes)
metadata               JSON   (content_entries — SEO, OpenGraph, custom fields)
preferences            JSON   (user_preferences — UI settings)
quiet_hours            JSON   (notification_preferences — time-range config)
rules                  JSON   (feature_flags — rollout percentages, targeting)
arguments              JSON   (mcp_tool_calls — dynamic parameters)
context                JSON   (ai_conversations — system prompts, memory)
```

---

# 11. Pivot Tables

Pivot tables use alphabetical order for the two primary tables, followed by the relationship:

```
component_tag         (components ↔ tags)
theme_token_group     (themes ↔ token_groups)
coupon_product        (coupons ↔ products)
coupon_plan           (coupons ↔ plans)
role_permission       (roles ↔ permissions)
user_role             (users ↔ roles)
team_role_permission  (team_roles ↔ permissions)
```

Pivot tables that carry additional data beyond the two foreign keys use a singular noun naming pattern (e.g., `order_items`, `subscription_items`, `invoice_lines`).

---

# 12. Reserved Column Names

These column names are reserved and must not be used for other purposes:

- `id` — primary key
- `created_at` — creation timestamp
- `updated_at` — update timestamp
- `deleted_at` — soft delete timestamp
- `uuid` — optional public identifier (used where public IDs replace numeric IDs)

# 19. Foreign Key Constraint Patterns

Complete foreign key naming patterns used throughout the schema:

```sql
-- Standard 1:N foreign keys
ALTER TABLE orders ADD CONSTRAINT orders_user_id_foreign
    FOREIGN KEY (user_id) REFERENCES users(id) ON DELETE CASCADE;

ALTER TABLE orders ADD CONSTRAINT orders_billable_type_billable_id_foreign
    -- NO constraint for polymorphic columns

ALTER TABLE team_members ADD CONSTRAINT team_members_team_id_foreign
    FOREIGN KEY (team_id) REFERENCES teams(id) ON DELETE CASCADE;

ALTER TABLE team_members ADD CONSTRAINT team_members_user_id_foreign
    FOREIGN KEY (user_id) REFERENCES users(id) ON DELETE CASCADE;

-- Self-referencing foreign keys
ALTER TABLE cms_menu_items ADD CONSTRAINT cms_menu_items_parent_id_foreign
    FOREIGN KEY (parent_id) REFERENCES cms_menu_items(id) ON DELETE SET NULL;

ALTER TABLE content_entries ADD CONSTRAINT content_entries_parent_id_foreign
    FOREIGN KEY (parent_id) REFERENCES content_entries(id) ON DELETE SET NULL;

-- Nullable foreign keys (SET NULL on delete)
ALTER TABLE team_invitations ADD CONSTRAINT team_invitations_invited_by_foreign
    FOREIGN KEY (invited_by) REFERENCES users(id) ON DELETE SET NULL;

-- CASCADE delete for dependent content
ALTER TABLE components ADD CONSTRAINT components_user_id_foreign
    FOREIGN KEY (user_id) REFERENCES users(id) ON DELETE CASCADE;

ALTER TABLE component_variants ADD CONSTRAINT component_variants_component_id_foreign
    FOREIGN KEY (component_id) REFERENCES components(id) ON DELETE CASCADE;

-- RESTRICT delete for financial records
ALTER TABLE subscriptions ADD CONSTRAINT subscriptions_user_id_foreign
    FOREIGN KEY (user_id) REFERENCES users(id) ON DELETE RESTRICT;

ALTER TABLE invoices ADD CONSTRAINT invoices_subscription_id_foreign
    FOREIGN KEY (subscription_id) REFERENCES subscriptions(id) ON DELETE RESTRICT;

-- SET NULL for optional references
ALTER TABLE order_items ADD CONSTRAINT order_items_product_version_id_foreign
    FOREIGN KEY (product_version_id) REFERENCES product_versions(id) ON DELETE SET NULL;

ALTER TABLE downloads ADD CONSTRAINT downloads_product_version_id_foreign
    FOREIGN KEY (product_version_id) REFERENCES product_versions(id) ON DELETE SET NULL;

-- Pivot table foreign keys
ALTER TABLE component_tag ADD CONSTRAINT component_tag_component_id_foreign
    FOREIGN KEY (component_id) REFERENCES components(id) ON DELETE CASCADE;

ALTER TABLE component_tag ADD CONSTRAINT component_tag_tag_id_foreign
    FOREIGN KEY (tag_id) REFERENCES tags(id) ON DELETE CASCADE;

ALTER TABLE user_role ADD CONSTRAINT user_role_user_id_foreign
    FOREIGN KEY (user_id) REFERENCES users(id) ON DELETE CASCADE;

ALTER TABLE user_role ADD CONSTRAINT user_role_role_id_foreign
    FOREIGN KEY (role_id) REFERENCES roles(id) ON DELETE CASCADE;
```


|---|---|---|

| Slugs, short codes | VARCHAR(255) UNIQUE | `slug`, `order_number` |

| Booleans | BOOLEAN / TINYINT(1) | `is_published`, `has_downloads` |

| Dates only | DATE | `due_date`, `birth_date` |
| Money amounts | BIGINT UNSIGNED | `amount` (in cents) |
| Currency codes | CHAR(3) | `currency` (ISO 4217) |
| Status enums | ENUM or VARCHAR(50) | `status`, `subscription_status` |

| UUIDs | CHAR(36) | `uuid` |

| Search vectors | TEXT | `search_vector` |

# 25. Naming Anti-Patterns

The following naming patterns are explicitly prohibited:

```
❌ tbl_users           → ✅ users (no table prefix)
❌ userID              → ✅ user_id (snake_case)
❌ TblUsers            → ✅ (not PascalCase for tables)
❌ is-active           → ✅ is_active (no hyphens)
❌ status              → ✅ status (not STAT or status_code)
❌ created             → ✅ created_at (include _at suffix)
❌ deleted             → ✅ deleted_at (include _at suffix)
❌ key                 → ✅ license_key or api_key (be specific)
❌ type                → ✅ product_type (be specific)
❌ count               → ✅ download_count (be specific)
❌ order               → ✅ orders (plural for tables)
❌ user                → ✅ users (plural for tables)
❌ UserRoles           → ✅ user_role (snake_case for pivot tables)
❌ order_number_seq    → ✅ order_sequences (use table naming)
❌ _tmp                → ✅ (no temporary tables in migrations)
❌ user_data           → ✅ user_profiles (descriptive naming)
❌ misc                → ✅ (no vague column names)
❌ notes_or_whatever   → ✅ notes (clean column names)
❌ fn_get_user_count   → ✅ (no function prefixes in table/column names)
```

# 32. Naming Convention Validation Checklist

Before creating any migration, verify:

```
□ Table name is plural snake_case
□ Column name is snake_case
□ Foreign key is {singular_table}_id
□ Boolean columns use is_ or has_ prefix
□ Timestamp columns use _at suffix
□ Enum columns describe what the enum represents
□ JSON columns indicate the data shape in the name
│   □ metadata (extensible data)
│   □ rules (feature flag config)
│   □ preferences (user settings)
│   □ arguments (dynamic parameters)
│   □ context (system/memory data)
□ Index follows {table}_{columns}_{type} pattern
□ Unique constraint follows {table}_{columns}_unique pattern
□ Foreign key constraint follows {table}_{column}_foreign pattern
□ Pivot table uses alphabetical table name order
□ Reserved names (id, created_at, updated_at, deleted_at) are not reused
□ Migration file has timestamp prefix in correct order
□ No abbreviations used (write full words)
□ Description column is TEXT NULLABLE (not VARCHAR)
□ Status columns use VARCHAR(50) or explicit ENUM
□ Money amounts are BIGINT UNSIGNED (minor units)
□ Currency is CHAR(3) (ISO 4217)
□ URLs are VARCHAR(2048)
□ File paths are VARCHAR(1024)
□ IP addresses are VARCHAR(45)
□ Checksums are CHAR(64)
□ UUIDs are CHAR(36)
```

# 38. Database Character Set and Collation

All tables use `utf8mb4` character set with `utf8mb4_unicode_ci` collation:

```sql
-- Default table options
ENGINE=InnoDB
DEFAULT CHARSET=utf8mb4
COLLATE=utf8mb4_unicode_ci
ROW_FORMAT=DYNAMIC
```

MySQL/MariaDB column-level overrides for specific use cases:

```sql
-- Binary data stored as string (checksums, hashes)
checksum CHAR(64) CHARACTER SET ascii COLLATE ascii_general_ci NOT NULL

-- Email addresses (case-insensitive)
email VARCHAR(255) CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci NOT NULL

-- Slugs (URL-safe ASCII only)
slug VARCHAR(255) CHARACTER SET ascii COLLATE ascii_general_ci NOT NULL
```

# 39. Naming Convention Enforcement in Code

Laravel migration blueprint helpers that enforce naming:

```php
// Enforces foreign key naming convention
$table->foreignId('user_id')->constrained();

// Enforces unique index naming
$table->unique(['team_id', 'user_id']);
// Creates: team_members_team_id_user_id_unique

// Enforces composite index naming
$table->index(['billable_type', 'billable_id']);
// Creates: orders_billable_type_billable_id_index

// Enforces soft delete column name
$table->softDeletes();  // Always creates 'deleted_at'

// Enforces timestamp column names
$table->timestamps();  // Always creates 'created_at' and 'updated_at'

// Enforces morph columns
$table->morphs('billable');
// Creates: billable_type (VARCHAR 255) + billable_id (BIGINT UNSIGNED) + index
```
