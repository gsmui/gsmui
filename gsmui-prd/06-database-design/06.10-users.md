**Project:** GsmUi
**Domain:** Core Platform

# Purpose

This document defines the database schema for the Users & Teams domain. It covers user identity, team workspaces, membership, invitations, and user-specific profile and preference data.

# 1. Users

## Schema

```
id                BIGINT UNSIGNED AUTO_INCREMENT PRIMARY KEY
name              VARCHAR(255)       NOT NULL
email             VARCHAR(255)       NOT NULL
email_verified_at DATETIME(3)        NULL
password          VARCHAR(255)       NOT NULL
remember_token    VARCHAR(100)       NULL
status            VARCHAR(50)        NOT NULL DEFAULT 'active'
created_at        DATETIME(3)        NOT NULL DEFAULT CURRENT_TIMESTAMP(3)
updated_at        DATETIME(3)        NOT NULL DEFAULT CURRENT_TIMESTAMP(3) ON UPDATE CURRENT_TIMESTAMP(3)
```

CHARSET = utf8mb4, COLLATE = utf8mb4_unicode_ci

## Indexes

| Index Name | Columns | Type |
|---|---|---|
| users_pk | id | PRIMARY |
| users_email_unique | email | UNIQUE |
| users_email_index | email | INDEX |
| users_status_index | status, created_at | INDEX |

## Constraints

- `email` must be unique across all users.
- `status` uses application-level validation. Allowed values: `active`, `inactive`, `suspended`, `pending`.

## Soft Delete

Not applicable. User identity records are not soft-deleted.

## Relationships

```
users 1 ──* teams (as owner)
users 1 ──* team_members
users 1 ──* team_invitations (as invited_by)
users 1 ──1 user_profiles
users 1 ──1 user_preferences
users 1 ──* blocked_users (as user_id)
users 1 ──* blocked_users (as blocked_user_id)
users 1 ──* user_verifications
```

## Eloquent Model

```php
<?php

namespace App\Domains\Users\Models;

use Illuminate\Database\Eloquent\Model;
use Illuminate\Database\Eloquent\Relations\HasMany;
use Illuminate\Database\Eloquent\Relations\HasOne;

class User extends Model
{
    protected $fillable = [
        'name',
        'email',
        'password',
        'status',
    ];

    protected $hidden = [
        'password',
        'remember_token',
    ];

    protected $casts = [
        'email_verified_at' => 'datetime',
    ];

    public function teams(): HasMany
    {
        return $this->hasMany(Team::class, 'owner_id');
    }

    public function teamMembers(): HasMany
    {
        return $this->hasMany(TeamMember::class);
    }

    public function sentInvitations(): HasMany
    {
        return $this->hasMany(TeamInvitation::class, 'invited_by');
    }

    public function profile(): HasOne
    {
        return $this->hasOne(UserProfile::class);
    }

    public function preferences(): HasOne
    {
        return $this->hasOne(UserPreference::class);
    }

    public function blockedUsers(): HasMany
    {
        return $this->hasMany(BlockedUser::class, 'user_id');
    }

    public function blockedByUsers(): HasMany
    {
        return $this->hasMany(BlockedUser::class, 'blocked_user_id');
    }

    public function verifications(): HasMany
    {
        return $this->hasMany(UserVerification::class);
    }
}
```

# 2. Teams

## Schema

```
id          BIGINT UNSIGNED AUTO_INCREMENT PRIMARY KEY
name        VARCHAR(255)       NOT NULL
slug        VARCHAR(255)       NOT NULL
owner_id    BIGINT UNSIGNED    NOT NULL
is_personal BOOLEAN            NOT NULL DEFAULT false
created_at  DATETIME(3)        NOT NULL DEFAULT CURRENT_TIMESTAMP(3)
updated_at  DATETIME(3)        NOT NULL DEFAULT CURRENT_TIMESTAMP(3) ON UPDATE CURRENT_TIMESTAMP(3)
```

CHARSET = utf8mb4, COLLATE = utf8mb4_unicode_ci

## Indexes

| Index Name | Columns | Type |
|---|---|---|
| teams_pk | id | PRIMARY |
| teams_slug_unique | slug | UNIQUE |
| teams_slug_index | slug | INDEX |
| teams_owner_id_index | owner_id | INDEX |

## Constraints

- `slug` must be unique across all teams.
- `owner_id` references `users.id` with `ON DELETE CASCADE`.

## Soft Delete

Not applicable. Team workspace records are not soft-deleted.

## Relationships

```
teams 1 ──* team_members
```

# 3. Team Members

## Schema

```
id          BIGINT UNSIGNED AUTO_INCREMENT PRIMARY KEY
team_id     BIGINT UNSIGNED    NOT NULL
user_id     BIGINT UNSIGNED    NOT NULL
role        ENUM('owner','admin','member') NOT NULL DEFAULT 'member'
invited_by  BIGINT UNSIGNED    NULL
invited_at  DATETIME(3)        NULL
joined_at   DATETIME(3)        NULL
created_at  DATETIME(3)        NOT NULL DEFAULT CURRENT_TIMESTAMP(3)
updated_at  DATETIME(3)        NOT NULL DEFAULT CURRENT_TIMESTAMP(3) ON UPDATE CURRENT_TIMESTAMP(3)
```

CHARSET = utf8mb4, COLLATE = utf8mb4_unicode_ci

## Indexes

| Index Name | Columns | Type |
|---|---|---|
| team_members_pk | id | PRIMARY |
| team_members_team_id_user_id_unique | team_id, user_id | UNIQUE |
| team_members_team_id_index | team_id | INDEX |
| team_members_user_id_index | user_id | INDEX |

## Constraints

- Composite unique: `(team_id, user_id)` — one membership per team per user.
- `team_id` references `teams.id` with `ON DELETE CASCADE`.
- `user_id` references `users.id` with `ON DELETE CASCADE`.
- `invited_by` references `users.id` with `ON DELETE SET NULL`.

## Soft Delete

Not applicable. Membership records are not soft-deleted.

## Relationships

```
team_members belongsTo teams
team_members belongsTo users
team_members belongsTo users (as invited_by)
```

## Eloquent Model

```php

}
```

# 18. Soft Delete Handling

## Policy

User identity records (`users`) are never soft-deleted. When a user requests account deletion:

1. A `user_deletion_requests` record is created with a 30-day grace period.
2. During the grace period, the user account is set to `status = 'deletion_pending'`.
3. After the grace period expires, the account is hard-deleted.
4. Related records are cascade-deleted via foreign key constraints.

## Deletion Cascade Order

When a user is hard-deleted, the following cascade occurs:

```
users.id
├── teams (owner_id → SET NULL or transfer ownership)
├── team_members (user_id → CASCADE)
├── team_invitations (invited_by → SET NULL)
├── user_profiles (user_id → CASCADE)
├── user_preferences (user_id → CASCADE)
├── blocked_users (user_id → CASCADE)
├── blocked_users (blocked_user_id → CASCADE)
├── user_verifications (user_id → CASCADE)
├── user_activity_logs (user_id → CASCADE)
├── user_notifications (user_id → CASCADE)
├── user_connected_accounts (user_id → CASCADE)
├── user_metadata (user_id → CASCADE)
├── user_login_history (user_id → CASCADE)
├── user_deletion_requests (user_id → CASCADE)
├── password_reset_tokens (user_id → CASCADE)
├── sessions (user_id → SET NULL)
├── personal_access_tokens (tokenable → CASCADE)
└── user_roles (user_id → CASCADE)
```

## Ownership Transfer

Before deletion, team ownership must be transferred:

```php
<?php

namespace App\Domains\Users\Actions;

use App\Domains\Users\Models\Team;
use App\Domains\Users\Models\User;

class TransferTeamOwnership
{
    public function execute(Team $team, User $currentOwner, User $newOwner): void
    {
        $team->update(['owner_id' => $newOwner->id]);

        $currentMember = $team->members()->where('user_id', $currentOwner->id)->first();
        if ($currentMember) {
            $currentMember->update(['role' => 'member']);
        }

        $newMember = $team->members()->firstOrCreate(
            ['user_id' => $newOwner->id],
            ['role' => 'owner', 'joined_at' => now('UTC')]
        );

        if ($newMember->role !== 'owner') {
            $newMember->update(['role' => 'owner']);
        }
    }
}
```

## Anonymization Before Deletion

For GDPR compliance, certain data may be anonymized rather than deleted:

```php

        ]);

        $user->profile?->update([
            'bio' => null,
            'avatar_url' => null,
            'website' => null,
            'location' => null,
        ]);

        $user->preferences?->update([
            'preferences' => [],
        ]);

        $user->metadata()->delete();
    }
}
```

# 20. Performance Considerations

## Index Strategy

All foreign key columns are indexed to support JOIN performance:

- `users.email` — indexed for login lookup
- `users.status` — composite index with `created_at` for filtered listing
- `teams.slug` — indexed for URL routing
- `teams.owner_id` — indexed for owner lookups
- `team_members.team_id` — indexed for team member listing
- `team_members.user_id` — indexed for user membership lookups

## Query Patterns

### Fetching a User with Profile and Preferences

```sql
SELECT u.*, up.bio, up.avatar_url, up.timezone, up.preferences
FROM users u
LEFT JOIN user_profiles up ON up.user_id = u.id
LEFT JOIN user_preferences upref ON upref.user_id = u.id
WHERE u.id = ?;
```

### Listing Team Members

```sql
SELECT u.id, u.name, u.email, tm.role, tm.joined_at
FROM team_members tm
JOIN users u ON u.id = tm.user_id
WHERE tm.team_id = ?
ORDER BY tm.joined_at ASC;
```

### Checking User Status

```sql
SELECT status FROM users WHERE id = ?;
```

This query benefits from the primary key index and is O(1).

## Caching Strategy

| Data | Cache Key Pattern | TTL | Invalidation |
|---|---|---|---|
| User profile | `user:{id}:profile` | 1 hour | Profile update |
| User preferences | `user:{id}:preferences` | 1 hour | Preference update |
| Team member list | `team:{id}:members` | 15 minutes | Member add/remove |
| Team count | `team:{id}:member_count` | 15 minutes | Member add/remove |
| User status | `user:{id}:status` | 5 minutes | Status change |

# 22. Index Deep-Dive

## Composite Index Strategy

The following composite indexes are designed for the most common query patterns:

### users Table

```sql
-- Filter users by status with date ordering (admin dashboard)
CREATE INDEX users_status_created_at_idx ON users (status, created_at);

-- Lookup by email (login, registration)
CREATE UNIQUE INDEX users_email_unique ON users (email);
```

### team_members Table

```sql
-- Membership lookup: "Is this user a member of this team?"
CREATE UNIQUE INDEX team_members_team_user_unique ON team_members (team_id, user_id);

-- List all members of a team (sorted by join date)
CREATE INDEX team_members_team_id_joined_idx ON team_members (team_id, joined_at);

-- List all teams for a user
CREATE INDEX team_members_user_id_idx ON team_members (user_id);
```

### team_invitations Table

```sql
-- Token lookup for invitation acceptance
CREATE UNIQUE INDEX team_invitations_token_unique ON team_invitations (token);

-- List pending invitations for a team
CREATE INDEX team_invitations_team_id_idx ON team_invitations (team_id);

-- Email lookup for duplicate invitation check
CREATE INDEX team_invitations_email_idx ON team_invitations (email);
```

### user_notifications Table

```sql
-- Unread notification count per user
CREATE INDEX user_notifications_user_read_idx ON user_notifications (user_id, read_at);

-- Notification listing by type
CREATE INDEX user_notifications_user_type_idx ON user_notifications (user_id, type);
```

### user_activity_logs Table

```sql
-- Activity feed by user
CREATE INDEX user_activity_logs_user_created_idx ON user_activity_logs (user_id, created_at);
```

# 23. Performance Considerations (Extended)

## N+1 Prevention

### Eager Loading Patterns

```php
// BAD: N+1 query
$teams = Team::all();
foreach ($teams as $team) {
    echo $team->owner->name; // Each owner triggers a query
}

// GOOD: Eager load
$teams = Team::with('owner')->get();
foreach ($teams as $team) {
    echo $team->owner->name; // No extra queries
}

// GOOD: Nested eager loading
$users = User::with(['teams', 'profile', 'preferences'])->get();
```

### When to Use `withCount`

```php
// Instead of loading all members just to count them
$teams = Team::withCount('members')->get();

// Access count without loading relation
foreach ($teams as $team) {
    echo $team->members_count;
}
```

### Slow Query Identification

```sql
-- Enable slow query log
SET GLOBAL slow_query_log = 'ON';

-- Find queries without indexes
SELECT * FROM sys.statements_with_full_table_scans
```

### Batch Operations

```php
// BAD: Individual inserts
foreach ($users as $user) {
    UserMetadata::create(['user_id' => $user->id, 'key' => 'status', 'value' => 'active']);
}

// GOOD: Batch insert
$records = collect($users)->map(fn ($user) => [
    'user_id' => $user->id,
    'key' => 'status',
    'value' => 'active',
    'created_at' => now('UTC'),
    'updated_at' => now('UTC'),
])->toArray();

UserMetadata::insert($records);
```

## Connection Health Monitoring

```php
<?php

namespace App\Services;

class DatabaseHealthCheck

            return false;
```
